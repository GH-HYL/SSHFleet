# 汇总给开发者：三段式

本附件是本技能的**收尾规程**：审计跑完之后怎么把结果交给开发者。判据与轴在本体 `SKILL.md`。

**独立跑本技能时按它收口；被别的技能（如 `/audit-retrofit`）派为一路时不读它**——那一路只要轴、判据与报告格式，收口由派它的技能统一负责。

**最终回复按下面三段排，顺序固定，直接输出到终端；三段式本身不另存文件。** 某段没有内容就**整段省略**，不要写「无」占位。

## 第一段：过程与待验证

这一轮实际跑过的命令、构建、本地实验，以及需要开发者自己确认的前提。每条写三样：**做了什么 → 结果 → 还差谁确认什么**。

**放在最上面**：它决定下面两段的可信度，读者要先知道哪些是验过的、哪些还没验。

## 第二段：缺陷清单

证据确凿、执行者自己能认定的——事实错误、边界被破坏、引用了不存在的东西。逐条给 `文件:行号` + 现象 + 证据。

**只列不改，不排优先级，不写修法**——清单是给开发者看的，不是施工单。

## 第三段：待决策

有歧义、两处说法打架、本体第四节 B 轴判出的废话里拿不准该不该删的——需要开发者在几条路里选一个。**用 `my-grill` 问。**

**审计到此已经结束**，可以按 `domain-modeling` 的策略落 ADR 或词表条目；**只写它该写的，不碰被审对象**。

- **技能识别不到就直接读技能文件**：技能目录下找 `my-grill`，按它指向的 `grilling` 执行。**不要因为它没被加载就退化成随便问几句。**
- **先盘点，再发问**：把所有待决策项编号列全，每条只写一句话标题，不展开。这份总清单是「没漏」的唯一凭据，不许省。
- **一轮 3 个，最多 5 个**，按「卡住后续的先问」排序，每问带推荐答案与依据；推荐答案**只给取舍依据与代价，不写具体改法**。**超过 5 个就是刷屏**，剩下的排下一轮。
- **每轮发问前先对一遍总清单**（不落文档，脑子里过；**一轮问满 5 个之后这次必做**）：哪些问过、哪些没问、回答里新冒出哪些。发现漏了就补进编号并**重报总数**。清单只许变长，不许因为问过几轮就默认「差不多了」。
- **每轮末尾报进度**：`已问 3 / 共 12，剩 9`。**没清零不许收工**；总数变了按新数报。
- **收工判据**：清单清零，且最后一轮没有新增。问了三四个就结束，就是漏。

**为什么分批**：`my-grill` 一轮最多五个，二三十个问题一起倒出来会刷屏。这里只取最靠前的三到五条；总清单只给标题，展开的只有当前这一轮那三到五个。

**与本体第五节的关系**：第五节是三轴原样并列，本段按「谁来处置」重排。同一批发现有两种排法，**不要合并成一份**。
