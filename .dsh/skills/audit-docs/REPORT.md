# 汇总给开发者：三段式

本附件是**收尾规程**：四份回执落盘之后，怎么把它们讲成一份给开发者的回复。轴与判据在本体 `SKILL.md`。

回执只做收集、不许改论述；这一步反过来是主观活——挑哪些、怎么并、哪几条要他拍板，都由你判断。**最终回复直接输出到终端，不另存文件**；某段没有内容就整段省略，不写「无」占位。顺序固定。

## 第一段：我怎么核的

这一轮自己跑过的核对与实验，以及被它们推翻的判断。一条一句：**为什么怀疑 → 查了什么 → 结论 → 还差谁确认什么**。

放最前，因为下面两段的分量全看它：读者先要知道哪些是核过的、哪些只是照字面推的。

## 第二段：已定的缺陷

证据确凿、用不着开发者拍板的：事实错误、引用了不存在的东西、边界被破坏、该删的废话。一条一行：`文件:行号` + 现象 + 证据。

**只列不改**，不排优先级，不写修法——他要的是知道「都有什么事」，不是看怎么修。

## 第三段：要你定的事

两处说法打架、有歧义、取舍拿不准的，**用 `my-grill` 问**——一问几段、一轮几条、怎么排，全按它走。

问完就收工。审计到此为止：要落 ADR 或词表条目的另开工作，不碰被审文档。
