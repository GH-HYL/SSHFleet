# 文档审计

对 `HEAD` 与一个固定基点之间的**文档改动**做多轴审计，各轴并行跑子 agent，分轴报告。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

子 agent 一律后台跑：主 agent 不等、不轮询、不反复读回执，也不亲自审，腾出手来随时回复开发者；无活可做就提前结束本轮。

审计只针对语言描述性内容：代码本身不在范围内，代码里的输出与注释要审——判据见 [PHASE-1-SURVEY.md](./PHASE-1-SURVEY.md) 1.1 末。

## 本文件只管入口

四段正文不在这里，一段一个文件：

| 段           | 进这一段的判据                                             | 读哪份                                       |
| ------------ | ---------------------------------------------------------- | -------------------------------------------- |
| 一、梳理     | 技能一触发，从这里起；受众、基点、分类、要问的话都在这一份 | [PHASE-1-SURVEY.md](./PHASE-1-SURVEY.md)     |
| 二、分发     | 说完「授权开工」，意图清单已写成编号                       | [PHASE-2-DISPATCH.md](./PHASE-2-DISPATCH.md) |
| 三、成果输出 | 四个子 agent 都派出去了                                    | [PHASE-3-COLLECT.md](./PHASE-3-COLLECT.md)   |
| 四、收尾     | 四份回执全落盘、自查过一遍                                 | [REPORT.md](./REPORT.md)                     |

**没到那一段，不要打开那段文件。** 判据只看上表第二列，别的都不算数。四段哪一段都要跑很多轮，开头读到的细节到中段就淡了——按段切开、到段再读，手上只有这一段用得上的东西。

## 每段出场清单

**进下一段之前，回头核这张表。** 四段各有几件事，不做也看不出来——活干完了不等于这一段完了。

| 段           | 必须交出的                                                              | 漏了会怎样                       |
| ------------ | ----------------------------------------------------------------------- | -------------------------------- |
| 一、梳理     | 受众与基点已定、改动已分类、该问的话问过                                | 四轴各按自己理解的受众审         |
| 二、分发     | 已拿到「授权开工」、意图清单已编号、四轴提示词已按 2.1 各自的模板填好、四个子 agent 已后台派出 | 轴与轴审同一块，或者谁都不碰     |
| 三、成果输出 | A / B / C / D 四份回执已落盘，D 的提示词带着前三轴全文                  | 补查轴把前三轴重跑一遍           |
| 四、收尾     | 三段式；第二段逐条列全；**第三段用 `/my-grill` 问，问题不落盘**         | 报告像总结，开发者没有可点头的地方 |

**读到哪份就只按哪份办。** 本文件不重复各段做法；段内编号 `1.x`–`3.x` 全篇唯一，文件里写「见 1.4」「见 2.1」指的是那个号，可能在另一份文件里。四轴代号 A/B/C/D、收尾那份里的「第一/二/三段」，都不是阶段号。

本文件不写：受众怎么定、提示词怎么写、回执怎么收、报告怎么落。

## 边界

- 不审「实施计划对不对」——那是设计评审。
- 不评价写得好不好。
