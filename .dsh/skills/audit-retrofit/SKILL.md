# 回顾审计

**用途**：审**代码实现与实现效果**。独立技能，不是 `/code-review` 的补丁——分界见「边界」。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

锚链只有一条：议题说明**问题是什么**，只作引路；**ADR 的决定与理由是唯一基准**；规格与工单**不可信**，只当被审对象。

**派发审计只为一个目标：代码质量。** 文档不是审计目标——顺带发现的文档错误记下来提报；因文档导致实现跑偏的，着重记。

主 Agent 只做调度：摸底、切轴、写提示词、核实疑点，**不亲自审**。

**子 agent 一律后台跑**：不等、不轮询、不反复读回执；无活可做就提前结束本轮。唯一例外是**分发审**（见 2.3）。

**派出去、指向别的技能，都是为本次审计服务**：它们算工具，不算约束；约束上有差异，以本文件为准。

**大流程四段：梳理 → 分发 → 收集 → 收尾。** 每段结束前核一遍「每段出场清单」，不核不算完。

## 本文件只管入口

四段正文不在这里，一段一个文件：

| 段       | 进这一段的判据                                       | 读哪份                                       |
| -------- | ---------------------------------------------------- | -------------------------------------------- |
| 一、梳理 | 技能一触发，从这里起；1.1 判不成立就停               | [PHASE-1-SURVEY.md](./PHASE-1-SURVEY.md)     |
| 二、分发 | `audit-run-<日期>/` 已建、交接清单六节填完、锚已编号 | [PHASE-2-DISPATCH.md](./PHASE-2-DISPATCH.md) |
| 三、收集 | 提示词过完分发审、问过开发者、各轴与复核员都已派出   | [PHASE-3-COLLECT.md](./PHASE-3-COLLECT.md)   |
| 四、收尾 | `回执/` 到齐、跨轴矛盾核完                           | [REPORT.md](./REPORT.md)                     |

**没到那一段，不要打开那段文件。** 判据只看上表第二列，别的都不算数。四段哪一段都要跑很多轮，开头读到的细节到中段就淡了——按段切开、到段再读，手上只有这一段用得上的东西。

## 每段出场清单

**进下一段之前，回头核这张表。** 四段各有一两件事，不做也看不出来——活干完了不等于这一段完了。

| 段       | 必须交出的                                                                                                 | 漏了会怎样                       |
| -------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 一、梳理 | ADR 的决定已抄成编号锚、标了授权来源；`audit-run-<日期>/` 已建、交接清单六节填完                           | 各轴自己找基准                   |
| 二、分发 | 规范轴已派 `/code-review`；分发审的缺口已改进提示词；**派发前已向开发者问过（测试环境与账号、ADR 哪几条是重点）**；各轴与复核员已后台派出 | 环境靠猜、重点靠猜，提示词带缺口出门 |
| 三、收集 | 回执到齐（一轴一份）；跨轴矛盾已核，自己核的写明怎么查的                                                   | 拿一轴的回执当全部，矛盾推给开发者 |
| 四、收尾 | 锚质疑排最前、打架的双方原话并排；**第三段已用 `/my-grill` 四段式问过，问过的清单已记进 `报告.md`**        | 报告像总结，开发者没有可点头的地方 |

**读到哪份就只按哪份办。** 本文件不重复各段做法；前三段编号 `1.x`–`3.x` 全篇唯一，文件里写「见 1.2」「见 2.3」指的是对应编号那一节，可能在另一份文件里。收尾那份里的「第一/二/三段」指报告的三节，不是阶段。

本文件不写：轴怎么切、提示词怎么写、缺口怎么查、报告怎么落。

## 边界

- **只审计，不改被审对象。** 修复、补用例、改文档都等开发者授权，另开工作。
- **审计思路不得被工单塑造。** 轴的切法来自代码结构与 ADR 层级，不来自施工顺序。
- **不重复 `/code-review`。** 规范轴直接派它，本技能只补它覆盖不到的部分（架构、跨模块不变量、真机复现）。
- **不追对话。** 决策以 ADR 为准，会话记录不在审计范围内。
- 不预设仓库结构；摸底查到什么用什么。
