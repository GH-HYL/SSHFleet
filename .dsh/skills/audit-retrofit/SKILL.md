# 落地后重型审计

对一次**已经完工的大范围重构**做多轴并行审计。主 Agent 只做摸底、分发、仲裁、聚合，**不亲自审**。

**这不是看一次 diff。** 范围大到单轴装不下，且议题文档里充斥实施层主张（怎么修、行号、清单）——**它们不能当审计基准**，只能当被审对象。

## 与另外三个技能的分工

| 技能 | 审什么 | 什么时候用 |
| --- | --- | --- |
| `/code-review` | 一个 diff 的规范符合度 + 规格符合度 | 提交前、看一个分支或 PR |
| `/audit-docs` | 一批文档改动的自洽、规范、事实 | 文档刚改完 |
| `/audit-conversation` | 文档是否忠实于对话结论 | 长对话刚写完总结，趁记忆还在 |
| **本技能** | **整场重构落地后的整体验收** | **活已经干完，另开会话回头查** |

**本技能不重复它们的做法，只负责分工与调度**：文档轴直接派 `/audit-docs`，代码规范轴直接派 `/code-review`，本技能只补它们覆盖不到的部分（架构、跨模块不变量、真机复现）。

**本技能不看会话记录。** 活已干完，「当时用户怎么说的」已由工单与 ADR 固化；要追对话走 `/audit-conversation`，性质不同。

## 一、摸底：主 Agent 亲自做

### 1.1 锚是什么：ADR，不是工单

**审计基准只取自 ADR 的「决定」与「理由」。** 议题文档里的实施方法、行号、清单、勾选状态，**全部是待审对象，不是标准答案**。

把 ADR 的「决定」逐条抄成**大方向锚**，编号，随每份子 Agent 提示下发。开头一句固定：

> 以此为准。议题文档里的具体修法是被审对象，不要被它带偏；发现实现与锚不符，报锚，不要报工单。

**为什么要这么定**：工单是施工顺序的产物，它记的是「当时怎么做的」；ADR 记的是「为什么这么做」。重构完成后，能判断「做对了没有」的只有后者。

### 1.2 范围与结构

- **git 范围**：从议题自述的摸底基准（如 audit.md 里写的「摸底基准 cfb7ecc」）到 HEAD；用 `git show --stat` 确认主提交的文件面。用户没说范围就自己定，并说明理由。
- **代码落点**：哪个模块目录、哪些包被大量改动。
- **复现环境**：有无现成测试机、账号、构建方式。

## 二、切轴与分发

按**代码结构**切，不按工单顺序切。每轴一个子 Agent，文件域白名单隔离。

### 2.1 交给现成技能的两轴

| 轴 | 怎么派 |
| --- | --- |
| **文档** | 直接按 `/audit-docs` 的做法派：一致性 + 规范符合度 + 事实准确性三路。**额外加一条**：ADR 里「不再约束」「已被取代」的句子，对应实现是否真的撤干净了 |
| **代码规范** | 直接按 `/code-review` 的做法派：规范符合度 + 规格符合度两路 |

### 2.2 本技能独有的轴（示例，按重构实际调整）

| 轴 | 审什么 |
| --- | --- |
| **架构** | 唯一定义落点是否最优、依赖方向、层级边界、窄接口、调用链 |
| **跨模块不变量** | 同一概念在多处的定义是否真的一致；不变量被谁破过 |
| **判定/决策层** | 旧概念撤净否、优先级次序、覆盖缺口（**多出 = 永远认领不到；遗漏 = 永远归不了类，后者最重**） |
| **配置与映射** | 配置条目与实际产出是否一一对应、顺序、退役条目撤净否 |
| **呈现层** | 回落口径、统计口径、自有文本的边界 |
| **真机复现** | 构建 / vet / 全量测试 + 按场景分账号复现。先梳理复现方案再执行，跑不通如实记，**不许编造结果** |

**隔离手段**：每个提示词写明文件域白名单（明确「不碰 X，那归另一轴」）。跨轴疑点**不在子 Agent 间互传**，一律回主 Agent 仲裁。

## 三、审计员自建框架（留给新会话的一条通路）

**主 Agent 派出的轴，切法来自摸底时的视角，必然有盲区。** 所以要额外派**一个审计员**，它不接任何现成轴，任务是：

1. 读锚（ADR 决定）、读改动面、读议题文档；
2. **自己设计一套本轮的审计框架**——本重构特有的风险在哪、上面那些轴漏了什么；
3. 按自己设计的框架执行，或再派子 Agent 执行；
4. 报告里必须写明**它设计的框架是什么、为什么这么切、以及上面哪些轴它认为有盲区**。

**给它的授权放宽**：它只读，但可以自由选择读什么、按什么顺序读。**它的价值在「不同的切法」**，不在于审得更细。

**注意**：它不需要「对话忠诚度」——活已经干完，追「当时用户怎么说的」由 `/audit-conversation` 负责，性质不同，别混进来。

## 四、每份子 Agent 提示词的固定件

1. **大方向锚**：ADR「决定」的浓缩条目（编号），配那句「以此为准」的固定话。
2. **授权声明**：「只做只读分析，本轮未授权开工，不得修改任何文件」。跑构建/测试的轴另写：临时产物只落 `build/`。
3. **文件域白名单** + 要对照的议题文档章节。
4. **报告格式**：每条发现给 文件:行号 + 证据（命令/原文），区分【硬伤】（事实错误、边界被破坏）与【判断题】（可权衡，说明理由与代价）；**没发现问题就明说「未发现问题」，不许凑数**；限字数。

## 五、真机复现的分工

- 允许直接复现时**按场景分账号**，避免多 agent 同账号互相打架；明确禁危险操作。
- 复现环境信息从议题文档抄，账号密码原样下发。
- **复现行为异常回主 Agent**，路由回对应实现轴定位——不要在复现轴里直接下结论。

## 六、仲裁与聚合（主 Agent）

1. **跨轴矛盾自己读源码裁**，不信任何一轴的转述——两轴对同一行结论相反是常事，各自只核了自己关心的那份。仲裁结论写入汇总。
2. **提交信息 / 文档与实现不符**的事实问题，转文档轴核对（CHANGELOG、手册有无同句）。
3. 聚合按「架构 / 实现 / 复现 / 文档」分节，**不合并不重排**，每条保留轴来源与硬伤/判断题标签。结尾一行：各节计数 + 各节最重的一条。
4. **【硬伤】一律给出修复方向**；**【判断题】交开发者拍板**。
5. **单独一节写审计员的框架**：它切了什么、你认为其中哪几条值得并入下一轮。

## 边界

- **只审计。** 修复、补用例、改文档都等开发者授权，另开工作。
- **审计思路不得被工单塑造。** 轴的切法来自代码结构与 ADR 层级，不来自施工顺序。
- **不重复现成技能。** 文档轴派 `/audit-docs`，规范轴派 `/code-review`，本技能只补它们覆盖不到的。
- **不追对话。** 那是 `/audit-conversation` 的事。
- 不预设仓库结构；摸底查到什么用什么。
