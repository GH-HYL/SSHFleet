# 回顾审计

**用途**：一个议题从问题、决策、规格到实现全流程走完之后，回过头审**代码实现与实现效果**。文档齐、实施验收过了才轮得到它；小修小改不配用——大炮不打蚊子。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

锚链只有一条：议题说明**问题是什么**，只作引路；**ADR 的决定与理由是唯一基准**；规格与工单**不可信**，它们是施工顺序的产物，只当被审对象。

**所有派发审计只为同一个目标：代码质量。** 文档不是审计目标——顺带发现的文档错误记下来提报；因文档导致实现跑偏的，着重记。

主 Agent 只做调度：摸底、切轴、写提示词、核实疑点，**不亲自审**。它一旦下场当审计员，独立复核就没了。

**子 agent 一律后台跑**：主 Agent 不等、不轮询、不反复读回执，腾出手来随时回复开发者；无活可做就提前结束本轮。

**产物落议题目录，必须留档。** 这是重型审计，不是看完就扔的轻型核对。

**派出去、指向别的技能，都是为本次审计服务**：它们算工具，不算约束；约束上有差异，以本文件为准。

**大流程四段：梳理 → 分发 → 收集 → 收尾。**

## 一、梳理

### 1.1 确认主场

判据看三样：议题目录下有没有 `issues/` 子目录、`git diff` 有没有实现改动、ADR 文首「实施载体」写的是「待排期」还是具体路径。三样齐了才是主场。

文档不齐、或还没验收就想跑：问开发者一次。他说强行跑，就按现有材料跑——**本技能不为它降要求，也不保证质量**，不另开一套适配逻辑。

### 1.2 定锚

**基准只取 ADR 的「决定」与「理由」。** 议题文档里的实施方法、行号、清单、勾选状态，全是待审对象。

把 ADR 的「决定」逐条抄成**大方向锚**，编号，随每份提示词下发。开头一句固定：

> 以此为准。议题文档里的具体修法是被审对象，不要被它带偏；发现实现与锚不符，报锚，不要报工单。

**每条锚要标授权来源**：开发者明示的，还是执行者推导的。**推导的那些是重点审对象**——没人明说过的结论，最容易被当成「已经定了」带进工单。

工单记的是「当时怎么做的」，ADR 记的是「为什么这么做」；只有后者能判断「做对了没有」。

### 1.3 盘代码面

- **git 范围**：从议题自述的摸底基准到 HEAD；`git show --stat` 确认主提交的文件面。开发者没说范围就自己定，并在清单里写清理由——本技能把整个审计的决策交给主 Agent，范围是这套决策的一部分。
- **代码落点**：哪个模块目录、哪些包被大量改动。
- **复现环境**：有无现成测试机、账号、构建方式。

### 1.4 查既往审计记录

**审过的点不要再审。** 查议题目录有没有 `audit.md`、`findings-*.md`、历史报告；有就列出来：审过什么、结论是什么、改过没有。

**这一轮审的是改完之后剩下什么。**

### 1.5 传什么、不传什么

新会话不继承记忆，但也不能对路径一无所知——什么都重测一遍，重型到没人跑得起。

判据：**传「不要怎么走」，不传「路已经走过了」。**


| 类型                           | 传不传               | 理由                               |
| ------------------------------ | -------------------- | ---------------------------------- |
| **被证伪的结论**（试过、错了） | **必传，且标明**     | 不传，新会话必然再走一遍同一条死路 |
| **踩过的坑**（方法错误）       | **传方法，不传结论** | 传结论等于给它一个免检             |
| **已验证的结论**（测过、对了） | **不传**           | 审计的价值是独立复核，让它自己测   |

写法：「X 这个方向已经证伪，原因是 Y，**不要再走**」，而不是「X 已经证伪，所以你只需要验 Z」。

### 1.6 交接清单

产物落议题目录下的 `audit-run-<日期>/`，**不落 `build/`**（那边按天清理，审计记录要长期留存）。里面放 `分发缺口.md`（分发审的缺口清单）、`回执/`（各轴回执）、`报告.md`（收尾）。清单六节：

1. **被审对象**——哪些文件、哪些代码，以及「只看不碰」的边界。
2. **关键前提**——是不是主场、文档齐不齐、有没有强行跑的授权。
3. **锚**——ADR 核心主张，编号，标授权来源。
4. **必须知道的背景**——被证伪的方向（含原因）、踩过的坑（只给方法）、已审过的轮次。
5. **建议的审计轴**——按代码结构定，不套模板。
6. **环境与授权**——测试环境、账号、只读声明。

**第 2、4 节最容易被省、又最该写。** 没有第 2 节，执行者套错模板；没有第 4 节，执行者重复走死路。

## 二、分发

按**代码结构**切，不按工单顺序切。每轴一个子 agent，文件域白名单隔离。

### 2.1 派谁

**规范轴直接派 `/code-review`**：规范符合度 + 规格符合度。**只借它的本体**——轴与判据；它的收尾规程不读、不执行，收口只有本技能的三段式。子 agent 提示词里写明这一句。

其余轴自己切，示例（按这次重构的实际调整）：


| 轴               | 审什么                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------- |
| **架构**         | 唯一定义落点是否最优、依赖方向、层级边界、窄接口、调用链                                     |
| **跨模块不变量** | 同一概念在多处的定义是否真的一致；不变量被谁破过                                             |
| **判定/决策层**  | 旧概念撤净否、优先级次序、覆盖缺口（**多出 = 永远认领不到；遗漏 = 永远归不了类，后者最重**） |
| **配置与映射**   | 配置条目与实际产出是否一一对应、顺序、退役条目撤净否                                         |
| **呈现层**       | 回落口径、统计口径、自有文本的边界                                                           |
| **真机复现**     | 构建 / vet / 全量测试 + 按场景分账号复现                                                     |

**隔离手段**：每份提示词写明文件域白名单（「不碰 X，那归另一轴」）。

### 2.2 提示词固定件

1. **大方向锚**：编号条目，配「以此为准」那句。
2. **重心声明**：只审代码质量；文档问题顺带记，因文档跑偏的着重记。
3. **授权声明**：「只做只读分析，本轮未授权开工，不得修改任何文件」。跑构建/测试的轴另写：临时产物只落 `build/`。
4. **文件域白名单** + 要对照的议题文档章节。
5. **报告格式**：每条给 文件:行号 + 证据（命令/原文），区分【硬伤】（事实错误、边界被破坏）与【判断题】（可权衡，说明理由与代价）；**没发现问题就明说「未发现问题」**，不许无中生有。
6. **沙盒与资源**：写清本轴能用哪台机、哪个账号、哪些操作禁做。**测试账号按轴分发，不许两轴共用一个**——重型审计必然有测试，几路同压一个资源就是互相打架。

### 2.3 分发审：发出去之前审提示词

派一个**分发审**，只审这包提示词本身，**不查代码**。它读的是地图，不读内容：这地盘多大、该切几块、切全了吗。

**给什么**：审计目标（一句话）、提示词包全文、被审对象的结构与规模（目录、文件数、行数）。
**不给什么**：主 Agent 的推理过程与预设结论、被证伪的历史、具体技术论证。给了它就会被主 Agent 的思路带跑，只查「主 Agent 想到的地方」。

**四类必查，逐条给结论**：


| # | 查什么         | 判据                                                                              |
| - | -------------- | --------------------------------------------------------------------------------- |
| 1 | **轴间缝隙**   | 几轴文件域并起来，覆盖被审对象全部了吗？有没有哪块说好了「谁都不碰」              |
| 2 | **轴间重叠** | 有没有两轴审同一块——重叠会得出相反结论，还得多一轮核实                          |
| 3 | **预设污染**   | 提示词里有没有夹带主 Agent 的判断（「注意 X 可能有问题」已经是替子 agent 下结论） |
| 4 | **边界与产出** | 每轴的文件域、报告格式、硬伤/判断题的标注要求写清了吗                             |

**产出**：只给**覆盖缺口清单**，落 `audit-run-<日期>/分发缺口.md`，每条说清「缺什么、补哪个轴或补哪条约束」。

拿到清单改完再发，**一轮就够，不循环**。这轮等待是设计内的：分发前多这一步，省掉后面几轮的返工与来回核实。

### 2.4 派发前问开发者

切完轴、提示词过完分发审，**发出去之前问一次**，用 `my-grill`：

- **测试环境与账号**：这轮在哪台机上跑、账号怎么给。议题文档没写、`build/` 又翻不到，就直接问，不要自己猜。
- **决策内容**：ADR 里哪几条是这次的重点、有没有没落进文档的口头约定。

问完等「授权开工」再发轴。

### 2.5 复核员：独立自建框架

**主 Agent 派的轴，切法来自摸底时的视角，必然有盲区。** 所以要额外派一个复核员，它不接任何现成轴：

1. 读锚（ADR 决定）、读改动面、读议题文档；
2. **自己设计一套本轮的审计框架**——本阶段特有的风险在哪、上面那些轴漏了什么；
3. 按自己的框架执行，或再派子 agent 执行；
4. 报告里写明**它设计的框架是什么、为什么这么切、上面哪些轴有盲区**。

**授权放宽**：只读，但读什么、按什么顺序读，由它定。**它的价值在「不同的切法」，不在审得更细。**

### 2.6 两个角色的分工


|                  | **分发审**                       | **复核员**                   |
| ---------------- | -------------------------------- | ---------------------------- |
| 时机             | 提示词写好、**发出去之前**       | 各轴**跑的同时**             |
| 靶子             | **审计设计**（提示词包）         | **审计内容**（代码与文档）   |
| 读什么           | 只读地图：结构、规模、提示词全文 | 深入读：锚、改动面、议题文档 |
| 能不能自己查代码 | **不能**，只审设计               | 能，授权放宽                 |
| 负责什么         | **查「有没有漏」**               | **查「框架对不对」**         |

**两个都要派。** 只派复核员，没人查分发是否周全；只派分发审，没人跳出框架看整体。

### 2.7 真机复现

- 先定复现方案再跑；跑不通如实记，**不许编造结果**。
- 明确禁危险操作；复现环境信息从议题文档抄，账号密码原样下发。
- **复现行为异常回主 Agent**，路由回对应实现轴定位——不要在复现轴里直接下结论。

## 三、收集

**子 agent 直接写自己的回执文件**，落本次目录的 `回执/`（`01-架构.md`、`02-…`）；返回文本可以简略，完整证据在文件里。`回执/` 与 `分发缺口.md` 只读。

**盯着各轴的回执**。某轴迟迟不到，接着等就是：子 agent 还在后台跑，主 Agent 结束本轮就行，回执传回会自动唤醒它，不用守着，也别替它提前收工。真卡住了，开发者会来说。

**跨轴矛盾不在子 agent 间互传**，一律回主 Agent 核实：自己读源码核出的标 `[主查]`，写清怎么查的；核不了的进第三段交开发者定。

## 四、收尾

按 **[REPORT.md](./REPORT.md)** 三段式，落 `audit-run-<日期>/报告.md`。

## 边界

- **只审计，不改被审对象。** 修复、补用例、改文档都等开发者授权，另开工作。
- **审计思路不得被工单塑造。** 轴的切法来自代码结构与 ADR 层级，不来自施工顺序。
- **不重复 `/code-review`。** 规范轴直接派它，本技能只补它覆盖不到的部分（架构、跨模块不变量、真机复现）。
- **不追对话。** 决策以 ADR 为准，会话记录不在审计范围内。
- 不预设仓库结构；摸底查到什么用什么。
