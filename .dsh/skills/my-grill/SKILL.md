# 拷问补丁

审计技能要向开发者提问时，每一问按下面四段写：标题、要你定的事、分析、选项。

衡量标准只有一条：**开发者不打开任何文件，也能听懂在争什么、要定什么。**

## 一问四段

**1. 标题**

**责任**：把读者的思绪引进来。

审计跨几十份文件，问题散在不同地方。标题用**完整的一句话**叙述，说出对象（哪份文件、哪个技能、哪件事）与在争什么，并把两边各是什么在这个句子里带出来。

定性标签属于复查场景——那里读者已经知道是怎么回事，扫一眼关键词就够；这里是第一次见，浓缩成几个字的标题，读者看不懂。

长度：**三十字上下，不超过四十五字**。再短只撑得起定性；超过一行，读者要断开重读。

```txt
差：问 1｜audit-docs 对交付口径有两种说法
好：问 1｜audit-docs 两份文件对交付口径各说各话：一处要原样照抄，一处要按处置重排成三段式
```

**2. 要你定的事**

**责任**：把读者整个拉进现场，让他到这里就开始动脑。长度随事情多少定，不设上限。

写成一段连贯的叙述，把来龙去脉一路说下去：一处怎么规定的、另一处又怎么规定，两处摆在什么位置上打架，最后落到「以哪边为准」或「选哪个」。读者读到句尾，就知道要他点头的是哪一件事。

**行号与文件名跟着叙述走**：讲到某份文件的某句话时，就地标上 `文件:行号`，让位置长在叙述里。

行号与文件名是**辅助锚点**，靠上下文起作用：一句论断配上出处，读者顺手看一眼「哦，是这份文件」，就知道这句话出自哪、那份文件大致干什么，思绪随之跟进来。一串没有叙述的位置，读者看到的只是一串位置。

用浓缩、判断、你自己的理解把事讲透；凡加引号的必须是原话，行号必须给——浓缩归浓缩，不能编。

**3. 分析**

**责任**：让他看见不定的代价——不定的话，下一个照着这份技能或这份代码干活的人，在哪一步走岔。

**4. 选项**（个数看情况）

**责任**：让他一眼选出。每项各给取舍与代价，**代价一栏不许空**。

选项写成 `- A. <取舍与代价>`。推荐的那条在行首标 `⭐`，字母紧随其后：`- ⭐ B. <取舍与代价>`。符号落在行首，读者一眼扫得到；字母写在符号后，推荐理由按它指代。

推荐理由另起一条，以 `➡️` 开头，点名推荐的字母：

```txt
➡️ 推荐B理由：<为什么是它，而不是另外几条>
```

## 一轮最多五个

五个是上限，能问三个就问三个。

## 交出去之前自查

1. 只读标题，能不能说出这一问在争什么；
2. 「要你定的事」读到句尾，有没有落到「以哪边为准」；
3. 每条选项的代价栏，有没有空的。

三条都过，才发出去。

## 框架示例

> **问 1｜audit-docs 两份文件对交付口径各说各话：一处要原样照抄，一处要按处置重排成三段式**
>
> **要你定的事**：`SKILL.md:157` 规定审计收上来「原样列」，并明写「不改一个字、不带判断」，`:159` 又补一句「不合并不重排，也不判哪条更要紧」；而 `REPORT.md:36` 要求把同一批发现「按谁来处置」重排成三段式，还自陈「同一批发现有两种排法，不要合并成一份」。两处管的是同一件事——交什么给开发者——却一个要原样、一个要重排。现状是收口时执行者不知道该抄一份还是抄两份：抄两遍，两份措辞一旦不同就互相打脸；只抄一份，又撞上「不合并不重排」。再深一层，重排本身是判断，与「不带判断」相斥，所以这不是笔误，是两条口径并存。**以哪边为准，你定。**
>
> **分析**：不定的话，执行者会挑一条自己看着顺的照办，另一个人可能挑相反的：同一批文档，两个人交出来的东西形状不同，后续核对、归档、再审计全都没法比。
>
> **选项**：
>
> - A. 只留四节原样，删掉三段式。代价：缺陷与待决策项混成一份，开发者得自己挑出哪几件要他定。
> - ⭐ B. 四节原样不改，每条由出它的那轴标【硬伤】或【判断题】，三段式只按标记落位。代价：四轴提示词各加一条归类要求，主 agent 从「不判断」变成「不改判断」。
> - C. 只留三段式，废掉第五节。代价：主 agent 得自己判哪条算缺陷、哪条算待决策，正好破掉「不判哪条更要紧」那条独立性。
>
> ➡️ 推荐B理由：标记归子 agent、落位归主 agent，只交一份，也没给聚合者多出判断权。
