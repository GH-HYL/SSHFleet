# 拷问补丁

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

**本技能是 `grilling` 的补丁，不独立行走。** 要定哪些事、一轮怎么推进、什么时候算问完——全按 `grilling` 走：先调它，再回来按本文件写每一问。本文件只补三件：**该不该问**、**每一问长什么样**，以及**一轮几条**。

问出来之后，标准只有一条：**开发者不打开任何文件，也能听懂在争什么、要定什么。**

## 先筛：拿得定的不问

写四段之前先分两堆。错得明白、修法只有一条的——引用过期、路径缺目录、一个概念两个名字——不占一轮，一行一条报上去：在哪、错什么、准备怎么改。开发者扫一眼能驳，不驳就是默许你照改。只有你替他定不了的才写四段：两处规矩对着干、一个词两种解、改这边要动那边。

判据一句话：说不出为什么不选另一边，才问。

## 一问四段

### 1. 标题

审计跨几十份文件，问题散在不同地方。标题用**完整的一句话**叙述，说出对象（哪份文件、哪个技能、哪件事）与在争什么，并把两边各是什么在这个句子里带出来。

读者是头一回见这件事：标题缩成几个字的标签，他认不出在说什么，只能回头再问你一遍。

长度**四十五字以内**，通常三十字上下。再短只装得下标签；超过一行，读者就得读而不是扫——标题的活是让人一眼定位这一问在争什么。

```txt
差：Q 1｜audit-docs 对交付口径有两种说法
好：Q 1｜audit-docs 两份文件对交付口径各说各话：一处要原样照抄，一处要按处置重排成三段式
```

### 2. 要你定的事

一段连贯的叙述，长度随事情多少定，不设上限。把来龙去脉一路说下去：一处怎么规定的、另一处又怎么规定，两处摆在什么位置上打架，最后落到「以哪边为准」或「选哪个」。读者读到句尾，就知道要他点头的是哪一件事。

**路径与行号跟着叙述走**：讲到某份文件的某句话时，就地标上 `相对路径:行号`，让位置长在叙述里。路径带上所属目录——写 `audit-docs/REPORT.md`，不写 `REPORT.md`；光有文件名，读者认不出是哪个目录里那份。

没有路径与行号，一句论断就只是空话——读者不知道说的是哪份文件的哪句话，思绪只能飘着。锚点是让话落到实处的钉子：顺手一看，就知道该翻哪里、那份文件大致干什么。

钉点别太密：一段叙述两三个就够，只给「两边各是什么」那几句；同一份文件连着引，后一处只写 `:159`。满段都是路径和行号，读者眼前就只剩这些，思绪的节奏也断了。

用浓缩、判断、你自己的理解把事讲透；加了引号的必须是原话——浓缩归浓缩，不能编。

### 3. 分析

写不定的代价：不定的话，下一个照着这份技能或这份代码干活的人，在哪一步走岔。

### 4. 选项（个数看情况）

每项各给取舍与代价，**代价一栏不许空**。

选项写成 `- A. <取舍与代价>`。推荐的那条在行首标 `⭐`，字母紧随其后：`- ⭐ B. <取舍与代价>`。符号落在行首，读者一眼扫得到；字母写在符号后，推荐理由按它指代。

推荐理由另起一条，以 `➡️` 开头，点名推荐的字母：

```txt
➡️ 推荐B理由：<为什么是它，而不是另外几条>
```

## 一轮几条

靠前的三到五条在这一轮展开成四段，按「卡住后续的先问」排序；超过五条就是刷屏，其余的排下一轮。

## 交出去之前自查

1. 超过五条的有没排到下一轮；
2. 只读标题，能不能说出这一问在争什么；
3. 「要你定的事」读到句尾，有没有落到「以哪边为准」；
4. 每条选项的代价栏，有没有空的；
5. 拿得定的有没有混进四段——有就剔出来，降成一行报掉。

五条都过，才发出去。

## 参考示例

> **Q 1｜my-grill 只管摊几条，audit-docs 要清单加进度：一轮怎么收口按哪边**
>
> **要你定的事**：`audit-docs/REPORT.md:28` 要求「把所有待决策项编号列全」，并写明这份总清单是「没漏」的唯一凭据、不许省，`:31` 还要每轮末尾报进度（`已问 3 / 共 12，剩 9`），没清零不许收工；而 `my-grill/SKILL.md:56` 只说「靠前的三到五条在这一轮展开成四段」，总清单和进度都没了。两处管的是同一件事——一轮怎么收口——一处要清点加报数，一处只要摊几条。现况是跑审计的人得自己挑一边：照 REPORT.md 走，每轮多维护一份清单、多说一行进度；照 my-grill 走，两样都省了，但漏没漏没人对账。**以哪边为准，你定。**
>
> **分析**：不定的话，下次谁跑审计就随手挑一边——挑 REPORT.md 的那次多报几行没人看，挑 my-grill 的那次二三十条只问完靠前几条就收工；同一批审计，出来的东西随人而变。
>
> **选项**：
>
> - A. 两处都留：清单与进度归 audit-docs，my-grill 只摊条数。代价：同一条规矩两个家，改一处漏一处。
> - ⭐ B. 删掉 REPORT.md 的总清单与进度，一轮只摊三到五条。代价：漏没漏不再有对账凭据，二三十条时容易只问完靠前几条就收工。
> - C. 把清单与进度并进 my-grill，audit-docs 只留指针。代价：补丁从「只管每问形状」扩到管流程编排，边界变糊。
>
> ➡️ 推荐B理由：清单和进度是编排，不是问题长什么样；my-grill 只答「这一问怎么写、这一轮摊几条」，漏没漏回给跑审计的人自己盯。
