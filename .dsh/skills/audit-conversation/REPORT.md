# 汇总给开发者：三段式

本附件是本技能的**收尾规程**：审计跑完之后怎么把结果交给开发者。判据与四问在本体 `SKILL.md`。

**每次独立跑本技能都要按它收口**——本技能不派子 agent，也不会被别的技能派成一路。

**最终回复按下面三段排，顺序固定，直接输出到终端；三段式本身不另存文件。** 某段没有内容就**整段省略**，不要写「无」占位。

本体第三节那张报告表照旧，本段是在它之上收口一次，**不另存汇总文件**。

## 第一段：过程与待验证

本技能不跑实验，这段通常省略。有下面两样时才写，每条写清：**是什么 → 结果 → 还差谁确认什么**：

- **无法核实**的条目——对话里找不到依据、需要开发者回忆或补一句的；
- **会话记录截到哪条**——当前步还没落盘时，写明截止的 `U几`。

## 第二段：缺陷清单

本体第三节的「必须修正」按这里重排：**与用户原话直接矛盾的、拿推测当事实的、引用错的**，都归第二段。逐条给文档位置 + 现象 + 依据（`U几` / 原话片段）。

**只列不改**——审计阶段不改被审文档；**不排优先级，不写修法**，修法等授权。

## 第三段：待决策

「建议修正」里的可权衡项（`⚠️` 无明确授权、`➕` 对话有但文档漏）归第三段：结论对不对、要不要动，开发者定。**用 `/grill-with-docs` 问。**

**审计到此已经结束**，可以按 `grill-with-docs` 的策略落 ADR 或词表条目；**只写它该写的，不碰被审文档**。

- **技能识别不到就直接读技能文件**：技能目录下找 `grill-with-docs`，按它指向的 `grilling`、`domain-modeling` 自己执行。**不要因为它没被加载就退化成随便问几句。**
- **先盘点，再发问**：把所有待决策项编号列全，每条只写一句话标题，不展开。这份总清单是「没漏」的唯一凭据，不许省。
- **一轮 3 个，最多 5 个**，按「卡住后续的先问」排序，每问带推荐答案与依据；推荐答案**只给取舍依据与代价，不写具体改法**。**超过 5 个就是刷屏**，剩下的排下一轮。
- **每轮发问前先对一遍总清单**（不落文档，脑子里过；**一轮问满 5 个之后这次必做**）：哪些问过、哪些没问、回答里新冒出哪些。发现漏了就补进编号并**重报总数**。清单只许变长，不许因为问过几轮就默认「差不多了」。
- **每轮末尾报进度**：`已问 3 / 共 12，剩 9`。**没清零不许收工**；总数变了按新数报。
- **收工判据**：清单清零，且最后一轮没有新增。问了三四个就结束，就是漏。

**为什么分批**：`grilling` 的规矩是一轮问完整个 frontier，但三段式本身已经不短，二三十个问题一起倒出来会刷屏。这里只取 frontier 里最靠前的三到五条；总清单只给标题，展开的只有当前这一轮那三到五条。

**`✅` 有依据的不进任何一段**——三段式只放「要处置的」，不是把本体第三节重抄一遍。
