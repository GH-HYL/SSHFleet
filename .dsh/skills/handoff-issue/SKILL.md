# 议题交接

**用在什么时候**：这一轮把「梳理、定方案、写文档」做完了，但实施要交给别人（新会话 / 另一台机器 / 隔天再来）。或者上下文快到限，怕做到一半接不上。

**要达成的效果**：新会话看到仓库里这些文档，**不需要再问任何人**就能知道——这是什么、从哪开始、按什么顺序做、什么算做完、哪些坑不能踩。

## 一、先确认「能不能接」

按下面逐条过，**有一条不满足就先补上再交接**：

- [ ] **决策已闭环**。所有争论过的点，结论都落在 ADR 或 spec 里，且没留「待定」。
- [ ] **文档口径一致**。同一件事在 ADR、spec、工单、词表里的说法不打架——**这一条最容易翻车**，跑一遍 `/docs-review` 或至少人工对一遍关键术语。
- [ ] **有实施入口**。议题目录下有一份 `README.md`（或 spec 头部）说清：去读哪几个文件、从哪张工单开始、什么顺序。
  - **这份 README 是交接用的临时文件，不是长期文档。** 它必须自己写明这一点，并写明**什么条件下该删**（通常是「全部工单 `Status: done`、CHANGELOG 已更新」）。不写，下一个人会以为它是常驻设施，一边维护一边疑惑它为什么和 spec 重复。
  - 同时列一份**收工清单**：议题完成时要做完的几件事，其中最后一项就是「删掉本 README」。
- [ ] **工单是可执行的**。每张有明确的验收条目，条目指向的是真实存在的代码位置——**别写「改一下那里」，要写文件与函数**。
- [ ] **状态字段准确**。还没做的写 `ready-for-agent`，做完的写 `done`；**做完的事不许还挂着 ready**，下一轮的人会重做一遍。
- [ ] **代码没有被顺手改动**。纯梳理的轮次，工作区应当只有文档改动。

## 二、把「没写进文档的东西」倒出来

梳理过程里一定有些东西只在对话里，没落到纸上。逐项过：

- **跟人讨论定下的判断**——为什么不是另一种写法。→ 进 ADR「备选方案」或被否掉的方案表。
- **踩过的坑**——某个看着像 bug 其实是设计、某处代码有个隐蔽前提。→ 进工单 `## Comments`，或 spec 的 Further Notes。
- **核对到的硬事实**——行号、计数、某个函数在哪。→ 进工单验收条目，带上你在哪查到的。
- **明确排除的东西**——试过不行、本次不做、留给以后。→ 进 `Out of Scope` 或 `wontfix`。

**别写「我已经想清楚了」**——新会话看不到你的脑子。要么落成字，要么它就得重新推一遍。

## 三、收尾文档

- CHANGELOG 若本轮有使用者可见的改动，按仓库规矩写；**纯文档轮次通常不用动 CHANGELOG**。
- 本轮碰过的每个 spec / 工单 / ADR，**`Status:` 都回到与实际相符**。
- 新增或改过的文档，**互相之间有指针**：至少 spec → README、工单 → README、ADR → spec。
- **交接用的 README 要自带「何时删除」**。它是为这一轮交接临时建的，议题完成后应当删掉；不写这句话，后来的人会把它当成要长期维护的文件，或者反过来以为议题还有没写完的部分。

## 四、交付前自查

拿一句话问自己，然后去文档里找答案：

> **「我一个从没见过这个议题的人，打开仓库，能在五分钟内知道下一步做什么吗？」**

做不到，就补到做得到。具体看两处：

- 议题目录下有没有一个**能当入口读的文件**；
- 第一张工单的「要做的」看完，能不能**不翻别的文件就动手**。

## 五、写交接语

**最后必须产出这一段**，供人复制粘贴到新会话。格式固定，照抄结构：

````
接手一个议题，先读这几份文档再动手：

- 入口：<议题目录>/README.md（从哪开始、什么顺序、坑在哪）
- 决策：<ADR 路径>（重点看第 N 条）
- 规格：<spec 路径>
- 工单：<issues 目录>/01 至 0N

**当前进度**：<做到哪了。没开工就写「代码一行未动，文档已定稿」>

**本轮要做**：<从哪张工单开始，做到哪停>

**约束**：
- <这条议题最容易踩的坑，一到三条>
- 授权：本轮已授权开工 / 只做只读分析——**明确写出来**
- 每完成一张工单，把它的 Status 改成 done，并在 Comments 里记一条

技术栈与目录结构：<一句话>
````

**这段必须能独立读懂**——不许出现「上一轮说的那个」「按我们刚定的那样」。新会话没有那个上下文。

## 六、提交

文档改动单独提交，与代码改动分开。提交信息写清：**这一轮只落文档，代码另由后续会话实施**——将来翻历史的人要靠它区分「写了计划」和「做了事」。

## 边界

- **不替开发者定方案**。交接时发现还有没定的事，列出来问他，别自己拍。
- **不写「以后再说」**。文档里每句模糊的「后续再处理」，都是新会话将来要重新推一遍的债。
- **不动代码**。这一轮的目的是把纸面理顺，不是顺手改两行。
- **交接入口不留常驻**。那份 README 完成后就该删；交接时不要把它写进 CHANGELOG 或手册，也不要让它成为 spec 的一部分。
