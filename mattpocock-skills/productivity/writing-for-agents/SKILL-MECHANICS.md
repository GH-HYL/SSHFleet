# Skill mechanics（技能机制）

[`writing-for-agents`](SKILL.md) 中技能专有的那一支：当文档是一个技能时，哪些地方不一样（frontmatter、调用方式的选择，以及路由技能）。其余关于怎么写的内容，都是 `SKILL.md` 里的通用参考。

## Invocation（调用方式）

两个选择，交换的是那两种负载：

- 一个**模型调用（model-invoked）**的技能保留 `description`，这样 agent 能自主触发它，其他技能也能抵达它。你仍然可以打出它的名字：模型调用永远**包含**用户可达；description 只会增加 agent 的发现能力，从不夺走人的。description 是技能顶层的上下文指针，被迫永远保持加载：用永久的上下文负载，换可发现性。一个内容全是参考的模型调用技能，也是共享参考的一个归宿：另一个技能能调用它，因此多个技能都需要的参考可以住在一个地方。机制：不写 `disable-model-invocation`，并写一个面向模型的 description，承载那些触发分支（`SKILL.md` 里的指针写法规则完全适用）。
- 一个**用户调用（user-invoked）**的技能把 description 从 agent 的可达范围里剥掉：只有人打出它的名字才能调用，别的技能都不行。上下文负载为零，但它花认知负载：你就是那个必须记得它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变成面向人的：一句单行摘要，触发列表剥掉。

只有当 agent 必须自行抵达这个技能，或另一个技能必须抵达它时，才选模型调用。如果它只会被人手敲触发，就把它做成用户调用，不付任何上下文负载。

两个用户调用技能都需要的共享参考，两边都住不了：没有 description，谁也触发不了谁。把它推到一个技能系统之外的普通文件里：任何技能都能指过去的外部参考。

## Splitting by invocation（按调用方式拆分）

拆分的调用切法（序列切法住在 `SKILL.md` 里）：当你有一个独特的、应当自行触发它的领头的词（一个你在提示词里真的会用的触发词），或者另一个技能必须抵达它时，就把一个模型调用的技能拆出来。你要为新的常驻 description 付上下文负载，所以这份独立可达必须值这个价。

## Router skills（路由技能）

当用户调用的技能多到你记不住时，那份堆积起来的认知负载可以用一个**路由技能（router skill）**来治：一个用户调用的技能，它列出其他技能以及各自何时该去够，于是人只需要记一个技能而不是许多个。它只能提示，永远无法触发它们：用户调用的技能没有 description，所以除了人，什么都抵达不了它们。
