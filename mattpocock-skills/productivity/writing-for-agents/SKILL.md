这是写任何 agent 会消费的文档的参考：一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针抵达的文档。包装形式不同，写法不变：同一批杠杆让每一份都变得可预测，因为 agent 每次运行走的是同一个**过程**，而不是产出同样的结果。

当你正在写的文档是一个技能时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择和路由技能。

## Context pointers（上下文指针）

**上下文指针（context pointer）**是存在于 agent 上下文中的一处引用，它指明某份在上下文之外的材料，并编码了抵达它的条件。技能的 description 是一个；`AGENTS.md` 里指明某份文档的一行是同一个东西。决定 agent 何时去够那份材料、以及够得有多可靠的，是指针的**措辞**，不是它的目标。一个必需的目标挂在一个措辞软弱的指针后面，就是一个方差 bug（variance bug）：先把措辞磨利，只有在磨利失败时才把材料内联。

一个指针干两件事：说明材料是什么，并列出应当触发去够它的那些**分支（branches）**（一个分支就是文档处理的一个不同情形，所以不同的运行会走不同的路径穿过它）。常驻加载的指针，每一个字每一轮都要付费，所以它比正文更该被狠心修剪：

- **把领头的词放到最前面**：指针正是在那里做它的触发工作。
- **一个分支一个触发器。** 给同一个分支改名的同义词，是同一个分支写了两遍；把它们合并，只留下真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## The two loads（两种负载）

你添加的每一份文档和每一个指针，都在花两种预算中的一种：

- **上下文负载（Context load）**是常驻加载的材料压在 agent 窗口上的成本：`AGENTS.md` 的一行、一个技能 description、任何每一轮都待在上下文里的东西，不管它触不触发，都在花 token 和注意力。
- **认知负载（Cognitive load）**是压在人身上的成本：有哪些文档存在，以及什么时候该去够哪一份。人就是索引本身。这不是一项要最小化的成本：它是人类能动性的代价；把它花在人的判断重要的地方，在不重要的地方移除它。

只通过指针抵达的材料，以指针自身那一行为代价，逃掉了上下文负载；而完全没有指针的材料，则完全靠认知负载承载。

## Information hierarchy（信息层级）

一份文档由两类内容搭成：**步骤（steps）**（agent 按顺序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者自由混搭：全是步骤（一份食谱）、全是参考（一份复查的规则、本技能），或者两者兼有。核心决策是每一块坐在**信息层级（information hierarchy）**的哪一级上——那是一架按「agent 多急需这份材料」排序的梯子：

1. **文件内步骤（In-file step）**是主层级：agent 按顺序做什么。
2. **文件内参考（In-file reference）**按需查阅。常常是一组合法地平级的同类项（一次复查的每条规则都在同一级上），这是一种很好的安排，不是坏味道。
3. **外置参考（Disclosed reference）**被推到单独的文件里，通过一个上下文指针抵达，只在指针触发时加载。范围从同文件夹里的兄弟文件，一直到完全外部的参考——它住在任何地方，任何文档都能指过去。

往下压得太少，顶层就会臃肿；压得太多，你就把 agent 真正需要的材料藏了起来。这个张力就是整个决策。

**渐进式披露（Progressive disclosure）**就是沿着梯子向下移动（移出主文件、放到指针后面），好让顶层保持可读。它首先不是一项 token 优化：它是保护层级的方式。分支是检验披露是否得当的最干净标准：每个分支都需要的就内联，只有部分分支会够到的就推到指针后面。当一份文档有步骤时，那些本该被外置的文件内参考会把步骤埋掉，让「关注步骤」变成掷硬币：这是一个方差杠杆，不只是可读性杠杆。

**就近放置（Co-location）**是文件内部的对应手段：梯子决定一块内容坐得**多深**，就近放置决定它落位之后**旁边坐着什么**。把一个概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，这样读其中一部分就会把邻居一并带进来。检验标准是：文档应当读起来像为 agent 写的文档。成组放置的材料读起来是这样；散落的材料不是。（这与重复不同：重复是把同一个含义在两处各说一遍；散落是把同一个含义碎成许多片。）

**蔓延（Sprawl）**是这里的失败模式：一份文档就是太长了，即便每一行都是活的、独一无二的。注意力在冗余中被摊薄，而每多一行就多一行需要保持相关。解药就是那架梯子：把参考外置到指针后面，并按分支或顺序拆分，让每条路径只携带它需要的东西。

## Steps and completion criteria（步骤与完成判据）

每一个步骤都以一条**完成判据（completion criterion）**收尾，也就是告诉 agent 活干完了的那个条件。两个属性让它成为一个杠杆：

- **清晰度（Clarity）**：agent 分得清「做完」和「没做完」吗？一个模糊的边界（「达成理解」）会招来**过早完成（premature completion）**：在真正做完之前就结束这一步，注意力滑向**「做完了」这件事**。前方还看得见的那些步骤（**完成后步骤（post-completion steps）**）提供拉力；判据的清晰度则是阻力。按顺序防守：**先磨利边界**（局部且便宜）；只有当它确实无法消除模糊**并且**你观察到了那种赶工，才通过拆分序列把后面的步骤藏起来。隐藏只在真正的上下文边界上才有效（一次交接或一次子 agent 派发；内联调用会把后面的步骤留在上下文里，什么也没清掉）。
- **要求量（Demand）**：它要求多少。 「每个被改动的模型都要交代清楚」逼出彻底的工作，而「产出一份变更清单」不会。要求量驱动**跑腿功夫（legwork）**（agent 在工作内部做的挖掘，它潜伏在措辞里，而不是被写成单独的步骤），并且它不限于步骤：「每条规则都应用了」约束的是一整块平铺的参考，正如「每一步都做了」约束的是一个序列——一份全参考文档就是这样仍然带着一条穷尽性的门槛。

最强的判据既可核查，又穷尽。

## When to split（何时拆分）

把一份文档拆成两份，要花掉两种负载中的一种，所以只有当这个切法值回票价时才拆：

- **按序列（By sequence）**：把一串步骤拆开，前提是那些完成后步骤会诱使 agent 赶它面前这一步。让它们不在视野里，会驱动 agent 在当前任务上多下功夫。当心反过来的情况：把序列合并，会让每一步后面的步骤暴露给接下来要做的事，从而招来过早完成。
- **按调用方式（By invocation）**，技能专有：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## Leading words（领头的词）

**领头的词（leading word）**是一个紧凑的概念，它本就活在模型的预训练里，agent 在运行文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。作为一个 token 反复出现，而从不作为一句话出现，它积累出一份分布式的定义，用最少的 token 锚住一整片行为区域，靠的是招募模型已经持有的先验。自造一个词也行，只要你把它定义清楚，但生造词招募不到任何先验：预训练里就有的词白送你东西，自造词则要你用定义 token 去付账；先去找一个现成的词。

它锚两次。在正文里锚**执行**：词一出现，agent 每次都会去够同一套行为；在平铺参考里，它把注意力聚焦到一类要找的东西上。在指针里锚**调用**：当同一个词同时活在你的提示词、你的文档和你的代码库里时，agent 会把这份共享语言与那份材料联系起来，从而更可靠地够到它。

去找用领头的词做重构的机会。一个三元组在三个地方各被拼写一遍，一个指针花一整句话去指一个想法。每一处都是央求着坍缩成单个 token 的段落：

- 「快、确定、低开销」→ _tight_（一个 _tight_ 的回路）。
- 「一个你信得过的回路」→ _red_，把一个模糊的闸门变成二元的可观察状态（回路在 bug 上变 _red_，或者不变）。

你赢两次：token 更少，而且 agent 挂靠思考的钩子更锐利。假定每份文档都带着一些可以被领头的词退役的复述。去找出来。

**否定（Negation）**是紧挨着这个杠杆的失败模式：靠禁令来操控，会把被禁的行为拖进上下文，让它**更**可及，而不是更不可及。_别想大象_，结果满脑子只有大象；否定是一个弱修饰语，会被那个被强烈激活的概念冲垮，于是这条禁令有一半读起来像是在指示去做那件事。要提示**正面**：说出目标行为（「写单行注释」），这样被禁的那种就永远不会被说出口。一条禁令只有在它作为一条你无法正面表述的硬护栏时才配得上位置；即便如此，也要把它和正面目标配成一对，让注意力落在该做什么上。

## Pruning（修剪）

- 把每个含义放在**单一事实来源（single source of truth）**里：一个权威的位置，这样改变行为就是改一个地方。**重复（Duplication）**（同一个含义出现在不止一处）要付出维护和 token 的代价，并且会把一个含义在梯子上的显眼程度抬到超出它真实的位置。（它是领头的词意外的反面：领头的词故意重复一个 token，但从不重复含义。）
- **环境（environment）**也是一个事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），而重述它的文档就是一份**缓存（cache）**：一次查询的副本，只有在那次查询很贵时才值回它的负载。缓存那些 agent 查不到的东西：没写下来的约定、某个选择背后的理由、没有哪份配置会坦白的小坑。把一文件、一命令就能查的东西留给环境，在那里它们不会过时。
- 逐行检查**相关性（relevance）**：它还和这份文档要做的事有关吗？一行失去相关性，或是因为它从不与任务相关（纯粹的铺陈，或一个本该被外置的分支），或是因为它所描述的行为或世界变了而过时。更短的文档更容易保持相关。没有修剪纪律，默认的结局就是**沉积（sediment）**：因为添加感觉安全、删除感觉冒险而一层层沉淀下来的过时地层，直到你必须打钻穿透它们才能找到仍然活着的东西。
- 逐句猎杀**空操作（no-ops）**：模型默认就已经遵守的指令，是花钱说了句废话。检验标准（它相对默认行为改变了行为吗？）是相对于模型的，不是相对于读者的：两个人对某个空操作意见不一，其实是对默认行为意见不一，解决办法是跑一遍那份文档，而不是辩论。当一句话不合格时，删掉整句，而不是从里面删几个词。这条检验也能给领头的词打分：一个弱到赢不过默认的词（当 agent 本来就挺彻底时还说 _be thorough_）就是空操作，修法是换一个更强的词（_relentless_），而不是换一种技巧。
