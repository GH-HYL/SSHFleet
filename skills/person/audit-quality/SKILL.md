# 质量审计

**用途**：判一次改动做得对不对。三件事，按可靠性排——**有没有另造一套**最硬，**决定履行了没有**最软。

**不判**：好不好看、你满不满意、合进去会不会坏。满意度是验收；会不会坏是合并那一刻的事，不在这里判。

**判据只有仓库**：代码里同形的写法、`GLOSSARY.md`、ADR、已有的导出符号。通用最佳实践不作判据——那是教科书的意见，不是你的决定。

**前提**：新会话。开发者只给议题名——**提交边界自己找，别问他要 SHA。**

**配跑的门槛**：净 diff 新增了导出符号、新建了文件、或跨了模块边界。纯内部改动、改名、格式化不跑——`commit-then-diff-review` 够用。

## 定位

`<base>` 一律取本地主分支（本仓是 `master`；远端另有 `main`，别猜）。

1. **未合并的议题分支**：`git branch --no-merged <base>` 按议题主题词匹配；命中用 `git diff <base>...<branch>`。合并前跑，走这条。
2. **已合并**：`git log --merges --grep=<主题词>` 找合并提交，用 `git diff <merge>^1 <merge>`——净效果，不含合并之后的修补。
3. **都没中**：读 `docs/issues/<议题>/` 的 spec 与修复记录，按里面提到的日期或提交缩小区间。
4. **仍定不了**：列出候选（分支名 / 合并提交 / 时间区间）让开发者挑一个。别猜，也别拿附近的议题凑。

分支上混了不属于本议题的提交，报出来，别静默排除。

## 一、取判据

### 1.1 事实（最硬）

**反推**：同一形式（字面量、后缀、前缀、格式、标点）在净 diff 里由两个及以上写入点各自拼出。这不是违反断言，是**断言缺失**——两处各拼一次，说明本来就该有一个构造点。

**辅助**：`GLOSSARY.md` 与改动文件注释里带排他语义的句子（「只许它写」「由 X 自己拼」「唯一」「只在……出现」）。有则用；没有不妨碍 1.1。

### 1.2 决定（最软）

按议题反查 ADR：读 `docs/issues/<议题>/spec.md`，顺它引的 `adr/` 找决定；没引时用 ADR 里的「实施载体」字段反查回来。定位不到就报「判据缺失」，别拿附近的 ADR 凑。

抄编号原文，不改写。只取「决定」段，不取背景与备选方案。

**判据不足的决定不拿来判代码。** 验锚的结论是很多决定判不动；拿模糊的决定去核代码，只会产出你确认不了的假阳性。判不动的那条写「判据不足，跳过」，不硬判。

### 1.3 既有形状

只列**能指认的**：一个具体符号，加重叠的形式（同形字面量、同格式、可复制的同一段逻辑）。

说不出具体形式的不算。「这两个函数职责看起来差不多」不报——那是模型最容易编的话。

## 二、核对

**分批，不分阶段。** 这里的问题是对象体量，不是步骤跨度：净 diff 超过三个目录就按目录切批，一批一轮，各自出分母。并发上限仍是两个子 agent，批次不限。

**A 事实轴**（1.1）：找反例。被独占的形式出现在指定写入点之外；或同一形式在两个及以上写入点各自拼出。

**B 判据轴**（1.2 + 1.3）：决定逐条找落点，判履行 / 未履行 / 走反方向 / 无落点；新增单元与既有符号的重叠，必须给出重叠的形式。

每份提示词固定带三条：

- 判据原文（决定编号或断言原句，整句贴上）。
- 只报命中，不给修法。
- 每条带 `file:line`；找不到落点写「无落点」，**不许推定它应该实现了**。

## 三、输出

两种形状，按有没有替代物分。

**有替代物**（1.1 / 1.3）：

```text
你看到的：<界面上或终端里能看见的现象>
实现：<file:line>，一句话说它怎么做的
本该调用：<符号名>（<file:line>）
差别：<改一处要改几处／哪种情况会不一致>
```

**无替代物**（1.2 未履行——要求的东西根本没出现，填不出「本该调用谁」）：

```text
决定原文：#<编号> <照抄>
它要求：<一句话>
diff 里有：<实际做了什么>
缺：<什么没出现>
```

每条上头挂判据原文。**没有判据原文的是编的，没有 `file:line` 的是猜的**——缺一不报。

末尾先给分母，再给命中：

```text
分母：新增可调用单元 X 个；格式化字面量 Y 处；涉及模块 Z 个
命中：事实轴 A 条；判据轴 B 条
```

分母对不上，说明它抽查了几个文件就交，不是全扫。

## 边界

- 不报这三类之外的任何问题。命名、注释、风格、性能一律不报。
- 通用最佳实践、`codebase-design` 这类设计词汇，只用来解释命中，不作判据。
- 不给修法、不排优先级、不落盘。
- 不跑真机，不判能不能合——那两件在别处判。
- 只审，不改被审对象。
