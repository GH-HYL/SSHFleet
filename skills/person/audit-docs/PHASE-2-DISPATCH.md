# 二、分发

> 全局约束与段间导航见 [SKILL.md](./SKILL.md)；本文件只讲本段做法。

## 2.1 四轴分工

**四份提示词都带这句**：只报问题，不给修法，不排优先级。

### A. 一致性

```
本轮只做只读分析，不改任何文件。
diff：git diff <基点>...HEAD
受众：<1.1 的结论>
本轮意图清单：<编号清单>

报告（每条引用原文 + 文件:行号）：
(a) 同一个词或同一个数值在两处以上出现、用法不一致——**每处原文与行号都要给**；只给一处的，这条不算；
(b) 清单里有、文档里没落实的；
(c) 文档里出现了清单外的说法（越权承诺、凭空新增的规则）——先写一句「清单覆盖到哪」，落不进这句范围的才算越权；
(d) 引用了不存在的章节号、工单号、路径——点明即可，展开写篇幅太大。

不评价文笔。找不到问题就明说。
末尾一行：比对了 N 处说法、核了 M 条清单项、点了 K 处引用。
```

### B. 规范与文本

```
本轮只做只读分析，不改任何文件。
diff：git diff <基点>...HEAD
受众：<1.1 的结论>
本仓库的规范与纪律：<规范文件，或「无」>
体例参照：<同目录既有同类文档>

先在报告开头写一句「这份文档的目的：……」，后面每条都对着它判。

报告，前两条要用手段，不许凭感觉：
(a) 沿革串：grep「此前是」「现已改为」「我们讨论过」，每处给文件:行号；
(b) 示例能不能原样照抄跑通：照抄执行一遍，给命令与输出；
(c) 废话：删掉这句话或这几个字，是否影响上面那句目的。
    不受损就是废话。每条给：文件:行号 + 原文 + 删掉之后文档少了什么。
    常见：同一段意思在两处写、一节只是把别处链接抄一遍、为将来预留的字段/章节、
    破折号后与括号里的解释理由、把上一句换个说法再说一遍。
(d) 违反上列条款的，引用条款原文；
(e) 与同类文件体例不一致的——给出参照文件的 文件:行号，并指出具体哪一项不同（标题层级／字段顺序／称呼）；
(f) 按受众检查内容。

受众是使用者：
· 未定义术语：`GLOSSARY` 里没有、且首次出现处没有一句话定义的词。按词计，给词与位置。
· 缺动作：出现「可以」「支持」「建议」，却没给命令、路径或字段名。
· 缺陷包装成文案：描述的现象能在本仓复现为某个已知缺陷或已知限制，而文档没标成限制（那会丢掉排查现场）。
· 泄漏实现：出现源码路径、函数名或内部步骤名（`internal/`、`pkg/`、`.go`、函数名）。

受众是执行者：
· 结论有没有标来源：开发者明示，还是执行者推导
· 决策处有没有给取舍理由，还是只落了结论
· 引用能不能点回原文：章节号、工单号、ADR 编号

受众是开发者：
· 这类文档少，遇到就按受众表里开发者那一行的问题逐条看

同一份内容可能同时服务几类受众：分开审，每类受众单独过一遍。

跳过 linter 能抓的（缩进、链接语法）。

末尾一行：沿革串 X 处、示例 Y 个（跑通／跑不通）、废话 Z 处、体例不符 W 处、受众四条各报条数。
```

### C. 事实准确性

```
本轮只做只读分析，不改任何文件。
diff：git diff <基点>...HEAD

凡是断言仓库事实的地方，逐条回源码核对：
- 文件、函数、行号是否存在、内容是否如描述
- 计数是否属实（用 grep/wc 实际数）
- 配置条目、字段名、环境取值是否一致
- 引用的其他文档路径是否存在

每条对不上的给：文档位置 → 文档说的 → 源码实际 → 证据（命令+输出）。
只报对不上的。查不到的优先报。
末尾一行：核了 N 处断言，对不上 M 处。
```

### D. 补查

A/B/C 各看一类对象，D 补没被它们看的那一类——不是把它们再跑一遍，也不是挑几处深查。

四轴并发派出，D 看不到别的回执，缺口只能由主 agent 派发时算好：A 看跨文件说法之间、B 看单份逐处文字与体例、C 看断言与源码之间。算不出缺口就写「无」，空跑比编一个强。

```
本轮只做只读分析，不改任何文件。
diff：git diff <基点>...HEAD
受众：<1.1 的结论>
前三轴的分发提示词：<A/B/C 三块全文>
A/B/C 覆盖不到的对象：<按上一段算出的缺口>

只查这几类对象，不重跑 A/B/C 的判据。判据自己定，但每条要写得出违反形态。

报告：查了哪几类 → 每类结论（有问题／无问题）。与 A/B/C 撞车不用管，汇总时去重。
```
