# 对话忠实度审计

审一份**总结性文档**是否忠实于**本轮对话真正得出的结论**——只审这一件事，**不审代码、不跑实验、不核实技术事实**。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

要抓的错只有一种：文档内部读起来完全自洽，只与对话不符——第 20 轮改过的结论，第 30 轮写文档时写成中间某个已废的版本，或把执行者推的写成开发者确认的。所以每条判断都得回对话里找依据。

**定位用对话的锚**：`U12`（第几条用户原话）、轮次、原话片段。

**子 agent 一律后台跑**：主 agent 不等、不轮询、不反复读回执，腾出手来随时回复开发者；无活可做就提前结束本轮。

**大流程四段：梳理 → 分发 → 收集 → 收尾。** 小流程随场景变，这四段不变。每段结束前核一遍「每段出场清单」，不核不算完。

## 本文件只管入口

四段正文不在这里，一段一个文件：

| 段       | 进这一段的判据                                     | 读哪份                                       |
| -------- | -------------------------------------------------- | -------------------------------------------- |
| 一、梳理 | 技能一触发，从这里起；判据与取数都在这一份         | [PHASE-1-SURVEY.md](./PHASE-1-SURVEY.md)     |
| 二、分发 | 受众那句写完、截止点写明、拿到「授权开工」         | [PHASE-2-DISPATCH.md](./PHASE-2-DISPATCH.md) |
| 三、收集 | A 的回执落盘（这时派 B、C 的动作还在前一份里进行） | [PHASE-3-COLLECT.md](./PHASE-3-COLLECT.md)   |
| 四、汇总 | 三路回执齐、跨路矛盾核完                           | [PHASE-4-REPORT.md](./PHASE-4-REPORT.md)                     |

**没到那一段，不要打开那段文件。** 判据只看上表第二列，别的都不算数。四段哪一段都要跑很多轮，开头读到的细节到中段就淡了——按段切开、到段再读，手上只有这一段用得上的东西。

## 每段出场清单

**进下一段之前，回头核这张表。** 四段各有几件事，不做也看不出来——活干完了不等于这一段完了。

| 段       | 必须交出的                                                                                       | 漏了会怎样                       |
| -------- | ------------------------------------------------------------------------------------------------ | -------------------------------- |
| 一、梳理 | 受众那句与截止点已写死、判据 Q1–Q4 已归档                                                        | 后两路没有坐标                   |
| 二、分发 | 已拿到「授权开工」；三路提示词写死四样；**A 先派，B 等 A 的回执到手再派，C 与 B 并行**            | B 抢在 A 前面，坐标自己编         |
| 三、收集 | A / B / C 三份回执齐，B 用的坐标取自 A 的回执                                                    | 拿 B 的推断当坐标，越查越偏       |
| 四、汇总 | 三段式；**第三段用 `/my-grill` 问，问题不落盘**；真找不出问题就明说                              | 加一条假问题，整份报告作废       |

**读到哪份就只按哪份办。** 本文件不重复各段做法；判据用 Q1–Q4，段内编号 `1.x`–`3.x` 全篇唯一，文件里写「见 Q2」「见 1.2」指的是那个号，可能在另一份文件里。收尾那份里的「第一/二/三段」指报告的三节，不是阶段。

本文件不写：会话怎么取、提示词怎么写、回执怎么收、报告怎么落。

## 边界

- 审计阶段不改被审文档；会话导出落 `build/audit/`，不进被审目录。
- **只有开发者本人的话算依据**。派出去干活的回报、系统注入的上下文，都不算。
- **不给改法**——改法等于替开发者下结论；修法另开工作，另走授权。
- **找不出问题就明说**，加一条假问题整份报告就废了。
