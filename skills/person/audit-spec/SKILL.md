# 规格审计

**用途**：开工前判两件事，按可靠性排——**会不会破坏框架**最硬，**有没有替你拍板**最软。

**为什么在开工前**：结构问题在代码里被发现，改法通常是重写；在规格里被发现，改法是改一句话。这是这个技能存在的唯一理由——不是审得更细，是审得更早。

**不判**：实现好不好、能不能跑、代码对不对——这时候还没有代码。文案好坏、手册口径也不归这里，那是 `/audit-docs`。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

## 一、取判据

**判据只有仓库**，三类，按可靠性排。

### 1.1 结构决定（最硬）

来源两处，取最新的：

- `docs/adr/` 里**状态为 accepted、且内容约束代码结构的**那几篇。当前是 `ADR-0032`（五站分层、契约只放类型、交接件新造、横切叶子包、塔尖只搬不做）。
- `docs/issues/2026-10-30-2134-架构重构/` 里 `Status: resolved` 的决策工单——它们的 `## Answer` 就是更细的结构判据。

**先确认它还算数**：读 `状态:` 行与 `## 更新记录`，被取代的顺指针走到当前决定。作废的不拿来判。

**判据没落定的，不硬判。** 结构定义仍在施工期（01–13 号工单没定完）时，凡落到还没定的那一块，写「判据不足，跳过」并点名缺哪一条，不许拿常识补。

### 1.2 词表与既有形状

`GLOSSARY.md` 里的术语定义；新工程已有的导出符号。规格里用的词与词表对不上、或要求一个与既有符号同形的新函数，指出来。

### 1.3 出处（最软）

规格里每一条写成「决定」的话，都要能指出是谁定的：开发者本轮原话、已 accepted 的 ADR、还是执行者推导。取数照 `skills/person/audit-adr/SESSIONS-WORKBUDDY.md` 与 `SESSIONS-DSH.md`，导成 `U<n>` 编号后引用。

## 二、查什么

### A 轴：结构风险（硬）

**判据一句话**：一个需求要的数据，**只许从相邻那一站的交接件里拿**。凡是绕开交接件的拿法，都是这条轴要找的东西。

规格里出现下列任一种形状，就报——**每条要给规格原文与行号**，指不到原文的不报：

1. **穿站回取**：某站需要的数据不在它上一站交给它的交接件里，规格的解法是「执行时再去读一遍配置 / 清单 / argv」，而不是「回上游那条纵切把字段加进交接件」。
2. **反向依赖**：下游站要 import 上游站（例如呈现站 import 执行站的数据类型），或塔尖替某一站做它该做的事。
3. **契约长函数**：要求往 `contract` 里加校验、格式化、拼装一类的函数。那个包只许有类型与常量。
4. **横切包长出业务**：要求 `console` / `log` / `ask` / `archive` / `exitcode` 里做业务判断，或让它们导出「顺便」用的 helper。判据是「它产不产业务数据」。
5. **新模块无家**：规格描述的新东西说不清属于哪一站、也不像横切——尤其「来回穿插」的那类。**这正是开发者最怕的一类**：它不是大模块，是到处都要用一小点的那种。
6. **同一件事算两遍**：上游已算出的值不在交接件上，规格让下游重算一遍。重算的代价不是性能，是两处将来会不一致。

**来回穿插的模块要单独看**：规格里凡是「多处都要用它」的说法，追问一句——它是**横切**（不产数据、叶子包），还是**业务**（产数据、该归某一站）？两者都说不清的，就是第 5 类。

### B 轴：越权（软）

规格的读者是执行者，它不要求每条都标来源，所以这一轴只抓三类明显形状：

1. **结论没标来源**：开发者只在收集依据（「你觉得呢」「嗯」「有道理」），规格里写成「已决定」。
2. **把试探句写成决定**：原话是「可能」「要不」「先这么看」，规格里落成硬决定。
3. **数没出处**：具体数字、条数、版本号，指不出实测记录、原话、源码位置三样之一。

## 三、怎么走

**门槛**：只审文档，不跑程序，不需要测试环境。

**分批**：一次审一个议题（一个 `docs/issues/<slug>/` 目录）。目录里 `spec.md` 加全部 `issues/NN-*.md` 一起过，不拆批——工单脱离 spec 判不出结构风险。

**两轴可以并行**，各派一个只读子 agent；也可以一个人顺序过。A 轴要通读全文，B 轴要对着会话原话逐条核，两者互不依赖。

**派活时写明**：只做只读分析；判据原文整段贴上（维度、编号）；只报命中不给修法；每条带 `file:line`；找不到落点写「无落点」，不许推定。

**规格里没有的，不算命中。** 这一轴找的是「写下来的东西会引导出坏结构」，不是「还没写到的东西」。漏写本身归 `/audit-docs` 的清单核对。

## 四、输出

两栏，硬在前。

```text
规格审计：<议题名>｜A 轴 3 条，B 轴 2 条

结构风险
1. <一句话说这条要干什么>
   原文：<spec 或工单原文>（<file:line>）
   撞的是：<哪条结构决定，照抄编号与原句>
   照这么写会怎样：<下游从哪儿拿到什么、为什么那一步就绕开了交接件>
2. …

越权
1. 原文：<…>（<file:line>）—— 原话说的是「<U 编号 原话>」，规格写成了「已决定」。

判据不足
- <哪一块结构还没定，因此这一处判不了>
```

**末尾一行给分母**：`过了一遍 spec.md 与 N 张工单，A 轴命中 X 条、B 轴命中 Y 条、判据不足 Z 处。`

分母对不上，说明抽查了几段就交，不是通读。

## 边界

- **不给修法，不排优先级**，但每条要说清「照这么写会怎样」——只报问题不给后果，开发者判不了轻重。
- **不判实现**：规格说「要做什么」，不要求它写「放哪个包」。拿包名去卡规格是反的——那会逼规格提前把结构定死。只卡**数据从哪来**这一类必须回答的问题。
- **不替开发者选**。两个方案都合理时，把代价摆出来，写「待定」，不推荐。
- 判据没落定就写「判据不足」，不拿通用最佳实践补位——那是教科书的意见，不是他的决定。
- 只审文档，不改被审对象。
