# 规格审计

**用途**：开工前判两件事，按可靠性排——**架构会不会被磨掉**最硬，**有没有替你拍板**最软。

**为什么在开工前**：结构问题在代码里被发现，改法通常是重写；在规格里被发现，改法是改一句话。这是这个技能存在的唯一理由——不是审得更细，是审得更早。

**不判**：实现好不好、能不能跑、代码对不对——这时候还没有代码。文案好坏、手册口径也不归这里，那是 `/audit-docs`。

**三个角色按这一套用**：开发者下指令、拍板；执行者照技能干活（AI 或后来的维护者）；使用者用做出来的工具。

## 零、这一轴在找什么

**一句话判据**：

> 照这份规格写出来，ADR-0032 的哪一条会从**「结构上做不到」退化成「纪律上不该做」**？

ADR-0032 的立身之本不是"定了五站"，是**把纪律从靠人盯换成结构上够不着**。所以腐蚀不是"某条决定被违反"，是**那条决定失去牙齿**——违反了也不报错、不编译不过、没人看得见。

**拼接只是最典型的一种**：想要一个值，本来该回上游纵切加字段，图省事就地拿一个。它之所以危险，不是因为它难看，是因为**它把「够不着」变成了「够得着，只是不该」**——从那一刻起，后面每一个 AI 都有了一条可走的路。

**所以这一轴不看"写得对不对"，看"写得会不会让人走上那条路"。**

## 一、取判据

**判据只有仓库**，三类，按可靠性排。

### 1.1 结构决定（最硬）

来源两处，取最新的：

- `docs/adr/` 里**状态为 accepted、且内容约束代码结构的**那几篇。当前是 `ADR-0032`（五站分层、契约只放类型、交接件新造、横切叶子包、塔尖只搬不做、单向依赖）。
- `docs/issues/2026-10-30-2134-架构重构/` 里 `Status: resolved` 的决策工单——它们的 `## Answer` 是更细的结构判据。

**先确认它还算数**：读 `状态:` 行与 `## 更新记录`，被取代的顺指针走到当前决定。作废的不拿来判。

**判据没落定的，不硬判。** 结构定义仍在施工期（01–13 号工单没定完）时，凡落到还没定的那一块，写「判据不足，跳过」并点名缺哪一条，不许拿常识补。

### 1.2 词表与既有形状

`GLOSSARY.md` 里的术语定义；新工程已有的导出符号。规格里一个概念两个名字、一个名字两个意思，或要求一个与既有符号同形的新函数，都指出来。

### 1.3 出处（最软）

规格里每一条写成「决定」的话，都要能指出是谁定的：开发者本轮原话、已 accepted 的 ADR、还是执行者推导。取数照 `skills/person/audit-adr/SESSIONS-WORKBUDDY.md` 与 `SESSIONS-DSH.md`，导成 `U<n>` 编号后引用。

## 二、查什么

### A 轴：架构会不会被磨掉（硬）

按「哪一层边界被绕过」分五组。**每组末尾那句「退化成什么」就是判定标准**——想不出退化后的样子，这条不成立，别报。

#### 甲、数据流被绕开

1. **穿站回取**。某站要的数据不在上一站交给它的交接件里，规格的解法是「执行时再读一遍配置 / 清单 / argv」，而不是「回上游那条纵切把字段加进交接件」。
   *退化：下游随时能拿到源头，交接件变成可选。*
2. **同一件事算两遍**。上游已算出的值不在交接件上，规格让下游重算。代价不是性能，是两处将来会不一致。
   *退化：同一事实有两个来源，改一处另一处不知道。*
3. **共享可变状态**。规格里出现包级变量、单例、全局配置对象、共享缓冲，让某处能「伸手去拿」。判据是：有没有人真的写它，不是语法上能不能写。
   *退化：够不着变成够得着，而且没有任何一处代码需要改就能改到。*

#### 乙、唯一出口被绕

4. **自己出字**。规格让某处自己 `print`、自己拼报错串、自己决定报错长什么样，而不走已定的构造点或输出包。
   *退化：报错格式回到「每个包一套」，而那正是上一次重构要治的病。*
5. **自己退场**。规格让某站在内部 `os.Exit`、`panic` 了事、或自行中断流程。
   *退化：退出权散开，收尾（defer、日志落盘、码页还原）随时断。*
6. **契约长出行为**。要求往 `contract` 里加校验、格式化、拼装、默认值填充。
   *退化：契约从「一张纸」变成抽屉，下游依赖它就开始成环。*
7. **横切长出业务**。要求 `console` / `log` / `ask` / `archive` / `exitcode` 里做业务判断，或导出「顺便」用的 helper。判据是「它产不产业务数据」。
   *退化：叶子包不再纯，人人依赖的包开始被业务缠住，环从这里长出来。*
8. **塔尖变厚**。规格让入口文件里出现拼字符串、判业务规则、读写文件、装配数据。
   *退化：塔尖是唯一「不读代码、看一眼行数就知道薄不薄」的指标；它一厚，这个指标就没了。*

#### 丙、形状被改

9. **加站、劈站、并站**。规格描述的处理环节既不属于已定的五站、也不是横切——它在悄悄加第六站；或把某一站劈成两个、把两站并成一个。
   *退化：五站这个切法失去意义，之后没有「该放哪儿」的答案。*
10. **反向依赖**。下游站要 import 上游站（例：呈现站 import 执行站的数据类型），或塔尖替某一站做它该做的事。
    *退化：单向变双向，改一站要连带改上下游，改动面从此不可预测。*
11. **阶段顺序被动过**。规格让闸门顺手修 `Plan` 里的值、让整理站回写执行站的产物、或跳掉某一站。
    *退化：没人说得清「这个值是那站定的还是这站改的」，正是交接件要防的那件事。*
12. **新模块无家**。规格描述的新东西说不清属于哪一站、也不像横切——尤其「来回穿插」的那类。它不是大模块，是到处都要用一小点的那种。
    *退化：它会被随手塞进某一站，或被攒成一个新的 `common`。这是最容易发生、也最难事后看出来的一类。*
    *追问一句：它是横切（不产数据、叶子包），还是业务（产数据、该归某一站）？两者都说不清的，就是这一类。*

#### 丁、接口变浅

13. **导出零件而不是整件事**。规格要求某包导出的是「格式化字节」「拼个路径」「判一下类型」这种小件，而不是「生成主密钥」「执行一次上传」这种整件事。
    *退化：深模块变浅模块。零件一多，复用零件这条路就宽了——AI 想省事时不用再造，拼一拼就行。*
14. **接口变宽**。一个函数十个参数、返回五个值、或要求调用方先调 A 再调 B 再调 C 才能用。整件事的复杂度漏到了调用方。
    *退化：模块深度消失，调用方要懂内部次序，边界形同虚设。*

#### 戊、例外口子

15. **「暂时」「特殊情况」「先这样」「这次例外」**。规格里出现这类措辞，或某条要求只在少数路径生效而没写清边界。
    *退化：例外一旦落地就再没人收回来，而腐蚀都是从一次例外开始的——有一个，就有第二个。*

**这一组最隐蔽**：它看着是务实，实际是把「做不到」改成「这次可以做」。凡是这类措辞，一律报，不问轻重。

### B 轴：越权（软）

规格的读者是执行者，它不要求每条都标来源，所以这一轴只抓三类明显形状：

1. **结论没标来源**：开发者只在收集依据（「你觉得呢」「嗯」「有道理」），规格里写成「已决定」。
2. **把试探句写成决定**：原话是「可能」「要不」「先这么看」，规格里落成硬决定。
3. **数没出处**：具体数字、条数、版本号，指不出实测记录、原话、源码位置三样之一。

## 三、怎么走

**门槛**：只审文档，不跑程序，不需要测试环境。

**分批**：一次审一个议题（一个 `docs/issues/<slug>/` 目录）。目录里 `spec.md` 加全部 `issues/NN-*.md` 一起过，不拆批——工单脱离 spec 判不出结构风险。

**两轴可以并行**，各派一个只读子 agent；也可以一个人顺序过。A 轴要通读全文，B 轴要对着会话原话逐条核，两者互不依赖。

**派活时写明**：只做只读分析；判据原文整段贴上（组别、编号、那句「退化成什么」）；只报命中不给修法；每条带 `file:line`；找不到落点写「无落点」，不许推定。

**规格里没有的，不算命中。** 这一轴找的是「写下来的东西会引导出坏结构」，不是「还没写到的东西」。漏写本身归 `/audit-docs` 的清单核对。

**十五条不要求全命中。** 一条都没中就是没有——别为了凑输出硬找。反过来，一条规格里同时踩中三组，说明它整体方向就偏了，在汇总里单说一句。

## 四、输出

硬在前。每条都要能回答「退化成什么」——答不出的不报。

```text
规格审计：<议题名>｜A 轴 3 条，B 轴 2 条

架构腐蚀
1. 甲-1 穿站回取
   原文：<spec 或工单原句>（<file:line>）
   撞的是：<ADR-0032 或决策工单的哪一条，照抄原句>
   退化成：<照这么写之后，哪条约束从「做不到」变成「不该做」>
2. 戊-15 例外口子
   原文：<…>（<file:line>）
   退化成：<这个例外一旦落地，谁以后还会照着原路走>
3. …

越权
1. 原文：<…>（<file:line>）—— 原话说的是「<U 编号 原话>」，规格写成了「已决定」。

判据不足
- <哪一块结构还没定，因此这一处判不了>
```

**末尾一行给分母**：`过了一遍 spec.md 与 N 张工单，A 轴命中 X 条、B 轴命中 Y 条、判据不足 Z 处。`

分母对不上，说明抽查了几段就交，不是通读。

## 边界

- **不给修法，不排优先级**，但每条要说清「退化成什么」——只报问题不给后果，开发者判不了轻重。
- **不判实现**：规格说「要做什么」，不要求它写「放哪个包」。拿包名去卡规格是反的——那会逼规格提前把结构定死。只卡**边界会不会被绕过**这一类必须回答的问题。
- **不替开发者选**。两个方案都合理时，把代价摆出来，写「待定」，不推荐。
- **不拿"最佳实践"当判据**。判据只有仓库里的结构决定；通用的分层理论、设计模式一律不作数——那是教科书的意见，不是他的决定。
- 判据没落定就写「判据不足」，不拿常识补位。
- 只审文档，不改被审对象。
