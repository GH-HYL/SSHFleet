# 二、分发

> 全局约束与段间导航见 [SKILL.md](./SKILL.md)；本文件只讲本段做法。

按**代码结构**切，不按工单顺序切。每轴一个子 agent，文件域白名单隔离。

**白名单按三圈给，不给单个文件。** 轴要判的是关系——依赖方向、同构一致、上下文联动——这些都在邻域里；只给改动面，等于让它猜。同一份文件允许两轴都读，但必须写清读的是哪一面，以及「不碰什么、那归另一轴」。

## 2.1 派谁

**每份提示词都带这句**：只报问题，不给修法，不排优先级。

**规范轴直接派 `/code-review`**，只用下表的「用」那半：

| 用                                                                 | 不用                                                                                                                       |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 两轴的切分：规范符合度、规格符合度                                 | **它的 Spec 基准**：它拿 spec 原句当判据（`Identify the spec source`、`quote the spec line`）。本技能里 spec 只作被审对象，**判据是锚**；spec 与锚冲突时按锚判，冲突本身走锚质疑 |
| 规范来源检索顺序：仓库文档 → 缺省 smell 基线                       | **它的收尾**：`## Standards` / `## Spec` 两节并列 + 一行总结。本技能收口只有回执 + 三段式                                  |
| smell 基线十二条，以及它自带的三个约束（仓库文档压过基线、smell 一律算判断题、工具能抓的跳过） | **前台并发**：它要求两个子 agent 前台同时发。本技能的子 agent 一律后台跑                                                    |
| diff 取点：三点 `...` 对 merge-base                                | **`Under 400 words` 上限**：回执不限字数，证据写全进文件                                                                    |
| —                                                                  | **它的两个前置**：`/setup-matt-pocock-skills` 那套 issue tracker（本仓库议题在 `docs/issues/<slug>/`）、「没有 spec 就跳过 Spec 轴」（本技能不跳，没有 spec 就纯按锚判） |

子 agent 提示词里固定写这一句：**本轮只用 `/code-review` 的轴与基线，不用它的基准、收尾、字数上限与并发方式；spec 是被审对象，不是判据。**

其余轴自己切，示例：

| 轴               | 审什么                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------- |
| **架构**         | 依赖方向、层级边界（下层不许 import 上层）、循环依赖、窄接口（方法数与参数）、调用链深度     |
| **跨模块不变量** | 同一概念在几处各自定义或各自拼装（谁在写这个值）、不变量被谁破过。**「同一概念」只归本轴**   |
| **判定/决策层**  | 映射表的结构病：子串抢注、特异性倒序、自撰文案、样本覆盖比（做法见 2.8）                    |
| **配置与映射**   | 只判接线：配了有没有人读、默认值、退役项撤净否。**不判规则内容**，那归判定层                 |
| **呈现层**       | 回落口径、统计口径、自有文本的边界                                                           |
| **真机复现**     | 构建 / vet / 全量测试 + 按场景分账号复现                                                     |

**隔离手段**：每份提示词写明文件域白名单（「不碰 X，那归另一轴」）。

## 2.2 提示词固定件

1. **大方向锚**：编号条目，配「以此为准」那句；**另加锚质疑出口**（规则见 1.2）：发现锚与证据冲突，单列一节回报。
2. **重心声明**：只审代码质量；文档问题顺带记，因文档跑偏的着重记。
3. **授权声明**：「只做只读分析，不得修改任何文件」。跑构建/测试的轴另写：临时产物只落 `build/`。
4. **文件域白名单** + 要对照的议题文档章节。
5. **回执写什么**：每条给**位置与证据**（命令或原文），照它能翻到原处；区分【硬伤】（事实错误、边界被破坏）与【判断题】（可权衡，说明理由与代价）；**没发现问题就明说「未发现问题」**。
   末尾给分母：本轴核了 N 处（依赖边／配置条目／用例／断言），报了 M 条。分母对不上，说明它抽查了一段就交。
6. **沙盒与资源**：写清本轴能用哪台机、哪个账号、哪些操作禁做。**测试账号按轴分发，不许两轴共用一个**。
7. **旧名残留清单**：1.3 扫出来的残留按域切分随提示词下发——归判定层的给分类名、归呈现层的给提示语、归配置层的给配置键。**本条只作事实，判不判由该轴自己定。**

## 2.3 分发审：发出去之前审提示词

派一个**分发审**，只审这包提示词本身，**不查代码**。它读的是地图，不读内容：这地盘多大、该切几块、切全了吗。

**给什么**：审计目标（一句话）、提示词包全文（**锚随包给，不算预设**）、被审对象的**三圈清单**（改动面 / 一跳邻域 / 边界，见 1.3 与 1.6 第 1 节）。
**不给什么**：主 Agent 的推理过程与预设结论、被证伪的历史（这些只给审计轴，见 1.5）、具体技术论证。

**四类必查，逐条给结论**：

| # | 查什么         | 判据                                                                              |
| - | -------------- | --------------------------------------------------------------------------------- |
| 1 | **轴间缝隙**   | 几轴的文件域并起来，覆盖**三圈**了吗？改动面、邻域里的下游/上游/同构兄弟，有没有哪块说好了「谁都不碰」 |
| 2 | **轴间重叠**   | 有没有两轴审同一块——重叠会得出相反结论，还得多一轮核实。同一文件的不同面不算重叠，前提是白名单写清了各读哪一面 |
| 3 | **预设污染**   | 提示词里有没有夹带主 Agent 的判断（「注意 X 可能有问题」已经是替子 agent 下结论） |
| 4 | **边界与产出** | 每轴的文件域、回执要写什么、硬伤/判断题的区分，写清了吗                           |

**产出**：只给**覆盖缺口清单**，落 `audit-run-<日期>/分发缺口.md`，每条说清「缺什么、补哪个轴或补哪条约束」。

拿到清单改完再发，**一轮就够，不循环**。

## 2.4 派发前问开发者

切完轴、提示词过完分发审，**发出去之前问一次**，用 `my-grill`：

- **测试环境与账号**：这轮在哪台机上跑、账号怎么给。议题文档没写、`build/` 又翻不到，就直接问，不要自己猜。
- **决策内容**：ADR 里哪几条是这次的重点、有没有没落进文档的口头约定。

**只读不需要「授权开工」。** 要动真机、要占账号、要跑构建与测试的，把那几条单独问一次再发。

## 2.5 复核员：独立自建框架

**另派一个复核员，它不接任何现成轴**：

1. 读锚（ADR 决定）、读改动面、读议题文档；
2. **自己设计一套本轮的审计框架**——本阶段特有的风险在哪、上面那些轴漏了什么；
3. **只执行框架里「上面几轴覆盖不到」的部分**；轴已覆盖的不重跑——重跑的结论必然与轴相同，白花一轮；
4. 报告里写明**它设计的框架是什么、哪些对象没被任何轴覆盖、它补的只是那几块**。

**授权放宽**：只读，读什么、按什么顺序读由它定；**要的是不同的切法，不是审得更细**。

## 2.6 两个角色的分工

|                  | **分发审**                       | **复核员**                   |
| ---------------- | -------------------------------- | ---------------------------- |
| 时机             | 提示词写好、**发出去之前**       | 各轴**跑的同时**             |
| 靶子             | **审计设计**（提示词包）         | **审计内容**（代码与文档）   |
| 读什么           | 只读地图：结构、规模、提示词全文 | 深入读：锚、改动面、议题文档 |
| 能不能自己查代码 | **不能**，只审设计               | 能，授权放宽                 |
| 负责什么         | **查「有没有漏」**               | **查「框架对不对」**，只补漏的那块 |

**两个都要派。**

## 2.7 真机复现

- 先定复现方案再跑；跑不通如实记，**不许编造结果**。
- 明确禁危险操作；复现环境信息从议题文档抄，账号密码原样下发。
- **复现行为异常回主 Agent**，路由回对应实现轴定位——不要在复现轴里直接下结论。

## 2.8 映射表的结构审法（判定/决策层用）

凡「输入文本 → 分类名」的映射（判据表、路由表、错误码表），审结构，不审覆盖——覆盖要输入全集，仓库里没有。

1. **子串抢注**：靠前的关键词是后面某条的子串 → 后面那条永不命中。逐对比较，报被抢的规则 + 抢它的那条。
2. **特异性倒序**：越短越宽的关键词应越靠后；靠前却更宽的，报次序可疑。
3. **自撰文案**：关键词不是上游原文，而是本仓自己拼的话——上游措辞一改就死。逐条列。
4. **样本覆盖**：拿历史日志或测试日志跑一遍，算「命中 M / 共 N」；未命中的是「多出」候选，报清单不报结论。

遗漏只能靠覆盖推，没样本就写「未覆盖 N−M 条，遗漏无法判断」，别凭想象补。
