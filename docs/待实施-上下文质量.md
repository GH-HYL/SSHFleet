## 七、工作区结构

### 现状：`tools/` 混了三种寿命不同的东西

`.gitignore` 是白名单制：`*` 全忽略，再逐个 `!tools/xxx` 点名放行。于是同一层目录里躺着：

四类东西混在一层：工程部件（`check.sh`、`test.sh`、`install-hooks.sh`、`hooks/`、`release/`）、本机工具（`skill-manager/`、`ab/`）、一次性车架（`refactor/`）、未追踪杂物（`command-description/`、`__pycache__/`）。

**判据是「每个 clone 下来的人是不是都需要它」**，不是目录名好不好听。

### 定法：先清干净，再整体放行

`.gitignore` 现在逐层点名（`!tools/check.sh`、`!tools/hooks/`……），每加一个工具都要回来补两行，忘了就**静默掉队**——它自己那行注释都写着「没列到的会静默掉队」。这跟 ADR 规则漏抄是同一个病：手工同步的状态。

所以改成 `!tools/` + `!tools/**` 整体放行，把这份状态消掉。**但顺序不能反**：`!tools/**` 是无差别放行，`__pycache__` 和 `command-description` 会一起进来。先清，再放。

要清的四样：

| 现在有 | 处置 | 为什么 |
| --- | --- | --- |
| `refactor/` | 删 | README 与 `.gitignore` 都写着「阶段 10 切换之后删掉」，切换已完成 |
| `ab/` | 挪出或删 | A/B 比对车架是防重构搬错的手段，重构已结束 |
| `skill-manager/` | 挪出 | 本机建软链与拉上游，是环境脚本，不是工程部件 |
| `command-description/` | 挪出 | 本地杂物，现在也没被追踪 |

清完之后 `tools/` 只剩 `check.sh`、`test.sh`、`install-hooks.sh`、`hooks/`、`release/`——全是工程部件，这时整体放行是安全的。

挪出去的东西放哪：建议仓库内建一个不进库的 `local/`（白名单默认忽略，一行都不用配），或直接放仓库外。**别留在 `tools/` 里**，否则「只放真工具」这条纪律当场破功。

放行后仍要单独排掉产物：

```
!tools/
!tools/**
tools/**/__pycache__/
tools/**/*.pyc
```

`.gitignore` 里「没列到的会静默掉队」那段警告可以一并删掉——整体放行之后这个风险不存在了。

### 两样已经到期，却还在

`tools/refactor/README.md` 与 `.gitignore` 都写着「重构完成（阶段 10 切换之后）连同本段一起删掉」。而现在：`modules/SSHFleet_Go` 已改名 `_bak`、新工程在跑、`1.0.1` 已发布。

**到期条件已经满足，但没有任何机制去发现它。** 这不是「需要整理」，是「过期了没人执行」——又一个「约定没有人类读者就不会被兑现」的实例。

`tools/ab/` 是同性质的东西：A/B 比对车架是防重构搬错的手段，README 自己写「它是手段，不是目标」。

### 调用逻辑（现状，三条）

```
git commit
 ├─ pre-commit  ─ 暂存区有 .go？没有就 exit 0
 │                有 → WSL → tools/check.sh（gofmt / go vet / 一条结构测试）
 └─ commit-msg  ─ 标题格式；Merge / Revert 放行
手动（人或 AI 执行）
 ├─ tools/test.sh   → WSL → go test ./...     ← 全量测试只在这里
 ├─ tools/release/release.py                   ← 打包发布
 └─ tools/ab/*                                 ← A/B 比对
```

三条要记住的：

1. **脚本里没有一行 AI。** 方向是钩子或 AI 去调脚本，脚本只做确定性判断、不联网、不调模型。它们不会「调用 AI」。
2. **没有任何一条命令能「全部跑」。** `check.sh` 不调 `test.sh`；`pre-commit` 里只跑 `-run TestProjectIsClean` 一条测试，不是全量。所以**闸门绿 ≠ 测试过**——这个空档现在靠自觉。
3. **钩子没装，以上全部不生效。**

### 作废 ADR 的归档位置

放 **`docs/adr-archive/`（与 `docs/adr/` 平级）**，不放 `docs/adr/archive/`。

理由是同一句原则：**能靠路径排除的，别靠内容判断。** 平级之后，任何「扫 `docs/adr/`」的动作天然不命中；做成子目录，凡是 `**/*.md` 的扫描照样进去。编号不动（`0003` 还是 `0003`），索引行保留，要翻直接按编号去 `docs/adr-archive/` 取。

代价：白名单要加两行（`!docs/adr-archive/` 与 `!docs/adr-archive/**`），因为父目录被排除时子文件无法重新纳入。

## 八、CodeGraph 实测（2026-11-19，v1.6.3）

**装了什么**：`npm i -g @colbymchenry/codegraph`；仓库根加了 `codegraph.json`（排除 `_bak`、`build`、`history`、`tools/ab`、`tools/refactor`）；`codegraph init --local-only`。

**索引**：404 个文件、3,788 个符号、9,341 条关系，9 秒建完。`_bak` 确实被排除。`.codegraph/` 自带 `.gitignore` 忽略自己，白名单制下本来也不进库。

**问题出在出口，不在索引。** 默认的 `explore` 一次返回：

| 问题 | 返回 |
| --- | --- |
| 上传回滚从 execute 到 sftp 经过哪几个包 | 656 行 / 5 个文件 |
| rollback 函数被谁调用 | 536 行 / 5 个文件 |

它把命中文件的**整份源码逐字倒出来**（`transfer.go` 这类都是几百行的大文件）。同一个问题用 grep 定位 + 读 30 行就能答，代价差一个量级。**对「少数几个大文件」的项目，这个出口是负收益。**

**可用的那一半是窄命令**：

```
$ codegraph callers rollback
Callers of "rollback" (1):
method client::rollback (go) — internal/execute/run_upload.go:283
method      upload             — internal/execute/run_upload.go:112, 125, 134, 162
```

8 行，拿到的是 grep 拿不到的东西：调用点行号、跨函数的上游。

**结论：留。** 三条理由：

1. 建索引 9 秒、12 MB，不常驻进程，平时不占任何东西；
2. `callers` / `callees` / `impact` 给的是 grep 拿不到的：调用点行号、跨函数上游、接口动态分派；
3. 它只碰代码，不影响本仓文档侧的任何结论。

**怎么用**：不当「AI 会自己用的工具」，当「用之前先敲一条命令」。查询前 `codegraph sync`（实测 4 秒），再 `codegraph callers X`。不起 daemon——为一件低频事常驻一个进程不值。

**不接 MCP**：它的 MCP 会主动注入「优先用 `codegraph_explore`、不要用 grep 复核」。在实测为负的出口上加这条引导，只会把上下文推得更肥。

**过期风险要写明**：没有 daemon，索引不会自己更新。过期之后它给的答案是错的，而且看起来一样可信——**这比 grep 危险**。所以「用前 sync」不能靠记性。若长期用，做一条入口 `tools/cg.sh`，内部先 sync 再转给 codegraph，只放 `callers` / `callees` / `impact`，把 `explore` 挡在外面。这也正好是规范第 1 条的第一次应用：规矩必须配一条可直接粘贴的命令。

## 十、减法（比加法更要紧）

**先纠正一个推论：能机检 ≠ 能从规范里删。**

规范管**事前知道边界**，脚本管**事后必被抓**。把描述删掉，执行者不知道边界在哪，只会反复撞墙再返工——返工的往返本身就是上下文损耗，比读那几行贵得多。机检条目的价值是保底，不是替代描述。

真该减的是另外三类：

### 1. 重复的副本

`AGENTS.md` 的「必读／按需读」与 `个人开发规范.md` 总则的「怎么查」讲的是同一件事，只是详略不同。两份要人工同步，必然错开——与 ADR 规则漏抄是同一个病。

**改法**：分档只在 `AGENTS.md` 里留一份（它是每轮都传的地图），规范里删掉那三行，只留「怎么查见 `AGENTS.md`」。
