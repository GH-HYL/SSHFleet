## 背景

作者最初的直觉是「五种模式各一个包，深模块一路深到底」。问了一句「五个包是哪个站下面的」，问题就出来了：**五种模式从解析到报告全都不一样**，按模式拆包不会住进执行站，而是从解析一路穿到报告——五条纵切插进五站，切出五乘五的格子。

这正是 ADR-0032 备选方案里否掉过的路（「按功能纵切优先」）。否掉的理由当时就写在：纵切切不出「拒绝权只许一处」这种权责边界。

第二个被澄清的担心是「同包里五种模式会互相借参数」。不会——一次只跑一种模式，它们不会同时在场。真正会出的事是另一件：**共用的那段被谁顺手改了，另一种模式跟着变**。而拆包也挡不住它，只会把那段公共代码挪到另一个包里，让五个包都去依赖。

## 决定

**一、模式不聚成包，只在站内分文件。**

第一刀横着（按站，切墙），第二刀竖着（站内按模式分文件，切格子）。**格子不升级成墙**：一个模式的文件散在五个站里，不汇成一个包。谁想「把命令模式整体挪出去」，等于把竖切提到第一刀。

**二、载荷用一个带标签的格子装五种内容。**

信封上那一格写着「这次干什么活」，内容可能是命令原文、脚本内容、本地路径、远端路径、改密的提示词。标签说清是哪一种，五种内容各是各的类型，不合并（ADR-0035 决定二）。标签与内容对不上，由闸门验（ADR-0035 决定七）——契约里不放任何校验函数。

**三、密钥管理独立成包，凭据读取再单列一个叶子包。**

那三条小命令（生成主密钥、看状态、转凭据）不在流水线上，自己一个包，需要配置就在自己包里读自己那一小块。**但「这次是那三条里的哪一条」仍由解析站认出来**——解析是唯一读命令行的地方，塔尖不许自己看参数（ADR-0032 五）。批量改密要用的凭据读取（读主密钥、解密）不归它——那是两边都要的能力，单列一个叶子包，两边都从它取。老工程把这两件事装在一个包里，劈开是为了不让任何一边复制一份。

**它不受五站那套约束**（不切站、不造交接件、不过闸门），**但换两条**：只许往下依赖契约与横切包（凭据包在内）；**五站谁也不许 import 它，它也不许 import 任何一站**。两条路并列，塔尖在分叉点上看一眼选一条——这样它出问题波及不到流水线，流水线也不会长出一条「顺手把密钥生成了」的分支。07 的依赖检查加这一条。见 14 号工单。

**四、塔尖留一个分叉：这次走流水线，还是那三条独立小命令。**

这是塔尖唯一被允许的分支。分不分支这件事只有塔尖知道——站都在流水线里面，看不见「这次根本不进流水线」。另一条路是让解析站认出来、回一张「无事可做」的纸，可塔尖仍要看这张纸才能决定退不退，同一个分叉换了个名字，不如摆明。

## 理由

**为什么不聚成包**：五个包会让每个站对所有下游开五个口子，加一种模式口子再多一个——那是往浅模块走。深模块要的是「一个入口、背后把五种模式的差别吃下去」。作者要的「一路深到底」，靠的是站薄而深，不是把线切细。

**为什么拆包挡不住「顺手改公共件」**：公共件总是要有人提供。拆成五个包，它要么被复制五份，要么被抽成第六个包让五个包都依赖——后者就是抽屉换个位置，而且更难清理。

**为什么密钥管理不进流水线**：它没有「对谁做」这一步（改的是本机的主密钥），也没有「执行多久、进度如何」。硬塞进五站，等于给每一站加一句「如果不是改密钥的话」。

**为什么凭据读取要单列**：不单列就得二选一——要么密钥管理包把它导出给执行站（执行站依赖「工具命令包」，方向别扭），要么两边各留一份（同一件事两个来源）。单列是唯一不复制、也不让站反过来依赖工具包的办法。

## 影响

- **执行站会长成最大的包**。五种模式的活都在里面，共用件也在里面。这是「一改改一条线」的另一个副作用。
- **横切叶子包从五个变八个**（凭据、`message`、`mask`）。ADR-0032 第四条权限表是现行清单；判据（产不产业务数据）没有变。
- **塔尖多三五行分叉**。ADR-0032 第五条「塔尖只搬不做」被放宽了一处，边界写在那条后面。
- **05 号（塔尖多薄）拿到一半答案**：塔尖 = 分叉 + 搬信封 + 退出，没有第三种活。
- **07 号多一条可查**：进入流水线的那一侧，不许出现「工具命令」的分支。

## 代价

- **加一种模式要动五个地方**：契约加一格、五个站各加一块。这就是纵向那条线，作者已认。
- **站内没有硬墙**：同包文件互相全可见，A 模式能看见 B 模式的私有件。ADR-0032《代价》里那条「站内仍可能长抽屉」在这里最具体——只能靠规格审计与 07 号兜，结构上挡不住。
- **塔尖多一个分支**，破了「一行活都不干」的干净说法。
- **凭据读取单列成包**，比老工程多一个包，目录结构多一层要记。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 五种模式各一个包 | 那不是执行站下的五个包，是从解析穿到报告的五条纵切；每个站要开五个口子，越拆越浅 |
| 命令与脚本合包、上传与下载合包 | 与 ADR-0035 同一条理由：现在没有事实支持合并，是预判 |
| 密钥管理塞进执行站 | 它不「对谁做」、没有并发与进度，塞进去每站都要加一句「如果不是改密钥」 |
| 密钥管理包同时提供凭据读取 | 那个包会变成「装两件不相干的事」的盒子，正是 03 号议题要防的抽屉 |
| 让解析站认工具命令、回一张「无事可做」 | 塔尖仍要看这张纸才能决定退不退，分叉只是换了名字 |
