# ADR-0041: 改密那张失败分类表按模式接进判定，配置节名统一单数

- **状态**：已接受（accepted）
- **日期**：2026-11-03
- **决策人**：
  - **开发者明示**（2026-11-03，阶段 05 断点三验收之后，就「改密失败分类要不要接上」的追问）：「不考虑老代码，就一个通用分类，一个改密专用，你打算怎么设计 我倾向就不合并」；「如果非说后面都改密 最后分类事，也是先匹配 step 再匹配 category」；「配置文件 categories 改名 我说的是 sshfleet2，老代码别改」；最后「就按上面讨论的走」。
  - **执行者按此推导**：把「不合并」落成三条可判的口径——专用表只在改密模式参与且排最前、呈现侧按名字查三张表、配置节名改单数但老工程不动。推导的部分在下面《决定》里逐条标了。
- **实施载体**：`modules/SSHFleet2_Go/internal/execute/verdict.go`、`internal/message/stats.go`、`internal/parse/tables.go`、`config/keywords_error.conf`
- **前身**：老版 `internal/verdict/keywords.go` 的 `PrependCategories`（改密专用分类插进通用表最前，`modules/SSHFleet_Go/main.go:347` 调用）

## 背景

判定要认两类东西，分别住在两份文件里：

- `config/keywords_error.conf` —— 整条 SSH 流程的失败分类（连不上、认证失败、会话被拒、命令非 0），全模式共用。
- `config/keywords_passwd.conf` —— 改密这一段自己的两件事：`[[step]]` 认远端在问什么，`[[category]]` 认「改密对话跑了、没改成」算哪一类失败（15 条）。

老版把后者**前置拼进**前者，运行时只有一条有序表。新版（阶段 05）把两者读成纸上两个字段（`Tables.Categories` 与 `Tables.PasswdCategories`），但没有一处读后者——判定、取提示语、判「是否未归类」三处都只认通用那两张。表现是改密失败的分类名回落成报错原文：统计块里显示 `sshfleet.passwd.not_expired: no password-expiry prompt seen`，既不聚合、也没有一句排查提示，还因为「表里查不到这个名字」被归进「未归类」，末尾引导人去改 `keywords_error.conf`——而它登记在另一份文件里。

## 决定

**一、不合并两张表。**（开发者明示）

它们服务的是流程的两个阶段，各有各的维护节奏：通用那张答「这台机器为什么没跑成」，改密那张答「改密对话跑了、为什么没改成」。纸上的两个字段照旧，谁也不吞并谁。

**二、判定处按模式选表，专用表在前。**（推导，依据开发者的「先匹配 step 再匹配 category」）

- 改密模式：候选顺序 = `PasswdCategories` + `Categories`（通用两块的第二组 `ExitCategories` 保持原样，改密没有目的命令的退出码，走不到）。
- 其余模式：只认通用那一组，专用表一概不看。

这个顺序有两处硬要求，也都是可验证的：专用表里「改密未完成」那条必须抢在通用表前面——早收场时工具自己那句报文说的正是这件事；而「连不上」那类远端原文，专用表里没有对应措辞，自然会落到通用表。

**三、呈现侧不认模式，只认名字。**（推导）

「提示语」与「是不是未归类」两处按分类名查表，三张表一起找。名字是全局的键，不因为登记在哪份文件里而改变；让呈现去判模式，等于把判定的知识漏到呈现层。

**四、`keywords_error.conf` 的两个节名改单数。**（开发者明示，范围限定在新工程）

`[[categories]]` → `[[category]]`、`[[exit_code_categories]]` → `[[exit_code_category]]`，与 `keywords_passwd.conf` 的 `[[category]]` 对齐。`modules/SSHFleet_Go`（老工程）不改；因此 `parse/reconcile_test.go` 的配置对账多一张折名表，只在比 `keywords_error.conf` 时把新名折回老名——对账要的是「这份料一个字没少」，不是「名字一辈子不变」。

## 影响

- **配置格式变了**：v2 还没发布，随包一起发即可；旧键名会被当未知字段报出来，不静默忽略。发布之后若要再改名，就得让解析站两个键都认。
- **分类名从此有两种来源**。往后加一条改密失败分类，要知道它落在 `keywords_passwd.conf`；加一条通用分类，落在 `keywords_error.conf`。两处都是单数节名，看名字分不出来，只能看它服务哪个阶段。
- **`Tables.PasswdCategories` 第一次有了读者**。它此前是「解析站填了、没人用」的一格——这一格的存在感来自本条第二、三条，别的地方仍然不该读它。
- **判定只多一处分支**。`failCategories` 是这一段唯一的合流点；呈现侧不参与模式判断，两处各自只是多遍历一张表。

## 复审时该看什么

- 通用表与专用表的关键词有没有开始互相咬：出现同一条原文在两张表都能命中时，「谁在前」就开始影响结果，那一刻要回来重看第二条。
- 「未归类」那栏有没有重新出现改密专用的措辞：出现即说明呈现侧又只查了两张表。
