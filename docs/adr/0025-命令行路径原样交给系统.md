## 零、先说这一条（全文的主心骨）

> **凡是用户输入的命令里带的路径，只要这条路径要由本地解析，就整条原样交给 OS 库——不去首尾空白、不换分隔符、不补前缀、不做 `Abs`、不做 `Clean`、不 `TrimSpace`、不展开 `~`。程序在本地只做两件事：拦（形态不对就报错退出）与报（把 OS 给的原文带出来）。花活只许出现在远端那一侧：远端那条路径本机不加工，只按形态拦；要错就全错。**
>
> 后面九条决定、六条理由、七条备选，都是这一条在不同位置上的展开。读哪一节之前都先回到这段：凡本文件的措辞与它冲突，以它为准。

> **本 ADR 的地位**：**不推翻** ADR-0002（上传的 `-p` 必须绝对、以 `/` 结尾）与 ADR-0023（内联值只写一条）。
>
> **它做的唯一一件事**：把 ADR-0023 决定 5 里「值先原样交给系统」那条，从 `-f` / `-a` 推广到其余命令行路径选项，并写成一条通用规则。

> **用词**：`GLOSSARY.md` 里的「拼接（assembly）」**专指命令拼接**，不指路径。本文说「补齐」时，指「把相对凭据名补到 `secret_dir` 下」。

## 一、背景

命令行一共有八个选项会收到路径：`-s` `-u` `-p` `-d` `-f` `-a` `--convert-secret`，以及打开加密时的 `--change-password`（那时它的值是密文文件路径）。其中四个已经是「原值交给系统」——`--convert-secret`（提交 `48eede7`）、`-f` 与 `-a`（ADR-0023 决定 5）、`--change-password`（它从来没走过规范化）。

剩下四个仍在做字符串规范化：`-s` `-u` `-p` `-d` 一起过 `normalizePath`。它做四件事——去首尾空白、`\` 换成 `/`、盘符归一成 `C:/`、`path.Clean`（保留结尾 `/`）；盘符那一类走单独一支，只做盘符归一（大写 + 去掉紧跟其后的多余 `/`），既不做 Clean、也不补回结尾 `/`。

于是同一形态的路径在不同选项上结局不同：Linux 上 `-s 'docs\a.sh'` 会被改写成 `docs/a.sh` 从而打开，同样的写法给 `-f` 却报「文件不存在」。上传的 `-p` 与 `-d` 本身是远端路径，也被同一份本地逻辑加工。

另有一处口径没写清：`secret_dir` 到底服务谁。手册第 3 节「路径怎么写」说它只对清单里的相对路径生效、配置里的凭据路径一律写绝对；而代码里配置的 `credential.key` 也会走进那个补齐函数（绝对路径原样返回，等于白走一趟），看起来像「配置也参与补齐」。

> 本节现状描述**来自读源码**（`internal/cli/args.go`、`internal/nodelist/precheck.go`、`internal/ssh/sftp.go`）；其中「路径被改写」这件事已在两套 Linux 真机上复现（见「影响」的括号与空白两节）。

## 二、决定

1. **这八个选项的值一律原样交给系统**：不去两端空白、不换分隔符、不归一盘符、不做 `path.Clean`、不拼任何前缀。本地路径交给本机 `os` / `filepath`，远端路径交给远端的 POSIX 语义——程序只当字符串拿着。唯一的动作是**拦**：远端值中间含空格就报错（决定 3），本地不做这条检查。
2. **`-p` 是唯一随模式换库的值**：上传时它是远端目录（远端语义），下载时它是本地目录（本机 `filepath`）。`-d` 恒为远端，`-s` / `-u` 恒为本地；`--change-password` 在打开加密时它的值是文件路径、按本地处理，不开加密时那是密码本身、与路径无关。用反了的地方一并纠正。
3. **远端两个值也不加工**：不去空白、不换分隔符、不 Clean。程序只做一件事——**拦**：值中间含空格就报错（那是「引号漏了 / 参数打错了」唯一能捕捉到的信号）。这条检查**只落在远端两个值上**（上传的 `-p`、`-d`）：本地路径能不能打开由系统回答，比「有空格」准得多，所以本地不走它。两端带空白的值原样交给远端，由远端判断它是不是一个存在的路径。
   用户给的值本身**从不做转义**；拼远端命令时由程序用单引号整体包住（括号、空格都在引号里），这层不动。
4. **`secret_dir` 只服务清单，且只在打开加密时用得上**：第 5 列（私钥，恒为路径）、第 4/6 列（开加密时才是装了密文的文件路径，可写相对名由 `secret_dir` 补齐；不开加密时那两格是密码 / 口令本身，没有路径可补），以及 `-f` 的内联节点记录（它按同一条 CSV 记录解析）。**开关关着时，`secret_dir` 既不参与补齐，也不做任何检查**——它这时没有用途，写没写、写成什么都不该拦人。命令行给的路径、配置文件里的路径，都不经过它。
5. **配置文件里的凭据路径必须写本机绝对路径，不参与补齐**；配置侧不再调用那个补齐函数——它是清单的书写约定，不是路径解析的通用规则。
6. **报错口径分两层**：**参数与前置检查阶段**（本地路径找不到、清单凭据路径读不到）照使用者口径写——我们只写「怎么改」那一句，后面跟系统原文（形如「原因：<系统给的错误>」），**不用报文格式**；`sshfleet.<环境>.<环节>` 那套报文只服务执行阶段（结果判定要按它分类），本轮不动它。清单第 4 列在 `secret_dir` 未配置且写了相对名时，要指出去配置文件的 `[credential]` 段里配 `secret_dir`，与第 5 列同一口径。
7. **传输层把文件落到目标目录时的路径合成维持现状**（上传侧由目录加相对路径，下载侧同理）。它作用于程序自己算出来的路径，不是解析用户给的路径。
8. **不抬主版本**：这次是优化，不是不兼容（作者定）。这条与 CHANGELOG 的默认判据（旧命令跑不通即主版本）不一致，属作者对判据的豁免；落地时记进当天那一段（`[12.0.1]`，修订档），不另起版本号。

9. **清单第 4/6 列的路径解析以 OS 库为核心**（2026-10-26 作者定）：这一列要拼（`secret_dir` + 相对名），但拼的每一步都要落在 OS 库上——
    - **简单处理不交给 OS**：去首尾空白属于「值本身怎么取」，不是路径解析，程序自己做完就往下走；
    - **识别交给 OS 库**：是不是绝对路径由 `filepath.IsAbs` 判，程序不自己看首字符；
    - **拼接交给 OS 库**：目录 + 文件名由 `filepath.Join` 合成，不在字符串上撒 `/`；
    - **拼完必须再交回 OS 库解析一次**：`filepath.Clean` 得出一条完整、规范的路径，此后只交给 `os.Stat` / `os.ReadFile` 消费，程序不再对它做任何字符串加工。
    - **`~` 展开从此取消**：它不属于「简单处理」，也没有 OS 库对应物。清单第 4/6 列与第 5 列一样，`~` 是字面字符，写什么就找什么。

## 三、理由

- **命令行路径已经由 shell 与系统解析过了。** 用户敲的是 Tab 补全出来的那个字符串，引号会不会被解析是 shell 的事。程序再加工一遍，等于给同一个路径造出第二个事实来源——这正是「同一形态两种结局」的来源。
- **加工要求程序知道「这是哪一边的路径」，而这一层最容易错。** 现有几处用反了库：下载侧取远端文件名用了本机语义；默认备注里取本地脚本与上传名、以及脚本后缀识别，又用 POSIX 语义。路径不经手，这类错就没有生长的土壤。
- **`-p` 的含义随模式反转，交给哪套语义必须跟着模式走。** 一旦在解析阶段就把值改写成统一形态，这个反转就看不出来了。
- **补齐是二义性的来源。** 清单里写 `A`，必须能解释成「`secret_dir` 下的 A」；命令行里写 `A`，只能是「当前目录下的 A」。两种解释并存才需要「补不补」这条规则，所以规则只留给有书写约定的一侧。
- **配置里写的是长期备着的东西，本来就该写全路径。** 允许它补，等于允许配置依赖另一个配置项的位置，排查时多一层「它到底解析到哪」。
- **报错要能让人当场改对。** 路径不存在、读不了，系统给的原因比我们猜的准；我们自己加的那一句负责「怎么改」，系统原文负责「为什么」。

## 四、影响

- **三类旧写法由「能跑」变「报错」**：Linux 上 `-s 'docs\a.sh'`；Windows 上把远端路径写成 `-p '\opt\app\'` 或 `-d '\var\log'`；任何路径两端带空白（以前被 `normalizePath` 吃掉，现在原样交出去，找不到就是找不到）。变化落在 CHANGELOG 当天段与手册（按修订档记，见决定 8）。
- **Windows 使用者写远端路径必须用 `/`**。这不是新要求，ADR-0002 已经要求远端目录以 `/` 结尾；只是不再有人替他换分隔符。
- **配置里的 `credential.key` 不再经过补齐函数**，行为不变（它本来就只能是绝对路径），变化的是「配置看起来像参与补齐」这个错觉消失。议题里那条「配置里的凭据路径拼不了 `secret_dir`」由此**不再是缺陷**，而是本决策的形态——别有人再按缺陷去「修」它。
- **清单第 4 列在 `secret_dir` 未配置时的报错会变**：从「密码文件不存在（打开加密时这里填的是凭据文件的绝对路径…）」变成点名 `secret_dir` 与配置文件。既有用例把旧文案写成了预期，随行为一起改。**第 6 列保持不检查**（取不到就留空）：本地判断不了私钥要不要口令，这件事只能交给远端，执行前做了检查也拦不住——这是既有决策，本 ADR 不动它。
- **配置项 `secret_dir` 的校验要跟着开关走**：现在即使关着加密，它仍按「必须本机绝对路径」被校验，写个相对目录会当场加载失败；按决定 4，关着时它没有用途，不该拦人。这条随本轮一起改。
- **`--change-password` 的值在凭据读取处还会被去一次首尾空白**：无论去不去，最终都由 `os` 判断文件在不在，本轮不为它加任何处理，也不把它算作问题。
- **括号与反斜杠：实测结论（Ubuntu 26.04 与 CentOS 7 各跑一遍，SSHD 真机）**
  - Tab 补全敲出来的 `-s a\(1\).sh`，反斜杠**由 shell 剥掉**，程序收到的是 `a(1).sh`，本地找得到、远端也执行成功（远端 `$0` 就是 `a(1).sh`）。双引号形态同理。**用户不需要为括号做任何事。**
  - 只有把带 `\` 的文本塞进单引号（`-s 'a\(1\).sh'`）才会失败，而且现在失败得莫名其妙：`\` 被换成 `/`，路径成了 `a/(1/).sh`。改后按原值判断——Linux 上真存在名为 `a\(1\).sh` 的文件时反而能找到，找不到时的报错也显示原值。
  - 远端路径的括号靠**引号**保护（拼命令时用单引号包裹），加反斜杠是错的：`-p '/opt/my\(1\)/'` 现在被改写成 `/opt/my/(1/)/`，远端必然不存在；`-p '/opt/my(1)/'` 在 SFTP 与 `--sudo` 两条路上都成功。`-d` 同理（下载侧始终过 shell，路径在单引号里，括号安全）。
- **空白：不必由程序处理（实测，Windows + WSL 两套 Linux）**
  - Linux 上 `os` 按字节区分：`a.sh`、`␣a.sh`、`a.sh␣` 是三个不同文件，原始字符串都能精确打开；一旦 trim，三条全塌到 `a.sh`，**读到的是别的文件**。
  - Windows 由 Win32 自己吃掉**尾部**空白（写 `a.sh␣` 落盘就是 `a.sh`），前导空格是真实字符、能精确区分。所以 trim 在 Windows 上既无用也无害，在 Linux 上必错。
  - 远端：纯 SFTP 路径带空格（`"/tmp/a b/"`）能正常落地；走 shell 的那条（`--sudo`）由单引号整体包住，同样成功。**结论：空格原样交出去即可。**
- **代价要说清**：中间空格那条检查仍保留（作者定：漏引号的唯一信号），于是**合法的带空格远端路径进不来**（`-p "/tmp/a b/"` 会被拦）。这是刻意的取舍，不是遗漏；备选方案里有对比。
- **手册有两处口径要统一**：第 1 节正文与 2.1 的表格写「清单第 4 列也必须是绝对路径」，第 3 节又说「相对路径只在清单里能用」。以第 3 节为准，另两处随本次一并改。
- **测试**：在命令行入口（解析 + 合规检查）这一层钉「原值不被改写」与「空格检查只拦中间」两组行为；不新增测试入口，不测私有函数。
- **不影响**：配置里路径的归一规则（`\` 与 `/` 通用、盘符大写、必须本机绝对）照旧；`-r` 是归档目录名不是路径，字符替换照旧。

## 五、明确不做

- 不给旧写法留兼容层（不做「先按原值试、失败再试改写后的形态」）。
- 两端空白一律不处理、也不拦（远端只拦**中间**的空格）。
- 不把补齐借给命令行或配置文件，也不为「命令行也能写短名」另开口子。
- 不在本决策里改 `-r`、配置路径的归一规则、产物的目录结构。
- 不动传输层的目录与相对路径合成（决定 7）。

## 六、备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 保留 `normalizePath` | 它正是「同一形态两种结局」的制造者；且让程序必须知道哪一边的路径该用哪套分隔符，现有那几处用反了库就是证据 |
| 统一改成全部交给 POSIX 语义 | Windows 本地路径会失效（盘符与 `\`）；本地路径必须交给本机 `os` / `filepath` |
| 只改本地两个（`-s` / `-u`），远端两个继续加工 | 同一个 `-p` 在两种模式下会有两种行为，比现状更难讲清 |
| 本地路径也去首尾空白 | 去空白会改指向：`-s " a.sh"` 被当成 `a.sh`，两个文件都在时打开的不是指的那个。实测：Linux 上三个文件会全塌到一个 |
| 把中间空格的检查也去掉 | 它确实挡掉了合法的带空格远端路径（`-p "/tmp/a b/"`），但它是「引号漏了」唯一能捕捉的信号，作者要求保留。漏引号的另一种形态（参数被空格切开）已由「多余的参数」拦下，但在 `-p "/tmp/a b"` 这类整体带引号又写错位置的情况下，只有这条能发现 |
| 让配置也补齐 `secret_dir` | 配置必须写绝对路径，补齐对它没有意义；允许它补等于让配置依赖另一个配置项的位置 |
| 抬主版本 | 作者判定这是优化，不抬（决定 8）。代价是旧写法失效却没有版本号信号，只能靠 CHANGELOG 条目与报错文案补 |

## 七、复审

> 本节只放两样东西：复审时要守的方法纪律，以及哪些结论还没被证实。触发条件与待办属于工单，不写在这里。

### 7.1 方法纪律

1. **判断「路径有没有被改写」不能在 Windows 上看结果。** Windows 的 `os` 同时认 `\` 与 `/`，`-s A\b.sh` 与 `-s A/b.sh` 都能打开，「原样」与「被改写」在那里看不出差别。要么在只认一种分隔符的平台上验，要么直接断言进入程序的那个字符串。
2. **「同一个值在不同模式下」必须分开判。** `-p` 上传是远端、下载是本地；拿上传模式的结论去推下载模式，会得出相反的结论。
3. **报错文案的改动要连用例一起看。** 本仓库有把现状写成预期的用例（第 4 列的「密码文件不存在」），改行为而不改用例，等于留了一条反向的锁。
