# helper 替测试喊失败，也要入指纹

- **状态**：已接受（accepted）
- **日期**：2026-11-09
- **决策人**：开发者。原话：「都按你的建议走」。
- **前身**：`ADR-0045` 决定二只堵了「测试体里的断言被掏空」这一层。

## 背景

`ADR-0045` 落地后，42 条红线里只有 `TestCheckDepsClock` 的断言数记 0。查下去，它整条测试只有一行：

```go
wantOne(t, CheckDeps(loadFixture(t, "clock")), ClassDeps, "internal/parse/run.go", "time.Now")
```

四句 `t.Fatalf`／`t.Errorf` 全在 `internal/guard/helpers_test.go` 的 `wantOne` 里——判「正好一条违规、位置对不对、话术里有没有 `time.Now`、四样写全没」。同文件里 `loadFixture` 也在替测试喊失败（样本读不到时 `t.Fatalf`）。

后果：把 `wantOne` 里那四句删掉、或把 `!=` 改成 `==`，三条调它的红线一起变松，而指纹（符号集 ＋ 次数）一个都不动。掏空断言有上下两层，`ADR-0045` 只堵了下面那层。

## 决定

**一、helper 登记。** `guard` 包里所有**非 Test 开头的顶层测试函数**，函数体里对 `*testing.T` 喊失败的调用点要登记成一条；三种情况报红：喊了但没登记、次数对不上、登记了但函数已经不在。

**二、只登记「喊失败」的 helper。** `inClass`、`fixtureRules` 这类纯读取／纯判断的不登记——掏空它们不会让测试变绿，只会让它算错，那由测试自己的断言接住。

**三、口径与 `ADR-0045` 决定二一致**：只数调用点（`Fatal`／`Fatalf`／`FailNow`／`Error`／`Errorf`／`Fail`），不数条件表达式。

**四、登记表属检查本体**：改它与改红线区同程序（`ADR-0032` 更新记录第 7 条「单独点头」档）。

## 理由

**为什么登记而不内联。** 把 `wantOne` 拆回三条测试，等于把同一段断言抄三遍——审计 04 把「重复」列为四类形态里的第一类，这个交换不划算。

**为什么要扫「没登记的」而不只钉现有的两个。** 只钉 `wantOne` 与 `loadFixture`，等于承认「以后新增的 helper 是盲区」。扫全包、要求登记，顺带把「新增一个 helper 来绕开指纹」这条路也堵上。

**为什么不管纯判断 helper。** 判据是「掏空它之后，测试还会不会绿」：`inClass` 返回错，断言仍然会发现；`wantOne` 不喊，断言就没人喊了。

## 影响

- 名单旁边多一张小表：`loadFixture` 1 次、`wantOne` 4 次。
- 以后写新 helper，只要它喊失败，第一次跑会红一次，补一行即可。
- 与 `ADR-0045` 的两张表合起来，`go test` 能看见四种拆法：删入口、删测试、掏空测试体、掏空 helper。

## 代价

- 登记表要人维护，新增 helper 会红一次。
- 只数调用点，所以把 helper 里的 `!=` 改成 `==` 仍然看不出来——那是断言**内容**的强弱，与 `ADR-0045` 同一层局限。要再深就得读断言文本，成本不成比例，不做。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 把 `wantOne` 内联回三条测试 | 同一段断言抄三遍，重复密度上涨，改一处要改三处 |
| 只钉 `wantOne`，不扫全包 | 以后新增的喊失败 helper 仍是盲区，等于把洞换个位置 |
| 连纯判断 helper 一起登记 | 它们不喊失败，掏空只会算错、不会变绿，登记了只是负担 |
