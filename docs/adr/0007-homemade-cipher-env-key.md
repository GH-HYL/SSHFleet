# 凭据加密：自建流密码 + 环境变量密钥

威胁模型是"凭据文件被拷走后被人还原出明文密码"，不防 root 权限、不管内存明文。`high` 密码安全等级下，凭据文件用纯标准库自建的流密码（SHA256 密钥流 + XOR + HMAC 完整性校验）加密，解密所需的**主密钥**持久化在系统环境变量 `SSHFLEET_KEY` 中（Linux 写 `~/.bashrc`，Windows 用 `setx` 写注册表），与凭据文件物理分离。

## Considered Options

- **AES 加密库（cryptography / pycryptodome）**：工业强度，但违背工具零第三方依赖的硬约束，否决。
- **Windows DPAPI（ctypes 调系统 API）**：无依赖且绑定当前用户，但仅 Windows 可用，工具需跨平台，否决。
- **OS 凭据管理器（keyring 库）**：体验最好但同样是第三方库，否决。
- **主密钥存密钥文件**：免配环境变量更省事，但整个凭据目录被一起拷走时密钥随文件一同泄露，分离失效，否决。

## Consequences

- 单独泄露凭据文件或单独泄露环境变量都无法还原密码；两者都拿到才能解密。
- root/Administrator 权限可同时读到文件和环境变量，此方案明确不防该层级。
- 键盘交互式输入的密码是明文原文，不落盘、不走解密路径，不受等级影响。
- 自建流密码强度取决于实现正确性而非经受了公开审查的算法，接受这一折扣换取零依赖。
