# ADR-0023: 内联值只写一条记录，`-f` 与 `-a` 不再支持任何换行写法

- **状态**：已接受（accepted）
- **日期**：2026-10-21
- **决策人**：作者（2026-10-21 本轮对话）
- **实施载体**：`docs/issues/2026-10-21-1304-内联值只写一条/spec.md`

## 背景

`-f`（节点清单）与 `-a`（代填）共用一种取值形态：给一个 CSV 文件路径，或直接写同样格式的内联文本。内联要写多条记录，就得有一个「行分隔」记号。这个记号换过两次：

1. 起初是字面 `\n`（反斜杠 + n），装载时无差别替换成真换行。Windows 路径里 `\n` 是常态（`D:\new`、`D:\nodes`、`D:\nginx`），路径被切断、报错却指向 IP 格式；`-a` 侧更彻底——代填内容里的换行与行分隔抢同一个记号，内联里根本无法表达带换行的内容。见 ADR-0020。
2. 2026-10-19 改成 `;;`，字面 `\n` 回到普通字符。

2026-10-21 排查「`-f 'ip;;ip'` 不识别双 IP」时把这条路重新走了一遍，看到三件事：

1. **手册教的裸 IP 多台写法在 `-f` 侧跑不通（带完整列的多台能跑）。** 启动时的参数检查判断「这是文件还是内联」时，按逗号切出首字段再看它是不是 IPv4；`ip;;ip` 里没有逗号，整串被当成一个字段，于是报「文件不存在」——手册里那条三台示例（`-f "192.168.1.10;;192.168.1.11;;192.168.1.12" -c "uptime"`）照抄就失败，而 `ip,22,root,pw;;ip,22,root,pw` 这种首字段是 IP 的写法照旧能跑。`-a` 侧的识别条件又是另一套（值里含逗号），两处各写各的。
2. **内联里同时存在三套「行」的说法**：字面 `\n`（曾是分隔）、`;;`（现在是分隔）、真换行（bash 的 `$'…'` 能传进来，解析也认它）。讲清哪套生效、哪套被拒，比记一个记号更难。
3. **`;;` 的冲突面没有消失**：密码或触发词里真写 `;;` 就会被切行，只能靠「这类内容走文件」兜底。

## 决定

1. **内联值只有一条记录。** `-f` 的内联值是一台节点，`-a` 的内联值是一条代填。
2. **内联里没有任何换行写法。** 字面 `\n` 是普通字符，`;;` 是普通字符，真换行不被解释为分行——**直接拒绝**，不静默当分隔。不设转义，不设第二个记号。
3. **多条一律走 CSV 文件。** 多台节点、多条代填、内容里要含回车的代填，都写进文件。
4. **文件侧的解析口径不变。** `#` 注释、空行、BOM、双引号、变长列这些规则原样保留——它们只在文件里成立，因为只有文件有「行」。
5. **内联识别收口到一处，次序固定。** 值先**原样**交给系统按路径解析——不做 `\`→`/` 的替换、不去空白、不拼任何前缀；不是已存在的文件，再看它能不能当**一条**记录读：`-f` 看 CSV 读出的首字段是不是 IPv4，`-a` 看值里有没有列分隔符（含逗号才可能同时给出内容与触发词）；两者都不是，就报「文件不存在」并给出该侧固定的那一句写法提示。`-f` 与 `-a` 共用这一个判定与这套报错形态，两侧只提供各自那一条判据；这个判定只在合规检查阶段走一次（`-f` 的来源也在这里落定，不在解析参数时先判一遍）。上一轮那条缺陷的根因（两套各写各的启发式）随之消失。

## 理由

- **二义性无解，只能让它在内联里不存在。** 只要记号是 `\n` 这两个字节，字段里合法的 Windows 路径就与它同形；任何「收紧规则」或「先猜一种解释」的做法，在代填侧（内容可以是任意文本、没有 IP 这类锚点）都必然存在两种解释都合法、只能静默选一边的输入。让内联不含记录分隔，问题从根上消失。
- **一句话能讲完，才守得住。** 「内联写一条，多条写文件」是一句规则；「多行用 `;;`，但 `;;` 出现在密码里就自求多福，真换行算不算要看你用哪个 shell」不是。
- **收窄的代价落在少数场景。** 临时多传几台要多建一个文件；而多台场景本来就该有清单文件，内联的本意是「临时测一台」。
- **顺带收口两处分叉。** 识别层统一之后，`-f` 与 `-a` 不会再因为各写一套判断而各自出错。
- **路径这件事本来就不该由程序加工。** 命令行给的路径一律原样交给系统（不拼、不展开、不换分隔符），判定里只剩「系统找不找得到」，内联判定排在它后面。次序固定，报错也就只有一种形态，不必为「看起来像路径」「看起来像多台」各写一套话术。

## 影响

- **使用者可见面**：手册、帮助、常见问题、示例、README 里所有「内联多台 / 多条」的写法改为「写文件」，内联只演示一条；CHANGELOG 已封口的旧段不动，改动当天在新段记最终形态。这是不兼容改动——照着旧示例写的脚本会失败，按 CHANGELOG 的判据要抬主版本。
- **报错文案**：判定失败一律沿用既有形态——「`-f` / `-a` 参数指定的文件不存在」加该侧那一句写法提示；内联值里出现真换行时单独拒绝，原因只说一句「`-f` / `-a` 的内联值里不能有换行：内联只写一条」，去路放在下一行（「把节点 / 代填写进 CSV 文件，再用 `-f` / `-a` 指向它」），两处不重复同一件事。`;;` 与字面 `\n` 不被识别，也**不改变任何提示**：提示是固定的那一句，不因值里出现 `;;`、`\n` 或看起来像几台而变化。`-f` 那句提示里的「几台」改为「一台」，与「只写一条」对齐。
- **启动时的参数检查**：`-f` 与 `-a` 的「是不是文件 / 能不能当一条记录」合成一处，次序固定为先路径、后内联、最后报错；命中文件之后路径原样使用，不再做字符串规范化。
- **装载**：内联不再做任何整备（原来那步替换退役）；文件侧保持原样。
- **脱敏跟着同一把尺子**：日志、确认屏与归档报告里，内联清单的第 4 段密码、第 6 段口令整段换成 `****`。判断「这是不是一条内联节点」只此一处（`common.LooksLikeInlineNodeRecord`），取值判定与脱敏都调它——否则会出现「放行认得出、脱敏认不出」，密码明文落盘。打码按 CSV 字段切、按 CSV 写回，Excel 导出的带引号单行与引号里包着逗号的值都切不错段。
- **既有能力回归**：文件侧多行、带真换行的代填内容不受影响，需有用例钉住。
- **历史文档**：ADR-0020 只作沿革；`docs/issues/2026-10-19-0024-内联路径误当换行/` 已完成，其结论由本决策与后续议题接替。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 维持 `;;`，只把 `-f` 侧的识别修对 | 修完能跑，但三套「行」的口径仍在，`;;` 与密码 / 触发词的冲突仍在，识别层仍是两套 |
| 回到字面 `\n`，靠转义（`\\n`）区分路径 | 要求 Windows 用户改写路径，等于给一侧开特例；与「内联与文件内容完全一致」的口径冲突 |
| 回到字面 `\n`，靠「先试一种解释、不合法再试另一种」 | 代填内容没有锚点，必然存在两种解释都合法的输入，只能静默选一边，错得不报错 |
| 只认真换行，不设任何记号 | cmd 传不出真换行，内联多台在那半边彻底消失；各 shell 写法不一，复制粘贴失效 |
| `;;` 与真换行都认 | 内联多一套要解释的写法，与「一条」的简单口径相反 |
| 值里出现 `;;` 就提示「内联只写一条」 | `;;` 只是普通字符，靠它触发提示等于把它变回记号；而且路径里也可能出现两个分号，提示会打到不相干的人身上。提示只留「真换行被拒」这一处触发点 |
| 另立 `-F` 选项专门收内联多行 | CLI 形态变大，且不解决记号本身的二义 |
