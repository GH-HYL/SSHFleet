# ADR-0062: 二十九句拒绝不合成一个构造点

- **状态**：已接受（accepted）
- **日期**：2026-11-18
- **决策人**：
  - **作者明示**（2026-11-18）：「都得做，无所谓先后，开始吧，授权开工，你根据工作合理安排一下」——交接里 D 节的前提是「先建模，结论若是不该合就写 ADR 收工、不开工」。
  - **执行者实测**：二十九个函数的参数形状与调用点逐个数过（下表），结论是「共性都在版式上，不在事实上」。
- **前身**：ADR-0034 决定三（拒绝只住闸门）、决定八（闸门不写话）；ADR-0028 决定一（话只在构造点成形）；ADR-0052 决定六（三句齐）

## 背景

`internal/message/refuse.go` 里二十六个、`confirm.go` 里三个（`RefuseEnvelope*`），一共二十九个「拒绝」构造点，每个返回一句给使用者看的话。数量本身不是问题，问题是它们**看起来**是同一件事：都是「套外壳 + 一段正文」。于是排期里挂着一条：要不要收成一两个构造点。

这次只做建模：抽共同的事实形状，判断该不该合。守的前提是 ADR-0034 那两条——拒绝只住闸门（造不出这个类型就拒绝不了），话只在构造点成形。

## 建模：二十九个的事实与版式

**先说已经抽出来的三样**，它们都是版式，且都已抽出，不必再动：

- 三句外壳（`HeadParse`／`HeadCompliance`／`HeadDangerRules`），由 `shell` 套上；
- 两段版式 `problemhint(问题, 提示)`——十八处；
- 三段版式 `problem(哪一格, 为什么, 下一步)`——一处（`RefuseManifestMissing`，ADR-0052 决定六）。

**再说剩下的**。按事实形状分族：

| 族 | 事实是什么 | 个数 | 措辞是否一种 |
| --- | --- | --- | --- |
| 选项不认识／缺值 | 一个选项名 | 2 | 否（「不认识的选项：x」与「选项 x 缺少值」） |
| 多余位置参数 | (主选项名, 多余段原文) | 1 | — |
| 数值选项取值不对 | (选项名, 主语类别, 原文) | 1 | — |
| 模式零个／多个 | 无 | 2 | 句同、提示不同 |
| 两个选项互斥 | 两个选项名 | 10 | **否，四种**：「不能和 x 一起用」「不能和 x 一起使用」「只能和 x 一起使用」「不能搭配 x 使用」，其中一句还带括注 |
| 必填项缺失 | 无（主语写在句里） | 3 | — |
| 给了但空 | 无 | 2 | — |
| 远端路径形状不对 | (选项名, 是什么, 原文) | 3 | — |
| 长度／解释器 | 三个整数 / 一个字符串 | 2 | — |
| 信封那一组 | 标签表／期望／实得 | 3 | — |

**调用点**：二十九个里二十七个只有一个调用点（`RefuseUnknownOption` 与 `RefuseNoShellWithOtherMode` 各两处），全部在解析站与闸门。

## 决定

**不合。** 二十九句原样留着，一个字不改，也不再抽公共构造点。本轮不写代码。

## 理由

**一、共性在版式上，而版式已经抽完了。** 剩下能抽的只有「哪一格、哪句问题、哪句提示」这三格的内容——那不是事实，是文案本身。把文案搬进表，字面量一个不少，只多一层查表。

**二、措辞不通用，合起来必须带一格「用哪套话」。** 互斥那一族十个，事实同样是（两个选项名），措辞却有四种。要合成一个构造点，就得给它加一格措辞类别或几个分支——那只是把今天分散在十个函数里的 `switch` 搬进构造点，读的人还要多跳一层。

**三、文案是行为。** `refuse.go` 的头注释写着「改一个字都是改行为」。表驱动的写法让「改一句」变成「改一行数据的某个字段」，看着更省事，实际是把「改话」的门槛抹平了——挡人的那点摩擦在这里是好事。

**四、合了会让一种错法变成编译得过。** 「拒绝」这个类型的价值在 ADR-0034 决定三：造不出来就拒绝不了。今天闸门要拒哪一句，必须先 `import` 那个函数名；合成 `Refuse(kind)` 之后，闸门能造任意一句——写错枚举值的后果从「编译不过」退化成「屏上换了一句」，而那正是这份文件里最不该出的错。

**五、二十七个只有一个调用点。** 一个只用一次的句子，包装成可复用的构造点，换来的是「以后可能复用」——`docs/agents/按需-写代码.md`「代码工程」明确不许为这种理由预留。

## 影响

无代码变化。本条的作用是：把「该不该合」这个问题一次答完，下一轮排期不必重新想；谁再提「二十九个太多」，先读这张表。

## 代价

- **导出面仍是二十九个。** 这是有意留着的：一个含义一个名字，读调用点不必查表。
- **新增一句就要加一个函数。** 这是这套写法的正常成本，不是缺陷。

## 退路

不涉及代码，无需退路。真要合，重新开一条 ADR，说清是哪个前提变了。

## 什么条件下该重开

三条任一条成立时，这个结论要重看：

1. **第三个地方也说同一批话**（今天只有解析站与闸门）。那时要解决的是「同一句话两处要一致」，与「二十九个要不要合」是两件事。
2. **文案要从配置或语言包来**。那时需要的是文案表，但落点仍应是「一个场景一个键」，而不是把构造点合成一个。
3. **一族的措辞被统一**（例如产品口径决定所有互斥都说「不能和 x 一起用」）。那时互斥那一族的事实形状才真的变成了（两个选项名），合成才有东西可合。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 合成一个 `Refuse(kind)` + 一张表 | 闸门能造任意一句，错法从编译不过退化成屏上换一句；且措辞仍需一格分支 |
| 只合互斥那一族（十个） | 四种措辞要变成参数或分支，剩下九个函数还得各留一个包装，收益只在一个函数体少两行 |
| 把正文拆成「事实 + 模板」两段 | 模板与事实的边界在中文语序里切不干净（「-p 参数不能搭配 -c 或 -s 使用」的主语是多词），切出来是给人看的假抽象 |
| 原样不动（本条） | 采纳 |
