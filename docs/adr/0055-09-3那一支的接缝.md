# 09-3 那一支的接缝：进程出入口＋源码形状

**状态**：已接受（accepted）
**日期**：2026-11-16
**决策人**：开发者——原话「接缝的事情我不懂」，把这件事交执行者定（2026-11-16 15:31：「都你决定」）。**本条自「背景」起全是执行者的判断**，不是他的原话。

## 背景

`7ceeeb6` 定了「执行期日志开不出来就停」：塔尖那一处原先吞错（`lerr` 丢掉、不留痕），现在与执行站同一个口径、都停在启动段。改动本身没有测试盖住——塔尖的收场是 `fatal` → `os.Exit`，不在现有接缝上。规范三.3 要求「没说定就别写」，所以先定这一条。

## 决定

**不新造接缝**，用现成的进程出入口，判据分两层：

1. **行为层**（`TestExecLogCannotOpenStopsAtStartup`）：起二进制，用文件系统让执行日志打不开——归档目录名是「秒级时间戳_模式_备注」，所以先把接下来几秒的目录全建好，每个里面放一个同名**目录**顶住 `SSHFleetExec.log`，`os.OpenFile` 打不开一个目录。然后判：退非 0、那一屏带 `[ERROR]` 与「建执行期日志失败」、本次归档目录里没有 `report.txt`／`terminal.txt`。
2. **形状层**（`TestExecLogInitFailureEndsAtFatal`）：解析 `main.go`，判 `log.InitExec` 那一句紧跟着的失败分支必须是裸的 `<变量> != nil`，且块里必须有一条 `fatal(...)`。

## 理由

- **行为层单独不够**。两处开执行期日志现在是同一个口径，屏上的话一字不差；而 `log.Logger` 的方法对 nil 是**空动作**（`Close` 的注释里写着这一条）。于是把塔尖那一支改成「记一句就往下走」，进程层看不出任何区别——实测：把 `if lerr != nil` 改成 `if lerr != nil && false`，行为层那条**仍绿**，因为执行站接着也会在同一个路径上打不开、说出同一句话。要判「塔尖那一支没被吞」，只能判它长什么样。
- **不给塔尖加可替换的退出口子**。把 `os.Exit` 或 `fatal` 抽成可替换的函数值，正是 01-S4 记过的那种写法：检查器看不见，类三形同虚设。
- **不给生产代码加「只在测试时」的钩子**。那种钩子会跟着二进制一起发出去，代价比这一支没有测试更大。
- 形状判据在本仓有先例：类七那一族全是「解析源码、判形状」，这里只是把它用在塔尖自己身上（自定义区，文件名不带 `redline_` 前缀，不进红线名单）。

## 影响

- **代价写在这儿**：形状判据钉的是「那句 `fatal` 在不在、条件裸不裸」。哪天有人把 `fatal` 包进一个包装函数、或把条件写成 `errors.Is(...)` 之类，这条会红——那时要连判据一起改，不是绕过它。
- 行为层那一条会起进程、编二进制，与 `expect_order_test.go` 共用 `orderBinary`／`stageOrderDir`，不另造一套场景。
- 行为层按秒预建目录，跨秒不命中就会退化成「执行站那一处先撞上」——仍是红（话一样），所以不会假绿。

## 备选方案

- **`TestMain` 里换掉退出函数**：`TestMain` 的收尾本身就是 `os.Exit`，而类三对 `_test.go` 不豁免；同一份文件里既禁又用，判据会自相矛盾。
- **环境变量钩子**（`SSHFLEET_TEST_FAIL_EXECLOG=1`）：最省事，但它会跟着交付的二进制走，且给了使用者一条能把工具弄停的口子。
- **只做行为层**：实测不成立，见上。

## 复审

**未证实**：行为层只在 Windows 本机跑过；POSIX 侧未跑（同一份代码，落点与权限语义不同，理论上更宽松）。
