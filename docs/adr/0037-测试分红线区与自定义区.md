# ADR-0037: 测试分红线区与自定义区，红线区只放结构

- **状态**：已接受（accepted）
- **日期**：2026-11-01
- **决策人**：以下按**授权来源**分列

## 背景

这次重构的前提是「行为一点不变、结构全换」。而规范三.3 有一条反向判据：**重构后行为没变、测试却红了，说明测错了地方。** 两条放在一起，接缝选错就会集体变红，变红就被当成噪音删掉——等于没有测试。

老工程的现状（现数）：51 个测试文件、413 个测试函数、11688 行，散在 12 个包里，**全是包内测试**；今天没有任何一个测试从程序外面敲门；「行为没变」唯一被证明过的一次是手工 A/B 逐字比对（ADR-0013，2026-10-07），不是常态。

**测试压不住腐蚀，这是天性**：它只看跑出来的结果对不对，不看这段代码该不该待在这儿。所以本条不承诺「测试保住框架」，它只把测试分成两堆——一堆只放结构、熬得住重构；一堆随便写、跟得上需求。

## 决定

**一、分两区，判据一句话：一条测试红了，先问「是结构被人动了，是需求变了，还是环境没起来」。** 前两者进两区；第三者两区都不进，也不许按需求变更归档。**第三桶是测试层的桶**：容器没开、网络不通、超时抖动——程序自己遇到远端连不上，仍按 ADR-0034 算一台的连接失败，与本桶无关；本桶只有一条处置，能修就修，修不掉说明那条测试不该要机器（打标，无机器时跳过，跳过不算绿）。

**二、红线区只放结构，一条行为断言都不放。** 只收机械判得出来的约束：07 那五类，加「测试站在哪儿」这一类。断言只碰**纸的形状与流向**（字段在不在、谁填的、下一站读不读得到、编译过不过），不碰**值算得对不对**。混进行为，改一个小需求就得改红线，红线就被拖下水了。**红线越纯，越不用动。**

**三、红线区只许站三种口子。** 塔尖的进程出入口（起二进制、喂参数、看产出——唯一允许看内容的地方）；站的入口（递一张纸、收一张纸）；横切包的那一件事（叶子包只有一个公开面，测它时 import 的就是它）。

**判据是可判的那一版，两半，都按文件讲**：

- **import 白名单**：一个红线测试文件只许 import 标准库、契约包，以及被它钉的**那一个包**——站包或横切包，二选一；import 第二个被测包、或 import 两区共用的假件包，即报。
- **出口白名单**：每个站包只许导出**一个函数加一个类型**（形状见本段之后的白名单段）。

**红线测试不享 `_test.go` 的依赖方向豁免**，否则它是全工程唯一不被依赖检查看的代码，有人在里面按序调五站就是一个第二个 `main`。

> 原判据「测试里出现被测包私有符号即报」作废：住单独包的红线区跨包引私有符号本来就编译不过，报不出东西；真正的越界方向是反的——为了让红线够得着而把站里的内部函数导出。

**所以出口也要白名单：每站只许导出一个函数加一个类型**——入口函数，和替身插口的类型（它是入口的参数，字段只许是函数）；纸的类型在契约包，不算站的导出；多一个就红。**出口仍然只有一个**：替身插口是往里递的东西，不是往外给的东西，与 15「执行站对外只有一个口子」不冲突。**例外一个，由本条规定**：ADR-0034 要塔尖认出「拒绝」，闸门包必须导出拒绝的类型，白名单点名放行它。

**四、红线区住新工程里单独一个包，与结构检查同住，不塞进任何一站。** 它要把全工程摊开数，住进某一站就破了那一站的单向。

**五、改红线区的程序比改约束类文件更重。** 默认不能改；确需改，先单开议题、再写 ADR，写明是哪个条件变了——工程设计变了，还是代码复杂度变了。只问一句「能不能改」不算。红线名单与每条的指纹同住一处，对不上 `go test` 直接红。**指纹钉两样、不钉字节**：测试名，加这条测试**直接**引用到的生产符号集合（经测试文件内 helper 间接引用的不算，`gofmt`、改注释、重排语句也都不算）。**新增一条不算改；删掉、改名、缩窄引用面算改。**

**六、自定义区跟着被测包走，怎么顺手怎么写。** 唯一硬规矩：**不许与红线区共用假件包**——红线自己要用的假连接、假时钟放它自己的目录里，各写一遍，认这笔重复。老工程那 413 个测试不搬。

**七、A/B 逐字比对不进两区。** 它不是常驻测试，是切换那天的一次验收（归 09）。归一化抹掉了什么必须写明，并留一条不归一化也应当一致的路径当哨兵——**细则（抹哪几样、比哪几份、哪三条路径当哨兵）见 08 号答案第五节**；ADR-0018 记过归一化把漂移一起抹掉的教训。**中段是认下的空白**：从建站第一行到新工程能整条跑起来之前，没有任何东西能证明行为没变——红线区不管行为，自定义区跟着新代码长，A/B 没东西可比。写在明处，不当漏项。

## 理由

**为什么必须分两堆，而不是定一个接缝。** 两个目标方向相反：红线要熬得住重构（结构随便动它不许动），自定义要跟得上需求（改一次就得改它）。钉在同一个口子上，必然有一头坏死——要么红线被需求拖着改，要么自定义测试把结构钉死。老工程今天就是后者：413 个测试全伸进包里，动一下结构就集体红。

**为什么「改红线」要议题加 ADR，而不是点头。** 框架不是「我现在喜欢这个样子」，它是多个条件同时成立时的平衡点：工程设计压着，代码本身的复杂度也压着。条件变了平衡点才该移，而「哪个条件变了」必须写下来——不写，下一个人只会看到「有人改了一条红线」，看不出为什么。这也正是 ADR 的三道门槛（难回头、没上下文会困惑、真做过取舍）同时成立的地方。

**为什么红线区的边界要机械核，而不是靠约定。** 约定挡不住省事的路：AI 想测一个内部函数，最省事的做法就是在红线区私开一个口子。留着这条口子，红线区三年后就会变成第二个老测试集。要它「做不到」，就得扫符号。

**为什么自定义区的质量不管。** 一个测试写歪了不影响业务，代价落在「改坏了自己那一轮不知道」，届时的返工就是账。作者明示这一档不拦。

## 影响

- `docs/个人开发规范.md` 增一.1 第七条（改红线走议题加 ADR）与三.3 的两区规则。原文「测试只写在预先说定的接缝上」不动，本条补的是取接缝的办法。
- 07 的检查表要加第六类（红线区只许站三种口子），07 自己写着「加一类要开发者点头」——本次点头已记在决策人栏。
- 新工程动工时多两样东西：红线区的那个包，和一份红线名单加指纹。
- 老工程 413 个测试不迁移；纯算的那部分（显示宽度、脱敏、危险规则）按横切包的口子重写。

## 代价

- **红线区管不了站内。** 站等于一个包，包内文件互相全看得见。「站里自己攒一个抽屉」既测不出也扫不出，只能靠规格审计与人读。ADR-0032《代价》认过同一条。
- **「结构动了还是需求变了」这句话本身要人判。** 它是一刀切的问法，不是自动判据；判错一次就是一条红线被当需求改了。
- **指纹让每次合理修改多一步。** 改一条红线要同时动测试、名单、指纹，缺一样红着。这是故意的：留痕的代价。
- **放弃一份现成的行为网。** 413 个测试不搬，新工程开工那天测试覆盖率接近零，靠红线区加逐轮补的自定义区慢慢长回来。
- **第六类检查比现有五类重。** 它要认「这个 import 属于哪个包」，不是数调用形状。
- **这套东西对「行为没变」几乎没有贡献。** 红线区管的是结构不许变样；行为对不对只有 A/B 与自定义区管。别指望它顺手把行为钉住。
- **红线测试是外部测试包。** 住单独一个包，就碰不到站里的私有符号，也造不出站内的假件；能造假的只有站收下的那个替身插口。
- **站只许露两个名字，是有代价的。** 站内想给别处一点只读信息，得从入口递出去或塞进纸里，绕一条线；每加一个导出名都要走审批，容易演成「先加上再说」。04 的摊法要跟着核：老包里凡是「顺手多导出一个函数」的地方，摊进站时都得想清楚它走哪条路。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 一刀切封死所有测试的口子（我上一轮的提法） | 与「AI 怎么写顺手怎么来」打架。每条测试都要先问站哪个口子，那不是约束，是添堵；而且需求一变就得改口子 |
| 只留进程出入口 | 最稳但最粗：红了只知道哪条路坏了，不知道哪一站；要机器、要归一化；老工程 413 个细粒度校验全废 |
| 红线区混进行为断言 | 改一个小需求就得改红线，红线被拖下水，几次之后成普通测试 |
| 老测试照搬（同包改包名） | 等于把老的分包边界一起搬进新工程——而那正是这轮要拆的 |
| 判据写成「测试里出现被测包私有符号即报」 | 住单独包的红线区跨包引私有符号编译就不过，这条永远报不出东西 |

## 尚未定的

- **出口白名单的例外清单，等实施时读代码定。** 现在只放行一个（闸门的拒绝类型）。还可能冒出第二个、第三个（比如解析站要把选项清单交给帮助文本），都要等站真写出来、读到那一段代码才知道——**形状现在定，清单那时定**，不是拖，是这个顺序本来就该这样。
- **红线区今天到底装哪几条。** 07 五类加测试位置是能装的；「更窄」（两张纸比宽窄）、「塔尖不许拼字符串」两条仍暂缓，要不要进红线索审时定。
- **第六类能不能认准 import 与导出名属于哪个包。** 语法树应该够，动工时验；认不准就退一步，按目录前缀判。
