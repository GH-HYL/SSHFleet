# ADR-0066: 判重的位置——下载由解析站保证空目录，上传开传前问一次

> 原话是证据，不是要求；要遵守的是下面「决定」一节。

- **状态**：已接受（accepted）
- **日期**：2026-11-23
- **决策人**：
  - **开发者明示**（2026-11-23 上一轮对话，原话据交接记录）：「下载那块，应该让闸门那边加个判断，要保证下载的本地目标是个空目录，执行站这边就不判断了，就按一定是空目录，不重名检测。」；「上传换 test 就 test 你的测试，他有好几个选项，得测试 文件 目录 软连接什么的，能不能真的服务于咱们的需求。」
  - **开发者明示**（2026-11-23 本轮对话）：落点被问到「放闸门里还是跟材料自检同族」时答「放解析站里面，但报错退出，你看看架构，不要腐蚀架构设计，看看是算不算起不来」；上传时机被问到「整批先查还是只换手段」时选「开传前整批查（推荐）」。
  - **执行者推导**（他未点名，本文标为推导）：谓词取 `[ -e ] || [ -L ]` 并联；「非空」归「起不来」而不归「拒绝」；壳不认那条循环时退回逐文件 `Stat`；分批沿用命令行长度上限。
- **前身**：ADR-0063 决定 7（下载前查本地重名，**已由本条取代**）、决定 8（判重与创建之间的时间窗不处理）

## 背景

两处判重都住在执行站，各有一个代价。

上传是**逐文件** `Stat`：一个文件一次协议往返，几千个文件就是几千次，而判断要问的只是「这个名字被占着没有」。下载是**逐文件** `Lstat`：同样一次一文件，且这段判断写在开跑之后、已经枚举完整批之后。

两处都用一个「跟随软链接」的谓词（`Stat` 跟、`Lstat` 不跟，下载侧取的是后者，上传侧取的是前者）。上传侧因此有一个已知的洞：断链与自指环在 `Stat` 眼里「不存在」，紧接着的 `Create` 会顺着链接写到别处去。

开发者要把下载这一处整个撤掉，理由是他那边的用法是每个节点各建独立目录。执行者核过代码：这个结论只在**第一趟**成立——落地目录按 `本地目录/<IP>` 拼，已存在就复用，同一个 `-p` 跑第二趟会撞上。他听完仍选择由前面一道门保证。

## 决定

### 1. 下载不判重，改由解析站保证 `-p` 是空目录（落点开发者明示，归类执行者推导）

执行站不再查本机落点，一律按「一定是空目录」办：删掉开传前那段逐文件 `Lstat`，也删掉「本机文件已存在」这个分类与它的环节名 `local_exists`。

「空目录」这条检查加在解析站的材料自检里，与「目录不存在」「不是目录」同一处、同一族（`materialDownloadDir`），结论是**起不来**，不是拒绝。

**为什么不是拒绝**（推导，按 ADR-0034 决定一）：判据是「前提完备不完备」。执行站已经不再有能力处理非空目录，于是「落点是空目录」成了这次开工的前提之一，与「`-p` 要已建好」同一性质；「输入不合规」那一类管的是参数搭配、取值与危险命令，不沾它。

**为什么不放闸门里**（推导，按 ADR-0034 影响）：闸门不读文件、不读配置——判据由前一站读一次随信封带下来，闸门不另读，否则同一个事实两个来源。本机目录空不空只有解析站能看见。

列不出目录内容（权限、IO 错）按「读不到」报，不按「不是空的」报：这时判不了空不空，说「非空」是瞎报。

### 2. 上传判重：开传之前整批问一次（时机开发者选定）

一条远端循环把这一批落点一起问掉，只付一次往返（几千个文件按命令行长分批，不是一次一个）：

```sh
for p in '<路径>' '<路径>'; do if [ -e "$p" ] || [ -L "$p" ]; then printf '%s\0' "$p"; fi; done
```

`--sudo` 时前面加 `sudo -n `。命中按 NUL 切出来，交回完整路径，报文里还原成清单里的相对名。

**谓词为什么是两个并联**：`-e` 跟随软链接，断链与自指环在它眼里是「不存在」，而这两个名字确实被占着；`-L` 不跟随、只看名字。并起来才是「这个名字被占着」。这同时堵上了上面那个洞。

**退出码怎么读**：`if` 包住 `printf` 是为了让「一条都没命中」也交 0；裸写 `[ -e ] || [ -L ] && printf` 时零命中交 1，与「命令坏了」撞在同一个值上。实测两种形态的退出码见文末。

**命中即零写入**：整批计失败、一个字节都不传，报文列出撞上的那些名字。这与下载、与「目标盘装不下」那两条早退同口径——一个文件都没开始传，就都算失败。**回滚这一路因此不再参与判重**：没有写过任何东西，没有要删的。

**壳不认这条**（csh 一类，命令退非 0）时退回逐文件 `Stat`：慢、看不见断链，与换这条之前同一口径。判重宁可慢，不能不判。

## 理由

- **判重的位置决定代价的量级**：逐文件的代价随文件数线性涨，而判重问的是同一件事——「这一批名字里哪些已经被占着」。一次问完是这一件事的天然形状。
- **判断要在写入之前**：写入之后再发现重名，只能靠回滚把已写的删掉；那是补救，不是判重。
- **前提与拒绝分开**：落点非空不是「你不该这么干」，是「这次的工具处理不了」——它已经是执行站的一条假定，不是一条裁量。
- **一处保证胜过两处判断**：同一个事实（落点是否重名）只让一处说，另一处按它办。两处都判会漂移，实测中的第一趟/第二趟差别就是漂移的样子。

## 影响

- **分类表少一条**：「本机文件已存在」（`sshfleet.transfer.local_exists`）退役。按分类名过滤报表的脚本会少一条，这是行为变化。
- **重跑同一个 `-p` 从「静默覆盖」变成「开跑之前就报错」**：报的是「-p 指定的本地目录不是空的」，要重跑先清空。
- **上传的四个数变了**：撞上远端重名时，`SuccessFiles` 是 0、`FailFiles` 等于清单条数；以前是「前面已传的算成功、随后被回滚删掉」。
- **上传多一条前置命令**：每次上传多一条 exec 会话（判重那条）。没有任何文件的清单不会发这条。
- **`Stat` 与 `Lstat` 的分工不变**：`Stat` 仍用在「远端路径存不存在、是不是目录」这类预检上，那里要的正是跟随链接的语义。
- **ADR-0063 决定 7 不再约束**；决定 8（判重与创建之间的时间窗不处理）仍在，但上传那个窗口从「紧邻 `Create`」变成「整个上传时长」——见「未证实清单」。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 把「空目录」检查放进闸门 | 闸门不读文件；要读就得在纸上加一格由谁填的事实，而同一件事解析站已经在读了（`-p` 存在与形态），两个来源必漂移 |
| 只把上传的 `Stat` 换成 `test`，时机不动 | 每文件一条命令会话，比现在还贵；省不下往返，只买到堵洞 |
| 上传判重改一条 `find` 拿整棵目录树 | 拿全集只适合「顺带还要目录清单」的场合，成本随目标目录规模涨，而我们要的只是这一批名字 |
| 下载不动，继续在执行站逐文件 `Lstat` | 开发者要的是「执行站不判断」；而且它挡不住重跑同一个 `-p` 时的静默覆盖以外的所有情况，判断位置本身就选错了 |
| 上传命中重名后仍走回滚，保留原有四个数 | 没有写过任何东西，回滚是空转；数字还会把「成功」说给已被删除的文件 |

## 实测与推断的分界

| 结论 | 强度 | 怎么取的 |
| --- | --- | --- |
| `test -e` 对断链与自指环交 1（「不存在」），`test -L` 交 0；`-f`/`-d` 各按类型分，断链两者都交 1 | 实测 | WSL 的 sshd（`127.0.0.1:2201`），账号 `sshfleet`，登录 shell bash 5.3.9；夹具为普通文件、目录、软链接→文件、软链接→目录、断链、自指环、不存在、父目录不存在、700 的 root 父目录 |
| 父目录 700 且属 root 时，`-e`/`-L` 都交 1；加 `sudo` 后 `-e`/`-f` 交 0 | 实测 | 同上 |
| 单条 `test` 只交 0 与 1，空串与无权限父目录也是 1，没有 2 | 实测 | 同上 |
| 合并循环「零命中」交 1，`if` 形态零命中交 0、命中交 0，命令不存在交 127 | 实测 | 同上，两种形态各跑一遍 |
| NUL 输出无多余字节：四条命中 84 字节 = 80 字符 + 4 个 NUL；零命中 0 字节 | 实测 | 同上 |
| 路径带空格、单引号、中文时原样返回（`EscapeSingle` + 单引号包裹，循环只 `printf` 不 `echo`） | 实测 | 同上 |
| `/bin/sh`（dash）也认 `-L`/`-h`，`printf '%s\0'` 同样出 NUL | 实测 | 同上 |
| 提权那一路必须 `sudo -n sh -c '<整条循环>'`：`sudo -n for p in …` 是语法错（退出码 2，一条都没执行） | 实测 | 同上，两种写法各跑一遍，看文件删没删掉 |
| BusyBox 的 ash 上这两个谓词与 `printf '%s\0'` 的行为 | 未验证 | 这台没有 busybox，Windows 也没有 podman |
| 登录 shell 不是 POSIX（csh/tcsh）时这条循环会语法错——退路接得住，但退路本身没见过真机 | 未验证 | 同上 |

实验形态与真实形态的差别：探针走 OpenSSH 客户端，程序里走 `x/crypto/ssh` 的 exec 通道；两者都是「用户登录 shell 带 `-c` 跑一条命令」，无终端、stdout 分开。

## 未证实清单

1. 上传那条判重命令与第一个文件写入之间隔着整个判重耗时；远端在这段时间里被人建了同名文件的窗口，比原来「紧邻 `Create`」的毫秒级窗口大得多。这个代价在选择时已写明并被接受，但**窗口到底有多长没有实测**——几千个文件分几批、每批多少毫秒，没有样本。
2. 几千个文件的清单要分几批问，批数随路径总长涨；真实节点上这条命令的耗时没有样本。
3. 壳不认这条循环时退回 `Stat` 的那一路，只在假目标机上验过，没有真机（csh 目标）样本。
4. 解析站列目录失败归「读不到」这一支，只在用例里造过（临时目录权限），没有在真正的无权限目录上跑过。
5. `--sudo` 时那条判重命令的形态（`sudo -n sh -c`）只在真 sshd 上用探针验过，程序里这一支没有用例：假目标机起不了提权会话，现有用例都不带 `--sudo`。
