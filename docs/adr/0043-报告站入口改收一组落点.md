# 报告站的入口改收一组落点，红线那条形状断言随之改口

- **状态**：已接受（accepted）
- **日期**：2026-11-06
- **决策人**：执行者推导（建站 07 规格第一条），随该规格与六张工单一起经开发者 2026-11-06 认可（「行 拆工单吧」「授权开工」）。**不是他逐条拍板的**，复审时请按推导看待。

## 背景

阶段 04 定报告站入口时，它只写一样东西——`report.txt`，所以入口就是「第三张纸 + 一条落点字符串」，红线 `TestRedlineReportScreenAndPath` 把这两点钉成了形状：`NumIn()==2`、第二参是 `string`、只交回一个 `error`。

阶段 07 要给这个站在收尾加三件事：两张表格（各自一条落点）、备份原料（要 `assets/` 落点）、「最新一次」链接（要历史根）。落点从一条变成五条。

## 决定

**报告站入口改成「第三张纸 + `archive.Paths`」，交回「要留痕的话 + error」。**

- 落点组用现成的 `archive.Paths`，不为报告站另造一个结构：那几个路径本来就由归档包一处发出，报告站只是读。
- 不摊成五个字符串参数——那是把「这一摊落在哪儿」的复杂度漏给调用方。
- 交回的 `warnings []message.Line` 是「打过了、还要记进工具日志」的那几句（今天只有链接那两句）：报告站自己上屏（ADR-0032 决定四把「报告站上屏」列为四处之一），留痕交塔尖——它不持日志句柄，与闸门把「非交互放行」那句话交上来落盘同一个形状。
- 红线那条断言跟着改成新形状：仍然是「入口收什么、交什么」的形状判据，一个字的内容都不判；**不新增红线用例**（`report.Run` 这一个符号没变）。名单里那一行的符号集随之少一个 `Kind`——旧断言用 `reflect.Kind()` 比第二参是不是字符串，新断言比类型名，那个方法不再被引用，指纹因此变了这一格；改名目的与形状范围没变，属同一次改动。

## 理由

**为什么必须动这条红线**：三种实现的成本不对称——摊参数让每个新产物都往签名上挂一个字符串；让报告站自己拼路径，红线第二条就白立了（落点归归档包）；把落点塞进第三张纸，那是让纸装下一站才用得上的路径，撞 ADR-0035 决定三。剩下的只有「换掉第二参的类型」。

**为什么这是「工程设计变了」而不是「代码复杂度变了」**（《个人开发规范》一.1 第七条要的那个判断）：产物从一份长到五份，入口收的东西跟着变；不是因为某个函数太长、难读才改。

## 影响

- `report.Run` 的调用点只有塔尖一处，改一行；`main.go` 多三行把 warnings 记进日志。
- 红线区本条**不新增用例**；`TestRedlineReportScreenAndPath` 的第二段断言换了形状，指纹少一个 `Kind`。同一阶段另有一张单新增 `TestCheckMask` 一条（新增不算改），那之后红线是 40 条。
- 建站 04 规格里「报告站入口只收一条落点字符串」那句话不再约束，以本条为准。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 保持两参，第二条传本次目录，报告站在里面自己拼文件名 | 红线第二条就是「落点由别人给，它自己不拼路径」；这么改等于把那条红线废掉 |
| 摊成五个字符串参数 | 调用方要懂「这一摊有哪几样」，边界漏到外面 |
| 把落点塞进第三张纸 | 纸只装下一站要用的数据格；路径是落点，不是这一棒的事实 |
