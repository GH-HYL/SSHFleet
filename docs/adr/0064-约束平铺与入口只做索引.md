# ADR-0064: 约束平铺在 `docs/agents/`，`AGENTS.md` 只做索引

> 原话是证据，不是要求；要遵守的是下面「决定」一节。

- **状态**：已接受（accepted）
- **日期**：2026-11-20
- **决策人**：
  - **开发者明示**（2026-11-19 定交接文档时）：平铺成一份一件事、按 `必读-`／`按需-` 两族分前缀，粒度细到 21 份；理由是「太细随时可以合并，不怕细」。他推翻过一版「每条纵切各走四步」的拆法——这次不拆工单，四个步骤直接当执行顺序。
  - **开发者明示**（2026-11-20 本轮）：「那个技能的文档是 setup-matt-pocock-skills 创建的，他有一套写死了路径，那些东西不能动」；「按照技能要求该写什么写什么，其他的做咱们这次约束架构重构」。
  - **执行者推导**（他认可规格、未逐条拍板）：目录取 `docs/agents/` 而不另起单数目录、21 份的具体归属、`AGENTS.md` 那一段只留技能要求的三条——这三处他没单独说过，是从「收进单一目录」与「上游写死的路径不能动」两条推出来的。

- **前身**：`个人开发规范.md`、`doc-guide.md`、`测试环境使用指南.md` 三份长文（都在 `docs/` 下，本轮删除）；它们的条目按「一次动作一起读」重切成这八份。

## 背景

规则散在三份长文里：`个人开发规范.md` 356 行、`doc-guide.md` 305 行、`测试环境使用指南.md` 152 行；另有一份 `docs/交流方式.md`，3 行，是开发者自己的回话口径，不属这套约束。取一条规矩得在长文里定位，同一件事还有两处各写一遍、已经分叉的：ADR 模板与纪律、使用者文案口径、工单落点与竖切、测试沙盒。引用只能引整节，节号随增删漂移，写进 ADR 与代码注释之后指不准。`AGENTS.md` 自称「只放地图」，实际是规范的摘要，两处维护。

## 决定

### 1. 全部平铺在 `docs/agents/`，按前缀分两族

约束文件直接躺在 `docs/agents/` 下，不建子目录、不设分组层。`必读-` 二份每轮开工读，`按需-` 六份照动作查。**一份装一次动作里会一起读的东西**：先按「一件事」切，再按「一起读」合回去——写代码的三节、写文档的六节、报做完到提交的那一串，各占一份。文件名即主题，不带原节号。

### 2. 上游三份不动

`docs/agents/issue-tracker.md`、`triage-labels.md`、`domain.md` 由 setup 技能生成，那套技能把这三个路径写死在 `AGENTS.md` 的 `## Agent skills` 段里：改名之后重跑 setup 会判成未配置，并在原位重造一份。**路径与内容都不动。**

`## Agent skills` 段只留技能要求的三条（`### Issue tracker`、`### Triage labels`、`### Domain docs`），指向这三份的路径原样。本仓此前自加的两条（`### Document formats`、`### Skills index`）撤掉——它们指的是旧文里的节，内容已由按需表覆盖。

### 3. 入口只做索引

`AGENTS.md` 不承载规则，只写「什么动作读哪一份」：必读表（时机 → 文件）、按需表（触发场景 → 文件）。改规则不碰入口，加入口不动规则。

### 4. 旧节号引用失效，改指文件名

旧文里按节号互指的（「一.1 第七条」「三.3」「四.3」这类）随旧文删除一起失效，替代是文件名加条名：`必读-约束.md` 第 7 条、`按需-写代码.md` 的「测试怎么写」、`按需-写文档.md` 的「改已有的文档」。全仓按关键词重对一遍，不按节号机械替换。

上游三份里还留着两处旧节号，都是「授权记录」里的来源标注，不动原文：`issue-tracker.md:39` 与 `triage-labels.md:16` 的「一、约束·1·2」，现在指的是 `必读-约束.md` 第 2 条（约束类文件要单独点头）。

### 5. 删旧三份单独一笔提交

删不可逆，放在索引重写与本篇提交之后单独成笔；指针清账另成一笔追在后面。回滚时只回删的那一笔。

## 理由

- **一条规矩一处**：双份不再靠人维持同步——载体只有一份，另一份改不成。
- **引用不再靠节号**：文件名不随增删漂移，代码注释与 ADR 里的指向能一直准。
- **入口与规则分开**：`AGENTS.md` 从摘要退回索引，省掉两处维护；改一条规则不用碰入口。
- **先细后合**：起手切到 21 份，看过实物后按「一次动作一起读」合回 8 份；合并不丢内容，再拆也只在原文里加标题。

## 影响

- `tools/check.sh`：过滤名单里为旧规范留的排除项、两处指旧写作指南的提示、只听「零节」的那处注释，都要换成新落点。
- `tools/hooks/commit-msg`、`tools/test.sh` 的注释、`.gitignore` 的三行注释，以及 `modules/SSHFleet2_Go` 下五处代码注释：路径与节号一起换成文件名。
- ADR、议题、手册里按旧节号指的说法一律失效，靠关键词对；`docs/adr/` 下的历史文档不改，`modules/SSHFleet_Go_bak` 只读区不动。
- 上游两处「一、约束·1·2」保持原文，映射记在决定 4，不改文件。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 另起单数的 `agent/` 目录 | 与上游三份分家，`AGENTS.md` 要多指一条路径；重跑 setup 还可能在 `docs/agents/` 重造一份 |
| 保留那几份长文，只在里面加锚点 | 节号仍会漂，双份仍在，只是换了个定位办法 |
| 保持按章节切的 21 份 | 起手就是这么切的，开发者看过实物后判为太碎：六行的文件打不开也用不上，读完仍要在几份之间跳。改按「一次动作一起读」合回 8 份 |
| 合成三四份大文件 | 一次动作里用不到的内容也一起读，换来的是无关篇幅；按动作分已经够粗 |
| 把约束塞进 `AGENTS.md` 一份 | 与「入口只做索引」相反，且它每次会话都在上下文里，篇幅直接变成常驻成本 |
