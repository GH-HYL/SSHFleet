# ADR-0004: 非 0 退出码下允许「会话被拒」类判据覆盖分类

- **状态**：已接受；**「覆盖」方案已被 2026-09-29 取代**（见文末《2026-09-29 取代》）
- **日期**：2026-09-16

## 背景

`internal/result/classify.go` 的既定语义是「退出码是权威信号」：退出码一旦非 `nil` 就按退出码分类，**不再匹配关键词**。这条语义写在 `CONTEXT.md` 词表（「退出码」）与该文件头的注释里，从未进过 ADR。

（该注释把退出码语义引作「ADR-0003 退出码语义」，是**误引** —— ADR-0003 的主题是「执行模式判定不做集中化」。本 ADR 正式承接这条语义。）

2026-09-16 真机复现发现，该语义在「会话被拒」这一族场景下会把**已经拿到手里的信号丢掉**：目标机密码过期时，连接与认证均成功、会话也建起来了，命令被 PAM 拒下——sshd 把固定文案打进会话的 stderr（`WARNING: Your password has expired.` / `Password change required but no TTY available.`），命令以退出码 `1` 结束。

此时 `output` 字段里有完整文案、`error` 字段为空，但分类器在退出码那一步就返回了，分类落成「执行失败(退出码1)」——"密码过期"这个事实在报表与统计里完全消失。

同一形态经实测确认还有三种：登录 shell 为 nologin（`此帐户目前不可用。`）、`ForceCommand internal-sftp`（`This service allows sftp connections only.`）、账号不在 sudoers（`sudo: I'm sorry …`）。

## 决定

错误关键词表**拆为两块，触发条件互斥**：

- 现有 `[[categories]]`：仅在**退出码为 `nil`** 时参与匹配 —— 行为不变。
- 新增 `[[exit_code_categories]]`：仅在**退出码非 `0`** 时参与匹配，命中即**覆盖**退出码分类。

**同名分类允许两块各写一遍**（用户 2026-09-16 裁定）：同一个诊断横跨两个阶段——「密码过期」既可能以认证阶段的服务端提示出现，也可能以会话内拒绝语出现。两块各登记该阶段会出现的文案，**谁命中就按谁分类**。实现上 `Has()` / `Names()` 取两块并集（`Names()` 去重），否则第二块的名字会被 `IsFallbackCategory` 当成兜底原文。

判据必须是**服务端自己打印的固定文案**（不是用户命令的输出），且取尽量长的整句。

**命中只改分类，退出码原样保留**（用户 2026-09-16 二次裁定）：退出码字段与它的显示逻辑一行不动——命中时只换分类，`exit_code` 与该处呈现照旧。先前"命中后清除退出码"的裁定已作废。

## 理由

- 「会话被拒」场景下的退出码 `1` **不是命令的退出码**，而是拒绝方（nologin / sudo / sshd 会话）自己的退出码。用它当"命令失败"的权威信号本身就是语义错位；覆盖的是**分类**，不是这个值——留着它不碍事，还能看出"服务端确实是以非 0 结束的"。
- 判据能精确到"服务端固定文案"这一级：这些句子由 sshd 打入会话 stderr，用户命令无法伪造出同样的上下文，误伤面可控。
- 覆盖权做成**显式声明**而非全局放开：未声明的分类行为不变，现有语料零回归。全面放开会让用户自己执行的命令输出污染分类（例如 `grep 'has expired' /var/log/x` 会被判成密码过期）。

## 影响

- 「退出码是权威信号」自此改为「**除非该分类在第二块里显式声明**」。`CONTEXT.md` 词表同步。
- 命中覆盖的行，明细里 `exit_code` **照旧保留**（用户 2026-09-16 二次裁定）；呈现层那行「命令执行失败，退出码 X」同样不动。
- **关键词表的语义不再冻结**：D11 约束的只是迁移时 YAML → TOML 逐字节平移，本次是迁移完成后的语义修正，不构成对 D11 的违反。
- 新块的分类名必须能被 `Keywords.Has()` 命中，否则 `IsFallbackCategory`（`internal/output/terminal.go:159`）会把它当成兜底原文，在统计里被排到单独一行。
- 判据会随发行版与语言漂移：sshd 不翻译自己的消息（英文稳定）、`sudo` 被工具包装强制成英文，但 **nologin 那句跟随系统 locale**（实测 `zh_CN` 下为中文），故判据需中英双份。
- **未覆盖 · 认证阶段被拒**：账号过期、`/etc/nologin` 的拒绝发生在预认证阶段，退出码为 `nil`，不属本 ADR 的范围；它们的原因由 **ADR-0005**（接住服务端 banner）解决。
- **未覆盖 · 传输模式**：上传 / 下载走 SFTP，拿不到会话内文案（实测报 `SFTP 客户端创建失败 - error receiving version packet…`）；但认证阶段已到手的 banner 仍可用于分类（见 ADR-0005）。

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 全面放开：退出码非 `0` 时也跑全部关键词 | 用户命令的输出会污染分类；且推翻既有语义的收益与风险不成比例 |
| 只在退出码 **== 1** 时匹配 | 精度全部来自关键词长度，与退出码取值无关——绑 `1` 不减误伤，只会丢掉"不是 1"的场景。实测这四种场景的 `1` 都是拒绝方自己的退出码，协议层并不保证它恒为 `1` |
| 判据写死在 Go 代码里（对位 `AuthFailure` 的做法） | 文案会随发行版与语言变（nologin 那句实测是中文），写死就要跟着发行版打补丁；放进可维护的配置更合适 |
| 在包装命令里插哨兵，用「命令是否真的执行过」判定 | 更本质（一次覆盖所有会话被拒场景、不依赖服务端文案），但 `BuildCommand` 现无哨兵、`--nobash` 路径需另处理，改动面明显更大，本次不引入 |
| 只改呈现层，把这类行单独标出来 | 不满足"要正确分类"的诉求；分类字段与统计口径都不会变 |
| 给每个分类加一个 `override_exit_code` 开关（不分表） | 会把"哪些判据能在退出码非 `0` 时生效"散落到每一个分类上，边界不如独立表一眼可见；用户 2026-09-16 裁定用独立表 |

## 2026-09-29 取代：「退出码优先 + 覆盖」→ 按目的命令的退出码选判据组

**决定：本 ADR《决定》一节的分块依据与「覆盖」机制不再成立。** 分块依据从「结果退出码是否为 `0`」换成**纯字段判据**：

> **`CommandExitCode != nil` → 第二组 `[[exit_code_categories]]`**（目的命令真的跑了并给了退出码）
> **`CommandExitCode == nil` → 第一组 `[[categories]]`**（没有目的命令的退出码：连不上、认证失败、传输失败、预检失败、改密……）

理由：

- 本 ADR 的分块依据看的是「**结果退出码**」这个被加工过的值。下载预检查（`test -e`）失败时，预检自己的退出码 `1` 被塞进结果退出码，分类只能走第二组，逼出 2026-09-24 `3eb936a` 在第二组补「远程路径不存在」的补丁——它不是设计，是被"执行侧编结论"逼出来的应景之作（`docs/issues/result-verdict/spec-已闭环.md` 4.3 有完整考证）。
- 「覆盖」是个补救动作：执行侧先写结论（退出码），判定再改一次——同一件事动了两道手。本轮立的更高一条规矩是**执行侧只写事实、已写下的值不许再改**（`docs/issues/result-verdict/spec-已闭环.md`）。执行侧改为：**目的那条命令**的退出码进 `CommandExitCode`（中间步骤的进 `Steps`，带名字）；结果退出码 `ExitCode` 由结果判定最后赋值或保持 `nil`。
- "这条命令是不是目的本身"在结构层就已经答完（谁写进 `CommandExitCode`，谁就是目的命令），所以选组**不需要看错误发生在哪一段、也不需要看模式**。

本 ADR 的处置：

- **本文正文（背景 / 决定 / 理由 / 影响 / 备选方案）原样保留**，作为"当时为什么这么定"的记录，不改写历史。其中文件名（`internal/result/classify.go`、`internal/output/terminal.go`）为当时路径，随结果统一重构已变。
- 「命中即覆盖」机制**取消**：第二组不再是"命中后改一次分类"，而是**本来就该查的那一组**。
- 「**命中只改分类，退出码原样保留**」（2026-09-16 二次裁定）的意图**以更好的方式成全**：不再靠"改分类前先别动退出码"，而是判定最后一步按同一判据决定"赋不赋"——目的命令有退出码 → 赋它（明细里保留）；否则保持 `nil`。
- 第二组删掉 2026-09-24 补进来的「远程路径不存在」（第一组那条保留）。预检退出码进 `Steps` 后，上传与下载两侧统一走第一组，**用户看到的分类名不变**。第二组剩三条：密码过期 / 登录被禁止 / 仅允许 SFTP。
- 「同名分类允许两块各写一遍」**不再需要**——「密码过期」只留第二组那条。
- `Has()` / `Names()` / `KeywordsOf()` 取两块**并集**的逻辑**不变**：漏掉某一组的名字，兜底判定会把选出来的分类当兜底原文，统计里单排一行。

以下各条**继续成立**（与「覆盖」机制无关）：判据必须是**服务端自己打印的固定文案**、取尽量长的整句（精度全部来自这里）、nologin 判据中英双份（跟随系统 locale）、命中不改报错原文、`sudo` 被拒不立判据维持原文回退、未覆盖的**认证阶段被拒**归 **ADR-0005**、**传输模式**拿不到会话内文案。

| 项 | 2026-09-16 版 | 2026-09-29 版 |
| --- | --- | --- |
| 分块依据 | 结果退出码是否为 `0` / `nil` | `CommandExitCode` 是否为 `nil`（纯字段判定） |
| 第二组命中语义 | 覆盖既定的退出码分类 | 本来就该查的一组，无"覆盖"概念 |
| 预检失败 | 退出码塞进结果 → 第二组 → 需要同名补丁 | 进 `Steps` → 第一组，补丁删除 |
| 同名分类两块各写一遍 | 允许（「密码过期」需要） | 不再需要（「密码过期」只留第二组那条） |
| 定论退出码 | 命中覆盖只改分类、退出码照旧 | 同一判据同时定"赋不赋"：目的命令的退出码赋、否则 `nil` |

影响：

- `config/keywords_error.conf`：第二组删「远程路径不存在」，头部两组说明改按新判据表述。
- `internal/verdict`：`matchText(second, text)` 一个匹配入口，选组由判定做；原 `match` / `matchExitCode` 两入口合并。
- 结果明细里「退出码」列的**语义不变**（会话被拒时该值来自拒绝方而非命令，见 `CONTEXT.md`「退出码」）；变的是它的**来源**——由判定赋值，不再由执行侧写。
- 真机复跑专项确认：上传到不存在的远程目录、下载不存在的远程路径，两侧分类名都是「远程路径不存在」（`docs/issues/result-verdict/spec-已闭环.md` 9.5 #1）。

## 补充（2026-10-09）：退出码走字段，分类名只作呈现

「执行失败(退出码N)」这个分类名由 `verdict.Judge` 产出，产出时退出码**同时**写进了 `Result.ExitCode`（必然相等）。但统计只把**分类名与台数**交给呈现（`result.CategoryCount`），呈现侧要那个数字时，只能拿正则 `退出码(\d+)` 从名字里解回来——`output/terminal.go` 有两处这么做（「常见退出码」行、分类说明行）。

后果是那串给人看的中文承担了数据契约：分类名一改措辞（换个全角括号、加个空格），正则不再命中，两处提示**静默**退化成通用文案——不报错，改的人不会知道自己碰坏了什么。

本次让 `CategoryCount` 多带一格退出码（`Statistics` 从 `Result.ExitCode` 搬，只对带退出码的那类分类填），呈现侧改读字段、删掉正则。

**分类名形态不变**：它照样内嵌数字。`docs/issues/category-stats-layout/spec-已闭环.md` 里"分类名彻底不带数字"那个方向（该 spec 的方向丁）仍不实施——本次只切断「呈现侧解析名字」这一条，不动 xlsx、判据表与既有语料。

`verdict.go` 的 `IsFallbackCategory` 仍按分类名前缀判「是不是兜底原文」（它判的是前缀、不含数字），本次不动。
