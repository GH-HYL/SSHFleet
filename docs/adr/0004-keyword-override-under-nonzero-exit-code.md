# ADR-0004: 按目的命令的退出码选判据组（原「非 0 退出码下的判据覆盖」）

- **状态**：已接受（本版整体取代 2026-09-16 的「覆盖」方案，取代缘由见《与 2026-09-16 版的差异》；原版全文见 git 历史）
- **日期**：2026-09-29（原版 2026-09-16）

## 背景

2026-09-16 的问题：`internal/result`（现 internal/verdict）的既定语义「退出码是权威信号」在「会话被拒」一族场景下会把已经拿到手里的信号丢掉——目标机密码过期时，连接、认证、建会话都成功，命令被 PAM 拒下，sshd 把固定文案打进会话 stderr（`WARNING: Your password has expired.` / `Password change required but no TTY available.`），命令以退出码 `1` 结束，而分类落成没用的「执行失败(退出码1)」。"密码过期"这个事实在报表与统计里完全消失。同形态经实测还有三种：登录 shell 为 nologin（`此帐户目前不可用。`）、`ForceCommand internal-sftp`（`This service allows sftp connections only.`）、账号不在 sudoers（不立判据，维持原文回退）。

当时的方案：关键词表拆成 `[[categories]]` 与 `[[exit_code_categories]]` 两块，按**结果退出码是否为 `0`** 触发，第二块命中即**覆盖**退出码分类；同名分类允许两块各写一遍。方案有效，但留下两个别扭：

1. **分块依据看的是"结果退出码"这个被加工过的值**。下载预检查（`test -e`）失败时，预检自己的退出码 `1` 被塞进结果退出码，分类只能走第二组，逼出 2026-09-24 `3eb936a` 在第二组补「远程路径不存在」的补丁——它不是设计，是被"执行侧编结论"逼出来的应景之作（`docs/issues/result-verdict/spec.md` 4.3 有完整考证）。
2. **"覆盖"是个补救动作**：执行侧先写结论（退出码），判定再改一次——同一件事动了两道手。

## 决定（2026-09-29，随结果统一重构落地）

执行侧只写事实：**目的那条命令**的退出码进 `CommandExitCode`（中间步骤的进 `Steps`，带名字），结果退出码 `ExitCode` 由结果判定最后赋值或保持 `nil`。分块依据随之从"结果退出码是否为 0"换成**纯字段判据**：

> **`CommandExitCode != nil` → 第二组 `[[exit_code_categories]]`**（目的命令真的跑了并给了退出码）
> **`CommandExitCode == nil` → 第一组 `[[categories]]`**（没有目的命令的退出码：连不上、认证失败、传输失败、预检失败、改密……）

"这条命令是不是目的本身"在结构层就已经答完（谁写进 `CommandExitCode`，谁就是目的命令），所以选组不需要看错误发生在哪一段、也不需要看模式。"覆盖"机制随之取消：第二组不再是"命中即覆盖"，而是本来就该查的那一组。定论退出码与选组同源：目的命令有退出码 → 赋它（明细里保留）；否则保持 `nil`。

第二组删掉 2026-09-24 补进来的「远程路径不存在」（第一组那条保留）——预检退出码进 `Steps` 后，上传与下载两侧统一走第一组，用户看到的分类名不变。第二组剩三条：密码过期 / 登录被禁止 / 仅允许 SFTP。

`Has()` / `Names()` / `KeywordsOf()` 取两块并集的逻辑不变：漏掉某一组的名字，兜底判定会把选出来的分类当兜底原文，统计里单排一行。

## 与 2026-09-16 版的差异

| 项 | 2026-09-16 版 | 本版 |
| --- | --- | --- |
| 分块依据 | 结果退出码是否为 `0` / `nil` | `CommandExitCode` 是否为 `nil`（纯字段判定） |
| 第二组命中语义 | 覆盖既定的退出码分类 | 本来就该查的一组，无"覆盖"概念 |
| 预检失败 | 退出码塞进结果 → 第二组 → 需要同名补丁 | 进 `Steps` → 第一组，补丁删除 |
| 同名分类两块各写一遍 | 允许（「密码过期」需要） | 不再需要（「密码过期」只留第二组那条） |
| 定论退出码 | 命中覆盖只改分类、退出码照旧 | 同一判据同时定"赋不赋"：目的命令的退出码赋、否则 `nil` |

不变的部分：判据必须是**服务端自己打印的固定文案**、取尽量长的整句（精度全部来自这里）、nologin 判据中英双份（跟随系统 locale）、命中不改报错原文、`sudo` 被拒不立判据维持原文回退。

## 影响

- `config/keywords_error.conf`：第二组删「远程路径不存在」，头部两组说明改按新判据表述。
- `internal/verdict`：`matchText(second, text)` 一个匹配入口，选组由判定做；原 `match` / `matchExitCode` 两入口合并。
- 结果明细里「退出码」列的语义不变（会话被拒时该值来自拒绝方而非命令，见 CONTEXT「退出码」）；变的是它的来源——由判定赋值，不再由执行侧写。
- 真机复跑专项确认：上传到不存在的远程目录、下载不存在的远程路径，两侧分类名都是「远程路径不存在」（result-verdict spec 9.5 #1）。
