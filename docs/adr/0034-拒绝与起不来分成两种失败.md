# ADR-0034: 拒绝与「起不来」分成两种失败，拒绝权只归闸门

## 背景

老工程里「不让往下走」有八处出口，散在参数检查、危险命令检测、参数确认屏、改密前置检查四个地方，各自调一个「打日志顺便退出」的帮手。

教学骨架给的方案是「闸门独占拒绝权」，但骨架自己留了个说不通的地方：它把危险命令检测划进闸门，而那个包的注释写着「我只是提示，不是拦人的闸门」。工单 01 谈下来发现，两处口径之所以打架，是因为「不让走」被当成了同一件事，而它其实是两件：

- **计划已经成形，结论是不能跑**——这是拒绝，是权责，该只有一处。
- **连计划都生不出来**（配置读不到、清单打不开、日志目录写不进去）——这是「起不来」，它不是拒绝，也不该有「换个说法继续」的余地。

同一个错误也用在了「判据缺失」上：闸门自己要用的规则坏了，它判不了，这不是「你参数错了」，是「我没能力判断」。

## 决定

**一、判据：前提缺一样就是「起不来」，前提齐了才轮得到「拒绝」。**

不逐条枚举情形，只问一件事：这件事发生的时候，工具该有的东西齐不齐。配置文件读不到、是空的、格式错、必须的那一份没配、清单读到一半失败——缺的每一样都归「起不来」，与闸门无关；齐了、只是这一份不放行，才是拒绝。据此归闸门的有三类：输入不合规、危险命令、使用者当场喊停。

**判据不取「计划成形了没有」**：那是结果，还得先定义什么算一份计划。取「前提完备不完备」，一眼可判，也不必说清「走到哪一站才发现」。

**「判据缺失」归起不来，不归拒绝**：它是摄入阶段的检查项——该有的配置读不到、空了、格式错、必须的那份没配。「整张表没配」与「表齐了少一条」不是两件事，都没过摄入那份必须项清单；哪一项算必须由摄入定。表里没有的那一条不另造「未分类」，归类取远端原话（执行站归类那一格的事）。

**「输入不合规」把信封本身算在内**：信封上写「上传」，格子里装的却是命令，这跟参数写错是一类事——都是送进来的东西对不上，不是流程决定的。所以验信封归这一类，不另立第五类。

**二、闸门三个出口。**

放行；放行但要跟使用者说一句；拒绝。骨架那个「一句留痕 + 一个错」装不下第三种——主密钥预检查这种「照跑，但你得知道」没有地方去，只能退化成一条没人看的日志。

**三、拒绝与起不来是两种类型：拒绝只住闸门，起不来放通用类型包。**

在别处表达「我不让走」，得先能造出那个类型——造不出来，就只能改用「起不来」。反过来，「起不来」谁都能造，因为它不是一种权力，是任何一站都可能撞上的事实。**它就住在契约包里**——那里本来就只放类型和常量，多一种失败类型不破规矩。

**四、任何站遇到起不来，只能把结论往上交，不许自己退。**

ADR-0032 第五条说的是「退出动作只许在塔尖」，本条补的是它靠什么成立：各站拿不到退出这个东西。两条合起来才是结构：**想停停不了，想拒绝得先能造出拒绝**。

**「停」和「退出」是两件事**：停是判断（这一批还能不能往下走），只有闸门能下；退出是动作（进程怎么收场、给什么码），只有塔尖能做。各站既不退出，也不自己决定停——它只能把结论交上去。

**「起不来」不进信封**。信封的前提是计划已经成形，而起不来正好在成形之前，装不进那个盒子。它作为自己那一种失败，一路交到塔尖；塔尖因此要认两样进来的东西：一份信封，或者一个「起不来」。

**五、危险检测只出判断，不出处置。**

「不是防御闸门」指的是不承诺「挡住所有恶意」，不等于没有拒绝权。它命中的结论交给闸门，停不停由闸门说。

**六、主密钥预检查不进拒绝。**

它现在只警告、然后照跑。按字面归成「守卫」会让下一个接手的人顺手让它拒人，那是改行为（ADR-0032 第一条）。走第二个出口。

**七、判据不全单列一种报错口径。**

规则文件坏了、读不到、改密关键词没配——报「工具没能力判断」，不报「你参数错了」。**这一类归「起不来」（见决定一），但话术仍单独一套**：它说的是「东西不齐」，不是「你不该这么做」。

**改密模式里「密码过期」那一类关键词是必须项**：缺它归「起不来」，**启动时就报，不等跑到改密那一步**（开发者 2026-10-31 定）。配套的检查按清单逐条过：文件在不在、格式对不对、这一项有没有、内容空不空、分类名有没有重。**这是行为变化**——老工程跑到改密那一步才提示，新工程一启动就报；使用者能感觉到，切换时要在 CHANGELOG 写一句。

**八、闸门不写话。**

出判断的地方只交事实（哪一条没过、哪一档），句子由报错构造点按固定形态拼（ADR-0028）。闸门既不拼句子，也不打屏：它只看攒起来的那堆结论里有没有「不让走」，再按三个出口处置，该说的那句原样转交。

这一条同时管住两头：判断处没机会顺手把退出拼上；闸门也不会因为要适配 N 种说法而变宽。

## 理由

**为什么判据是一刀切，而不是把八处出口挨个归类**：归类靠人力，以后新加一处，还是要问「该放哪」——那正是这次要消灭的问题。一刀切问的是同一个问题，答案不依赖枚举有没有穷尽。

**为什么拒绝类型只住闸门**：只写「不许在别处拒绝」是纪律，管不住后来的执行者；让别处**造不出**那个类型，才轮不到他发挥。这也是作者要的那句「把不该做的事变成做不到的事」在一条工单上的具体长相。

**为什么要把「起不来」也钉死**：它是最容易被顺手改成拒绝的地方——「反正这里也失败了，就地退掉算了」。一旦两件事共用一个出口，事后查问题会互相盖住：分不清是「这次的活干不了」还是「这活儿没资格干就先趴下了」。

**为什么危险检测可以既说「不是闸门」又参与拒绝**：因为它管的是判定，闸门管的是处置。判定可以散，处置只一处。

**为什么闸门不能写话**：写话等于把「适配 N 种说法」的活拉进闸门。入口还是那份计划，可计划里得背着一堆半成品句子——这就从深模块变成了宽口子（露出来的口子要求外面喂很多东西）。而不让判断处写话，是防止它顺手把退出也拼上：**判断处一旦开始组织句子，离顺手 `return err` 只有一步**。作者的原话是「它看到检测那块儿直接就把报错内容写好了，那它会不会直接把退出什么的也一块儿捎带上」。所以话必须落在第三处——报错构造点，那里本来就只管拼句子，不掌握任何流程。

**为什么「起不来」的类型反向放开**：它不是权力，是事实。任何一站都可能读不到文件、撞上写不进去的目录；把它关进某个包，等于逼着别处自己造一个长得像的，分型就废了。

## 影响

- **闸门要用判据**：危险规则、错误关键词、改密提示词。这些都是摄入站读一次、随信封带下来的那一份（ADR-0035 决定五），闸门不另读——另读就是同一个事实两个来源。
- **05 号（塔尖多薄）少一个悬念**：退出只在塔尖，闸门只出结论。
- **07 号有东西可查**：退出动作只在塔尖、拒绝类型只在闸门构造、依赖方向不回流。这三样是机械可验的。
- **报错文案多一套口径**：起不来、拒绝两种说法不能混用；「东西不齐」还要在自己的口径里再说清一层，别退化成「你参数错了」。
- **参数确认屏的拆分是推导，不是拍板**：屏的措辞归闸门、问那一句走 `ask`、渲染原语走 `console`。作者认的是「都归闸门」，这一层细分来自已定边界，复审时可推翻。
- **与 ADR-0028 接上了**：它的射程是「使用者能当场改」那一层，参数检查的报错正好落在里面；本篇只是把「谁来拼句子」这件事指到它那儿。
- **判断散开之后，结论要送到闸门**：各站产生的问题清单得随计划往上带，交接件因此比只带业务数据更厚。这件事与 03 号（交接件宽窄）是同一件。

## 代价

- **闸门会随时间变厚**。任何新拒绝理由都要进闸门改——权责集中必然如此。作者认的是这一条，不是「闸门永远很薄」。
- **起不来与拒绝分两套类型**，跨站传递时多一层判断，代码比「一个错误类型打天下」啰嗦。
- **判断与句子分家，新加一条检查要动两处**：一处判断（交事实），一处文案表（拼句子）。比现在「一处写全」多一个落点——换来的是再也不会牵动退出。
- **清单读到一半的边界写死了**：一律算起不来。代价是某些「其实还能跑一部分」的情形会被整体拦下；这是选「计划要么完整要么没有」的结果。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 窄闸门：只拒「现在不能启动」的，改密检查留在执行站自检 | 拒绝权留两处，以后新加前置检查还是得问「该放哪」；07 号只看依赖方向，验不出「判定散没散」 |
| 靠纪律：写「各站不许自己退」，不动作结构 | 纪律是建议，不是边界。老工程八处出口就是「谁都觉得自己只是顺手退一下」长出来的 |
| 全用 panic 统一往上抛 | 不是不能用，是它同时承载「预料之内的失败」与「代码有 bug」，不区分就分不清。这是设计选型，机械校验定不了，等 07 号谈机械检查时一并看 |
| 把八处出口逐条归类，不取判据 | 归类靠穷举，新情形一来就漏；判据只问一个问题，新情形自己落位 |
| 判断处自己把话拼好再交上去 | 它一旦在组织句子，离顺手把退出也拼上只有一步——作者担心的正是这个。而且同一套说法会在八处各长一遍 |
| 闸门替所有人拼话 | 入口还是那份计划，但计划里要背一堆半成品句子，闸门从深模块变宽口子；再往后每加一种报错，闸门跟着改 |

## 尚未定的

- **确认屏的三份拆法**（屏 / 问 / 判）只是推导，未逐条拍板。
