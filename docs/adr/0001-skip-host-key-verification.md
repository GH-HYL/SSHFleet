# ADR-0001: 跳过 SSH 主机密钥校验

- **状态**：已接受
- **日期**：2026-09-11

## 背景

SSHFleet 的目标机清单由用户自行维护，实际使用规模可达数千台。

SSH 协议的主机密钥校验要求客户端维护一份「已知主机」记录（`known_hosts`），首次连接需人工确认指纹；主机重装、换 IP 或迁移后记录失效，需重新确认。在批量场景下，这些确认点会落在每一次执行的关键路径上。

## 决定

连接目标机时**跳过主机密钥校验**，等同于 `ssh.InsecureIgnoreHostKey()`。

## 理由

- 维护数千台机器的主机密钥记录不现实：首次确认与重装后的重新确认，都会成为批量执行的阻塞点
- 目标清单是用户自有的、由用户显式指定的；威胁模型不包含"中间人伪装成清单里已有的某台机器"

## 影响

- **无法防御中间人攻击**：持有目标 IP 的主机（例如 IP 被重新分配后）可能被当作目标连接
- 使用方需自行确保网络环境可信（内网 / 专线 / 受控环境）
- 这是**刻意接受**的安全取舍，不是疏漏；不要因为"看起来不安全"而静默改成校验——那会直接打断数千台规模的批量执行

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 支持 `known_hosts` 校验（配置开关，默认关） | 增加配置项与维护负担，当前规模下无实际价值 |
| 跳过校验，但对端指纹记入执行日志 | 不增加维护成本，可作为后续增强（每次执行多若干行日志） |
