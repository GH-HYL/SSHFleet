# 红线区清掉两处值断言

**状态**：accepted
**日期**：2026-11-12
**决策人**：开发者（2026-11-12 原话：「行 按照你的推荐走」）

## 背景

规范三.3 写死：红线区只放结构，一条行为断言都不放，断言只碰形状与流向，不碰值算得对不对。
审计 11-J1／11-H3 在红线区里找到两类漏网：结算那条钉了三个具体台数，结果行那条钉了分隔线
宽度（50 个等号）。11-09 之后 0045／0046 清掉了一批，今天实测只剩这两处。

## 决定

两处都改：结算那条判守恒（跑完的加没跑的等于总数）与「总数不为零」，分隔线那条判「整行
都是等号的那种行出现一次」，不钉宽度、不钉字符。

## 理由

- 红线红的时候必须只有一种解释：结构被动了。钉了值之后多出第二种解释「值变了」，而值变了
  是需求或版式的事，本该由自定义区管。
- 这两处要判的东西本来就有家：台数由 `settle_test.go` 判（3／2／1），宽度由 `message` 的
  自定义区与 A/B 比对判。红线这一份是重复，不是保障。
- 版本行那两处（`版本: v` 前缀）不动：那是规范四.2 写死的格式，属于契约，判它是判形状。

## 影响

- 改分隔线宽度、改结算的数字口径，红线不再红——这是有意的，代价写在议题的「你会失去什么」里。
- 两条红线的指纹会变（符号与次数），逐条记进工单的 `## Comments`。
