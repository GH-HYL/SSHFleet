## 背景

使用者把参数乱写、写错顺序、把命令塞进 `-s`，决定「两处都错时先给看哪一句」。老版那套次序是两年试出来的，源码里只有结果、没有理由；新版按五站重排之后，跨站的先后变了样。

**实测**（2026-11-13，HEAD `8927738`；Windows 11 + Git Bash；新老两版各自带自己的 `config/`，加密关；78 条 argv，现场 `build/sb_order/order_ab.py`，临时文件）：**40 异，其中 39 条是真差异**（另一条只是连接耗时不同）。这 39 条里 25 条是同一件事——材料与清单的失败顶掉了第二至四层的结论：`-p 配 -c` 报「清单读不到」、`-c " "` 报「清单读不到」、危险命令报「清单读不到」。另有一条方向相反：`-t abc -f /nope.csv`，新版报 `-t`、老版报清单。

**这个环境的边界**：Git Bash 会把 `/tmp` 一类绝对路径改写成 `C:/…`，与 Linux 上的生产形态不同；这批用例只用来判「谁先说」，不用来判「那句话长什么样」。`-s` 塞命令、`--gen-key` 配 `-c` 那几组用的是相对路径与纯文本，不受影响。

原先的判据是「与老版逐字一致」，于是把这批记进 A/B 的 `KNOWN_EXPECT` 算「认下」。这条判据被实测推翻：`-t abc -f /nope.csv`，老版把第五层的「清单读不到」排在第三层的「`-t` 不成」前面；人修好清单，重跑还是报 `-t`。按本文的层序，取值属第三层、材料属第五层，老版这一处是倒的。所以判据既不能是老版，也不能是一致。

另一处争议是「加密三条命令与批量参数同给，报哪一边」。实测 10 组组合：两版逐字相同，主语恒是加密命令那一侧（`--gen-key 不能和批量执行选项一起用：同时给了 -c、-r`），批量参数只作为「同时给了什么」被列出；先后是词法错 ＞ 多余段 ＞ 三条命令互撞 ＞ 与批量同给。这一族没有顺序问题，但它给出了反证：**同一套「先分层、再判断」的规矩，在这一角已经落地，在材料与搭配之间没有落地**。

## 决定

**一、判据：根因优先。第一条可执行，不必靠经验也不必靠人拍板。**

1. **第一句指出的东西改完，重跑时剩下的错不许落在比它更前的层**（同层可以）。落在更前，说明第一句报的是下游：`-t abc -f /nope.csv`，先报清单（第五层），修完清单还剩 `-t`（第三层），就是排错了。
2. **同层两条互不为前提时，按第二条各层里列出的先后**（选项名按帮助里那一组），**不按使用者敲写的次序**——同一组错换个书写顺序不该换答案。词法那一层例外：按扫描先撞上哪个算哪个。
3. **主语只能是出问题的那一格**（哪个选项、哪份文件）。不许拿另一格的现象当主语（`-p` 配 `-c` 却报「清单读不到」违反这条）。

**二、七层，一个方向：上一层没判清，下一层的现象不能拿出来说。**

下面是**报出**的先后，不是「谁先读文件」：材料在判决之前就被读了（判决要用正文、屏要用节点），只是读失败这件事要等到它那一层才说。理由见第四条。

**一个例外**：如果上层这次**确实要下结论**、而它要用的那份材料拿不到（最典型：判决要脚本正文），那么报这个缺失不算「下层顶上层」——因为上一层并没有得出结论。**这个例外不扩大**：上层自己已经先判出别的问题时（比如 `-p` 配 `-c` 在第三层就拦下了），轮不到材料开口；它只管「上层要判、前提不在」这一种形状。

1. **词法**——认不出的选项、缺值、多余位置参数。后面全靠它。
2. **结构**——这次是哪一类事：加密三条命令 / 批量执行；批量执行里五个模式选一个。
3. **搭配、取值与必填**——开关互斥（`--no-shell` 的用法、`--sudo` 与 `--no-sudo`）、改密与 `-p`/`-a`/`-k`、`-p` 配 `-c`/`-s`、`-u`/`-d` 必配 `-p`、`-c` 空白、`-n`/`-t`/`-T`、缺清单；这一段**尾上是解释器回退那一问**（它的答案改变下发行，长度判据量的是下发行，所以它是取值的一部分；判据：**答案改变后面判什么→取值；答案只是允许或叫停→人点头**）。
4. **判决**——危险命令。禁止档是结论（当场结束），提醒档是结论后紧跟的一问。**判决之前先确认判据表齐不齐**（规则文件在不在、那一类关键词空不空）：判决要用它，不齐就按 ADR-0034 决定七单列口径报「工具没能力判断」，不报「你参数错了」。**判据表是工具自带的，不是使用者给的材料**；它「齐不齐」仍由解析站判（ADR-0034 决定一），这里只说这件事要排在判决之前报。
5. **材料可达**——脚本、上传源、下载目录、清单文件读得到、非空、非二进制、是 UTF-8。
6. **材料内容**——CSV 语法、表头、凭据预检、逐行补齐、上传源清点。
7. **人点头**——`--sudo` 撞 `--no-shell`、english 撞中文代填、上传内容树、并发建议、参数屏与确认问句。

**三、三处归层与老版不同。** 这三处与老版相反，依据是第二条的层序，不是偏好：

- **`-n`/`-t`/`-T` 属第三层**，不是最后。老版把它们放在整段末尾，是代码顺序的副产品；按层序，取值排在材料之前。
- **判决排在材料失败之前**。判决只用得上命令原文或脚本正文——**正文不是材料**：正文是 `-c` 的值或脚本文件的内容，材料是脚本、上传源、下载目录、清单这几份文件。正文拿不到时判决不成立，按第二条那个例外报「读不到」。可见的代价：`-c "rm -rf /" -f /nope.csv` 老版报「清单读不到」，本文报「禁止命令」。
- **缺清单属第三层必填**，不是「材料内容」的读失败。老版把它交给系统报 `open : 没有那个文件`，主语错、也没有下一步。

**四、报出顺序不等于站序。** 判定归属不动（ADR-0032：校验归最懂材料的那一站，裁量全在闸门；ADR-0034：拒绝只在闸门造），但**谁先说**由层决定。

**五、落地四样。** 落地形状只有这四件事：

- **「起不来」不进纸。** 解析站照旧读（判决要用正文、屏要用节点），材料失败不当场报；但它不再装进那张纸，而是与纸一起交出去——塔尖的结局从「纸 / 起不来」二选一，变成「纸 ＋ 可能附一条延后的起不来」。纸仍然只装「计划已成形」的东西，ADR-0034 决定四那条不动。
- **闸门多收一个参数。** 闸门按层判一至三层与第四层判决；塔尖把「这次别出屏」作为参数递进去，闸门据此跳过第七层确认段直接放行。闸门不知道失败是什么、也不需要知道——它只知道这一趟不用问人。
- **带延后项时，第四层那一问照问**（危险提醒档）：它在判决层，材料失败在它之后，所以使用者会先答一个注定作废的「继续？」。不为这一处白问让闸门多判一次「这一问该不该出」——那会把第四层和第七层绑在一起。
- **塔尖按三种情形收场**：拒绝 → 报拒绝；放行且带延后项 → 报它、按「起不来」退；放行且不带 → 往下走。塔尖仍不判断，只认这三样。

**闸门不拆两段**。一度以为要拆，是因为把「材料内容」排在判决之前；判决提到材料之前以后，失败永远发生在确认之前，一段就够。多出来的那个参数，是本文唯一付出去的接口宽度。

**六、提示的写法四条。**

- 主语＝出问题的那一格。
- 三句：哪一格错了 / 为什么（系统原话或判断）/ 下一步。能改的那类给「改哪个字」；结论类（禁止档、判据不全）给能做的那个动作（换掉这条命令 / 补齐哪份文件），不强求「一个字」。
- **在列举「你给了什么」的场合，不许出现使用者没敲过的东西**。`--gen-key -c ls` 报「同时给了 -c、-r」，那个 `-r` 是工具自己补的自动备注——两版都这么报，都不合这条。建议句里提到别的选项不受此限。
- **判据不猜，但可以补方向句**：`-s "ls -l"` 判不了他是想执行命令还是想跑脚本，所以仍然说「`-s` 要一个脚本文件，`ls -l` 不是文件」，再补一句「要执行命令请用 `-c`」。补方向句，不改判据——猜着拦会挡住合法写法（ADR-0025 的教训）。

**七、意图判不出就不判。** 工具只保证「我判得出的那件事说清楚」。「勺柄喝汤」是使用者的自由：值合法就照跑，值不合法就按第六条说清哪一格、下一句给方向。

**八、顺序的验收是期望表，不是 `KNOWN_EXPECT`。** 一行一条：输入 → 该先报的那一格。范围三样，不再多：① 实测出差异的那 39 条；② 每对相邻层各一条底线；③ 同层只配「必须互斥」的那几对。**不做同层全组合**——第三层十几项两两上百对，写不完也维护不动。它钉的是「正确答案」，不是「和谁一致」。撤掉的是「把差异登记成已认下」这一用法，不是撤 A/B 比对本身——切换那一档的「逐字比对最近一次通过」（ADR-0038 可切门槛第三条）照旧，两样不互相替代。

**九、`--yes` 只关「问」，不关「说」。** 分类的判据是**这句话在陈述谁**：

- **陈述「工具对这次输入做了什么、没做什么」的是事实**，照说——表头被移除、清单里配了私钥但没加 `-k`（工具这次没拿它）。
- **陈述「你以后该怎么做」的是教学**，在 `--yes` 下不说。

老版一刀切静默，按本文的目标改。

## 理由

- **把「正确」定义成可执行的一句，是为了不再靠老版背书。** 「像老版」在 2 条上是错的，「两版一致」在 25 条上是错的；只有这条判据对两种情形都成立。
- **分层比逐条排队稳。** 判据会加，队会变长；层不会。新加一条判据只要答「它是不是另一条的前提」，位置自己落。
- **判决排前、解析排后，是为了不白花。** 一次注定被拒的运行不该去解密凭据、解析 CSV——那两件事在 1000 台时是实打实的开销。
- **提示的主语规则来自现场**：使用者拿到「清单读不到」，会去建清单，而他真正的问题是多给了一个 `-p`。这不是措辞问题，是那句在说另一件事。
- **`--yes` 关问不关说**：他要的是「跳过确认」，不是「别告诉我你改了表头」。静默一份被工具动过的输入，比多说一句更糟。
- **不改红线**：顺序的毛病不需要新的权力分配，只需要换报出的位置。ADR-0032 那五条一条都不用动，这是本文能与现有结构共存的原因。

## 影响

- **纸不加格，解析多交一样**：材料失败不进 `Plan`，与纸一起交给塔尖。ADR-0034 决定四与 ADR-0035 都不用动；纸仍然只装「计划已成形」的东西。
- **闸门签名宽一格**：多收一个「这次别出屏」的参数。出口仍只有一个，红线不动；但「出不出屏」的知情权从闸门挪到了塔尖。
- **塔尖多一段编排**：拿到纸与延后项 → 闸门判 → 有延后项就报并退 → 否则照旧。塔尖仍不判断，只搬。
- **ADR-0032 决定五「解析递回四种结局」里「信封→进流水线」这一半不再无条件**：解析递回纸、闸门也放行，但另附一条延后的「起不来」时，塔尖报它并按「起不来」退。已在 0032 末尾追加更新记录指向本文。
- **该议题原交接文件（已删）的几条改法不再约束**，包括它「倾向第一条」那个版本——本文是那条路的收紧版：不是「把起不来延后」一句话，还要按层把取值、必填、判决各归其位。
- **老版的四处不合本文**：`-t`/`-n` 与清单的先后、`-s` 塞命令时主客颠倒、互斥提示里的 `-r` 影子、缺清单交给系统报 `open :`。这四处按本文改，不回退到老版。
- **一条可见的行为变化**：禁止档命令与读不到的清单同时给时，先看到禁止框（老版先报清单）。
- **37 场 A/B 不受影响**：场景表里没有一场走这条分支（`-f` 全是存在的文件，参数也都合规）。
- **`--yes` 的行为有变**：表头移除、私钥未用这两类提示会照印。使用者能感觉到，切换时要在 CHANGELOG 写一句。

## 代价

- **站序不再一眼看懂**：解析→闸门→执行，中间要「读在前面、报在后面」。新读者会觉得别扭，所以这条必须靠本文解释，不能靠代码自明。
- **闸门多一个参数**：它从此知道「这趟要不要问人」，而那本来由它按纸自己判。参数只有一个调用点，但它是本结构里第一个「开关式」入参——以后每加一个「这趟特殊处理」，都会有人想再加一个布尔，复审时要盯住它有没有长成第二个、第三个。
- **期望表要人维护**：每加一条判据，加一行；漏加不会红，只会让某个组合漂走——这是这套办法唯一的软肋。
- **判决提前会遮蔽材料问题**：致命命令 + 清单读不到时，先看到禁止框，看不到清单错。认这个代价，因为清单在那一刻没有意义。
- **带延后项时第四层那一问照问**：危险提醒档在判决层，材料失败在它之后，所以使用者可能先答一个注定作废的「继续？」。老版也是这样，本文不改。
- **`--yes` 下会多说几句**：表头、私钥那两类提示会出现在自动化日志里，可能显得吵。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 照老版逐字复刻 | 老版自己在这条判据上错了两处（`-t`/`-n` 先于材料），复刻等于把错也搬过来 |
| 认下差异，写进 `KNOWN_EXPECT` | 它是免责不是判据；切换后 25 条组合仍把人指向「去建一份清单」 |
| 把材料检查搬进闸门 | 撞 ADR-0032 决定一（校验归最懂那份材料的那一站），闸门变「又读又判」，依赖表跟着宽 |
| 把延后的「起不来」塞进纸里一格 | 省一个返回值、闸门的签名不动；但纸里从此能装失败，ADR-0034 决定四「起不来不进信封」从签名保证退成「谁都得记得看那一格」，而漏看不会红——省下的是一行签名，换掉的是一条机械能守的约束 |
| 闸门拆「判」与「确认」两段 | 判决提到材料之前以后，失败永远在确认之前发生，一段就够；拆两段要改红线（ADR-0037 出口白名单），代价白付 |
| 闸门保持一段，把确认屏挪到塔尖 | 塔尖造不出拒绝类型（ADR-0034 决定三），屏的判定归闸门，挪过去等于给塔尖开口子 |
| 解析站直接判前四层（判断是知识、散着不怕） | 「能说不的只能一处」；且同类话会两处成形，改口径必漏一处 |
| 只在解析站内重排（材料挪到全部合规之后） | 闸门那一段是一整块，材料要么全在它前、要么全在它后；「判一半」做不到 |

## 复审时请重估的

- **层归属是推导**：`-n`/`-t`/`-T` 放第三层、回退问放第三层尾、缺清单放第三层必填，这三处没有作者逐条表态。重估方法：用第一条判据构造同时触发两条的输入，看哪一条先报之后另一条落在哪一层。
- **「判决先于材料失败」只在一种组合上有观测**：危险命令与读不到的清单同时给。实测到的是老版行为（先报材料）；本文选了相反的一边，理由是「注定被拒的运行不白花」，**这条理由未实测**（没有量过解密与解析的耗时占比）。
- **「延后项 ＋ 闸门参数」未实现、未验证**：跳过确认段之后，屏、`--yes` 那行、上传并发建议都不出——这与老版在材料失败时的表现是否逐字相同，没有跑过。
- **`--yes` 那两类现在有判据，但还没有样例表**：判据是「这句话在陈述谁」，「上传树里少了什么」这类新提示归哪边要试一次才准；`--yes` 下会多几行，需实跑确认不吵。
- **`-r` 影子与 `-c`/`-s` 主客是措辞层**，本文只立了规则（第六条），没有落具体句子；它们的实际改动可能落在措辞迁移那一批（4.2），不在本议题。
