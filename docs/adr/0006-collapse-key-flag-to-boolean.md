# ADR-0006: `-k` 从三态压成一态

- **状态**：已接受
- **日期**：2026-09-24

## 背景

`-k` / `--key` 原先有三种用法，靠"有没有带值"区分：

| 形态 | 含义 |
| --- | --- |
| 不写 | 强制空密钥，清单第 5、6 列整体忽略 |
| `-k`（裸写，无值） | 逐节点按「清单第 5 列 > 配置 `account.key`」解析私钥 |
| `-k <路径>` | 所有节点统一用命令行给的这把私钥，忽略节点自带的私钥与口令 |

这套设计的问题不在能力，在**入口**：用户要先知道"裸写与带值不一样"才会去用第二种，而这两种形态在帮助里只能写成一长句；同时"统一私钥"这个能力被绑在命令行上，用户为了"随时能加 `-k`"还得在配置里预置一份私钥路径。

## 决定

`-k` / `--key` 压成**布尔开关**，只保留一个含义：**这次用密钥登录**。

私钥路径的取值顺序固定为「清单第 5 列 → 配置 `account.key`」。原第三态（`-k <路径>` 统一私钥）的能力由「在配置里配一把默认私钥」承担。

与此连带：**密钥认证失败不再回退密码**（另见 ADR 中的认证口径）。密钥就只是密钥，密码就只是密码。

## 理由

"三态"是**同一条命令行上塞了三件事**：用不用密钥、私钥从哪来、要不要统一。压成一态之后，用户只需知道一句话——**要用密钥就加 `--key`，私钥写在清单第 5 列（或配置里配一把）**。

原第三态的能力没有消失，只是换了承载位置：它本来的语义就是"全局统一"，而配置天生是全局的；放在配置里比放在命令行上更贴合它的性质。

## 影响

- 命令行的三态判定（以及 `-k` 后随参数的预处理）整块删掉，`Args` 上只剩一个布尔
- 帮助表里 `-k` 那行从"三态说明"变成一句话
- 清单的凭据检查范围随这个开关变：不带 `-k` 只查前 4 列；带了 `-k` 额外查第 5 列（含"配置里也没有默认私钥"的情况，报错退出）
- 旧写法 `-k /path/to/key` 会变成"路径被当成多余参数"，直接报错。**不设兼容、不做迁移提示**

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 保留三态，只在帮助里写得更清楚 | 概念数没减少。用户仍要记住"裸写与带值不同"，而这是最容易被忽略的一类差异 |
| 用两个开关（`--key` + `--key-path <路径>`） | 多了一个参数名、一组互斥规则，还要求用户理解"路径是全局而不是逐台的" |
| 保留 `-k <路径>`、去掉裸写 | 裸写才是高频（逐台私钥很常见）；而统一私钥放配置里比放命令行更自然 |
