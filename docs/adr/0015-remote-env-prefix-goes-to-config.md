# ADR-0015: 远端环境前缀改为配置驱动（`[execution] env`）

- **状态**：已接受
- **日期**：2026-10-09

## 背景

下发命令的外壳在起解释器之前，会先往远端导入一段环境变量。这段内容此前是代码里的常量 `envPrefix`（`internal/ssh/command.go`）：

```
export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin;
```

它解决的问题是真的：SSH 非交互会话拿到的是**目标机自己的默认环境**，各机器不一样——locale 不同会让同一条命令在一台机器上输出正常中文、在另一台变成乱码，排序与数字格式也跟着变，于是「同一批机器跑同一条命令」的输出**没法逐字比对**，报告里的失败分类也可能失准；`PATH` 则常常只剩 `/usr/bin:/bin`，而 `sudo` 在 `/usr/sbin`、`python3` 常在 `/usr/local/bin`，不补就是 `command not found`。

写死有三个问题：

1. **用户改不了**：目标机的 locale 不是 `en_US.UTF-8`（或想用 `C.UTF-8`）时没有出口；想额外补一条（如 `DEBIAN_FRONTEND=noninteractive`）也没出口。
2. **"统一"的力度不由用户定**：有人要的就是这四条，有人一条都不想要。
3. **想整段不要，只能加 `--no-shell`**——但那连外壳与执行身份（`sudo`）一起剥掉了，过重。

## 决定

1. 配置新增 **`[execution.env]`**（进阶配置）：一行一个，写成 `名字 = "值"`。出厂给出四条：

   ```toml
   [execution.env]
   LANG   = "en_US.UTF-8"
   LC_ALL = "en_US.UTF-8"
   PATH   = "/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
   TERM   = "dumb"
   ```

2. 前缀在**参数解析阶段**拼一次、存进 `Args.EnvPrefix`（与既有的 `Args.Interpreter` 同一手法）；长度检查、`batch` 拼装、日志三处读的是同一个值，执行侧不回头读配置。
3. 拼装规则（`ssh.ExportPrefix`）：键名**排序**后拼成 `export K1=V1 K2=V2;`；**`export` 与 `;` 由工具补**（用户只写 `名字 = "值"`）；值**按需加引号**（shell 安全字符裸拼，含空格等才包单引号）。
4. **空表 = 不导入**（下发行里没有 `export` 段）；但**外壳照旧**——`sh -c` 结构不动，只是里面那段变空。
5. **校验**（启动即拦）：键名必须是合法 shell 变量名（`[A-Za-z_][A-Za-z0-9_]*`），否则报错并点名；**空键或空值一律丢弃**——值留空 = 关掉这一条。
6. **`--no-shell` 不读这份配置**：它是"原样下发、工具不附加任何东西"，环境与身份都归目标机。
7. 出厂配置放在**进阶配置**段（它属于进阶知识，不是开箱必改的那几个）。

## 理由

- **为什么可配**：那段环境的目的是"让一批机器的结果形态一致"，而"一致成什么"取决于用户面对的机型。做成配置后，出厂值让开箱行为不变，想出格的用户有出口；同时也给了"整段不要、但保留外壳与 `sudo`"这个此前不存在的选项。
- **为什么用子表（`名字 = "值"`）而不是两个固定字段**：与既有的 `[interpreter.script]` 同款；变量名不限、想加就加一行，不写死"只有 locale 与 PATH 两个"。固定字段想加第三个就没地方放。
- **为什么用 `export` 内建，而不是 `env` 外部命令**：实测 `env 123=x cmd` 确实能设任意名字（含数字开头），但 `env` 是**外部程序**，要靠 `PATH` 找得到——工具一贯的取向是"目标机只要 `/bin/sh` 在就能跑"，为一个极窄的场景引入外部依赖不划算。代价是**变量名必须守 shell 的规矩**，于是把它做成启动期校验（`123`、`A-B` 这类当场报错、点名）。
- **为什么键名排序**：TOML 子表在程序里是 map，遍历顺序随机；不排序会让同一份配置每次拼出的串不同，日志与 A/B 比对出现无端差异。
- **为什么值按需加引号**：无脑加引号会让出厂那四条变成 `export LC_ALL='…'`，而它整体又在外层单引号里，经 `shellQuote` 转义后在日志里显示成 `'"'"'` 一堆噪声。按需加引号——出厂的四个值全是安全字符，裸拼，形态与过去一致；只有含空格这类才单独包起来。

## 影响

- **常量 `envPrefix` 删除**；`ssh.BuildCommand`、`ssh.InteractiveCommand`、`ssh.DescribeCommand` 都改收 `envPrefix`（`DownlinkSpec` 与 `DescribeInput` 各加一格）。
- **日志与报告的「说明」一行不再枚举变量名**（改为"先导入配置文件里的环境变量"）——具体是哪几个、值是什么，「命令行」那一行已逐字给出。
- **出厂配置多了 `[execution.env]` 段**；老配置缺这段会在启动时报「配置缺少必填字段」（作者口径：不提供兼容）。
- **`--sudo` 下变量在 `sudo` 之前导入**，能否穿过 sudo 取决于目标机 sudoers（多数发行版保留 `LC_*`；`PATH` 由 sudo 的 `secure_path` 决定）。不带外部依赖就修不了这一点，文档已写明。
- **`--no-shell` 语义不变**，只是明确"它不读这份配置"。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 两个固定字段（`env_locale` / `env_path`） | 写死"只有这两个"，将来想加第三个没地方放；而子表本就能"单独删一行" |
| 用 `env` 外部命令 + 任意变量名 | 引入外部程序依赖，与"目标机只要 `/bin/sh` 在就能跑"的取向冲突；"数字开头的变量名"实用面极窄 |
| 配置里写整段 shell 片段（`export …;`） | 无法做防御性校验——`123` 作为 shell 片段语法上合法，工具无从判断用户是不是写错了；且要求用户懂 shell 语法 |
| 值一律加引号 | 出厂四条会变成 `'"'"'` 噪声，日志难读 |
| 不排序、直接遍历 map | 同一份配置每次拼出的串不同，日志与 A/B 比对失真 |
