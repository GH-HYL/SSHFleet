# ADR-0011: 批量改密接入既有交互底层，按第 5 档执行模式

- **状态**：已接受（尚未实施）
- **日期**：2026-09-29

## 背景

目标机密码过期时，工具连得上、会话也建得起来，命令却被 PAM 拒下——这类机器已经能被归到「密码过期」（ADR-0004 / ADR-0005）。批量改密要做的是：让工具自己把这批机器改掉，而不是让运维逐台手敲。

实测（`docs/issues/remote-password-change/spec.md` 第五节，2026-09-28 真机）已经把这个场景的形态钉死：

- 改密对话在 exec 会话内**真实出现**，顺序固定：当前的密码 → 新的密码 → 重新输入新的密码 →「passwd：已成功更新密码」；
- 改完之后**原命令不执行**，会话直接结束、退出码 0——改密与执行是两次运行；
- 弱新密码会被 PAM 拒并**重问**「新的密码：」，改喂强密码仍能成功；
- 走完改密需要 PTY（无 PTY 时同一场景是「密码过期」拒绝）。

同期代填（`--answer`）刚刚落地，它的交互分支已经备齐了这次要用的全部底层：PTY 200×50、正文 base64 编入命令行（ADR-0010）、写侧钩子（去 `\r` + 落缓冲 + 喂匹配器）、超时与中断的等价包装。

一条绕不开的前例：**ADR-0003** 决定「执行模式判定不做集中化」，其全部理由建立在**「后续不再新增模式」（用户 2026-09-15 明确）**这个前提上。本次要加第 5 档执行模式。

## 决定

**改密按第 5 档执行模式接入既有主干，复用交互底层；只对语义真正不同的两处另起实现。**

1. **模式**：`--change-password <密码>`（无短选项）与 `-c`/`-s`/`-u`/`-d` 五选一互斥；模式名 `passwd`（归档目录名 `<时间>_passwd`）。
2. **复用**（一律照用，不抄）：PTY 尺寸常量、`connectFor` / `applyBanner` / `lockedBuffer` / `trimOuterBlankLines` / `extractExitCode`、写侧钩子去 `\r` 的手法、超时与中断包装的契约。
3. **分叉**（新写，不动代填的既有实现）——这是「开分支」的准确边界，只有两处：
   - **匹配器**：代填一条规则只送一次（命中即 `done`）；改密要**可重复消费、带上限**（弱密码重问）。
   - **收尾判定**：代填判「触发词未命中」；改密判「是否出现过期信号」。
4. **提示词表**：`config/passwd_prompts.conf`（TOML），只配「提示原文 → 该喂哪个值」（`current` / `new` 两个枚举），值本身不进配置。**定位是过渡形态**——跑稳之后多半写回程序里写死。
5. **取值**：随 `credential.encrypt` 开关——`false` 时参数就是明文密码，`true` 时是密文文件路径；不做「文件还是文本」的自动判定。

## 理由

**为什么共享「怎么把字节送进去」，分叉「什么时候送、送完怎么判」。** 判断能不能复用，看的是**语义是否相同**，不是代码像不像。送字节这件事（PTY、钩子、超时、中断）两条路语义完全相同，占那条路的绝大部分；照抄一份出来，日后 PTY 尺寸或 `\r` 手法一改就要双端同步。而"什么时候送"这两条路**方向恰好相反**：代填的「密码过期」是**中止词**（命中即杀会话），改密的同一批关键词是**入场信号**（命中才开始喂）；代填一条规则只送一次，改密要重复送。把这两件事塞进同一份实现，等于让一个共用件同时服务两种互斥语义——任何一侧的需求变化都会牵动另一侧，而代填那条路刚验收不久。

**为什么不把改密做成独立工具模式**（像 `--gen-key` / `--convert-secret` 那样处理完即退出）：它要走清单、并发、超时、归档、报告、失败分类统计——这些全在批量管线里，另起一套等于把管线复制一遍。

**为什么提示词表放配置**：提示文案随目标机语言与 PAM 版本变，撞到新措辞时要能当场补一条、不必等发版。它只是调试期的便利，不是承诺的配置项。入场信号不在这份文件里配（取判据文件「密码过期」分类）——两处同时能配就是两份真相。

**为什么不借这次做模式判定集中化**：ADR-0003 列的 7 处判定点本次确实要逐处各加一路，代价是真的。但本次要交付的是改密，不是模式判定重构；《个人开发规范》二明写"发现缺陷可以排期整改，但不得据此发起未授权重构"。

## 影响

- **与 ADR-0003 的冲突（显式指出，不静默覆盖）**：ADR-0003 拒绝集中化的**唯一前提**是"模式集合已封闭"，本次加第 5 档使其**失效**。处置：ADR-0003 状态改记为「已被本 ADR 修正前提」；其结论（维持分散判定）本次仍照办，但该 ADR 里"后续架构审查不必再提此项"一句不再成立——**新增模式的成本现在是真的**。是否重开集中化，另立议题，不在本次范围。
- **模式文案要逐处核对**：第 5 档进 `ModeName()` 后，报告「执行参数」、归档目录名、执行期日志文案、统计三档口径（execute / upload / download）各处都会多一个取值要交代。
- **新密码进 argv（固有代价）**：明文状态下 `--change-password <密码>` 会让密码出现在**进程命令行**里，目标机/本机的 `ps`、auditd 都能读到——与 ADR-0010 记录的 argv 暴露面同源。工具能做的是日志、报告、参数屏一律按 `common.MaskSecret` 脱敏（明文密文都脱），**挡不住 `ps`**。
- **不进危险命令检测、没有下发长度上限**：改密不执行任何用户命令（实测 M3），下发的是固定形态的 `exec :`。
- **未过期机器计入失败数**：批量里"大部分机器不需要改"时，统计会以失败为主。这是刻意口径（`error` 写明「密码未过期，跳过改密」+ 退出码置 nil）。为免落进「未归类」提示，另补一条 conf 分类。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 用代填 `-a` 承载改密 | 2026-09-28 已裁定拆分：改密对话顺序固定、改完命令不执行，写死流程更简单；且不该让用户为改密配触发词 |
| 照抄一份交互分支实现给改密 | 复用面（PTY / 钩子 / 超时 / 中断）占那条路绝大部分，复制即双份维护 |
| 扩展现有 `cursorMatcher` 加「可重复」参数 | 让刚验收的共用件同时服务两种消费语义，一侧变化即双端回归 |
| 不匹配、按序盲喂（依据是"喂入在 tty 缓冲排队、喂早无害"） | 未过期机器上分不出「没有对话」与「对话没喂成」；会话里若另有一个密码提示（sudo 等），盲喂会把新密码当字面字符喂进去 |
| 把 `--change-password` 做成独立工具模式 | 清单、并发、超时、归档、报告、统计全在批量管线里，另起一套等于复制管线 |
| 借这次把模式判定集中化（回应 ADR-0003） | 属未授权重构，且会把"交付改密"与"重构模式判定"混在同一次改动里 |
