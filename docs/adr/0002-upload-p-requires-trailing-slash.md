# ADR-0002: 上传模式的 `-p` 一律要求绝对路径且以 `/` 结尾

- **状态**：已接受
- **日期**：2026-09-11

## 背景

`-p`（目标位置）的方向随执行模式反转：

- 上传模式：`-p` 是**服务器上的目录**
- 下载模式：`-p` 是**本地的目录**

上传单个文件时，远端路径写成 `/opt/app` 还是 `/opt/app/` 在技术上都不算错，语义上却可能被理解成两种东西。

## 决定

上传模式下，`-p` **必须同时满足**：绝对路径、以 `/` 结尾。

**与 `-u` 指向文件还是目录无关，一律要求。**（旧实现的注释写的是"`-u` 是目录的情况下"，但实现是无条件要求——本 ADR 明确以**无条件**为准，并修正注释。）

## 理由

`-p` 以 `/` 结尾是一条**消歧义约束**：它断言"这是目录"。由此排除两种误读：

1. 用户以为远端路径是**文件名**（会被重命名）
2. 用户以为可以借这里指定远端的目标文件名

工具**不做远端重命名**，`-p` 只表示"放到哪个目录"。强制 `/` 结尾让这个语义在命令行上就自明，不需要用户去读文档。

## 影响

- 上传单个文件时也必须写 `/opt/app/`，初看略啰嗦——**这是刻意的，不要当成冗余校验删掉**
- 下载模式对 `-p` 的要求不同（必须是**已存在**的本地目录）。两侧口径不必统一：
  - 上传侧：远端目录由工具创建
  - 下载侧：本地目录需用户先建好（工具不替用户决定往哪写）

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 仅当 `-u` 是目录时要求 `/` 结尾 | 会让"单文件→目录"与"目录→目录"两套语义并存，反而更难记 |
| 不做要求 | 无法阻止"以为在指定文件名"的误读，且与"工具不做重命名"的事实冲突 |
