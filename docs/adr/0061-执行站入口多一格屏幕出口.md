# ADR-0061: 执行站入口多一格屏幕出口，让面板在用例里也画得起来

- **状态**：已接受（accepted）
- **日期**：2026-11-18
- **决策人**：
  - **作者明示**（2026-11-18）：「都得做，无所谓先后，开始吧，授权开工，你根据工作合理安排一下」——交接里 B 节写的就是这一条。
  - **执行者实测**：把 `run.go` 里 `closeNode` 的回填那一行注掉，全量仍然全绿（只在新增用例下才红），缺口是实的。
- **前身**：ADR-0060（执行站入口收落点纸）；ADR-0037 决定三（站的出口白名单）；议题 `docs/issues/2026-11-18-1103-执行站成功路径进默认套件/spec.md` 的 Implementation Decisions 第七条与 Out of Scope 第一条

## 背景

传输面板上「完成台数」曾经恒为 0：收口那一步没把结果交给聚合器，面板就永远显示 0。缺陷已修，但**默认套件守不住它**：非终端下 `screen` 一进门就退化成直通（`internal/execute/progress.go` 的 `transfer` 开头返回），`go test` 里面板根本不渲染。`close_node_test.go` 只测收口那个函数自己，不测谁在调它——把 `Run` 里那一行调用删掉，全量照样全绿。

## 决定

**一、`execute.Run` 增第四个参数 `screen io.Writer`。** 零值（nil）是生产那一路：流从 `console` 拿、按「是不是终端」决定画不画面板。递一个流进来：写那个流，并且照画——非终端也画。

**二、不进 `Landings`。** 那张纸装的是落点（两个路径），屏幕出口不是路径，是「谁在看」。ADR-0060 刚把落点收成两格，再塞第三种东西进去，这张纸就从「执行站写得着的地方」变成「随便装」。

**三、不新增类型。** 站的出口白名单只给「一个函数 + 一个类型」，那个类型位是替身插口的（`MatchOptions` 已占）。一个 `io.Writer` 参数不占位。

## 理由

**缺陷修好了不算完，得有一处红得起来。** 默认套件观测不到面板，等于这条路径没有守卫：下次谁把回填挪走、把聚合器的调用顺序改了，屏上又是恒 0，而测试全绿。给入口一个流，这条路才在 `go test` 里跑得起来。

**流是入口本来就有的东西。** 生产上它就是 `console.Writer()`；把它从「站内自己取」改成「可以递进来」，只是把已经在的那一格挪到参数上，不新增机制。

**零值即默认，塔尖不必知道这件事。** 塔尖传 `nil`，与今天的行为逐字相同；只有用例传流。

## 影响

- `execute.Run` 的签名多一格；七个调用点各补一个 `nil`（塔尖、四处站内用例、两处红线测试）。
- 两条红线测试只改调用点的实参，引用到的生产符号与断言数不变，按 ADR-0037 决定五**不算改红线**，指纹不动。
- 新增一条用例：上传跑完一趟，读注入的那个流，断言传输面板最后一帧写着「1/1 台完成」。

## 代价

- **入口多一格参数。** 它今天只有一个调用方（塔尖）与一批用例；多这一格的读法是「零值就别管」。
- **多一条要维护的用例。** 它连着假目标机，跑一趟真传输（约 0.1 秒）。
- **注入的流会被两块面板同时写。** 命令那一行与传输面板共用一个流（生产上也是如此），用例要按标签挑行，不能整段搜一个数——这一点写进了用例的注释，免得下一个人把断言写松。

## 退路

把第四个参数删掉、七个调用点去掉 `nil`、`newScreen` 改回收一个流（`plain` 回到只由 `console.IsTerminal()` 判），新增用例一并删除。撤回成本半小时，不属于「不可逆」。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 不守，靠人读调用点 | 今天的缺口就是这么来的：修好了没人知道哪天又被挪走 |
| 给 `console` 加一个「测试时换流」的钩子 | 生产包里留一个只有测试会调的开关，等于给所有包开了绕过 `console` 的门 |
| 用例跑在真 pty 里 | 要一台有终端的机器，Windows 侧还要额外的东西；测试从此挑环境 |
| 让面板在非终端也画（去掉 `plain`） | 重定向与管道的输出会被 ANSI 与重绘污染，使用者那头先坏 |
