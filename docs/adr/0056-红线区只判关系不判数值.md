# 红线区只判关系，不判数值

**状态**：已接受（accepted）
**日期**：2026-11-16
**决策人**：开发者 2026-11-16 16:17 原话「行 按你说的做 授权开工」——他拍的是「改」这件事，以及执行者先前报的那条顺序（先给 `internal/exitcode` 建表、再收窄红线）。**「怎么判」这一节的具体口径是推导**：零／非零留红线、数值搬自定义区、两种失败同码留红线。

## 背景

红线区只放结构（ADR-0032 第四条、ADR-0050）：它红了，意思应当是「有人把结构动了」。审计 `02-J1` 与 `11-J1` 各点了一次红线区里混着值断言，红线区第二轮（2026-11-12）清掉两处（结算的守恒关系、分隔线的「整行都是等号」），随后写下「今天扫过，没有别的值／版式断言」。

**变了一样，是工程设计：** 那次扫是按「版式与业务值」这一种口径扫的，漏了「退出码」。实测三处仍在：`guard/redline_exitcode_test.go:16-19` 钉 `0／1／1／130`，`guard/redline_tip_endings_test.go:27,44` 钉 `code != 1`，`guard/redline_tip_test.go:53,62,67` 钉 `code != 0`。而 `internal/exitcode` 自己一条测试都没有——**这些数现在只挂在红线上**。

## 决定

红线区判**关系**，不判**数值**：

- 允许留在红线的：成功收场为零、起不来与拒绝都非零、拒绝与起不来同码（这是老版既有行为，写进 `exitcode.Code` 的注释里），以及「哪一种收场」这件事本身有没有落到塔尖。
- 必须搬走的：任何具体数字。它们搬进 `internal/exitcode` 的自定义区，一张表钉四个数。

## 理由

- **零／非零是使用者能感觉到的**：脚本 `if sshfleet; then` 判的就是这一位。它属形状。
- **哪个数字是表里的取值**：1 还是 130 由 `exitcode` 一张表定，改它要跑那张表；挂在塔尖红线上，改一次码就红一次塔尖，红的原因还写着「结构被动了」——那是假信号。
- 判据的落点应当与被判的对象同处（ADR-0050 同一条理由）：红线红的时候只有一种解释、只有一个地方该被怀疑。
- `internal/exitcode` 现在零测试，这是本决策顺手补的一个洞：搬家之后那些数才有家。

## 影响

- 红线指纹变：`guard/redline.go` 里 `TestRedlineExitCodeTable` 的符号面会缩（不再引用 `exitcode.Kind` 的那四个常量），喊失败的次数也变；照报错里印出的那一行抄。
- `internal/exitcode` 新增 `exitcode_test.go`，属自定义区（跟着被测包走）。
- 塔尖的进程级红线（`redline_tip_test.go`）仍跑真进程，只是判「非零／为零」，不判 1 与 130 的分别。

## 备选方案

- **整条撤掉退出码那两条**：不行。`exitcode` 只有 Kind 与 Code 两样东西，撤了就没有任何判据在场。
- **红线里把数写成常量引用（`exitcode.Interrupted`）**：不成立——比的是 `Code()` 的返回值，常量引用绕不开「数是多少」这件事，只是把字面量挪了个地方。

## 复审

**已落实**：搬完跑过 `go test -count=1 ./...` 全绿（19 包），`go vet`、`go vet -tags integration`、`gofmt -l` 干净；`TestProjectIsClean` 零违规，红线 46 条在岗。

**未证实的一条**：「改一次退出码只红一处」没有实跑。落地时只验到「指纹按新口径更新、真工程零违规」；要证它，把 `Refused` 的码临时改成 2 跑一次——应当只红 `internal/exitcode` 那张表、`internal/guard` 全绿。这一步没做，留在这里。
