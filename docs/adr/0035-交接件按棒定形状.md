## 背景

工单 03 问的是「交接件宽结构一份，还是每种模式各一份」。谈下来发现两个轴被混成了一件：

- **纸按哪一维分**——按站分，还是按模式分；
- **纸里装什么**——这一棒交给下一棒的东西，是上游那份的子集还是另一个更小的集合。

这两个轴一旦分开，答案就自己出来了：**纸属于「站与站之间」，所以按棒定；模式是纸里的一种变化，不该把纸劈成五份。**

另一处模糊来自执行与结算：作者指出「执行过程中就需要整理」，因为每跑完一台就要按配置归类、刷一行到屏幕上。这不是两个站搅在一起，而是作者当时用的「整理」一词把两道工序合称了：**只依赖这一台的归类，和要依赖全体的汇总。**

## 决定

**一、信封只有一份，随站换三次口径。**

信封按「棒」定、不按模式定：整条线上只有一种信封结构，不是五种模式各一种。它换的是**口径**，不是结构——「要做什么」「发生了什么」「总共怎么样」。三张纸是按口径数的，不是三套不同的结构。

一句话记法：**一个信封、三次口径、五种装法。**

- **解析交闸门：口径是「要做什么」。** 解析站手里有配置全文、用户敲的整行命令、清单文件、日志开关；交出去只有七样：这次干什么活（五份载荷之一，含各模式参数与代填明细）、对谁做、执行参数（并发、超时）、判据表、执行资源（脚本、代填、清单文件的路径）、运行上下文（密文：执行命令、执行参数、备注）、解析时发现的问题。运行上下文是**原值通道，只给报告站解**（决定九）；别的站要什么，信里给什么，与它无关。配置全文和原始命令行**不进纸**——下游拿到了就会顺手用。**「原始命令行」指使用者敲的那一整行 argv（含参数与内联值）**；运行上下文里那一格「执行命令 / 执行参数」是下发给远端的东西，见决定九，两回事，别混。
- **闸门交执行：只加结论，不加数据。** 闸门不改任何一个已有字段，把「上一棒那张纸的全部字段 + 一句结论（过了 / 要人点头 / 不让走）」造成一张新纸往下递。**它加的是结论，不是数据**——这一格是本棒的产出，不算把纸变宽。**留痕是给日志看的记要，不是给使用者的句子**——使用者看到的话归报错构造点（ADR-0034 决定八）。
- **不让走的时候，纸不往下递。** 停在闸门；塔尖拿「拒绝」这个结论去做两件事：先调日志包记一笔，再退出。往下递的那条路上，只有「能走」的信封。
- **执行交结算：换口径，讲「发生了什么」。** 执行站手里有「要做什么」那张纸；交出去是每台机器的事实：原文、退出码、归到哪一类、超时没有、被取消没有。成败不在这里算（见决定九）。这张纸不再回答「这次要干什么」，只回答「刚才发生了什么」。
- **结算交报告：再换一次口径，讲「总共怎么样」。** 统计、分类分布、按类归拢的机器清单。原文跟着走，因为报告要贴。

口径一换，服务对象就换了：前三棒服务的是「这一批活怎么干」，后两棒服务的是「干完之后怎么说给人听」。

**二、载荷格五份，不合并。**

命令、脚本、上传、下载、改密各一份，各自判断。命令与脚本共用的那段、上传与下载共用的那段，各写一遍——作者认了这笔重复。理由不是「合并不好」，是**现在没有事实支持合并**（ADR 规范三.2 不许为以后可能要用预留抽象）；将来真出现「改了一处不得不改另一处」，再合并，那时是事实驱动。

**三、同一个口径往下传时，除本棒结论外，后一张不许比前一张多一格。**

这条只管前两棒——解析交闸门、闸门交执行，它们讲的是同一件事（要做什么）。**多出一格数据 = 这一棒偷拿了不属于它的东西**：要么那一格本该在上游就给（去上游加），要么这一棒在替下游做判断。至于结论格，每棒都该有，那是它自己的产出，不算变宽。

**给闸门立的意思是**：它除了结论那一格，一格数据都不许加。它不改数据，加数据的诱惑最大，加完还显得很守规矩。

**换口径的那两棒不受这条约束**：执行交结算讲的是「发生了什么」，本来就不该有「要做什么」的格子；结算交报告讲的是「总共怎么样」，也不该有逐台的原文以外的过程数据。对它们的要求是另一句：**只装下一站要用的，用不上的不许带。** 装不上是缺字段，去上游加；带多了是把下游用不着的东西塞进来。

**运行上下文不算「一格」**：它不是这一棒的数据，是原值通道（决定九），不参与这条的计法。

**四、单台归类留在执行里，全体汇总归结算。**

判据：**只依赖这一台机器的结算，放在执行里；要依赖全体才能算的，等跑完再算。** 归类只依赖「这一台的输出 + 判据表」，所以它必然长在执行里；把它挪到后面，只能靠回调，那是往回走。

执行交结算那张纸上装的不是「原始返回」，是「一台的结论」：原文、退出码、归到哪一类。

**五、判据表进信封，塔尖不单独递。**

它至少有两个人要用（执行侧认「密码过期」这类提示，结算侧看分类规则），而它只能由解析站读一次。让塔尖单独递，等于塔尖得知道「谁要哪张表」——编排知识一进塔尖，它就开始长肉。

**它进第一张纸**，也就是解析交闸门那张；后面换口径时，下一站还用它就跟着带，不用就不带。

**六、契约里不放函数。**

破例放一个校验，等于给「抽屉」开第一道门：有了第一个函数，第二个就有地方站。

**七、信封的合法性由闸门验。**

纸上写「上传」，格子里装的却是命令——这种对不上只在一处露头，验一次就完。它**算在「输入不合规」那一类**（ADR-0034 决定一），不另立一类。

**八、塔尖只搬不装。**

「不单独递」的边界落在这里：塔尖把信封原样交给下一站，不许往里塞格子，也不许把某一项从信里抽出来当另一个参数递过去。塔尖手上除了信封、这一棒的结论，以及入口那个编译期常量，不该有第四样东西。

**九、结果侧的纸由通用格、一个带标签的附加格、随行件三样组成。**（作者 2026-11-01 认下「通用格 + 带标签的附加格」，否掉了「五份纸各算一套」与「先归一成一种结果」。）

- **通用格**：五种模式都有的事实——IP、连接成败、连接耗时、执行耗时、分类、退出码、超时、取消、错误原文、原文。**「成败」不在里面**：它由结算站解释（分类是不是本模式的成功分类），有的模式压根没有退出码，不能拿退出码猜成败。
- **附加格**：一个，带模式标签，装这个模式多出来的东西。业务上的样子：命令与脚本装输出的解读，上传下载装文件数、字节数、目标，改密装每台走到哪一步、哪台要人工。
- **结算只算通用格**，附加格一个字段都不打开，原样递给报告。五套结果在结算这一步合成一份总账，同一条算法只写一遍。

**随行件是第二类格子，不是例外。** 站与站之间必须新造交接件、只装下一站要用的（决定三「最窄」）；可报告第一段要的「执行命令 / 执行参数」必须是使用者敲的**原值**，重新打包一遍就不叫原值了。原值要是一路直传，中间站就成了「拿到了、不用、也不处理，原样转手」——这正是「最窄」要禁的样子。两条规矩对着干，解法不是让哪条让步，而是**给它单立一类**：运行上下文（run metadata）不算数据格，因此不参与「后一张不许比前一张宽」的计法。解析站放进去，一路原样传，**只有报告站打开**。

**它只服务 `report.txt` 那一段，别的站不许用。** 别人要什么，闸门那张信里给什么——并发、超时、代填明细都在信的数据格上，跟这一格没有关系。判据表也一样，各站本来就该读。

**怎么封：密文，不靠自觉。**（作者 2026-11-01 提的，签下「这是野路子」）解析站把上下文加密成一段字节放进纸上，报告站解开才用；密钥就写死在加密与解密两处、各写一次，不留变量、不往下传。这样别的包拿到那格只是一段看不懂的字节，想拿值得先把密钥抄过去——**拦的是顺手，不是存心的**。字段旁用备注写明用意：这一段是防着旁人从上下文里取值的，只有报告站解得开。

**为什么不靠字段访问检查**：那要类型信息，比现有几类检查都重，还得常驻。密文这个法子不需要新判据，代价是报告站多一次解密、调试时看不见明文。

**加密与解密两段代码住哪儿，建站时按横切包权限表定**：要么单独立一个小包、在依赖白名单里只放解析站与报告站进来（这样连「抄密钥」都得先违规加一行 import，机械扫得出来），要么两边各写一遍（省一个包，但改算法要改两处、写歪了当场对不上）。密钥同样写死两处，改一处漏一处，一跑就露。

## 理由

**为什么信封不能按模式分**：信封属于「站与站之间」，模式是纸里的内容。按模式劈纸，等于每个站要开五个口子，加第六种模式每个站再多一个——**那是往浅模块走，不是往深模块走**。深模块要的是「一份纸、一种进法」，背后把五种模式的差别吃在自己肚子里。

**为什么「一样宽就不该造两次」**：两站之间要是没有东西被过滤掉，这道边界其实不存在。抄一份一模一样的，只会让「改一个字段要改两处」凭空多出来一次，而且会让下游误以为「我只拿到该拿的」——其实上游早把整本账递过来了。

**为什么归类不能往后挪**：它只依赖一台，不依赖全体。挪到结算站，要么得在执行过程中回调（反向依赖），要么得等全部跑完才刷屏（体验退化）。两条都比现状差。

## 影响

- **执行站变重**：要背判据表，要算归类。这是「单台归类留在执行」的直接代价。
- **刷屏是一条旁路**：执行过程中被打、不控制生命周期，与主链方向无关。它由执行站直接交给终端输出包，**不经过塔尖**；具体怎么刷是 13 号。
- **05 号少一个悬念**：塔尖不做「谁要哪张表」的编排，判据随信封走。
- **07 号多一条可机械验的**：交接件的字段集合，除本棒结论外，必须是上一棒的子集。**2026-11-01 重估：改为可核**——判据是「闸门那张纸的字段集 = 解析那张纸的字段集 + 一个叫 `Conclusion` 的格子」，只核同一口径那一段。代价是结论格子在同一口径那两棒上要同名（见 07 号工单的更新记录）。
- **给 0032 决定三补了边界**：那条只说「必须新造」，没说新造的要更窄」；不补，新造就会退化成抄写。
- **加一格不是一处也不是满仓库**：通用格是「契约定义 + 执行填 + 结算算 + 报告读」，附加格去掉结算那一处，要回头从解析拿就是改一整条线。删比加安全——删了没跟上，编译就报。

## 代价

- **重复**：命令与脚本、上传与下载共用的段落各写一遍。作者明示认下。
- **一改改一条线**：信封更厚、判据进纸，改一个需求要动的站更多。作者认这是重构的必然代价，不是副作用。
- **三次换口径 + 五份载荷 = 结构件变多**：读代码的人要先弄清「这一棒在哪个口径上、信封里那一格装的是哪种活」。
- **报告的表格可能与确认屏各写一份**：确认屏在闸门（最前面），报告站在最后面，两者要打同样形状的表。省这一份就得让闸门反向依赖报告站，不划算。
- **闸门要验信封合法性**，它比「只看问题清单」多一道活。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 五种模式五个信封 | 每个站开五个口子，加一种模式口子再多一个；深模块要一种进法，不是五种 |
| 命令与脚本合一、上传与下载合一（三份） | 现在没有事实支持合并，是预判。以后真出现「改 A 不得不改 B」再合，代价更低 |
| 全流程一个大兜，谁用谁取 | 下游拿得到全部字段，就会顺手用；「不许跨阶段回取」当场失效 |
| 归类放到结算站，执行只交原始返回 | 要么回调（反向依赖），要么延迟刷屏（体验退化） |
| 契约里放一个校验函数 | 契约一旦有行为，抽屉就有了第一道门 |

- 2026-11-03：决定九那句「**结算只算通用格**，附加格一个字段都不打开，原样递给报告」**作废**。开发者当日口径：「这个决策是错的，五种模式，各有特殊情况，他们的信息都在附加格上，不然看附加格，自断臂膀，这个约束作废。」理由是这条把结算站的手绑死了：五种模式的特殊事实（上传的文件数与字节数与目标、改密每台走到哪一步、哪台要人工）全装在附加格里，而总账本来就要按模式出这些数；不许打开，等于逼结算站要么算不出来，要么绕开纸回头去问执行站。**新口径**：结算站**可以**读附加格里的字段，按模式算它该算的东西；**「附加格原样递给报告站」这一半不变**（报告站要贴明细，附加格不能在这一棒被消费掉）；「五套结果在结算这一步合成一份总账、同一条算法只写一遍」这条用意也不变——能复用通用格的地方仍复用，加模式时该写的是那一个模式的差异，不是另起一套总账。落点与连带：`internal/settle/settle.go` 的包注释（原先照抄那句）改成现行口径；`internal/guard/redline_settle_test.go:49` 的注释跟着改（断言不动——它判的是「附加格原样传下去」，与新口径一致；改注释不算改红线，ADR-0037 决定五）；建站 04 的 14 号单 `## Comments` 与议题 `spec.md` 各追加一条；上一张图 `docs/issues/2026-10-30-2134-架构重构/map.md` 与 15 号工单 `## Answer` 里同一句话随之不再约束（那两个文件是历史记录，按「只追加不原地改」留原样，以本条为准）。
