# ADR-0003: 执行模式判定不做集中化

- **状态**：**已被推翻**（2026-09-29）—— 拒绝集中化的唯一前提「模式集合已封闭」已被 ADR-0011 打破，结论不再成立。见文末《2026-09-29 推翻》。
- **日期**：2026-09-15

## 背景

执行模式（execution mode）有四档：命令（`-c`）/ 脚本（`-s`）/ 上传（`-u`）/ 下载（`-d`），四者互斥，每次只选一种。

判断「本次是哪一档」的方式，是看这四个字段哪个非空。这段判定分散在多个包，且同一事实存在**四套口径**：

| 口径 | 取值 | 用在哪 |
| --- | --- | --- |
| 四档中文名 | 命令 / 脚本 / 上传 / 下载 | batch 执行期日志、报告「执行参数」栏 |
| 四档英文名 | command / script / upload / download | 历史记录目录名 |
| 三档统计名 | execute / upload / download | 结果统计（命令与脚本合并为 execute） |
| 两分类 | 执行类 / 传输类 | 成功分类、报告里超时行的措辞 |

2026-09-15 的架构审查提出把判定收敛到一处——在 `cli` 上做一次类型化判定（先例是同一个包里的 `KeyMode()`），其余包消费枚举而不看裸字段；并顺带把四套口径的映射表放在同一处。

## 决定

**不做这项收敛。** 维持各调用点自行判定。

## 理由

- 四档执行模式是两年打磨定型的结果，**后续不再新增模式**（用户 2026-09-15 明确）
- 集中化的全部收益只在「新增模式 / 修改模式判定规则」时兑现；该前提不存在，收敛本身即为无收益改动
- 收敛需要引入新的枚举类型并改动 7 个文件，属纯替换：**无收益 + 有改动面 = 不做**

## 影响

- **刻意接受**：模式判定分散在下列各处，四套口径并存，将来若真要动模式需逐处核对——
  `internal/cli/check.go`、`internal/batch/batch.go`、`internal/ssh/command.go`、
  `internal/dangercheck/check.go`、`internal/output/report.go`、`internal/output/archive.go`、
  `internal/result/statistics.go`
- 报告 / 归档 / 日志里的模式文案同样分散在各处各自维护，改措辞需逐处检查
- `internal/cli/check.go` 里数四个字段的「互斥校验」**不是**同一回事（它要报「指定了几个」），
  无论本决策如何都不应被合并掉
- **后续架构审查不必再提此项**：这不是遗漏，是评估后拒绝的选项
- **2026-09-29 修正**：本决策的理由建立在「后续不再新增模式」这个前提上，而 **ADR-0011** 把批量改密作为**第 5 档执行模式**接了进来，前提**不再成立**。结论（维持分散判定）本次仍照办——上面那 7 处判定点确实要逐处各加一路，这正是本 ADR 记下的代价；但"不必再提此项"这句作废：**新增模式的成本现在是真的**，是否重开集中化属独立议题

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 在 `cli` 上做类型化判定（枚举 + 访问器），各包消费枚举 | 收益仅在扩展模式时兑现，而模式集合已封闭 |
| 只把四套口径的映射表合并到一处，判定仍留在原地 | 仍要改动 7 个文件；且口径分化由各消费场景本身决定（统计只要三档、归档只要英文名），强行合并反而增加一层间接 |

## 2026-09-29 推翻

**决定：本 ADR 的结论不再成立，重开「模式判定与模式文案集中化」。**

理由：

- 上面「理由」一节的三条，**第一条已被 ADR-0011 证伪**：模式集合已封闭这个前提没了——2026-09-29 改密作为第 5 档接了进来。第二、三条（收敛要改 7 个文件、属纯替换）站在"不会有收益"之上，前提一倒，它们只剩"改动面大"，不再是理由。
- **代价已被实测过一次**：落地改密那一档，整个特性一次动了 **28 个文件、8 个 Go 包**；其中模式名字相关的核对点七处、要手改的四处（`cli/check.go` 的五选一互斥、`batch/batch.go` 的文案表、`output/report.go` 的报告段落、`confirm/confirm.go` 的参数屏）。ADR-0011 的影响一节当天已记为"模式文案要逐处核对"。
- 作者 2026-09-29 裁定：**「自己定的 ADR，后面情况变了就该改，没有不让改的道理。」** 依此推翻。

本 ADR 的处置：

- 上面「备选方案」一节两个方案都建立在"模式集合封闭"上，随之作废——集中化的形状重新开放，**新决定另立 ADR**，不在本条内改。
- 「本 ADR 是评估后拒绝的选项，后续审查不必再提此项」一句**作废**；后续审查可以（且应当）提。
- **本文正文（背景 / 决定 / 理由 / 影响 / 备选方案）原样保留**，作为"当时为什么这么定"的记录，不改写历史。
- 「影响」一节列出的判定点清单仍然有效——它是重开这件事的**改动清单**：`internal/cli/check.go`、`internal/batch/batch.go`、`internal/ssh/command.go`、`internal/dangercheck/check.go`、`internal/output/report.go`、`internal/output/archive.go`、`internal/result/statistics.go`，另加本次新增的 `internal/output/terminal.go` 与 `internal/confirm/confirm.go`。
- 「`cli/check.go` 里数四个字段的互斥校验不是同一回事（它要报『指定了几个』）」这一条**继续成立**：即便重开集中化，它也不该被合并掉。

待定（属新 ADR 的范围，本文不预设）：

- 判定的集中化做到哪一层——只集中"一档模式的全部名字"（判定仍留原地），还是连判定一起类型化；
- `Args.ModeName()` 已经是唯一判据点，它与新枚举的关系；
- 五档之外会不会还有第六档（若会，本次就必须做成可扩展的形状而不是再枚举一遍）。
