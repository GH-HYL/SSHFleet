# 报告红线不钉 `message` 的签名

**状态**：已接受（accepted）
**日期**：2026-11-16
**决策人**：开发者——判定表族一「11-J10 判动」（`docs/issues/2026-11-16-1449-架构取舍判定/spec.md`）；做法由执行者推导，2026-11-16 15:31 他授权：「都你决定，我授权你修改adr，接缝的事情我不懂」。**本条「决定」一节是推导出来的做法**，他拍的是「改」与「做法交你定」。

## 背景

`internal/guard/redline_report_test.go` 判报告站的两件事：上屏的是一句「话」、落点由别人给。当年没有别处能钉「上屏的是一句话」，于是在第一节用反射读 `message.StatisticsLine` 的返回类型，要求它是 `message.Line`。

**变了一样，是工程设计：** 「上屏的只能是话」现在由类型系统硬管——`console.Print(l message.Line)`（`internal/console/print.go:20`）的形参就是它，别的类型塞不进去。同一时期还定了两条口径：ADR-0048「判据按引用面判不按写法判」、ADR-0051「判据收进叶子包」。

## 决定

删掉第一节那段反射（`reflect.TypeOf(message.StatisticsLine)` 及其两条判断）。

保留另外两节，一字不改：`report.Run` 的入口形状（第三张纸进、落点组进，交回「要留痕的话」与 error），以及「本包不 import `path`／`path/filepath`、不自开第二个终端出口」的扫描。

## 理由

- **射程错位**：那条反射钉的是 `message` 的导出符号。`message` 一改签名，红的是挂着报告站名字的那条红线——下一个人会去报告站找原因。红线红的时候必须只有一种解释、且只有一个地方该被怀疑（ADR-0050 同一条理由）。
- **这条判据已经有更强的落点**：`report/report.go:42` 把 `message.StatisticsLine(...)` 直接交给 `console.Print`。返回类型一变，编译就不过，用不着反射再判一遍。重复不是保障，是把一条判据挂在两个站名下。
- 报告站自己的形状仍由红线管：入口签名、不开第二出口、不自己拼路径——这三样没有别的落点。

## 影响

- `message.StatisticsLine` 改成别的返回类型时，这条红线不再红；那时红的是编译（`console.Print` 的调用点）。这是有意的。
- 红线指纹会变：`guard/redline.go:98` 那一行里 `message.StatisticsLine` 要从符号表去掉，喊失败的次数从 6 减 1。改完照报错里印出的那一行抄，并在那一行加一句说明改的是什么。
- `message` 的 import 仍要留：`wantOut` 里还有 `[]message.Line`。

## 备选方案

- **把这条判据搬到 `message` 自己的用例**：可以，但那是 `message` 的纸面，不是本批；本批只把射程收回来。等 `message` 那边要判「统计块交回的是话」时再立。
- **整条红线撤掉**：不行。`report.Run` 的入口形状与「不开第二出口」在别处没有落点。

## 复审

**未证实**：「`message` 改签名后这条红线不再红」是推导，实施时用 `-overlay` 挂探针实跑一次确认（不往包里写文件）。
