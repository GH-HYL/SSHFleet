## 背景

这个工具维护了两年，代码基本由 AI 写，作者只把控方向、不逐行审代码。半年下来出现一种失效：**每遇到一个小问题就地改一点，改完看着都对，但没有任何东西能挡住它绕开已经抽象好的那层。**

具体失效长这样：作者抽象了一个报错构造点，希望所有报错都从它出来。可执行者如果想让某个地方自己 `print` 一句，语法上完全合法——构造点那个包里没人拦得住，编译器也不会说一句话。事后作者读代码，只看得出「这里有一句 print」，看不出它本该走构造点。这不是作者读得不够细，是**结构上没给它留下够不着的余地**。

根因落在老工程 `modules/SSHFleet_Go/main.go:216`（`func main()` 起到文件末尾）：**十步主干全部写在同一个函数里**。同一个包里，一切互相可见——第 8 步想用第 1 步读进来的配置，写个变量名就行。没有包边界，就没有任何一条「这个值不该从这儿拿」能被机械发现。

所以这次重构的目标不是「代码更好看」，是**把纪律从「靠人盯」换成「结构上做不到」**。作者原话（2026-10-30）：「虽然说避免不了后面 AI 再随意发挥，但也不算是无用功吧。」

## 决定

**一、主干按五站分层，方向单一。**

解析 → 闸门 → 执行 → 结算 → 报告。每站一个包，数据只往下走，不许回头。站的名字与边界由决策工单 01–04 定，本条只定「分成五段、段与段之间单向」这个形状。**跑的过程里的显示与实时定分类归执行站；报告站只管跑完之后**（屏幕统计、报告文件、两张表格）。

**站与站之间按「懂不懂这份材料」分判断，不按「是不是判断」分。**

- **校验**：这份材料本身对不对——文件在不在、读得出来吗、格式对不对、必须项齐不齐、内容空不空。归**最懂那份材料的那一站**；配置与清单的校验因此留在解析。
- **裁量**：这件事该不该做——参数合不合规、命令危不危险、人喊不喊停。**全在闸门**。
- 越界的形状机械抓得到：闸门去读配置（依赖白名单报）、闸门里造「起不来」（失败类型的构造点报）。

**为什么不把判断全塞进闸门**：那一站要从「审计划」变成「又读、又造、又审」，接口变宽——而宽不是本方向。**判断是知识，散着不怕；能说「不」的才必须只有一处。** 老工程那个 512 行的入口，正是「什么都判断」长出来的。

**二、跨站数据契约独立成包，只放类型与常量。**

`contract` 不属于任何一站：上游填它、下游读它，它自己不依赖任何人（除标准库）。**一个函数都不许有**——没有行为的包无从堆积逻辑，也就长不成抽屉。（包级变量可以，只当哨兵错误这类不可变的值的落点用。）

**三、阶段交接件必须是新造的，不许把上一站的原结构体递下去。**

下游缺字段时，只能回上游那条纵切去加，不许跨阶段回取。这条的成本是明确的：改一个需求要改一整条线。作者认了这个成本。

**边界**（ADR-0035 补）：新造的那份，除本棒结论外不许比上一份多一格；两张纸一样宽，说明这一棒没有过滤任何东西，就不该造两次，直接递上一份。

**四、横切关注点分成若干叶子包，各自只干一件事。**

终端输出、日志、问人、落盘根、退出码，一样一个包；凭据读取另算一个。判据是「它产不产业务数据」：产数据的归站，不产的才是横切。叶子包只依赖标准库与契约，人人依赖它也不成环。

权限表：

| 包 | 只干这一件 | 可以依赖 | 硬规矩 |
| --- | --- | --- | --- |
| `console` | 往终端写字（**唯一出口**） | 标准库、契约 | 其余包一律不许自己 `fmt.Print`、不许直接写 stdout / stderr；`_test.go` 文件除外（按后缀划，不按目录划——否则打印会搬进一个被生产代码调用的「测试辅助」包） |
| `log` | 写运行日志 | 标准库、契约 | 只写日志，不写报告；路径由 `archive` 给 |
| `ask` | 摆出问题、收一行回答 | 标准库、契约、**`console`**、**`message`** | 叶子之间的依赖只此两条（→ `console`、→ `message`）；它不判断答案的含义 |
| `archive` | 建本次运行的落盘目录、发路径字符串 | 标准库 | 不返回句柄（句柄是可变共享物）；不替别人写文件 |
| `exitcode` | 种类 → 退出码 | 标准库、契约 | **不提供 Exit**；只认「种类」，不认具体错误类型 |
| 凭据包 | 读主密钥、解密、报它齐不齐 | 标准库、契约 | 不碰业务，不判断该不该跑 |
| `message` | 把事实拼成一句话并摆好（**唯一拼句处、唯一改字处**） | 标准库、契约 | 只收事实（哪一条没过、哪一档），产出句子；按给定宽度折行与截断、数字写成大小；不判断该不该、不打屏、不决定措辞之外的任何事 |
| `mask` | 认出秘密、把它遮住；清单的脱敏副本也由它写 | 标准库、契约 | 只认凭据与清单这两类秘密，不碰业务判断 |

**写盘的归属：谁产内容谁写，路径只能从 `archive` 拿。** 日志归 `log`，报告文件与两张表格归报告站，备份脚本与代填文件（原样复制）归 `archive`，清单的脱敏副本归 `mask` 写（它认得出秘密与数据行），目录本身归 `archive`。`archive` 不代写——代写就得懂所有格式，那是抽屉。

**遮秘密是横切包，谁要谁现算。** 屏幕上要显示、日志要写、报告要贴、清单副本要落盘——各处到用的时候调它算一次，**不产生字段，也不往下传**：把「已经遮好的值」装进纸里，等于凭空多一格，还让下游以为那就是原值。老代码就是这么干的（各处 `MaskSecret`），搬过来照旧。

**清单脱敏副本由报告站在收尾写**：它向 `archive` 要 assets 路径，把「源路径 + 目标路径」交给 `mask` 去算与写；脚本与代填由 `archive` 原样复制，不过 `mask` 的手。`mask` 不自己问 `archive` 要目录（横切包之间不许互相依赖），所以目标路径由报告站递。

**为什么不挪到开工前**：挪早更合「备份」的本意（防跑到一半文件被改），但老代码就是在出报告这一步做的；重构不夹带改动，先照原时序搬，挪不挪等建完站再单独提。代价是「执行资源」那三条路径要跟到第三张纸——报告站收尾时用它。

**危险警告归闸门管，字仍从外面出。** 危险规则、判定、提示还是禁止，全在闸门——最高那一档就是「不许跑」，那本来就是它唯一的权力。但它不亲手写：不许跑时把「拒绝 + 那张表」交回塔尖，塔尖打出来再退；要提醒时把「要问的事」交给 `ask`，`ask` 摆出来再问。表怎么排只有一处，`message`。代价是 `ask` 多一条依赖（见上表）。

**打印不单设一站。** 作者 2026-11-01 提过在执行前加一站专管打印，结论是不加（原话：「如果叶子包能解决，那就不用加站」）。三条理由：站按「产不产业务数据」分，打印不产数据；那类字要在五个时刻出（帮助、危险提示、拒绝、执行中刷屏、跑完的报告），一个站只占一个位置；帮助与拒绝停在塔尖、根本不往后走，收进站里就得让它们先穿过执行。要的是「谁都不许自己拼字」——`message` 拼、`console` 打已经做到。**不必再加检查**：别的包就算把字拼出来也送不到屏幕（`console` 只收 `message` 造得出来的类型，编译就挡住）；判据是「拼了也没出口」，不是「有没有拼」。扫字符串拼接这类检查误报太多（配置取值、路径拼接全在拼），不值当。

**`console` 只收一种类型，那种类型只有 `message` 造得出。** 别的包想打印，连字都构造不出来，编译就过不了——这比检查硬，也比审计硬。构造函数按「事实的种类」命名（一行结果、一句拒绝、一张危险表），不提供通用的「原样输出」：加一个通用构造就是给自己开逃生口，那要审计抓。代价是 `message` 会长大，且报错时会指向一个新人没见过的类型——所以构造函数的命名要让报错本身说清「该用哪一个」。

**它长大是值的。** 字只在这一处成形，想乱发挥也只有一个地方可改，破坏面被关在一个包里；读那个包的人一眼看得出「这里有格式」，不遵守的概率低，即使不遵守也只坏这一处。所以**宽度与折行、数字写成大小都并在这里**，不为它们另开小包——多开一个包，就多一处可以发挥的地方。**但判二进制不进来**：那是「这份料能不能当文本用」的判断，不产字，归解析站。

**`exitcode` 为什么只认种类、不认错误**：退出码的规则要只有一处，可「认出这是拒绝、那是起不来」要认识闸门里的拒绝类型；让 `exitcode` 去认，它就得依赖站，叶子就破了。所以由塔尖认（它本来就依赖站），认完把「种类」交过去查表。

**这一条怎么核**：07 定了一个结构检查——**它本身是一个测试，跟着 `go test` 跑**，不另加一步命令。五类越界一次扫完：

- **写终端**：凡往标准输出、标准错误写字即算——`fmt.Print` 族、直接写 `os.Stdout`／`os.Stderr`、`io.WriteString` 写到标准输出、内建 `println`，一律算，不看走哪个函数；只有 `console` 包与 `_test.go` 文件例外。
- **依赖方向**：八个横切包（`console`／`log`／`ask`／`archive`／`exitcode`／凭据／`message`／`mask`）只许依赖标准库与契约，例外只有两条：`ask` → `console`、`ask` → `message`；契约包只许依赖标准库；站只许依赖契约与横切包，不许依赖别的站，也不许反向；塔尖的依赖清单只许五站、八个横切包、契约、密钥管理包，`os`／`os/signal`／`errors` 只许用三个点名的符号：`os.Exit`、`signal.Notify`、`errors.As`（`errors.Is` 同理）。
- **退出动作**：`os.Exit` 的调用点只许在塔尖（入口那个包）；「打日志再退」那种收口也归这一处，别处只许把结论往上交。
- **契约纯净**：契约包里出现函数就报，带接收者的方法也算；类型、常量可以，变量不算。它也不许依赖任何包（除标准库）。
- **失败类型的构造点**：`起不来` 许在解析与执行、结算、报告各站造，**闸门包里造就报**；`拒绝` 只在闸门构造（构造函数不外露），**类型本身可见**——塔尖要认出它才能把话交出去。

**第六类专管测试站在哪儿**：红线区的测试只许站三种口子——塔尖的进程出入口、站的入口（递一张纸、收一张纸）、横切包的那一件事。判据两半：**import 白名单**（一个红线测试文件只许 import 标准库、契约包，以及被它钉的那一个包）；**出口白名单**（每个站包只许导出入口函数与替身插口的类型，闸门的拒绝类型点名放行）。**红线测试不享下面那条 `_test.go` 的依赖方向豁免**。测试为什么分两区、出口为什么这么收，见 ADR-0037。

五条都不靠人读。**判据按语法树数，不按字搜**——Go 自带把源码解析成语法结构的库，只认真正的调用与 import，注释与字符串不算；按文本搜既能被注释骗过，也会误报。**`_test.go` 只在「写终端」「依赖方向」两条上豁免**（那类文件不进生产程序，且常要跨包取被测对象）；退出动作与契约纯净不豁免。**调终端的地方有四处，按文件列**：塔尖（帮助——含版本那一行、拒绝、起不来、开工前那句提醒）、执行站刷屏那一处（进度不经过塔尖）、`ask`（问句）、报告站（结论与报告上屏）。**解析、闸门、结算三个站一个字都不许写**；也不是「`console` 包内随便写」。检查自己住新工程里单独的一个包，不塞进任何一站——它要把全工程摊开数，住进某一站就得跨出去看别人的文件，那一站的单向就破了。行业管这类东西叫架构守护测试（也叫适应度函数）。

**规矩怎么让人知道：写在每个包的头注释里，只点名，不抄条文。** 一句话说清这个包只干哪一件、判据在本 ADR 第几条，就完了——权限表加塔尖那两段四百来字（现数 430 个汉字），抄进十二个包就是四千多字，改一次口径要改十二处。头注释是 Go 的包文档（`go doc` 读的就是它），改哪个包就一定看得见，不必指望谁先读过 `AGENTS.md`。它只是「让人不去撞」，删了也不报错；真正拦人的是上面那个测试。

**分档的界线是「能不能机械判」。** 扫得到的是红线——红了就交不了；扫不到的只是取向。不另列一份分级清单：清单要人记，判据是当场可判的。放行口子另留一份台账（与检查同住一处，一行一条：哪条规则、哪个位置、为什么放、谁批的），**改它等同改约束类文件**——它能让闸门闭嘴，权力与 `.gitignore` 同级；每次跑测试先打一行「当前放行 N 条」，条数涨起来谁都看得见。

**凡是能让检查闭嘴的东西，改它都等同改约束类文件**——台账、检查本体、它读的规则表，三样一样算。不逐条列举：以后长出第四样，这句话自动盖住。这条比台账那条更要紧——绕过整套东西最省事的动作不是改十个站，是把检查删掉或放宽，改完测试全绿、看起来一切正常。

**五、塔尖只搬不做。它做的是编排，不是判断。**

塔尖只做三件：**分叉**（这次走哪条路）、**搬**（把信封交给下一站）、**退**（给退出码；退之前用日志包记一笔）。它不下任何业务判断——判断全在站里。

**它不是横切**：横切是那几个叶子包（不产数据、每站都要用）；塔尖管的是先后与收场。两样都不做业务判断，但不是一回事。

**分叉的依据是递回来的结局，一共五种。** 解析递回四种——信封（进流水线）、一条小命令（交给密钥管理包）、一句要打给使用者的话（帮助之类）、起不来；闸门退回一种——**拒绝（连同那句话）**。塔尖认这五种、各交各的去处，自己不判断「该不该」。**不许它自己去看配置、看文件在不在**——那就从搬变成做了。

**拒绝的话也走塔尖**：闸门不碰屏幕（见 ADR-0034），所以拒绝时把「拒绝 + 那句话」一起交回塔尖，塔尖把话交给 `console`、再从退出码表换码退。这与「帮助」那条是同一个动作，不是新增职责；代价是塔尖认的结局从四种变五种，来源分成两处（解析、闸门）。

**怎么判它薄不薄：看依赖清单，不看行数。** 清单里只许出现：五站、横切包全体、契约、密钥管理包；再加 `os` / `os/signal` / `errors` 里**点名的几个符号**（退出、订阅信号、认错误类型）——不是「这三个包里的东西随便用」。行数只是对外说的观测量，不是判据：塞十行字符串拼接，行数照样好看。

**这条是必要条件，不是充分条件。** 清单干净了，仍可能有人在塔尖用 `+` 拼字符串——那不进清单，扫不出来。充分条件要靠 07 再加一条（塔尖不许出现字符串字面量与拼接），或者靠审批。**07 暂缓这一条**：扫字面量会把「搬一格」里正常的常量一起扫进来，判据得再想；先靠审批，不硬塞进第一批。

**不在塔尖的东西**：帮助里「有哪些选项、各是什么」由解析站给（与选项定义同源，分开就有两个来源），话由 `message` 拼（字只从 `message` 出）；版本拼装归报告站，塔尖只把入口那个常量传下去。

**那个常量不算「手上的东西」**：它是编译期定死的，不随运行变，不是第三样数据。

退出动作只许出现在塔尖（`os.Exit`，以及包在它外面的「打日志再退」那种收口）。

**边界**（ADR-0036 补）：塔尖另有一处允许的分叉——这次走流水线，还是那三条不进流水线的小命令。

**取消（Ctrl+C）归塔尖，不新建包。** 它听着像横切（每站都可能要响应），实际只有两件事——订阅信号、最后退出——都在塔尖。**信号只订阅一处**；往下靠 `context.Context` 逐层递，不设共享的取消标志（那是可变全局状态）。**取消是通知，不是杀死**：直接中断进程会让 `defer` 不跑（码页不还原、日志不落盘、上传残留留在目标机），所以在跑的收手、没跑的记作未执行，然后照常走完结算与报告。退出码不为它单列：塔尖认的仍是那五种结局；取消不进「结局」表，但退出码表里加一种「被中断 → 130」，塔尖认出来再交 `exitcode` 查表。见 12 号工单。

**六、新工程与老工程并排，老工程冻结。**

新工程在 `modules/SSHFleet2_Go/`（Go 模块名 `sshfleet2`），老工程 `modules/SSHFleet_Go/` 原样不动、只修紧急缺陷。不拆独立仓库、不开长期分支——老工程冻结之后，搬家是单程的，退路靠提交点。

## 理由

**为什么这五条能挡住「自己单写一套」：** 它们都不是禁令，是**够不着**。契约在独立包里，下游想拿配置只能拿到 `Plan`；横切包是叶子，想复用只能调那一整件事；塔尖薄，能塞私货的地方只剩几行。

**为什么契约要独立：** 假如 `Plan` 由解析站定义，执行站为了拿到这个类型就得 import 解析站整个包。而解析站为了内部拆文件会把读配置、解析选项、读清单全部导出，门可能有一百多个符号——等于为了一张纸买一整本书。

**为什么交接件必须新造：** 传原结构体等于把上游的全部字段摊给下游。摊开之后就没人说得清「这个值是解析定的，还是执行改的」；而一旦下游能改它，下一个需求就会顺手在那里改。

**为什么横切要按「产不产数据」切：** 这条来自作者 U8 自己的观察——把无状态的公共函数单独放一个封闭的包，AI 想自造就得从头造，而「造的话，它可能输入很多个条件，完全就是生造」。零件散在 `common` 里，省事的路就宽了。

## 影响

- **老代码全部要搬一遍**。51 个测试文件、13 个 internal 包、13147 行非测试代码 + 入口 512 行。搬法见工单 04。
- **`common` 会被拆散**。它现在 694 行、导出 28 个符号，从 `FormatBytes` 到 `ErrUser` 到 `Interactor` 什么都有，正是「抽屉」的样本。拆法按其产物分流：产数据的归站，不产的进横切。
- **15 篇旧 ADR 里的 `internal/*` 路径会全部失效**，按行数计共 41 处（0021 有 11、0003 有 5、0004 有 4、0028 / 0025 / 0014 各 3、0020 / 0019 / 0012 各 2、0026 / 0024 / 0022 / 0017 / 0015 / 0005 各 1；按出现次数计 63 处，0003 与 0021 各有几行里写了多个路径）。按《个人开发规范》四.3，旧文不就地改写，等映射定下来（工单 04）后在各自末尾追加「更新记录」，写明新落点。
- **`tools/release/release.py:54` 写死 `modules/SSHFleet_Go`**：两套并存期间它仍只打老工程，这是对的；改它留到切换那天（工单 09）。
- **`docs/个人开发规范.md` 三.1「旧工程作 `*_bak*/`」这条本次不适用**：`.gitignore:88` 排除 `modules/*_bak*/`，老工程一改名就从版本库消失，而它是当前发布版唯一源码。等切换确认不再回退后再动。

## 代价

- **五站之间传的东西变多了**。为守「只传交接件」，要给每站造结构体，写的时候比直接传指针啰嗦。
- **改一个需求要改一条线**。这是作者明示认下的代价，不是副作用。
- **站内仍可能长抽屉**。站等于一个包，包内文件互相全可见——这条挡不住「站里自己攒一个 helper」。07 那套结构检查也扫不出来：它只认五类形状（写终端、依赖方向、退出动作、契约纯净、失败类型的构造点），「这段逻辑该不该在这儿」数不出来。这一条只能靠规格审计与人读。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 在旧工程上原地改 | 旧工程在服役、是发布版唯一源码。原地改没有退路，改坏了没有对照物 |
| 拆成独立仓库 | 把 31 篇 ADR、30 个议题、规范与技能跟代码切开。搬代码时查「这段逻辑的来历」靠 `git log -S`／`blame`，换仓库这段历史就断了 |
| 保持十步主干，只补注释与文档 | 注释是建议，不是边界。老 `main.go` 512 行、十步同在一个函数，正是「建议挡不住」的现成证据 |
| 按功能纵切优先（先分上传/下载/改密，再分阶段） | 纵切切不出「拒绝权只许一处」这种权责边界。作者 U5 已指出横纵都还好说，**来回穿插的那个才破坏抽象**——而穿插只有横切成独立包才关得住 |
| 开一条长期重构分支 | 老工程冻结之后 master 上没有要合进来的东西，长期分支只剩合并义务，没有收益 |
