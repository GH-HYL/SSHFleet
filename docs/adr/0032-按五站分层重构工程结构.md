## 背景

这个工具维护了两年，代码基本由 AI 写，作者只把控方向、不逐行审代码。半年下来出现一种失效：**每遇到一个小问题就地改一点，改完看着都对，但没有任何东西能挡住它绕开已经抽象好的那层。**

具体失效长这样：作者抽象了一个报错构造点，希望所有报错都从它出来。可执行者如果想让某个地方自己 `print` 一句，语法上完全合法——构造点那个包里没人拦得住，编译器也不会说一句话。事后作者读代码，只看得出「这里有一句 print」，看不出它本该走构造点。这不是作者读得不够细，是**结构上没给它留下够不着的余地**。

根因落在老工程 `modules/SSHFleet_Go/main.go:216`（`func main()` 起到文件末尾）：**十步主干全部写在同一个函数里**。同一个包里，一切互相可见——第 8 步想用第 1 步读进来的配置，写个变量名就行。没有包边界，就没有任何一条「这个值不该从这儿拿」能被机械发现。

所以这次重构的目标不是「代码更好看」，是**把纪律从「靠人盯」换成「结构上做不到」**。作者原话（2026-10-30）：「虽然说避免不了后面 AI 再随意发挥，但也不算是无用功吧。」

## 决定

**一、主干按五站分层，方向单一。**

摄入 → 闸门 → 执行 → 整理 → 呈现。每站一个包，数据只往下走，不许回头。站的名字与边界由决策工单 01–04 定，本条只定「分成五段、段与段之间单向」这个形状。

**二、跨站数据契约独立成包，只放类型与常量。**

`contract` 不属于任何一站：上游填它、下游读它，它自己不依赖任何人（除标准库）。**一个函数都不许有**——没有行为的包无从堆积逻辑，也就长不成抽屉。

**三、阶段交接件必须是新造的，不许把上一站的原结构体递下去。**

下游缺字段时，只能回上游那条纵切去加，不许跨阶段回取。这条的成本是明确的：改一个需求要改一整条线。作者认了这个成本。

**四、横切关注点分成若干叶子包，各自只干一件事。**

终端输出、日志、问人、落盘根、退出码，一样一个包。判据是「它产不产业务数据」：产数据的归站，不产的才是横切。叶子包只依赖标准库，人人依赖它也不成环。

**五、塔尖只搬不做。**

入口文件里出现任何一行「自己干活」的代码（拼字符串、判业务规则、读写文件），都说明有一站漏了东西出来。退出动作只许出现在塔尖。

**六、新工程与老工程并排，老工程冻结。**

新工程在 `modules/SSHFleet2_Go/`（Go 模块名 `sshfleet2`），老工程 `modules/SSHFleet_Go/` 原样不动、只修紧急缺陷。不拆独立仓库、不开长期分支——老工程冻结之后，搬家是单程的，退路靠提交点。

## 理由

**为什么这五条能挡住「自己单写一套」：** 它们都不是禁令，是**够不着**。契约在独立包里，下游想拿配置只能拿到 `Plan`；横切包是叶子，想复用只能调那一整件事；塔尖薄，能塞私货的地方只剩几行。

**为什么契约要独立：** 假如 `Plan` 由摄入站定义，执行站为了拿到这个类型就得 import 摄入站整个包。而摄入站为了内部拆文件会把读配置、解析选项、读清单全部导出，门可能有一百多个符号——等于为了一张纸买一整本书。

**为什么交接件必须新造：** 传原结构体等于把上游的全部字段摊给下游。摊开之后就没人说得清「这个值是摄入定的，还是执行改的」；而一旦下游能改它，下一个需求就会顺手在那里改。

**为什么横切要按「产不产数据」切：** 这条来自作者 U8 自己的观察——把无状态的公共函数单独放一个封闭的包，AI 想自造就得从头造，而「造的话，它可能输入很多个条件，完全就是生造」。零件散在 `common` 里，省事的路就宽了。

## 影响

- **老代码全部要搬一遍**。51 个测试文件、13 个 internal 包、13147 行非测试代码 + 入口 512 行。搬法见工单 04。
- **`common` 会被拆散**。它现在 694 行、导出 28 个符号，从 `FormatBytes` 到 `ErrUser` 到 `Interactor` 什么都有，正是「抽屉」的样本。拆法按其产物分流：产数据的归站，不产的进横切。
- **15 篇旧 ADR 里的 `internal/*` 路径会全部失效**（按引用数：0021 有 11 处、0003 有 5 处、0004 有 4 处、0028 / 0025 / 0014 各 3 处、0020 / 0019 / 0012 各 2 处、0026 / 0024 / 0022 / 0017 / 0015 / 0005 各 1 处）。按《个人开发规范》四.3，旧文不就地改写，等映射定下来（工单 04）后在各自末尾追加「更新记录」，写明新落点。
- **`tools/release/release.py:54` 写死 `modules/SSHFleet_Go`**：两套并存期间它仍只打老工程，这是对的；改它留到切换那天（工单 09）。
- **`docs/个人开发规范.md` 三.1「旧工程作 `*_bak*/`」这条本次不适用**：`.gitignore:88` 排除 `modules/*_bak*/`，老工程一改名就从版本库消失，而它是当前发布版唯一源码。等切换确认不再回退后再动。

## 代价

- **五站之间传的东西变多了**。为守「只传交接件」，要给每站造结构体，写的时候比直接传指针啰嗦。
- **改一个需求要改一条线**。这是作者明示认下的代价，不是副作用。
- **站内仍可能长抽屉**。站等于一个包，包内文件互相全可见——这条挡不住「站里自己攒一个 helper」。真要挡，得靠工单 07 那套机械核对，而它还没定。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 在旧工程上原地改 | 旧工程在服役、是发布版唯一源码。原地改没有退路，改坏了没有对照物 |
| 拆成独立仓库 | 把 31 篇 ADR、15 个议题、规范与技能跟代码切开。搬代码时查「这段逻辑的来历」靠 `git log -S`／`blame`，换仓库这段历史就断了 |
| 保持十步主干，只补注释与文档 | 注释是建议，不是边界。老 `main.go` 512 行、十步同在一个函数，正是「建议挡不住」的现成证据 |
| 按功能纵切优先（先分上传/下载/改密，再分阶段） | 纵切切不出「拒绝权只许一处」这种权责边界。作者 U5 已指出横纵都还好说，**来回穿插的那个才破坏抽象**——而穿插只有横切成独立包才关得住 |
| 开一条长期重构分支 | 老工程冻结之后 master 上没有要合进来的东西，长期分支只剩合并义务，没有收益 |
