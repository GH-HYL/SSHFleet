# 不经 import 的边一律禁：`go:linkname` 与汇编

**状态**：accepted
**日期**：2026-11-12
**决策人**：开发者（2026-11-12 原话：「禁掉这两样（推荐）」）

## 背景

`//go:linkname` 能在不 import 的情况下绑到别的包的私有符号，`.s` 汇编能直接 `CALL` 任意符号。
审计第 91 号用例造过真样本：解析站用 linkname 调执行站的内部函数，编译过、
`TestProjectIsClean` 零违规——「站之间单向」这条边界被完全绕开，而检查器一个字看不见。

类二判的是 import 表；这两样机制做的事，恰好就是「在 import 表上不留痕迹地建一条边」。

## 决定

**禁掉这两样**：工程里出现 `//go:linkname` 指令、或出现任何 `.s` 汇编文件，类二即报。

## 理由

- 这两条是唯一能做到「完全不经 import 的跨包绑定」的机制。禁掉它们，类二那张 import 表
  才等于「所有的边」；不禁，它只等于「愿意登记的边」。
- 被否掉的备选是「读链接产物」（`go tool nm`／`objdump`）：看得更宽，但要把编译接进检查器，
  每次检查都编一遍；产物里还混着标准库与编译器自己的内部符号引用，误报难清。一个不需要
  编译就能判的判据，胜过要跑构建才能判的判据。
- 备选「先不做」也否掉了：切换后 A2 是唯一防线，留一条已知的暗道，等于防线有洞还记着洞在哪。

## 影响

- 现在工程里 `go:linkname` 零处、`.s` 零个，这条判据立起来不动任何代码。
- 判据只看生产文件（与类二其他判据同口径，`_test.go` 豁免）；汇编文件不分生产与测试，一律报。
- 以后真要放开（例如某个平台必须用汇编），走「改红线、单独点头」，不在这条 ADR 里留口子。
