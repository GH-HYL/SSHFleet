# 屏幕正文收成具名类型，系统原文走一个数得出来的口子

**状态**：accepted
**日期**：2026-11-12
**决策人**：执行者按开发者「授权开工」（2026-11-12）推导；底本是审计 `修复面盘点` §4.2 选定的那条路

## 背景

`message.Fatal` 原来收 `(where, body string, logPath)`。`where` 有具名常量，`body` 没有——站里
任何一个包都能把自己拼的字符串、或 `err.Error()` 的系统原文直接贴到那屏上。0044 把**纸**里的
句子收干净了（`CannotStart.Body` 已删），但**屏**这道口子还在：塔尖至今把建归档目录、写报告
这两处失败的 `error` 原样上屏，屏幕上出现的是半句中文半句英文。

## 决定

正文改成具名类型 `message.FatalBody`，字段不导出，与 `message.Line` 同一道闸：**只有 `message`
能造**。`Fatal`、`TraceRefusal` 只收它。系统原文不是不能上屏，而是必须走「系统原文」那一类别
（`Kind` ＋ `Origin`），口子因此数得出来。

## 理由

- 与 0044 同一条思路：站里只交「哪一类、什么参数」，句子在一处成形。0044 已经这么做了纸，
  屏再单独立一套只会更乱。
- 与 `Line` 同一道闸：**类型拦得住顺手，比检查硬，也比审计硬**（ADR-0032 第四条）。再加一条
  检查器判据是补第二道，不是拿它替第一道。
- 被否掉的另一条路是「`Fatal` 直接收类别 ＋ 变参，模板搬进 `Fatal`」。那样 25 个拒绝句与
  97 个起不来类别的模板会挤进同一个 switch，且每加一种说法都要动 `Fatal` 本身——现在
  加说法只加一个成形函数。

## 影响

- 站里想往那屏放字，先得有 `message` 给的一段正文；「随手贴一句」在编译期过不去。
- 这一版**不迁**站里 54＋93 处自拼中文（`execute`／`parse`）：那些走的是纸与日志，不走这屏。
- 「系统原文」那一类别是过渡：`archive` 与 `report` 那两句中文迁进类别表之后，它就没有调用者，
  届时删掉（届时另开一单，不在这条 ADR 里排期）。
