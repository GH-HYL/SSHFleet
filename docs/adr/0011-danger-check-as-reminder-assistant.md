# ADR-0011: 危险命令检测定位为「分类提醒助手」

状态：已接受（2026-09-10）

## 背景

SSHFleet 在向目标机下发命令前，对命令内容做危险检测。历史上（ADR-0005 剥壳、ADR-0006 去锚定）
为封堵漏检，采取了「去掉首尾锚定、任意位置匹配、宁错杀不放过」的策略。代价在实测中显性化：
58 条语料识别准确率 62.1%（通过 36），22 条失败中 17 条为误判（业务目录被当删根、非递归被当递归、
纯文本引用被拦）、5 条为漏判（`rm --recursive --force /` 甚至完全无命中、静默放行）。

误判与漏判同源：把正则作用在**整行原始字符串**上（混有包装命令、引号、分隔符、其他命令的参数），
只能靠「任意位置匹配」「字符集吞并」兜底，而这两种兜底手段同时就是误判来源。调正则无法收敛。

## 决策

检测的定位是**操作助手，不是防御闸门**。

- **目标**：把命令内容正确分类，准确提醒使用者「这条命令的风险等级、执行需谨慎」。
  用户有时意识不到命令的危险程度，检测的价值在于补上这一层判断。
- **非目标**：不追求对抗刻意绕过（编码后执行、多层嵌套转义、动态拼装）。
  这类场景不计入设计目标，不为其增加解析复杂度。
- **优先级**：不误判 > 不漏判。误判干扰正常作业（且用户只能改配置自救），漏判损失有限。
- **简单高效优先**：不为覆盖对抗场景引入重型解析；识别层保持轻量可读。
- **forbidden 是最强一档提醒**（直接退出），不是不可逾越的安全边界——用户可通过修改配置文件调整。
  因此四级阶梯的行为差异只有「是否直接退出」，high/medium/low 只影响提醒颜色与措辞强度。

## 后果

- **正向**：验收标准收敛为「分类是否正确」；实现可保持轻量；不再需要为「假想的恶意输入」付复杂度成本。
- **负向（明确接受）**：刻意绕过的命令可能不被识别；脚本模式不追踪跨行状态（`cd`、变量、alias）；
  变量目标的命令无法静态证明，只提醒不拦死。
- **约束**：识别结果必须**可配置、可自查**——规则可单条禁用、路径清单集中一处、
  规则改错时启动即校验并指名报错（原「防篡改」预留接口与可配置互斥，放弃）。
