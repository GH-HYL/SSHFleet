## 一、背景

改密的新密码只有一个来源，命令行给法有两种：

- 打开加密时，`--change-password` 后面写**密文文件的绝对路径**，程序读文件、解密，得到新密码（ADR-0011 决定 5）；
- 不加密时，后面写的**就是新密码本身**。

两种写法都合法，但收到的值怎么处理不一致：

| 位置 | 现状 |
| --- | --- |
| 清单第 4 列的登录密码 | 去掉首尾空白（ADR-0025 决定 9 的「简单处理程序自己做」） |
| 加密模式：值当路径 | 原样交 OS，读到什么算什么（ADR-0025 更新记录 2026-10-26 ③） |
| 加密模式：密文文件内容 | 去掉两端空白后再解密（编辑器常补末尾换行） |
| 明文模式：新密码本身 | **一个字节都不动**（`TestCheckPasswdChangeKeepsOuterSpace` 钉住） |

最后一行是唯一的例外。后果有两类：

- 首尾多打的空格被当成密码的一部分设上去。屏幕上按前 2 后 2 脱敏显示，看不见那个空白；事后使用者也敲不出同一个密码。
- 值里带换行或回车时，改密是把字节喂进远端 PTY——换行等于回车，半截密码被提交上去。远端会重问或直接失败，报错指不到原因。

## 二、决定

1. **值一律不改写。** 两种模式都不做去空白、不删换行。加密模式的值当路径原样交给 OS；明文模式的值原样当密码。这一条与 ADR-0025 第零节同源（程序在本地只做「拦」与「报」），并保持 2026-10-26 那条「凭据读取处不再 `TrimSpace`」有效，**不推翻它**。
2. **改为在检测阶段拦，命中即报错退出，本次不执行改密。** 检查作用于「最终要设的那个值」，所以明文模式的原值与加密模式解出来的明文走同一条判断：
   - 开头或结尾有空白（空格、制表符）→ 拦；
   - 任意位置有 `\r` 或 `\n` → 拦；
   - 中间的空格 → 放行（`我的 密码 2026` 是正常写法，也不影响喂入）。
3. **报错站在使用者那边写清三样**：哪里错了、为什么、怎么改。提示要求的是**换一个密码**，不是让程序替他清理——清理等于悄悄改值。
4. **装命令行原值的字段改名**，让「原样值，不一定是密码」进到名字里。加密时它装的是路径这件事，靠名字与注释一起触达。
5. **加密模式的值当路径这件事不动**：原样交 OS，只由系统回答「这个文件在不在、读不读得了」（ADR-0025 决定 6 的报错口径照旧）。

## 三、理由

- **为什么拦而不 trim。** trim 会悄悄改掉使用者设的密码：他以为设的是 `␣pass`，实际设成 `pass`，而屏幕上看不出差别。拦则把选择权交回使用者，也不会给同一个值造出两种形态。
- **为什么中间的换行也要拦，不能只拦首尾。** 改密走 PTY，写侧是逐行喂的；密码里任何位置出现 `\r` / `\n`，都会被远端当成「这一行输完了」，提交的是半截密码。失败现象是「远端重问密码」或「密码不合规」，看的人根本想不到是自己值里多了个换行。
- **为什么两种模式同一口径。** 若只拦明文，加密模式里把带首尾空格的密码写进密文文件照样能设上去，同一个人在两种配置下会遇到两套规矩。
- **为什么这条不违反「本地不做空格检查」。** ADR-0025 决定 3 拒绝的是拿空格去判**本地路径**——路径能不能打开由系统回答，比「有空格」准得多。密码没有这个替代：系统不会替我们判它合不合规，喂进 PTY 之前只有程序能拦。
- **为什么不把「模式」顺手做成显式取值。** 那是原工单 02 的第 1 条。模式判定已经收在 `cli.Args.ModeName()` 一处，再拆一个存下来的值收益接近零；作者 2026-10-27 的表述是「对原值的判断只发生在是否存在上」，本次不动。

## 四、影响

- **使用者侧**：明文模式下带首尾空白或换行的新密码从「能设上去」变为「当场报错」。这是行为变更，实施时同步：手册「批量改密」小节加一句限制，`CHANGELOG.md` 未发布段记一条。
- **测试侧**：`TestCheckPasswdChangeKeepsOuterSpace` 的断言反过来（改为应报错）；新增「中间空格放行」「换行拦下」两条。
- **不变**：参数屏、归档报告、工具日志仍取解析后的 `NewPassword`；脱敏口径、退出码、`[ERROR]` 前缀、屏幕文案一律不动。
- **不涉及**：清单第 4 列仍去首尾空白（那是书写约定，不是当场输入）；加密模式的值仍是路径、仍原样交 OS。

## 五、备选方案

| 方案 | 否掉的原因 |
| --- | --- |
| 明文模式也去首尾空白 | 悄悄改值：屏幕显示与实际设置不一致，且与「值不改」的既有取向相反 |
| 什么都不做 | 同一工具两套口径（清单去空白、命令行不去）；带换行时失败原因指不到 |
| 只拦首尾，中间换行放行 | 中间换行会被 PTY 当回车，提交半截密码，失败现象难查 |
| 只拦明文，加密模式解出的明文放行 | 两种配置下规矩不同，同一个人会遇到两套 |
| 拦下后自动删掉空白再继续 | 等同于改值，还少了使用者的知情 |
