## 一、为什么静态取值这条路走不通

三条实测（2026-10-28，Ubuntu 26.04 与 CentOS 7.9 两个容器）：

1. **两类机器没有交集**。CentOS 7.9（glibc 2.17）有 `en_US.UTF-8`、**没有** `C.UTF-8`；Ubuntu 26.04 反过来——只有 `C` / `C.utf8` / `POSIX`，没有 `en_US`。任何单一名字都盖不住两类。
2. **「机器没有」不等于「不生效」**。`LC_ALL` 设一个不存在的名字，每次调用吐一行 `setlocale` 告警，并把进程落到 `C`（按字节）；而类别变量（`LC_CTYPE`）设错是**静默**回落，不告警。
3. **非交互会话通常拿不到 `LANG`**。CentOS 的 sshd 没配 `pam_env`、`/etc/environment` 是空的；Ubuntu 的 `/etc/default/locale` 只有一行注释。所以「不配置」在多数机器上等于按字节跑。

合起来：任何一个静态值，都只能让一半机器按字符、另一半按字节；「配了就一定有」这件事不存在。ADR-0024 取 `C` 的决定因此作废——它保住了零告警，代价是全场按字节，`cut -c` / `awk substr` 切中文会切坏。

## 二、决定

1. **编码不让用户配**，工具内建，每次都执行这四步：
   1. 问机器：`locale charmap` 是不是 `UTF-8`；
   2. 是 → 什么都不做（不多此一举）；
   3. 不是 → 在 `C.UTF-8` / `en_US.UTF-8` 两个中性名里挑一个**确实存在**的（大小写、连字符都不计；`C.utf8`、`en_US.utf8` 同样认）；
   4. 挑到就**只** `export LC_CTYPE=<挑到的>`；挑不到、`locale` 不存在、输出为空 → 一个变量都不设。
2. **语言只留一个开关**：新开 `[locale]` 段，键 `english`，默认 `false`。
   - 开 → `export LC_MESSAGES=C`。`LANGUAGE` 不用清——在 `C` 下 gettext 会忽略它（实测）。
   - 关 → 不加任何东西，语言跟随目标节点。
   - **开关放 `[locale]` 而不是 `[env]`**：`[env]` 是环境变量表，一个布尔混进去会被读成"可以传下去的一个变量"；而且编码已经没有开关，语言这个开关需要一个说得清归属的位置。
3. **`[env]` 收缩**：出厂只留 `PATH`；`LANG` / `LC_ALL` 从出厂配置里删除（由第 1、2 条接管）；用户仍可自由增删自己的变量。
4. **`TERM=dumb` 保留**，理由与代价见第五节。
5. **`-a` 用同一套**：片段进 argv，`sh -c` 外壳不变。
6. **不再设 `LC_ALL`**：它设错会刷屏，还会盖掉语言开关。

## 三、理由

- **只动 `LC_CTYPE`**：它只管「一个字符算几个字节」，不碰语言（`LC_MESSAGES`）、不碰排序（`LC_COLLATE`）、不碰时间与数字格式。两个诉求正好落在两个正交类别上，互不干扰。
- **只挑两个中性名**：`tr_TR` 一类会改大小写映射（`I` / `i`），脚本里的 `tr`、`[[:alpha:]]` 会跟着变；`C.UTF-8` 与 `en_US.UTF-8` 的字符分类是中性，换哪个都一样。
- **先查 `charmap` 再动手**：已经 UTF-8 的机器上不产生任何副作用，也不会把一台 `zh_CN.UTF-8` 的机器改成英文名下的字符规则。
- **挑不到不设**：不设就是保持机器原状（`C`，按字节），且零告警——这是「有就用、没有就不生效」唯一安全的实现方式。

## 四、影响

- **下发行**：`sh -c 'if [ "$(locale charmap …)" != UTF-8 ]; then …; fi; <英文开关那一行>; [sudo ]解释器 …'`。片段本身 **162 字节**，整条下发行（含 `sh -c '` 与 ` bash'`）**174 字节**（2026-10-28 实测）；`-a` 的 122880 上限几乎不受影响（正文上限从约 92KB 减约 200 字节）。
- **日志**：「命令行」那一行会带上这段判断，可读性下降，属已知代价。
- **`--no-shell`**：按契约不套外壳、不设环境，本决策不生效。
- **没有 `sh` 的目标**（交换机、小型机）：走 `--no-shell`，不在本决策范围内。
- **开销**：每次执行多 2–3 个进程（`locale charmap`、`locale -a`、`grep`），毫秒级。
- **存量配置**：工具尚未发布，不考虑兼容；`[env]` 里的旧键会被新语义接管或忽略。

## 五、`TERM=dumb` 的实测与代价

- **有 PTY（`-a`）**：`TERM=xterm` 下 `ls --color=auto` 25 行带转义，`TERM=dumb` 下 **0 行**——真的压得住。
- **无 PTY（`-c` / `-s`）**：两种取值都是 0 行，本来就没有彩色；那里它没有任何收益。
- **代价**：依赖终端能力的程序会失败。实测 `clear`、`tput cup` 返回 1；ncurses 类交互安装器（dialog / whiptail）预期也会失败——本机没有这两个程序，未测。
- **判断**：保留。收益落在彩色最脏的地方（`-a` 的 PTY），代价落在「需要光标寻址的交互界面」，而那种界面本来不是代填的主场景。

## 六、没证实的

- **AIX / HP-UX** 的 `locale -a` 输出格式。匹配用 `-i`，大写 `EN_US.UTF-8` 理论上吃得下，但无环境验证。
- **`locale` 命令被裁掉的系统**：`charmap` 为空 → 判为「不是 UTF-8」→ 去挑 → 也挑不到 → 不设。安全退化，只是不生效。
- **dialog / whiptail 在 `TERM=dumb` 下的确切行为**。
