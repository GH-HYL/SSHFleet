# ADR-0033: 规格审计单独立一个技能，专门挡「结构被绕开」

- **状态**：已接受（accepted）
- **日期**：2026-10-30
- **决策人**：作者明示（2026-10-30 本轮对话）
  - 「质量审计一般都是在我分支该提交的时候才做的，那时候代码都已经写完了，如果再发现问题，修改的代价太大了」
  - 「所以我想弄一个规格审计，尽量在开工前就把它约束住，这时候的成本还是比较低的」
  - 「审计的重心就是不要破坏我现有的框架，我就怕他随意从上游拿东西，然后自己拼接」
  - 「其实咱们大的模块都还好说，就怕后面有新的需求，需要来回穿插的那种模块」
- **实施载体**：`skills/person/audit-spec/SKILL.md`

## 背景

现有四个审计各有各的时点与判据，**没有一个落在「规格写完、开工之前」这个位置上**：

| 技能 | 时点 | 判据 | 挡得住结构被绕开吗 |
| --- | --- | --- | --- |
| `/audit-adr` | ADR 定稿前 | 决定有没有出处、与旧篇打不打架 | 不涉及代码结构 |
| `/audit-docs` | 一批文档改完 | 自洽、规范、说法属不属实 | 不涉及代码结构 |
| `/audit-quality` | 分支该提交时 | 有没有另造一套、ADR 决定履行了没有 | **挡得住，但太晚** |
| `/audit-retrofit` | 议题全走完 | 实现与 ADR 对不对得上 | 挡得住，但更晚，且重型 |

`/audit-quality` 的 1.1 轴（「同一形式由两个及以上写入点各自拼出，说明本来就该有一个构造点」）**正是要挡的那件事**，但它的时点是提交时——代码已经写完。改法是重写，不是改一句话。

作者对失效路径的描述很具体：不是大模块出问题，**是某个新需求需要来回穿插的那种模块**——「有一个玩拼接的，就有第二个玩拼接的」，越维护越坏。

## 决定

**新建 `/audit-spec`，在规格与工单写好、还没说「授权开工」时跑。**

它的重心只有一条：**一个需求要的数据，只许从相邻那一站的交接件里拿**。凡是绕开交接件的拿法都报，共六种形状（穿站回取、反向依赖、契约长函数、横切包长出业务、新模块无家、同一件事算两遍）。

判据取仓库，三类按可靠性排：已 accepted 的结构 ADR（当前 `ADR-0032`）与 `Status: resolved` 的决策工单；`GLOSSARY.md` 与既有导出符号；规格里每条「决定」的出处。

**判据没落定的写「判据不足，跳过」，不拿通用最佳实践补位。**

## 理由

**为什么不并进 `/audit-docs`**：文档审计的判据是「这份文档自洽吗、合规范吗、说法属实吗」，它的受众表里没有「代码结构」这一栏。并进去会让它同时背两套判据，而这两套的时点、对象、失效方式都不同——文档审计面对的是任意一批文档（手册、规范、词表），规格审计只面对一个议题目录、且必须通读全文（工单脱离 spec 判不出结构风险）。

**为什么不并进 `/audit-quality`**：它的时点是对的，位置错了。而且它审的是 diff，规格审计审的是文档——**没有 diff 可看的时候，它无从下手**。

**为什么必须在开工前**：这是唯一一条能改写法的时点。同样一个问题，在规格里发现是改一句话，在提交时发现是重写一段，在议题结束时发现是重开一轮。

## 影响

- **审计链变成五段**，时点互不重叠：

```text
ADR 定稿前   → /audit-adr       决定有没有出处、与旧篇打不打架
规格写完     → /audit-spec      会不会绕开交接件、有没有替作者拍板   ← 本条新增
一批文档改完 → /audit-docs      自洽、规范、说法属实
分支提交时   → /audit-quality   有没有另造一套、决定履行了没有
议题全走完   → /audit-retrofit  实现与 ADR 对不对得上（重型，只用于重视的议题）
```

- **`/audit-spec` 会在施工期大量输出「判据不足」**。结构定义仍在施工（`docs/issues/2026-10-30-2134-架构重构/` 的 01–13 号工单），凡落到还没定的那一块都判不了。这不是它的缺陷，是施工期的正常状态；随着工单逐张结算，可判的部分会变宽。
- **`/audit-quality` 不变**。它已经是「挡得住但太晚」的那一道，本条不取代它——晚的那道仍然要留，因为规格审不出「实际写出来的代码有没有照着规格做」。
- **`/audit-conversation` 计划退役**（作者 2026-10-30：与 ADR 审计重合，暂时留着）。

## 代价

- **多一个技能要维护**。它的判据依赖 ADR-0032 与后续决策工单；那些一旦改口径，这个技能跟着过时。
- **可能与 `/audit-docs` 的 B 轴重复**。两边都会查「有没有替作者拍板」，判断口径目前一致；若将来两边分叉，得收口到一处。
- **只在开工前有效**。代码写完之后它一点用没有——这是设计，不是缺陷，但意味着它必须真的被调用，否则等于没有。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 扩 `/audit-docs`，加一轴「结构风险」 | 那批文档里多数与代码结构无关（手册、词表、规范），加一轴会让它每次都要先判断「这批文档跟结构有没有关系」，多一步且容易跳过 |
| 把 `/audit-quality` 提前到规格阶段跑 | 它审 diff，规格阶段没有 diff。硬提前等于重写成另一个技能 |
| 靠 `/audit-adr` 顺带管 | ADR 审的是「决定有没有出处」，管不到「规格会不会引导出坏结构」；而且 ADR 只在有 ADR 时才有得审 |
| 不立技能，靠规范里加一句纪律 | 纪律是建议，不是判据。这套框架立身的理由就是「建议挡不住」——见 ADR-0032《背景》 |
