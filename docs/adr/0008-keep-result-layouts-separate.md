# ADR-0008: 终端与 Excel 结果行布局不合并

状态：已接受（2026-08-27）

## 背景

架构审查（architecture-review-20260827-114310.html 候选 #3）提出：`src/gotogo/go_to_go.py:_format_result` 与 `src/output/xlsx.py` 都在构造"连接行/执行行/分类行"布局，且各自判定 `exit_code == 0` 的成功语义，建议提取统一 ResultRow 模型供两端消费。

## 决策

**不合并。两处结果行布局各自独立演进。**

理由：

1. **时机不同**：终端输出是流式传输，随 SSE 消息到达立即打印，强调实时性；Excel 输出是整理流程，全部执行结束后按开关（是否有导出需求）才生成，强调结果汇总。两者生命周期阶段不同。
2. **输出内容不完全一样**：终端行含实时代宽/耗时排版，xlsx 行受开关控制、字段与格式与终端不一致（如逐文件明细、列宽、分类标签样式）。强行共用模型需为差异开参数，接口宽度反而增加。

## 后果

- **正面**：两端可按各自时机与内容需求独立演进，不互相牵制。
- **负面**：格式变更需同步两处（现状已如此，未恶化）；成功判定 `exit_code == 0` 存在两处定义。
- **边界**：若未来出现第三个消费方（如 HTML 报告、JSON 导出），届时再评估提取共享模型——一个消费方是复制，两个是巧合，三个才值得抽象。
