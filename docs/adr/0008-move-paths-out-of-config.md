# ADR-0008: 路径与文件名的 10 项从配置里移出

- **状态**：已接受
- **日期**：2026-09-24

## 背景

配置里原先有一整段 `[paths]`，管着产物的目录名与文件名：

| 项 | 管什么 |
| --- | --- |
| `historys` | 历史记录目录名 |
| `tool` / `exec` | 工具日志与执行日志的文件名 |
| `asset` | 归档里资源备份目录名 |
| `output` / `output_xlsx` | 终端输出的两种格式 |
| `report` / `results_xlsx` | 汇总报告与结果明细 |
| `error_keywords` / `dangerous_keywords` | 两份规则文件的路径 |

它们**看起来可配，实际上没人配**：改一个日志文件名既不影响使用、也不带来收益；而两份规则文件的路径一旦被改错，工具起来就报"配置文件缺失"——用户根本不知道是自己动过的那一行造成的。

## 决定

这 10 项**整段移出配置**，取值写死在程序内（`config.BuiltinPaths`）。

配置里**再出现 `[paths]` 即报错**，报错要说明"把整段删掉即可，其余字段不用动"。

**实现不删**：`Paths` 结构体与 `[paths]` 的读取定义原样留着，只在**校验层**把这些键列进一份"不允许出现"的名单。将来要恢复开放，删掉名单那几行即可。

## 理由

判据是"这项配置有没有可能让**用户**做出有意义的差异"。这 10 项没有——它们描述的是**工具自己的产物**，不随环境变化。留在配置里等于凭空多出 10 个要读、要判断"要不要改"的字段，而正确答案全是"不用改"。

做法上**拦在门口而不是把东西搬走**：读取结构不动，所以恢复成本几乎为零（作者明确要求保留回溯的余地）。代价是这份名单与结构体之间会短暂地"看起来不一致"——用注释写明这是刻意的。

## 影响

- 配置项从 27 降到 17，`[paths]` 整段消失
- **归档产物的名字与位置从此固定**，文档、帮助、报错里提到的路径不必再考虑"用户可能改过"
- 两份规则文件的路径也内置了。这带来一个直接后果：**改它们的文件名只需改一处**（程序内置值），不必再让用户跟着改配置
- `historys` → `history` 的改名顺势完成——配置里的字段名随整段移除自然消失，只需改磁盘上的目录名

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 保留 `[paths]`，在注释里写"通常不用改" | 曾经就是这么写的，结果是把"要不要改"这个判断留给了用户；且"通常不用改"这类说法本身就是学习成本 |
| 保留目录名可配、只移出文件名 | 一半可配比全不可配更难解释：用户会问"为什么这个能改那个不能" |
| 彻底删掉读取结构与字段定义 | 恢复时需要重写；而作者要求保留回溯余地，且留着不占用户视线（它已经不在模板里了） |
