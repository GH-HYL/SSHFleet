# ADR-0020: 内联值改用 `;;` 作行分隔，字面 `\n` 不再具有任何语法含义

- **状态**：已接受（accepted）
- **日期**：2026-10-19
- **决策人**：作者（2026-10-19 本轮对话）
- **实施载体**：`docs/issues/inline-list-backslash-newline/spec.md`

## 背景

`-f`（节点清单）与 `-a`（代填）都接受「一个 CSV 文件路径，或同样格式的内联文本」。命令行写不进真换行，所以内联值在解析前先把字面 `\n`（反斜杠 + n）替换成真换行（`common.ExpandEscapedNewlines`）。

这替换是无差别的，而 Windows 路径天然满是反斜杠：`D:\new\pw.bin`、`D:\nodes\…` 里的 `\n` 会被当成换行切开，后半截掉成新的一行（2026-10-19 实跑：`-f '10.0.0.1,22,root,D:\new\pw.bin\n10.0.0.2,22,root,pw2'` 报出 `行 3 (IP: 10.0.0.2)`，第 4 列只剩 `D:`）。

`-a` 侧的问题更彻底：代填内容里本来就需要表达换行（"一段内容打两行再回车"），而 `\n` 被拿去当行分隔符，这层意思**完全无法表达**——写 `-a 'a\nb,请选择'` 会被切成两行，第二行缺触发词而报错。

收紧替换规则（比如只认「前后是分隔符」的 `\n`）在字符层面无法成立：`root,D:\new\pw.bin` 与 `1.1.1.1\n2.2.2.2` 的上下文没有可判别的差别。

## 决定

1. **行分隔改为 `;;`**：内联值里两个连续分号表示一条记录的结束，`-f` 与 `-a` 共用这一个记号。
2. **字面 `\n` 回到普通字符**：不做任何替换，也不再有任何转义语义。路径里的 `\n` 原样保留。
3. **两者同一口径**：清单与代填的取值形态、「与文件内容一致」这条性质不变，只有分隔记号变了；**`-a` 不单设转义**，内联里就只有 `;;` 一个记号。代填内容要含真换行，走 `-a answer.csv` 文件。
4. **不考虑兼容**：使用者可见面按「`\n` 从来就不是分隔符」书写——手册、帮助、报错、CHANGELOG 里不出现「以前是 `\n`」「现已改为 `;;`」这类沿革。旧写法在新规则下按普通内容解析，不设专门的迁移提示，也不读旧写法。
5. **沿革留在维护者可见处**：`\n` 曾是分隔符、因 Windows 路径与 `-a` 内容换行而退役，这段来历记在本 ADR 与相关代码注释里。

## 理由

- **冲突面最小**：`\n` 与 Windows 路径必然冲突，与 `-a` 的内容换行也必然冲突；`;;` 在正常路径、密码、触发词里几乎不出现。
- **引号内无特殊含义**：`;` 不是 shell 元字符，在双引号里对 bash、cmd、PowerShell 都安全；`|`（管道符、PowerShell 别名）、`__`（太易误撞）都不如它。
- **不引入第二套概念**：清单与代填仍共用一份取值口径，只换了一个记号，`common.ReadCSVRows` 之下不变。
- **`-a` 顺带修好**：`\n` 不再被吃掉之后，代填内容里的换行写法不再与行分隔抢字符，两件事各自有清楚的位置（细节由本议题规格定）。

## 影响

- **使用者可见文档要改**：`docs/1-使用手册.md`、`docs/5-常见问题.md`、`docs/6-示例.md`、CHANGELOG 里所有以 `\n` 分隔内联多行的示例，都改写成 `;;`，并按「本来就这样」措辞。
- **`internal/common/csvtext.go` 的 `ExpandEscapedNewlines` 换实现或退役**：名称与注释都要跟着改，不能再叫「补换行」。
- **`internal/nodelist` 两个长期红的测试**（`TestReadRowPassphraseNeverValidated`、`TestReadPrecheckErrorsAggregated`）在临时目录名含换行字符时变红，本决策落地后应自然变绿。
- **`;;` 仍有剩余冲突面**：内联值里真出现 `;;`（密码、触发词）就会被切行。这一面靠「含这种东西就走文件」兜住，不另设转义。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 收紧替换规则（只认特定形态的 `\n`） | 取消路径前缀、分隔符之类的判别在字符层面不可行，`D:\new` 与正常换行同形 |
| 取消内联换行：内联只能单行，多行一律走文件 | 内联多台机器、内联多行代填都消失；`-a` 内容里的换行依然无处安放 |
| 用 `\|`（竖线）作分隔 | 在 cmd 里是管道符、PowerShell 里是别名，引号虽能保、但使用者第一反应会以为是危险字符 |
| 用真换行（`$'...'`、PowerShell 反引号） | 不同 shell、不同编辑器表现不一致，复制粘贴即失效 |
| 用 `<NL>` / `%NL%` 这类不冲突的长记号 | 冲突面确实更小，但多一层要解释的约定，键位也不顺；与 `;;` 的收益差距不值这份学习成本 |
| 新增 `-F` 选项专门吃内联文本 | 已经不算「内联」；CLI 形态变大，且不解决分隔符本身与路径冲突的问题 |
| 给 `-a` 的正文另设换行转义（如 `\N`） | 等于在内联里养第二套记号：谁能用、哪一列能用都要单独讲，而「与清单完全一致」正是当前口径的价值所在。要换行的代填内容用文件表达，不必再发明一个转义 |
