# ADR-0017: 控制台适配由程序自己做，不要求使用者配置环境

- **状态**：已接受（accepted）
- **日期**：2026-10-16
- **决策人**：作者（2026-10-16 本轮对话）

## 背景

客户机的 Windows 10 1909 上，Go 版参数屏的颜色变成转义序列残骸：

```text
【96m▶ 权限类型  -→【0m   【38;5;214msudo【0m
```

2026-10-16 排查已把根因定到具体某一行（证据见 `docs/issues/win10-ansi-color/findings-2026-10-16.md`）：

- 1909 的 conhost 出厂默认**不开启**虚拟终端（VT）处理；
- Go 版从程序到依赖**没有任何人**去开它，却无条件输出 ANSI 转义序列；
- 旧 Python 版不出这个问题，是因为 `loguru` 在 **import 阶段**经 `colorama` 把 VT 打开了
  （落点 `colorama/winterm.py:185` 的 `SetConsoleMode(..., ENABLE_VIRTUAL_TERMINAL_PROCESSING)`）。

也就是说：**同一个工具，旧版能用、新版不能用，差异不在使用者的机器，在程序有没有替自己适配。**

排查中曾出现过一条候选：在文档里写明「遇到乱码请把 `HKCU\Console\VirtualTerminalLevel` 置 1，
或改用 Windows Terminal」。

**作者裁定（2026-10-16）：要程序适配，而不是让工具用户自己去配置他的系统环境。**

## 决定

**控制台能力差异由程序在启动时自己适配，不通过文档、配置或报错把这件事推给使用者。**

两件事一起做：

1. **主动开**：程序启动、输出任何颜色之前，若输出流是控制台而 VT 未开，替它打开。
2. **开不成就不上色**：确认了是控制台、但 VT 打不开时，**本次运行全程不输出转义序列**——纯文字。

**输出流不是控制台（重定向 / 管道）时不在此列**：作者 2026-10-16 指示「不用考虑重定向的事情」，
该场景本次不动，行为维持现状。

本 ADR 记方向与边界；具体落点、改动清单与验收见 `docs/issues/win10-ansi-color/spec.md`。

## 理由

- **这是工具的责任，不是使用者的**。使用者是运维人员，工具部署在**他的**目标环境里。
  要求他改注册表或换终端，等于把工具的兼容责任转成他的系统管理负担；
  同一台机器上装十个工具，就要为十个工具各查一遍自己的系统设置。而同类问题下他往往不知道该改哪里。
- **这不是新需求，是回退后的修补**。旧版事实上就做了适配（虽然是无意的）。
  新版退回"什么都不做"是能力上的净损失，不是"多要求了一个特性"。
- **门槛很低**：探测与控制台能力各一次系统调用。仓库已有平台分文件先例
  （`internal/output/link_windows.go`），`golang.org/x/sys/windows` 也已在 `go.mod` 里。
- 与规范 四、产出·4「使用者可见文案」中「站在使用者那边写」同向：**"颜色显示不正常"是工具的问题，不是他的配置问题。**

## 影响

- 新增一处平台相关代码（探测 + 开 VT），非 Windows 平台给出恒真分支，行为不变。
- **26 个 ANSI 颜色常量由 `const` 改为 `var`**，值在无颜色时取**空串**。
  这样"降级"无需触碰任何调用点（引用形态全是字符串拼接）。
  **代价：颜色值失去编译期不可变保证**——将来谁误给 `colorRed` 赋值，编译器不拦。
- **不涉及面向使用者的行为变更**：作者 2026-10-16 指示「不用考虑重定向的事情」，
  输出重定向到文件 / 管道的行为本次不动。预期按修订档记 CHANGELOG，不抬主版本。
- 与 ADR-0008（路径移出配置）同向：都在把"本该由程序决定的事"从使用者手里拿走。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 文档里写「遇到乱码请改注册表 / 换终端」 | 作者明确否掉：这是让使用者替工具适配环境；且同类问题下用户不知道改哪里 |
| 只降级（探测不到就不上色） | 在本来能上色的机器上也无条件放弃颜色——治了病，也治掉了功能 |
| 只主动开（不降级） | 确认了是控制台、但 VT 打开失败时仍会外泄；B 是那种情况的兜底 |
| 保留 `const` 不变，改为在输出层剥掉转义序列 | 现有颜色输出**没有统一出口**（`fmt.Print` 直接写 `os.Stdout`，`fmt` 各处直写），要过滤得先把所有输出收敛到一处——那是重构，成本远高于改 26 个声明 |
| 继续沿用旧版那条路（引入 loguru / colorama 之类） | 那是 Python 生态的库，Go 侧没有对应物；且不该为一个系统调用引入新依赖 |
