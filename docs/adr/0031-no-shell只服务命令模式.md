# ADR-0031: `--no-shell` 只服务命令模式

- **状态**：已接受（accepted）
- **日期**：2026-10-28
- **决策人**：作者明示（原话见下）；「否掉的备选」与「影响」里的后果分析为助手推导，复核时请重估
- **取代**：2026-10-09 的「脚本模式支持 `--no-shell`」（`4690fc5`，当时只记在 CHANGELOG 与测试注释里，没有 ADR）
- **关联**：ADR-0010（正文投递走 stdin / 命令行）、ADR-0029（不落 `/dev/shm`）、ADR-0014（解释器配置驱动）

作者原话：

- 「-s 就不能给 no-shell 搭配使用，必须互斥……就只能给 -c 使用，别的一律都不允许使用」
- 「回归初始，就只给 -c 使用，然后跟其他所有的模式互斥」
- 「其实什么『上传没有命令可剥夺』『脚本必须走 stdin』，这些话都违背了这个提示信息。它面向的是使用者……咱们只提示『只能跟 -c 一起使用』就这么简单」

## 一、问题

`--no-shell` 剥三样：`sh -c` 外壳、`export` 环境段、`sudo`。

对 `-c`，剥完什么都不剩——命令原文交给远端登录 Shell 解析，语义与名字相符。
对 `-s`，剥完还剩一样：**脚本正文在标准输入上，必须有个程序去读它**（正文不落盘，ADR-0010），那个程序就是解释器。解释器一旦参与，「原样下发、工具不附加任何东西」就不成立了。

于是 2026-10-09 放开 `-s` 之后，参数屏那行「原样下发，本次不生效」成了假话。它是 2026-10-08（`d08413a`）写的，当时 `-s` 还与 `--no-shell` 互斥，能进那一行的只有 `-c`——文案没错，是第二天放开的组合让它错位。

## 二、决定

**`--no-shell` 只和 `-c` 一起用。** `-s` / `-u` / `-d` / `--change-password` 带上它，开跑前就报错退出；`-a` 本就互斥（ADR-0010 的范围修正）。

错误文案对所有模式只有一句：`--no-shell 只能和 -c 一起使用`，第二行说怎么改。**不解释剥的是哪一层**——那是维护者关心的事，使用者只需要知道配错了。

## 三、理由

1. **脚本模式下「原样下发」不成立**（源码事实，`ssh.BuildCommand` 的 `NoShell` 分支：`-c` 返回命令原文，`-s` 返回 `scriptInvocation`，即 `<解释器> -c '. /dev/stdin' '<脚本名>'`）。留下组合等于留一个做不到的承诺。
2. **开关的含义不该随模式变**。留着 `-s`，同一面参数屏要按模式写两套话（`-c` 说「不生效」、`-s` 说「由它解释」），使用者得先记住自己在哪个模式才读得懂。
3. **与 `-u` / `-d` 同一条口径**：那两个模式没有下发命令、没有外壳可剥，10-28 已改成互斥；`-s` 是同一类「这层并不存在」的情形。

## 四、影响

- **使用者可见**：原先 `-s … --no-shell` 合法，现在开跑前报错。`CHANGELOG` 已写明升级后怎么办：去掉 `--no-shell`；确实要在裸环境跑同一条命令，改用 `-c`。
- **代码**：`BuildCommand` 与 `DescribeCommand` 的 `NoShell` 脚本分支删除；`scriptInvocation` 仍被正常脚本路径与 `$0` 补名使用，保留。
- **手册**：`1-使用手册`、`3-进阶配置手册`、`4-进阶知识手册` 与 `README` 里「脚本同样支持」的表述全部撤掉，改成「只能和 `-c` 一起用」。
- **参数屏**：「原样下发，本次不生效」不再有歧义——它只可能在 `-c` 下出现。

## 五、否掉的备选

| 备选 | 否掉的原因 |
| --- | --- |
| 保留组合，文案按模式分开 | 开关含义随模式变；两套话都要维护，读的人还得先判断自己在哪个模式 |
| `-s --no-shell` 改成 `. /dev/stdin`，不点名解释器 | 那仍是交给远端 `$SHELL` 解释，只能跑 sh 语法脚本；且 `$0` 补不回来（`.` 的参数进位置参数，不进 `$0`），从自身名字取信息的脚本会失效 |
| `-s --no-shell` 先把正文写到目标机，再 `./脚本名` 执行 | 目标机磁盘满是常态（ADR-0010 实测落 `/tmp` 失败），`/dev/shm` 投递已被 ADR-0029 否掉；还等于给每次执行加一道落盘与清理 |
| 保留组合，只在文档里说明「解释器仍生效」 | 选项名叫 `--no-shell`、字面含义是「什么都不加」，与事实冲突，靠文档补不回来 |

## 六、复审

**只放方法纪律与未证实清单，不放计划与触发条件。**

- 本篇「解释器必须参与」的依据是源码形态与 ADR-0010 的「正文不落盘」，不是真机实测——本轮未在目标机上观测「`-s` 的正文读不到解释器会怎样」，因为组合已经被挡在开跑前。
- 「否掉的备选」第三条（落盘再 `./`）引用的磁盘满失败，是 ADR-0010 当时的实测，本轮未复验。
- 「使用者是否已有存量 `-s --no-shell` 用法」无从查证：仓库内无引用，工具尚未发布，按 ADR-0030 的口径不考虑兼容。
- 若将来要恢复 `-s` 的支持，必须先有「不靠解释器读 stdin 也能把正文交给目标机」的方案落地（例如 ADR-0029 之外的投递通道），否则会重新落回本篇第一节那个矛盾。
