# ADR-0014: 解释器改为配置驱动，下发外壳不再依赖 bash

- **状态**：已接受
- **日期**：2026-10-07

## 背景

命令模式（`-c`）与脚本模式（`-s`）此前把解释器写死：`.py` → `python3`，其余（含 `.sh`）→ `bash`（`internal/cli/script.go` 的 `ScriptInterpreter`）。两条硬伤：

1. **`.py` 一律 `python3`**：目标机只装了 Python 2 时，`.py` 脚本根本跑不起来。
2. **后缀集合封闭**：`-s` 的入口校验直接拒掉非 `.sh` / `.py` 的脚本（`internal/cli/check.go`），用户想跑 `.pl` / `.rb` / 无后缀脚本没有出口。

脚本语言有多少种不定，逐种写死不是办法。作者定的方向：做成"**后缀 → 解释器**"的映射，用户自己配、自己加。

另一件事在下发命令的外壳上：当时是 `bash -lc '<env; [sudo ]解释器>'`——靠"登录 shell 读 `/etc/profile`"补 PATH。这要求目标机有 bash、shell 认 `-l`（不是 POSIX 强制）、profile 还得是它能解析的语法。解释器既然要可配，外壳就不该再假设目标是 bash。

## 决定

1. 配置新增 `[interpreter]` 段（进阶配置）：
   - `command`：命令模式（`-c`）用的解释器；
   - `[interpreter.script]`：`"后缀" = "解释器"` 的映射，随包默认 `".sh" = "bash"`、`".py" = "python3"`，可自行增删。
2. 解释器在**参数解析阶段**算好、存进 `Args.Interpreter`（与既有的 `Args.Match` 同一手法）；执行侧一律从 `Args` 取，不回头读配置。
3. 后缀匹配：取文件名**最后一段扩展名**、比较**忽略大小写**；配置里的后缀键在加载时归一为小写。
4. 后缀**没配到**的脚本：参数合规检查之后、确认屏之前问一句"继续用 `<command>` 作为解释器吗"（默认 no，回车即退出）；同意则按命令解释器跑，不同意终止。`--yes` 下不弹问、直接按同意走。
5. 参数确认屏对**非 `bash`** 的解释器单列一行（只在 `-c` / `-s` 模式出现）。
6. **只对 `-c` / `-s` 生效**；上传 / 下载 / 改密不参与。
7. 下发命令的外壳由 `bash -lc` 改为 **`sh -c`**，环境（locale 与 PATH）改为**工具显式设好**，不再读 profile、不依赖 `-l`、不依赖 bash。

## 理由

- **配置形状取"映射表"**：`[interpreter.script]` 下 `".sh" = "bash"` 是 TOML 原生的"键 → 值"，加一行就多一种后缀，无空槽、无编号。备选的"固定项（`command` + `script_1..4`，两格留空）"在 TOML 里表达不了——两个空槽会撞成同一个空键（键不能重复），只能编号，反而难读；备选的"数组 `[".sh=bash", …]`"每项都要二次解析字符串，易写错，报错也指不准是哪一格。
- **解析提前到参数阶段**：`-a` 的长度检查（在 `CheckArguments` 里）要用**下发行的真实字节数**，解释器是它的一部分；提前算好存进 `Args`，长度检查、batch 拼装、确认屏三处读的是同一个值，也不必为此给 `CheckArguments` 串 `cfg`。
- **回退要问一句**：作者定的两条理由——① 后缀五花八门（`.bin` 之类），没配到的也得能跑，但不能"没配却静默按某个解释器跑"；② 让用户临时改配置太麻烦，问一句就能跑这一次。
- **外壳不依赖 bash**：外壳的唯一职责是"在起解释器之前把环境设好"（见 `envPrefix`）。改成显式 `export LC_ALL/LANG/PATH` 后，`/bin/sh` 在就行，`-l`/profile/bash 三样约束一起消失；PATH 写死一组标准目录，与"同一批节点、输出形态可比"的取向一致。非常规位置的解释器由用户写绝对路径（配置本就把"值可写绝对路径"作为基本用法）。
- **默认值落在模板里**：`[interpreter]` 与其他字段一样"必填"，不兼容老配置——作者明确要求"新的需求就改新的规矩，不需要兼容"。

## 影响

- **`-s` 不再限定后缀**：`internal/cli/check.go` 里"扩展名必须是 .sh 或 .py"那道拦截删除；未知后缀走回退询问。
- **上传 / 下载 / 改密不受影响**：它们的中间命令（`test -e`、`find` 等）仍是固定形态，工具不会拿用户配的解释器去跑它们。
- **`$0` 补名的判断泛化**：原先只对 `interpreter == "bash"` 补脚本名，现改为对 **shell 家族**（`bash` / `sh` / `dash` / `ksh` / `zsh`，按 basename 判）补——把 `.sh` 配成 `sh` 也照样把名字补回 `$0`。边角：`exec -a` 只有 bash/ksh 系认，dash 不认，配成 `dash` 时 `$0` 补不回去。
- **解释器值原样使用**：写命令名或绝对路径都行，工具不做可用性判断；目标机报「找不到某某命令」时由用户改绝对路径（文档已写明）。
- **下发行形态变了**：日志与报告里的「命令行」一行由 `bash -lc '…'` 变成 `sh -c '…'`。
- **老配置需补 `[interpreter]` 段**：缺了会在启动时报「配置缺少必填字段」。

## 备选方案

| 备选 | 否掉的原因 |
| --- | --- |
| 固定 N 项（`command` + 若干编号脚本项）配 | 与"可拓展"直接冲突；空槽在 TOML 里表达不了，只能编号 |
| 数组 `[".sh=bash", …]` | 每项是整段字符串要二次解析，用户易写错、报错难定位 |
| 忽略 `-s` 后缀、一律走 shebang 探测 | 正文不落盘、没有文件路径，shebang 读不到；且用户配 `.py`→`python2` 这类需求也覆盖不了 |
| 外层继续 `bash -lc` | 目标机没 bash 就起不来；`-l` 非 POSIX 强制；profile 未必是当前 shell 能解析的语法 |
| 外层加一个"PATH 配置项" | 与"可配只有 -c/-s 两个"冲突；其想解决的"解释器在非常规目录"已被"值可写绝对路径"覆盖 |
| 后缀没配到时不问、直接报错退出 | 会挡掉 `.bin`、无后缀这类脚本——作者要的是"能跑，但让用户知情" |
