# ADR-0013: 危险检测规则回到平级正则，匹配前先归一化命令

状态：已接受（2026-09-10）

## 背景

ADR-0012 把规则文件改成了三段结构（`syntax` 语法清单 / `path_classes` 路径分级 /
`rm_rules` 决策表 / `commands` 正则），rm 的「旗标 × 目标路径」用结构化条件字段表达。
准确率达到 100%，但**配置文件对使用者不可读**——而使用者正是要改配置的那个人。

事实：改配置的人（本工具作者本人）明确表示看不懂；这样的配置等于不可配置，
ADR-0011 定的「误拦时用户可自行修改」目标落空。可读性在这里不是美观问题，是功能问题。

同时确认了一条判定口径：**把普通路径判成「删根/删系统目录」是不允许的误报**
（如 `rm -rf /opt/test.sh` 必须有别于 `rm -rf /`）；而**文本里提到危险命令允许命中**
（如 `echo "rm -rf /"`、`grep "rm -rf"`）——这类误报可接受。

## 决策

**规则文件回到平级列表，正则不写 `^`、任意位置匹配；准确度由「匹配前先归一化」保证。**

1. **规则形状**：一条 = `name` / `example` / `regex` / `risk_level`（可选 `enabled: false`）。
   正则对该命令**任意位置**匹配（不再限定开头）；命中多条取最高风险。
   同一个分类可以写多条（名字与级别相同），或/且都在正则内部表达（`|` 是或，合并到同一条是且）。

2. **语法清单内置**：包装命令、间接执行命令（shell -c / eval / ssh）是 shell 机制而非用户策略，
   移入代码常量（`shell_tokenize.DEFAULT_SYNTAX`），配置文件中不再出现。

3. **匹配对象是归一化后的命令**，不是原始整行。解析层负责：
   - 按分隔符切分命令段、剥除环境变量赋值 / 包装命令（sudo 连其选项、nohup、xargs…）/ 重定向
   - **把 rm 旗标拍平为固定次序**：`-rf` / `-r -f` / `-R` / `--recursive` → `-r`；`-f` / `--force` → `-f`
   - 目标路径归一：合并重复斜杠、词法解析 `.` / `..`、剥引号
   - 末尾补一个空格，使 `\s` 可作为最后一个 token 的边界

   因此**一条正则即可覆盖用户的所有旗标写法**，正则才短得下来、可读。

4. **判定口径**（沿用 ADR-0011 的定位与优先级）：
   - 文本命中允许（`echo "rm -rf /"` 会提示）——匹配上就提示，不做「命令词是不是 echo」的额外判断。
   - 路径分类必须准确：`rm -rf /opt/test.sh` → 业务目录级提醒，绝不判成删根 / 系统目录。
   - 越界即拦只在可证明时：变量目标（`rm -rf $DIR`）落递归强制删除（high，确认）而非 forbidden。

5. **规则校验保持**：缺字段、字段为空、`risk_level` 非法、正则无法编译、规则条数不足（<10），
   启动即指名报错。

## 后果

- **正面**：配置文件回到单层列表，与使用者原有认知一致（有问题直接注释掉该条）；
  正则短且稳定（旗标已被拍平）；语料准确率保持 100%（81 条）。
- **负面（明确接受）**：路径名恰好等于命令词时会误报（`rm -rf /tmp/reboot` 被判「系统重启」）
  ——属「文本命中」类误报，罕见，符合当前取舍。
- **取代关系**：ADR-0012 的 `rm_rules` 决策表 / `path_classes` 路径清单 / `syntax` 语法段
  被本 ADR 取代；ADR-0012 关于「解析层 + 判定层」的分层（分词、包装解包、间接执行递归）
  与「可证明才拦」的口径继续有效。
- **ADR-0011 的定位与优先级不变**：提醒助手、不误判优先、用户可改配置。
