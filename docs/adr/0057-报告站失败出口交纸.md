# 报告站的失败出口交「起不来」的纸

**状态**：proposed
**日期**：2026-11-17
**决策人**：开发者 2026-11-17 授权开工，原话：「行，都按你的建议来，授权开工」；授权覆盖的是「把 ADR-0047 那个过渡口子收掉」这件事。**「决定」一节是执行者推导的做法**——他拍的是「办」，做法（换出参、改哪条红线）由执行者定，提请豁免一句：这条落在红线区。

## 背景

ADR-0047 收掉了「塔尖往屏上贴站里拼的原文」这道口子，但留了一个过渡类别 `CannotStartSystemFault`：塔尖把 `report.Run` 交回的 `error` 原文整句贴上屏。报告站因此至今用 `fmt.Errorf` 拼四句中文，`report/runmeta.go` 解运行上下文那几句也一样。

**变的是工程设计，不是代码复杂度**：报告站的失败现在没法「只交一句原文」——`message` 是唯一拼句处（ADR-0044、ADR-0047），它按类别成形，站点交来的东西必须先是类别。执行站已经是这个样子：`execute.Run` 交 `*contract.CannotStart`。

## 决定

`report.Run` 的出参从 `([]message.Line, error)` 换成 `([]message.Line, *contract.CannotStart)`；红线 `TestRedlineReportScreenAndPath` 里判出参的那一节跟着改。

红线另外两节一字不动：入参形状（第三张纸 + 落点组）、「本包不 import `path`／`path/filepath`、不自开第二个终端出口」的扫描。`guard/redline.go` 里那一行登记照报错里印出的照抄。

## 理由

- **纸是工程里既有的失败载体**：ADR-0034 决定三——「起不来」谁都能造，闸门里不许造。执行站已经这么交，报告站没有理由另开一套。
- **不换就删不掉那个类别**：塔尖拿到的是一个可能来自任何一处的字符串，除了原样贴屏没有别的办法成形。留着它，「屏上的字都由 `message` 出」这条判据永远有一个数得出来的例外。
- 这条红线判的正是「入口交回什么」，变的是设计；按规范一.1 第七条，这是该走议题＋ADR 的那一类。

## 影响

- 报告站的调用点只有塔尖一处（`main.go:194`），改法照执行站那一段。
- 屏上字节不变：模板拼出来与改前逐字一致。
- 红线指纹会变：符号表加 `contract.CannotStart`，喊失败次数不变（同一处断言换了被钉的类型，没有多一条）——与立条时预想的「5→6」不同，实测照抄的就是 5。
- `CannotStartSystemFault` 失去最后一个调用者，另开 03 号单删它。

## 备选方案

- **保留 `error`，报告站交一个带类别的自定义错误、塔尖 `errors.As` 之后造纸**：不必动红线，但工程里就有了第二套失败载体（契约外的一个类型），塔尖还要多一步判断——与「塔尖只搬不做」相悖。
- **只迁 `report.go` 那三句，`runmeta` 那几句留着走 `SystemFault`**：类别删不掉，这轮等于白做。

## 复审

**未证实**：「屏上字节逐字不变」以 `message` 模板与改前那几句逐字对照为准；实施时比过一次，记录在 02 号单 Comments。样本取自同一台机器、同一条路径形态（`history/…`），换平台（POSIX）时系统原话本身就会不同，那与本条无关。
