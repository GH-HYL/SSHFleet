# ADR-0039: 红线区那条 ask 指纹换样本——过渡形态到期删除，样本跟着换

- **状态**：已接受（accepted）
- **日期**：2026-11-02
- **决策人**：
  - **开发者明示**（2026-11-02，建站 04 的 16 号工单原文）：「放行后那屏『流水线还没接上』连同它的构造点一起删」——删掉 `message.NotWiredLine` 是这一单点名要落的事。
  - **执行者按此推导**（未经逐条拍板）：那条话被红线区的 `TestRedlineAskNonInteractive` 当样本用着，删它必然动指纹，所以按 `docs/个人开发规范.md` 一.1 第七条补这一篇。
- **实施载体**：`docs/issues/2026-11-02-0905-建站04-命令模式全链路/issues/16-spire-wire-and-ab.md`
- **前身**：ADR-0037 决定二、五（指纹钉测试名与该测试直接引用的生产符号；删掉、改名、收窄引用面算改）

## 背景

`TestRedlineAskNonInteractive` 要的只是一句现成的「话」（`message.Line` 的字段不导出，红线测试也得向 `message` 要），当年随手取了 `message.NotWiredLine()`——那是一句过渡形态的话，「流水线还没接上」，本来就说好随阶段 04 消失。

阶段 04 的 16 号工单要把五站接成一条链，这句话连同它的构造点一起删。删了它，那条红线测试就没样本可用，指纹里钉着的 `message.NotWiredLine` 也就不存在了。

规范一.1 第七条：改红线区（含名单与指纹）MUST 先开议题、再写 ADR，写明是哪个条件变了。议题是 16 号工单本身，这篇补的是 ADR 那一半。

## 决定

**一、样本换成 `message.ConfirmPrompt()`。** 它是一句稳定的确认问句（07 号工单的确认屏在用），与「过渡形态」无关，不会随某个阶段到期而消失。

**二、指纹同步改成 `{"ask.Ask", "ask.Yes", "message.ConfirmPrompt"}`。** 只换这一个符号，测试名与其余两个符号不动。

**三、红线测试的判据一个字不改。** 它判的仍是「非交互时 `ask` 交回按缺省放行」，与样本是哪句话无关。

## 理由

**为什么条件算「工程设计变了」。** 这句话从立项起就写着「随阶段 04 消失」，它的消失是计划内的一步，不是代码变复杂、也不是结构约束松了。规范第七条要写清的那一句就是这一句。

**为什么换样本而不是留着那句话。** 留着它等于给一句没人调用的过渡话术续命：它不进任何屏幕，却要占着 `message` 的一个导出，还会让下一个读代码的人以为「放行之后还有一屏没接上」。

**为什么不改成「样本由测试自己造」。** `message.Line` 的字段不导出，测试造不出来——那正是这个设计要的效果（字只能从 `message` 要）。

## 影响

- `guard/redline.go` 那一行的指纹换一个符号；`guard/redline_ask_test.go` 换一句样本。
- 红线区其余条目、名单条数、台账一律不动。
- `message` 少三个导出：`NotWiredLine`（本单要删的那句过渡话术）与 `RefuseLine`、`CannotStartLine`（后两个本来就没有调用者，属 03 质量审计推后的死导出）。

## 代价

- **红线区被碰了一次**，而红线区的价值一半在「不轻易动」。这一笔靠「议题 + 本篇」两道留痕来抵，不是靠「这次特殊」。
- 若将来有人再把过渡话术当样本用，同样的手续要再走一遍——这一点写在这里，当作下一手的提醒，不当作拦路。

## 备选方案

| 备选 | 否掉的理由 |
| --- | --- |
| 留着 `NotWiredLine` 不删，红线一条不动 | 16 号工单点名要删；留着就是给废弃话术续命，还占着导出 |
| 让测试自己拼一句字塞给 `ask` | `message.Line` 字段不导出，造不出来；能造出来就说明「字只从 message 出」这条破了 |
| 把这条红线测试整个删掉再新开一条同名测试 | 指纹按测试名对账，删了再建等于绕过规范第七条那道门 |
