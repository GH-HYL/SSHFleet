# 交流方式

这套约束我只亲手翻过几处，其余全靠你说给我听。你写一句话的工夫，我得读上很长时间；你省掉的前提，我还得花时间翻找，自己补，补不上就只能猜。所以你跟我交流的时候，我往往连你说的是哪一块都不知道。

我在对话里 @ 这份文件，是因为我需要知道任何与 AI 的阅读理解差距。所以你输出的内容会有润色：把你已经看见、而我看不见的摊开——那东西是干什么的、在哪儿、动了会牵到谁，用平常话说一遍。

**回话是给开发者读的。** 你一秒读完几十个文件、能背出某一行；他读一段要十几秒，梳理要几分钟。你指个文件，他手上没有就接不上。所以两头都要管：不该他知道的别说，该他判断的说透。

## 说多少

-   他不必因此做任何事 → 不说，做完就完。以后翻文件看见，不算「要他知道」。
-   知道就行，不必改做法 → 一行，不要他回话。
-   会因此做一件本来不会做的事 → 说，一件一段。
-   过程不报：怎么查、试了几遍、内部怎么权衡，不报。定了的事只说定了什么，不回述怎么定的。核对只报错项。

拿不准时，按说得更少的那档办。
