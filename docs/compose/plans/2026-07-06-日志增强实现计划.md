# 日志增强实现计划

> [!NOTE]
> This document may not reflect the current implementation.
> See the final report for up-to-date state:
> [Final Report](../reports/日志增强实现报告.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use compose:subagent (recommended) or compose:execute to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 增强SSH Fleet Go代码的日志记录，添加请求体详细信息、启动参数记录、连接统计、SSH连接尝试日志、请求拒绝事件和结构化字段改进

**Architecture:** 在现有日志系统基础上，通过修改关键文件添加缺失的日志信息，使用zap结构化字段替代字符串拼接，提高日志可读性和可解析性

**Tech Stack:** Go, zap logger, SSH/SFTP

## Global Constraints

- 保持现有代码风格和日志级别
- 不修改现有日志接口，只添加新的日志调用
- 使用zap结构化字段（zap.String, zap.Int等）替代fmt.Sprintf
- 记录敏感信息时进行脱敏处理（如密码不记录）

## 任务6：结构化字段改进

**Covers:** 结构化字段改进需求

**Files:**
- Modify: `SSHFleet_go/internal/httpserver/server.go`
- Modify: `SSHFleet_go/internal/core/batch_executor.go`
- Modify: `SSHFleet_go/internal/ssh/ssh_run.go`

**Interfaces:**
- Consumes: 现有日志调用
- Produces: 使用zap结构化字段的日志

- [ ] **Step 1: 改进server.go中的日志调用**

将`fmt.Sprintf`替换为zap结构化字段：

```go
// 示例：替换前
log.Zlog.Info(fmt.Sprintf("收到执行请求，开始处理..."))
// 替换后
log.Zlog.Info("收到执行请求，开始处理...")
```

```go
// 示例：替换前
log.Zlog.Info(fmt.Sprintf("上传请求解析成功: file_path=%s, remote_path=%s, nodes=%d, sudo=%v",
    req.FilePath, req.RemotePath, len(req.Nodes), req.Options.Sudo))
// 替换后
log.Zlog.Info("上传请求解析成功",
    zap.String("file_path", req.FilePath),
    zap.String("remote_path", req.RemotePath),
    zap.Int("nodes", len(req.Nodes)),
    zap.Bool("sudo", req.Options.Sudo))
```

- [ ] **Step 2: 改进batch_executor.go中的日志调用**

```go
// 示例：替换前
log.Zlog.Info(fmt.Sprintf("批量执行器 - 开始执行%d个任务，并发数:%d", e.totalTasks, e.maxConcurrency))
// 替换后
log.Zlog.Info("批量执行器开始执行",
    zap.Int("total_tasks", e.totalTasks),
    zap.Int("concurrency", e.maxConcurrency))
```

- [ ] **Step 3: 改进ssh_run.go中的日志调用**

```go
// 示例：替换前
log.Zlog.Error(fmt.Sprintf("连接失败 - %s: %v", ip, err))
// 替换后
log.Zlog.Error("SSH连接失败",
    zap.String("ip", ip),
    zap.Error(err))
```

- [ ] **Step 4: 验证日志输出**

运行程序，检查日志是否使用结构化字段格式
