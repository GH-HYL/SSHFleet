# 规格：面板那一环有人看着

**状态**：done（done）
**底本**：ADR-0061（入口多一格屏幕出口）；上一议题 `docs/issues/2026-11-18-1103-执行站成功路径进默认套件/spec.md` 的 Implementation Decisions 第七条与 Out of Scope 第一条。

## Problem Statement

「传输面板完成台数恒 0」这个缺陷修好了，但默认套件守不住它：非终端下屏幕退化成直通，`go test` 里面板不渲染；`close_node_test.go` 只测收口函数自己，不测谁在调它。把 `Run` 里那次回填删掉，全量照样全绿——同一个缺陷可以悄悄回来。

## Solution

给 `execute.Run` 一个屏幕出口（第四个参数，零值即生产那一路）。用例递一块缓冲区进去，面板在非终端下也照画，跑完一趟真上传之后读最后一帧：传输面板那一行写着「1/1 台完成」，就说明收口真的把结果交给了聚合器。

## Implementation Decisions

**一、出口是参数，不进落点纸。** 落点是路径，屏幕出口是「谁在看」；理由与代价见 ADR-0061。

**二、断言挑行，不整段搜。** 两块面板共用同一个流，命令那一行的台数是工人自己数的——整段搜「1/1」在缺陷下照样能找到。所以按 `message.NodeProgressLabel()` 挑出传输面板那一行再判。

**三、这条用例住自定义区。** 它连着假目标机、读渲染出来的字，属「跑起来对不对」；红线区只判形状。

## Testing Decisions

- 反证跑过一次：把 `closeNode` 里 `ag.onResult(...)` 那一行注掉，新用例红在「传输面板最后一帧没写 1/1」；恢复后绿。
- 跑法：`bash tools/test.sh -run TestRunTransferPanelCountsCompletedNodes ./internal/execute/`，全量另跑一次。

## Out of Scope

- **`internal/log` 的导出方法面不在白名单。** 检查器只数包级导出，十个导出方法与 `*Logger` 的方法面没人管。与本轮无关，仍记在原处。
- **命令模式那一行的台数。** 它由工人自己数，不经聚合器，缺陷面与传输类不同；本轮只守传输面板。
- **面板的视觉。** 颜色、清屏、帧率不判。

## Further Notes

- 注入的流会被两块面板同时写，所以断言里那句注释要留着——它是这条用例唯一容易被写松的地方。
