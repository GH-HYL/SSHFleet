# 04: 配置解码——把六份 `.conf` 读成有类型的结构，缺字段与多字段当场报

**要做的**：`config/SSHFleet.conf` 被读成一份有类型的配置，删掉一行必填项、写坏一个引号、多写一个不认识的键，都能拿到老版同一句话并以 1 退出；`[paths]` 与 `[execution.env]` 这两个已移除的段各有一句「照这样做就行」的说明。

**Blocked by**：无，可立即开工（03 号单的日志不阻塞本单）。

**Status**：done

## 判据

- **解码器只认随包六份配置真用到的 TOML 形态**：`[节]`、`[[数组表]]`、`[a.b]` 点号节、`键 = 值`（带引号字符串、不带引号字符串、整数、布尔）、跨行数组、`#` 注释（引号里的 `#` 是值）。引号外转义、重复键这两样出厂配置里没有，遇到就报，不猜。
- **零第三方依赖**：不引 `BurntSushi/toml`。解码器住解析站内（读配置是它的事），不新开包。
- **三段报错逐字照老版**：位置没有配置文件那四行；`解析 TOML 失败：…` 加「多数是引号或方括号没配对」；`配置包含未识别字段：…` 加「请使用随包提供的配置文件，不要增删任何字段」。
- **必填项清单照老版 22 条**：字段要出现、值可留空；缺了报 `配置缺少必填字段：<逗号分隔的键>`。
- **已移除的段单列**：`[paths]` 与 `[execution.env]` 各一句专用说明，不混进「未识别字段」。
- 02 号单留下的 `readRawConfig` 与 `executionOf` 由这套解码器取代；帮助那一屏取 `[execution]` 四格改从新结构读，**行为不变**。
