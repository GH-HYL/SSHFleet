# 14: 塔尖接上四种结局、码页与早期信号，`exitcode` 出码表

**要做的**：敲下去之后，塔尖按老版步骤 0 适配控制台、步骤 2 建日志、步骤 3 把 argv 交给解析站，认回四种结局（一句话／起不来／拒绝／放行），把那一屏交给终端、从退出码表换一个数退；启动段按 Ctrl+C，还了码页再以 130 退。做完之后，新工程的启动段与老版一个样。

**Blocked by**：01、02、03、10、12、13。

**Status**：ready-for-agent

## 判据

- **塔尖只做四件**：适配控制台、建日志、把 argv 交给解析站并把纸交给闸门、按结局打屏加查表退出。它不判参数、不读配置、不拼句子（ADR-0032 第五条）。
- **塔尖手上有四样**：argv（`os.Args`）、入口那两个编译期常量（版本号与工具日志路径）、日志句柄（建与关都归它）、各站递回来的结局。**不许有第五样**——不拿配置、不拿规则表、不拿终端宽度；也不许自己拼字符串（屏都由站或 `message` 造）。
- **认结局靠 nil 组合**，不靠类型断言成串：解析站给「一句话」「纸」「起不来」三样，闸门给「纸 + 拒绝」；四种结局各一种组合。第五种（三条密钥小命令）随阶段 08。
- **`exitcode` 只认种类**：成功 0、起不来 1、拒绝 1、被中断 130。它不认识 `CannotStart`／`Refusal`，也不提供 `Exit`——认结局是塔尖的活，换码是它的活（ADR-0032 第四条）。
- **码页由 `console` 给、塔尖调、退出前一定调**：`os.Exit` 不跑 `defer`，所以退出那条路自己收尾。
- **早期信号**：启动段（还没接执行）收到中断，先还码页再以 130 退——这一段最容易按 Ctrl+C（参数写错想重来），不还就是整窗乱码。
- **退出码与老版逐项一致**：老版只有 0／1／130 三个值，「拒绝」与「起不来」同码是既有行为，本阶段不拆。
- 02 号单留下的过渡形态「其余用法一律走起不来」的代码随本单删掉；「放行之后打一屏流水线还没接上」保留到阶段 04。

## 验收

- [ ] `go build ./...`、`go vet ./...`、`gofmt -l .`、`go test ./...` 全干净
- [ ] 四种结局各跑一次：`-h` → 0；配置删掉 → 1；`-u` 与 `-d` 同给 → 1；合法命令（`-c "uptime"`）→ 打「流水线还没接上」→ 1
- [ ] 帮助那一屏与阶段 02 的 A/B 结论不变（`-h` 逐字）
- [ ] 启动段按 Ctrl+C → 130，且同一窗口 `chcp` 是原值（**手工跑一次**，Windows 真控制台；Unix 上另有一条自动化测试）
- [ ] `exitcode` 四个种类换出四个数，断言写死（0／1／1／130）
- [ ] 塔尖的依赖清单没有变长（`os` 仍只用 `Exit` 与 `Args`）
- [ ] **日志建不起来**那一屏由塔尖把「环节 + 三段话」交给 `message` 造（只有这一处是塔尖触发造屏），话术与老版同一句、不带「日志：」那一行
- [ ] 红线：塔尖的起不来、拒绝**各开一个新测试文件**加进名单；已有的 24 条一个不动、指纹一个不改

## 不在这单

执行站之后的任何一站、三条密钥命令的分叉（08）、执行期日志。

## 做完之后

四种结局的命令与退出码贴进 `## Comments`，15 号单拿它当 A/B 期望值。
