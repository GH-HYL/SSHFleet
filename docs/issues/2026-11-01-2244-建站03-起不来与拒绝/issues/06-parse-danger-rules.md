# 06: 危险规则表——读进来、校验、编译成能用的判据

**要做的**：`config/keywords_dangerous.conf` 读得进来、坏得出去的条条指得准：规则里写了不认识的字段、等级写成五档之外的值、正则编译不过、示例或说明宽过一个汉字算两列的 30 列，报错都点名到那一条规则、那一项。做完之后，闸门手上有编译好的判据，自己不碰文件。

**Blocked by**：04（解码器）。

**Status**：ready-for-agent

## 判据

- **六项字段照老版**：`name`、`example`、`reason`、`regex`（字符串数组，一条规则可挂多条）、`risk_level`、`enabled`（缺省视为开）。
- **等级只有四档**：四个取值是契约里的常量（01 号单落的），本单只拿它们校验「在不在四档里」，不排序、也不另写一份取值表；排序的知识只住闸门（13 号单）。
- **校验逐条**：名字非空、正则数组非空、每条正则编译得过、等级在四档里、`example` 与 `reason` 的显示宽度不超过 30 列（超了就报是哪条，不许静默截断）。
- **读表归解析，判归闸门**：本单只到「编译好、校验过、能交出去」；匹配与处置在 13 号单。规则表随第一张纸走，闸门不读文件（ADR-0035 决定五、ADR-0032 决定一）。
- **报错形态照老版**：读不到／解析失败／未识别字段三句各说清「出处」，规则只认那六项。
- 表里的正则是数据不是代码：解析站只负责把它们编译成结构，不解释任何一条命令的含义。

## 验收

- [ ] `go build ./...`、`go vet ./...`、`gofmt -l .`、`go test ./...` 全干净
- [ ] 随包那份规则全部加载通过；坏样至少五条各跑一次（未识别字段、等级非法、正则坏、`regex` 空数组、示例超 30 列），报错逐字等于老版
- [ ] 一条规则挂两条正则、命中任意一条即算命中（形状由本单的加载结果证明：编译后的条数对得上）
- [ ] `enabled = false` 的规则加载后不参与判定（本单证明它被读出来且标成了关）
- [ ] `-h` 与配置那几条（04、05）不受影响
- [ ] 红线不加新条目

## 不在这单

命中的判定（去注释、路径片段整备、排序）、警告框的排版、问人。

## 做完之后

交出去的那份判据长什么样写进 `## Comments`；13 号单照它判。
