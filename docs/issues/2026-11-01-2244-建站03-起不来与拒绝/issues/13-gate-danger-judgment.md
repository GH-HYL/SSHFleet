# 13: 危险命令——判出等级，两档处置

**要做的**：`-c` 的命令原文或 `-s` 的脚本正文，按判据表判出危险等级：命中禁止档就造拒绝、把那张框交给塔尖打、以 1 退；命中提醒档就把框打出来、问一句，答否造拒绝（当场喊停），答是放行。

**Blocked by**：01（`Refusal`）、06（编译好的判据）、08（命令原文与脚本正文在纸上）、11（问人）。

**Status**：done

## 判据

- **判定对象是命令原文**（ADR-0019）：不管命令写在 bash、python、perl、node、php 里，都按同一份文本匹配。判定前先整备：去注释、路径片段处理；整备规则照老版，一处不添。
- **一条规则可挂多条正则**，命中任意一条即该规则命中；同一条规则的多次命中合成一条（带全部行号，升序去重）。
- **四档排序只有一处，住闸门**：`forbidden` 在前，其余按 `high`／`medium`／`low`。取值是契约里的四个常量，顺序这张 `map` 只在闸门写一次——解析那边只校验取值、不排序，所以不会出现第二份顺序知识。
- **两档处置照老版，但闸门一行都不打**（ADR-0032 第四条末、ADR-0034 决定八）：
  - 禁止档 → 造拒绝，`Say` 就是那张 `✕  发现禁止命令  ✕` 的框 → 塔尖交 `console` 打到 stdout → 以 1 退。**不往下递纸**。
  - 提醒档 → 把「框 + 问句」合成一屏交给 `ask` 打出并收一行；答否 → 造拒绝（`Say` 是「操作已取消」，stdout）；答是 → 放行；`ask` 交回「按缺省放行」（`--yes`）→ 放行，并由闸门让 `log` 记一条「非交互模式放行危险命令：…」。**框照打**——`--yes` 只替人回答了「y」，不该连「命中了危险规则」也抹掉。
- **闸门不拼句子、不打屏**：框与问句由 `message` 排，闸门只交「命中了几条、各是什么档、哪一条规则」这些事实。
- 没有命中就原样放行，纸的字段一个不改（ADR-0035 决定三：闸门除了结论不加数据）。

## 验收

- [ ] `go build ./...`、`go vet ./...`、`gofmt -l .`、`go test ./...` 全干净
- [ ] 判定样本：写入注释里的危险命令**不**命中（去注释生效）、路径片段（`/bin/rm`）命中、同一条规则三处命中合成一条带三个行号、四档混排按风险降序
- [ ] 禁止档跑一次：stdout 有那张框、退出码 1、没有往下走（老版对照）
- [ ] 提醒档答 `n` 跑一次：框 + 问句 + 「操作已取消」+ 退出码 1
- [ ] 提醒档答 `y` 跑一次：框 + 问句，然后走到「流水线还没接上」（过渡形态，04 删）
- [ ] 带 `--yes` 跑提醒档：不问、框照打、日志里有「非交互模式放行危险命令」那条
- [ ] 无命中：拒绝为 nil，纸原样交回
- [ ] 红线不加新条目
