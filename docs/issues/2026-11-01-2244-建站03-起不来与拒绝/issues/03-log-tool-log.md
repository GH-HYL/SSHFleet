# 03: 工具日志建起来、写得进去、致命错误落得下

**要做的**：启动段跑起来之后，磁盘上有一份工具日志，里面记着这次的工作路径、原始命令行（脱敏后）、日志目录；任何一个「起不来」都把那段话逐行写进日志再退；错误屏末尾那一行「日志：<绝对路径>」指得到它。做完之后，起不来的现场不会只剩屏幕，关掉终端也查得到。

**Blocked by**：无，可立即开工。

**Status**：ready-for-agent

## 判据

- **路径由调用方给，日志包不记路径**（ADR-0032 第四条 `log` 那行：「路径由 `archive` 给」）。本阶段 `archive` 还没落地，所以由塔尖把契约里那行内置常量递进来——`Init(路径 string)` 收一个完整路径，日志包自己不 import 解析、不读配置、不记全局路径。`archive` 落地后（随 04）改由它发路径，`Init` 的签名不变。
- **「日志在哪」是个纯计算**：另给一个入口，按内置常量加当前目录算出**绝对路径**，不读任何包级状态、不依赖「建没建起来」。解析造屏时向它要那一行「日志：」（老版 `toolLogPath` 的语义，但不再是查全局变量）。
- **没有包级可变状态**：句柄由 `Init` 返回、由塔尖持有并关闭；日志包不留一个「当前日志」的包级变量——那会让同一事实有两个来源。
- 写下去的内容逐条照老版步骤 2：分隔线、`SSHFleet工具开始执行`、工作路径、日志目录与文件名。**「原始选项/参数」那一行本阶段不写**：它要先脱敏，而脱敏归 `mask`（随阶段 07）；宁可缺一行，也不拿明文顶替（见过渡形态第 6 条）。
- **致命错误逐行落日志**：错误文本本身就是多行的（问题／原因／提示），每条日志一行、续行缩进两格、格式与其他行一致，写完关闭句柄——`os.Exit` 不跑 `defer`，这一笔必须显式做。这一笔由塔尖在退出那条路上调。
- **建不起来时只交事实**：`Init` 失败返回一个错误，不造屏、不退出、不 panic；那一屏由塔尖交给 `message` 造。
- 日志包只写日志，不写报告、不拼句子、不打屏（类一）。

## 验收

- [ ] `go build ./...`、`go vet ./...`、`gofmt -l .`、`go test ./...` 全干净
- [ ] 正常启动一次，`history/SSHFleetTools.log` 里那几类行都在、顺序与老版一致（拿老工程同一份配置跑一次对照）；**「原始选项/参数」那一行不在**，且这一点在 `## Comments` 里写明是已知缺口
- [ ] 造一个「起不来」：日志里逐行都有那三段话，续行缩进两格
- [ ] 日志建不起来（把 `history` 建成同名文件）时 `Init` 返回错误，自己不退出、不打屏
- [ ] 日志包里没有任何包级可变状态（读代码确认，`## Comments` 写明）
- [ ] 红线不加新条目

## 不在这单

执行期日志（`SSHFleetExec.log`，随阶段 04）、日志轮转、日志里的执行明细。

## 做完之后

日志包的导出面写进 `## Comments`；12 与 14 号单靠它拿路径。
