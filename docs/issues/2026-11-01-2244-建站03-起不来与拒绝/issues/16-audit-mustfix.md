**顺带修的（不在审计清单里，但都是「跟老版不一样」——规格的判据表点过名）**

1. **三条原话抄错了**：老版是「不认识的选项：--zzz（使用 -h 查看帮助）」「选项 -c 缺少值（使用 -h 查看帮助）」「-n 参数格式错误，并发连接数必须是正整数」，此前抄成 pflag 的英文原文与缩短过的称呼（并发数／命令或传输超时／连接超时）。
2. **空值等于没给**：老版 `-c ""` 与 `--change-password ""` 落进「模式零个」，新版原来报「不能为空」。改成按值认模式。
3. **`-n 0`**：老版放行（0 等于不填），新版原来报非法。
4. **改密三条互斥**（与 `-a`／`-p`／`-k`）：规格判据表里有、代码里没有，补上。
5. **材料自检的「原因」**：老版只取系统那一句（`The system cannot find the file specified.`），新版原来带着 `open ./x.sh:` 前缀。
6. **危险规则编译补 `(?i)`**：老版编译时统一加，`RM -RF /etc` 此前漏报。

**认下的差异（列在明处，不当漏项）**

1. **`--no-shell` 配一个读不到的脚本**：老版先报 no-shell 冲突，新版先报脚本读不到——材料自检在参数合规之前，是分站造成的顺序差，与阶段 03 规格已认下的「判据表先于参数合规」同类。
2. **放行之后没有下一站**（`-n 0`、提醒档 `--yes`、读到输入结束）：老版继续走到读清单，新版停在「还没接上」。过渡形态，随 04 消失。
3. **`--gen-key`**：阶段 08。
4. **多余位置参数没接**：老版 `-c "echo hi" extra` 报「出现多余的参数（未被使用）：extra」加「常见原因」三条，新版静默忽略。这是**漏判**，不在本单七条、也不在规格判据表里——按「范围外只报告」记在这儿，要不要现在收，请开发者定。
5. **TOML 语法错原文**：阶段 03 规格已记。

**契约动了三格（待追认）**：`Task.Path`、`RunParams.SudoGiven`／`NoSudoGiven`、`RunParams.Answer`。前两格是本单 H5、H6 的直接落点；`Answer` 是改密互斥要判的那一格。按阶段 03 规格「六格已获授权自行落」的预填充口径办的，已在本图「框架条目」追加一行。
