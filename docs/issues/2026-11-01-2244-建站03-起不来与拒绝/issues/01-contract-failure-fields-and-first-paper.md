# 01: 契约里放这几样——两个失败类型的字段、一句话的流、四档常量、日志路径、第一张纸

**要做的**：让「起不来」与「拒绝」各带得动一屏话，让塔尖拿得到那屏话又分得清该写哪条流，让闸门手上有纸可判，让两站共用同一张四档表、同一行日志路径。做完之后，解析站造得出一个带话的「起不来」，闸门造得出一个带话的「拒绝」，塔尖读得到它们，而别处仍然造不出「拒绝」。

**Blocked by**：无，可立即开工。契约这六格按开发者 2026-11-01 的原话（「你自己评估到底应该写什么、创建什么，这属于一个预填充的行为，允许后面推翻」）由执行者自行定形，不走「单独点头」那道门；代价是形状由我定、后面允许推翻，所以每格都要在注释里写明「预填充、打算在第几阶段重做」。

**Status**：ready-for-agent

## 判据

- `contract.CannotStart` 落两个字段：`Where`（老版 `[function:cli]` 那个环节标签）、`Say`（那一屏话）。**类型可见、不设构造函数**——它是事实不是权力，谁都能造（ADR-0034 决定三）。
- `gate.Refusal` 落一个字段：`Say`（那一屏话）。**只有这一个**——「写到哪条流」住在 `Text` 上，别在两处各放一份（同一件事两个来源）。构造函数不导出；塔尖读得到 `Say` 才交得出话，而别处写 `gate.Refusal{…}` 会被第五类当场判红——「造不出来」靠的是这条检查，不是靠字段藏起来。
- `contract.Text` 加一格「写到哪条流」。老版里同一句「参数错」走 stderr、「发现禁止命令」走 stdout，这个差别重定向时看得见，必须在纸上带着，不能由塔尖猜。**这一格是把阶段 02 那笔「Text 字段导出」的旧账再扩大一次（02 交付时标了待追认），一并请开发者追认。**
- 四档风险等级的**取值**落契约常量（`forbidden`／`high`／`medium`／`low`）：解析拿它校验规则文件。**先后顺序不进契约**（契约只许类型与常量，顺序会落成一张 `map`，那就是变量了），顺序只住闸门一处。
- **工具日志的落点落契约常量**（`history` 目录名与文件名两个内置值）：塔尖把它递给 `log`，`log` 自己不记路径、不 import 解析（ADR-0032 第四条 `log` 行「路径由 `archive` 给」，`archive` 落地前由常量顶，见阶段规格过渡形态第 7 条）。
- 第一张纸（解析交闸门）落**最小形状**：这次干什么（模式标签 + 该模式的参数）、执行参数（并发、超时、执行身份）、判据表、解析时发现的问题。`对谁做`、`执行资源`、`运行上下文` 本阶段**不加**，随阶段 04。
- 契约包仍然一个函数都没有，只依赖标准库。
- 六格都标成**预填充**：注释里写明「预填充：占位，随阶段 04 补齐/重做」，并写清这一版刻意没做什么（纸缺三格、拒绝的构造函数还没有第二个用例）。
- 站仍然只露「一个函数加一个类型」：纸的类型在契约包，不算站的导出；`gate` 的 `Refusal` 是出口白名单点名放行的那个例外。
