# 规格：阶段 03——起不来与拒绝

**Status**：done

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

使用者敲下去之后，工具得先告诉他三件事里的哪一件：**东西不齐、跑不了**（配置删了、规则文件没解压出来、脚本读不到），**东西齐了、这事不许干**（参数搭配错、命令命中禁止规则、他在警告框前答了否），或者**可以跑**。

新工程现在这三件事长成同一个样：除 `-h`、`--help`、空参数之外，一切用法都回一句「这条用法还没接上」，退出码一律 1。也就是说，它连「我的配置是不是写错了」都答不了——而这是使用者每天最先撞上的那一屏。

## Solution

把启动这一段做完：**塔尖读 argv 之前先适配控制台、把日志建起来；解析站把配置、判据表、命令行三份材料读进来，读不成器就造一个「起不来」；闸门拿解析交来的那张纸下判断，判下来不让走就造一个「拒绝」；塔尖按结局把屏打出去，再从退出码表换码退。**

做完之后，老版启动段那六种失败（配置读不到、配置空或格式错、必须项缺、输入不合规、危险命令、当场喊停）在新工程里同样是六种，话与退出码逐字逐码相同；唯一的差别是那一条已经定过的行为例外：改密提示词表缺「密码过期」时，新工程一启动就报（老版跑到改密那一步才报）。

这一段之外，本阶段一律不出手。

## User Stories

1. 作为运维人员，我把 `config/` 删了再敲命令，拿到的是「这个位置没有配置文件 / 应该在这里 / 当前目录 / 提示」那四行原话，退出码 1。
2. 作为运维人员，我把配置里的引号改坏，拿到的是「解析 TOML 失败：…」加上一句「多数是引号或方括号没配对」；我把 `timeout_execute` 那行删了，拿到的是「配置缺少必填字段：execution.timeout_execute」。
3. 作为运维人员，我把 `-u` 和 `-d` 一起给，拿到的是「执行模式选项：-c、-s、-u、-d、--change-password 互斥，只能指定一个」，退出码 1。
4. 作为运维人员，我写 `-c "rm -rf /"`，看到那张红色的「发现禁止命令」框，进程以 1 退出，一个字都没跑。
5. 作为运维人员，我写一条命中「提醒档」规则的命令，看到黄框，回车答 n 之后看到「操作已取消」，退出码 1；答 y 则继续往下（本阶段走到「流水线还没接上」）。
6. 作为运维人员，我带着 `--yes` 跑同一条提醒档命令，不问我、直接放行，工具日志里留一条「非交互模式放行危险命令：…」。
7. 作为运维人员，我在启动之前按 Ctrl+C，进程以 130 退出，控制台不乱码。
8. 作为运维人员，我在 Windows 出厂控制台（936 码页）里跑，中文不乱码；退出之后那个窗口的码页回到原样。
9. 作为运维人员，我删掉 `config/keywords_error.conf` 里「密码过期」那一类的关键词，**一启动**就拿到「改密缺少入场信号」那句话（老版跑到改密那一步才说）。
10. 作为维护者，我知道哪个失败该由谁造：「起不来」是解析自检出来的，「拒绝」只有闸门造得出来；别处想拦人，得先造出那个类型。
11. 作为维护者，我看塔尖仍然只有几十行：它不判参数、不读配置、不拼句子，只认结局、把屏交出去、查表退出。
12. 作为维护者，我改一条判据表的口径只需要改解析站那一处；闸门里没有第二份读表的代码。
13. 作为维护者，我一眼看得出每个失败归谁：配置/规则表/脚本/上传源读不到是「起不来」，参数搭配、取值、危险命令、当场喊停是「拒绝」。

### 二、两类失败的判据（本阶段的核心）

**一句话判据：缺的是「工具自己要用的东西」，叫起不来；对不上的是「这次给的东西」，叫拒绝。**

| 起不来（解析造 `contract.CannotStart`） | 拒绝（闸门造 `gate.Refusal`） |
| --- | --- |
| 配置文件读不到、TOML 格式错、含已移除的段、未识别字段、必填项缺、取值非法、路径不是本机绝对路径 | 模式零个或多个、`--no-shell` 搭配错、`-p` 与 `-c`／`-s` 撞、`-p` 没以 `/` 收尾、`-d`／`-u` 缺 `-p`、`--sudo` 与 `--no-sudo` 同给、`-c` 为空、远端路径不以 `/` 开头或含换行、`-n`／`-t`／`-T` 非正整数、改密参数不合规 |
| 日志建不起来 | 命令或脚本命中 `forbidden` 档规则 |
| 三份判据表读不到、格式错、未识别字段、必须项缺、正则编译失败、等级不在四档里 | 提醒档问人，答否（当场喊停） |
| `--change-password` 模式下，`keywords_error.conf` 里「密码过期」那一类没有关键词（**行为例外，启动即报**；不带这个选项时不成立） | 提醒档问人时读到输入结束（同样算当场喊停） |
| 脚本文件读不到／是目录／为空／二进制／非 UTF-8；上传源读不到／是符号链接／目录里没有真文件；下载的 `-p` 本机目录读不到或不是目录；清单原值既不是文件也当不了一条记录 | 信封标签与载荷对不上（随阶段 04 才有可判对象，本阶段只留判据） |

**「解析时发现的问题」是事实，不是结论**：认不出的选项、缺值、取值认不出（`-n abc`），解析只记「哪个选项、原值是什么、哪一处对不上」，由闸门下「这条不过」的结论（01 号工单的原话：语法错解析只发现、不下结论）。

**外壳句逐字照老版**：老版 `fatal("cli", wrapFatal("选项/参数合规性检查未通过", err))` 这一层外壳，在新工程里仍照原样出，即使那条失败按新分类归了「起不来」。理由只有一条：09 的逐字比对要过，而这句话是使用者看得见的面。

> **判读，写在这里免得下一个人当成错**：这句话在两个失败类 **共用**，不是「拒绝的专属外壳」。ADR-0034 决定七 要的「判据缺失单列一种报错口径」，说的是**别把「东西不齐」写成「你参数错了」**——老版这三处判据表的原话本来就是这个口径，照搬即满足；而「材料读不到」在老版里本来就套在「合规性检查未通过」这句壳里，改掉它就是改使用者可见面。**结论：外壳不改，两类分开靠类型不靠措辞。**

### 三、契约要动的三样（**属「单独点头」档**）

1. **`contract.CannotStart` 落字段**：`Where`（老版 `[function:cli]` 那个标签）与 `Say`（那一屏话，`contract.Text`）。类型可见、无构造函数——谁都能造，这是它存在的意义。
2. **`gate.Refusal` 落字段**：只有 `Say`（那一屏话）。「写到哪条流」住在 `Text` 上（见第 3 样），不重复放第二份。构造函数不导出；第五类检查盯着「`gate.Refusal{}` 只许出现在闸门包里」。塔尖读得到 `Say`，才交得出话。
3. **`contract.Text` 加一格「写到哪条流」**：老版里同一句「参数错」走 stderr、「发现禁止命令」走 stdout，这个差别是使用者看得见的（重定向时一半进文件一半进屏幕）。塔尖不判流，`console` 按这一格选流。

   > 这一样有个旧账要一并认：`Text` 是阶段 02 落的，字段导出意味着任何包都造得出一句话交给 `console`，与 ADR-0032 第四条「另一种包连字都构造不出来」不完全一致——02 交付时已标成「待追认」。本阶段在它上面再加一格，是把那笔账扩大一次，**请在点头时一并追认或否掉**；否掉就改走「两套屏类型各自由 `message` 造」，那样 `console` 的收口更硬，代价是塔尖要认两种类型。

**第四样是「第一张纸」提前到本阶段**：交割清单里那张「解析交闸门、口径是要做什么」的纸，原计划随阶段 04 落格子。本阶段闸门要判东西，手上不能没有纸（否则一个函数挂六七个参数，正撞「接口变宽」）。所以本阶段落**最小形状**：这次干什么（模式标签 + 该模式的参数）、执行参数（并发、超时、执行身份）、判据表、解析时发现的问题；`对谁做`、`执行资源`、`运行上下文` 随阶段 04 加格子——加格子是加字段，不是推倒重来。

> **这六格已获授权自行落**：开发者 2026-11-01——「不行，你就造一个，后面该造造，直接给他代码，类似于填充框架。为了现在能完工，你自己评估到底应该写什么、创建什么，这属于一个预填充的行为。允许后面推翻」。据此按预填充办：形状由执行者定、标明会被重做、允许后续阶段推翻（推翻时在那一阶段的工单记一句）。落完之后在本图「框架条目」与 04 号迁移地图各追加一条更新记录。

### 四、判据表由解析读，闸门只判

危险规则、错误分类、改密提示词三份表**由解析读一次、校验一次，随第一张纸交给闸门**（ADR-0035 决定五：判据表进第一张纸，塔尖不单独递）。

**与 04 号迁移地图那一行的关系**：那张表把 `dangercheck/rules.go`（读表那半）划在闸门下面。本阶段按 ADR-0032 决定一「校验归最懂那份材料的那一站」与 ADR-0035 决定五办——**读表与编译正则归解析，匹配与处置归闸门**。迁移地图那一行按「判」读，不按「读」读；这一条已在 04 号工单末尾追加更新记录。

**四档的取舍**：四个合法取值（`forbidden`／`high`／`medium`／`low`）写成契约里的字符串常量——取值只有一处；**先后顺序的知识只住闸门**（解析只校验「在不在四档里」，不排序）。顺序不放进契约，是因为契约只许类型与常量、不许变量，而「顺序」在 Go 里落成一个 `map` 就破了这条规矩。

### 五、话术：四套，全部由 `message` 造

| 哪一套 | 形态（逐字照老版） |
| --- | --- |
| 起不来 | `[ERROR] [function:<环节>] <外壳>：<问题>\n原因：…\n提示：…`，末尾统一附 `日志：<工具日志绝对路径>`（日志还没建起来时没有这一行） |
| 判据缺失 | **外壳照老版各处原样，不统一**：危险规则表那两处带 `危险关键词内容检查未通过`，错误分类表与改密提示词表两处不带外壳。ADR-0034 决定七 要的「单列一种报错口径」落在**话的内容**上（说的是「东西不齐、工具没能力判断」，不是「你参数错了」），不是另起一套版式——老版这三处的原话本来就是这个口径，照搬即可 |
| 拒绝 | 三种来源各自照老版：输入不合规走 stderr，同一副 `[ERROR]` 外壳，**末尾同样附「日志：」那一行**（老版所有 `fatal` 都追加）；禁止档走 stdout 那张框（`✕  发现禁止命令  ✕` 加框体），没有 `[ERROR]` 也没有日志行；喊停走 stdout「操作已取消」，读到输入结束时那半句「输入结束，操作已取消」由 `ask` 先打出 |
| 危险提醒 | 老版那张 `⚠  发现危险命令  ⚠` 框：多命中全列、按风险降序、字段按显示宽度截到 46 列、装饰符不带变体选择符 |

**颜色**：`message` 拼出来一律带色码，`console` 打之前决定要不要去掉，判据**照搬老版、一个字不改**——Windows 上先看这条流是不是控制台：不是控制台（重定向、管道）**照旧输出转义序列**；是控制台就看 VT 位，位开着照旧输出，没开就替它打开，开不起来才整场不输出转义序列。非 Windows 恒输出。**所以重定向到文件时文件里仍有转义序列，与老版一致**，不是「重定向就去色」。

**塔尖一个字都不拼**：起不来的屏由解析造（它知道是哪个环节、哪句话），拒绝的屏由闸门造。塔尖只把 `contract.Text` 交给 `console`。

**「日志：」那一行从哪儿来**：`log` 只提供两样东西——建起来（返回一个句柄给塔尖收尾）与「工具日志的绝对路径」（**纯计算**：内置常量加当前目录，不读任何包级状态）。解析造屏时向 `log` 要路径；而「日志建不起来」那一次失败发生在解析之前，那屏由塔尖把「环节 + 三段话」交给 `message` 造——这是塔尖唯一一处自己触发造屏的地方，它仍然不拼字、不判格式。

**闸门不碰屏幕**（ADR-0032 第四条末、ADR-0034 决定八）：提醒档那张框与那个问句合成一屏，交 `ask` 打出来再收一行；禁止档把「拒绝 + 框」交回塔尖打。闸门自己一行都不写。

### 六、退出码表

`exitcode` 只认种类，不认类型（塔尖认完把种类交过去）：

| 种类 | 码 |
| --- | --- |
| 成功（帮助、跑完） | 0 |
| 起不来 | 1 |
| 拒绝 | 1 |
| 被中断（启动阶段按 Ctrl+C） | 130 |

与老版逐项一致：老版只有 `0`／`1`／`130` 三个值，「拒绝」与「起不来」同码是既有行为，本阶段不拆。

### 七、塔尖认几种结局（本阶段）

- **一句话**（帮助）→ 打屏 → 0
- **起不来** → 打屏 → 1
- **拒绝** → 打屏 → 1
- **放行**（拿到第一张纸，但没有下一站）→ 打一屏「流水线还没接上」→ 1

第四种是**过渡形态**，随阶段 04 消失；它由 `message` 造，塔尖只搬。另外塔尖本阶段多两件活：**码页适配**（步骤 0：`console` 里一个「切过去」、一个无参的「还回去」，塔尖在步骤 0 与每个退出点各调一次，**不持有句柄**）与**早期信号**（启动段按 Ctrl+C 还码页后以 130 退），两件都在老版 `main` 的同一处。

塔尖手上有四样：argv、入口那两个常量（版本号与工具日志路径）、日志句柄（建与关都归它，ADR-0032 第五条「退之前用日志包记一笔」本来就是它的活）、以及各站递回来的结局。**它不再有第五样**：不拿配置、不拿规则表、不拿终端宽度。

### 八、过渡形态清单（04／05 接手时逐条替掉，别当口径抄）

1. 放行之后打「流水线还没接上」并以 1 退（04 接上执行站）。
2. 第一张纸只有四格（对谁做、执行资源、运行上下文随 04）。
3. `-f` 清单与 `-a` 代填只判「原值能不能当一条记录／能不能当一个文件」，内容一行都不读（04／05）。
4. 信封标签与载荷对不上这一条判据只有形状、没有可判对象（04）。
5. 危险提醒档答 y 之后无处可去，落回第 1 条。
6. **工具日志里「原始选项/参数」那一行本阶段不写**（它要脱敏，而脱敏归 `mask`，随阶段 07）。日志其余各行与老版逐字相同；这一行是已知缺口，写在明处，不许拿明文顶替。
7. 日志路径暂时由解析向 `log` 那一个纯计算要（内置常量加当前目录）；`archive` 落地后（随 04）改由它发路径，`log` 的入口签名不变。
8. 工具日志里没有执行期日志（`SSHFleetExec.log`）——那一份随 04。

## Testing Decisions

- **接缝五处**（ADR-0037 决定三，本阶段新增三处）：
  - 塔尖的进程出入口（已有，本阶段另立两条同口子的测试：起不来、拒绝）；
  - 解析站的入口（已有，本阶段扩到配置、判据表、命令行的三种失败形状）；
  - 闸门的入口（新）：递一张纸，收「一张纸 + 一个拒绝」；
  - `message` 的那一件事（已有，本阶段扩到起不来、拒绝、危险框三套）；
  - `ask` 的那一件事（新）：摆一屏、收一行；`exitcode` 的那一件事（新）：种类换码。
- **红线区只判形状**：塔尖那两条起真进程，只看**退出码与首行在哪条流上**，不判措辞；闸门入口只判「不让走时返回的拒绝非空、放行时为 nil」；`exitcode` 只判「四个种类换出来的四个数」；`ask` 只判「非交互时按缺省放行、读到输入结束交回事实」。
- **红线一律新增、不动已有 24 条**：塔尖那两条起不来与拒绝**各开新文件**，不去改那张帮助的测试——ADR-0037 只把「删掉、改名、缩窄引用面」算改，而顺手往旧测试里加断言会让指纹跟着变，说不清算不算改，索性不碰。
- **自定义区跟着被测包走**：
  - 解析站：配置三份 `testdata` 小样（缺字段、坏引号、未知字段、非法取值、路径形态四种）；三份判据表的坏样（未识别字段、等级非法、正则坏、第一组空、step 缺 value）；选项表逐条对老版；「语法错只记事实」的样本。
  - 闸门：两类各一组样本——参数搭配（互斥、`-p` 收尾、`-n` 取值）、危险判定（去注释、路径片段、同规则多处命中、四档排序）；期望值用**写死的字面量**，不用被测代码自己算。
  - `message`：三套屏在「颜色留着」与「颜色去掉」两档下各断言一次，期望串从老工程跑出来录。
  - `ask`：非交互跳过时交回的「按缺省放行」这个事实、读到输入结束时交回的「没答完」。
- **A/B 比对不进两区**：本阶段结束在 `build/` 下当天沙盒起新老两个二进制，六种失败各跑一次，比 `stdout`、`stderr` 与退出码；结果贴进本议题 `## Comments`。
- **环境类失败不进两区**：码页适配要在 Windows 真控制台里手工跑一次（本环境有），结论写进对应工单 `## Comments`；跑不出来就写明哪一步没法验。
