# SSHFleet 全 Go 重写 · 规划覆盖面

Status: needs-info

> 本文件定义**规划要覆盖哪些面**，以及每一期怎么按面推进。
> 目的：防止"拆东补西"——盯着一段旧代码改得挺好，回头发现另一个面上有个老行为没接住。

---

## 一、十个覆盖面

| # | 面 | 主问题 | 时点 |
| --- | --- | --- | --- |
| F1 | **功能面** | 这个用户可见功能还要不要？要的话行为变不变？ | 贯穿 M1–M5 |
| F2 | **结构面** | 这段逻辑属于主干哪一步？放哪个目录？函数怎么分层？ | M1 起；每期动工前先定归属 |
| F3 | **数据面** | 工具读写的一切文件：格式、字段、路径、兼容性 | M1 / M2 / M4 / M5 |
| F4 | **接口面** | 外部怎么调用、看到什么、依赖什么 | M1 |
| F5 | **行为面** | 出错时怎样？边界在哪？与旧版是否一致？ | M2（字段补全 / 输入记忆）、M3、M4 |
| F6 | **构建面** | 从源码到可运行产物（依赖版本、交叉编译、产物落位） | M6 |
| F7 | **文档面** | `CONTEXT.md` 词表、`docs/adr/`、README、CHANGELOG、迁移说明 | `CONTEXT.md` 与 ADR **已建**并随决策更新；README / CHANGELOG / 迁移说明在 M6 |

| F9 | **验证面** | 拿什么对照才算做对 | 各期出口 |
| F10 | **风险面** | 已知的坑 | M1 识别；各期逐个消解 |

## 二、每个里程碑必过的面

| 里程碑 | 必过面 |
| --- | --- |
| M1 框架层 | 结构面、接口面、数据面（配置）、风险面（识别） |
| M2 数据层 | 数据面（清单 / 凭据）、行为面（字段补全 / 输入记忆）、结构面 |
| M3 执行层 | 行为面（超时 / 中断 / 并发 / 部分成功）、风险面（SFTP / 路径差异）、结构面 |
| M4 判定层 | 功能面（危险检测 / 错误分类）、行为面（等级 / 退出码）、数据面（规则文件）、验证面 |
| M5 输出层 | 数据面（归档结构）、功能面（呈现 / 报告 / xlsx）、结构面 |
| M6 收尾 | 构建面、文档面、迁移面 |

## 三、每期动工的规程

1. **先过面**：把本期应覆盖的面逐条列出，找出**决策点**（反常、不一致、要改的地方）。
2. **以旧代码为事实来源**：去旧实现里找答案，不凭印象（D20）。
3. **三问**：① 能不能优化 → ② 优化后是否**保持原功能** → ③ 保持不了、或确有更优方案 → **ask 用户裁定**。
4. **结论归宿**：差异进 `spec.md` 决策表；与旧代码一致的不落文档（详见 D20）。
5. **提问按前沿分批**：一轮只问当前前沿（前置已定的问题），编号 + 附推荐，答完再推下一轮；依赖未定问题的题留到后续轮次。

> 不记录与旧代码一致的内容——旧代码本身就是那份记录，重写时直接看它。
