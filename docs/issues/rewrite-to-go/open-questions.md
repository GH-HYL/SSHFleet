## 待决的 ADR 候选

**「上传模式 `-p` 必须 `/` 结尾」** —— 已裁定维持（无条件要求），但理由容易被人误解为一处冗余校验。

- 难回退：是（改掉会让既有命令报错）
- 不看背景会疑惑：是（"传单个文件为什么也要写 `/`？"）
- 真有权衡：是（宽松 vs 消歧义）

理由：`/` 结尾是**消歧义约束**——断言"这是目录"，排除用户误以为远端路径是文件名／会被重命名。

→ 待用户确认后写入 `docs/adr/`。

## 我直接定案（实现层，不占用户判断）

| 事项 | 结论 |
| --- | --- |
| 凭据解码缓存 | **删除**。旧版缓存是为"校验 / 使用两阶段读盘"而生；新版把两阶段合并为一次"读 → 校验 → 直接用"，缓存失去存在理由 |
| `--disinteractive` 下 `get_user_confirmation` 的语义 | 改为**显式**表达（非交互即返回"确认"），不再借用 `yorn` 参数值——旧写法需回溯每个调用点才能判断行为 |
| 表头识别 | 改为"首列解析失败**且**该行含逗号 → 判为表头；否则报错"，落实 D13（域名不得静默丢弃） |
| 错误出口 | 全链路返回 `error`，`main.go` 独占退出权；保留"致命 / 警告后继续"的区分 |
