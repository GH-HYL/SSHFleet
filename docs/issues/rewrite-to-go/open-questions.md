## 前沿：路径解析规则（唯一未决）

用户点出：「好多相对路径的问题，尤其凭据的相对路径，还支持可配置，解析起来比较麻烦。」
选项：不是"沿用旧的三套"，而是**重新设计**（用户明确"不用管 old 代码，可以择优"）。

### 诊断：复杂度从哪来

不是来自"相对路径 + 可配置目录"这个需求本身，而是来自**旧实现里三套并存的规则**：

| 旧规则 | 用在哪 | 基准 |
| --- | --- | --- |
| 字符串梯子 | 清单第 4/5/6 列、配置凭据字段 | 绝对直用；相对拼 `secret_dir` |
| `~` 展开、原样 | `-k` 路径 | 当前工作目录（且不吃"禁空格"限制） |
| 先找再拼 | `--convert-password` 目标 | 先按原样找，找不到再拼 `secret_dir` |

三套规则里，**只有"先找再拼"是真的多余**——它让解析结果依赖于"当前目录碰巧有没有同名文件"。

### 提议：两条规则，一个解析顺序

**分类不按参数名，按"这个路径指向什么"：**

| 类别 | 包含 | 相对路径的基准 |
| --- | --- | --- |
| **凭据路径** | 清单第 4/5/6 列 · 配置 `account.password` / `key` / `key_passphrase` · `-k` 路径 · `--convert-password` 目标 | `secret_dir` |
| **操作路径** | `-f` 清单 · `-s` 脚本 · `-u` 上传源 · `-p`（下载模式的本地目录） | 当前工作目录 |
| **远端路径**（不参与本地解析） | `-p`（上传模式的远端目录） · `-d` 下载远端路径 | — |

**两条规则共用同一套解析顺序，只差基准：**

```
去首尾空白 → ~ 展开 → 是绝对路径则原样使用 → 相对路径则拼基准
```

**其余简化：**

1. **`secret_dir` 未配置时**：凭据类相对路径无解 → 明确报错，给两条出路（"写绝对路径" 或 "配 `secret_dir`"）
2. **取消 `secret_dir = "none"` 的宽容**：那是 YAML 裸写 `None` 的产物；TOML 里 `secret_dir = ""` 就是未配置，`"none"` 就老老实实是个目录名——语义不再有歧义
3. **`-k` 归入凭据类**：它就是凭据，跟清单第 5 列同性质，走同一条规则
4. **删除"先找再拼"**：`--convert-password` 目标改走凭据规则

### 收益

- 三套规则 → 一条解析顺序 + 一个基准参数，实现上是一个函数
- 用户侧只需记一句话：**"凭据文件的相对路径拼 `secret_dir`，其他相对路径按当前目录"**
- 解析结果不再依赖"当前目录碰巧有什么文件"

### 代价（唯一一处行为变化）

`--convert-password pw.txt` 若 `pw.txt` 恰好在当前目录、且没配 `secret_dir`，旧版会命中它，新版会报错。
→ 但 README 里的用法本来就写的是 `~/.MyPW/pw.txt`（`~` 展开，两版一致），实际影响面很小。

**待用户确认后写入 `spec.md`。**

## 待决的 ADR 候选

**「上传模式 `-p` 必须 `/` 结尾」** —— 已裁定维持（无条件要求），但理由容易被人误解为一处冗余校验。

- 难回退：是（改掉会让既有命令报错）
- 不看背景会疑惑：是（"传单个文件为什么也要写 `/`？"）
- 真有权衡：是（宽松 vs 消歧义）

理由：`/` 结尾是**消歧义约束**——断言"这是目录"，排除用户误以为远端路径是文件名／会被重命名。

→ 待用户确认后写入 `docs/adr/`。
