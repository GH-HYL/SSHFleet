# SSHFleet 全 Go 重写 · 方向稿

Status: needs-info

> **只记录与旧实现不同的决策，以及重要架构决策。**
> 与旧代码一致的行为不在此记录——重构时以旧代码为准（见 D20）。
> 旧工程位于工作区内的 `modules/SSHFleet_bak/`，只读参考。

> **编号说明**：D10 已并入 D15；D16–D19 已并入 D26。其余编号连续。

## 一、目标

以 Go 重写整个工具，产出**单一可执行文件**：原 Python 编排层与原 Go 执行引擎合并为同一进程内的一条主干流程。

**这是重构，不是从头开发** —— 目标是一个经得起后续演进的好架构，而不是尽快跑通功能。

## 二、架构决策（与旧实现根本不同）

| # | 决策 | 与旧实现的差异 |
| --- | --- | --- |
| D1 | 单可执行文件 | 旧：Python 入口进程 + 独立 Go 引擎进程 |
| D2 | **不保留事件流模型** | 旧：`init` / `progress` / `result` / `done` 四类 SSE 消息。新：进度聚合归 `internal/batch`、结果统计归 `internal/result` |

| D21 | 框架冻结 | 骨架定稿即硬边界，此后所有改动都在框架内调整 |
| D22 | 内聚优先 | 逻辑上属一体的保持整体，不为拆而拆；允许函数调用链加深 |

### D2 展开：进度相关代码的归属

"事件流"消亡后，进度这条链拆成三段，各有明确归属（D39）：

| 环节 | 归属 | 说明 |
| --- | --- | --- |
| 进度读写器 | `internal/ssh` | 包裹 SFTP 读写的 `io.Writer` / `io.Reader`，传输过程中累计字节数 |
| 进度聚合器 | `internal/batch` | 汇总各节点的字节 / 文件数 / 完成数，跨调用保存状态；与 worker pool 同一生命周期 |
| 进度渲染 | `internal/output` | 终端进度条、速度显示 |

**衔接方式**：`main.go` 把 `internal/output` 提供的渲染函数作为**参数注入**给 `internal/batch`。这是依赖注入（D32 条件 4），不是回调控制生命周期——渲染函数只负责画，不决定流程起止。

### 实现途径优化（Go 相对旧实现的天然做法）

旧实现里有一批做法是被 Python 或双进程逼出来的，换成 Go 后可以走更直接的路。以下均为**实现层**决策，不改变用户可见行为。

| # | 旧实现途径 | Go 的做法 | 收益 |
| --- | --- | --- | --- |
| 1 | 命令 / 脚本经 **base64 通道**下发：本地编码 → 拼进命令行 → 远端 `base64 -d` → 管道给解释器 | `session.Stdin` 直接喂内容，命令仅剩 `bash -lc '…; sudo bash'` | 去掉编解码；**消除命令行长度上限风险**（base64 让命令行膨胀 33%，大脚本会撞 `ARG_MAX`）；引号转义问题从根上消失；日志可直接打印原始内容 |
| 2 | 手写终端宽度与对齐：逐字符查 East Asian Width，加上 `pad_to_width` / `pad` / `center`，散布在三处 | `lipgloss.Width()` / `.Width(n)` / `.Align()` | 一批手写函数消失。旧版曾因此出过"全角标点导致表格错位" |
| 3 | `-k` 三态靠魔法字符串：`nargs='?'` + `const='no_value'`，代码里判 `args.k == "no_value"` | pflag 的 `NoOptDefVal` | 不再需要魔法字符串 |
| 4 | 配置里三个凭据字段各写一段几乎相同的路径拼接 | 一段遍历 | 三段重复变一段 |
| 5 | 未知配置字段靠 pydantic `extra="forbid"` | 解码后取未识别键集合 | 报错能列出具体是哪个键 |
| 6 | `password_security` 声明为 `str` 再 `str()` 兜底（YAML 弱类型） | TOML 强类型，直接 `int` | 少一层转换、少一类错误 |
| 7 | Windows 主密钥读取：起 `reg query` 子进程，再正则解析 stdout | 直接读注册表 | 不起子进程、不解析文本 |
| 8 | 凭据错误码是字符串字面量，拼错会静默落入兜底分支 | 自定义字符串类型 + 常量 | 拼错编译不过 |
| 9 | 危险检测的"间接执行递归提取"手写实现（`bash -c` / `eval` / `ssh` 各自处理） | 遍历语法树里的所有调用表达式 | 递归逻辑不用自己写；对管道 / `&&` / `$( )` / 反引号覆盖更全 |

**明确不动（避免为整齐而整齐）：**

- **字段补全的三套函数不合并。** 端口 / 用户名 / 密码三者看似同构，但优先级链、交互文案、记忆变量、询问时机各不相同；统一会变成一个多分支函数，比三个直白函数更难读（D32）。
- **`check_arguments` 的 23 条校验不表格化。** 把 if 变成闭包表不必然更好读；真正的收益来自"错误统一由 `main.go` 打印"，而不是形式上的整齐。

**须注意的坑：**

- Go 的 `encoding/csv` 默认要求每行列数一致；旧版容忍变长行（缺列自动补空），必须设 `FieldsPerRecord = -1`，否则遇到短行会直接报错。

### D31 展开：路径解析规则

| 路径 | 来源 | 相对路径的基准 | 校验 |
| --- | --- | --- | --- |
| 清单第 4/5/6 列（密码 / 私钥 / 私钥口令） | 清单内 | `secret_dir` | 拼后须存在 |
| 配置 `account.password` / `key` / `key_passphrase` | 配置内 | `secret_dir` | 拼后须存在 |
| `-f` 清单 · `-s` 脚本 · `-u` 上传源 · `-k` 私钥 · `--convert-password` 目标 · `-p`（下载模式的本地目录） | 命令行 | 当前工作目录 | 按各自规则 |
| `-p`（上传模式的远端目录）· `-d`（远端路径） | 命令行 | —（不参与本地解析） | 仍要校验：必须是绝对路径；上传的 `-p` 还要以 `/` 结尾（ADR-0002） |

- `secret_dir` 的定位：只服务凭据文件。配置里那三个字段是**清单列的默认值**，与清单列同性质，故走同一规则
- 统一解析顺序（两类共用一个函数，只差基准）：`去首尾空白 → ~ 展开 → 绝对则原样 → 相对则拼基准`
- 取消 `secret_dir` 字面量 `none` 的宽容：那是 YAML 裸写 `None` 的产物；TOML 里 `""` 即未配置，`"none"` 就是名为 none 的目录名
- 删除旧版 `--convert-password` 的"先按原样找、找不到再拼 `secret_dir`"
- `secret_dir` 未配置时：凭据类相对路径无解 → 明确报错，给出两条出路（写绝对路径 / 配置 `secret_dir`）

**行为变化（两处，均在 `--convert-password`）：**

1. 未配 `secret_dir` 且 `pw.txt` 在当前目录：旧版命中、新版报错（无基准可拼）
2. 已配 `secret_dir` 且当前目录也存在同名文件：旧版先命中当前目录、新版一律去 `secret_dir` 找

README 既有用法写的是 `~/.MyPW/pw.txt`（受 `~` 展开，两版一致），实际影响面小。

## 五、工作方式与编码取向

### D32 展开：编码取向

本工具的形态是一条跑一次就退的流水线，没有长生命周期、没有需封装的并发共享状态。因此：

**主干与各功能环节一律以「函数 + 数据」表达。** 不引入无状态的服务对象，不按 Service / Manager / Handler 分层，不用类型层次表达"是一种"（Go 只能组合）。

**只有满足下列任一条时，才引入带方法的类型：**

| # | 条件 | 本项目命中者 |
| --- | --- | --- |
| 1 | 跨调用保存状态 | 进度聚合器（住 `internal/batch`） |
| 2 | 有生命周期（创建 → 使用 → 释放） | SSH 客户端 |
| 3 | 需满足接口（`io.Writer` / `io.Reader` / `error` 等） | 进度读写器 |
| 4 | 需注入依赖（读哪里、写哪里、问谁） | 交互器、日志器 |
| 5 | 纯数据载体（struct，几乎无行为） | 配置、节点信息、结果记录 |

**明确禁止：**

- 为只有一个实现的东西预先抽 interface（Go 谚语：*don't design with interfaces, discover them*）
- 用 struct 包住一组无状态函数，只为"看起来面向对象"
- 按 Service / Manager / Handler 分层
- 用继承 / 层次表达复用关系

> 按此判据，全工具的对象是**可枚举的**：SSH 客户端、进度聚合器、进度读写器、交互器，加上配置 / 节点信息 / 结果记录三个纯数据载体。其余全部是函数——主干十步是十个函数，每个 `internal/<功能>` 目录是一组函数。

> **补充（回答"方法能不能跨文件"）**：Go 只要求类型与方法同属一个 package，不要求同文件。包内「函数」与「方法」在文件组织上完全等价，都可按功能边界拆到多个文件。

### D39 展开：归属明确

> 用户原话：**「我所有重构逻辑、最终结构、所有代码，要有所归属；可以深度调用，但不需要杂乱无章。」**

**每一段重构逻辑、每一个类型、每一个函数，都必须有明确归属**——能回答"它属于主干哪一步、属于哪个目录"。

- **允许**：函数调用链加深，跨目录按依赖方向调用（如 `batch` → `ssh` → `common`）
- **不允许**：找不到归属的代码；"哪个目录都能放"的代码；为了放不下而新开目录
- **判据**：任何一个文件，都应能说出"它属于 `internal/<某个功能>`，因为……"

配套约束：

- 新目录只在确实存在一个独立功能边界时开，不为收纳零散代码而开
- `internal/common` 有明确准入标准（见第六节），它不是"放不进去就扔这儿"的地方
- 归属一旦定下即为框架的一部分（D21 框架冻结）

## 六、骨架与硬性约束

依据 `个人开发规范.md`（原文为硬性约束）：

- 入口 `main.go` 置于工程根目录，承载「初始化 → 运行 → 退出」主干全流程
- 其余文件均为主干某一环节的分支实现，由入口统一调用并回收结果
- **禁止**子模块反向驱动主流程（回调控制生命周期、全局状态跨模块流转）
- 工程根必须建 `internal/`：其内只建功能目录、不放散文件，且必须含 `log` 模块
- 工程根另置 `config/`（与 `main.go` 同级）存放模板配置
- 按功能分目录；单文件过大按功能边界拆分，不按行数机械切割
- 提交信息中文，格式 `类型(作用域): 简短描述`；`CHANGELOG.md` 只记用户能直接体验到的变化
