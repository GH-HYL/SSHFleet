## 范围

用户 2026-09-14 裁定（原 Q4，设计经确认后实施），落 spec **D44**：

- **私钥链**：`off` 态关闭整条链（清单第 5/6 列不看，D41）；`default` 态「清单第 5 列 > 配置 `account.key`」；`universal` 态由 `-k` 路径强制接管。口令与私钥同源（D42）
- **密码链**：清单第 4 列 > 配置 `account.password` > 输入记忆 / 交互；**该节点持有私钥时配置默认密码不参与**（清单显式写的密码仍保留，作为私钥之后的兜底）
- **修掉的状态泄漏**：原实现把「配置默认密码」排在「有无私钥」之前，导致混合清单里只要有一个节点需要默认密码，同批私钥节点也会被塞上默认密码
- **认证失败分类**：私钥与密码都尝试且都失败 → `ssh.Result` 新增 `AuthFailure` 字段，文案「密钥与密码均失败」；单一凭据失败或非认证类错误保持原文错误、不带分类
- 判定方式：`x/crypto/ssh` 客户端认证全失败只给字符串 `ssh: unable to authenticate, …`（`*ssh.ServerAuthError` 是服务端类型），故按该特征串判定，并额外要求「公钥确实挂进了认证列表」（私钥解析失败而回退密码时不算两种都试过）

## 验证

本地测试 SSH 服务端（x/crypto/ssh server 端）7 例 + 真机复核 3 例，全过：

| # | 场景 | 期望 | 结果 |
| --- | --- | --- | --- |
| 1 | 只错密码 | 原文错误、无分类 | ✅ |
| 2 | 只未授权私钥 | 原文错误、无分类 | ✅ |
| 3 | 未授权私钥 + 错密码 | 分类「密钥与密码均失败」+ 保留原文错误 | ✅ |
| 4 | 未授权私钥 + 正确密码 | 私钥被拒后回退密码成功、无分类 | ✅ |
| 5 | 只正确密码 | 成功 | ✅ |
| 6 | 只已授权私钥 | 成功（只配私钥就只用私钥） | ✅ |
| 7 | 已授权私钥 + 错密码 | 成功且无分类（密码未参与） | ✅ |
| 真机 1-3 | 错密码 / 两者都失败 / 回退密码 | 同上口径 | ✅ |
