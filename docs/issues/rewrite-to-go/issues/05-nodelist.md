## 一、已查明的事实

### 1.1 读取与清洗

| 步骤 | 旧行为 |
| --- | --- |
| 两种来源 | 内联文本与文件走**同一套**清洗逻辑 |
| 跳过空行 | 是 |
| 跳过注释行 | 首列以 `#` 开头且非空 → 整行跳过 |
| 全空判定 | 无任何有效行 → 报错"CSV 中未解析出任何有效节点"后退出 |
| 表头识别 | 第一行第 1 列**不是合法 IPv4** → 当作表头删掉，打印 INFO"第一行不是IP格式，已移除表头行" |
| 删表头后再判空 | 同上，仍无有效行则报错退出 |
| 列数不足 | 每行不足 6 列 → 自动补空字符串 |

### 1.2 字段补全优先级（**三套规则，各不相同**）

| 字段 | 优先级 |
| --- | --- |
| 端口 | 清单列 > 配置默认 > 输入记忆 > 交互输入 |
| 用户名 | 清单列 > 配置默认 > 输入记忆 > 交互输入 |
| **密码** | 清单列 > 配置默认 > **有密钥则置空（跳过）** > 输入记忆 > 交互输入 |

> 密码那条多出来的一档"有密钥则跳过"是刻意的：配了密钥就不该再逼用户输密码。

### 1.3 输入记忆（`FieldMemory`）

- 端口 / 用户名 / 密码**各持一组**独立记忆（`use_input` + `input_value`）
- 触发条件：本次是**交互输入**得来的值，**且**当前行不是最后一行（`idx < total_nodes`）→ 询问"是否将此 X 应用于所有后续 X 为空的节点？"
- 用户答 y → 记入记忆，后续同字段为空的节点直接取用，不再询问
- 该询问走 `get_user_confirmation(yorn=True, disinteractive=...)` —— 即**非交互模式下会自动答 y**

### 1.4 凭据预检查（`validate_csv_credentials`）

在逐节点解析**之前**，把全部节点的凭据文件一次性体检：

- 密码文件：可解码**且非空**
- 私钥文件：`-----BEGIN` 前缀
- 私钥口令文件：可解码（**不判空**）
- 依赖默认密码的行：校验配置里的默认密码文件
- 有节点用密钥且配了全局口令：校验全局口令文件
- **所有错误一次性列出**（带行号 + IP + 具体原因），然后统一退出

密钥三态对预检查范围的影响：

| 状态 | 范围 |
| --- | --- |
| `off`（未指定 `-k`） | 跳过**所有**密钥相关检查 |
| `default`（`-k` 无路径） | 逐节点检查清单第 5 列 / 配置 `account.key` 及第 6 列口令 |
| `universal`（`-k` 带路径） | 只检查 `-k` 指定的私钥一次，**忽略**节点自带密钥与口令 |

### 1.5 密钥三态在解析期的表现

| 状态 | 密钥来源 | 口令来源 |
| --- | --- | --- |
| `off` | 强制空 | 第 6 列 > 配置 `account.key_passphrase` |
| `default` | 清单第 5 列 > 配置 `account.key`（值为字符串 `"None"` 视为未配置） | 第 6 列 > 配置 |
| `universal` | `-k` 路径（`~` 展开、走**终端工作目录**，不走 `secret_dir`） | **交互询问**，直接回车 = 无口令 |

- 全局口令（配置 `account.key_passphrase`）**只读盘一次**，所有节点共用
- 状态 3 + `--disinteractive` → **直接报错**（因为需要交互输入口令）

## 二、问题

### ❓ N1 — 表头识别的新规则（D13 的落地细化）

D13 已定"域名必须明确报错、不得静默丢弃"，但旧规则是"第 1 行第 1 列不是 IPv4 就当表头"——**域名恰好会落进这个判定里被吞掉**。

- (a) 改为"首列解析失败 **且** 该行含逗号 → 判为表头；否则报错'第 1 行不是合法 IPv4'"
- (b) 取消自动识别表头，要求清单第一行必须是节点（表头需用户自行注释掉）
- (c) 保留自动识别，但对被删掉的那一行**打印原始内容**并警告，便于用户发现

➡️ 推荐 **(a)**。旧规则的意图是"容忍带表头的清单"，而表头行必然多列（`IP,端口,用户...`），"含逗号"能把它与"孤零零一个域名"区分开；孤零零一个非 IP 值就该报错。

### ❓ N2 — 注释行只判首列

旧规则是 `row[0].startswith("#")`——**只判第一列**。所以 `192.168.1.10,22,root,#注释` 不会被当注释（正确），但 `# 这是一行说明` 会被跳过（正确）。

➡️ 推荐**保留**。这是"整行注释"的常见语义，且与 CSV 解析天然契合。

### ❓ N3 — 密码补全里"有密钥则跳过"那一档

➡️ 推荐**保留**。它让"配了密钥的节点不必再输密码"，是你在实际使用中长出来的细节。

### ❓ N4 — 输入记忆的语义

有一点需要你确认：现存记忆的启用**只在"交互输入"这条路径上触发**——如果某行的值来自清单或配置，不会触发"是否应用于后续"的询问，也不会写入记忆。

➡️ 推荐**保留**这个边界。若扩大到"清单首行也触发询问"，会把"每台机器不同参数"的场景变啰嗦。

### ❓ N5 — 凭据预检查"一次性列全部错误"

➡️ 推荐**保留**。批量场景下"一次把 12 个错都告诉你"远好于"改一个跑一次"。

### ❓ N6 — 密钥三态的术语

`off` / `default` / `universal` 这套命名是旧词表的资产，但只在代码和 README 里出现，CLI 上并没有这三个词（用户看到的是"不带 `-k` / 只带 `-k` / 带路径"）。

- (a) 术语保留，进入新 `CONTEXT.md`
- (b) 改名（如 `disabled` / `per-node` / `global`）更自解释

➡️ 推荐 **(a) 保留**。它已经写进 `CONTEXT.md` 词表，且概念本身准确；(b) 的收益只是"字面更直白"，不值一次术语迁移。

### ❓ N7 — `-k` 的路径基准不统一（遗留问题）

旧版：`-k` 路径相对**终端工作目录**（`os.path.expanduser`），而其他三个路径参数（`-s/-f/-u/-p/-d`）走 `args_normalize_path`，且**不允许含空格**。两套规则并存。

➡️ 推荐**保留现状**（`-k` 走原样展开，不吃空格限制），但在文档里写明"两套路径规则并存"。**若你要求统一，属于改变行为**，请明示。

### ❓ N8 — 状态 3 口令交互与非交互的冲突

旧版：`-k 路径` 时需要交互输入口令，因此 `--disinteractive` 下直接报错并提示"去掉 --disinteractive 或改用状态 2"。

➡️ 推荐**保留**。报错文案已经把两条出路都给了，比"静默用空口令"安全得多。
