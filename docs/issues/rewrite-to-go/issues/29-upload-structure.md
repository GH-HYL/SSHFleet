## 一、上传目录保留相对层级（spec D49）

### 事实核查（纠正 M3 过面时的判断）

M3 过面时我判断旧实现"平铺上传、不保留子目录结构"并当作旧行为保留。这次的证据链显示：**旧实现在早期确实是按"保留层级"设计的**，只是从未接通——

| 证据 | 内容 |
| --- | --- |
| `6d3cb87`（新增文件上传功能） | `localfs/collector.go` 里 `FileItem` 带 `RelPath` 字段，`newFileItem` 用 `filepath.Rel(basePath, fullPath)` + `filepath.ToSlash` 算出来 |
| `git grep RelPath <每一版>` | **只命中 collector 自身**（定义 + 赋值），上传侧从未消费 → 实际行为一直是全平铺 |
| `c544a68`（清理第一批死代码） | 提交信息明写「删 collector.go 的 FileItem.RelPath 字段及相对路径计算」——把它当死代码删了 |

用户描述的目标语义与当年那个 `RelPath` 公式完全吻合（相对上传根、不含根自身那一层）。故本次是**把这个设计接通**，不是新增行为。

### 改动

| 位置 | 改动 |
| --- | --- |
| `ssh/types.go` | `LocalFile.Name` → `Rel`（相对上传根的 POSIX 路径；单文件即文件名），一个字段一个含义 |
| `batch/collect.go` | 目录递归时算 `filepath.Rel(root, p)` + `ToSlash`；单文件取基名 |
| `ssh/sftp.go` | 远端路径改为 `path.Join(remotePath, f.Rel)`（POSIX 拼接，不用 `filepath`，避免 Windows 上出现反斜杠）；非 sudo 路径在上传前 `sftpClient.MkdirAll(path.Dir(...))`；sudo 路径先 `sudo mkdir -p` 建中间目录，临时文件名取 `path.Base(rel)`，再 `sudo mv` 到**完整最终路径**（此前是 `mv` 到目录、靠临时文件名落到位置）|
| `ssh/sftp.go` | 顺手把内联的单引号转义提取为 `escapeShellArg`（sudo 侧新增两处使用）|

**`-p` 与通配符的结论（用户 2026-09-14 裁定）**：`-p` 保留、界面不动；**不引入通配符**——在"目录内容进 `-p`、内部层级保留"的语义下，用户永远不需要 `*`（写目录本身就够），这条也让 cp 那套"尾斜杠改语义 / `/.` 表内容"的歧义完全没有存在空间。

### 验证（真机 172.28.118.49）

本地造 `modules/{file1.txt, second file.txt, dir1/sub1.txt, dir1/deep/deep.txt}` 上传到 `/tmp/sshfleet_uptest/`：

| 用例 | 结果 |
| --- | --- |
| 非 sudo 路径 | 远端得到 `file1.txt` / `second file.txt` / `dir1/sub1.txt` / `dir1/deep/deep.txt`——**层级完整、中间目录自动创建、空格文件名正常**，且无多余的 `modules` 那一层 |
| sudo 路径（`-m sudo`） | 与上完全一致（`sudo mkdir -p` + `mv` 到完整路径） |
| 清理 | 远端测试目录与文件已删 |

## 二、多余参数校验（spec D50）

### 为什么必须补

实测（临时解析测试：`-u /x/abc/f1 /x/abc/f2 /x/abc/sub -p /tmp/` 等四例）——除"完全没给 `-p`"能被既有的组合检查挡住外，**多出来的参数一律静默忽略**。最危险的组合：bash 把 `-u /x/abc/*` 展开成多个路径时，`-u` 只吃第一个，其余悄悄丢失，而结果显示"成功"。含空格路径未加引号、参数打错同理。对 `-d` 也成立（其远端路径在实现里被单引号包裹传给 `find`，远端 shell 不展开通配符，写 `*` 既不报错也不生效）。

### 改动

`cli/args.go`：解析完成后检查 `fs.Args()`，非空即报错，并把**未被使用的参数原样列出**；文案给出三类常见原因（通配符被终端展开 / 路径含空格未加引号 / 参数打错），并说明"上传目录不需要通配符，直接写目录本身即可"。

### 验证（真机 + 退出码）

| 用例 | 结果 |
| --- | --- |
| `-u <本地>/modules/* -p /tmp/x/`（bash 展开） | 报错并列出两个未被使用的参数，退出码 1 |
| `-u <...>/modules/second file.txt -p /tmp/x/`（空格未加引号） | 报错并列出 `file.txt`，退出码 1 |
| 正常单路径上传 | 不受影响，成功 |
