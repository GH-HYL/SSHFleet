### 1.3 路径规范化（`args_normalize_path`，作用于 `-s/-f/-u/-p/-d`）

- 反斜杠统一转 `/`
- Windows 盘符转 `C:/` 形式，且**不处理结尾 `/`**
- 其余走 `normpath` 处理 `.` / `..`，但**还原用户输入结尾的 `/`**
- 另有一条前置限制：**路径参数中间不能含空格** → `路径参数中间不能包含空格`

### 1.4 脚本文件的内容校验（`check_script_file`）

- 含 `\x00` → 判为二进制，报错
- 带 UTF-8 BOM → 读取时剥除（不算错）
- 非 UTF-8 → 报错
- **含 `\r\n` → 就地改写为 `\n`，并打印 warning** ← 见 C3

### 1.5 退出码

| 情形 | 退出码 |
| --- | --- |
| 正常完成 | `0` |
| 任何校验/加载失败 | `1` |
| `KeyboardInterrupt` | 由 Python 默认处理（打印提示后退出） |
| 未给任何参数 → 打印 help | `0` |

## 二、问题

### ❓ C1 — 选项总表是否逐项照旧

➡️ 推荐：**全数照旧**（含 `-f`、`-p` 方向反转、`--nobash`、`--disinteractive`、`-k` 三态）。
依据 D24：保持平级选项、不引子命令，正是为了不动使用习惯。

### ❓ C2 — 上传模式 `-p` 必须以 `/` 结尾：注释与实现不符

规则 3 的**注释**说"`-u` 是目录的情况下"，但**实现无条件**要求 `-p` 以 `/` 结尾——传单个文件时也得写 `/opt/`（合法，但语义上有点怪）。
另外规则 7 对下载的 `-p` 要求"已存在目录"，两边口径不一致。

- (a) 保持无条件要求 `/` 结尾（行为不变）
- (b) 按注释本意改为"仅 `-u` 是目录时要求 `/` 结尾"
- (c) 两边统一为"必须已存在目录"（跟下载一致）

➡️ 推荐 **(a)**：这是你天天在用的行为，改成 (b)/(c) 都会让某些既有命令突然报错。属于"优化会改变功能"，按 D20 必须由你裁定。

### ❓ C3 — 脚本换行符被**就地改写**

`check_script_file` 发现脚本含 CRLF 时会**直接覆盖写回 LF**。这是工具在改用户磁盘上的文件，且发生在"校验"阶段——名字叫 check，实际有写副作用。

- (a) 保留（自动修正，省事）
- (b) 改为只警告，不改文件
- (c) 改为在上传时于内存中转换（发到远端的是 LF，本地不动）

➡️ 推荐 **(c)**：既保证远端能正常执行，又不动用户文件。但这改变了可见行为（本地文件换行符不再被改）——**需你裁定**。

### ❓ C4 — `-c` 禁止以 `for/while/until/if/case` 开头

旧版直接拒绝，引导去用脚本模式。这是你的取舍（命令模式不套复杂控制流）。

- (a) 保留
- (b) 放开（新实现有能力处理）

➡️ 推荐 **(a)**：保留限制能让"命令模式"和"脚本模式"的边界清晰，放开只会让两种模式职责重叠。但这属于"要不要删功能"，也交你定。

### ❓ C5 — `--help` 的形态

旧版是**手工三列对齐**（`pad_to_width` + 全角宽度计算），为的是中文标签不被挤乱。新版 pflag 自带的 usage 不做宽度对齐。

- (a) 自写 usage 模板，保留三列对齐与全角处理
- (b) 用 pflag 默认输出（英文风格、不做对齐）

➡️ 推荐 **(a)**：你关心的就是这个——帮助信息是用户第一眼看到的东西。全角宽度计算函数本来就该进 `internal/common`（见 01-structure 的 S1）。

### ❓ C6 — 退出码约定

- (a) 沿用：`0` 成功 / `1` 失败，不细分
- (b) 细分（如 `2` 参数错误、`3` 配置错误…）

➡️ 推荐 **(a)**：脚本调用方多半只判 0/非 0；细分反而增加维护面且旧调用方感知不到差别。

### ❓ C7 — `-r` 备注的自动生成规则

旧规则：`-c` 取第一个字段截前 8 字符，把 `/ : * ? " < > | \` 替换成 `_`；`-s/-u/-d` 取 `basename`。

- (a) 照旧
- (b) 简化（如统一取 basename 或时间戳）

➡️ 推荐 **(a)** 照旧——历史目录名是你在用的检索手段，规则一改，老目录新目录风格就不一致了。
