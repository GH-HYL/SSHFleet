# 内联清单里的反斜杠路径被误当换行 · 规格

Status: needs-triage

> **来历**：2026-10-19 核对 `internal/nodelist` 两个一直红的测试时查出，不在当轮的缺陷清点范围内，单独立项。

---

## 问题陈述

用 `-f` 直接把清单写在命令行里（内联清单）时，值里的**字面 `\n`** 会被当成换行切开。

Windows 路径天然满是反斜杠，于是路径一旦含 `\n`（`D:\new\...`、`D:\notes\...`、`D:\node_modules\...`），就被从那里切断，后半截掉到下一行、被当成一个新的节点。

## 现象

```text
$ ./SSHFleet.exe -f '10.0.0.1,22,root,D:\new\pw.bin' -c "uptime"
[ERROR] [function:nodelist] 发现以下错误:
行 2 (IP: ew\pw.bin): - IP格式不正确
```

用户写的是一个节点、一个密码文件路径，工具看到的是两个节点。

## 根因

内联清单先把整串文本里的字面 `\n` 全部换成真换行（`internal/common/csvtext.go` 的 `ExpandEscapedNewlines`：`strings.ReplaceAll(text, "\\n", "\n")`），再做 CSV 解析。替换是无差别的——**它分不清「用户想换行」和「这是路径的一部分」**。

只影响**内联**：用文件方式给清单（`-f nodes.csv`）时内容原样读入，不经过这一步。

## 影响

- **Windows 用户写内联清单时，只要路径含 `\n` 就会被切断**，报的是「IP 格式不正确」——错得看不出跟路径有关
- 同一段文本里如果既有真换行意图、又有含 `\n` 的路径，两者没法同时表达
- 顺带：`internal/nodelist` 有两个测试因此长期是红的（`TestReadRowPassphraseNeverValidated`、`TestReadPrecheckErrorsAggregated`）——测试的临时目录路径里恰好含 `\n`。**它们红不是测试写错了，是这个缺陷在测试环境里显形。**

## 方案

未定。待选方向：

1. **收紧替换规则**：只把特定形态当换行（比如独占的 `\n`、或前后是分隔符的 `\n`）
2. **取消内联换行**：内联清单只允许单行，多行一律要求文件
3. **改分隔表达**：内联多行改用别的记号（如 `;;`），不再借 `\n`

选定前**不改代码**。

2. 作为偶尔用内联清单的人，我想知道「内联」到底支持哪些写法，而不是撞一次错才知道。
