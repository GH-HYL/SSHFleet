# 内联清单里的反斜杠路径被误当换行 · 规格

Status: done

> **来历**：2026-10-19 核对 `internal/nodelist` 两个一直红的测试时查出，不在当轮的缺陷清点范围内，单独立项。

---

## 问题陈述

用 `-f` 直接把清单写在命令行里（内联清单）时，值里的**字面 `\n`** 会被当成换行切开。

Windows 路径天然满是反斜杠，于是路径一旦含 `\n`（`D:\new\...`、`D:\notes\...`、`D:\node_modules\...`），就被从那里切断，后半截掉到下一行、被当成一个新的节点。

## 现象

```text
$ ./SSHFleet.exe -f '10.0.0.1,22,root,D:\new\pw.bin' -c "uptime"
[ERROR] [function:nodelist] 发现以下错误:
 行 2 (IP: ew\pw.bin): - IP格式不正确
```

用户写的是一个节点、一个密码文件路径，工具看到的是两个节点。

**同样的替换也打在 `-a`（代填）上**，而代填侧的后果更彻底：

```text
$ SSHFleet -f nodes.csv -s install.sh -a 'a\nb,请选择架构'
```

代填内容里想表达「a 换行 b」的一行，被切成两行；第 2 行没有触发词，报错。**内联代填里根本无法表达含换行的内容。**

## 根因

内联清单先把整串文本里的字面 `\n` 全部换成真换行（`internal/common/csvtext.go` 的 `ExpandEscapedNewlines`：`strings.ReplaceAll(text, "\\n", "\n")`），再做 CSV 解析。替换是无差别的——**它分不清「用户想换行」和「这是路径的一部分」**。

`-f` 与 `-a` 共用这一个函数（`nodelist/csvread.go` 的 `csvText`、`cli/answer.go` 的 `answerText`），所以两侧同时受影响。

只影响**内联**：用文件方式给清单或代填（`-f nodes.csv`、`-a answer.csv`）时内容原样读入，不经过这一步。

## 影响

- **Windows 用户写内联清单时，只要路径含 `\n` 就会被切断**，报的是「IP 格式不正确」——错得看不出跟路径有关
- **内联代填无法表达含换行的内容**：`\n` 被行分隔占用，代填内容里要打两行再回车，这条路不存在
- 同一段文本里既想写多行、又想写含 `\n` 的路径，两者没法同时表达
- 顺带：`internal/nodelist` 有两个测试因此长期是红的（`TestReadRowPassphraseNeverValidated`、`TestReadPrecheckErrorsAggregated`）——测试的临时目录路径里恰好含换行字符。**它们红不是测试写错了，是这个缺陷在测试环境里显形。** 复现方式（2026-10-19 实跑，目录名必须是含真换行的字符，不是字面 `n`）：

  ```bash
  TMPDIR=$'/tmp/a\nb' go test -count=1 -run 'TestReadRowPassphraseNeverValidated|TestReadPrecheckErrorsAggregated' ./internal/nodelist/
  ```

  报错里可见 `行 2 (IP: b/TestReadPrecheckErrorsAggregated…/not-exist.bin): 用了 -k，但没有找到可用的私钥`——临时目录被从 `\n` 处切成两行。

## 方案

方向已定，全文见 ADR-0020（`docs/adr/0020-inline-value-uses-semicolon-pair-as-line-separator.md`）。要点：

1. **行分隔改为 `;;`**：内联值里两个连续分号表示一条记录的结束；`-f` 与 `-a` **共用这一个记号**，取值口径继续「与文件内容完全一致，内联不是另一套格式」。
2. **字面 `\n` 回到普通字符**：不做替换、不再有转义语义；路径里的 `\n` 原样保留。
3. **`-a` 一并修**：原「不在本次范围」里标为待核实的代填侧，纳入本议题。
4. **不给 `-a` 开单独规则**：内联里只有一个记号 `;;`，没有第二种转义、没有「只对第 1 列生效」的写法。代填内容里要含真换行（打两行再回车），走 `-a answer.csv` 文件；内联代填一行一条。
5. **不考虑兼容**：使用者可见面按「`\n` 从来不是分隔符」书写，手册／帮助／报错／CHANGELOG 不写沿革、不设旧的写法迁移提示；沿革只留在 ADR 与代码注释里。

## 使用者故事

1. 作为 Windows 上的运维人员，我想在内联清单里写 `D:\new\pw.bin` 这样正常的路径，而不是被切成两行。
2. 作为写内联清单的人，我想知道「内联」到底支持哪些写法，而不是撞一次错才知道。
3. 作为要代填多行内容的人，我想知道这种内容该写成文件，而不是在内联里到处找转义记号。
4. 作为接手这个仓库的人，我不想看到两个长期红的测试没人管。

## 测试决策

`internal/nodelist` 那两个红测试是现成的回归网：修好之后它们应当自然变绿（用上面那条 `TMPDIR` 命令验证，不能只看默认临时目录下的绿）。

另外要补的回归：
- `-f` 内联里含 `D:\new\pw.bin` 这类路径的第 4–6 列，不被切开
- `-f` 内联 `;;` 分行照常解析多台
- 内联里的字面 `\n` 按普通字符原样保留
- `-a` 内联用 `;;` 分行照常解析
- `-a` 的 `.csv` 文件里带真换行的代填内容照常解析（回归既有能力，确认没被内联侧改动波及）

## 不在本次范围

- 文件方式清单／代填的一切行为（不受影响）
- `;;` 与真实内容（密码、触发词里真写了 `;;`）的冲突：不另设转义，靠「这类内容走文件」兜住
