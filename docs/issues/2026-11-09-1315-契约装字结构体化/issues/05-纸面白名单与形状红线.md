- 2026-11-10：落地口径（开发者 2026-11-10「行都按你的建议走，授权开工」）：白名单登记现有全部裸 `string` 格子，一格一行、每行标类别；名单写在检查器里（`internal/guard/paper.go` 的 `paperFields`），不进 `internal/guard/exceptions.md` 那张四格台账——台账粒度是「规则 ＋ 路径」，放行一格等于放行那个文件里的这一类全部，挡不住「再塞一句」。
- 形状：`PaperField{Type, Field, Kind}`，`Kind` 四取一——事实／配置原文／类别常量／报文原文。判据 `bareString` 只认 `string`、`[]string`、`*string`、`map[string]string`；具名类型（`Mode`、`CannotStartKind`、`ProblemSubject`…）不算，ADR-0044 要走的就是把自由串收成具名类型，判据得认得出这一步，否则收完了还红。
- 两个方向都报：契约里多一格名单外的裸 `string`，报「契约里 X 是一格裸 string，白名单上没有它」；名单里多一行契约里已经没有的，报「白名单里的 X 在契约里已经没有了」。只判前一个方向，名单会越攒越松——与放行台账「没人用还在」同一条理由。
- 并进类四 `CheckContract`，不新开类（加一类要开发者点头，ADR-0037 影响段）。判据只看形状与名单，不看字面量内容、不数字节；「名字像句子」在语法树上判不出来——判名字就得看长度或字面量，而那是这张单自己禁掉的。所以判据落成「裸 `string` 而名单上没有即红」：名字骗得过去，登记时选的那个类别骗不过审计。
