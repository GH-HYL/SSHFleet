## 0 一句话结论

**Go 版从不主动打开控制台的 VT（虚拟终端）处理，却无条件输出 ANSI 转义序列；而旧的 Python 版会主动打开。**
宿主 conhost 若 VT 处于关闭态（Win10 1909 出厂默认就是关的），转义序列就被当普通文字逐字节画上屏 —— 这就是客户机上的"残骸"。

**Python 版为什么正常，已定案到具体某一行**：`colorama/winterm.py:185` 的 `SetConsoleMode(..., ENABLE_VIRTUAL_TERMINAL_PROCESSING)`，
由 `loguru` 在 **import 阶段**替它调用（见第 4 节）。

**已在本机复现，不需要客户机、不需要连任何远端节点。**

## 1 证据链（全部为本机实测，可逐条复核）

### 1.1 本机 console 的 VT 默认是关的

```text
CONOUT$    mode=0x0003   VT-OUT=false  VT-IN=false
```

`0x0003` = `ENABLE_PROCESSED_OUTPUT | ENABLE_WRAP_AT_EOL_OUTPUT`，**不含 `ENABLE_VIRTUAL_TERMINAL_PROCESSING（0x4）`**。与客户机 1909 的状态同型。

### 1.2 Go 版自己从不主动开 VT

全仓 grep `GetConsoleMode` / `SetConsoleMode` / `ENABLE_VIRTUAL_TERMINAL`：

```text
项目代码（modules/SSHFleet_Go 下 .go，排除测试）  →  零命中
```

全仓唯一会开 VT 的代码在依赖里：

```text
github.com/charmbracelet/bubbletea@v1.3.10/tty_windows.go:49
  SetConsoleMode(stdout, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING)
```

而它**只在 `Program.Run()` 里被调**（`tea.go:650` → `initTerminal()` → `initInput()`），`Run()` 在整个项目里只有一处入口：

```text
internal/output/reporter.go:156  ensureProgram()   ← 懒创建，要等第一个进度事件
internal/output/reporter.go:171  go p.Run()
```

对照主干步骤：

```text
main.go 步骤 7   confirm.Confirm()      ← 参数屏在这里，转义序列在这里外泄
main.go 步骤 8   batch.Run() → reporter.Progress() → ensureProgram() → bubbletea 开 VT
```

**参数屏比第一次开 VT 早了整整一个步骤。** 程序走到参数屏时，进程内没有任何人调过 `SetConsoleMode`。

### 1.3 参数屏无条件输出转义序列

沙盒里真跑 `SSHFleet.exe`（`-c "echo hi" -f nodes.csv`，`stdout` 重定向抓字节）：

```text
总字节 1187    ESC(0x1B) 出现 48 次
```

参数屏每个字段的形态：

```text
\x1b[96m▶ 执行身份-→\x1b[0m   \x1b[38;5;214mroot\x1b[0m
```

与客户机截图逐字对上：

```text
我抓到的字节    \x1b[96m▶ 执行身份-→\x1b[0m   \x1b[38;5;214mroot\x1b[0m
客户机截图      【96m▶ 权限类型  -→【0m   【38;5;214msudo【0m
```

**不查 VT、不查 isatty，一律照发。**

### 1.4 VT 关 → 残骸（拿真程序的输出做的对照）

取 `SSHFleet.exe` 的真实输出行 `"\x1b[96m▶ 节点数量-→\x1b[0m   \x1b[38;5;214m1\x1b[0m"`（48 字节），在两种 VT 状态下写进 console 并**读回屏幕缓冲区**：

| 状态 | 光标前进 | 缓冲区内容 | 现象 |
|---|---|---|---|
| VT 关（客户机状态） | **40 格** | 整段字节原样落地，ESC 全在 | **残骸** |
| VT 开 | **16 格** | 只剩 `▶ 节点数量-→   1` | **正常上色** |

40 格 = 每个字节各占一格；16 格 = 只剩可见文字。同一段字节，差别只在 VT 开关。

### 1.5 裸 python 在 VT 关的 console 上同样外泄

以 `CONOUT$` 为 stdout 跑 `python -c "print('\033[96m亮青色测试\033[0m')"`，VT 强制关闭：

```text
读回  "\x1b[96m亮青色测试\x1b[0m"   仍含 ESC → 外泄
```

即**交接文档附件 03 上半已在本机复现**。

## 3 顺带纠正一处：Python 版里 rich 确实早于参数屏

交接第 3 节第 4 条记「开发者指出参数屏早于 rich 控制台创建」。**这个时间关系反了**：

```text
sshfleet.py                 from src.output.terminal import ...   ← main() 之前
src/output/terminal.py:29   console = Console()                   ← 模块级，import 时即执行
src/input/confirm.py        _print_info_table（裸 print + 裸 ANSI）← 参数屏，晚于上面
```

rich 的 Console 在**模块被 import 那一刻**就创建了，早于参数屏。

**但这一条不改变结论**：rich 不开 VT（见第 2 节第 4 条）。此处只是把时间关系记正，免得下一轮按错的顺序去找。

## 4 客户机 Python 版为什么正常 —— 已定案

**结论：Python 版在 import 阶段经 `loguru → colorama` 主动打开了 console 的 VT。Go 版不做这件事。**

> 判断反转记录：本节初版曾判「不是进程差异，是那个窗口的 console 本来就开着」。
> 拿到真实打包版实测后**推翻** —— 确实就是进程差异，且已定位到具体某一行。
> 初版误判的原因：只对照了「现打的 PyInstaller 包」与「裸 python」，而**现打的包不含 loguru**。

### 4.1 完整调用链（全部在 import 阶段完成，早于 `main()`）

```text
sshfleet.py                                 ← import 阶段，main() 还没跑
  └─ src/log/logger.py:10      from loguru import logger
       └─ loguru 导入时建立默认 sink
            └─ loguru/_logger.py:813       _colorama.should_wrap(sink)
                 └─ loguru/_colorama.py:59     enable_vt_processing(stream.fileno())
                      └─ colorama/winterm.py:185   SetConsoleMode(handle, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING)
```

参数屏在 `main()` 的**步骤 7** —— 走到那里时 VT 早已被打开，所以裸 `print` + 裸 ANSI 也能正常上色。

### 4.2 逐模块实测（探针先把 VT 关掉，再启动，读跑完之后的 mode）

| 跑的东西 | 跑之前 VT | 跑之后 VT | 开了 VT 吗 |
|---|---|---|---|
| 裸 `python.exe` | false | false | 否 |
| `python -c "import rich"` | false | false | 否 |
| `python -c "from rich.console import Console"` | false | false | 否 |
| `python -c "from rich.console import Console; c = Console()"` | false | false | 否 |
| `python -c "import colorama; colorama.init()"` | false | **true** | **是** |
| `python -c "from loguru import logger"` | false | **true** | **是** |
| 现打的 PyInstaller 包（纯 `print`） | false | false | 否 |
| 现打的 PyInstaller 包（带 rich，未用 loguru） | false | false | 否 |
| Go 版 `SSHFleet.exe` | false | false | 否 |

**「import 一下就开」是 loguru 与 colorama 的特征** —— 注意 loguru 那行只是 import，连 `logger.info()` 都没调。

### 4.3 真实打包版实测（客户机上的就是这一版）

包：`Old-Code_Bak/SSHFleet/release/SSHFleet_Py打包版_2026-09-10_13-36-56`
（**整个复制到沙盒再跑**，只读旧工程本身未动）

```text
无参数（打印帮助）：
   跑之前  mode=0x0003  VT-OUT=false
   跑之后  mode=0x0007  VT-OUT=true      ← 0x0003 | 0x0004
   【判定】是它把 VT 打开的

带参数 -c "echo hi" -f nodes.csv（复现客户机窗口 B 那条错误路径）：
   跑之前  mode=0x0003  VT-OUT=false
   跑之后  mode=0x0007  VT-OUT=true
   读回第 0 行  "[ERROR] CSV凭据预检查失败，共 1 处错误："
   读回第 1 行  "  默认密码文件不是有效的加密格式或主密钥不匹配（…） → C:\Users\Administrator/.MyPW\SS…"
   读回内容含 ESC = false                ← 转义序列被消费，渲染成了颜色

对照 Go 版同一条命令：
   跑之前  mode=0x0003  VT-OUT=false
   跑之后  mode=0x0003  VT-OUT=false
   读回第 0 行  "\x1b[31m[ERROR]\x1b[0m\x1b[33m [function:config]\x1b[0m 加载配置文件失败：…"
```

**同一台机器、同一套探针、同一个 console：Python 版把 VT 打开了，Go 版没有。**

读回的那条 `[ERROR] CSV凭据预检查失败…` 与客户机窗口 B 的 `[ERROR] CSV凭据预检查失败：` 是同一条路径。

### 4.4 于是附件 03 该怎么读

交接第 2.1 节读作「同一环境下两种进程表现不同」。**这个读法是对的**（初版本文档否定过它，现纠正）——原因不是 rich、也不是 PyInstaller，而是**两者 import 的模块不同**：

| 窗口 | 跑的东西 | 有没有走到 loguru | VT | 表现 |
|---|---|---|---|---|
| A | `python -c "print(...)"` | **否**（没 import 程序代码） | 关 | 外泄（`□96m…□0m`） |
| B | `.\SSHFleet.exe` 完整程序 | **是**（import 链里带 loguru） | 开 | 正常上色（`[ERROR]` 红） |

### 4.5 像素证据（与上面的判断一致）

| 区域 | 红系像素 | 说明 |
|---|---|---|
| 窗口 A（跑裸 python） | **13** | 全是 `(224,160,96)` 一类橙黄，来自窗口图标；**无文字红** |
| 窗口 B（跑 SSHFleet.exe） | **439** | `(224,0,0)`、`(192,0,0)` —— **纯正文字红** |
| 附件 01（Go 版乱码屏） | 36 | 全是橙黄，**无文字红** |

窗口 B 有 439 个纯红像素 —— 那里确实渲染出了红色文字。

### 4.6 排除清单（第 4 节的完整对照）

| 嫌疑 | 依据 | 结果 |
|---|---|---|
| rich 开 VT | rich 全包 grep `SetConsoleMode` | 零命中；只调 `GetConsoleMode` 探测。实测不开 |
| PyInstaller bootloader | `pyi_utils_win32.c` | 无任何 console mode 操作 |
| CPython 自身 | 探针实测 | mode 不变 |
| PS 转发破坏 ESC | PS 捕获后写文件读字节 | ESC 完整保留 |
| 两个窗口是不同终端程序 | 放大标题栏对比 | 都是 `PowerShell 7 (x64)` conhost |
| **loguru → colorama** | 全链实测 + 源码 | **就是它**（`colorama/winterm.py:185`） |

## 5 复现手段（红线 5 要求的那个「已跑过、能当场重现」的东西）

全部落在 `build/atest-8/`，不依赖网络、不依赖客户机、不改系统配置：

```bash
cd D:/Desktop/Code/SSHFleet/build/atest-8
./probe.exe     # 读 console 的 VT 状态
./probe3.exe    # VT 关/开 A/B：同一段字节，读回屏幕缓冲区对比
./probe4.exe    # 拿 SSHFleet.exe 的真实输出行做同样的 A/B
./probe6.exe    # 裸 python 在 VT 关时的外泄（附件 03 上半）
./probe7.exe <程序> [参数...]   # 关掉 VT → 跑目标程序 → 读 mode 变化 + 读回屏幕

# Go 版外泄
cd fleet && printf 'n\n' | ./SSHFleet.exe -c "echo hi" -f nodes.csv > raw.txt 2>&1
# raw.txt 里 ESC 出现 48 次

# Python 真实包自己开 VT（对照）
cd ../pypkg && ../probe7.exe ./SSHFleet.exe -c "echo hi" -f nodes.csv
# mode 0x0003 → 0x0007，读回不含 ESC
```

**判据**：`raw.txt` 里 ESC 计数 > 0，且 `probe4` 的 VT 关那一轮光标前进格数 ≠ VT 开那一轮 —— 即为复现。
