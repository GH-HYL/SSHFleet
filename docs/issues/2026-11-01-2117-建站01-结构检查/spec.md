# 规格：阶段 01——结构检查

**Status**：done

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

接下来每个阶段都要往十七个包里填代码，而填的人是新会话，手上没有上一轮的上下文。老工程两年下来的失效不是「写不出功能」，是**没有任何东西拦得住一段逻辑落在不该落的地方**：一个包内一切互相可见，人读不出「这句 print 该不该在这儿」（ADR-0032《背景》）。

新工程现在有边界、没有栅栏。第一个往 `parse` 里写 `fmt.Println` 的人，编译过、测试绿、看起来一切正常；而等他写完两百行，谁也不知道哪儿破的。

## Solution

六类越界检查跟着 `go test` 跑，撞上就红，红了交不了。每一类都在一个**小假模块**上练过：坏样本必红、好样本必不红——所以「这套检查到底有没有用」本身可验，不必信它。

红线区与检查同住 `guard`；名单与指纹同住一处，删一条、改个名都对不上；放行的口子只有 `guard/exceptions.md` 一份，每次跑测试报一行条数。

## User Stories

1. 作为维护者，有人在 `parse` 里写 `fmt.Println`，`go test` 立刻红，并且告诉他该调 `console`。
2. 作为维护者，某个站 import 另一个站、横切包 import 了站、契约包 import 任何工程内的包，`go test` 红。
3. 作为维护者，有人在塔尖之外调 `os.Exit`，红；有人在塔尖用 `os.Getenv` 之类没点名的符号，也红。
4. 作为维护者，有人往契约包里加一个函数或方法，红。
5. 作为维护者，有人在闸门里造「起不来」、或在闸门之外造「拒绝」，红。
6. 作为维护者，有人把一个红线测试钉两个包、或让某个站导出第三个名字，红。
7. 作为维护者，规则表与真实包清单对不上（多一个、少一个），红，并说出是哪一行。
8. 作为维护者，交接件比上一棒宽（除结论格外多一格），红。
9. 作为维护者，有人把某一类的检查删掉或放宽，`go test` 指着名单说不认识这条测试——要改它得先走议题加 ADR。
10. 作为维护者，翻到一份旧 ADR 写着 `internal/cli` 时，末尾的更新记录直接告诉我它现在住哪个包。

## Implementation Decisions

**六类，类号不动**（判据唯一出处 ADR-0032 第四、五条与 ADR-0037；本规格只定落点与形态）：

| 类 | 名 | 一句话判据 |
| --- | --- | --- |
| 一 | 写终端 | 除 `console` 与非 `_test.go` 文件外，出现 `fmt.Print` 族、内建 `println`、或引用 `os.Stdout`／`os.Stderr` 即报 |
| 二 | 依赖方向 | 生产文件按规则表；`_test.go` 豁免；红线测试按自己的白名单（走第六类）。另含包清单对账、塔尖三个包的点名符号、零第三方依赖 |
| 三 | 退出动作 | `os.Exit` 的调用点只许在塔尖 |
| 四 | 契约纯净 | 契约包里出现函数即报，带接收者的方法也算；类型、常量、包级变量不报 |
| 五 | 失败类型的构造点 | 「起不来」不许在闸门造；「拒绝」只许在闸门造 |
| 六 | 测试站位 | 两条判据：红线测试的 import 白名单＋每个站至多导出「一个函数加一个类型」；交接件是否比上一棒宽 |

**第六类是两条判据、一个类号**，不另立第七类（map.md 阶段表 01 那一行）。

**扫描根＝模块根。** 走目录的顺序与 `go list ./...` 同口径：跳过 `testdata`、以 `.` 或 `_` 开头的目录、`vendor`。老工程不扫——那是范围，不是豁免。

**判据按语法树数，不按字搜**（ADR-0037 决定二）：注释里写一句、字符串里带一段都不算。

**检查器的形态**（纯技术选型，按 map.md「框架条目」记一行）：`guard` 里一个 `Target`（模块根、模块名、规则表、两处失败类型、交接件对账表、放行台账），一个 `Load` 把源码读成「包 → 文件 → 语法树」，七个 `Check*` 各管一类，`Check` 按类号顺序跑全。真工程由 `guard` 自己的一条测试跑；样本模块由各 `Check*` 的单测跑。

**样本住 `guard/testdata/`**，一个假模块一个目录，只含最小可解析的 `.go`（不要求能编译——判据只看语法树）。真工程不动一根线。

**两个失败类型本阶段落地**（ADR-0034 决定三；map.md 框架条目已定「只放这两个类型」）：`contract.CannotStart`（起不来，谁都能造）与 `gate.Refusal`（拒绝，只许闸门造、类型本身可见）。本阶段只落类型本身，**格子随阶段 03／04**——第五类要的是「有可判对象」，不是把字段先占了。

**报错话术**（07 号答案第十条）：每条违规必须写清四样——类名、位置、哪里绕开了、该走哪一处；开头一句「这是结构约束，不是功能测试」。不说清，下一次看到红的第一反应是改测试。

**红线名单与指纹**（ADR-0037 决定五）住 `guard/redline.go`，只放数据：测试名、它钉的包、它直接引用到的生产符号。指纹按名字与符号集合钉，不钉字节。

**放行台账**住 `guard/exceptions.md`，一行一条四样（哪条红线、哪个位置、为什么放、谁批的）。每一行都是**让检查闭嘴**的动作，改它等同改约束类文件。

## Testing Decisions

- **接缝**：检查器自己就是被测对象，测它的口子是 `Check*(Target)`（递一个模块根、收一串违规）；真模块由 `Check` 整跑一次。不测 `Load` 内部、不 mock 文件系统。
- **每类两样本**：`testdata/` 里坏样本必产出一条指定类的违规（连同话术四样），好样本零违规。**「检查坏了」与「代码坏了」要分得开**——所以坏样本的断言写死类名与位置，不是只看 `len(violations) > 0`。
- **真模块常绿**：`Check` 对着 `modules/SSHFleet2_Go` 跑，零违规、十七个包。
- **环境类失败不进两区**，本阶段不涉及机器。

## Out of Scope

- **三张纸的格子**：随阶段 04；本阶段只落两个失败类型，交接件对账表**0 行**。
- **把行为钉住的测试**：红线区只管结构，一条行为断言都不加。
- **各站的实现**：本阶段一行业务代码都不写；`parse`／`gate`／`execute`／`settle`／`report` 仍只有包注释（`gate` 多一个拒绝类型）。
- **老工程**：一个字不动，也不扫。
- **41 处之外的任何 ADR 改写**：那 15 篇只在末尾追加更新记录，正文一字不改。
- **`/implement` 与本仓库约束类文件**：不动。

## Further Notes

- **塔尖的符号白名单会先在阶段 02 撞一次**：ADR-0032 第五条只点名 `os.Exit`、`signal.Notify`、`errors.As`（`errors.Is` 同理），而塔尖拿到 argv 要读 `os.Args`。撞上时按红线办——要走议题加 ADR，不在本阶段预先放宽。
- **红线区本阶段 0 条成员**：真正的红线测试（站在三种接缝上）随 03／04 的站一起长；本阶段立的是它的名单、指纹与 import 白名单，成员由样本模块练。
- **进场顺序**：先立检查，再搬代码。所以本阶段结束时新工程仍然「只有骨架＋两个类型」。

### 两处要说清的偏离

**一、「当前放行 N 条」进不了 `go test ./...` 的默认输出。** 实测（`build/` 下的探针）：不带 `-v` 时连 `TestMain` 打到 stdout 的行都被吞。所以那行走测试日志——`-v` 时可见、测试红时一定可见。要它进默认输出得另加一个命令，与「不另加命令」的既定口径冲突，本阶段不做。

**二、41 处是就地换掉，不是只追加更新记录。** 判读：这 41 处是**引用失效**，不是决策被取代——决定、理由、备选一字未动，只把指错的位置换成现在的位置，末尾留一行说明。这样「只剩一处」的验收成立，看决策怎么变的凭据也还在。
