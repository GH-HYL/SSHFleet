# 02: 类一写终端 ＋ 类三退出动作——两个「调用点该不该在这儿」

**要做的**：谁往终端写字、谁自己让进程退场，两样都在编译之前就被指出来。

- **类一**：除 `console` 包与非 `_test.go` 文件外，出现 `fmt.Print`／`Printf`／`Println`、内建 `println`、或引用 `os.Stdout`／`os.Stderr`，即报。`fmt.Fprintf` 写到内存缓冲不算，写到标准输出算（它必然引用 `os.Stdout`，所以不做特例）。
- **类三**：`os.Exit` 的调用点只许在塔尖；别处只许把结论往上交。

两样合在一单，是因为它们共用同一件事：**扫调用点，问一句「这个动作凭什么在这儿」**。写完这两条，ADR-0032 第四条那两条最常被绕的边界就有了栅栏。

**Blocked by**：01。

**Status**：ready-for-agent

## 判据出处

ADR-0032 第四条（写终端、退出动作）、第五条（退出只许塔尖）；ADR-0034 决定四（各站拿不到退出这个东西）。

## 验收

- [ ] 坏样本：`testdata/violations` 里有一个非 `console` 包写 `fmt.Println`、一个包引用 `os.Stdout`、一个包调 `os.Exit`，三条各自产出**指定类名**的违规，位置指到文件与行
- [ ] 好样本：`console` 包里同样的调用零违规；某个 `_test.go` 里写 `fmt.Println` 零违规；塔尖里调 `os.Exit` 零违规
- [ ] 报错话术里出现「该走 `console`」／「该把结论交给塔尖」，不是只说「不许」
- [ ] 真工程跑一遍零违规（`console` 还是空包，塔尖还是空 `main`）
- [ ] `go test ./...` 绿

## 不在这单

依赖方向（03）——`console` 能被谁调、塔尖能 import 谁，那一单管。
