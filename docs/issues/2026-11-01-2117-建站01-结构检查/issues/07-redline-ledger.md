# 07: 红线区：名单与指纹、放行台账、每次报一行条数

**要做的**：让「删掉一条检查」这件事从「没人发现」变成「当场红」。

- **名单与指纹**住 `guard/redline.go`，只放数据：测试名、它钉的包、它直接引用到的生产符号（集合，顺序无关）。指纹钉名字与符号集合，**不钉字节**——`gofmt`、改注释、经 helper 间接引用的都不算改。新增一条不算改；**删掉、改名、收窄引用面算改**。
- **范围**：`guard` 包里全部 `Test` 开头的函数。红线区与结构检查同住这一处，所以这一处每加一条测试都要留痕——删掉 `TestCheckTerminal` 正是「把闸门拆了」最省事的那个动作。
- **放行台账**住 `guard/exceptions.md`，一行一条四样：哪条红线、哪个位置、为什么放、谁批的。台账命中的违规不报，其余照报。**每次跑测试先报一行「当前放行 N 条」**。
- 台账与名单都是**能让检查闭嘴的东西**：改它们等同改约束类文件，要开发者单独点头，不走「授权开工」那道门。

**Blocked by**：02–06（名单要有东西可收；一条都没有的名单等于没写）。

**Status**：done

## 验收

- [x] 真工程跑一遍，测试输出里有「当前放行 0 条」与「红线 N 条」，N 与 `guard` 里 `Test` 函数个数一致
- [x] 坏样本：从名单里删一条、或把某条的符号集合改窄一个 → 红，并点名是哪条测试
- [x] 坏样本：名单里有一条代码里已经没有的测试 → 红
- [x] 好样本：名单与代码一致 → 零违规
- [x] 台账：样本模块上给一条违规开一行放行 → 那条不报、其余照报；行数报得对
- [x] 台账文件在一个空台账时也数得出 0 条，不是读不到就静默过
- [x] `go test ./...` 绿

## 不在这单

改名单与台账的审批程序（已在 ADR-0037 决定五与规范一.1 第七条，这里只是落点）。

## Comments

### 2026-11-01：交付

`redline.go` 装名单与指纹（现 21 条，覆盖 `guard` 里全部 Test 函数），`ledger.go` 读台账并做过筛，`exceptions.md` 空表（0 条）。真工程跑一遍报「当前放行 0 条；红线 21 条」。

**一处实测偏离**：「每次跑测试先打一行条数」进不了 `go test ./...` 的常规输出——不带 `-v` 时，连 `TestMain` 打到 stdout 的行都会被吞（在 `build/` 下的探针里跑过）。所以条数走测试日志：`go test -v ./internal/guard/` 能看见，测试红时也一定看得见。要让它在默认输出里出现，得另造一个命令，那与「不另加命令」的既定口径打架，故不做。

台账另有一条自律：**盖不住任何违规的那一行也报**。台账烂着的长相就是条目越攒越多、谁也不敢删。
