# 04: 类四契约纯净 ＋ 类五失败类型的构造点——两个失败类型在这里落地

**要做的**：先让两种失败有真身，再让「谁能造它」变成可判的。

**落地两个类型**（ADR-0034 决定三；只落类型本身，格子随 03／04 阶段）：

- `contract.CannotStart`——「起不来」。它不是一种权力，是任何一站都可能撞上的事实，所以谁都能造。**不许实现 `error` 接口**：那会在契约包里长一个 `Error()` 方法，与契约纯净打架；塔尖按类型认它。
- `gate.Refusal`——「拒绝」。类型本身可见（塔尖要认出来才能把话交出去），**构造只许在闸门内**。

**两条判据**：

- **类四**：契约包里出现函数就报，带接收者的方法也算；类型、常量、包级变量不报。
- **类五**：`CannotStart` 在闸门包里造即报；`Refusal` 在闸门之外造即报。造，指出现这个类型的复合字面量。另有一条：**约定的类型不见了也报**——第五类没有可判对象时不许静默放过。

两样合在一单，是因为第五类要判的正是「契约里有、闸门里不许有」这件事的两头；先有类型，才轮得到判据。

- [ ] 契约包里没有函数、没有方法、没有 import（`go doc` 与源码两处都核）
- [ ] 坏样本：契约包里加一个函数 → 类四报；带接收者的方法 → 也报
- [ ] 坏样本：闸门包里造 `CannotStart` → 类五报；闸门之外造 `Refusal` → 类五报
- [ ] 坏样本：把某个约定类型删掉 → 类五报「可判对象不见了」，不是静默零违规

- [ ] 真工程跑一遍零违规（闸门此刻只有类型、没有构造点）
- [ ] `go test ./...` 绿
