# 05: 类六之一 测试站位——红线测试钉几个包、每个站露几个名字

**要做的**：红线区的测试站错位置会红，站给外面多露一个名字也会红。两条判据都按文件讲。

- **import 白名单**：一个红线测试文件只许 import 标准库、契约包，以及被它钉的**那一个包**。import 第二个被测包、或 import 样本共用的假件包，即报。
- **出口白名单**：每个站包至多导出**一个函数加一个类型**（入口函数、替身插口的类型；闸门的 `gate.Refusal` 是同一类东西，一格已占）；多一个即报。

**怎么认出「红线测试文件」**（纯技术选型，记进 map.md 框架条目）：文件名以 `redline_` 开头且以 `_test.go` 结尾。检查本体自己的单测不叫这个名字——它测的是尺子，钉的不是结构。

**Blocked by**：01、03（依赖方向那一档要先把「哪类文件按哪一档判」立起来）。

**Status**：done

## 验收

- [x] 坏样本：一个 `redline_*_test.go` import 两个站包 → 报；import 站包加一个样本包 → 报
- [x] 坏样本：某个站导出两个函数 → 报；导出两个类型 → 报
- [x] 好样本：`redline_*_test.go` 只 import 标准库＋契约＋一个站包 → 零违规；站只导出零个或一个名字 → 零违规（骨架阶段 0 个也算过）
- [x] 真工程跑一遍：`gate` 只多一个 `Refusal`，其余站 0 个导出，零违规
- [x] 报错话术说清「红线测试只许钉一个包」与「站只许露入口与替身插口」，不是只说「违规」
