# 03: 类二依赖方向——规则表当尺子，包清单对不上也算这一类

**要做的**：谁 import 谁，按 `guard/rules.go` 那张表判；表与真实包清单对不上（多一个、少一个）并进这一类，不另立类号。

三档，判据不一样（map.md 框架条目「依赖检查怎么判」）：

- **生产文件**：按规则表那一行。站只许依赖契约与横切；横切只许依赖标准库与契约，例外两条 `ask` → `console`、`ask` → `message`；契约不许依赖任何工程内的包；密钥管理只许契约与横切；检查包只读源码，不 import 任何一站与契约；塔尖按它那一行的整张清单。
- **普通 `_test.go`**：豁免（ADR-0032 第四条）。这类文件不进生产程序，常要跨包取被测对象。
- **红线测试**：不享上面那条豁免，按它自己的 import 白名单判——那条在第五单（第六类）。

另含两条窄判据：

- **塔尖的点名符号**：`os`／`os/signal`／`errors` 只许 `os.Exit`、`signal.Notify`、`errors.As`（`errors.Is` 同理），不是「这三个包随便用」。
- **零第三方依赖**：除本模块与标准库之外任何 import 都报（`go.mod` 里一条 `require` 都没有）。

**Blocked by**：01。

**Status**：ready-for-agent

## 验收

- [ ] 坏样本：一个站 import 另一个站、一个横切包 import 站、契约包 import 别的包、一个包 import `example.com/x`、塔尖用 `os.Getenv`——五条各自产出**指定类名**的违规，位置指到文件与行
- [ ] 坏样本：假模块里多一个包（规则表里没有）、少一个包（表里有、目录没有），两条都报「依赖方向」这一类，并说出是哪个包
- [ ] 好样本：`ask` import `console` 与 `message` 零违规；`_test.go` 里 import 站零违规；塔尖 import 五站与横切零违规
- [ ] 真工程跑一遍：十七个包与表逐行对上，零违规；违规话术里能看出「该依赖谁」
- [ ] `go test ./...` 绿
