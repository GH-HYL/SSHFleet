# 使用者可见的文字去 AI 味：空话、行话与模板节奏逐处改掉

- **Status**：done
- **日期**：2026-11-25
- **关联**：ADR-0025 决定 6（三行套的形状）、ADR-0028 决定 4（只抽格式、不抽文案，报错文案由写它的那处就地定）、ADR-0032 第四条（字只在一处成形）

## Problem Statement

使用者读到的文字，读着像模板写的，读完仍要自己猜下一步。三处最典型：

**空话与铺垫。** 句子先宣告再交代：「本文深入探讨」「这标志着……」「接下来让我们看看」。删掉之后意思不变，读者却要多读一行才拿到信息。

**行话。** 手册拿维护者的词解释给使用者看的事：使用手册讲「失败原因的原文是什么样」那一段、进阶知识手册讲「结果是怎么定下来的」那一节，都用「报文」说终端上那行字。读者得先学会这个词，才看得懂自己机器上发生了什么。

**模板化节奏与重复。** 同一件事在相邻两句里说两遍；三项排比占一行却只有一个信息；正文里夹着「好问题！」「希望对您有帮助」这类客套；结尾落在「让我们拭目以待」。

合起来的效果是：读者读完知道它设计得不错，说不出下一步做什么。

另有一类是同源发现，判据不是味道；那几样不在本规格内，另行上报。

## Solution

每一处使用者可见的文字都过一遍「味道」判据：删掉删了意思不变的句子，把行话换回使用者的语言，把「怎么做」写在「为什么」前面，手册每句要能照出一个动作。判为空的删、判为模板的拆；不为了「像人写」补故事、补情绪、补第一人称。

审的面按字数切片，一片按四步走：审、说理由、改、复审。

改完之后：读者在终端、README、手册里拿到的每一句话，都不再多绕一层，也不再有只宣告不交代的句子。行为、参数、退出码一律不动。

## User Stories

1. 作为运维，我希望手册每一句都告诉我要做什么，而不是先介绍这件事多重要。
2. 作为运维，我希望手册里没有「本文深入探讨」「这标志着」这类只宣告不交代的句子。
3. 作为运维，我希望终端上的说法是我能对上号的词，不用先学「报文」「闸门」这类行话。
4. 作为运维，我希望同一条信息不要在两处说两遍。
5. 作为运维，我希望三项排比里每一句都带信息，不要三句说一件事。
6. 作为运维，我希望正文里没有「好问题！」「希望对您有帮助」这类客套。
7. 作为运维，我希望结尾不要落在「让我们拭目以待」这种不给动作的话上。
8. 作为运维，我希望「为什么这样才对你有用」跟在「怎么做」后面，而不是挡在前面。
9. 作为运维，我不希望读到「此前是……现已改为……」——我只关心现在怎么用。
10. 作为运维，我希望 README 每一段都能让我做一件事：装、配、跑、查。
11. 作为运维，我不希望为了看懂一句话去查源码或词表。
12. 作为运维，我希望同一件事在 README、手册、终端三处叫同一个名字。
13. 作为维护者，我希望每一处改动都能指回一条判据，而不是「我觉得更自然」。
14. 作为复核人，我希望判定表能让不看代码的人判得出这句为什么算空话。
15. 作为开发者，我希望这轮只改说法，不改行为、不改退出码。

## Implementation Decisions

### 判据

- **废话**：删掉之后读者理解的意思不变，就删。这一条最硬，也最好判。
- **四条硬要求**里的前三条：站在使用者那边写（行话换成他的语言）、简洁不铺垫（怎么做在前、为什么在后）、只写当下不写沿革。
- **手册条款**里的两条：每一句都要能照出一个动作；只写结论，不写取证过程（「实验形态」「实测发现」「源码推断」这类都不许出现）。
- **模板形态**作检查线索，不当词表用：假对比（不是 X 而是 Y）、单句收尾的戏剧性碎片、格言式伪深度、起跑式铺垫、强凑三段式、重复开头、万能破折号、限定词堆叠、句尾拔高、宣传语、借权威、客服腔、首句复读标题、谈论上一稿、套话收尾；中文常见的还有长定语、被字句堆叠、四字词排比、「随着……的发展」开头。命中不等于要改——回到上下文，看它是否空泛、重复、与文体不符。

判定三档：**空**（删或并）／**模板**（改成直陈）／**合规**。理由一句，不许写「不够自然」「AI 味重」这类不可复核的话。

### 范围

进：

- `README.md`
- `docs/1-使用手册.md`、`docs/2-基础配置手册.md`、`docs/3-进阶配置手册.md`、`docs/4-进阶知识手册.md`、`docs/5-常见问题.md`、`docs/6-示例.md`
- `modules/SSHFleet2_Go/internal/message/` 全部非测试文件里拼出的中文文案

不进：`modules/SSHFleet_Go_bak/`、`CHANGELOG.md`、`docs/adr/`、`docs/agents/`、代码注释、运行日志、panic 与内部断言、`personal/`、`build/` 下的产出物。

### 落点与改法边界

- 中文字只在一处成形（ADR-0032 第四条）。改文案不动构造点：三行套的标签、换行、留白仍由 `screens.go` 的 `problem` 系列加（ADR-0028 的构造点，形状见 ADR-0025 决定 6）。
- 报错那句该怎么说，仍由写那个报错点的人就地定；本规格不把文案集中到构造点。
- 手册逐句修优先；整节删干净之后没有一个动作可做，才整节重写。
- 不改行为：参数语义、默认值、退出码、分类名、判定顺序一律不动。
- 不加戏：不补作者经历、不补数据、不补结论，也不把「可能」写成「确定」。删空话之后句子短了，不需要拿新内容填回去。

### 每片四步

1. **审**：逐处写判定表——位置（`路径:行号`）、判定（空／模板／合规）、点到的形态、一句理由。原文不抄进表：改完那句就变了，抄进去的那份会成为第二个真相，判定与复核一律按位置回原文取。判定表落 `build/audit-<日期>/<片>/`，不入库；它不是测试沙盒，不按天清，留到本轮收尾。
2. **说理由**：一条一句，写清「空在哪」「照哪条判」。
3. **改**：只动判「空」与「模板」的；每条改动回指判定表那一行。一片改完跑一次门与测试。
4. **复审**：每连续三片（或一个族收尾）交一次 SubAgent。只给它三样——那片原文、判定表、改后文本；只判两件事：判定成不成立、有没有加戏（补事实、编经历、把可能写成确定、把删掉的话换成一堆新话）。结论回写判定表末尾。

### 不外露的四样：同源发现，单独上报

这四样读文本时必然撞见，但判据不是「味道」，不进本规格的验收，也不占分片：

- **报错缺第三行「提示：」**：要走。做法是给门加一条形状检查，先评估哪些形态语法树判得出（确认类提示本来就允许只有一行），评估结论报开发者后再动 `internal/guard` 与它的红线区测试。
- **手册示例能不能原样跑通**：要真连目标机跑，属正确性。
- **常见问题按阶段还是按症状**：属结构。
- **包外有没有在拼句**：属「字只在一处成形」；直写 stdout 那一层门已经在查，拼句这一层要在另一条线上判。

## Testing Decisions

味道没有机器判据，能做的就是三样：

- **判定表**：每一处都有判定与理由，复核照它复述得出「这句为什么算空」。这是本规格唯一能落成文件的东西。
- **人读一条**：每族抽十处，给没读过源码的人或 SubAgent 读，看他能不能说出下一步动作、能不能指认哪句是空话。机器判不了，由开发者或派出的复审 SubAgent 判。
- **既有测试要绿**：文案改了期望跟着改，不许为了让测试过而放松断言；不为文案新加快照。每片跑 `bash tools/check.sh`，代码片再跑 `bash tools/test.sh ./...`。

## Out of Scope

- 报错三行齐不齐、门加不加形状检查：另一条线，单独上报
- 手册示例的可跑性：正确性，单独上报
- 常见问题的结构：该按症状，但属结构问题，单独上报
- 包外拼句的核对：属「唯一出口」，单独上报
- 行为与语义：参数含义、默认值、退出码、分类名、判定顺序
- 视觉：颜色、宽度、分隔线、表格列宽
- 英文版与多语言：`[locale] english` 只管开关，不做翻译
- `modules/SSHFleet_Go_bak/` 那一棵、`CHANGELOG.md`、ADR、`docs/agents/` 下的约束
- 代码注释、运行日志、panic、内部断言
- `personal/`、`build/` 下的产物、`skills/` 正文
- 本轮不拆工单

## Further Notes

- 改代码里的字符串要「授权开工」；README 与手册是说明性文字，可直接改。
- 判定表落 `build/audit-<日期>/<片>/`，跨天留到本轮收尾；测试沙盒另按天清，两者不混。议题目录里只留这份规格。
- 片表的字数是切片用的量，改完不必重算；片内文件增删了就按判据单元挪，不按字数重切。
- 本轮不新增 ADR。
