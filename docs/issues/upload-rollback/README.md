# 上传失败即回滚 · 议题

> **入口**：这件事要做成什么样看 `spec.md` 与 ADR-0022；落点与工单见下方表格。

## 这是什么

上传一个目录时，今天只要有一个文件失败就中断，已传成功的那些留在目标机上，分类落成「部分成功」。本议题把它改成**全成或全不成**：失败时删掉本次已写入的文件与半成品，让目标机恢复到本次执行前的样子。

下载**不做**同样的处理（ADR-0022 决定第 5 条：下载动的是本机自己的产物，删目录重下即可）。

## 已知的坑

- **只删本次写成功的路径**，不许扫目录、不许通配符、不许删中间目录——上传的「写入前必查重名」是这条安全的依据，动手前先核对它还在。
- **sudo 路径**要能删到 root 属主的文件；回滚本身失败时如实报告，不许静默。
- **`finished` 报文与「部分成功」是同一个决策的两面**：删一个留一个，就会留下一条永远发不出去的认领。
