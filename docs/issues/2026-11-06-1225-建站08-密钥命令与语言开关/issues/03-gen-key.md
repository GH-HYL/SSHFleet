# 03: `--gen-key` 全链路

**要做的**：做完之后，`sshfleet2 --gen-key` 生成一把新主密钥、写成本机持久值，屏上只出现指纹与「下一步做什么」（写到哪、怎么让它生效、生效前转换会被拦下）；本机已有密钥时先说清现状再问要不要覆盖，回车即保留、`--yes` 下拒绝自动覆盖并说清怎么才能覆盖。

**Blocked by**：02。

**Status**：done（Windows 那次真跑没做，见 Comments）

- [x] 空现场（`HOME` 指到空目录）跑一次：退出码 0，rc 文件末尾出现唯一一条主密钥行，屏上三句与指纹都在、没有密钥本体
- [x] 已有密钥时答「否」：退出码 0，rc 文件一字不改，屏上「已保留原密钥，未做修改」
- [x] 已有密钥时读到输入结束（EOF）：与答「否」同一收场，退出码 0
- [x] 已有密钥时答「是」：退出码 0，密钥换了一把（指纹变了），屏上「已确认覆盖，正在重新生成主密钥...」
- [x] 已有密钥时加 `--yes`：退出码 1，屏上是「非交互模式不自动覆盖」加「如需覆盖：去掉 --yes 后重新执行 --gen-key」，rc 文件不动
- [x] 两处不一致时开场那段含「→ 两处不一致——这正是凭据解密报「主密钥不匹配」的常见原因」
- [x] 每次覆盖确认只问一句、问完不再吞掉后续输入（共用 `ask` 那一条 reader）
- [ ] **Windows 侧真跑一次 `setx` 并复位**——本机拦着，没做

## Comments

**A/B**（`t2.sh`）：答否／回车／EOF／`--yes`／答是五档，随机密钥那几行按八位指纹归一之后两侧逐字相同；`--yes` 那一档连「日志：」行之外一字不差。

**Windows 那一步没做，原因记清楚**：spec 第十二节那三步要 `reg query` 与 `setx`，本机把 `reg.exe` 列进了沙箱的禁止启动名单（`reg query HKCU\Environment` 直接被拒），`setx` 属同一类系统程序，没有绕过它去查注册表的道理。已做的替代验证只有一半：`GOOS=windows` 交叉编译过（`persist_windows.go` 的注册表读与 `setx` 写都能编译）。**三步留给开发者在自己的终端里走**：先 `reg query HKCU\Environment /v SSHFLEET_KEY` 记原值（可能不存在）→ 跑一次 `sshfleet2 --gen-key` 比屏上三句与指纹 → 原本有值就 `setx SSHFLEET_KEY "<原值>"` 写回，原本没有就 `reg delete HKCU\Environment /v SSHFLEET_KEY /f`。这条路径一旦抄错，症状是「密钥写进去了、新终端读不到」，所以不验就等于发布平台上留一个洞。
