# 规格：阶段 08——三条密钥命令、主密钥那摊事与语言开关

**Status**：已完成（done）—— 六张单全结；Windows 侧那次真跑 `setx` 没做（本机 `reg`／`setx` 被沙箱拦住），三步留在 03 号单里由开发者手工走。

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

**本阶段动一次红线区的文件，但不构成「改红线」**：`parse.Run` 要递回第四样（那条小命令），红线测试 `TestRedlineParseSaysOrFail` 的调用点跟着加一个空位。按 ADR-0037 决定五的判据（「新增一条不算改；删掉、改名、收窄引用面算改」），这里测试名没动、它直接引用的生产符号 `parse.Run` 没动、四条断言一字没动，动的只是调用点上返回值的位置——同一个判据里，重排语句都不算改。

所以不另开议题（本目录就是）、不写新 ADR：决策早就在 ADR-0032 第五条（结局有四种，第二种就是那条小命令），本阶段只在它末尾记一笔「第四种落成真的出口」，写明改动落在哪个文件、哪几行。

## Problem Statement

加密开着的使用者今天少两样东西。

第一样是那三条小命令。`--gen-key`、`--key-status`、`--convert-secret` 在帮助里印着、在选项表里认得出，敲下去得到的却是「这条用法还没接上：三条密钥命令随阶段 08 接线」——一句过渡期的话。老版这三条是能用的：生成主密钥并写进 shell 的 rc 文件、查「读到哪把、已存哪把、一致不一致」、把凭据文件在明文与密文之间转一次。搬到现在，`encrypt = true` 的人其实没法把手上那份明文清单变成密文。

第二样是每次开跑前那句提醒。老版在开工前看一眼主密钥的两处来源：终端里读到的，和本机存着的。不一致、存了没读到、只活在这个终端里——三种都会让「用这把密钥加密的文件，重开终端就打不开」，而使用者看到的只是后来某次解密报「主密钥不匹配」。老版为此在步骤 4.5 主动说一段，新版这一屏跟着 03、04 一起推迟到了本阶段，现在还没有。查文档能查到它归塔尖（04 号迁移地图的更新记录），但那一屏从未存在。

第三样只是账没对清：`[locale] english` 的实现早随 05 搬完了（下发行那一段、代填值含中文那道门、执行期日志的「说明」行三处都在），但纸上一句注释还写着「判据表按语言选哪一套，是阶段 08 的事」。这句要么当期兑现，要么当众撤销。

## Solution

敲 `--gen-key`，拿到一把新的主密钥，它被写进本机（POSIX 是登录 shell 的 rc 文件，Windows 是 `setx`），终端上只出现指纹与「下一步做什么」；已有密钥时先问一句再覆盖，`--yes` 下拒绝自动覆盖。敲 `--key-status`，看到两处来源各自是哪一把、一致不一致、下一步做什么。敲 `--convert-secret <文件>`，按 `[credential] encrypt` 的方向把它在明文与密文之间转一次，写完回读、只报长度不回显内容。

加密开着的每次批量执行，开工前多一段提醒——只在主密钥有问题时出现，只在 `encrypt = true` 时出现；加密关着时一个字都不多。三条命令进不了流水线，流水线也不因为它们多一条分支以外的东西。

`[locale]` 只剩一件事：把纸上那句失实的注释改成事实（判据表只有一份、两种语言的词都在同一张表里），并用一次 A/B 把 `english = false` 那一档的下发行钉住。

## User Stories

1. 作为运维人员，我敲 `--gen-key`，终端告诉我主密钥已生成、写到了哪里、下一步要做什么，而不是「还没接上」。
2. 作为运维人员，我本机已经有主密钥时再敲 `--gen-key`，工具先说清现状（两处各是哪把、一致不一致），再问我要不要覆盖，缺省是不覆盖。
3. 作为运维人员，我不想被问话时加 `--yes`，工具拒绝自动覆盖并告诉我怎么才能覆盖——它不会替我把旧密钥换掉。
4. 作为运维人员，覆盖确认的提示上我直接按回车，原密钥保留，工具正常退出而不是报错。
5. 作为运维人员，我敲 `--key-status`，一眼看到「正常／不一致／已保存但当前终端没读到／未持久化／未设置」里的哪一种，以及下一步该执行什么。
6. 作为运维人员，我从不把主密钥本身打到屏幕上——屏幕上只有指纹（八位十六进制），日志里也一样。
7. 作为运维人员，我敲 `--convert-secret <文件>`，`encrypt = true` 时它变成密文、`false` 时变回明文，屏幕上只报「转换成功：明文 → 密文：<路径>」与内容长度。
8. 作为运维人员，我把已经是密文的文件再转一次，工具告诉我「当前已是密文，无需转换」，不覆盖、不报错。
9. 作为运维人员，我在两处主密钥不一致时想加密，工具把它拦下来并给两条出路——宁可这次转不成，也不让我造出将来打不开的文件。
10. 作为运维人员，我写在清单里的路径打错时，转换报的是「读不到那个文件」而不是「主密钥不匹配」。
11. 作为运维人员，三条密钥命令任意两条一起给、或跟 `-c`／`-f`／`-n` 这类批量参数一起给，工具当场拒绝并说清「分成两次执行」。
12. 作为运维人员，加密开着、而主密钥两处来源不一致时，我跑一次批量执行，开工前看到那段提醒，执行照旧继续。
13. 作为运维人员，加密关着时我跑批量执行，屏幕上一个字都不多——不加密还查主密钥是纯干扰。
14. 作为运维人员，`[locale] english = false` 时下发行里没有那句把提示语钉成英文的片段，目标机说它自己的语言。
15. 作为运维人员，`english = true` 而代填值里写着中文时，那条门照旧拦我（05 已落，本阶段只验它没被碰坏）。
16. 作为维护者，三条命令的每一句话都出自 `message`，密钥包不自己拼字。
17. 作为维护者，密钥包不碰终端：打字走 `ask.Show`、问话走 `ask.Ask`，ADR-0032 第四条那四处照旧是四处。
18. 作为维护者，结构检查拦得住「五站 import 密钥包」与「密钥包 import 某站」这两个方向。
19. 作为维护者，我在任一台机器上跑 `go test ./...` 都不会写坏自己的 rc 文件或注册表——持久值那一摊在测试里是注进去的假件。
20. 作为维护者，切换那天我不用担心这三条命令：它们与老版逐字对过、退出码逐个对过。

### 一、两个包各拿什么：主密钥归凭据包，三条命令归密钥包

老版把「读主密钥、加解密、生成、持久化、转换、三条命令」装在 `credential` 一个包里。ADR-0036 决定三劈过一次（凭据读取单列一个叶子包、三条命令另起一个）；本阶段按开发者的裁定再挪一次：**主密钥那摊是独立功能，回凭据包；密钥包只留三条命令的流程**。

| 这一摊 | 归谁 | 为什么 |
| --- | --- | --- |
| 读主密钥（环境变量那条路）、解密、报齐不齐 | `credential` | 站每台机器都要用；高频路径上它只读环境变量，一次盘都不碰 |
| 主密钥的另一处来源：本机持久值的读与写、指纹、五种状态判定 | `credential` | 主密钥是一件事，「本次运行这把」与「本机存着的那把」一致不一致，只有住在同一个包里才判得出来 |
| 封一段明文成密文、生成随机主密钥 | `credential` | 密文格式是一个整体：解与封分住两个包，格式一改就得跨两个包改；生成出来的就是主密钥本身，与持久值同族 |
| 三条命令的流程、问话、屏、失败、读自己那一小块配置 | `keytool` | ADR-0036 决定三 |

`credential` 从此是**「凭据与主密钥」那一路**，一句话仍说得清：主密钥从哪来、往哪存、齐不齐，密文怎么封怎么解，凭据值怎么读出来。站要的东西一样不多（`Status`／`MasterKey`／`Secret`／`Decrypt`）；新增的那几样（另一处来源的读写、指纹、五状态、封、生成）只有那三条命令与预检查在调，不在流水线的任何高频路径上。

**注意「封」的边界**：`Encrypt` 只吃「明文 + 主密钥」，交回密文串；它不读盘、不写盘、不管方向、不做一致性保护——那些是命令的事，住 `keytool`。

### 二、塔尖分叉的第四样：解析递回「一条小命令」

ADR-0032 第五条早就写了结局有四种：「信封（进流水线）、**一条小命令（交给密钥管理包）**、一句要打给使用者的话、起不来」。骨架里只落了三种——`parse.Run` 现在是 `(说话, 纸, 起不来)`。本阶段把第四种落成真的：

```
parse.Run(...) (message.Line, *contract.Plan, *contract.KeyRun, *contract.CannotStart)
```

- **谁认出这是哪条命令**：解析站。它是唯一读命令行的地方（ADR-0032 五），塔尖不许自己看 argv。
- **`contract.KeyRun` 只装三样事实**：哪一条、`--convert-secret` 的那个值、`--yes` 给没给。多一样都不装——它不是第一张纸，不该背上那张纸的重量。
- **塔尖的 switch 从三种变四种**，多出来那一支只做一件事：把这条命令交给 `keytool.Run`，然后按它交回的结局收场。塔尖仍然不判断「该不该」。

**先后与老版对齐**：老的次序是「命令行词法错（未知选项、缺值）→ 密钥命令互斥检查 → 批量参数合规」。新工程把前一半落成纸上的 `Problems`、由闸门拒，后一半在本阶段之前根本不存在。所以本阶段的判法是：

1. 扫出词法问题（`ProblemUnknownOption`、`ProblemMissingValue`）时**不进密钥分支**，仍走既有那条路（闸门拒）——与 0x 定的先后一致，不新增差异；
2. 词法没问题，就要么递回 `KeyRun`、要么递回纸，二者必有其一；
3. 密钥命令的两种不合规（一次给了两条、与批量参数同给）当场是「起不来」，不走闸门——老版这两句也是 `fatal`，环节名 `cli`，外壳句「选项/参数合规性检查未通过」。**这是开发者 2026-11-06 的裁定**：「他不用走什么闸门一类的，不需要，他是独立的」——三条命令不进闸门、不进流水线那套合规判定，由解析站在分叉口当场判掉，流程简单。

### 三、密钥包读自己那一小块配置，不借解析站的手

ADR-0036 决定三：「需要配置就在自己包里读自己那一小块」。本阶段照字面办——三条命令是独立功能，不掺和主流程，要什么自己读：`[credential] encrypt` 由 `keytool` 自己从 `./config/SSHFleet.conf` 取。

- **只读一格**，标准库手写扫一遍就够（配置文件在解析站那边本来就是手写解析，没有 TOML 库），不 import 模块外的包。
- **读不到、读不出**：按「起不来」收场，句子仍从 `message` 出。这条路径实际上走不到——进密钥分支之前，解析站已经把整份配置读通了一遍，坏配置在那一步就报过。
- **代价认下来**：同一份文件有了第二个读取器。它只认一格布尔，且只在「解析站已经读通过」之后才跑；将来要改这一格的写法，两处都要改。

三样事实仍由解析站带上：`KeyRun.Which`、`KeyRun.Path`（原样不 trim）、`KeyRun.Yes`。命令行只有解析站读（ADR-0032 五），塔尖不许看 argv——**密钥包读的是配置文件，不是命令行**。

### 四、打字走 `ask`，密钥包不碰终端

ADR-0032 第四条把「调终端的地方」数成四处，其中一处就是 `ask`。所以密钥包的三摊输出一律经它：陈述用 `ask.Show`（只打一屏、不问），问话用 `ask.Ask`（打完再收一行）。`keytool` 因此不 import `console`，那四处一处不增；ADR-0032 第四条一个字不改。

**这也是「一次交互问两句」那个坑的正解**：`ask` 的 stdin 整进程共用一条 reader（06 交接里记着），自己不另开 `bufio.Scanner` ——老版 `--gen-key` 是「先说一段、再问一句」，正好是这条路径。

### 五、看状态：五种状态、两处来源、只报指纹

判定与老版逐条对齐（`InspectKey`）：`Diverged` → `EnvSet && PersistedSet` → 只剩 `PersistedSet` → 只剩 `EnvSet` → 都没有，依次落成「不一致／正常／已保存但当前终端没读到／未持久化／未设置」。

- 指纹 = `sha256(密钥)` 前 4 字节的十六进制（八位）；空密钥印「（未设置）」。**屏幕上与日志里都不出现密钥本身。**
- 两处来源的位置要照老版说清：POSIX 是那个 rc 文件的绝对路径，Windows 是 `注册表 HKCU\Environment`。
- POSIX 侧还要带「另一处持久值」那一行（两个 rc 文件里存着不同的密钥），Windows 恒空。
- 五种状态各自的报告正文照老版逐字，含那句「不需要 --gen-key」——它专治「生成的密钥没生效，于是又生成一次，把旧密文全废掉」这个坑。

### 六、生成主密钥：覆盖要问，非交互不替人决定

- 已有密钥（环境变量或本机持久值任一有值）时：先打一段现状（两处各是哪把、不一致就点明「这正是凭据解密报主密钥不匹配的常见原因」），再说一句「注意：如果覆盖，用旧密钥加密的凭据文件将永久无法解密」，然后问「是否确认覆盖？」——缺省否。
- `--yes` 时不问，直接报错收场：「检测到已存在主密钥，非交互模式不自动覆盖……如需覆盖：去掉 `--yes` 后重新执行」。
- 交互下读到输入结束（EOF），按「否」办：保留原密钥、正常退出（退出码 0），不是取消。
- 写持久值：POSIX 把当前 shell 的 rc 文件（`$SHELL` 含 zsh 用 `.zshrc`，否则 `.bashrc`）里的主密钥行**收敛成末尾唯一一条**（清掉旧行与那行分组注释，末尾追加一组）；另一侧 rc 文件若已存在且已有密钥行，一并改成同一把。文件不存在时不新建。Windows 走 `setx`（写注册表要广播 `WM_SETTINGCHANGE`，`setx` 替我们做了）。
- 收尾三句照老版：写到哪、请 `source` 或重开终端生效、「注意：在此之前，本次运行读到的仍是旧密钥，执行 `--convert-secret` 会被拦下（避免加密出将来看不开的文件）」——「注意：」与括号尾巴都不能少。
- **绝不打印密钥本身**，只打印指纹。

### 七、转换凭据：方向由开关定，加密方向先过硬保护

- 目标路径原样交给系统：相对、绝对、`../` 都由 `os` 按当前工作目录解析；**不 trim、不展开 `~`、不判形态**（ADR-0025 第零节）。
- 方向：`Encrypted` 为真 → 明文转密文；为假 → 密文转明文。**先看形态再动手**：已经是目标形态就报「当前已是密文／明文……无需转换」并正常退出（退出码 0），不覆盖。
- 加密方向先过老版那道硬保护：两处来源不一致时**拒绝加密**，并给出两条出路（先 `source`／或把当前这把写成持久值）。理由是加密不可逆——用旧密钥加出来的文件，重开终端就打不开了。
- 解密失败归一句：「解密失败：主密钥与加密该文件时使用的密钥不一致，或文件已损坏/被修改：<路径>」，把底层原因附在后面。
- 解出来是空串时**拒绝写回**（老版同一条）。
- 写完从磁盘回读一次，只报「转换成功：X → Y：<路径>」与「内容长度：N 字符，请用编辑器打开该文件确认结果」——**不回显内容本体**，尾巴那句照老版。

### 八、主密钥预检查：塔尖在建纸之后、递给闸门之前问一句

位置照 04 号迁移地图的更新记录（「不归解析、归塔尖」）。塔尖拿到纸之后、交闸门之前问一句，只在 `encrypt = true` 时问：

- 正常就一个字都不说；**「未设置」（两处都空）也一个字都不说**——老版 `PrecheckKey` 只有三支，`KeyStateOK` 与 `KeyStateUnset` 都落到那个 `return ""`；

### 十、那几句必须逐字照老版，且只能从 `message` 出

字全部照老版抄，一处不重写。本阶段要新增的构造点（不含逐条穷举）：

| 场合 | 老版原句（`%` 处按老版填） |
| --- | --- |
| 两条命令一起给 | `%s 只能给一个——它们是三个独立命令，一次做一件事` |
| 与批量参数一起给 | `%s 不能和批量执行选项一起用：同时给了 %s` + 换行 + `提示：分成两次执行——先跑密钥管理命令，再跑批量执行` |
| 已有密钥、非交互、不给覆盖 | `检测到已存在主密钥，非交互模式不自动覆盖（覆盖后旧密钥加密的凭据文件将无法解密）。` + 换行 + `如需覆盖：去掉 --yes 后重新执行 --gen-key` |
| 覆盖确认那一问 | `是否确认覆盖？`（缺省否） |
| 覆盖后 | `已确认覆盖，正在重新生成主密钥...` |
| 保住了原密钥 | `已保留原密钥，未做修改` |
| 转换已是目标形态 | `当前已是密文，无需转换：%s` ／ `当前已是明文（文件内容即密码本身），无需转换：%s` |

「指纹」「两处来源行」「rc 文件末尾收敛」「Windows 的 `setx` 提示」这几段同理——中文句子一律住 `message`，平台差异只以事实（路径、命令名）递进去，`message` 不判平台。

### 十一、失败怎么收场：三条命令的错都是「起不来」，环节名沿用 `credential`

- 三条命令运行中出错（生成失败、转换失败、解密失败）一律是「起不来」，退出码 1，环节名写 **`credential`** ——**沿用老版的名字，不改成新包名**。先例在解析站：老包 `nodelist` 并进解析站之后，那一屏仍写 `nodelist`。
- 那个名字**不是定位线索，只是逐字一致的一部分**：同一屏上还有「无法生成主密钥」这类中文句子，维护者靠那句话找地方，不靠 tag。反过来，写 `keytool` 就等于在这个阶段唯一的判据上记一笔不必要的差异。
- 命令行不合规那两句（互斥／与批量参数同给）环节名写 `cli`，外壳句照老版「选项/参数合规性检查未通过」，也是「起不来」。
- 成功一律 0：`--key-status` 打完就退、`--gen-key` 写完就退、`--convert-secret` 转完就退。三条命令都不建归档目录、不写 `report.txt`、不进闸门、不造交接件。
- 一条命令跑完，工具日志照老版留一行「进入……模式」；开工那几行（工作路径、原始选项）与流水线共用同一套，不必另写。

### 十二、平台：POSIX 做 A/B，Windows 真跑一次并复位

- POSIX（WSL 里那个本机 sshd 那条环境）做 A/B：rc 文件读写、`source` 提示、`--gen-key` 全链路、逐字比对都在这里。
- Windows 侧**真跑一次 `setx` 那条路，跑完复位**。零证据的代价落在发布平台上：这条路径一旦抄错，使用者第一次 `--gen-key` 就失败，而且失败形态最难看——密钥写进去了，新终端读不到。这不是结构问题，是验证漏洞，而它能补：

  1. 先 `reg query HKCU\Environment /v SSHFLEET_KEY` 记下原值（可能不存在，存在就抄下来）；
  2. 跑一次 `sshfleet2 --gen-key`，比屏上的三句话与 `reg query` 回来的值（指纹要对得上）；
  3. 复位：原本有值就 `setx SSHFLEET_KEY "<原值>"` 写回，原本没有就 `reg delete HKCU\Environment /v SSHFLEET_KEY /f`。

  风险只在第 3 步，手工能修（一个用户环境变量）。**只在开发机上做，不进自动化测试**——测试里 `setx` 一律走注进去的假件。
- 持久值那一摊照老版先例收成**一个可注入的值**（老版 `KeySource` 的三个字段就是这个形状），住凭据包：读环境变量、读本机持久值、写持久值三件事各是函数，默认实现按平台，测试注入假件。这不是探针，是那一件事的接口。

## Testing Decisions

- **接缝沿用既有的，本阶段不加新接缝**：

  | 塔尖的进程出入口 | 三条命令各跑一次：退出码 0、屏上的话、`--convert-secret` 真的把文件转过去；两条一起给、与 `-c` 一起给各一次：退出码 1、两句话同老版；加密开着跑一次批量执行：多一段预检查、执行结果不变 |

- **持久值的测试不许写坏本机**：注进去的假件把 rc 路径指到测试临时目录；跑测试时 `HOME` 也别依赖真实值。
- **A/B 口径**：`build/` 下当天沙盒起新老两个二进制，**各自一份 HOME**（沙盒里建 `home_new/`、`home_old/`，两侧都从空 rc 起跑）：
  - `--key-status`：未设置 → 生成后 → 再改一把制造不一致，三档屏逐字比；
  - `--gen-key`：覆盖确认答「否」与 `--yes` 两档逐字比；
  - `--convert-secret`：明文转密文、再转回来（密文本体不复现，比「转换成功」「内容长度」与回读后的明文是否与原文件相同）；

  两侧必须从同一现场复位起跑（每支脚本自己复位 HOME）。
- **环境类失败不进两区**：目标机没起先修；修不掉就写明哪一步没验。
