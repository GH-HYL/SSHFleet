# 02: 中断这个事实进纸，屏幕与报告都出「未执行」

**要做的**：跑到一半按 Ctrl+C，工具把「这次是被中断结束的」记进纸，于是统计块给「未执行：N」、`report.txt` 同一行、屏幕先补那句提示，退出码 0。做完之后，中断的那次运行在屏幕上与盘上都收得完整。

**Blocked by**：01（要能拿到被取消的 context）。

**Status**：done

- [x] 执行站收尾时按 `ctx.Err() != nil` 写 `paper.Interrupted`
- [x] 两条用例钉住这一格：被取消的 `ctx` → 真；没取消的 → 假（现有那条只断言了每台的 `Cancelled`，这一格今天无人填、无人验）
- [x] 结算站按这一格算缺额，`Verify` 置空（不是「异常」）——那条已有用例覆盖，本单只验接线到位
- [x] 屏幕那句逐字：`已收到中断信号，SSHFleet 停止执行（已完成节点的结果已写入日志/输出文件）`，成品由 `message` 造（契约里不装字）
- [x] 日志那句 `收到中断信号，执行已停止` 同样由 `message` 造，塔尖只转手走 `Warn`（先例：确认屏答否那句 `CancelTrace`）
- [x] 次序：结算 → 执行期日志收尾行 → 屏幕那句 → 统计块；与老版同
- [x] 真机：`-n 1` + 三台 + `sleep 30`，起进程 2 秒后发 `SIGINT` → 屏幕一句提示、统计块「节点总数 3 完成总数 1 未执行 2」、`report.txt` 写「未执行：2（执行被中断）」、码 0
- [x] `gofmt -l .` 空、四项检查与 `go test -race` 绿

**不在这单**：被中断的机器归哪一类（03）；六条通道各自的收尾（04、05）。
