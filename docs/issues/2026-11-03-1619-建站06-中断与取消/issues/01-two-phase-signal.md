# 01: 塔尖接上中断——一次登记、两段收场

**要做的**：按 Ctrl+C 时，执行前与执行中走两条不同的路——执行前立刻退、码 130、不建归档目录；执行中把取消交给执行站，走正常收尾；连按多次也不退出。做完之后，中断不再是「进程被系统杀掉」。

**Blocked by**：无，可立即开工。

**Status**：ready-for-agent

- [ ] **前置：两处检查本体的点头**（ADR-0042 已由开发者 2026-11-05 认下这套设计）——规则表加一行（`interrupt`，横切类，只依赖标准库）、塔尖符号表撤掉 `signal.Notify` 一格。这两处不动，新包一建、塔尖一改，依赖那条检查立刻红
- [ ] 新横切包 `interrupt`：控制台摆正之后登记一次 `SIGINT`／`SIGTERM` 并建可取消的 `context`；一个循环读信号，先取消、再看状态位；执行段的重复信号一律忽略；登记到进程结束**不撤、不 `Stop`、不重登记**
- [ ] 塔尖只在三处碰它：起来时登记并拿到取消句柄、把取消通知递给执行站、在建归档目录之前翻状态位；塔尖的 import 里没有 `os/signal`、没有 `syscall`
- [ ] 启动段（控制台摆正之后、翻状态位之前，含解析、闸门、确认屏）收到信号：走 `finish`（还控制台、关日志、退 130）、**不建归档目录**
- [ ] 执行段收到信号：取消递给执行站；重复信号无动作；收场走正常路径，退出码 0（节点有失败也是 0）
- [ ] 真机：确认屏停住时发 `SIGINT` → 码 130、`history/` 下没有新目录；`-c 'sleep 30'` 跑到一半发 `SIGINT` → 进程自己退、码 0
- [ ] 真机：执行段**连按五次** `SIGINT` → 进程仍在、走完整收尾、码 0（ADR-0042 的第一项就靠这一条验，别当可选项）
- [ ] `gofmt -l .` 空、四项检查与 `go test -race` 绿、18 包零违规、红线仍 39 条

**不在这单**：纸上那格 `Interrupted`、屏幕那句提示（02）；两条通道的报文（03）。
