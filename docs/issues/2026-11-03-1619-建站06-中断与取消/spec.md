# 规格：阶段 06——中断与取消

**Status**：done

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

运维人员敲下回车之后会按 Ctrl+C，两种时刻：还没开跑（正在看确认屏、或者正在读清单），和跑到一半（一批机器里前几台已经跑完）。

老版这两种时刻的收场不一样：没开跑就退，码 130，一个归档目录都不建；跑到一半则是**收工不是硬杀**——没开跑的机器不开工、已开工的跑完并照常上交，屏幕上多一句「已收到中断信号」，统计块把缺额单列成「未执行：N」而不是「异常」，`report.txt` 里同一行、`terminal-output.txt` 与执行期日志照写，退出码仍是 0。

新版这两种时刻都做不到：塔尖根本没装信号处理，按下去是**进程被系统杀掉**——Windows 上码页不还、日志不关、归档目录半截、`report.txt` 一个字不写、统计块与那句提示都不出现；跑到一半的那些机器连「被中断」都认不出来，屏幕上是一串 `context canceled` 原文，每台各占一个分类。

## Solution

按 Ctrl+C 之后，运维人员拿到的东西与老版一致：**没开跑就是干净退场，跑到一半就是把这次收工收完整**——屏幕、统计块、`report.txt`、`terminal-output.txt`、执行期日志、退出码，六处对得上；被中断的机器归到「建连被取消」或「任务已取消」，不刷出一堆原文分类。

## User Stories

1. 作为运维人员，我在确认屏上按 Ctrl+C，进程立刻退、退出码 130、不建归档目录，与老版一样。
2. 作为运维人员，我在一批机器跑到一半按 Ctrl+C，工具不硬杀：屏幕补一句「已收到中断信号，SSHFleet 停止执行（已完成节点的结果已写入日志/输出文件）」，统计块给出「未执行：N」，退出码 0。
3. 作为运维人员，中断那一刻还在建连的机器归「建连被取消」、已经连上跑着命令的归「任务已取消」，两者报错原文里各带一句报文，我一眼看得出它是「没跑到」还是「跑过一段」。
4. 作为运维人员，中断时已经开跑的机器结果照样落盘（`terminal-output.txt`、执行期日志、`report.txt` 都要有它），没开跑的一台都不造行。
5. 作为运维人员，上传跑到一半按 Ctrl+C，目标机上不留本次已经写进去的文件；下载跑到一半，本机不留半成品。
6. 作为运维人员，代填与改密跑到一半按 Ctrl+C，屏幕上说的是「被中断」，不是「代填没送完」或「密码没改成」。
7. 作为维护者，中断之后归档、统计、报告三步照常走完，不是停在半路；`report.txt` 的结果统计段写着「节点总数／完成总数／未执行：N（执行被中断）」。
8. 作为维护者，中断场景下新老两版归一化后逐字节同（屏幕、退出码、`report.txt`、`terminal-output.txt`、执行期日志）。

## Implementation Decisions

### 一、信号只登记一次，两段只是状态位，信号层收进横切包

老版是两段两次登记：执行前一条兜底（收到就还控制台、`os.Exit(130)`），执行期换成 `signal.NotifyContext`，两段之间靠「先建 `NotifyContext`、再 `signal.Stop`」的次序完成交接。**新版不照这个形状搬**（ADR-0042）：登记从进程起来到退出只有一次，中途不撤。

| 段 | 覆盖范围 | 收场 |
| --- | --- | --- |
| 启动段 | 控制台摆正之后 → 状态位翻转那一刻（含解析、闸门、确认屏） | 还控制台、查表退 130、不建归档 |
| 执行段 | 状态位翻转那一刻 → 进程结束（**建归档目录这一步已归它**） | 取消 context；已开工的跑完照常上交；走完结算与报告，退出码 0 |

- 控制台摆正之后第一件事：登记 `SIGINT` 与 `SIGTERM`、建一个可取消的 `context`。这条登记活到进程结束，**不 `Stop`、不关通道、不重登记**——撤登记是唯一能让默认动作（当场杀进程）回来的时刻，设计里不设这个动作，也就没有交接窗口。
- 一个读信号的循环：读到先 `cancel()`，再看状态位。启动段调塔尖给的收场回调（还控制台、关日志、查表退 130）；执行段什么都不做——**重复按一律忽略**，这是老版既定行为（重复取消幂等），不加强杀档。
- 状态位在**建归档目录之前**翻转，也就是说「确认屏上按 Ctrl+C」归启动段，连归档目录都不建。
- 登记、判段、取消、忽略重复整段住一个横切包（`interrupt`）。塔尖只做三个动作：登记并拿到取消句柄、把取消通知递给执行站、在开跑那一刻翻状态位。塔尖不认识 `os/signal`、不认识 `syscall`；`context.Background()` 那处换掉。
- 退出码仍由 `exitcode` 一处换：启动段 `Interrupted`（130），执行段走正常收场 `Success`（0，节点有失败也是 0）。
- 启动段收场走塔尖那条 `finish`（关日志 + 还控制台 + 退出）；老版第一段只还控制台、不关日志，屏幕上没有差别。

### 二、中断这个事实由执行站写进纸，塔尖读纸

`ResultPaper.Interrupted` 这一格早就摆着，但没人填——结算站按它算「未执行」，于是永远算成 `false`。

**产出地定在执行站**：`Run` 收尾时按 `ctx.Err() != nil` 写一格。塔尖需要它（要打那句提示、要写日志警告），读纸上那一格。

为什么不照老版在塔尖自己算：老版那时没有这张纸，塔尖自己拿 `execCtx.Err()` 是最省的；现在纸上已经有这一格，两处各算一次就是同一个事实两个产出地。这条与「并发数按生效值由执行站带上纸」同一条先例（ADR-0035 末尾更新记录）。

### 三、两句报文补到建连与命令两条通道

判据表里「建连被取消」「任务已取消」各有两条关键词：一句工具报文、一句系统原文（`operation was canceled` / `context canceled`）。系统原文那句是**兜底**，配置注释写得很清楚——正常路径应由工具直接说清「中断在哪一步」。

阶段 05 已经给代填、改密、上传、下载四条通道写上了 `abort.canceled` 那句；**建连与命令两条漏了**：

| 中断在哪一步 | 报错原文该有 | 归到 |
| --- | --- | --- |
| 还没连上 | `sshfleet.abort.connect_canceled: interrupted while connecting` | 建连被取消 |
| 已连上、跑在命令中途 | `sshfleet.abort.canceled: interrupted after session established` | 任务已取消 |

- 两句都**接在原文之后**（原文在前、报文在后），与其余四条通道同一个次序。
- 建连那一支现在是「只置 `Cancelled` 标志、原文原样」，命令那一支是「只置标志」。补的就是这一句。
- 分类仍由判据表认领，判定层不按结构字段起名——ADR-0021 决定三那条没变。

### 四、那句提示：由 `message` 造，塔尖在统计块之前打

- 屏幕那句逐字照老版：`已收到中断信号，SSHFleet 停止执行（已完成节点的结果已写入日志/输出文件）`。它是使用者可见文本，因此**只能由 `message` 造**（契约里没有装字的格子），塔尖拿成品往 `console` 打。
- 日志那句也照老版：`收到中断信号，执行已停止`，**同样由 `message` 造**，塔尖拿成品走 `Warn`。先例是确认屏答否那句 `CancelTrace`——老版 `logger.Warn` 的原话收进构造点，塔尖只转手，不持字。
- 次序照老版：结算算完总账 → 执行期日志收尾那一行 → 屏幕那句 → 统计块。也就是说它排在统计块**之前**、日志收尾行**之后**，别插错位置。

### 五、停摆语义照搬，不重写并发池

取消之后的三条已经在新版的 `Run` 里写着（注释也有），本阶段**不改结构、只验**：

- 不再开新工（工作协程见到 `ctx.Done` 就退出循环）；
- 已开工的那台跑完照常上交——目标机可能已经被改过，结果丢了，统计里就变成「未执行」，把「回滚做没做」一起吞掉；
- 压根没开跑的那台不造行，只在总台数里以缺额出现。

边界如实记一笔：`select` 在选择「取下一台」与「看到取消」之间是随机的，所以取消的一瞬间可能刚好又开工一台。老版同一段代码、同一个随机，**不是差异**，也不为了确定性去改它。

### 六、阶段边界上的三件事

- **改动落在五处**：新增横切包 `interrupt`、塔尖、执行站、`message`，加上 `guard` 的两处检查本体（规则表多一行、塔尖符号表撤掉 `signal.Notify` 一格）。后两处属「单独点头」档——ADR-0042 已由开发者 2026-11-05 认下这套设计。**点头动工之前不建包、不动表、不动塔尖。** 包清单十七行变十八行、横切包八个变九个；不新增接缝；`execute.Run` 的签名不变（它本来就收 `ctx`）。
- **不动 `exitcode` 那四格**，中断的码本来就有一格。
- **新开 ADR-0042** 记这一处取舍（一次登记 + 收进横切包，取代老版两段交接）；`Interrupted` 的产出地从塔尖挪到执行站仍只记 `map.md` 框架条目一行——那是接线，不是取舍。

## Testing Decisions

- **接缝沿用 04／05 那六个，本阶段不加新接缝**：

  | 接缝 | 本阶段扩什么 |
  | --- | --- |
  | 塔尖的进程出入口 | 发 `SIGINT`：启动段一次（码 130、无归档）、执行段一次（码 0、归档齐全） |
  | 执行站的入口 | 递一张已取消的 `ctx` 的纸：纸上 `Interrupted` 为真；再递一张没取消的，为假。**两条都是新写的**——现有 `TestRunCanceledContextStopsAtOnce` 只断言了每台的 `Cancelled`，`Interrupted` 一格今天没人填也没人验 |
  | 判定那一处 | 两条 abort 报文各自认得出对应分类（喂固定原文，期望分类名写死） |
  | 报告站的入口 | 中断态的总账：统计块与 `report.txt` 都出「未执行：N」，`Verify` 为空串。两处措辞不同——统计块是「未执行：N」，`report.txt` 多一个后缀写成「未执行：N（执行被中断）」，照老版 |

- **红线区一条不加**：中断只改行为，不改纸的形状与流向。红线仍是 39 条；`exitcode` 那张表已有指纹，一格不动。
- **自定义区跟着被测包走**：`interrupt` 钉两条——启动段收到信号只调回调不取消、执行段收到信号只取消不回调，以及连着喂多次信号后只收场一次；`message` 加一个构造点的逐字断言；`execute` 用喂进去的 `ctx` 与固定原文钉两档；结算站那两条已有用例（`TestRunInterrupted`）不动。
- **「连按不退」的另一半靠真机**：ADR-0042 的第一项建立在「登记在册即关掉默认动作」这条运行时性质上，它是文档与源码结论、本仓库未实测。验收就是执行段连按五次 `SIGINT`，进程仍在、走完整收尾、退出码 0。这是新包的验证手法，不是新的接缝。
- **A/B 口径**：`build/` 下当天沙盒起新老两个二进制，同一份配置与清单、同一时序（`-n 1`、命令 `sleep 30`、起进程 2 秒后 `kill -INT`），比屏幕、退出码、`report.txt`、`terminal-output.txt`、执行期日志；归一化时间戳、路径、耗时、目录名里的秒级时间戳。**两侧必须从同一现场复位起跑**（05 的坑：先跑的那侧会改掉后跑那侧的现场）。
- **环境类失败不进两区**：容器没起、网络不通先修；修不掉就写明哪一步没法验。

## Out of Scope

- **第二次 Ctrl+C 强制退出**：老版没有这一档（重复取消是幂等的），本阶段不新增——执行段收到的重复信号一律忽略，进程照常把收尾走完。
- **Windows 上 `SIGTERM` 的差异**：老版按 `os.Interrupt` + `syscall.SIGTERM` 一起登记，新版照抄，不做平台分支。
- **两张 xlsx 与资源备份在中断后的形态**：随 07。
- **归档目录在中断后的完整性**（除 `report.txt`、`terminal-output.txt`、执行期日志这三份之外）：随 07。
- **`no_prompt` 一档与改密收尾另三句**：仍旧只有代码没有用例，不在本阶段补。
- **行为改动**：老版怎么跑新版就怎么跑。本阶段**没有已知差异**——`select` 的随机边界两边同源，不算差异。
- **老工程**：一个字不动。
- **约束类文件**：`docs/个人开发规范.md`、`AGENTS.md`、`docs/agents/` 一律不动。`guard` 那两处检查本体（规则表多一行、塔尖符号表撤一格）不在此列，按第六节走「单独点头」。
- **CHANGELOG**：本阶段不增条目（中断本来就是老版的行为，属重构进度）。
