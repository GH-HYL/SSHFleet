# 终端明细看不到目标输出 · 规格

Status: done（2026-10-22 收尾，真机验证已回，见 `findings-2026-10-20.md` §六）

## Problem Statement

用 Windows 连 iBMC 跑 `ipmcget -d health` 这类命令时，13 台全部「执行成功」，但终端明细里每台只剩「连接 / 执行 / 分类」三行，**命令输出是空白**；同一批运行的 `terminal-output.txt` 与两张 xlsx 里却字字都在。使用者看不到输出，只能事后翻归档，而终端上看起来像「没有输出」。

现成证据见 `findings-2026-10-20.md`：输出行尾带的回车被终端当成「回到行首」，那一行随即被擦成空白；归档文本不做解释，所以完好。

## Solution

**两处一起做，谁也不替谁。**

1. **采集侧定「行怎么断」**：CRLF 与孤立 CR 都归成 LF。归档、两张 xlsx、终端拿到的是同一份断好行的文本，不在每个去向各清一遍。
2. **终端明细再加一层保险**：到了呈现层仍会改写屏幕的控制字符（`\b`、NUL、`\v`、`\f`、DEL，以及万一又冒出来的 CR）换成看得见的写法（`␍`、`␈`…），制表符与换行不动。

## User Stories

1. 作为使用者，我要在终端上直接看到命令输出，不用事后翻归档。
2. 作为使用者，我要在输出里带了控制字符时看到它「长什么样」，而不是看到一片空白。
3. 作为使用者，我要 `terminal-output.txt` 与终端上看到的一致，不能一个有一个没有。
4. 作为使用者，我要行首缩进与中间空行照旧保留（`who -b`、`ls -l` 的排版不能被改掉）。
5. 作为维护者，我要「行怎么断」只在采集侧做一次，不在每个去向各清一遍。

## Implementation Decisions

- **断行归一在采集侧**：`Output` 是原始字段，采集完就是干净的。CRLF 与孤立 CR 归成 LF，再照旧去掉整块首尾的空白行。不引入「按行丢弃空行」——那会改掉输出结构。
- **控制字符可见化在呈现层**：`ResultLine` 是终端与 txt 共用的那一个函数，只在这一处替换，不散到各个去向。
- **替换而不是删除**：删掉就看不出「输出里原本有什么」，以后同类问题只能靠猜。
- **替换表只收会改写屏幕的那些**：`\r`、`\b`、NUL、`\v`、`\f`、DEL。制表符（终端按列宽展开正是想要的）与换行（已经归一好了）不收。
- 不改 xlsx 侧：它已有的清理照旧，现在等于对已经干净的文本再做一遍无害处理。

## Testing Decisions

测试打在两个**纯函数**接缝上，都不需要真机：

- 采集侧的整备函数（包内测试，先红后绿）：CRLF、多行 CRLF、行中孤立 CR、混用、行首 CR，各一条；既有 6 条用例必须照旧全绿。
- 呈现侧的 `ResultLine`（包外可见行为）：同一段输出在明细里显示成什么，并断言明细里不残留任何会让终端改写屏幕的控制字符。

## Out of Scope

- **CR 由 iBMC 的哪条指令产生**：不追——已验到这类命令的整段输出都带回车（`findings-2026-10-20.md` §六），而工具侧不该依赖源的形态。
- ANSI 颜色转义（`ESC[...m`）：它在终端上是正当用途，是否也要换成可见写法另行决定。
- 进度界面与明细的版面关系（本议题没有改动它，见 findings §4）。

## Further Notes

同一次运行里终端和 txt 对同一段字节的行为不一致，是这次问题难查的根因之一——**看到「文件里有」很容易误判为「渲染丢了」**。
