# 01: 远端回 CRLF / 孤立 CR 时，归档文本里不再残留回车

**要做的**：远端命令回 `\r\n` 或孤立 `\r` 时，`terminal-output.txt`、两张 xlsx 和终端明细里都只看到「断好行的文本」，不再有会改写屏幕的回车。行首缩进与中间空行照旧保留。

**被谁阻塞**：无，可立即开工。

**状态**：done（2026-10-20 实施）

- [x] CRLF 归一：`"System in health state.\r\n"` → `"System in health state."`
- [x] 多行各自 CRLF：`"a\r\nb\r\n"` → `"a\nb"`
- [x] 行中孤立 CR：`"第一行\r第二行\r"` → `"第一行\n第二行"`
- [x] 混用与行首 CR 同样归一
- [x] 既有 6 条用例（去首尾空行、保留行首缩进、保留中间空行…）照旧全绿
- [x] 本机字节验证：本机 `printf '第一行\r第二行\r'` 经 `--no-shell` 跑一遍，归档里 CR 个数为 0

## Comments

- 2026-10-20：先写的 5 条用例在改动前全红（`实际 "System in health state.\r"` 等），改后转绿。同时核了一遍：**常见退出码、日志里的错误详情、xlsx 的清理都不受影响**——它们都读同一个 `Output`，归一后只是不再夹 CR。
- 2026-10-22（真机验证）：四条命令 × 13 台，远端原始输出**台台都带回车**（CRLF 或逐行 CRLF），而交给终端的文本与归档 `terminal-output.txt` 的 CR 个数**全是 0**，屏幕上输出都在。这条工单的做法即为问题不再复现的原因——不是「终端那边容忍了」，是行尾根本没有 CR 可被解释。取证明细见 `findings-2026-10-20.md` §六。
