# 02: 终端明细里，会让终端改写屏幕的控制字符变成看得见的写法

**要做的**：即使某段输出里仍带了回车、退格、NUL，终端明细上也不再出现「空白一片、只剩分隔线」——这些字符显示成 `␍`、`␈`、`␀` 这类图示，使用者一眼能看出输出里有什么。制表符与换行照旧。

**被谁阻塞**：无，可立即开工（与 01 互不依赖：01 管「行怎么断」，这条管「终端别看空」）。

**状态**：done（2026-10-20 实施）

- [x] 孤立回车分隔的两段：`第一行␍第二行`
- [x] 行中回车、退格、NUL、`\v`、`\f` 都换成图示
- [x] 制表符保留（终端按列宽展开）
- [x] 明细里不残留任何会让终端改写屏幕的控制字符（测试里逐字符断言）
- [x] 既有 `ResultLine` 用例全部照旧通过（字段顺序、行首缩进、中间空行、未送出的代填）

## Comments

- 2026-10-20：先红后绿。端到端：改动前 `printf '第一行\r第二行\r'` 在终端只剩分隔线，改动后两行都在。
- 替换表刻意不含 ANSI 颜色转义——那是远端正当用途，要不要也换成可见写法，见 spec 的 Out of Scope，另行决定。
- 2026-10-22（真机验证）：四次运行里这条**一次都没触发**——最终交给终端的文本控制字符个数全是 0，01 那层已经把 CR 削干净了。所以它现在是**保险**，不是失效的死代码：采集侧漏了、或换了来源的字节流，靠它顶住。别因为「没触发」删掉它，理由见 `findings-2026-10-20.md` §五 与 `showControlChars` 上面那段注释。
