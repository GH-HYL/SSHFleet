# 规格：该复用却自造

**状态**：ready-for-agent（2026-11-13 分诊：割接前最后一刻已到——顺序议题已结，阶段 10 未开工）
**底本**：`docs/issues/2026-11-09-0945-切换前回顾审计/修复面盘点.md` §4.3、`audit-run-2026-11-09/回执/06-parse.md` §3 的 H1、本目录 `audit.md`（2026-11-13，11 条判据逐条三问）

## Problem Statement

老工程 `internal/common/` 里有一批**判据**（不是一个函数，是「什么算合法」这件事）：IPv4、单引号转义、字符宽度、`SystemReason`、解释器归一。它们一份定义、多处引用。

新工程把它们搬进各站时，出现了三种走法：

1. **紧的没搬、松的抄两遍**——IPv4 就是这样：老版 `netip.ParseAddr` 一处不剩，新工程两份手写副本，都不拒前导零。代价已经付过：`010.0.0.1` 老版拒、新版收下送进凭据预检（审计 06-H1，实跑）。
2. **自己重写一份，配一句假的自我背书**——那份手写的注释原文是「与老版同一条判据（旧版正则不校验每段范围，已修正）」，两句话都不成立：老版不是正则，而且拒前导零。
3. **工单里从来没要求自造**——`建站04` 的 06 号单只写「IP 必须存在且是 IPv4」，用哪把尺子没规定。

所以问题不是「不许自造」，是**自造没有理由，而老逻辑明明能直接搬**。没有理由的替换，代价就是一条条实跑才看得见的差异，以及一句没人能核实的注释。

## Solution

割接前把这一类逐条审出来：老工程里那些「一份定义、多处用」的判据，新工程要么照搬、要么写清为什么不能照搬。判据是「能直接搬就搬」，不是「一律不许自造」。

## User Stories

1. 作为维护者，我希望新工程里每一处替换老判据的地方，都有一条能核实的理由。
2. 作为审计者，我希望「与老版同一条判据」这句话由机器核，而不是由写它的人担保。
3. 作为维护者，我希望割接公告里「新工程是重写而不是糊弄」这句站得住。
4. 作为使用者，我希望 `010.0.0.1` 这类输入在新旧两版停在同一个门口。

## Implementation Decisions

- **先筛，不通读**：拿三份现成的料交叉——4.7 的 `docs/issues/2026-11-10-1720-老新交集收全/audit.md`（交集 48、逐字同体 20）、老工程 `internal/common/` 的符号清单、新工程里同名或近义的自造判据清单。
- **每条只问三件事**：老的那份是什么（哪把尺子、紧还是松）、新工程里现在是什么、为什么不是直接搬。第三问答不出，就记成「无理由自造」。
- **「同一条判据」必须可核**：凡是注释里写了「与老版同一条」「同源」的，抽出来单独对一遍——06-H1 就是这句话说反了。
- **处置只有两种**：搬回老逻辑（多数情况）；或写进 ADR 说明为什么不能搬（例如老那把尺子依赖老包的形状）。
- **不新建包**：合并成一处归 `4.3 判据叶子包`（另一个议题，要改锚）；本议题只负责把「哪些该搬」查清楚、把能搬的搬完。

## Testing Decisions

- 接缝是进程出入口：每条搬回去的判据，用同一句输入跑新旧两版，比屏幕——这是 06-H1 抓差异用的同一手法。
- 不新增单测门类；搬动的那几处用它所在包既有的自定义区测试兜。

## Out of Scope

- 判据叶子包本身（`4.3`，要改锚、要 ADR）。
- 报告站／交互屏那些「逐字搬移」的处置（4.7 的表里已给意见）。
- 老工程本身的修改（A9 冻结）。
