# 改密（批量）· 规格

Status: done

**闭环说明（2026-10-08 复核）**：已实施。`--change-password` 随 `8.0.0` 上线（工单 01–05 全部 `resolved`，见 `docs/adr/0011`）。提示词表的实际文件名为 `config/keywords_passwd.conf`（本文写作 `config/passwd_keywords.conf`，实施按仓内命名落地）。真机实测（2026-10-08，非 root 账号）：未过期账号 → 分类「密码未过期」。

## 一、入口与参数（已定）

| 事项 | 结论 |
| --- | --- |
| 入口 | `--change-password <密码>`，**无短选项**（低频使用，2026-09-28 定）；作为执行模式与 `-c`/`-s`/`-u`/`-d` 互斥（**五选一**） |
| 取值语义 | 随配置 `credential.encrypt`（与 `password` / `key_password` 同构）：`false` = 新密码明文；`true` = 新密码密文文件的绝对路径。走现成的 `credential.ReadCredential(值, encrypt, true)`，**不做**「文件还是文本」的自动判定——明文密码可能恰好等于一个存在的文件名，自动判定会把密码当文件读，报错完全指不到真原因 |
| 新密码 | 全局一个值，全部机器改成同一密码；答案因机而异时由运维分批（与代填同一纪律） |
| 当前密码 | = 清单里那台机器的登录密码。实现从 `ssh.Config.Password` 取（`batch.newConfig` 已装载），**不另传一份**，也不进提示词表 |
| 允许共存 | `-f`（必填）、`-n`、`-t`、`-T`、`-r`、`--yes` |
| 互斥 | `-c`/`-s`/`-u`/`-d`（五选一）、`-a`、`-p`、`-k`、`--no-bash`、`--sudo`、`--no-sudo`。`--sudo`/`--no-sudo` 不留余地：改密走登录用户自己的密码，与执行身份无关（2026-09-29 定）。`-k` 的互斥理由：改密场景密码认证本来就能连上过期账号，支持密钥登录徒增字段校验与边缘场景（2026-09-28 定） |
| 模式名 | `cli.Args.ModeName()` 返回 `passwd`；归档目录名 `<时间>_passwd`（备注默认为空，`-r` 照旧可用）。英文，不用中文（2026-09-29 定） |
| 留痕 | 日志、报告、参数屏里的新密码一律 `common.MaskSecret`（前 2 + `****` + 后 2，≤4 位整段 `****`）——**明文密文都脱敏**（2026-09-29 定）。注意 `common.MaskCommandLine`（`main.go` 的「原始选项/参数」那行）现在只认内联清单这一种形状，**必须扩一条按旗标名的规则**（`--change-password` 与 `--change-password=X`），否则新密码原文落进工具日志 |
| 归档 | 改密的值即使是凭据文件，也**不**拷进 `assets/`（2026-09-29 定）：留一份密文密码没有复盘价值，只多一处暴露面 |

## 二、提示词表（配置文件，2026-09-29 定）

`-f`/`-a` 之外**新增一份配置文件** `config/passwd_keywords.conf`（TOML，随发布包提供，与
`error_keywords.conf` 同待遇：缺失即报错）。表的用途是**认出远端在问什么**，因此只配两样：
提示原文、这条该喂哪个值（`current` = 清单里的登录密码 / `new` = 新密码）。**值本身不进配置**。

```toml
[[step]]
keywords = ['当前的密码', 'Current password', '(current) UNIX password']
value = 'current'
max = 1

[[step]]
keywords = ['新的密码', 'New password']
value = 'new'
max = 4

[[step]]
keywords = ['重新输入', 'Retype']
value = 'new'
max = 4
```

- **可配置的理由**：提示文案随目标机语言与 PAM 版本变，撞到新措辞时要能当场补一条，不必等发版。
  **这份文件是为调试方便的过渡形态**——跑稳之后多半写回程序里写死（2026-09-29 定）。届时决定
  留不留配置，别现在就按"永久配置项"来设计。
- 入场信号**不在本文件配**：取 `error_keywords.conf`「密码过期」分类的关键词。两处同时能配就是两份真相（2026-09-29 确认）。
- 匹配口径（正则 / 大小写）随 `SSHFleet.conf` 的 `[interactive]` 段，与代填、中止词同一套开关。
- 「改密成功」的完成信号（远端打印 `已成功更新密码`）**评估过不加**：实测 M3 改完会话直接结束，
  后面没有可喂的对象，多一条关键词只增加一个要维护的真相源。

## 三、匹配与喂入（2026-09-29 定）

| 事项 | 结论 |
| --- | --- |
| 匹配器 | **新写一个改密专用的**，只复用 `keywordRule`（`internal/ssh/matcher.go`）。**不动 `cursorMatcher`**——它是"一条规则只送一次"（`feed` 里命中即 `done`），代填那条路刚验收过，不该为一个新语义去改共用件 |
| 入场信号 | **作真门**：没出现过期信号之前，三条提示规则不参战。实测 M2/M4：警告行第 0 秒出现，必然先于「当前的密码」，做门是白拿的一层保险 |
| 消费上限 | 每条 `step` 各自带 `max`，默认「当前的密码」1 次、「新的密码」「重新输入」各 4 次。远端重问就再喂一次，喂满即止 |
| 上限的定位 | **护栏，不是成功判据**：用不满不算失败（root 改密不问「当前的密码」，那一条从不被消费，结果照旧判成功）。一条 step 只有**一个值**，所以重喂永远是同一个值——它的价值是「远端重问时还能把答案再送一次」（时序容错），**不是**「换个更强的再试」（2026-09-29 定，见 B7） |
| 无话可给即收场 | 某条已喂满的提示**又出现**了 = 给出去的答案它一个都没收 → **立刻终止该节点会话**，不干等到 `-t`（2026-09-29 加，见 B5） |
| 会话形态 | PTY 200×50 + `:`（shell 内建的空命令，只为让 PAM 走完会话建立流程——改密对话发生在命令之前，命令是什么不影响它） |
| 中止词 | 改密分支**绝不传** `AbortKeywords`：那几条关键词在这里是入场信号，带上它会把自己的会场当第 0 秒终止掉（方向与代填恰好相反，最容易踩的一处） |
| 超时 | 不另立交互专用超时，全靠 `-t`（默认 `execution.timeout_execute`） |
| 长度检查 | 不需要：下发行是固定的 `exec :`，远不到 122880 上限 |

## 四、结果判定（已定，无验证步骤）

| 会话结束形态 | 判定 | 呈现 |
| --- | --- | --- |
| 输出从未出现「密码过期」信号（未过期机器） | 跳过改密 | `error` 写固定句「密码未过期，跳过改密」，退出码置 `nil` → **计入失败数**（2026-09-28 定） |
| exit 0 且出现过期信号 | 改密成功 | 退出码 0 照旧 → 归「执行成功」，不新立成功分类 |
| exit 非 0 / 早收场 / `-t` 到点 | 改密失败 | `error` = **远端最后说的那几句非提问行**（最多 3 行，只取「最后一次喂入之后」那一段，跳过密码回显的脱敏占位行），退出码**一律置 `nil`** → 分类由 `config/passwd_keywords.conf` 的 `[[category]]` 认（「写不进密码文件」「旧密码不对」「新密码不合规」「密码文件被锁定」「PAM 配置出错」「SELinux 拦截」「改密没有权限」「账号不允许改密」「改密太频繁」） |
| 远端一句原因都没给 | 失败 | `error` = 工具三句兜底文案之一（前缀统一是「改密没有完成」：「提示没认出来」/「反复重问」/「收下密码后不回应」）→ 兜底分类「改密未完成」。**这批改密分类整批插在通用判据表最前面**（装配层 Prepend，见 `config/passwd_keywords.conf`），不必再操心与「密码过期」的先后 |

- **未过期机器补一条 conf 分类**（2026-09-29 定）：走兜底原文的话，分类名会是 `error` 原文，
  且 `IsFallbackCategory`（`internal/result/classify.go`）判它是"未归类"，统计末尾会多一句
  「把特征词补进 conf 就能单独归一类」——在这里是误导。补 `[[categories]]`：
  `name = '密码未过期'`、`keywords = ['密码未过期，跳过改密']`、tip 写清这是预期。
  这只修分类名与提示，**不改「计入失败数」这条裁定**。
- **验证步骤已评估并省去**（2026-09-28）：成功 = exit 0 在 M2 与 T2（含弱密码救回）两次实测成立；
  失败 = exit 10（T1）+ 报错文本进 error。退出码是 sshd/PAM 的权威信号，与工具"只认退出码"的
  既有体系一致；验证的收益（防"exit 0 但实际没改"）没有实测反例支撑其成本。

## 五、-t 管辖（已定）

`-t` 是客户端本地计时（`context.WithTimeout` + Go 协程 + 到点 `session.Close()`），不是 SSH 协议
超时——改密会话沿用同一套，管「激发 → 对话 → 喂入 → 结束」的总时限；连接阶段照旧 `-T`。

## 六、实测记录（2026-09-28，172.28.118.49，Ubuntu 26.04 / WSL2，UsePAM yes）

| # | 场景 | 结果 |
| --- | --- | --- |
| M2 | 正常改密 | 对话完整出现（当前的密码 → 新的密码 → 重新输入新的密码 →「passwd：已成功更新密码」），固定节奏喂入成功，exit 0 |
| M3 | 改密完成后 | 原命令不执行，会话直接结束——改密与执行是两次运行 |
| T1 | 旧密码错 | 不重问，报「passwd：认证令牌操作错误」「passwd：密码未更改」，**exit 10**，喂入后约 2.4 秒会话结束 |
| T2 | 弱新密码 | PAM 拒（「您必须选择更长的密码。」）后**重新问「新的密码：」**，改喂强密码成功，**exit 0**——喂入自适应的实测依据 |
| M6 | 回显 | 密码输入全程不回显（passwd 关回显），不进输出与归档 |
| M10 | 提示文案 | 跟随目标机语言（该机中文）；首个提示不带换行。喂入为匹配驱动，双语提示词覆盖 |

**2026-09-29 真机复测（172.28.118.49，Ubuntu/WSL2，UsePAM yes）——实施后当场跑出来的四条：**

| # | 场景 | 结果 |
| --- | --- | --- |
| M2′ | 真机改密（root，先 `chage -d 0 root` 置过期） | 跑通：「WARNING: Your password has expired.」→「新的密码：」→「重新输入新的密码：」→「passwd：已成功更新密码」，退出码 0，归「执行成功」。连做四轮（A⇄B 来回改）全成功 |
| M2″ | 密码没过期的机器 | 归「密码未过期」并计入失败数，tip 正确显示——未过期这条分支的真机证据 |
| B1 | 曾用 `exec :` 作下发行 | **不可用**：bash 的 `exec` 不认内建命令 `:`，报 `exec: :: 未找到`、退出码 127，把改密结果搅成「执行失败(退出码127)」。下发行改为 `:` |
| B2 | **回显时机竞态（安全）** | `passwd` 关回显的时机在远端：我们写进去的字节可能落在它关掉之前被终端**原样回显**，实测到一次——**新密码整行出现在归档的 `terminal-output.txt` 里**。修法：喂进去的凭据（登录密码与新密码）一律从采集输出里抹掉，不指望远端 |
| B3 | root 改密**不问**「当前的密码」 | 该步永不命中，`max=1` 一条从未被消费，结果照旧判成功——真机证据支持「上限是护栏不是判据」 |
| B4 | 本机 PAM **不校验密码强度** | `--change-password abc` 被接受（root 走 pam_unix，该机没挂 pam_pwquality/cracklib）。所以「弱密码被拒、重问后救回」这条**在本机复现不出来**，仍需找一台开了强度校验的目标机验（工单 03 的验收条件） |
| B5 | 新密码被拒 + 远端反复重问 | **修前**：白等满 `-t`（60s），且分类被服务端提示里的「密码过期」抢走（第一组判据里「密码过期」排第 6、「执行超时」排第 11，而服务端那句提示会被 `applyBanner` 追加进 `error`）。**修后**：0.30s 收场、`error` = 「密码未被更改。」、分类「密码修改失败」、tip 正确 |
| B5′ | 早收场那条事件不带文本，收尾却还在按「文本非空」判中止 | 结果把失败当成了**正常退出**（退出码 0）→ 报成「成功」。修法：`interactiveOutcome` 加显式的 `aborted` 字段，判中止看它 |
| B6 | 非 root 账号改密 | 四步全中：当前的密码 → 新的密码 → 重新输入新的密码 → 已成功更新密码，退出码 0。**root 改密不问旧密码**，所以「当前的密码」这一步只能用普通账号验 |
| B7 | 「弱密码救回」在现设计下不可能 | 一条 step 只有一个值：新密码被拒后只能把**同一个值**再喂几次，9-28 的 T2（先喂弱、再改喂强）复现不了。要真救回，得让一条 step 挂多个候选值，而那要求用户给出第二个新密码——没有意义。故：上限的作用是时序容错，不是强度救回 |

无 PTY 时同一场景为「密码过期」拒绝（`docs/issues/2026-10-12-1150-远端交互代填/spec.md` M1）——本功能必须分配 PTY。

## 八、实施纪律与收口（2026-09-29 补，无剩余未决项）

- **版本号 = `7.1.0`**（次版本）。不兼容判定：用户自己编辑的 `SSHFleet.conf` 没有新增必填字段，
  提示词表属于随包提供、用户不维护的那类文件（与 `error_keywords.conf` 同待遇）。CHANGELOG 开
  `## [7.1.0] - <实施当天>`，与入口常量 `main.go` 的 `appVersion` **在同一次提交里同步改**。
- **结合主干**：本次是往既有主干接入一条新执行模式——能在既有结构里接入的就在既有结构里接入
  （`cli` 的校验骨架、`batch` 的 `task` / `work()` 分发、`output` 的呈现入口，都按现有形态各加一路）。
  可以开分支，但分支要**从主干切出、回到主干**，不留长期并存的两套实现。
- **优先复用**：`connectFor` / `applyBanner` / `lockedBuffer` / `trimOuterBlankLines` /
  `extractExitCode` / PTY 尺寸常量 / 写侧钩子去 `\r` 的手法 / 超时与中断包装的契约，一律照用。
  **不复用**的只有代填的匹配器与收尾判定（语义不同，理由见第三节）——这是有意的例外，不是漏掉。
- 取值形态（已定）：`credential.encrypt = false` 时 `--change-password` 后面直接写**明文密码**；
  `true` 时写**密文文件的绝对路径**。参数本身就是密码，不做"文件还是文本"的自动判定。
- 它的值**不参与**路径规范化与空格禁令（密码可含空格；不得混进 `internal/cli/args.go` 的
  `pathWithoutSpace` / `normalizePath` 循环）。
- `--change-password` 纳入 `batchParamsGiven`（与密钥管理命令同理）。
- 新密码密文文件的生成：走现有 `--convert-secret` 链路（运维写明文文件 → 转密文 → 路径给
  `--change-password`），工具**不**新增加密入口。

     是改密的**前提**（它就是入场信号），不是失败原因，混进去会把分类带成「密码过期」→ 改密走到对话之后不再并 banner
     （会话没走起来时照旧并，那是账号过期/登录被禁唯一的原因来源）。
  3. **原因提取范围太宽**：原来从整段输出里找「最后一行非提问行」，会捡到警告行与密码回显 → 改成只取
     「最后一次喂入之后」那一段，并跳过脱敏占位行 `****`。`passwd` 常把根因与结论分两句说
     （实测「认证令牌操作错误」＋「密码未更改」），所以最多带 3 行。

  另一进程占住 `/etc/.pwd.lock` → passwd **静默等待**（不报 `cannot lock`）→ 20s 超时 → 「改密未完成」。
