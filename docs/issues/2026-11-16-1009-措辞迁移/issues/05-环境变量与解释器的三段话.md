## Comments

**2026-11-16**：新增 `internal/message/config.go`——十个入口，一个错一处。`internal/parse/config.go` 的 `validateEnv` 与 `validateInterpreter` 只剩「判哪一条错了、把名字与原值递过去」。

四处判断：

- **三段由老构件拼**：整段仍用 `Problem`／`ProblemHint`／`CurrentValue` 那三个现成入口，换行、「原因：」「提示：」的版式一个字没重写——所以字节风险只剩抄字这一项。
- **`%q` 收成一个 `quote`**：原值那几处要「括起来、转义」的形态，`fmt.Sprintf("%q")` 与 `strconv.Quote` 同源；十个入口里八处用它，写一次。
- **后缀重复那条不进探针**：它靠遍历 map 挑出重复的两个键，先后由 map 顺序定，改前改后都可能翻——两次跑出来的句子里两个名字可能对调，比对不出真差异。它只有一格格式串，逐字对着抄。
- **`normalizeConfigPath` 那族没动**：它也是「哪里错 → 为什么 → 怎么改」，但不在本单点名的十处里，见下。

**字节证据**：`build/05_probe_2026-11-16/` 下 `old.txt` 与 `new_raw.txt`——同一支探针（九个坏配置：env 两条、command 两条、script 五条）在 `HEAD` 的临时工作树与本工作区各跑一次，九段输出 diff 为空（只差耗时行）。探针只落 `build/`、用完即删。

**还剩什么（不在本单，需开发者定）**：`parse/config.go` 里另有八处仍在替 `message` 填中文——

- 解析 TOML 失败那句的提示（「多数是引号或方括号没配对…」）
- `[paths]` 段、`[execution.env]` 段两句
- 「含未识别字段」「缺少必填字段」两句的提示
- 「这个位置没有配置文件」那一屏（三行正文 ＋ 提示）
- 字符串值要带引号那句的提示
- `normalizeConfigPath` 那一族：四句「哪里错」＋四句「为什么」＋`，例如 <路径>` 那个拼法

本单的判据只对点名的十处成立；上面这八处要清掉才能说「配置那一屏的字全在 `message`」。
