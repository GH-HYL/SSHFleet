## Comments

**2026-11-16**：`message` 新增两个文件——`toml.go`（词法器那五句 ＋ 配置那屏的头一句 `TOMLParseFailed`）、`tables.go`（判据表的「出处」一句）；另在 `message/nodelist.go` 补了 secret_dir 那句。

四处判断：

- **`toml.go` 收成一个带货的死值类型**：`tomlProblem{kind, line, key, section, arrayItem}`，`Error()` 只把句子转手给 `message`。它实现 `error` 不是要自己说话，是为了让调用点照旧 `if err != nil`、`err.Error()`，也让 `config_test.go` 那条 `strings.Contains(err.Error(), "写了两次")` 一字不改仍绿。
- **类别不出站**：没往契约里加类型。契约是站与站之间递的纸，词法器的毛病在 `parse` 内部就被读成一句话，跨不到别处；加进去还得动 `guard/paper.go` 的裸 `string` 名单。
- **`readFailure` 是删不是迁**：全包只此一处定义、零调用，而它要说的那句「读取内容时发生错误: 」`message` 早在 `CannotStartManifestRead` 里有一条，两处各写一遍正是它自己注释里要防的事。
- **`atoi` 两条没迁**：错误值只当布尔用（`if err != nil || n < 1`），屏上从不出现；按规格「`message` 只收屏上的字」不迁，要迁也只是给 `message` 添两条不显示的模板。**开发者 2026-11-16 裁定不搬**，本单结案。

**「出处」那句与判据钉在一起**：六个键的判据是本包 `dangerRuleKeys`（从 `unknownRuleKeys` 里提出来的一格），句子住 `message.DangerRuleKnownFields`——两处各一份是划界的代价（字归 `message`，判据归站）。`TestDangerRuleKnownFieldsCoverEveryKey` 把两份钉住：加第七项时它先红，屏上就不会继续说「六项」。

**字节证据**：`build/03_probe_2026-11-16/` 下 `old.txt` 与 `new_raw.txt`——同一支探针（六种坏 TOML、配置那屏、危险规则表那屏、secret_dir 那句）在 `HEAD` 的临时工作树与本工作区各跑一遍，九行输出 diff 为空。改前那份取自 `git worktree add --detach … HEAD` 的干净检出，探针只落 `build/`、用完即删，包里没留临时文件。没进探针的两条：错误分类表与改密表的 `CannotStartTableParse`——它们与危险规则表走同一行 `Origin: err.Error()`、同一个模板，故只取一条代表。
