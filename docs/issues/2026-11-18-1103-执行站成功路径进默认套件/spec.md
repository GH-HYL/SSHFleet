# 规格：执行站的成功路径进默认套件

**状态**：done
**底本**：ADR-0037（红黑两区与接缝）；上一议题 `docs/issues/2026-11-17-1230-架构复查落地/spec.md` 的 Testing Decisions。

## Problem Statement

默认套件里没有一条路能走到「连上、跑完」。

执行站的用例全占一个端口再让出来，拨过去必然被拒；收口那一段有一条自己的用例，但它只测那个函数本身，不测谁在调它。于是 `go test ./...` 里，执行站从来没有真的执行过一条命令、传过一个字节——改坏了连接、认证、会话、sftp 任何一环，只要没编译错，默认套件照样全绿。要走真路只有 `//go:build integration` 那批，而它要一台真机器。

## Solution

测试进程里起一个真的目标机。本机监听一个端口，握手、执行命令、读写文件都按协议真做，文件系统就是这台机器上一个临时目录；用例从执行站的入口 `Run` 进去，跑完一趟命令、一趟上传、一趟下载，读它交回的纸与终端输出档案，确认每一台的成败、输出、文件数与字节数都是真跑出来的。生产代码一行不改。

## User Stories

1. 作为维护者，我要在没有真机的情况下让一趟上传跑完，这样改完执行站我能立刻知道它还能不能跑。
2. 作为维护者，我要一条命令从入口跑到收尾，这样连接、认证、开会话这几环断了都有人报。
3. 作为维护者，我要上传与下载各跑到真文件上，这样 sftp 那一路断了不靠真机也能看出来。
4. 作为跑上传的使用者，我要终端输出档案里那一行与纸上的成败是同一件事，这样我事后对账不用猜。
5. 作为维护者，我要假目标机只做命令、上传、下载三件事，这样它不会长成半个远端系统，也不用维护改密与代填那套提示回放。
6. 作为复审的人，我要知道假件为什么不住红线区、也不必占替身插口那一格，这样下一个人不会把这两条重新提一遍。

## Implementation Decisions

**一、接缝只有一个：执行站的入口 `Run`。** 不放新接缝，不加参数、不改签名。用例给 `Run` 一张普通的运行纸，让它在纸里指定的地址上真的连上一个进程内的目标机。

**二、不造替身插口。** `*ssh.Client` 与 `*sftp.Client` 都是具体类型、伪造不了；但不必伪造——在测试进程里起一个真服务端，被测的仍是原来那条路。ADR-0037 决定三留给执行站的「一个类型」继续空着。

**三、假目标机住自定义区，与执行站的用例同包（一个 `_test.go` 文件）。** 它不被红线区引用，也不引用红线区，ADR-0037 决定六「不许共用假件包」不触发；不新增包，包清单仍是十九个。

**四、协议真做，不模拟。** 服务端用 `golang.org/x/crypto/ssh` 的服务端接口，文件系统走 `github.com/pkg/sftp` 自带的那份服务端；两个库都在现有的直接依赖名单里，不新增依赖。远端路径由用例拼成 `/C:/…` 这种带前导斜杠的绝对路径，服务端按平台规则落回临时目录。

**五、射程：命令、上传、下载。** 上传只走普通路径（不碰 sudo 那条）；下载同理。改密与代填要 shell、PTY 与几句提示的回放，那是另一件事，本轮不做。

**六、断言只碰纸与落盘的档案，不碰内部。** 用例读 `Run` 交回的纸与终端输出档案（`Landings.Terminal` 那份），不断言「内部调了几次」「哪个函数被调过」。

**七、不拿「屏上的完成台数」当验收。** 非终端下 `screen` 直接退化成直通（`progress.go` 的 `transfer` 开头就返回），面板在 `go test` 里根本不渲染；拿它当验收就得往入口塞一个屏幕出口，那是另一轮的账。那一路今天的守卫是同包的收口单元用例（`close_node_test.go`），它测的是「收口有没有把结果交给聚合器」，缺的那一环留在 Out of Scope。

## Testing Decisions

**接缝：`Run`，一个。** 假目标机自己的可用性单独一条用例（起服务、执行命令、sftp 放一个文件再读回来），先绿了再往上搭。

**反证要跑一次。** 把假目标机的监听关掉（或把它的地址换成一个没人听的端口），用例要红——这证明用例真的连的是它，而不是在空转。写进对应工单的 Comments。

**既有先例**：`internal/execute/close_node_test.go` 已经测过收口函数本身；本轮补的是「成功路径真的跑得通」，两者不重复。

**跑法**：`go test -count=1 ./internal/execute/`，全量另跑一次。

## Out of Scope

- **「谁在调收口」这一环。** 默认套件观测不到面板（见 Implementation Decisions 第七条），要守住它就得给入口带一个屏幕出口，属改入口形状，另起一轮并写 ADR。（已另起：`docs/issues/2026-11-18-1430-面板守卫/`，决策见 `docs/adr/0061`。）
- **改密与代填的成功路径。** 要远端 shell、PTY 与提示回放，假件会变成半个远端系统。
- **sudo 上传与下载。** 要走远端 shell 语义，本轮只保普通路径。
- **替身插口与两个适配器。** 见 Implementation Decisions 第二条。
- **真机集成用例。** `//go:build integration` 那批不动。
- **面板的视觉。** 颜色、清屏、帧率不在断言范围。

## Further Notes

- 上一份规格写过「不新造假 sshd、不加替身插口」，那时只修接线、砍的是规模。条件变了：现在要的是「执行站改完之后还能不能跑」，所以反转这一条；反转的理由写在本规格，不再开 ADR——ADR 的三道门槛（难回头、没上下文会困惑、真做过取舍）都不成立：假件住测试文件，删掉即回滚。
- `internal/archive` 的 `TestCreateLatestLinkPointsAtNewest` 在 Windows 上偶发 `Access is denied.`（建符号链接没权限），与本轮无关。
