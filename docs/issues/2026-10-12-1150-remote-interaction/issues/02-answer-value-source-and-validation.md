# 02: 代填值的来源与合规

Status: done
Blocked by: 01

**要做的**：`-a` 的值补齐两种来源，并把门控与长度上限落地。

来源判定照 `-f` 的先例：先 `os.Stat`，文件不存在再按形态判——含逗号即内联、不含逗号报「文件不存在」。判定结果存进 `cli.Args`，执行侧直接用，不两处各判一次。CSV 文件一行一条、与内联同构（第 1 列代填内容、第 2 列起触发词、列数自适应），空行与 `#` 开头跳过；文件与内联可混用，条目顺序即命令行给出顺序。CSV 逐行解析写在新文件里，不复用按节点为单位的清单读取器。

同在这一处（参数合规检查）做：每条至少一个触发词；代填内容与触发词都不含逗号；最终下发行字节数 ≤ 122880（阈值写死，仅 `-a` 运行检查），错误文案同时报原文大小。下发行由交互分支自己的构造函数单点生成，长度检查与实际执行同源。

**边界**：`-a` 的值不进 `Parse` 里那段路径参数循环——含空格不报错、不做路径规范化、不做 `\`→`/`。

- [ ] 内联 / CSV 文件 / 两者混用 三种给法都跑通，顺序与命令行一致
- [ ] 一条代填没有触发词 → 报错；代填内容或触发词含逗号 → 报错
- [ ] 超限在本地参数合规阶段退出，文案含原文大小；普通路径不受长度检查影响
- [ ] 含空格的触发词（如 `1,请 选择 架构`）正常通过
- [ ] `go vet ./...` 干净、`go test ./...` 全绿
