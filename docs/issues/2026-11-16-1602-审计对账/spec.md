# 规格：审计 110 条对账

**状态**：done（110 条：已办 58、判留 51、在 1；在的那条是 06-J3，要真机）
**底本**：`docs/issues/2026-11-09-0945-切换前回顾审计/audit-run-2026-11-09/报告.md` §2.5（全量发现单 110 条）＋ §2.6／§7；判定表 `docs/issues/2026-11-16-1449-架构取舍判定/spec.md`
**判据**：**落在代码上**，文档只当线索。审计那一句话是 2026-11-09 的现场，今天的结论以实测为准——`04-J5`「已办却记成没办」那种事，这一轮先查了一遍。

## Problem Statement

审计留了 110 条；判定表只盖住其中「只是架构取舍」的 39 条；此后五个议题（红线区第二轮、该复用却自造、判据叶子包、规范债测试侧、措辞迁移）与更早的六个（契约装字、检查器自反、比对口径收紧、切换前七处修正、老新交集收全、检查器按语义补判据）各盖了一部分。**没有人把这些加回去重算过**——手里只有 `修复面盘点.md` 那份「没盖住 103 条」，它写在任何一个议题之前，早就不作数。

后果不是数字难看，是**不知道有没有条目被静默丢掉**：切换之后没人再翻这份审计，漏掉的那条就永远漏了。这一刀是切换前该补的最后一遍账。

## Solution

逐条标三种结论之一，**一条一判、给落点**：

- **已办**——写清是哪一笔提交／哪一张单／哪一条 ADR；
- **判留**——写清代价，落在本表里（这是它唯一的存档处，不另开 ADR）；
- **在**——真剩下的，写清谁接，拆成工单。

「判留」的口径照判定表先例：单条代价不够格开 ADR，整批记在表里；读者是维护者，写清「留了以后会发生什么」就够。
