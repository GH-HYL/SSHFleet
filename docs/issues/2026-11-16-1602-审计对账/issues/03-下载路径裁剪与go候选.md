**2026-11-16 复核结果（没有真机，落在源码上）**：老版 `internal/cli/args.go:440-450` 只在 `a.Upload != ""` 时裁 `-p`，注释是明写的——「本地的 -p（下载模式）不在此列——本地路径一个字节都不动」。新工程 `parse/argv.go:228` 无条件裁。**两条对得上，审计那条成立。**

**但「改回不裁」不是一行**：`parse/material.go:80-90` 的本地目录自检读的就是纸上那格（注释还写着「纸上的值是去过首尾空白的」），去掉裁剪之后，`-p "out "` 那种多打一个空格的写法会变成 `os.Stat("out ")` 失败、当场「目录不在」起不来。老版没有这道自检，所以照搬 TrimSpace 的口径要连自检一起改，而改完就变成「照老版一起照搬这个坑」。

**两条路**：
- **照搬**：`-p` 不裁，自检跟着用原值。与老版逐字一致，代价是 Linux 上会老老实实建一个带尾空格的目录。
- **认下**：保持裁。多打空格被宽容（本意几乎总是那个不带空格的目录），代价是与老版在畸形输入上不一致——审计把它记成「行为变了」，这一判就归「认下」那一栏。

**2026-11-16 裁定：认下。** 理由两条：`06-H2`（`-f <目录>` 的报错口径变了）当时就是「认下，只登记不回改」，同一把尺子；而且照搬要连 `material.go` 的自检一起放宽，放宽之后 `-p "out "` 仍然被吃空白——等于白改。开发者补了一句判断：首尾的空格与回车本来就是笔误，吃掉不影响结果。确实如此——`strings.TrimSpace` 去的是 Unicode 空白（空格、`\t`、`\r`、`\n`），从 Windows 复制粘贴带进来的 `\r` 一并去掉；留着它，Linux 上会建出一个名字里带回车的目录，那才是真影响结果。
