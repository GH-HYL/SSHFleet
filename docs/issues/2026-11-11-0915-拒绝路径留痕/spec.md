# 规格：拒绝路径留痕

**状态**：已完成（done）——2026-11-11 落地，`go test ./...` 十七包全绿，`a3-unknown-option` 重跑一致
**底本**：`docs/issues/2026-11-10-1615-比对口径收紧/issues/07-收口复跑.md` 第四节（复跑的卡点）
**边界**：只补「拒绝时也落一条工具日志」。屏上那句话、退出码、拒绝的判据一律不动；4.2 的出口收口不在此列。

## Problem Statement

新版塔尖只有两条收场：`fatal`（起不来）与「拒绝」。`fatal` 里 `lg.Fatal` 落盘，屏幕末行报一句「日志：<路径>」；拒绝那条路只打屏、**一个字都不写日志**——而它的屏幕同样报着「日志：<路径>」。于是使用者按屏幕去翻日志，翻不到这次失败。

11-10 的 `a3-unknown-option` 实测到的就是这一处：同一个 `--nope`，老版工具日志尾部有一行 `[cli] 选项/参数解析失败：不认识的选项：--nope（使用 -h 查看帮助）`，新版没有；屏幕与退出码两侧一致。

这不是一行的疏漏：`gate.Run` 里 `return refuse(` 有 29 处，覆盖「认不出的选项／缺值／多余参数／模式零个或多个／搭配不合规／取值不成／危险规则拦下」整族。老版这一族全走 `fatal`（`SSHFleet_Go/main.go:267` 与 `:314`），条条落盘。

## Solution

让「拒绝」像「起不来」一样交两格话：一屏给当场看（`Say`），一行给事后翻（`Trace`）。塔尖在拒绝分支把 `Trace` 交给日志包，正文为空则不落——「使用者自己答否」不是失败，老版在 `ErrCancelled` 那条路上也是直接退。

## User Stories

1. 作为使用者，我在参数写错时看到屏幕上「日志：<路径>」，去那份日志里要能翻到同一次失败。
2. 作为维护者，我拿到一份 `SSHFleetTools.log`，要能看出这次是「没跑起来」还是「被闸门拒了」，而不是只知道跑过。
3. 作为维护者，我不希望为了这条留痕在塔尖拼句子——话只从 `message` 出。
4. 作为维护者，我不希望闸门抓着日志句柄：它只交事实，落盘是塔尖的活。
5. 作为使用者，我按了「不继续」不该被记成一次失败。
6. 作为维护者，我希望这条改动有一条能重跑的证据（重跑 `a3`），而不是只有一句「已修复」。

## Implementation Decisions

- **`gate.Refusal` 加一格 `Trace() message.Line`**，不新增结构体、不改接口的「别处造不出拒绝」那条性质（仍只有一个不导出方法守着）。备选是「塔尖自己从 `Say()` 里剥壳拼日志」，被否：剥壳就是拼句子，且 `Say()` 带着「日志：<路径>」那一行，剥漏一行日志里就多一行假话。
- **两个构造点分开**：`newRefusal`（只上屏，答否/取消用）与 `newRefusalLogged`（两格，`refuse` 那 29 处用）。不合并成「一个构造点 + 可选参数」——「这一拒要不要留痕」是构造时就定死的事实，不该留给调用方临时决定。
- **`cli` 标签提到契约**：`contract.WhereCLI`。它跨两个包（闸门造屏、塔尖落日志），与 `contract.WhereOutput` 同一个理由。现成的 `contract.WhereOutput` 注释里写着「其余几个取值各只在一个站里出现，住在那个站里就够」——这条改动正好把它变成了跨两处的那一类。
- **日志用 `message.TraceRefusal(body)` 造**，正文原样交出：外壳（`[ERROR] [function:cli]`）与「日志：」那行由屏幕那一格负责，日志包按老版 `logErrorLines` 的规矩补 `[cli] ` 前缀与「续行缩进两格」。多行正文不在闸门预处理——`log.Fatal` 与老版 `logErrorLines` 的分行、去空行、缩进规则逐字相同。
- **不写 ADR**：这一处可回头（去掉一格方法即可）、不会让后来者困惑（注释里写清了为什么两格）、且没有「换一个季度才能改」的选型。三缺一即不写。

## Testing Decisions

- 接缝用闸门入口（递纸收拒绝）。`gate/refusal_trace_test.go` 四条：
  - `TestRefusalTraceIsBodyOnly`：三条真实拒绝（未知选项 / 缺值 / 模式零个）的 `Trace().Plain()` 必须**正好等于** `message` 那一句，且不含 `[ERROR]`、`[function:`、`日志：`、色码。
  - `TestRefusalTraceKeepsMultiLineBody`：多行正文（多余参数那一条带三条编号原因）原样交出，不被压成一行、不被改写。
  - `TestCancelRefusalHasNoTrace`：答否那一格 `Trace` 为空、`Say` 仍有字。
- 期望值向 `message` 现要，不手抄文案——抄一遍等于把「逐字照老版」这条判据挪个地方再写一次，将来两边一起漂。
- 进程出入口那一头不写测试（塔尖 `main.go` 无测试文件），改由重跑 `a3-unknown-option` 真场景核：日志那行与老版逐字同。

## Out of Scope

- `message.Fatal` 仍收裸 `string`、`console.Writer` 直写屏——那是 4.2「出口收口」，不在此列。
- 拒绝之外的留痕路径（归档执行日志、`--yes` 跳过确认）不动。
- 屏幕文案、退出码、拒绝判据一律不动：这一轮只加一条日志行。
