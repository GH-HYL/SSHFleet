# 失败分类统计的显示重设计 · 规格

Status: done

**闭环说明（2026-10-08 复核）**：已解决。原始诉求「三种数字容易混淆」由 2026-09-28 的 `7.0.0` 修掉——失败分类计数由 `分类名：5` 改为 `分类名 ×5`（`internal/output/terminal.go` 的 `PrintStatistics`；真机实测输出形如 `执行失败(退出码3) ×1`，`×` 紧贴数字，与分类名内嵌的数字一眼分得开）。本文《三、设计方向》里的完整重设计（竖排成列、计数带「台」、退出码拆标签）与第五节 N1–N6 **不再实施**（开发者 2026-10-08 裁定：已闭环）。

> 起点：开发者 2026-09-28 指出统计块里**三种数字容易混淆**——① 分类名内嵌的数字（退出码，将来还会有触发词序号），② 计数（`：5`），③ 行内其它数字；并要求重新设计统计块的显示。
> **实施需用户明确授权**（个人开发规范 一、约束·1 红线 1）；本文档只落方向与取舍，不改代码。
> 本稿由「远端交互应答」引出（`docs/issues/remote-interaction/spec.md` 的「触发词未命中」分类会进这个统计块），但**是一件独立的事**，不夹在那个功能里做。

## 一、现状（照 `internal/output/terminal.go` 的真实行为）

终端统计块与 `report.txt` 的【结果统计】段**同口径**，两处一起改才不漂。

```
════════════════════════════════════════════════════════════   ← 60 个 ═
  总耗时：12.34 秒
  节点总数： 3000  完成总数：3000
  成功： 2990   失败： 10
  失败分类统计 >>>  密码过期：5  触发词未命中：3  执行失败(退出码1)：2
    未归类 1 类：上方直接显示的是报错原文，没能匹配到已有分类。
    若其中某类会反复出现，可把它的特征词补进 config/error_keywords.conf，
    之后就会单独归为一类。
  提示：
    密码过期：<tip 文本>
════════════════════════════════════════════════════════════
```

读法（`PrintStatistics` 的代码行为）：`>>>` 之后是**已归类**的失败分类，横排、两个空格分隔；**未归类**的那些一行一个、缩进 4 空格，且显示的**是报错原文**（判据未命中时的兜底，原文超 200 字截断，见 `classify.go:fallbackMaxLen`）。

## 二、问题诊断（逐条对到代码）

| # | 问题 | 成因 |
| --- | --- | --- |
| P1 | **三种数字同形** | 分类名里的数字（`执行失败(退出码1)`）与计数（`：5`）都是"汉字／半角括号 + 阿拉伯数字"，没有任何区分标记 |
| P2 | **竖着比不了大小** | 已归类横排一行、两空格分隔；分类名长短不一 → 冒号不对齐 → 计数在行内浮动 |
| P3 | **三层语义被混排** | 已归类（原因明确、可照做）／`执行失败(退出码N)`（有退出码但没识别出原因）／未归类（无判据命中）三类，行动含义完全不同，却只靠"是否换行"这一弱信号区分 |
| P4 | **`(退出码1)` 是半角括号** | 与中文语境混排，且括号里的 `1` 与计数数字形状一致 |
| P5 | **提示块与统计块重复** | 上行已有 `密码过期：5`，末尾又来 `提示：密码过期：<解释>`，同一个名字出现两次，"提示"里再跟一个冒号 |
| P6 | **未归类行长度不可控** | 未归类行显示报错原文（最长 200 字）。现状因"一行一个、不参与横排"而侥幸没事，**一旦改成竖排成列就会被它撑爆** |

## 三、设计方向

### 方向甲（推荐）：分层竖排 + 计数成列 + 数字带标签

```
════════════════════════════════════════════════════════════
  总耗时：12.34 秒
  节点总数： 3000   完成总数：3000
  成功： 2990       失败： 10
  失败分类统计 >>>
    密码过期                        5 台
    触发词未命中                    3 台
    执行失败（退出码 1）             2 台
  未归类 1 类（下方为报错原文，未匹配到任何分类）：
    <报错原文…>
    若某类会反复出现，可把它的特征词补进 config/error_keywords.conf
════════════════════════════════════════════════════════════
```

三条手法，各打一个痛点：

1. **计数一律带单位**（`5 台`）——数字后面有没有"台"，一眼可判，把计数与分类名内嵌的数字分开（打 P1）。
2. **每类一行、计数右对齐成列**——数字成列，可竖着比大小。技术上现成：`common.DisplayWidth` 与 `cli/args.go:usageText` 里已有同款对齐实现（打 P2）。
3. **退出码只在呈现层拆开并加标签**：`执行失败(退出码1)` → `执行失败（退出码 1）`。**分类名本身一个字不改**，`classify` 与 `results.xlsx` 都不动，只改终端与 report 两处呈现（打 P1/P4）。
   支撑：`terminal.go` 里已经在用 `exitCodeRe` 解析这个分类名来生成提示（`exitCodeHintLine`），"呈现层解析它"本就是既有做法。
   > **复核（2026-10-09）**：这条支撑已不成立——那一处正则连同 `exitCodeHintLine` / `categoryTipLines` 的解析一起删了，退出码改由 `CategoryCount.ExitCode` 字段给（见 `docs/adr/0004` 的补充节）。本方向仍不实施；若将来要做，呈现层已无"解析分类名"这条现成路子可援引。

未归类单独成组并给定语（打 P3）：它有自己的一段说明文字，而不是靠缩进猜。

### 备选（一并列出供取舍）

| 编号 | 变体 | 取舍 |
| --- | --- | --- |
| 乙 | 计数写成 `×5` 而非 `5 台` | 更短；但符号感强，`×` 与别的内容容易混 |
| 丙 | 计数挪到行首（`5 台  密码过期`） | 数字天然成列；但与"先看名字、再看数"的阅读顺序相反 |
| 丁 | **分类名里彻底不带数字**：`执行失败(退出码N)` 拆成固定名「执行失败」+ 另出「退出码分布：1 × 2」 | 最干净；但要动 `classify` 生成的分类名，牵动 xlsx／report／关键词表／既有语料／测试用例——属**独立工程** |
| 戊 | **把 tip 并进分类行**（缩进一行紧跟其下），取消末尾「提示：」块 | 消掉 P5 的重复；但推翻开发者 2026-09-16 定的"末尾提示块"形态 |

## 四、约束与影响面

- **两处同口径**：终端（`output/terminal.go:PrintStatistics`）与 `report.txt`（`output/report.go:WriteReport`）必须一起改。
- **xlsx 不动**：`results.xlsx` 里的分类名保持原串（`执行失败(退出码1)`），不参与本次重设计。
- **分组顺序保持现状语义**：组内按台数降序（`sort.SliceStable`），组间固定（已归类在前、未归类在后）。只是排版变，判定不变。
- **`IsFallbackCategory` 的划分不动**：它决定了 `known` 与 `fallback` 的归属（三类：`执行失败(退出码` 前缀、成功类、词表里有的），重设计只改呈现，不碰判定。
- **宽度与折行**：竖排成列的前提是给分类名列定一个宽度上限；未归类原文（最长 200 字）必须另行处理，否则撑爆对齐。
