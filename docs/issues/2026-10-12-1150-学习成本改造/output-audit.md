## 三、实测发现的缺陷（4 处，已修）

### P1 清单带 UTF-8 BOM 时解析失败（严重）

中文 Windows 上 Excel 另存的"CSV UTF-8"默认带 BOM。实测带 BOM 的清单报 `CSV 中未解析出任何有效节点`；多行清单则**首行被当成表头静默扔掉**（丢一台机器），单行清单直接报错。

脚本侧本来就容忍 BOM（`check.go` 的 `utf8ValidExceptBOM`，注释明说"允许带 BOM"），同一份工具两处口径不一致。

**修复**：`internal/nodelist/csvread.go` 读取时剥掉首行首列的 BOM；补回归测试 `TestReadCSVRowsStripsBOM`（多行不丢行、单行能解析）。

### P2 上传的"远程目标路径不存在"归不了类

上传侧报错写 `远程目标路径不存在: <路径>`（`sftp.go:61`），下载侧写 `远程路径不存在: <路径>`（`sftp.go:204`）；分类 `远程路径不存在` 的关键字是后者。实测上传到不存在的远端目录，整段报错原文（含路径）被当成"未归类"的分类名上屏。

**修复**：`sftp.go` 上传侧措辞统一为 `远程路径不存在`（与下载侧、分类名三方一致）。连带把该分类的 tip 里"-d 写的"这个限定去掉——上传同样会撞上。

### P3 Windows 上"拒绝网络连接"永远命中不了

分类关键字只有 `connection refused` / `connection reset`（Linux 报错文本）；Windows 上 Go 的报错是 `connectex: No connection could be made because the target machine actively refused it.`。实测在本机把端口写成 2222，落"未归类"——而 tip 里点名的例子恰恰就是"端口写错（如把 22 写成 2222）"。

**修复**：`config/error_keywords.conf` 给该分类补关键字 `actively refused it`。实测命中。

### P4 加密私钥没给口令的报错落"未归类"，且"错误"与"分类"两行逐字重复

工具生成的两行文案（`这把私钥有口令，没有给口令` + `提示：…`）不带任何关键字，导致它进兜底分类——分类名把两行文案整个复述一遍，输出里同一句话出现两次。

**修复**：`config/error_keywords.conf` 给 `密钥解析失败` 补关键字 `这把私钥有口令`（该分类的 tip 第一句就是"私钥有口令但没给口令"，这条分类本来就是为它准备的）。实测 `分类: 密钥解析失败`，重复消失。

**收尾核对**：`go vet` 干净、`go test ./...` 全绿（含新增用例）、两平台重建后四项修复逐一复测通过，五种模式回归无异常。

## 四、观察项（未改动，待作者裁定）

| # | 现象 | 说明 |
| --- | --- | --- |
| O1 | **下载失败被归成 `执行失败(退出码1)`，`远程路径不存在` 分类实际用不上** | 下载的远程路径预检失败时 `sftp.go:203` 会把预检命令（`test -e`）的退出码 1 写进结果，而 `Classify` 对非 0 退出码只查第二块 `[[exit_code_categories]]`，`远程路径不存在` 在第一块——永远轮不到。实测 `-d /tmp/不存在` → `执行失败(退出码1)`。且传输模式终端本来就不显示明细（设计如此），用户在终端上**完全看不到原因**，只能翻归档。**已修（作者 2026-09-24 定）**：给第二块补一条同名的 `远程路径不存在`——预检失败正是第二块描述的情形（连上了、命令没跑、退出码是预检给的），纯配置、零代码，先例是 `密码过期` 两组各一份。实测 `-d 不存在的路径` → `远程路径不存在` |
| O2 | **`--yes` 下上传并发建议行仍然打印** | `上传总大小 25.0 MB，按配置里的阈值建议同时传 1 个（当前是 1 个）。` 出现在 `[非交互模式]` 之前。机制上它确实"生效"（`Confirm` 直接返回已确认 → 并发数被改成建议值），但①建议值等于当前值时也打印（零信息量，实测 25MB > large_file 阈值 → 建议 1 个、当前就是 1 个）；②copy.md 八.3 写的是 `--yes` 只出 `[非交互模式]` 那一句。**作者 2026-09-24 裁定：保留现状**——`--yes` 直接采用建议值，正对应交互时"输入 y"的那一步 |
| O3 | 参数解析失败的"原因"是 Go flag 包的英文原文 | `flag needs an argument: --convert-secret` / `unknown flag: --nosuchopt`。copy.md 11.3 把 `args.go:190` 列为缺口，实施时补了 `（使用 -h 查看帮助）` 兜底，但"原因"本身仍是英文。**已修（作者 2026-09-24 定：工具使用错误必须易读）**：按 pflag 的三类错误分流——`不认识的选项：--xxx` / `不认识的选项：-xyz` / `选项 --xxx 缺少值` / `选项 --xxx 的值只能是 true 或 false，当前值：…`。同批扫出的另一处同类：清单 CSV 语法错（引号不配对）此前甩 Go 原文，改成"读取节点清单失败：nodes.csv 的第 N 行格式读不了——CSV 的双引号要成对出现"。其余英文报错（`dial tcp …` 等）属环境侧、只报事实，且分类 tip 已解释，不动 |
| O4 | 脚本带 BOM 会被容忍、但 BOM 原样进远端 | 实测带 BOM 的脚本，远端 bash 对第一行报 `No such file or directory`（BOM 让 bash 不再把 `#!` 行当注释；shebang 本就不参与 stdin 方式，废的是第一行），其余行照跑、整台算成功。**已修（作者 2026-09-24 定）**：`batch.go` 读进脚本内容后剥掉 BOM 再发，与清单侧同口径 |
| O5 | 上传同名文件会被拒，手册没提 | 实测（2026-09-24 复核）：**逐个传，传到那个同名文件就停**——排在它前面的已传上去，它自己和后面的不传；有传成也有没传成 → 分类`部分成功`，一个都没传成 → `远程文件已存在`，**两种情况统计里都算失败**。**已补**：`使用手册.md` 上传小节加一段、`示例.md` 示例六加一句 |
| O6 | 报告 `总耗时： 0.19  秒` 与终端 `总耗时：0.19 秒` 空格不一致 | 报告侧是旧版继承的写法（旧 `report.py` 就是 `总耗时： {x}  秒`）。**已修（作者 2026-09-24 定：统一）**：`report.go` 改成与终端一致的 `总耗时：%.2f 秒` |

**另有一处纯文档漂移（已顺手修）**：`docs/1-使用手册.md` 的危险屏样张写 `rm -rf /var/log/*` → `规则: 删除日志文件 / 级别: 高`，实际命中 `递归删除系统目录 / 禁止`（多条规则命中时取最高，13.8 记过这个机制）；页脚写的 `这条命令被禁止执行，工具将退出` 与实际 `此命令被禁止执行，程序将立即退出！` 不符。样张与页脚均已按实测改，并补了一句"取最高"的说明。
