## 一、目标与方针

| # | 决策 | 说明 |
| --- | --- | --- |
| L1 | 目标用户是**只能自学的陌生人** | 同事由作者当面教，不计入成本 |
| L2 | 不设客观验收指标 | 每项改动标注取舍，由作者逐项加权裁定 |
| L3 | 总方针取**混合**：默认路径做删除，能力集合做分层 | 判据：这项能力过去两年被主动用过几次 |
| L4 | **允许破坏性变更**，不留兼容、不设双轨 | |
| L5 | 痛点序：**概念多 > 配置重 > 步骤长** | 主攻"上手期"，其次"出错期"，最后"日常期" |
| L6 | **基础 / 进阶**两档分层贯穿全局 | 配置、文档、帮助表三处同一口径。**分层只改变"用户第一眼看到什么"，不改变任何行为** |
| L7 | 术语锚定 **SSH 生态**，不以 Ansible 为参照 | 只在真正会让人点错的地方对齐 |
| L8 | **一律不留沿革** | 注释、帮助、手册正文都不写"此前是……现在是……"。手册里出现"已取消 / 已改名 / 不再支持"都算沿革，重构时逐个清掉 |
| L9 | 同一命令里并列使用的参数，**形态保持一致** | 例：`--no-sudo` 与 `--no-bash` 同一构词法 |
| L10 | 授权范围为**全面重构** | 配置文件模板、README、注释可按新口吻整份重写 |
| L11 | **改造期间不许越界** | 不许顺手拆模块、不许为"以后可能要用"预留抽象、不许顺手改无关代码。认为需要越界时先问作者 |
| L12 | **批量场景下，隐式副作用比失败更危险** | 一千台机器被静默创建出一个目录，比在一台上报"目录不存在"糟糕得多 |
| L13 | **明文凭据不得落进任何日志或归档** | 脱敏规格：明文长度 > 4 位时显示为「前 2 位 + `****` + 后 2 位」；≤ 4 位时整个显示为 `****`。中间的 `*` 固定 4 个、不随真实长度变化，**连长度也不泄露**。覆盖：工具日志、归档报告、执行日志、参数屏、归档的终端输出、归档里备份的清单。**2026-09-24 补两条**：① **内联清单**（`-f 192.168.1.1,22,root,密码`）出现在参数屏、报告、工具日志里时，**只把凭据那几段整个换成 `****`**，IP／端口／用户名／私钥路径原样保留（用户要靠这几段认出是哪台机器）；这里**不比照"前 2 后 2"**——那条规格是给"显示某个凭据值、让人对上号"用的，内联清单里用户要看的是机器不是密码，没必要露头尾。② **归档里备份的清单改成脱敏副本**，不再是原样复制 |
| L14 | **文档的分类与每册内容由方案决定** | |
| L15 | **命名优选简单的英文词汇** | 面向的运维人员大多英语不好。`threshold`、`concurrency`、`passphrase` 这类生词一律换掉或去掉 |
| L16 | **交互只用于"确认"，不用于"补输入"** | 副产物是**可复现**：同样的命令加同样的文件，永远跑出同样的结果，不因"上次输了什么"而不同 |
| L17 | **配置是全局默认值，清单才是用户的逐台决策；只有后者配有提示** | 配置项长期备着、不会来回改（例如为"随时能加 `-k`"而预置的私钥路径），**配了没用上不是错误，不该提示**；清单里的每一格都是用户当场写下的判断，写错或多写才值得提醒 |
| L18 | **能用现有手段绕过的场景，不为它加功能** | 功能本身就是学习成本。判据与 L3 同源但更严：即便某个场景现有设计表达不了，只要**分两批执行就能绕过**，就不为它新增能力（例：清单不能逐台混用密码与密钥登录，分两次执行即可） |
| L19 | **退役能力统一手法：可见面移除，实现保留并加注释** | 已经从用户可见面拿掉、但代码留着不删，注释里写明保留理由（方便作者随时改回来）。本稿有两处用这条手法：base64 档（L25）、路径与文件名那 10 项（L53） |

## 四、密钥与凭据

| # | 决策 | 说明 |
| --- | --- | --- |
| L38 | **`-k` / `--key` 保留，且只保留一个含义：这次用密钥登录**（布尔开关，不带值） | 三态压缩成一态：不加开关 = 用密码；加了开关 = 用密钥。私钥路径取「清单第 5 列 → 配置 `key`」。原来第三态（`-k 路径` 统一私钥）的能力由「配置里配一把默认私钥」承担 |
| L39 | **密钥只做密钥认证，失败即失败，不回退密码** | 密码就只是密码登录，密钥就只是密钥登录。由此连带消掉：回退规则、"有密钥时配置默认密码不参与"、"密钥与密码均失败"这个分类（L26） |
| L40 | 清单**保持 6 列**，列序不变：IP / 端口 / 用户名 / 密码 / 私钥路径 / 私钥口令 | |
| L41 | 第 4 列与第 6 列**同一套规则**：不加密时填**明文**，打开加密后填**文件的绝对路径** | 同一个人在同一件事上只学一条规则 |
| L42 | 配置里的 `password` / `key` / `key_password` 三个字段保留（2026-09-24 作者定：`key` / `key_password` / `encrypt` / `secret_dir` 拆到独立的 `[credential]` 表，自成「凭据」一类；`password` 留在 `[account]`） | |
| L43 | **清单内容检查的范围随开关变**：不带 `-k` 查第 1–4 列；带 `-k` 额外查第 5 列（私钥路径必须可用，**并覆盖"配置里也没有默认私钥"的情况，报错退出**）；**第 6 列永不检查** | 第 6 列不检查的理由是实情：**工具无法判定私钥是否加密**，报了会是误报，只能靠用户自觉 |
| L44 | **加密私钥却没配口令 → 必须报错并给出去路** | 这是 L43"不检查第 6 列"的兜底。真正解析私钥时发现它是加密的、又没有口令，报错要说清"这把私钥有口令，请在第 6 列给口令，或在配置里配默认口令"。统一私钥下这一条会一次影响所有节点，更要说清 |
| L45 | 私钥口令**只能来自清单第 6 列或配置**，不再有运行时询问 | 临时场景仍有路：内联清单的第 6 段就是口令 |
| L46 | **"配了但没生效"只在两处出声，其余一律不提示**：① 加了 `-k` 而清单与配置都没有私钥 → **检查报错**（L43）；② 没加 `-k` 而**清单**第 5 列配了私钥 → **一行提示** | 按 L17：配置里的默认值是长期备着的，配了没用上不算错误；**只有清单里的逐台内容才配有提示** |

**简化后用户只需知道一句话**：要用密钥就加 `--key`，私钥写在清单第 5 列（或配置里配一把默认的）；有口令就在第 6 列给。

### 13.8 `使用 --no-preserve-root 危险旗标` 的处置：**不动**

**它是什么**：`rm` 自带一层保护——直接 `rm -rf /` 它会拒绝执行，除非显式加 `--no-preserve-root` 告诉它"别拦我"。所以这个旗标出现在命令行里，等于操作者在主动拆掉最后一道保险。举例：`rm --no-preserve-root -rf /`。

**结论：本次不新增规则、不改规则名、不改级别。** 理由是现状就是期望结果——危险规则的正则跑在**归一化之后**的字符串上，而归一化会把 `rm` 的旗标拍平成固定次序（`-r` / `-f` / `--no-preserve-root`），所以这个旗标一旦与 `-r`、根路径同时出现，就已经落进 `递归删除根目录` 的正则覆盖范围。实测四种写法：

| 输入 | 归一化后 | 命中 |
| --- | --- | --- |
| `rm -rf /` | `rm -r -f / ` | `递归删除根目录` / **forbidden** |
| `rm --no-preserve-root -rf /` | `rm -r -f --no-preserve-root / ` | `递归删除根目录` / **forbidden** |
| `rm -rf / --no-preserve-root` | 同上 | `递归删除根目录` / **forbidden** |
| `rm --no-preserve-root -rf /*` | `rm -r -f --no-preserve-root /* ` | `递归删除根目录` / **forbidden** |

唯一仍判 `high` 的是**删的不是根目录**时（例：`rm --no-preserve-root -rf /home` → 命中 `递归强制删除` / high）——那是原有设计，与"绕过根目录保护"无关。

规则文件里那条 `使用 --no-preserve-root 危险旗标`（级别 `high`）保持原样，它现在的实际作用只剩"命令里出现这个旗标、但删的不是根目录"这一类场景。

**顺带回答一个机制问题**（作者 2026-09-24 问："一个分类能不能配两个正则"）：**可以**。规则文件是平铺的 `[[rules]]`，每条的 `name` 不做唯一性校验——同一个 `name` 写多条、每条一个正则即可。而且判定只取**命中里风险最高的那一条**返回，所以同名规则同时命中也不会在屏幕上重复显示。
