# 传完核大小，不符就重传这一个文件

- **Status**：done
- **日期**：2026-11-20
- **关联**：ADR-0063 决定 9、决定 10、决定 11

## Problem Statement

一次传输报「成功」，不代表文件在对面是完整的：链路抖一下、目标盘写到一半满了、中间设备截断，TCP 层面都可能正常收场。使用者拿到的是一台机器「成功 3 个」，第二天才发现其中一个只有一半——批量场景里这种静默损坏最难追。

现在失败也不会重来：一个文件因为连接断掉传输失败，整批就跟着回滚，几十个已经传好的文件全白费，而重来一次大多能成。

## Solution

每个文件写完关掉之后，向目标机问一次它的大小，与本机（下载时是远端）对一下：

- 对得上：这个文件算成功，继续下一个。
- 对不上：当作可重传的失败，删掉这个文件重传一遍。
- 重传次数用完仍不对：这个文件计失败，整批回滚，分类名与详情说清「大小不符」。

连接断、读写出错这两类也按同一条路重传同一个文件，已传好的其它文件不动。权限不足、目标盘满、远端重名、路径不存在这四类不重传——重试只是把同一个结果再等一遍。

## User Stories

1. 作为运维，我希望「成功」意味着对面那个文件的大小对得上，而不是「写请求都发出去了」。
2. 作为运维，一个文件因为链路抖动失败时，我希望只重传它自己，不要整批回滚重来。
3. 作为运维，重传次数用完还不对时，我希望分类名一眼看出是「大小不符」，而不是笼统的写入失败。
4. 作为运维，权限不足这类不可能自己好的原因，我不希望工具傻等一遍又一遍。
5. 作为运维，下载回来的文件大小对不上时，我希望它自动重下一次，而不是留一个坏文件在本机。

## Implementation Decisions

### 配置：重试次数

`[execution]` 下新增 `transfer_retry`，整数，默认 `1`，`0` 表示不重试。取值不许为负。三份随包配置都要带这一项与一行注释。

它同时管上传与下载——两边的「重传这个文件」是同一件事，配一个数就够。

### 上传：核大小

每个文件 `io.CopyBuffer` 写完、`Close` 掉之后，`Stat` 一次远端路径，与本机 `os.Stat` 的大小比对。不一致按「大小不符」计，属于可重传的错误。

不比对内容（ADR-0063 决定 11 已定：只核大小）。

### 上传：重试

一个文件最多走 `1 + transfer_retry` 次。每次重来之前先删掉它自己的半成品（远端那个路径），再从 0 重写——不做续传。

哪些可重传，按错误来源判，不按文案判：

- **可重传**：传输中途的读写出错（`io` 层）、写完核大小不符、连接断（`sshfleet.transfer.*` 之外的库错误）。
- **不重传**：SFTP 状态码是「没有权限」「文件不存在」「操作不支持」；失败后探测到目标分区装不下；远端重名（这条在建文件之前就判过，不进重试）。

目标盘满不是状态码能认出来的（协议 v3 只有笼统的 failure），所以在决定重试之前探一次空间：探出来不够，就不重试，直接按原路失败并报「目标磁盘已满」。

### 上传：重试用完

照现有回滚走：本次已写成功的文件删掉，分类与详情说明原因。**大小不符**要有自己的报文与分类：

- 报文：`sshfleet.transfer.size_mismatch: local <本机字节数> bytes, remote <远端字节数> bytes`
- 分类名：`传输后大小不符`
- 位置：排在两条回滚之后。判据表「目标机现在是什么状态」先于「为什么失败」——回滚那两句说的是状态，这一条说的是原因；第一个文件就不符时没有回滚那句，分类才会落到它。

### 下载：核大小

每个文件写完关掉之后 `os.Stat` 本地文件，与枚举时远端给的大小比对。不一致删掉本地那份、重下一次，次数同上。用完仍不一致按「大小不符」计并删掉本地半成品。

## Testing Decisions

**接缝**：`execute.Run`——执行站入口，递一张纸收一张纸。测试只断言那张纸与假目标机上的文件。

**怎么造「大小不符」**：假目标机的 SFTP 服务端跑在真实文件系统上，写不短，也没有截断开关。能从枚举那一侧造——下载的期望大小就是枚举给的数，让假目标机的 `find` 把大小报大，本地落盘就必然对不上。上传侧造不出短写，只能靠下面那两条单测钉住判据。

**分三条**：① 下载枚举一直报大 → 该台失败，分类「传输后大小不符」，本机不留半成品；② `retryableTransferError` 对「没有权限／文件不存在／操作不支持」三个状态码返回 false，对读写中断与大小不符返回 true；③ 大小不符那句报文只说两个数。

**造不出来的那条**：重试之后对上的情形。期望大小来自枚举、重试不再枚举，所以「第一次不符、第二次对上」在本机没有构造点；这条只留在实现里，由代码复核，不写成验收项。

**判据**：`internal/execute/verdict_test.go` 的 `classifyTables` 按随包顺序补上这一条，再各加一条用例。

**配置**：`internal/parse` 的取值校验各补一条——`0` 合法、负数报错、缺省是 `1`。

## Out of Scope

- 内容校验（sha256）：ADR-0063 决定 11 已否。
- 续传：ADR-0063 决定 3 已否。
- 传输超时之后的重试：超时是整批的事，不进单文件重试（ADR-0063 决定 10 末句）。
- 已有两条回滚的删法（仍是逐个删）。
- 预检阶段的失败（远端路径不存在、目标不是目录、本地读不了）不进重试。
