# 02: 上传写完核大小，不符只重传这一个文件

**要做的**：每个文件写完关掉之后问一次远端大小，与本机对一下；不匹配就删掉它重传，次数取 `transfer_retry`。读写出错与连接断同样按这条重传，已传好的文件不动；权限不足、目标盘满不重传。用完仍不匹配时整批回滚，分类显示「传输后大小不符」。

**Blocked by:** 01（重试次数从配置来）。

**Status:** done

- [x] 写完核大小不符时按可重传处理，重试用完仍不符则计失败（`sizeMismatchMessage` 与判据用例）
- [x] 可重试的判据按 SFTP 状态码：没有权限／文件不存在／操作不支持不重试，读写中断与大小不符重试（`TestRetryableTransferError`）
- [x] 目标盘满在重试之前探一次，探出来不够就不重试（走 `spaceShort`，失败后那一问与它同一处）
- [x] 不重试的失败照旧：远端重名、目标盘满、预检失败的行为不变（既有上传用例全绿）
- [x] 端到端造不出短写：假目标机的 SFTP 服务端是真实文件系统（见 `## Comments`）

## Comments

- 2026-11-20：上传侧「短写」端到端造不出来——假目标机的 SFTP 服务端是 `pkg/sftp` 自带的那份，跑在真实文件系统上，没有截断开关；换 `RequestServer` 自造四个 handler 只为一格测试，代价大于收益。核大小与重试判据由单测钉住：`TestRetryableTransferError`（状态码 3／2／8 不重试、读写中断与大小不符重试）、`TestSizeMismatchMessage`（报文只报两个数），重试循环本身按同一形状在下载侧端到端跑通（`TestRunDownloadFailsWhenSizeNeverMatches`）。
