# 内联值只写一条：`-f` 与 `-a` 取消一切换行写法 · 规格

Status: ready-for-agent

> 决策依据：`docs/adr/0023-inline-value-is-a-single-record.md`（为什么 `\n`、`;;`、真换行三条路都不留，以及二义性为什么无解）。本文只写「做成什么样」，不重复取舍理由。

---

## Problem Statement

内联清单与内联代填，使用者现在面对的是三种说法并存、且没有一种被完整兑现：

1. **手册说能写多台，照抄就失败。** 手册里那条三台示例（`-f "192.168.1.10;;192.168.1.11;;192.168.1.12" -c "uptime"`）是真示例，照抄报「`-f` 参数指定的文件不存在」。
2. **同一个位置上到底什么算分行，讲不清。** 字面 `\n` 曾经是分隔、现在只是普通字符；`;;` 是分隔；直接回车（bash 的 `$'…'`）也能写进内联且被当成多行。三者混在一个取值里，使用者没有判断依据。
3. **代填内容里要回车，内联没有可指望的写法。** `-a` 的内联值可以用 `;;` 写多条，但内容里要回车，只能靠 shell 把真换行传进引号里——cmd 下写不出这种写法，手册里也没有这条路。

结果是：报错（「文件不存在」「IP 格式不正确」）都指不到真正该做的那一步。

## Solution

`-f` 与 `-a` 的取值只剩两种：一个 CSV 文件，或内联的一条记录。

- `-f` 的内联值是一台节点：`192.168.1.10` 或 `192.168.1.10,22,root,密码`。
- `-a` 的内联值是一条代填：`y,是否继续`。
- 字面 `\n`、`;;` 都只是普通字符，没有分隔含义；内联值里出现**真换行**直接拒绝，并提示「内联只写一条，多台 / 多条请写成 CSV 文件」。
- 多台节点、多条代填、内容里要含回车的代填，一律写进 CSV 文件；文件侧的注释、空行、BOM、引号、变长列口径保持不变。
- `-f` 与 `-a` 共用同一处「这是文件还是内联」的判定，报错同形。

## User Stories

1. 作为临时测一台机器的运维人员，我希望 `-f 192.168.1.10` 与 `-f 192.168.1.10,22,root,密码` 照旧能用，这样临时操作不用先建文件。
2. 作为要代填一条内容的人，我希望 `-a "y,是否继续"` 照旧能用。
3. 作为照着旧示例写了一次多台的人，我希望报错直接告诉我「内联只写一条，多台请写成 CSV 文件」，而不是「文件不存在」。
4. 作为想知道内联到底支持哪些写法的人，我希望手册、帮助和报错说的是同一件事。
5. 作为要把带回车的内容代填进去的人，我希望文档把我引到 CSV 文件，而不是让我在内联里找转义记号。
6. 作为 Windows 用户，我希望路径里的 `\n`（如 `D:\new\pw.bin`）永远不会被当成换行。
7. 作为接手仓库的人，我希望内联识别只有一处实现，不会在 `-f` 与 `-a` 之间各自错一次。

## Implementation Decisions

- **识别收口到一处**：`-f` 与 `-a` 共用同一个判定与同一份报错。判据两层——值是不是已存在的文件；不是文件时，值必须是一条，且首列符合本侧语义（节点看 IPv4，代填看至少两列，即含逗号）。两侧只提供各自的首列判据，不各自写 split。
- **不做装载期替换**：内联值不再有任何整备步骤，直接按单行 CSV 解析；字面 `\n` 与 `;;` 原样进入字段。
- **真换行必须拒绝**：内联值里出现真换行时明确报错，不静默当记录分隔，也不静默丢弃后半截。报错给出去路（写文件）。
- **诊断提示不设语法**：值里出现 `;;` 或字面 `\n` 不构成语法错误（它们是普通字符）；只有在按上述判据校验失败时，提示里补一句「内联只写一条，多台 / 多条请写成 CSV 文件」。这是给人找路，不是新记号。
- **帮助与使用者文档**：程序帮助与手册、常见问题、示例、README 里，`-f`、`-a` 的取值说明只保留单条形态；「多台 / 多条怎么写」指向 CSV 文件。任何地方都不得再出现内联多行的示例。CHANGELOG 已封口的旧段不动，实施当天在新段按最终形态记一句。
- **不设转义、不设第二个记号、不为旧写法做兼容**。

## Testing Decisions

- **接缝**：沿用既有接缝——命令行参数入口（解析 + 合规检查）与清单 / 代填装载的公开入口。不新增接缝，不测私有函数。
- **要钉住的行为**：
  - `-f` 单条裸 IP、单条四列都能通过识别并进入执行；
  - `-f` 值含真换行 → 拒绝，文案指向文件；
  - `-f` 值写成 `ip;;ip` → 不再被切成两台（整体按一条处理并报错，报错指向文件）；
  - `-a` 单条 → 通过；`-a` 值含真换行 → 拒绝；
  - 给文件路径、文件里多行 → 照旧解析（回归既有能力，确认没被内联侧改动波及）；
  - 把不存在的路径当内联 → 报「文件不存在」，且提示与内联只写一条的口径一致。
- **期望值**取自字面量（手写的 IP、行数），不用被测代码同款算法重算。

## Out of Scope

- 文件方式的解析口径与换行规则（不变）
- 代填内容里表达真换行的内联写法（走文件）
- 失败分类、退出码、报文
- 为内联另立选项（如 `-F`）

## Further Notes

- **这是一次不兼容改动**：旧示例里的 `;;` 多台写法会失效。按 CHANGELOG 的「升级后原命令还能不能跑」判据，实施时抬主版本，并在当天段落按最终形态记一句。
- 词表「CSV 取值」的现有释义仍写「或同一格式的内联文本」，本次决定之后这句话不再准确；词表属约束类文件，本议题不自行改，需作者同意后单独订正。
- 2026-10-21 排查出的「裸 IP 多台不识别」缺陷随本议题一起消失（该写法本身被取消），不另立工单；若本议题不实施，那条缺陷仍需单独立项。
