# 规格：测试临时目录与期望值（规范债 11-H1／H2）

**状态**：done

## Problem Statement

`go test ./...` 现在能不能跑干净，取决于跑之前有没有手工 export 过一组临时目录：全工程 75 处 `t.TempDir()` 默认落 `%TEMP%`，也就是工作区外。忘了 export 的那一次，测试产物与临时可执行文件掉进 `%TEMP%`，被 360 静默删掉，现象是「构建莫名失败、不报原因」——这个坑已经踩过一次。

另有两处断言，把被测生产代码当场算出来的字符串当期望值：两侧一起改就恒绿，等于没断言。

## Solution

测试自己把临时根钉进工作区的 `build/tmp/`：每个有测试的包一处入口，跑起来就把 `TMPDIR`／`TMP`／`TEMP` 指过去，不再依赖外部环境。两处取自生产代码的期望值，换成真跑出来的字面量。

## User Stories

1. As a 跑测试的人, I want 什么都不 export 直接 `go test ./...`, so that 忘了也不会有产物掉到工作区外。
2. As a 跑测试的人, I want `build/tmp/` 下按包分目录, so that 出问题的时候是哪一包的临时料一眼看得出来。
3. As a 维护者, I want 那两条断言在我改文案时跟着红, so that 期望值不是我改成什么它就跟着认什么。

## Implementation Decisions

- **一包一处 `TestMain`，不新建共享测试包**：这个仓库的测试假件按区各写一遍，新建测试专用包要动依赖白名单（属改锚），为这点事不值。
- **临时根**：模块根上两级的 `build/tmp/test/<包>`，跑测试时按需建。
- **`TestMain` 只做两件事**：钉环境变量、`os.Exit(m.Run())`。不改任何测试逻辑，不碰生产代码。

## Testing Decisions

- 判据是「不 export 就跑」：干净环境下 `go test -count=1 ./...` 全绿，且 `%TEMP%` 下不再出现本工程的测试目录。
- 两处期望值改成字面量后，反向验证一次：把生产侧的文案故意改一个字，这两条测试仍应是绿的——绿说明期望值已经不再跟着被测代码走。
