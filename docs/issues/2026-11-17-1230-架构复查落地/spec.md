# 规格：架构复查五条的落地

**状态**：done
**底本**：`architecture-review-20261117-1123.html`（另存于 `%TEMP%\arch-review\`）与四份 findings。本规格只收其中**复核后成立**的部分；被否掉与被砍规模的写进 Out of Scope，理由一并留在那里。

## Problem Statement

跑传输（上传／下载）时，终端上那块逐节点面板的汇总行永远是「0/N、成功 0、失败 0」，已经传完的机器还占着显示位不让位。使用者看到的是「一台都没完成」，而实际可能已经跑完大半——他把这个当成任务卡住了。

另外三处是维护者侧的：改一处传输记账要记两遍（上传写了、下载漏了）；代填与改密两段会话骨架各抄一遍；拼句包对外露了 202 个名字，其中 40 个外面一次都没用过，使用者读代码时无从判断哪个才是该调的。三条检查器里有一条永远绿灯——它判的对象在全工程没有一处赋值过。

## Solution

1. 传输面板的汇总与定格接回生产那一路：节点结束时把结果交回聚合器，面板的台数、成败、让位、收场定格都随真实结果动。
2. 撤掉那条没有对象的交接件判据，把「越传越窄」从「机械守着」降为「规格审计时看」。
3. 传输失败的四个数由一个入口回填，上传下载同口径。
4. 代填与改密共用的「开会话→装钩子→驱→收→关」收成一个函数，两个模式只留各自的差异。
5. 拼句包把包外零引用的名字收回包内，`CannotStartText` 与 `CannotStartBody` 两个门牌合一。
6. 执行站入口的两个同型参数收成一张具名纸，写反了编译不过。

## User Stories

1. 作为跑上传的使用者，我要面板上的「已完成／总数」随机器跑完而增长，这样我能判断还剩多少。
2. 作为跑上传的使用者，我要汇总行的「成功 N／失败 M」反映真实结果，这样我不用等报告就知道这一批的成色。
3. 作为跑上传的使用者，我要传完的机器让出显示位，这样在传的机器能补上来、屏幕不被已完成的占满。
4. 作为跑下载的使用者，我要收场时屏上留下的是「跑完了」那一帧，这样我一眼能确认这一趟结束了。
5. 作为跑下载的使用者，我要被中断的那一趟不显示成「全跑完」，这样我不会把没跑完当成跑完了。
6. 作为维护者，我要下载失败时报告与日志里的文件数、字节数与上传同口径，这样对账时不用先问「这条是哪个模式漏的」。
7. 作为维护者，我要改代填的会话收尾时不必同时改改密，这样两处不会各漂各的。
8. 作为维护者，我要拼句包的公开面只留调用方用得着的那些，这样我读代码时不用在 202 个名字里猜哪个是入口。
9. 作为维护者，我要「起不来」的那一屏只有一个公开出口，这样测试与生产不会各拿一个门牌比同一句话。
10. 作为维护者，我要执行站入口的两个落点各有名字，这样写反时编译器拦得住。
11. 作为维护者，我要结构检查里没有永远绿灯的空转判据，这样绿是真的绿。
12. 作为复审的人，我要知道「越传越窄」现在靠什么守，这样我不会以为还有一条检查在管它。

## Implementation Decisions

**一、面板汇总的接线点在执行站收口处。** 节点结果（含传输四个数）在 `visit` 收口时已经齐了（分类也在那里定），聚合器的完成回填就在那一处调用。成败取执行站**已有的那一个**成功判定（`ranClean`，分类函数也在调它），收口处算一次随结果交回；面板不另立一套判据，也不重复算——两处各写一遍，改口径时必有一处不知道。

**二、交接件对账表撤掉，不补对象。** 判据的形状是「后一张 = 前一张 + 一格结论」，它预设每一棒都造新纸；而闸门这一棒按 ADR-0035 更新记录改成等宽、不造新纸，前两棒现在是**同一张** `Plan`，没有两张可比。补一对 `Plan → Plan` 会当场要求一个 `Conclusion` 字段，而闸门的结论按设计不进纸（拒绝不往下递，放行不需要结论格）。所以撤判据、撤 `Pairs` 字段、撤对应红线与测试。代价写进 ADR-0058：这条规矩从此只靠规格审计与人读。

**三、传输失败回填收成一个函数。** 上传五个早退点已经各写一遍，下载侧一个都没写；统一后两边都在早退处调它，参数是这台的结果纸与已枚举的文件表。判定不受影响（`verdict.go:98` 要求成功项大于 0），改的是报告与日志印出来的数。

**四、PTY 会话骨架收成一个函数，收在 `execute` 包内。** 实测重复是两处 21 行、其中 17 行相同，差异只有三样：钩子怎么造、发送通道给多大、下发行是什么。收成一个函数，这三样作参数；代填与改密各自的事后处理（未送出的条目、过期信号）留在原处。ADR-0035 决定二说「各写一遍」，条件是「没有事实支持合并」；现在的事实是**已经抄漏一处**（下载侧回填），符合那条自己写的「将来真出现改一处不得不改另一处，再合并」。ADR-0035 追加更新记录。

**五、拼句包的公开面按「包外有没有人调」收。** 收回的是包外零引用、且本包内仍有引用的名字（findings 记 42 个，实施时以机械清单为准，不以那个数为准）；`credential.Inspect()` 这种生产与测试都零调用的壳一并删。`CannotStartText` 收回包内，测试改调 `CannotStartBody(c).Text()`。**不合并 29 个 `Refuse*`**：拒绝与起不来是 ADR-0034 有意分的两种失败，合表前要先抽出 29 个场景的共同事实形状，那是另一次领域建模。纪律写进 ADR-0059。

**六、执行站入口收一张具名纸。** `Run(ctx, plan, landings)`，两个落点各有字段名。**这张纸放契约包**：站的出口白名单只许「一个函数加一个类型」，而那个类型的位置是替身插口（ADR-0037 决定三），纸的类型归契约——放站里会当场撞检查器。调用点一个（塔尖），测试跟着改。**不动 `parse.Run` 的五个返回值**：改它要动塔尖 switch 与三族测试，而「加第六种结局」今天没有需求。

**七、碰红线的地方按 ADR-0037 决定五办。** 撤判据（第二条）与收回公开面（第五条）都算改红线：先有 ADR，再动名单与指纹。改签名（第六条）不在指纹口径里（指纹钉符号名，不钉签名），但若红线测试体因此改动、断言数变化，同样按改红线办。实施时先跑一遍 `go test ./...`，以实际是否变红为准。

## Testing Decisions

**接缝只有一个：执行站入口 `Run`。** 面板那条接线要能被证伪，必须从 `Run` 进——用现有 integration 那一套（真机或死端口）跑一次上传，断言面板收到的快照里「完成台数」不为 0。**不新造假 sshd、不加替身插口**：ADR-0037 给站留的那格配额本轮不用，理由见 Out of Scope。

其余五条按既有先例测：

- 撤判据：检查器的自反测试（`guard` 包里那份）要证明「判据不在了」能被发现——删掉名单条目后，`TestLoadCountsPackages` 一类计数断言要跟着改，这是预期的红。
- 回填统一：下载侧的早退路径各一条用例，断言四个数与上传同口径。
- 骨架收拢：从 `Run` 进的两条用例（代填一次、改密一次）在改前改后都绿；不加「内部调用了几次」的断言。
- 公开面收回：`go build ./...` 与 `go test ./...` 全绿即证；另加一条机械核对（包外引用清单为空）。
- 具名纸：编译过即证写反不可能；`TestRedlineExecuteRecordsConnectFact` 与 `TestRedlineExecuteWritesResultLine` 两条红线改调用形状，按改红线办。

## Out of Scope

- **`parse.Run` 收成 `Outcome` 一张纸。** 五个返回值确实难读、④⑤ 同型，但改法要动塔尖 switch 与三族测试，收益是「加第六种结局不动调用点」——今天没有第六种。留待真出现时做。
- **给传输能力造替身插口、两个适配器（真 SSH ＋ 进程内假件）。** 方向与 ADR-0037 的站出口配额一致，但成本是把 `*ssh.Client`／`*sftp.Client` 全包成函数字段，属中等重构。本轮只修接线，不换传输层。
- **把 29 个 `Refuse*` 铺成一张表 + 一个入口。** 见 Implementation Decisions 第五条。
- **17 份 `tmpdir_test.go` 收成一份。** 它是测试基础设施，收益是 767 行降到 48 行；与上面六条不同类，另起议题再定。
- **`guard/check_deps.go` 一个文件五条判据拆分。** 同上，另起。
- **`exitcode` 并回 `contract` 或升 ADR。** 同上，另起。
