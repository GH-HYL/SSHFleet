# 13: 执行站画进度——照老版那套界面搬，屏幕的 writer 从 console 拿

**要做的**：跑的过程中屏幕上有个「跑到哪儿了」的界面：底部固定一块（总进度条、当前并发、速度），上面滚已经跑完的行。做完之后，一台与多台跑起来，屏幕观感与老版一致。

**Blocked by**：12。

**Status**：done

## 屏幕的 writer 从哪儿来（已定，2026-11-02）

老版是 bubbletea 直写 `os.Stdout`（`output/reporter.go:163` 起 `tea.NewProgram(..., tea.WithOutput(r.out))`，结果行走 `prog.Println`），所以「跑起来那一段」屏幕由进度界面独占，画帧与结果行同一条流，不抢屏。

新工程照这个形状办，只把「那个 writer 从哪儿拿」换一处：

- **`console` 交出一个 writer**（生产环境就是它自己写的那个标准输出，测试里是缓冲区）。执行站拿到它，交给 `tea.WithOutput`；结果行也从它出去。全程序真正往终端写字节的仍然只有 `console` 一处，界面帧与结果行不各写一份。
- **不加「整帧转交」那层**：每帧再转手一次只是多一层，老版没有那层，加了也不改变任何行为。
- **类一检查补一条判据**：`console` 交 writer 的那个入口，调用点只许出现在执行站；别处调它就红。这样「唯一出口」从「只许调 `console.Print`」放宽成「写终端的实体只有 `console`，借 writer 的人只许一个」，口子数得出来。
- **这是动检查本体的一处**，开发者 2026-11-02 已点头（原话：「确定这个方案更好啊，不用考虑什么约束，都大重构了，如果重构过程中能顺手优化一下的小改动，当然是可以的」）；改动落进 `guard` 的类一，与 `console` 的新入口同一次做。

## 要落的判断

- 界面只在「是终端」时出；重定向到文件时退化——退化的判据与老版一致（老版是 `isTerminal(os.Stdout)` 决定 `plain` 那条路）。
- 生命周期归执行站（13 号工单：Program 的启动与收尾在执行站，主干仍独占执行与退出权）。
- 节流只节屏幕：采集侧那一层留着（500ms），渲染那侧那层删掉。
- 界面收掉之后，已经写下的结果行留着不动（那是这次跑到哪儿为止的证据）。
- **屏幕上的结果行与 `terminal-output.txt` 里那一段同版面**（开发者 2026-11-02 的原话：「终端输出的样子和那个 output.txt 的样子要一样，不说一模一样，也得版面一样」）。12 号单已经做到「同一段字、一次拼出」并有一条测试钉着（`TestReporterScreenAndFileMatch`）；13 号换出口时**不许在屏幕那一路另排一遍**——不折行、不截断、不加前导空白，也不许只在屏幕上加进度前缀。终端自己按窗口宽度软换行那是终端的事，文件里仍是一行。
- 颜色：`message` 拼出来带色码，`console` 打之前决定要不要去掉——与本阶段别处同一套判据。

### 2026-11-02：交付

**落了什么**：`console.Writer()`（交出往标准输出写字节的那条流）+ `console.IsTerminal()`；`execute/progress.go`（面板模型 + 屏幕那一路：面板懒起来，结果行走它上方，非终端直通）；`execute/run.go` 一开工就摆面板、每台跑完先推进度再出行。三件依赖按 04 规格第八节进 `go.mod` 与规则表白名单，版本与老版一致（`bubbletea v1.3.10`／`bubbles v1.0.0`／`lipgloss v1.1.0`）。

**类一补了第三条判据**（动检查本体，点过头的那个方案）：`console.Writer()` 的调用点只许在执行站，别处调它就红。样本 `testdata/writer` 里两站各取一次——解析站那次报红、执行站那次放过，正反两边都有。红线名单 33 → 34 条。

**两处落地时定下来的口径**：

1. **白名单按「库」认，不按包认**：`bubbles/progress` 是 `bubbles` 的子包，一行一个子包会把名单变成包清单。改成前缀匹配（`path == 名` 或 `path` 以 `名/` 开头），记在规则表那条判据的注释里。
2. **`IsTerminal` 按 isatty 判，不按列数判**：起初用「拿不拿得到列数」，实测伪终端（`script`、部分 CI、ssh 里的会话）报 0 列，界面直接不出了——那就不叫「与老版一致」。改成各平台一次 ioctl／GetConsoleMode，与老版 `isatty(os.Stdout)` 同一件事。

**验收**：

- **真机 + 伪终端**（`script` + 直接跑测试二进制，stdout 就是 pty）：面板先出（0.0%、`已完成 0/N`），结果行经由 `Println` 打在它上方，收工那帧到 100% 后擦掉自己那一行、光标落回下方——形状与老版一致。
- 非终端（`go test` 默认那一路）：不出界面，结果行直接落流；`terminal-output.txt` 的内容与界面在不在无关（它由 reporter 直接写，不经过屏幕那一路）。
- 面板单测：数字与字（总进度 / 已完成 x/y / 耗时 / 成功失败）、按台数算的百分比（0 → 0.5 → 封顶 1）、`elapsedText` 三种取值、直通那一路原样落流。
- 三台并行真机跑一遍：三条事实、文件三段、面板 3/3 成功 3。
- `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿；`GOOS=windows` 也编得过（三个平台的 `isterminal_*` 都在）；17 包零违规、放行台账 0 条、红线 34 条。

**没做到的**：**整屏与老版逐字比对**——那要新老两个二进制跑同一条命令，而塔尖还没接到执行站（16 号单才接）。本单只把「面板在、行在上方、收工擦行」这层形状验到；逐字比对是 16 号单 A/B 的一格。
