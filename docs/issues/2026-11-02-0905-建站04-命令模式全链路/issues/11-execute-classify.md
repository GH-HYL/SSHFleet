# 11: 执行站定分类——按判据表给这一台归一类

**要做的**：一台跑完之后，按判据表给它定一个分类（成功也算一类）。做完之后，每条结果上都挂着分类名与退出码；「这一批成功几台、失败几台」交给结算站，执行站自己不说「成功」还是「失败」。

**Blocked by**：10。

**Status**：ready-for-agent

## 要落的判断

- 判据表随第一张纸来（ADR-0035 决定五），执行站不读文件。
- **两组分类的用法照老版**：目的命令没有退出码时用第一组，目的命令自己以非 0 收场时用第二组（`contract.Tables` 里那两格）。顺序即优先级，命中即停。
- 匹配的文本：远端原话 + 工具自己那条报文 + 服务端提示，三样合起来撞关键词。
- **口径照老版写死，不读配置**：两边都转小写后比（大小写不敏感）、按子串包含、关键词里带 `*` 就按 `*` 切片段顺序查找（`verdict/keywords.go:194-220`）。**不要读 `[interactive]` 那两格**——那两格服务的是代填与改密，不是分类；执行站也不许回头读配置（跨站回取）。
- 「密码过期」这一类是**同一份配置取两次**（词表「中止词」）——本阶段只用到「跑完按全文判」这一次。
- 分类名与退出码是事实；**成败让结算站解释**（ADR-0035 决定四）。

## 验收

- [ ] 一份手搓的原文样本集（每类一条，加一条不命中任何类的），分类名逐条写死断言；期望值不用被测代码算
- [ ] 两组分类的分工各一条：有退出码走第二组、没有退出码走第一组
- [ ] 结果里没有「成败」这个字段——红线：第二张纸的字段集里不出现 `Success`／`Failed`
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

## 不在这单

改密那一步的分类（05 阶段）；提示语（分类的 `Tip`）由报告站取用，不在本单。

## 做完之后

12 号单把这一条拼成一行字；14 号单拿分类去算成功几台。
