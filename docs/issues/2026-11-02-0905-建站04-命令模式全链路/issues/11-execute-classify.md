# 11: 执行站定分类——按判据表给这一台归一类

**要做的**：一台跑完之后，按判据表给它定一个分类（成功也算一类）。做完之后，每条结果上都挂着分类名与退出码；「这一批成功几台、失败几台」交给结算站，执行站自己不说「成功」还是「失败」。

**Blocked by**：10。

**Status**：done

## 要落的判断

- 判据表随第一张纸来（ADR-0035 决定五），执行站不读文件。
- **两组分类的用法照老版**：目的命令没有退出码时用第一组，目的命令自己以非 0 收场时用第二组（`contract.Tables` 里那两格）。顺序即优先级，命中即停。
- 匹配的文本：远端原话 + 工具自己那条报文 + 服务端提示，三样合起来撞关键词。
- **口径照老版写死，不读配置**：两边都转小写后比（大小写不敏感）、按子串包含、关键词里带 `*` 就按 `*` 切片段顺序查找（`verdict/keywords.go:194-220`）。**不要读 `[interactive]` 那两格**——那两格服务的是代填与改密，不是分类；执行站也不许回头读配置（跨站回取）。
- 「密码过期」这一类是**同一份配置取两次**（词表「中止词」）——本阶段只用到「跑完按全文判」这一次。
- 分类名与退出码是事实；**成败让结算站解释**（ADR-0035 决定四）。

## 验收

- [ ] 一份手搓的原文样本集（每类一条，加一条不命中任何类的），分类名逐条写死断言；期望值不用被测代码算
- [ ] 两组分类的分工各一条：有退出码走第二组、没有退出码走第一组
- [ ] 结果里没有「成败」这个字段——红线：第二张纸的字段集里不出现 `Success`／`Failed`
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

## 不在这单

改密那一步的分类（05 阶段）；提示语（分类的 `Tip`）由报告站取用，不在本单。

## 做完之后

12 号单把这一条拼成一行字；14 号单拿分类去算成功几台。

## Comments

### 2026-11-02：交付

**落了什么**：`internal/execute/verdict.go`（定分类：成功规则、两组分工、大小写不敏感、关键词里的 `*` 按片段顺序查、判据表没认出就把原文当分类名、超 200 字截断）、`internal/message/category.go`（成功分类名 + 两个代码给的名字）、`execute/run.go` 的 `visit` 收口一处定分类。分类判据单开了一个文件，执行站对外仍只露 `Run`。

**一处纸上没写死、当场定下来的**：成功那一台也要有分类名（本单第一句「成功也算一类」），而那个名字「执行成功」在新工程里**没有落点**——老版挂在 `cli.Mode.Info()` 上（ADR-0013 把一种模式的全部叫法收在一处），新工程里 `cli` 劈进了解析与闸门、模式类型住契约，而契约不许有函数。取舍：

- 住 `message`（唯一改字处），`message.SuccessCategory(mode)`；执行站写、结算站对、报告站印，三处读同一份。理由：这是一句给人看的字，而契约 2026-11-02 刚把「装字」整条撤掉过。
- **预填充**：只搬「成功分类」这一列，其余七列（归档目录名、报告标题、模式行、超时行措辞……）随 05／07／15 各自要用时再并进来，并的时候整张表一处成形。总图框架条目已记一行。

**带来的一个已知差别（记账，不夹带修）**：判据表是使用者可改的，若有人把某个失败分类起名叫「执行成功」，新版按「分类名 = 本模式成功分类」会把这台算成功；老版按 `Verdict` 算失败（该撞名老版 2026-10-19 已记档，判「概率低、先记着」）。要不要抹平，随 09 逐字比对或开发者定——抹平要么给纸加一格「成败」（撞 ADR-0035 决定一），要么退回「分类为空即成功」（撞 14 号单的判据）。

**验收**：

- 手搓样本集 12 条，分类名逐条写死（`verdict_test.go`）：干净成功、连不上、认证失败、超时、星号、大小写、一条都不命中的原文兜底、全空兜底「原因未知」、第二组命中顶掉退出码兜底、退出码兜底「执行失败(退出码3)」、退出码 0 但有报文落回第一组、成功规则里超时不算成功；另加两条：两组分工只看退出码在不在、兜底原文截到 200 字加省略号。
- 红线：`guard/redline_result_test.go` 钉「第二张纸没有 Success／Failed／Verdict 字段」。**塞探针验过会红**（临时给 `NodeResult` 加一个 `Success bool`，当场报「出现了「成败」字段 Success」，撤掉后 `grep -c Success` 为 0）。
- 真机（`u1`，`-tags integration`）：六条全过，干净那条分类是「执行成功」、`exit 3` 那条是「执行失败(退出码3)」。
- `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全干净；17 包零违规、放行台账 0 条、红线名单 31 → 32 条（新增一条不算改）。

**没做的**：提示语（`Tip`）随 15 号单取用；上传／下载／改密三种模式的成功规则随 05——落在这里的别的模式一律不算干净走完。
