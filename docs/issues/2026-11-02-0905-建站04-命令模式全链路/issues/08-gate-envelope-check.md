# 08: 闸门验信封——标签与载荷对不上

**要做的**：纸上写着「这次是命令」，载荷那一格装的却是脚本——这种对不上只在一处露头。做完之后，闸门在放行之前先验一次：标签与载荷对不上就拒（算「输入不合规」那一类，不另立一类）。

**Blocked by**：01。

**Status**：done

## 边界

- 这是 03 规格记下的「只留判据、没有可判对象」那一条，本单把对象补上。
- 验的是**形状**：标签指向哪一份载荷、那份载荷在不在、必填格空不空。不验内容对不对（命令危不危险是危险检测那一条）。
- 契约里不放这个校验函数（ADR-0035 决定六）；校验住闸门。

## 验收

- [x] 四类对不上各一条样本：标签是命令而载荷为空、标签是命令而装的是脚本、标签为空而载荷有内容、标签合法但必填格缺——每条都交回 `gate.Refusal` 而不是 `CannotStart`
- [x] 一条正样本：合法纸放行，拒绝为 nil
- [x] 红线：闸门入口那条测试补上「对不上 ⇒ 拒绝非空」的形状断言（只判非空，不判措辞）
- [x] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

## 不在这单

另外四份载荷的合法性（随 05 加类型时一并加样本）。

## 做完之后

16 号单的 A/B 里，这一条与老版对一遍：老版在选项/参数检查里拦同一类事，屏上那句话应当一致。

## Comments

### 2026-11-02：交付

**落了什么**：`envelopeRefusal` 排在闸门最后一道——前面几条判的是「这次给的东西对不对」，这一条判的是**纸本身有没有被造错**，不该抢在人的毛病前面报。三条判据：载荷多于一份 ⇒ 拒；标签指的那一份是空的 ⇒ 拒；装的不是标签说的那一份 ⇒ 拒。算「输入不合规」那一类，走同一副 `[ERROR]` 外壳与同一行日志路径。

**一句话的内容是新写的**（`这次要做什么与它的载荷对不上（…）`）：老版没有这张纸，也就没有这句话。它只在纸被造错时才可能出现，正常使用撞不上，所以按「内部不一致」的语气写，不往使用者身上推。

**三处判断**：

1. **排最后**：纸被造错是工具的问题，不该让使用者先看到这种话、后看到他自己的参数错。
2. **模式零个／多个不归它**：那两条由模式判据报，这里见了 `ModeNone` 直接放手，不抢报告权。
3. **两种错分得开**：「同时装了两份」与「标签是命令，装的是脚本」说的话不同——修的地方不一样。

**验收**：三条坏样本 + 一条正样本 + 一条「被前一条拦下时不走到确认」全过。16 号单的 A/B 会拿这一条与老版对一遍措辞（老版在选项/参数检查里拦同类事）。
