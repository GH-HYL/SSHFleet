# 17: 站序——闸门该报的那句话，今天会被「清单读不到」顶掉

**要做的**：让「两份同时出错时先看到哪一句」与老版一致。现在不一样，A/B 里 15 条差异全是这一条长出来的。

**Blocked by**：05、06、07（要等材料自检与读清单都落地，才看得见这件事）。

**Status**：ready-for-human（三条改法都要动契约或动塔尖次序，等开发者定）

## 这件事是什么

老版 `modules/SSHFleet_Go/main.go` 的次序是：

1. 步骤 5：`CheckArguments`（313 行）——参数搭配、互斥、取值
2. 危险检测与危险确认（366 行）
3. 读清单（393 行）
4. 确认屏（414 行）

新版是：

1. 解析站：解析 argv → 材料自检（`-s`／`-u`／`-d` 的 stat）→ 读清单
2. 闸门：合规 → 危险 → 信封 → 确认屏

**问题**：材料自检与读清单跑在闸门之前，所以闸门本来要报的那句会被「起不来」顶掉。使用者敲 `-c "ls" -p /x`，老版说「-p 参数不能搭配 -c 或 -s 使用」，新版说「读取内容时发生错误: open : no such file or directory」。

## 已经收掉的一半

`internal/parse/argv.go` 的 `proceed` 判据已改成「模式定死、且纸上一个 `Problem` 都没有」才去读材料与清单。解析层已经判死的错（不认识的选项、缺值、多余参数、`-n`／`-t`／`-T` 取值、两个身份开关同给）因此不再被顶掉，A/B 真差异由 21 降到 15。

**剩下 15 条顶不掉**，因为它们是闸门判据，解析站手上没有：`-c` 只有空格、`-p` 配 `-c`、`--no-shell` 配 `-u`、`-u`／`-d` 缺 `-p`、`-u` 的 `-p` 不是绝对路径／不以斜杠收尾、`-d` 远端路径相对、改密配 `-p`／`-a`／`-k`、危险命令禁止档、危险提醒档、路径归一 `//`、大小写。

## 三条改法

**一、把「起不来」延后到闸门之后。** 解析站读清单或材料自检失败时不中断，把那个 `CannotStart` 挂在纸上（契约加一格），塔尖先走闸门，闸门放行后再报。
- 代价：动契约格子一格、塔尖加一个分支；ADR-0035 的「交接件不许比上一份宽」要为这一格写一句解释（它不往后递，只给塔尖）。**不破五站分工**。

**二、闸门里读清单。** 解析站只装 `-f` 原值与解析时判出的问题，真读文件与建节点挪到闸门「合规 → 危险」之后。
- 代价：闸门从「只裁量」变成「又读又判」，正撞 ADR-0032 第一条「校验归最懂那份材料的那一站」；闸门要多依赖归档包与文件系统，依赖表跟着改。

**三、解析站拆两个出口。** `parse.Run` 只出纸，另出一个 `parse.Manifest` 在闸门放行后调。
- 代价：撞出口白名单「至多一个函数」（ADR-0037 决定三，那是红线判据），要改检查本体。

**四、认下这 15 条。** 写进 A/B 的已知差异，等 09 逐字比对再统一处理。
- 代价：09 一定再撞一次，那时改的是已经通了的路。

## 验收

- [ ] 无 `-f` 且命令危险时，出的是危险框，不是「清单读不到」
