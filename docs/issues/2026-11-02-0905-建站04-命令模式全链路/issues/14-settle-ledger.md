# 14: 结算站算总账——把每台的事实解释成「总共怎么样」

**要做的**：跑完之后，把每台的分类对回本模式的成功分类，算出：总台数、跑完台数、没跑台数、成功几台、失败几台、连接成败几台、每个分类几台（带退出码）、每类下面哪些 IP、成功分类名、起止时间与总耗时。做完之后，报告站拿到的就是一张能直接写进 `report.txt` 的总账。

**Blocked by**：01（要有第二张纸）。

**Status**：ready-for-agent

## 要落的判断

- **成败只在这里解释**：分类是本模式的成功分类 ⇒ 成功；否则失败。有的模式没有退出码，不许拿退出码猜成败。
- **只算通用格**：附加格一个字段都不打开，原样递给报告站（ADR-0035 决定九）。
- 分类排序、同分次序、逐类 IP 的排列，逐字照老版（`result/statistics.go`）——这些次序是屏幕上看得见的。
- 「没跑台数 = 总台数 − 结果数」；中断造成的那笔差额本阶段不会出现（06 之前不会中断），但那一格**要留**，06 直接填。
- 不写终端、不写文件：只交一张纸。

## 验收

- [ ] 一份手搓的第二张纸（三台：成功、失败、没跑），总账逐字段写死断言
- [ ] 「成功率 100%」与「有失败」两种情形，分类排序与逐类 IP 排列与老版同一份输入下相同
- [ ] 附加格原样传递：造一个带标记的附加格，出来的纸里那个标记还在
- [ ] 红线：结算站入口一条新测试，只判「总账字段有值、附加格没被打开」
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿
