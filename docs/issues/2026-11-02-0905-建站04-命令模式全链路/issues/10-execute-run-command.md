# 10: 执行站跑一条命令——拼下发行、跑、收输出

**要做的**：会话建起来之后，把命令原文送下去跑，收回退出码、标准输出、标准错误与耗时。做完之后，`-c "uptime"` 对一台容器能真跑出结果。

**Blocked by**：09。

**Status**：done

## 要落的判断

- **下发行**（词表）：外壳 `sh -c '…'` + 环境段 + 执行身份（`sudo` 或登录用户）+ 解释器 + 正文。四段怎么拼、什么时候省哪一段，逐字照老版（`ssh/command.go`）。
- **`--no-shell`**：只服务 `-c`，剥掉外壳与环境段，命令原样下发（ADR-0031）。
- **超时**：取纸上「执行参数」里的命令超时；超时是**事实**（记一格），不是结论。
- **退出码**：目的命令自己的退出码进「退出码」那一格。会话被拒（sshd／登录 shell／sudo 拒了）与连不上是两件不同的事，原文与退出码来源各自照老版。
- **输出**：标准输出与标准错误都要收，收的时候不做编码转换（编码判断随 08 的语言开关）；收成的原文后面要给人看、也要进 `report.txt`。
- 出现「远端在问什么」的交互不在本单（那是代填，随 05 阶段）。

## 验收

- [ ] 四条路径各一次，对 `u1`：正常退出 0、非 0 退出、命令不存在（被拒的类型不同）、长命令超时
- [ ] 下发行的拼装逐条对照老版：`--no-shell` 与正常两种、sudo 与登录用户两种、有没有环境段
- [ ] 超时那一格是事实：结果里超时标志为真，且**还没有**成败结论
- [ ] 跑的过程中 context 被取消：这一台立刻收手、结果里那是「取消」这一格，不是「超时」（06 接信号之前，用测试里自己造的 context 验）
- [ ] 集成用例同上一条单的规矩（`integration` 标签，缺变量 skip）
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

### 2026-11-02：交付

**落了什么**：`execute/build.go`（下发行：外壳 + 环境段 + 执行身份 + 解释器；`--no-shell` 原样下发）、`execute/run_command.go`（开会话、stdin、超时、收输出、退出码、取消、输出整备）、`execute/stages.go`（本单用到的环节名）。`visit` 里「连上之后」那一段接上命令模式。

**纸上加了三格**（`contract.RunParams.Interpreter` / `.Env` / `.English`）。理由只有一条：执行站不回头读配置（ADR-0014、ADR-0015），这三样只能由解析站带上纸。前两格是配置原值，`export …;` 的拼法仍全在执行站一处；`English` 只负责下发行里那句 `export LC_MESSAGES=C`——判据表按语言选哪一套、提示语说什么，仍随阶段 08。

**推翻了原计划的一处**：原本打算 `english` 先固定 `false`，理由是「出厂配置本来就是 false」。动手后拿老版实测：`config/SSHFleet.conf` 第 52 行就是 `english = true`，老版下发行里恒有 `export LC_MESSAGES=C;`。按 false 拼，下发行立刻与发布版差一句，A/B 当场对不上。改成把配置原值带上纸。

**与老版逐字对过**（现场 `build/建站04_10_2026-11-02_1245/ab/`）：老版二进制对 u1 跑四种组合，从 `history/<run>/SSHFleetExec.log` 的「命令行：」抓出实际下发行，与新代码拼的串逐字节比。
