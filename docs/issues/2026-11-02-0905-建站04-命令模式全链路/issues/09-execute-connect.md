# 09: 执行站连一台——建连、认证、把原始错误翻成报文

**要做的**：拿第一张纸上那一台机器的 IP、端口、用户、密码（或私钥），连上去、认证过。做完之后，执行站能对一台容器建起会话，连不上时交回的是报文原文加分类，不是一句「连接失败」。

**Blocked by**：01（纸上要有那台机器）、02（加密开着时要解密码）。

**Status**：ready-for-agent

## 要落的判断

- **依赖**：老版走 `golang.org/x/crypto/ssh`，本阶段同样用它与老版同一个版本（`v0.57.0`）。这是规格第八节那份点名白名单的落点（开发者 2026-11-02 已点头）——**结构检查的白名单与 `go.mod` 的 `require` 同一次改**，白名单加名的方式按那一节办。
- **建连**：超时取纸上「执行参数」里那个连接超时，不在站内写死。
- **认证**：密码登录与私钥登录两条；给了私钥就不再试密码的先后顺序逐字照老版。
- **报文**：本工具自己陈述事实的那一行（`sshfleet.<环境>.<环节>: <描述>`）与远端原话都原样保留，不翻译、不裁剪（词表「报文」）。
- **服务端提示**（认证阶段 sshd 通过 banner 下发的 PAM 文本）要收进结果——老版是 2026-10 专门为此改的（ADR-0005），不收就等于丢掉「账号过期」这类原因。
- 收到 `context`，把它递到连接上；本阶段不响应信号，只保证 06 进来时不用改签名。

## 验收

- [ ] 对着 `u1` 容器连一次成功、一次密码错、一次端口不通，三种情形各交回一条可区分的事实
- [ ] 「账号已过期」那台（照 `docs/测试环境使用指南.md` 第四节造）拿到服务端提示，且它进了结果
- [ ] 集成用例带 `//go:build integration`，`go test ./...` 不加载它们；变量缺一个就整批 skip
- [ ] `context` 真的递到连接上：传一个已经取消的 context 进去，建连立刻以失败收场，不留后台 goroutine（`-race` 下跑一遍）
- [ ] 红线：执行站入口一条新测试，只判「收得到纸、连接成败那一格有人填」
- [ ] 白名单那一条：`go.mod` 只多 `golang.org/x/crypto`（连带它的 go.sum 条目），结构检查里那份名单同一次加名；已有违规样本一条都不少
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿
