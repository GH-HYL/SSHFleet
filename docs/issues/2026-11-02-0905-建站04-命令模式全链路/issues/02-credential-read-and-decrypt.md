# 02: 凭据包——读主密钥、解密码、报齐不齐

**要做的**：加密开着时，配置里的密码与私钥口令是**密文文件的路径**。做完之后，执行站拿着清单里那一格，能向凭据包要出明文密码；主密钥没读到时，凭据包交回「不齐」这个状态，由塔尖或解析站去说话——它自己不造屏、不退出。

**Blocked by**：无，可立即开工。

**Status**：done

## 边界

- 加密关着：本包**不参与**，凭据位置本身就是密码／口令（此时它的入口原样交回，一个字不动）。
- 主密钥从环境变量 `SSHFLEET_KEY` 读，读不到、格式不对，一律交回状态，不报错、不中断。
- 三条密钥命令（生成、看状态、转换）**不在这里**，随阶段 08 落 `keytool`。本包只有读、解、报状态。
- 横切叶子包：只许依赖标准库与契约（ADR-0032 第四条）。零第三方依赖——加解密走标准库。

## 验收

## Comments

### 2026-11-02：交付

**落了什么**：`credential` 包四个入口——`Status`（齐不齐）、`MasterKey`（读环境变量，去首尾空白）、`Secret`（凭据位置 → 明文：加密关着原样回、开着读文件再解）、`Decrypt`（0x02 格式：HKDF-SHA256 派生 + AES-256-GCM）。两个失败哨兵 `ErrKeyMissing` 与 `ErrBadCipher`，使用者下一步要做的完全不是一件事，所以不合并。

**格式照老版一字不改**：`base64(0x02 || nonce12 || ct||tag)`，HKDF 的上下文串仍是 `SSHFleet-credential-encryption-v2`。同一份凭据文件新老两版都要解得开——这是切换的前提。

**期望值怎么来的**：`testdata/password.enc` 里的密文不是本包加出来的，是**照抄老工程 `cipher.go` 的加密引擎**在 `build/建站04_02_2026-11-02_0930/gen/` 下生成的一份（主密钥与明文都写死在那份测试里）。所以「解得开」证明的是与老工具同一格式，不是自己跟自己。

**红线**：新增 `TestRedlineCredentialReportsState`（状态只有两种、入口在空值上不炸），名单 28 → 29 条，`redline.go` 加一行指纹；已有 28 条一条未改。

**验收**：`go build`／`go vet`／`gofmt -l`／`go test ./...` 全干净；17 包零违规、放行台账 0 条；`go.mod` 仍无 `require`（加解密与 HKDF 都在标准库）。
