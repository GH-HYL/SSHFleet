# 05: 解析站读清单——按 CSV 规则读，再按「清单优先、配置兜底」补字段

**要做的**：`-f` 那一格今天只判「原值能不能当一条记录」，不读内容。做完之后，解析站能真读出一份节点清单：一行一台，每台的 IP、端口、用户、密码、私钥、私钥口令都齐了，交进第一张纸的「对谁做」格。清单里的空列按配置兜底，写了的以清单为准。

**Blocked by**：01（纸上要有个格子装）。

**Status**：done

## 要落的判断

- 读：`-f` 既能是一个 CSV 文件，也能是一条内联记录——两种形态走同一套规则（词表「CSV 取值」）。
- 补：清单列 > 配置默认，**没有交互输入这一层**。密码那一格有个例外：该节点最终持有私钥时，配置默认密码不参与（清单里显式写的密码仍保留，作私钥之后的兜底）。
- 私钥与私钥口令**同源**：清单第 5 列配的私钥配第 6 列的口令；配置里的私钥配配置里的口令。
- 加密开着时，密码与口令那两格拿到的是文件路径——交给凭据包解（02 号单），解析站自己不解密。
- 本单**只读与补**，不判对错：IP 格式、重复、空行是 06 号单的事。

## 验收

- [x] `testdata/` 三份清单：正常、列数不足、含空列；补全之后的每台逐字段写死断言（期望值手写，不用被测代码算）
- [x] 内联形态与文件形态同一份内容，读出来逐字段相同
- [x] 「持有私钥时配置默认密码不参与」有一条专门断言
- [x] 清单读不成器（文件不存在、内容不是文本、列数对不上）时交回可分辨的失败，**屏上那句话由 `message` 造**
- [x] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

## 不在这单

## Comments

### 2026-11-02：交付

**落了什么**：`readManifest` 把 `-f` 的值读成一张行表。判定照老版：**先看原值能不能被系统找到**（是文件读文件，不是文件就当一条内联记录），再看内容读不读得了、空不空。CSV 口径一处写清（剥 BOM、`#` 注释行、空行、列数不限、引号成对时可含逗号与换行），后面 `-a` 代填直接复用这一份。

**表头那一句提示的着落**：老版读清单时顺手打一行「第一行不是IP格式，已移除表头行」。解析站自己不许写终端，所以这一屏挂在纸上的新一格 `Plan.Notices`，由塔尖在往下递之前打出去——**次序与老版一致**：提示在前、确认屏在后。纸的注释里写明了它为什么在这儿。

**与老版逐字对过的四种情形**：缺 `-f`（`读取内容时发生错误: open : …`）、空文件、既不是文件也不像记录、内联值带换行——四条的屏与退出码都与老版相同（`build/建站04_05_2026-11-02_1015/`）。

**一处刻意的写法**：`-f` 为空时把空串直接交给系统读一次，报的就是系统那句 `open : no such file or directory`——照老版办，不另写一句「没给 -f」。

**验收**：九条测试（文件、内联、表头、空文件、缺 -f、既非文件也非记录、带换行、语法错）全过；四项检查干净。
