# 05: 解析站读清单——按 CSV 规则读，再按「清单优先、配置兜底」补字段

**要做的**：`-f` 那一格今天只判「原值能不能当一条记录」，不读内容。做完之后，解析站能真读出一份节点清单：一行一台，每台的 IP、端口、用户、密码、私钥、私钥口令都齐了，交进第一张纸的「对谁做」格。清单里的空列按配置兜底，写了的以清单为准。

**Blocked by**：01（纸上要有个格子装）。

**Status**：ready-for-agent

## 要落的判断

- 读：`-f` 既能是一个 CSV 文件，也能是一条内联记录——两种形态走同一套规则（词表「CSV 取值」）。
- 补：清单列 > 配置默认，**没有交互输入这一层**。密码那一格有个例外：该节点最终持有私钥时，配置默认密码不参与（清单里显式写的密码仍保留，作私钥之后的兜底）。
- 私钥与私钥口令**同源**：清单第 5 列配的私钥配第 6 列的口令；配置里的私钥配配置里的口令。
- 加密开着时，密码与口令那两格拿到的是文件路径——交给凭据包解（02 号单），解析站自己不解密。
- 本单**只读与补**，不判对错：IP 格式、重复、空行是 06 号单的事。

## 验收

- [ ] `testdata/` 三份清单：正常、列数不足、含空列；补全之后的每台逐字段写死断言（期望值手写，不用被测代码算）
- [ ] 内联形态与文件形态同一份内容，读出来逐字段相同
- [ ] 「持有私钥时配置默认密码不参与」有一条专门断言
- [ ] 清单读不成器（文件不存在、内容不是文本、列数对不上）时交回可分辨的失败，**屏上那句话由 `message` 造**
- [ ] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿

## 不在这单

预检（06）；代填 `-a` 的内容层（05 阶段）；上传清单采集（05 阶段）。

## 做完之后

06 号单在它读出来的那批节点上做预检；07 号单的确认屏要摊开的就是这批人。
