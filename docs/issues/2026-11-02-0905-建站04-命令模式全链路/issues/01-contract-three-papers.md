# 01: 三张纸落格子——只装命令模式那一份

**要做的**：把这张链路要递的三张纸在契约包里定形——第一张补齐缺的三格（对谁做、执行资源、运行上下文），第二张（执行交结算）与第三张（结算交报告）从零落。做完之后，五个站能在纸上读写，谁填哪一格、谁读哪一格都有出处。

**Blocked by**：无，可立即开工。

**Status**：done

## 要落什么

- **第一张补三格**：节点列表（每台的 IP／端口／用户／密码／私钥／私钥口令）、执行资源（清单文件路径；脚本与代填随 05）、运行上下文（一段字节，密文；里面装执行命令与执行参数两样原值——备注不装，它已有明文一格 `RunParams.Remark`）。
- **第二张**：通用格（IP、连接成败、连接耗时、执行耗时、分类、退出码、超时、取消、错误原文、原文）、一个带标签的附加格（本阶段只装命令那一份）、全局格（总台数、起止时间、是否中断）、随行件（判据表、运行上下文密文）。
- **第三张**：总账、逐台明细、附加格原样、随行件（判据表、运行上下文密文、**执行资源**——`report.txt` 第一段的「节点清单：」那一行要用它）。
- **运行上下文的两段代码**：加密住解析站、解密住报告站，密钥写死两处各一次（规格第七节）。**本单把两段一起落**，不留一半——只落解密，报告站就无从验起；只落加密，纸上一段没人能读的字节。
- 契约里**一个函数都不许有**（含带接收者的方法），常量可以。加密与解密是两段普通函数，**不住契约包**。

## 验收

- [x] 三张纸的字段在契约包里各有出处注释：谁填、谁读（对得上 15 号工单的表格，第三张的随行件多一格「执行资源」）
- [x] 第一张纸的字段集 = 解析填的那些；闸门不另造纸（它交的是同一张 + 一个拒绝，格子一格不多）
- [x] 运行上下文封得住：纸上是一段看不懂的字节；同一份原值经「加密封 → 解密开」之后逐字段回来
- [x] 契约包仍零函数：`guard` 的契约纯净那条仍绿，样本不新增违规
- [x] `go build ./... && go vet ./... && gofmt -l . && go test ./...` 全绿；结构检查仍报 17 包零违规
- [x] 红线区不动：已有 28 条一条不改

## 不在这单

载荷另外四份（脚本、上传、下载、改密）的类型与它们的附加格——随 05。本阶段只落命令那一支；**加类型不是改结构**，05 进来时不该动这里的任何一格。

**落了什么**

- 解析站 `runmeta.go`：封。报告站 `runmeta.go`：解。**两段各写一遍**（规格第七节），密钥写死两处各一次。
- `buildPlan` 装上了执行资源那一格；`Run` 在计划成之后把原值封进 `Plan.RunMeta`，封不起来按「起不来」报——**不静默降级成明文**。

**一处形状上的判断（记在这里，免得下一个人当成漏项）**

第二张纸的附加格本阶段只有标签、没有内容：命令模式**没有**模式特有的事实，输出与退出码都在通用格里。其余四份随阶段 05 加字段，加字段是加格，不动这里的结构。

**封法的一个取舍**：nonce 取「明文 JSON 的 SHA-256 前 12 字节」，不取随机数。这样同一份原值封出来的字节永远一样，封与解两处就能各拿**同一条固定密文样本**对账——谁把密钥或格式写歪了，两边各有一条会红（`parse/runmeta_test.go` 比「封出来是不是这串」，`report/runmeta_test.go` 比「这串能不能开回同一份内容」）。代价：相同原值封出相同字节，泄漏的只是「这两次命令行一样」，那不是秘密。

**没做的**：解析站「真读一份配置 + 读清单 → 纸上三格都有值」的那条路径级测试没写——它要先有 05 的读清单，否则得在临时目录里备一套判据表才跑得起来。留下的判据是 `runMetaBodyOf` 的三条单测（装的是原值、命令模式不带目标位置、装进去的是副本）与两条封的样本比对。这条路径随 05 号单一起验。

**验收**：`go build`／`go vet`／`gofmt -l`／`go test ./...` 全干净；17 包零违规；红线 28 条未动；老工程零改动。
