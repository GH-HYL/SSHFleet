# 规格：阶段 04——命令模式全链路

**Status**：ready-for-agent

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

运维人员敲 `sshfleet -f nodes.csv -c "uptime"`，要的是三样东西：屏幕上逐台出一行、跑完一段统计、`history/<时间-模式>/report.txt` 里留着这次的全貌。

新工程今天走到闸门放行就停——打一屏「流水线还没接上」，退出码 1。也就是说，它连一台机器都没连过：解析只读到命令行，闸门只判该不该跑，后面的站还都是包注释。**这一刻它还不是工具，是个会挑错的空壳。**

## Solution

把「一台机器」这条路接通：**解析读清单、闸门摆确认屏、归档建本次的目录、执行站连上去跑、结算算总账、报告站出屏幕统计与 `report.txt`**，塔尖把五站串起来、照样只搬不判。

做完之后，`-c` 对一台机器跑一遍，屏幕过程、统计块、`report.txt` 与老版对得上（比对口径按上一张图 08 号工单 2026-11-01 的更新记录：一个节点的输出、分类与结果对得上，落盘几项按归一化）；一台失败时退出码仍是 0。

其余四种模式、中断、资源备份与两张表格、三条密钥命令，本阶段一律不碰。

## User Stories

1. 作为运维人员，我给一台机器的清单跑一条命令，屏幕上先出这次要做什么、问一句要不要继续，答 y 之后逐台出结果行。
2. 作为运维人员，跑完看到那段统计：总台数、成功与失败、连接成败、失败按分类排、成功分类名、总耗时，与老版同一个样子。
3. 作为运维人员，我在 `history/` 下找到本次的目录，里面有 `report.txt`、`terminal-output.txt`、`SSHFleetExec.log`，`report.txt` 第一段是我敲的那条命令与执行参数。
4. 作为运维人员，目标机连不上时，那一行给的是报文原文加分类，不是一句「失败」；整批跑完退出码仍是 0。
5. 作为运维人员，我答 n 或者带 `--yes` 跑，行为与老版一致（`--yes` 不问直接跑，日志里留痕）。
6. 作为运维人员，配置里开着加密，凭据文件是密文——工具照样能解出密码连上去（本机有主密钥时）。
7. 作为维护者，我看得出每台的结果由谁定：执行站交事实（原文、退出码、分类、超时、取消），结算站解释成败；执行站不写「成功/失败」这两个词。
8. 作为维护者，执行站跑的过程中往屏幕上写的那一处，是它自己那一处口子，不经过塔尖、也不经过报告站。
9. 作为维护者，某台机器的结果一行只拼一次，同时去屏幕、`terminal-output.txt` 与执行期日志三个地方——不是各拼一遍。
10. 作为维护者，三条纸的格子只住契约包；某个站想多要一格，只能回上游那条纵切去加。
11. 作为维护者，`archive` 只发路径字符串，不返回句柄、不替别人写文件。
12. 作为维护者，`go test ./...` 之后结构检查仍报「17 包零违规」，红线区新增的几条只判形状。

### 二、三张纸的格子（本阶段只装命令模式那一份）

按 15 号工单的 `## Answer` 落，**只落命令模式用得到的那一支**；其余四份载荷的类型与附加格随 05 加（加类型不是改结构）。

**第一张（解析交闸门）本阶段补齐剩下的三格**

| 格子 | 本阶段装什么 |
| --- | --- |
| 对谁做 | 节点列表：每台的 IP、端口、用户、密码、私钥、私钥口令（字段已按「清单优先、配置兜底」补全） |
| 执行资源 | 清单文件路径（脚本与代填的路径随 05；报告收尾备份原料时要用） |
| 运行上下文 | **密文一段字节**：执行命令与执行参数的**原值**，只有报告站解得开。**备注不装进去**：老版 `report.txt` 的执行参数段不印备注（`output/report.go:50-110` 逐行核过），而备注在纸上已有一格明文（`RunParams.Remark`）服务归档目录名；再装一份就是同一份原值两个来源（审计 A-甲 2） |

**第二张（执行交结算）与第三张（结算交报告）**：通用格、命令模式那一份附加格、全局格、随行件，全按 15 号工单的表格落。

**第三张的随行件要多带一样「执行资源」**：`report.txt` 第一段的「节点清单：…」那一行要用清单路径（ADR-0032 第四条：「『执行资源』那三条路径要跟到第三张纸——报告站收尾时用它」）。15 号工单第三张纸那张表没列它，是因为那几条路径当时只在收尾备份时才用得上；现在 `report.txt` 也要，按 ADR 补上。

**「成败」不进第二张纸**：执行站交分类，结算站把分类对回本模式的成功分类，才算得出成功几台、失败几台。

### 三、一条命令从 argv 到 `report.txt` 的路

```
argv ─解析→ 第一张纸 ─闸门→ 同一张 + 结论 ─执行→ 第二张（每台事实）─结算→ 第三张（总账）─报告→ 屏幕统计 + report.txt
                     │                    │
                     └─ 拒绝 ─塔尖退 1     └─ 刷屏（不跨站）
```

每站只认上一站交来的纸：解析不把配置全文递下去，闸门不把结论以外的数据塞进纸，执行站不回头读清单。

### 四、执行站只有一个口子，刷屏不出站

- 入口一个：递第二张纸该有的输入（闸门加过结论的那张），收「第二张纸」或「起不来」。按 `Plan.Mode` 分派，本阶段只实现命令那一支（其余分支随 05 加文件，不在这里写 `if 模式还不支持`）。
- 跑的过程中要上屏的（进度、每台一行）**不经过塔尖**；同一条结果行同时写进 `terminal-output.txt` 与执行期日志，**只拼一次**（12 号工单）。
- **屏幕的实体只有 `console`**：它交出一个 writer，执行站把它交给进度界面，画帧与结果行同一条流（13 号工单，已定）。执行站自己不 `fmt.Print`、不碰 `os.Stdout`。
- 执行站不拼字：「这一行长什么样」由 `message` 造，`console` 打。
- 取消（Ctrl+C）本阶段不作业务响应（随 06），但**执行站要收下 `context` 并把它递到每条连接上**——06 来了只需接信号，不动签名。

### 五、凭据包只做「读主密钥、解密码、报齐不齐」

- 加密关着：凭据位置本身就是密码／口令，本包不参与。
- 加密开着：凭据位置是密文文件路径，本包按主密钥解密；主密钥从环境变量读，读不到就交回「齐不齐」这个状态，**它不造屏、不退出**。状态交给塔尖，由塔尖说话（04 号工单的更新记录：主密钥预检查归塔尖，不归解析）——那一屏本阶段不做，随 08。
- 三条密钥命令（生成、看状态、转换）**不在本包**，随阶段 08 落 `keytool`。

### 六、归档包只建根、发路径

- 一个入口：给「模式 + 备注 + 当前时间」，建 `<history>/<时间-模式[-备注]>/` 与 `assets/`，交回一组路径字符串。
- 不返回句柄（句柄是可变共享物），不替别人写文件，不复制资源（随 07）。
- 日志包与报告站向它要路径；它自己不记住这次建了哪个目录（不设包级变量）。

### 七、运行上下文：密文，两处各写一遍，不新增包

ADR-0035 决定九给了两条路（单立一个小包，或两边各写一遍）。本阶段取**两边各写一遍**：加密住解析站、解密住报告站，密钥写死在这两处各一次。**两段代码的落点都在 01 号单**——解析站装第一张纸时封、报告站写 `report.txt` 时解，同一张单里成对落，免得只有一半。

理由：本阶段预算里再加一个包，就要动包清单、规则表与十七个包的对账——那是「动包布局」那一档，为一段两百行的对称代码不值。代价写在这里：**改算法要改两处，写歪了当场对不上**（这也是一条现成的判据：三张纸一路传到报告站解不开，就是这两处漂了）。

**与 ADR-0035 决定九那份清单的一处出入**：那一格写的是「执行命令、执行参数、备注」三样，本阶段只装前两样——备注不进 `report.txt`（`output/report.go:50-110` 逐行核过），而纸上已有明文一格 `RunParams.Remark` 服务归档目录名，装第二份就是同一份原值两个来源。已在 ADR-0035 末尾追加更新记录。

### 八、零第三方依赖改成一份点名白名单（**已点头，2026-11-02**）

老版的 SSH 走 `golang.org/x/crypto/ssh`、SFTP 走 `github.com/pkg/sftp`、进度界面走 `bubbletea`／`bubbles`／`lipgloss`、两张表格走 `excelize`。前两样没有标准库替代；后两样有，但代价是重写。

新工程到今天为止守的是「一条 `require` 都没有」，而且有一条结构检查在守它（类二「依赖方向」：模块之外的 import 一律报红）。所以这件事不是「加一行 require」，是要改检查本体。

开发者 2026-11-02 原话：**「零第三方依赖，我不知道当时是怎么拍脑袋写的，有现成的不用，那么造多少轮子。」**

据此改成：**这条不再守「零」，改成一张点名白名单。** 白名单住在 `guard` 的规则表里，与其余判据同住一处；模块之外的 import 只有名单里的那几个放行，名单外照旧报红。

- **本阶段点名**：`golang.org/x/crypto/ssh`（版本与老版一致，`v0.57.0`）、`github.com/charmbracelet/bubbletea`、`github.com/charmbracelet/bubbles`、`github.com/charmbracelet/lipgloss`（后三件是进度界面，与老版同版本）。
- **加一个名字**：记一行（`map.md` 的框架条目），不再单独点头——原则已经定了，剩下的是记账；但**新增一类用途**（例如运行期要起外部进程、要引入 cgo）仍属单独点头。
- **代价写在明处**：白名单本身要人核；供应链从「一个都没」变成「几个固定的」，升级时要连版本一起看。换来的是不重写 SSH，也不把手写 ANSI 重绘请回来。

后面两阶段按同一张名单加名：05 的 `github.com/pkg/sftp`、07 的 `github.com/xuri/excelize/v2`。

### 十、03 留下的东西，本阶段逐条处置

**替掉这四条过渡形态**（03 规格第八节）：

1. 放行之后打「流水线还没接上」并以 1 退 → 接上执行站，这句话删掉。
2. 第一张纸只有四格 → 补齐三格（第二节）。
3. `-f` 只判「原值能不能当一条记录」→ 真读内容。
4. 信封标签与载荷对不上只有形状、没有可判对象 → 本阶段落（08 号工单）。

**日志路径改由 `archive` 发**（03 过渡形态第 7 条）：`log.Init` 的签名不变，路径来源从「解析纯计算」换成「归档包给的目录」。

**删三处死导出**（03 质量审计复核推后的那一条）：`log.Logger.Path`、`message.RefuseLine`、`message.CannotStartLine`。

**`mask` 的「遮秘密」这一半在本阶段落地，落点是 07 号单**：确认屏要把内联清单里的密码遮掉、结果行与 `report.txt` 也要遮，三处都发生在 07 之后。横切包之间不许互相依赖，也不许报告站回头去用解析站的内部实现（那是反向依赖）——所以不「先顶一顶」，直接把这一半落了（认出秘密、把它遮住）；清单脱敏副本仍随 07 号阶段（那是另一件事，要认得出清单的列）。

**仍然留着、不属本阶段**：执行期日志里「原始选项/参数」那一行（`mask` 现在有了，但那一行的口径随 07 一并定）；日志里缺的那三行（随 09 判要不要补）。

### 十三、包与依赖

## Testing Decisions

- **接缝六处**（ADR-0037 决定三；本阶段新增三处——执行、结算、报告）：

  | 接缝 | 判什么 |

  | 执行站的入口（新） | 递一张纸、收第二张纸或起不来 |
  | 结算站的入口（新） | 递第二张纸、收第三张纸（只判形状与流向） |
  | 报告站的入口（新） | 递第三张纸、收要上屏的那一屏与写盘结果（只判形状） |

  横切包各有「那一件事」：`archive` 发路径、`credential` 报齐不齐、`log` 写执行期日志、`message` 拼那几屏。

- **红线区只判形状**：执行站入口判「收得到纸、字段谁填的、下一站读不读得到」；结算站入口判「总账的字段有值、没打开附加格」；报告站入口判「要上屏的类型是 `console` 收的那种」；`archive` 判「只回字符串」；`credential` 判「只回状态，不起进程」。**一条值断言都不进红线区。**
- **红线一律新增、不动已有 28 条**：每条新接缝各开新文件，不去改旧测试（改名字或往旧文件里加断言都会动指纹）。
- **自定义区跟着被测包走**：
  - 解析站：清单三种 `testdata`（正常、列数不足、含重复与坏 IP），期望值用写死的字面量。
  - 闸门：确认屏答 y／答 n／非交互三种交回值；信封标签与载荷对不上的样本。
  - 执行站：连接与执行走 `//go:build integration` 的用例，对着 `u1` 那台容器；分类用例喂一份固定原文，期望分类名写死。
  - 结算站：一份手搓的「第二张纸」（三台：成功、失败、没跑），期望总账逐字段写死。
  - 报告站：`report.txt` 整份逐字断言，期望串从老工程同一份输入跑出来录。
  - `credential`：密文与明文两份 `testdata`，主密钥用固定字节——**不读真环境变量**。
- **A/B 不进两区**：本阶段结束在 `build/` 下当天沙盒起新老两个二进制，`-c` 对一台容器跑一遍，比屏幕、`report.txt`、`terminal-output.txt` 与退出码；归一化时间戳、路径、耗时（口径按上一张图 08 号工单 2026-11-01 的更新记录）。
- **环境类失败不进两区**：容器没起、网络不通先修；修不掉就写明哪一步没法验。

## Out of Scope

- **其余四种模式**（脚本、上传、下载、批量改密）：随 05。本阶段执行站的入口只实现命令那一支。
- **中断与取消的响应**：随 06。本阶段只在签名里递 `context`。
- **资源备份、清单脱敏副本、「最新一次」链接**：随 07。
- **两张表格（xlsx）**：随 07。
- **三条密钥命令与主密钥预检查那一屏**：随 08。凭据包只做「读、解、报状态」。
- **`mask` 的清单脱敏副本**：随 07。「遮秘密」那一半本阶段落（07 号单），因为确认屏、结果行、`report.txt` 三处都要用；**不许拿解析站的内部实现顶**（站不许依赖站）。
- **`-a` 代填的内容层**：随 05。`-a` 是命令模式也能用的选项，本阶段只按 03 已落的那条判它「原值能不能当一个文件｜能不能当一条记录」，内容一行不读。
- **语言开关 `[locale]`**：随 08。
- **行为改动**：老版怎么跑新版就怎么跑；觉得该改的先记着。
- **老工程**：一个字不动。
- **约束类文件**：除第八节那份白名单（已点头）之外一律不动。
- **CHANGELOG**：本阶段不增条目——使用者能体验到的一样没变（从「还没接上」到能跑，是重构进度不是新功能）。

### 2026-11-02：12 号单交付——入口多两条路径、执行期日志的正文少了几级

**执行站入口多了两个参数**：`Run(ctx, plan, termPath, execLogPath)`。落点由归档包发、塔尖转手；本包收字符串而不收 `archive.Paths`——站多 import 一个包，红线测试就得跟着 import 第二个包（类六只许钉一个）。开不出来交「起不来」，这是本阶段第一条真会走到「起不来」的路。

**执行期日志照老版写节点明细，不写「那一行」**（2026-11-02 14:41 纠正）。12 号单判断里那句「三处同一个样子」起初被按字面落成了「日志也写那一行」，开发者当场纠正：「执行期日志不用一样，终端输出和 output 是给人看的，当然要一致，log 是记录的……我原来的代码不就是这么处理的」。现在：屏幕与 `terminal-output.txt` 同一段字；日志一级一条（成功一行 / 失败五级：连接、执行、错误详情、输出明细、分类），与老版真跑产物对过，**只少「登录方式 密码」那一截**（纸里没有那一格，猜会猜错）。

**「那一行里的秘密过 `mask`」这一条没有可遮的字段**：那一行每一格都是事实（IP、连接成败、耗时、分类、原文、退出码），没有凭据位；老版 `ResultLine` 也不遮（老版遮的是确认屏、`report.txt` 第一段、工具日志的「原始参数」行）。所以落成一条测试（密码不进两个落点），而不是往正文里做无差别替换——短密码会把正常输出一起糊掉，那是改行为。要做无差别兜底的话是一句话的事，等开发者定。

### 2026-11-02：13 号单交付——屏幕的流从 console 拿，类一多一条

**形状照规格那节落的**：`console` 多一个 `Writer()`（交出往标准输出写字节的那条流），执行站把它交给 `tea.WithOutput`，画帧与结果行同一条流；不加「每帧转交给 console」那层。类一（写终端）补第三条判据：这个入口的调用点只许在执行站，正反样本各一。**这是本阶段能动检查本体的最后一处**，之后 14–16 只碰站里的代码。

**`go.mod` 从一条 require 变成四条**（三件进度界面与老版同版本），间接依赖按 `go mod tidy` 那段清单落地；`go.sum` 同步。这是本工程第一次真的带第三方进来，与 04 规格第八节那张名单一致。

### 2026-11-02：14 号单交付——第二张纸多带一格「执行资源」

第三张纸的随行件要带执行资源（本规格第二节、ADR-0032 第四条），而结算站手上只有第二张纸——**所以 `ResultPaper` 也补了这一格**，执行站原样带过、结算站不打开。这是本阶段唯一一处「实现逼出来的契约加格」，加格按规矩属单独点头档；依据是本规格第二节已写死的「要跟到第三张纸」，落到实现上绕不开第二张纸。

成败判据落在 `message.IsSuccess`（分类 = 本模式成功分类），执行站与报告站读的是同一句；结算站没有第二套判法。排序照老版：失败分类数量降序、同分首现序、类内 IP 数值序、成功那一类排最后。

### 2026-11-02：15 号单交付——报告站的两样，字全在 `message`，缺的两样进运行上下文

**本节推翻本规格第二节的一句话**：「运行上下文」那一格原本写的是「执行命令与执行参数的**原值**」。报告站逐行核老版 `output/terminal.go` 后需要两样纸上没有的东西——`enable.show_category_tips`（统计块末尾出不出「提示：」）与判据文件的展示路径（「未归类」那三行引导里的一句）。开发者当日给了口径：「`report.txt` 这块是单独走个加密的上下文」「他要什么，解析站就给什么，反正一个解析站就直接全获取了，直接打包好加密」。**所以两格进 `RunMetaBody`，不进 `RunParams`**：消费者只有报告站，纸上因此一格都没变宽；代价是那一格的口径从「使用者敲了什么」扩成「报告站出那两样要用的原值」，已改 `contract/runmeta.go` 头注释，ADR-0035 末尾追加更新记录。

**版面的落点定了一条**：统计块与 `report.txt` 的**全部字**住 `message/stats.go`（`StatisticsLine` 交一句 `console` 收的话，`ReportText` 交整份文件），报告站只解上下文、遮秘密、上屏、落盘。理由与 12 号单同：字只在一处成形，报告站改版式就不该去动纸或去动终端。

**模式名字表又并进两列**：`modeTitle`（确认屏「执行模式」与报告同一行）与 `timeoutLabel`（执行超时／传输超时／改密超时）。确认屏那两处字面量改用它，屏幕输出一个字没变（`message` 的确认屏用例逐字钉着）。

**验的结果**：`report.txt` 与老版真跑（1 台、`exit 3`）**逐字节相同**；统计块与老版两次真跑（成功、失败）**逐字节相同**，含色码。四项检查全绿、`-race` 干净、17 包零违规、放行 0 条、红线 35 → 36（新增「报告站的屏幕那一段是话、落点由别人给、本包不 import 路径包」）。
