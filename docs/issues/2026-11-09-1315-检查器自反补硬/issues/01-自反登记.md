# 01: 检查器的自反登记

**要做的**：把检查入口文件与红线名单里的每一条测试做成登记；删掉任何一个，`go test` 红并说出缺了哪一项。

**Blocked by**：无。

**Status**：已完成（done）

- [x] 登记覆盖三样：检查入口文件本身、红线名单、每条红线的测试名
- [x] 删掉入口文件 → 红，报「登记缺一项：入口」
- [x] 从名单里删一条红线 → 红，报出是哪一条
- [x] 未改动时全绿；登记与名单同源，不另抄一张表
- [x] 登记机制本身写进「检查本体」，改它的程序同改红线区

## Comments

**2026-11-09 落地**

- 新文件 `internal/guard/registry.go`：`EntryFiles` 收三样里的第一样（`project_test.go`、`registry_test.go`、`exceptions.md`），`CheckRegistry` 用 `os.Stat` 判在不在——被删的文件解析不出节点，只能从「该在的不在」认。
- 第二、三样不另存：名单仍是 `redline` 表本体，测试名由 `CheckRedline` 拿代码去对，两个方向本来就有判据（名单有测试没了／测试不在名单里）。
- `CheckAll` 在台账 `Apply` **之后**调 `CheckRegistry` 与 `CheckLedger`：拿台账把「检查被拆了」放行掉，等于自己给自己开条子。
- **第二个触发点**：`registry_test.go` 自己也跑一遍真工程（`Dir: "../.."`）。所以删掉 `project_test.go` 时，剩下的这一条仍会跑 `CheckAll` 并看见缺项，不会静默全绿。
- 名单新增 `TestCheckRegistry`，指纹按工具给出的字面量落（15 个符号）。

**实跑（副本 `build/自反_20261109/SSHFleet2_Go`，原件零改动）**

| 拆解 | 命令 | 结果 |
| --- | --- | --- |
| 删掉入口 | `rm internal/guard/project_test.go && go test ./internal/guard -run TestCheckRegistry` | FAIL：`登记缺一项：入口（project_test.go 不在了）` |
| 从名单删一行 | `grep -v TestCheckLedgerRequiresFourCells redline.go` 后同上 | FAIL：`红线测试 TestCheckLedgerRequiresFourCells 不在名单里` |
| 还原 | 拷回两个文件 | `ok sshfleet2/internal/guard` |

**已知边界**：把所有测试文件一起删光，仍然没有东西能报（没有任何测试在跑）。这是「检查器只能由外部跑起来」的固有边界，写进报告未覆盖清单，不靠本工单解决。
