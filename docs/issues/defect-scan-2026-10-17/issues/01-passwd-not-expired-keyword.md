# 01: 改密模式的「密码未过期」不再靠一条死关键词撑着

Status: done（2026-10-18 实施）
Blocked by: None（可立即开工）

**要做的**：改密跑完、目标机密码没过期时，结果里显示的分类是「密码未过期」，并带着它该有的提示语——**不是「未归类」**。同时，改密配置里不再留一条永远匹配不上的关键词，配置校验允许「由程序定性、配置只留名字和提示语」的分类不再写关键词。

**被谁阻塞**：无，可立即开工。

---

## 为什么不能只删关键词

改密模式下目标密码没过期时，分类名是程序直接给的，不查判据表：

```go
// verdict.go
// 整场没出现过期信号 = 这台机器不需要改密
res.Category = catPasswdNotExpired   // "密码未过期"
```

所以配置里那条 `'密码未过期，跳过改密'` 永远匹配不上——**单删它不影响判定结果**。

删了之后会不会让分类名变成「未归类」？**查过，不会。** 判断「是不是兜底原文」的那一步，最后一行是「只有『执行失败(退出码N)』这类才算兜底」，其余一律不算——分类名走到那里会直接得出「不是兜底」。所以删关键词、连配置里那条占位一起删掉，上屏仍是「密码未过期」。

> 这一节原先写的是「那条死关键词一直在替分类名占位，删了会变成未归类」，**是错的**。用对照版实跑（删关键词但不做任何其他改动）验证：分类名照旧显示「密码未过期」。据实订正。

## 要做的事

1. **删掉死关键词**：改密配置里「密码未过期」分类下那条 `'密码未过期，跳过改密'` 删掉。
2. **保留分类条目**：`name` 与 `tip` 留好——`tip` 是使用者看到的那句提示，删了就没提示了。
3. **放宽配置校验**：分类的 `keywords` 允许为空（显式空列表或整个省略都算合法）。**但 `keywords` 里写成空字符串的仍要报错**——那是写错了，不是没写。

**MUST NOT** 把整个分类条目删掉。

> ~~4. 补内置清单：把「密码未过期」加进「由结构事实定性、不查表」的分类清单里~~
> **不做**：实跑对照证明不加它也不会变成「未归类」，那一步是显式短路、效果与末行返回相同，没有实际修复效果。按规范「观感类不算理由」，不加。
