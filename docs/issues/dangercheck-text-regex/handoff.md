## 一、这件事在做什么

SSHFleet 是 SSH 批量运维工具：一条命令并发跑在几十到几千台**生产服务器**上。它有一个「危险命令检测」——下发前先看一遍命令，命中规则就提醒。

**问题**：检测器按 shell 语法解析命令，而解释器表认可 15 种解释器，其中 8 种不是 shell。于是同一条 `rm -rf /etc`，写成 bash 拦得住，写成 python / perl / node / php / lua **整条溜过去**——**已实测，不是推断**。

**要做的**：判定方式从「语法解析」换成「对原文做纯文本正则匹配」。方向由开发者定案，见 `docs/adr/0019-danger-detection-matches-raw-text.md`。

**顺带做的**：规则从 38 条砍到 **17 条**（删掉日常运维动作、合并重复、出厂不再预置 `low`）。因为实测 31 条日常命令里有 24 条会弹警告——弹多了人就脱敏了，真正该看的也不看了。

## 五、最容易翻车的地方（按踩中概率排）

1. **01 会连带改配置，别以为是「只动代码」。**
   01 把 `regex` 改成数组后，`config/keywords_dangerous.conf` 里现存的 38 条**仍是字符串形态**，加载器会直接拒绝——**程序起不来**。01 必须同时把 38 条**只改形态、不改判定内容**地改成数组。哪条留/删/改档是 04–07 的事。

2. **Go 的正则不支持负向断言。**
   RE2 遇到 `(?!...)` 直接编译报错。「排除某写法」只能用**整行锚定 + 字符类排除**，且**不能省行尾锚定**——早退就看不见后面的排除项（`shutdown -h +10 -c` 就是这么漏的）。04 工单里有验证通过的写法。

3. **`Match.Line` 是单个 `int`，要改成能装多个行号。**
   牵涉：`internal/dangercheck/judge.go:20`（字段）、`internal/output/danger.go:80`（`%d` 渲染）、`main.go:312,334`（日志按单值取）、`internal/output/danger_test.go:20`（构造 `Match`）。漏一处就编译不过——编译期能拦住，是好事。

4. **警告框要显示 7 行，且不能撑破框。**
   每块：`来源 / 行号 / 内容 / 规则 / 示例 / 说明 / 级别`。`内容:` 超宽**截断**（它只是位置提示，使用者按行号回原脚本看即可）；**任何宽度下每行框线必须等宽**。现有 `TestDangerBoxLinesAreEqualWidth` 只覆盖短内容，**必须补超宽用例**。命中的规则**全列不折叠**。框内宽 56、字段显示上限 46，见 `internal/output/danger.go:13,17`。

5. **`firewalld` 的边界在 05 和 06 两处都写了。**
   `firewalld` 的 `mask` 与 `disable` **都归 medium**（06）；`sshd` / `network` 的 `mask` 归 high（05）、`stop` / `disable` 归 medium（06）。改一边要同时看另一边。

6. **`/tmp` 在 05 和 06 里结论相反。**
   05 说「`rm -rf` 一律 high」，06 说「`/tmp` 下不认」。**已定：由 05 的正则自己排除 `/tmp`**，不靠规则顺序去挡。05 工单的注里写了。

7. **`riskOrder` 是等级的唯一来源，`low` 一个键都不能删。**
   它同时干「校验规则取值」和「多命中排序」两件事。**MUST NOT** 在校验处特判放行 `low`——那会变成两处真相。

8. **语料要用带引号处理的 CSV 解析器读。**
   有 5 条多行脚本用引号包了多行单元格，用 `strings.SplitN(line, "\t", 3)` 按行切会直接错乱（老测试就是这么读的，03 要换掉）。**分隔符是制表符，不是逗号**。

9. **加载报错要「能定位、能理解、能处置」。**
   见定案 O。每条报错要指名哪条规则、哪个字段，并给可照抄的正确写法。适用于 `rules.go` 的**全部**加载报错，不只新加的。

## 七、最重要的一条：允许质疑，不强迫凑绿

**开发者原话**：「允许大模型在不通过的时候，分析一下语料是否合理，交给开发者去决策，咱们是允许提出质疑」。

规矩写在 spec 定案 I 和工单 09 的「不通过时怎么办」。摘要：

- 语料不通过时，先分辨是**规则错**、**期望错**、还是**两边都说得通**。
- **两边都说得通的不要自己拍板**——列出来交开发者。
- **MUST NOT** 为了让测试变绿而改期望值去迁就代码。那等于用代码给自己判卷。

**已预判会撞到的分歧**（工单 09 有列表）：

- 字符串里出现危险词会命中（`print("reboot")`、`echo "rm -rf /"`）。ADR-0019 说这是**接受的代价**；真实脚本里太频繁就该报告。
- `echo /etc | xargs rm -rf`：目标路径在 `rm` 前面，只认「rm 后跟路径」的正则抓不到。
- `shutil.rmtree("/etc")`：原文里没有 `rm`。
- `kill -1 -1`：语法上打不出去、语义上极危险。
- **字符串里的危险词无法用单条正则可靠区分**——前一个会话实测过：能做到「字面量全放过」，代价是漏掉 `sh -c "reboot"` 这类真正会执行的重启。这是已知边界，别加推断。

## 八、已定的决策速查（避免重新讨论）

| 项 | 结论 |
| --- | --- |
| 规则总数 | **17**：forbidden 6 + high 5 + medium 6 + low 0（出厂） |
| `low` 档 | **保留为合法取值**，出厂不预置，写进去不报错 |
| `mkfs` / `dd` | **不分主次盘符，一律 forbidden** |
| 规则新字段 | `reason`（为什么拦），与 `example` 都上屏，长度上限都是 30 个显示列，超宽**加载报错** |
| `example` vs `reason` | `example` 用于**定位**（大概什么命令触发的），`reason` 用于**理解**（为什么拦），两行都要有 |
| 停用规则 | 只校验 `name`，其余不查、不统计、不提示 |
| 多命中 | 同规则多行号合成一条；不同规则各列一块；**全列不折叠** |
| 语料 | 127 条迁入 `modules/SSHFleet_Go/testdata/`，老 81 例删除 |
| 按机器分组 | **不做**，所有机器一套规则 |
| `handoff.md` | 实施完成后删除 |
