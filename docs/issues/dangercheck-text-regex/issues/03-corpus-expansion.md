# 03: 测试语料补齐非 shell 与注释用例

## 背景

现语料 `testdata/dangerous_cases.tsv` 共 81 例，**全部是 shell 写法，零非 shell 用例**（`dangercheck_test.go` 里注明来自旧工程）。而本议题要解决的正是非 shell 漏报——**用一份全 shell 的语料去验收「非 shell 也能拦」，等于没验**。

语料还偏斜得厉害：`递归删除根目录` 19 例、`递归强制删除` 12 例、`递归删除系统目录` 4 例，其余多为 1 例；`运行级别6`、`杀死所有进程`、`设置SGID权限` **零覆盖**（见 `audit.md` 第七节）。

还有 11 行第三列为空——`none` 档不要求具体规则名，扩列时要照顾到。

## 要做的事

1. **补非 shell 用例**：8 种非 shell 解释器的写法都要有——`python` / `luajit` / `lua` / `node` / `nodejs` / `perl` / `ruby` / `php`。每种至少一条真危险命令 + 一条同语言的普通代码（用来防误报）。
2. **补注释剔除用例**：整行注释、行尾注释、引号内 `#`、`$#`、`url#frag`。每条都要写明期望（剔掉了还是保留了）。
3. **补旗标变体**：`-rf` / `-fr` / `-r -f` / `--recursive --force`，按 `spec.md` 定案 H（规则自己列全旗标写法）逐条给期望。
4. **补间接执行**：`bash -c` / `eval` / `xargs` / `ssh` 远端。现语料 `dangerous_cases.tsv:39-45` 这 7 行全是 forbidden，新方案下要**逐行重新给期望**，不能照抄。
5. **补多命中行号用例**：定案 B 定了「同规则多命中合成一条、列出全部行号」，要有一条能看见 `行号: 3, 7, 12` 的用例。
6. **给零覆盖的规则补例**：`杀死所有进程`、`设置SGID权限`（`运行级别6` 在 04 里并入别的规则，不必单独补）。
7. **扩列**：现格式 `命令 \t 期望级别 \t 期望规则名` 三列不够用，至少还要表达「期望命中哪几行」。**新增列的取舍由本工单定，定了写进规格的「测试决策」**。

## 硬约束

**期望值 MUST 独立于被测代码**——哪条命中、命中哪个级别，由人按「这条命令在 200 台生产机上执行会怎样」判断后写下，**不许拿规则文件反推**。反推出来的语料只能证明「代码等于代码」：规则把 `/etc` 写成 `/ect`，语料里也照抄 `/ect`，测试照样全绿。

**怎么让「反推」在结构上做不到——每行必须带「理由」列**（2026-10-19 定，方案 A）：

- 语料从三列扩到**六列**：`命令 \t 期望级别 \t 期望规则名 \t 理由 \t 翻译自 \t 备注`。
- **「理由」列写的是场景判断**，例如「删掉系统配置目录本身，200 台同时执行即灾难」「清 `/tmp` 临时文件是每日例行」。
- **「理由」列 MUST NOT 出现正则字符**（`\b`、`[0-9]`、`(?:`、`.*`、`^`、`$`）。出现即说明这一行是在复述正则，不是在作场景判断——这样的行不合格，要重写理由或删掉该行。
- 这条约束的作用：**抄的人写不出理由**。规则文件不告诉你「为什么删 `/etc` 危险」，只有生产常识告诉你。

> 为什么不用「随机抽查人工确认」：抽查是**动作**，不是**机制**——这次抽了下次未必抽，抽 10 行也未必覆盖到被改坏的那一段。要求每行写理由，是把判据钉在语料里，日后任何人改语料都得先回答「为什么」。

- [ ] 至少 1 条能看见多个行号的用例
