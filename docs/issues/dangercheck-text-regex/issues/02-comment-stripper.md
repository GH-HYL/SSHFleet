# 02: 去注释预处理器

Status: done
Blocked by: 01

**要做的**：判定前先把注释剔掉。做完之后，脚本里写一句 `# 千万别执行 rm -rf /` 不会再把整批作业拦下来；而真正写在代码里的危险命令照样拦得住。

---

## 背景

现引擎靠 shell 语法树天然分得清注释与代码。换成纯文本正则之后，**注释里出现 `rm -rf /` 就会被当成危险命令**——这是必然要出的误报，所以必须先剔掉。

`spec.md` 的「定案」第 3 条（方案节）已定：整行注释、行尾注释、纯空白行不参与匹配；其余内容全部参与。

## 要做的事

纯文本预处理，**不依赖任何语言解析**：

1. **整行注释**：一行以 `#`（允许前面有空白）开头 → 整行剔掉。
2. **行尾注释**：从行内未加引号的 `#` 起到行尾 → 剔掉。
3. **纯空白行**：剔掉。

**不是注释、必须保留**的三类（写得不对就会把真命令剔没）：

- **引号内的 `#`**：`echo "issue #123"` 里的 `#` 是内容，不是注释起点。
- **`$#`**：shell 里是「参数个数」，不是注释。
- **`url#frag` 这类紧贴字母的 `#`**：`http://x/#a` 里的 `#` 是路径片段。

## 行号怎么办（关键）

**剔除必须保住行数**。两种做法：

- 剔掉的内容**用空行占位**，行数不变；
- 或整行剔掉时**保留换行符**。

**不接受**「剔除后压紧行数」——那样行号会整体错位，使用者按行号去脚本里找，找到的是别处。

## 验收

- [ ] 整行注释 `# rm -rf /` 单独成行 → **不命中**任何规则
- [ ] 行尾注释 `ls -la  # 这里写 rm -rf /` → **不命中**
- [ ] 纯空白行 → 无影响
- [ ] `echo "issue #123"` → `#` 后面的内容**保留**（不误剔）
- [ ] `echo $#` → **保留**（`$#` 不是注释）
- [ ] `curl http://x/#a` → `#a` **保留**
- [ ] `rm -rf /etc  # 注释` → **照常命中**「递归删除系统目录」，且**行号正确**
- [ ] 一个 20 行、中间夹着 5 行注释的脚本：危险命令在第 15 行 → 报出的行号是 **15**，不是 10
- [ ] 剔注释**不改变总行数**（构造一个前后对比用例，断言行数相等）
