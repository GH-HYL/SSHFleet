# 01: 判定引擎改为纯文本正则匹配

Status: done
Blocked by: None（可立即开工）

**要做的**：把判定引擎从「按 shell 语法解析成命令段再判定」换成「拿整份原文直接跑正则」。做完之后，同一条 `rm -rf /etc` 不管写在 bash 里、python 里还是 perl 里，都能被同一条规则命中——不再是写 bash 拦得住、换种语言就整条溜过去。

---

## 背景

实测证据见 `audit.md` 第四、八节。最刺眼的一条：同一台机器、同一条 `rm -rf /etc`，写成 bash 是 forbidden，写成 python / perl / node / php / lua **全部漏报**；而 `print("reboot")` 反被判 forbidden。

原因在解析层：解释器表认 15 种解释器，其中 8 种不是 shell，非 shell 内容被硬当 shell 解析。

方向与代价已由 ADR-0019 定案，规格见 `spec.md` 的「方案」与「定案 A–H」。**本工单只做引擎替换，不碰规则内容**——规则怎么删、怎么并、怎么改档是 02–08 的事。

## 要做的事

1. **判定对象换成原文**：`-c` 的命令原文、`-s` 的脚本全文，解码后原样参与匹配。不再切分命令段。
2. **整份一次匹配**：对整份文本跑正则，**规则不得跨行**（不加 `(?s)`）。行号由命中起点的字节偏移反算（= 该偏移之前的换行数 + 1）；「内容」取命中所在行的原文（去首尾空白）——使用者看到的始终是自己敲的那一行。
3. **语法树解析退役**：解析成命令段、逐行回退、朴素分词、包装命令剥离、间接执行递归，**全部删干净**。`mvdan.cc/sh` 依赖随之摘除。
4. **`regex` 字段改为字符串数组**：只挂一条也写成数组；旧写法（字符串）**拒绝加载并指名报错**。不保留兼容分支。
5. **路径归一保留**，但降为纯文本片段替换：只把文本里的路径片段按字面整备（`//x` → `/x`、`/etc/` → `/etc`、`/a/../b` → `/b`）。**不得演变成分词或结构识别**；替换**不改变换行数**（否则行号口径就废了）。
6. **匹配用整备后文本，显示用原文**。
7. **读取侧与下发侧读同一份文本**：剥 UTF-8 BOM、去整块首尾空白，整备只做一次、一处来源（现在检测侧不剥 BOM、不 TrimSpace，与下发侧不一致）。

## 不要做的事

- **不要动规则的判定内容**（哪条留、哪条删、哪条改档）——那是后续工单。
- **不要改 `Analyze` 的签名**。它是测试接缝，见下。
- **不要保留任何兼容旧规则的加载分支**。
- **不要顺手补规则覆盖率缺口**（NVMe 盘符、Debian 包管理等）——见 `spec.md` 定案 G。

## 接缝

`Analyze` 保持导出、**签名不变**，这是能提的最高一处。语料测试、预处理测试、规则加载测试都从它进出。若实现中发现签名必须变，**先回来改规格的「测试决策」**，不许就地改接缝。

## 验收

- [ ] 同一条 `rm -rf /etc`，分别写成 bash、python、perl、node、php、lua 六种形式，**全部命中「递归删除系统目录」**（现只有 bash 与 ruby 反引号能中）
- [ ] 语法树解析相关代码删净，`go.mod` 里 `mvdan.cc/sh` 摘除，`go build` 通过
- [ ] `regex` 写成字符串（旧写法）时启动报错并**指名是哪条规则**；写成数组（哪怕单条）时正常加载
- [ ] 路径归一的三个 `//x`、`/etc/`、`/a/../b` 写法都能被正常整备；**换行数不变**（语料里含多行的用例，行号与整备前一致）
- [ ] 含 BOM 的脚本、首尾有多余空白的脚本，检测侧与下发侧看到的是同一份文本
- [ ] 现有一份真脚本（多行、带注释）跑一遍，行号指向正确的行，内容是那一行原文
- [ ] 规则里写 `(?s)` 或用 `.` 跨行匹配时，**不跨行生效**（构造一条能跨行才命中的用例，确认不命中）
- [ ] 警告框每块显示 7 行（来源 / 行号 / 内容 / 规则 / 示例 / 说明 / 级别），命中的规则**全列不折叠**；超宽的 `内容:` 行被截断且**框线等宽**（补超宽用例）

## 证据（2026-10-19 落地时实测，二进制在 `build/atest-1/e2e/`）

```text
$ SSHFleet -s u.sh -f nodes.csv --yes        # u.sh 第 2 行是 rm -rf /etc
╔════════════════════════════════════════════════════════╗
║                   ✕  发现禁止命令  ✕                   ║
╠════════════════════════════════════════════════════════╣
║    来源: 脚本: u.sh                                    ║
║    行号: 2                                             ║
║    内容: rm -rf /etc                                   ║
║    规则: 递归删除系统目录                              ║
║    示例: rm -rf /etc                                   ║
║    说明: 系统配置目录被删，整批难恢复                  ║
║    级别: 禁止                                          ║
...
exit=1
```

行号指向脚本第 2 行（BOM 与首尾空白整备后不偏移），七行齐全。`python3 -c 'import os; os.system("rm -rf /etc")'` 同样命中（改前不响）。
