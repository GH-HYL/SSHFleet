# 05: high 族重写

Status: ready-for-agent
Blocked by: 01, 02, 03

**要做的**：把 high 档收成 5 条。做完之后，「后果重、但可能真是你要做的」这一类——重启、递归删、清防火墙、删包、格式化非系统盘——都会在真正执行前被拦一次让你确认，而不再直接作废整批。

---

## 这一档的定位

high 是「**要你真看一眼，但拦不住你**」：打印警告框 → 问一次「确定继续？」→ `--yes` 下不阻断只留痕。

与 forbidden 的分界：**forbidden 是「执行了就毁、几乎不可能是本意」；high 是「后果重，但可能是本意」**。

## 五条规则

### 1. 系统重启（由 forbidden 降档）

吞并原「运行级别6」。必须覆盖：`reboot`、`shutdown -r now`、`shutdown -r +10`、`init 6`、`telinit 6`。

> **为什么降档（全表最需要解释的一处）**：批量重启是这类工具最正当的用途之一——内核升级后、滚动重启、维护窗口按计划重启，天天都有。留在 forbidden 意味着 `--yes` 下连重启都不让做，等于封死一种正当用法。
>
> **代价（明说）**：`--yes` 无人值守时，命令里混进一条 `reboot` 会照跑，只在日志留痕。原来 forbidden 能兜住这种情况。这是用「整批作废」换「正当用法可用」，开发者 2026-10-19 确认按此走。

### 2. 递归删除（由 medium 升档）

吞并原「递归强制删除」，原 medium 的「递归删除」也并进来。

必须覆盖全部旗标写法：`rm -rf`、`rm -fr`、`rm -r -f`、`rm -f -r`、`rm -R -f`、`rm --recursive --force`。

> 注：`rm -R -f` 与 `--recursive --force` 现引擎**已能命中**（靠旗标归一），换成纯文本正则后要靠规则自己列全——别以为旧测试过了就没事。
>
> **`/tmp` 排除写进正则本身**（开发者 2026-10-19 定）：`rm -rf /tmp/...` 属于日常清缓存，**不得命中本条**。排除由本条正则自己表达（`/tmp` 路径不进入匹配），**MUST NOT** 靠 06 的规则顺序去挡——两条规则各管各的，不依赖彼此的执行次序。

### 3. 屏蔽关键服务

原「屏蔽关键服务」，保留，但**名单要改**：`sshd` / `network` 留，**`firewalld` 移出**（CentOS 习惯性 `systemctl mask firewalld` 是日常，一票否决等于整批作废）。

> **与 06 的边界（必须对齐）**：`firewalld` 从本条移出后，它的 `mask` 与 `disable` **统一归 06 的「停止·禁用服务」（medium）**。理由：`mask` 与 `disable` 本是同一件事的两种强度，现在却分在 forbidden 与 medium 两档（实测：`systemctl mask firewalld` = forbidden，`systemctl disable firewalld` = medium），自相矛盾。
>
> `sshd` / `network` 相反：`mask` 留本条（high），`disable` / `stop` 归 06（medium）——按「会不会切断自己的管理通道」分，不按动词分。

### 4. 清空防火墙

原「清空防火墙规则」。必须覆盖 `iptables -F`、`iptables -F -t nat`、`ip6tables -F`。

### 5. 强制删包

原「强制软件包删除」。必须覆盖 `rpm -e --nodeps pkg`、`yum remove -y pkg`。
