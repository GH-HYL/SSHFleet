# 07: 移除出厂配置的 low 规则

Status: done
Blocked by: 01, 02, 03

**要做的**：把出厂配置里 6 条 `low` 规则删掉。做完之后，默认规则文件里不再出现 `low`；但 `low` **仍是合法档位**，使用者自己加一条 `low` 规则能正常加载、正常显示。

---

## 为什么出厂不预置、但档位保留

**出厂那 6 条 low 规则是日常运维动作**，每条都该删。但**档位本身不取消**——这是两件事：

- 删规则：这些动作弹出来只是噪音，删掉。
- 取消档位：会让使用者旧配置里写过的 `low` 启动失败，而多留一个取值**不增加任何维护成本**。

| 要删的 6 条 | 为什么删 |
| --- | --- |
| `软件包更新` | `yum update` 是例行运维 |
| `软件包删除` | `yum remove` 是例行包管理 |
| `强制安装软件包` | `rpm -i --force` 是装包的常规手段 |
| `清空命令历史` | 只影响事后追溯，不改系统状态 |
| `运行级别切换` | 与 `reboot` / `shutdown` 语义重复，`init 3` 在生产里罕见 |
| `普通服务重启` | `systemctl restart nginx` 是最高频运维动作 |

所以：`riskOrder` 仍是四档一个来源（`forbidden < high < medium < low`），`riskLevelText` 保留「低」；**不预置、不拒绝**。依据见 `spec.md` 定案 M。

## 要做的事

1. **规则文件**：删掉「为什么」一节表里那 6 条出厂规则。
2. **等级校验**：**不动**——`riskOrder` 保持四档，写 `low` 不报错。
3. **呈现层**：`output/danger.go` 的 `riskLevelText` **保留** `low` 分支（显示「低」），不要删。
4. **注释与文档**：规则文件头注释里关于等级的描述按「四档、出厂不预置 low」的现状写（文案同步归 08）。

> **一处容易漏的**：等级合法值的**唯一来源**是 `dangercheck` 包里那张排序表（`riskOrder`）。它同时干两件事——**校验规则文件的取值合法**、**给多命中排先后**。`low` 保留意味着这张表**一个字都不改**。**MUST NOT** 在校验处特判放行 `low`。

## 影响与代价（明说）

- 出厂不再提醒这 6 类动作。它们本就是日常，**这是刻意的取舍**。
- 使用者自己加的 `low` 规则照常生效、照常提示「低」。升级不会让他原有的 `low` 配置起不来。
