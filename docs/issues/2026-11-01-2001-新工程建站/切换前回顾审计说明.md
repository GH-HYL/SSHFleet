# 切换前回顾审计：审计说明

**给谁看**：这一次跑 `audit-retrofit` 的执行者。**技能本身一个字不改**——它管四段流程、锚、六节清单、只读与落档；这份只改三件事：**审什么、以什么为准、交什么**。

**为什么改**：技能默认「ADR 的决定是唯一基准，规格与工单是不可信的待审对象」。这一次的实情不一样——这里的四十三篇 ADR 是重构自己产出的，多数是「这块怎么搬」的施工决策，它们**本身就在被审范围里**；重构跨了一个多月、十个阶段，当初的规划有被现实推翻的（各 ADR 末尾的更新记录）。照原口径跑，审出来的只会是「文档之间对不对得上」，而真正要回答的是**这次重构做得好不好、能不能拿出去换**。

## 一、审什么：四个问题

**替代技能默认的轴切法**（轴按代码结构定，但这一次的结构从上往下就这四个问题）：

1. **架构成立吗。** 五站单向、塔尖唯一编排、契约包零函数、横切包只三条依赖边、话只从 `message` 出、闸门只许造拒绝——这些在代码里是**守住了**，还是**只写在文件里**？判据是拿一条真实改动走一遍：边界挡不挡得住、绕不绕得开。绕法就三种，挨个查：`_test.go` 的依赖方向豁免、`go:build` 标签、检查器读不到的写法。
2. **遵从度。** `guard` 六类与红线 40 条是不是真判据：违规样本报红、正样本不报；有没有为了过关改了检查面——放宽名单、收窄指纹、把断言挪去别处、把红线测试挪出自定义区。**检查本体被改过的地方，一条一条看是什么时候、为什么。**
3. **抗腐蚀性（本次重点）。** 拿数字说话：加一个选项、一条报文、一种模式、一个字段，分别要动几个包、几处？重复的密度？站点里有没有在拼话、回读源头、按老版特判？最近一个月「一处改动牵动五个包」的提交有几笔？
4. **等价性的边界。** 三十七场 A/B 与四条已知差异是 09 给的证据，这里不重跑，只审**口径有没有被悄悄放宽**：归一化是不是多了一样、场景是不是从表里少了、比法是不是改宽了（`cmp.py` 从整份比 XML 改成逐格比就是这类改动，要看它放宽了什么）。

## 二、以什么为准：锚分三层

技能的做法是「ADR 的决定抄成编号锚」；这一次锚要分三层，**下层与上层冲突时以下层为准**：

1. **重构的核心目的**：母规格 `spec.md` 的 Destination 与判据——老版行为等价、结构可持续、切换只改一行目录名。
2. **结构总纲 `ADR-0032`** 的五条决定（五站与权限表、塔尖、契约、横切边、话的出处）。
3. **各阶段 ADR 的决定**。

**实施期 ADR 与第 1、2 层冲突的，记「锚质疑」，单列在最前**，只抄证据与冲突，不许改写锚——改不改由开发者定。规格与工单仍然只是被审对象。

## 三、交什么

**要**（替代技能默认的 `报告.md` 三段）：

- **第一段·结论**：一句——重构目标达成到什么程度、现在能不能切；不能就写卡在哪一条。
- **第二段·架构与腐蚀的账**：第 1–4 个问题各一节，每条带 `file:line` 与「怎么查的」；抗腐蚀那一节要有数字（改一处牵动几个包、重复几处、特判几处）。
- **第三段·要开发者定的事**：锚质疑排最前；取舍两难的、两轴结论打架的原话并排；用 `/my-grill` 问过，问过的清单记进报告。

**不要**：逐条挑文档错（发现的另起一节「顺带」，按严重度排序，只提报不改）；重跑 A/B（除非怀疑证据本身）；把「ADR 之间措辞不一致」当发现——那是纸面摩擦，不是重构质量问题。

**保留**：四段流程、`audit-run-<日期>/`、交接清单六节、只读、不追对话、回执只收不改。

## 四、取证据的现成路径

- **结构**：`go list -deps ./...` 看实际边、`guard` 六条各跑一遍看报什么、红线名单与指纹、`git log --stat` 找牵动多包的提交。
- **腐蚀**：挑十处最近的改动（09 的收账、07 的遮、08 的密钥、09 的清单副本与引号），逐处数「改对一件事要动几处」。
- **等价边界**：`docs/issues/2026-11-06-1510-建站09-逐字比对/audit.md`、`spec.md` 第二节的归一化清单，与 `build/建站09_AB_2026-11-06_1535/cmp.py` 对一遍。
- **真机**：WSL 本机 sshd，地址与账号见 `docs/issues/2026-11-01-2001-新工程建站/交接.md`「环境」那一节；跑法与坑在同一份文件的「会咬人的几处」。

## 五、边界

- **只读。** 不改代码、不改检查面、不改文档；修复另开授权。
- **不重开旧决策。** 要推翻走议题加 ADR，不在审计里改。
- **不追对话。** 决策以 ADR 为准，会话记录不算。
- **发现缺陷先复现**：指得出一条跑过的命令才算数。
- **与已审过的分开**：09 的 `audit.md` 是 A/B 证据，04、07 各有一轮质量审计（命中条数与处置在各自 `Comments`），这次只审它们没审的那四件事。
