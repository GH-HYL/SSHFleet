# 协作约定：这个议题里，人和 AI 怎么说话

## 这份是什么

**它是给人看的谈话备忘，不是议题内容。** 议题内容是 `spec.md` 与 `issues/`；进度与账本在 `map.md`。这一份不归载体那套规矩管，也不进任何验收。

存在的理由只有一个：AI 说话爱甩名词、爱一口气堆十个文件路径，人读不懂也记不住，只好单独拿一份文件把故事背景和词义交代清楚。所以它只做两件事——**交代背景、把话说成人话**。

**规矩少而稳**：想到新的就加一行，别回头改写旧行；它不是文档工程，不用维护得漂亮，也不用跟谁对齐编号。

一句话：**别让人替你补上下文。** AI 一口气能读几十个文件、能背出某一行的原文，人就做不到；所以凡是 AI 觉得「这不是很显然吗」的地方，都要主动交代清楚——它是谁、在哪、跟当下这件事什么关系。

违反这份的典型长相：上来就说「请你拍板甲、乙、丙三条」，人不知道这三条指的是哪个文件里的哪件事，也不知道为什么现在要定它。

## 一、第一次提到一个名词，先给它三样

**它是什么、它在哪个文件、它跟当前这件事什么关系。** 三样缺一样，就当没交代。

反例（真实发生过）：

> 「规则表的形态，Go 表还是外部文件？」

——不知道规则表是什么、在哪、为什么突然要定它。

正例：

> 「我在新工程的检查包里要放一张**规则表**：一行一个包，写明每个包属于哪一类、能依赖谁。后面六类结构检查都要拿它当尺子，它也是『包清单没走样』的证据。这张表现在没地方放：同一张工单里写了『每个包只有一个文件、只准有注释』和『不写任何实现』，两种装法各撞一条。」

**为什么这条比别的都重要**：AI 的默认假设是「你和我看到的是同一份上下文」。事实不是——人手上是聊天窗口，不是文件树。

## 二、要人拍板之前，必须给三样

1. **背景**：这件事从哪儿冒出来的，不解决会卡在哪一步；
2. **两条路**：每条一句话说清是什么做法；
3. **代价**：每条各写「选它会付出什么」，不要只写好处。

**缺一样就不许问。** 只给两条路不给代价，等于让人猜。

**不许用「甲、乙、丙」或「方案 A、B」当代号**——代号逼人回头翻上文。直接说事情的名字。

## 三、一次只问能当场答的

- **一件事一段。** 不许把五件不相干的事压成一张清单，让人对着五个文件回忆。
- **每段标题写事情本身**，不写编号。
- **先说结论，再说理由。** 人看完第一句就该知道你要他做什么。
- 涉及改文件时，说清**改哪个文件、改哪一句、为什么改**；只报文件名等于没说。

## 四、动嘴和动手的边界

- **写代码要「授权开工」四个字。** 一次管**一个阶段**，从开工到该阶段交付；期间这个阶段里新拆出来的工单不必再要一次授权，换阶段要重新授权。「改吧」「继续」「动手」都不算。写文档、拆工单不受限。
- **约束类文件**（`AGENTS.md`、`docs/个人开发规范.md`、`docs/agents/` 下的口径、`.gitignore`、红线的名单与指纹、放行台账、检查本体、包的分法与规则表）要**单独点头**，不走「授权开工」那道门。这一条与第七节第 6 类是同一件事。
- **定不了才问**；定得了的自己定，定完写进 `map.md` 的「框架条目」。

## 五、常用词（第一次见也能懂）

| 词 | 白话 |
| --- | --- |
| 老工程 / 新工程 | `modules/SSHFleet_Go/`（冻结只读，现役发布版）／`modules/SSHFleet2_Go/`（重构目标，十七个包的骨架已建、零实现） |
| 五站 | 主干按顺序分五段，各一个包：解析 `parse` → 闸门 `gate` → 执行 `execute` → 结算 `settle` → 报告 `report` |
| 塔尖 | 入口那个 `main` 包，只做三件：分叉走哪条路、把信封交给下一站、给退出码 |
| 契约包 `contract` | 站与站之间递的那几张纸（结构体）住这儿，只放类型与常量，一个函数都没有 |
| 横切包（八个） | 每站都可能用到、但本身不产业务数据的小包：`console` `log` `ask` `archive` `exitcode` `credential` `message` `mask` |
| 密钥管理包 `keytool` | 那三条不进流水线的小命令（生成主密钥、看状态、转凭据） |
| 检查包 `guard` | 结构检查住这儿；红线区也跟它同住。检查跟着 `go test` 跑，不另加命令 |
| 规则表 | 一行一个包，写明「属于哪一类、能依赖谁」。所有检查拿它当尺子，也是「包清单没走样」的证据 |
| 红线区 | 一组只验证**结构**、不验证**数值**的测试：谁往终端写字、谁依赖谁、契约里有没有函数。改它要走议题加 ADR |
| 放行台账 | `guard/exceptions.md`，一行一条：哪条红线、哪个位置、为什么放、谁批的。每次跑测试先打一行「当前放行 N 条」 |
| 迁移地图 | 04 号工单的 `## Answer`：老工程每一块搬到哪个包、那个包只干哪一件 |
| 议题 / 工单 | 议题是一个目录（一份 `spec.md` + 一堆工单）；工单是 `issues/NN-*.md`，一单一会话 |
| 授权开工 | 那四个字，写代码的前置条件 |
| ADR | `docs/adr/` 下的决策记录：为什么这么定、否掉了哪些备选 |

词表的完整版在仓库根 `GLOSSARY.md`。

## 六、子 Agent 怎么用

### 什么时候派

- **冷读审计**：判「这套文档有没有洞」，要的正是没有上下文的视角——子 agent 只读文件，读到什么就是什么。
- **大批量只读检索**：要在几十个文件里找同一件事的痕迹。
- 不适合派：需要跟人来回确认的事、要改文件的活。

### 怎么派

**必须带 `run_in_background: true`，派完立刻往下走。** 不在同一轮里等结果——不写「等它跑完」，不调阻塞式的取结果接口。

### 怎么收

- **下一轮再收。** 它跑完会自己把结论送回来。
- **被打断、看到「Tool ran without output or errors」时，先去翻 `subagents/agent-*.jsonl` 把已经产出的内容捞出来**，别原样重发一遍——重发既费时间，还会得到一份和上一份不完全一样的结论。

### 派活时必须写明两句话之一

- 「**只做只读分析**」：不许建文件、改文件、删文件，不许跑会改状态的命令。
- 「**本轮已获授权开工**」：允许改代码。

没写这两句，按未授权办——子 agent 和主会话守同一条规矩。

### 子 agent 的结论不原样转

它没有上下文，会指着一条原文说得很肯定，也会指错。**转述之前先核引用**：它说的那句话在不在那个文件里、那一版是不是已被后来的「更新记录」推翻。**核不动的就点名说是误报**，别为了「它说得挺像」混进结论里。

### 不许写记忆

子 agent 不许生成任何记忆类文件（`MEMORY.md`、日志、画像）。这条对主会话同样有效。

## 七、什么该问人，什么自己定

**接手的人不是程序开发员，也不打算替 AI 做技术功课。** 判据只有一条：**这件事会不会落到人身上。**

**自己定的**（定完写进 `map.md` 的框架条目，一句话说清为什么）：

- 包**里面**怎么分文件、怎么命名；一张数据表写成代码还是写成独立文件；
- **用什么手段查、怎么查、查几遍**——检查是过程产物，不影响工程跑起来，只要最后查得清、结论立得住，怎么着都行；
- 测试怎么写、错误怎么处理、两种技术做法之间怎么选；
- 同一件事有两条路、代价都落在代码内部。

**必须问的，只有六类**：

1. 会改变使用者看得见的东西——屏幕上的字、退出码、报告里的一段；
2. 会动老工程、发布脚本、版本号、`.gitignore`；
3. 要花钱，或要人本人去真机上操作；
4. 定死了以后改起来很贵，而且人得知道这件事；
5. 人明确说过「这条我要拍」；
6. **会让检查闭嘴或动包布局的**：规则表、红线名单与指纹、放行台账、检查本体、包怎么分／要不要多一个包／包改不改名、契约里的格子；以及仓库级约束文件（`AGENTS.md`、`docs/个人开发规范.md`、`docs/agents/` 下的口径、`.gitignore`）。

**问的形态**仍是第二节那三样（背景、两条路、代价），但**开头先用一句人话说清「这事会影响你什么」**；影响不到人的，就别问。
