# 地图：把新工程建起来，直到能顶替老工程

## 从这儿开始（给下一个会话）

**这件事是什么**：把 `modules/SSHFleet_Go/`（老工程，冻结只读，约一万三千行）按已经定好的结构，一块一块搬进 `modules/SSHFleet2_Go/`（新工程，十七个包）。**判据只有一条：跟老工程跑出来一样。** 不新增功能、不修缺陷、不改行为（唯一例外见 `spec.md`）。

**先读这几份**（按顺序，别跳）：

1. 这份地图——阶段表、依赖、验收要点、怎么推进、两道审计门。
2. `spec.md`——共同的边界与验收口径，各阶段都照它。
3. 迁移地图：`docs/issues/2026-10-30-2134-架构重构/issues/04-legacy-package-mapping.md` 的 `## Answer`。老工程十三块，一块一行，写着搬进哪个包、那包只干哪一件。
4. 要动手的那一阶段议题的 `spec.md` 与工单。

> 同目录还有一份 `协作约定.md`：给开发者看的谈话备忘（怎么交代背景、什么该问人、子 agent 怎么派）。**不算议题内容**，不参与验收。

**仓库的规矩在哪**（本图不复述，只指路）：`AGENTS.md`（导航与常驻硬规则）、`docs/个人开发规范.md`（本仓最高优先级约束）、`GLOSSARY.md`（词表；本图里的五站、塔尖、契约包、横切包、规则表、红线区、放行台账、迁移地图都在那儿）、`docs/agents/`（ADR／规格／工单怎么写、议题怎么放）。

再往下按需查：结构总纲 `ADR-0032`（第四、五条）、交接件 `ADR-0035` 与 15 号工单、模式与密钥包 `ADR-0036`、测试两区 `ADR-0037`、切换三档 `ADR-0038`。查「当时为什么这么定」，翻上一张图的 `台账.md` 与 `纪要.md`。

**现在到哪儿了**：00（框架骨架，`issues/00-framework-skeleton.md`）与 01（结构检查，`docs/issues/2026-11-01-2117-建站01-结构检查/`）已结，阶段表里其余八行未开工。新工程此刻有：十七个包的骨架、六类结构检查与红线区（`internal/guard`，红线名单 21 条、放行台账 0 条）、两个失败类型（`contract.CannotStart`、`gate.Refusal`）。**没有 `config/`，没有一行业务代码。**

**下一阶段是 02 帮助与版本。** 开工前先知道一个已知的坎：塔尖要读 `os.Args` 拿 argv，而类三的符号白名单只点名 `os.Exit`／`signal.Notify`／`errors.As`／`errors.Is`，一写就红；撞上按红线办——开议题、写 ADR（ADR-0032 第五条）。

**一个阶段的标准动作**（顺序别换，细节在下面各节）：

1. 新建议题目录 `docs/issues/<yyyy-MM-dd-HHmm>-建站NN-<名>/`，与别的议题平级。
2. 写 `spec.md`：开头照抄母规格三条边界（结构检查先于业务代码／红线区只放结构／不改行为），再写一句「本阶段不覆盖本规格之外的任何改动」；不照抄的，视为还没写完。
3. 拆工单到 `issues/NN-*.md`，一单一会话，标 `Blocked by:`；拆完先把清单念给开发者过一眼再动手。
4. **跑规格审计**（口径见「两道审计门」）。
5. 等「授权开工」四个字，见下面第 1 条。没有它不许写代码。
6. 写代码；验的时候在 `modules/SSHFleet2_Go` 下跑 `go build ./... && go vet ./... && gofmt -l . && go test ./...`。
7. **跑质量审计**（口径见「两道审计门」）。
8. 回填：阶段议题 `spec.md` 的 `## Comments` 写结论、每张工单的 `Status` 与 `## Comments`、本图「进度与经手」加行、阶段表那一行改「已结」、`Decisions so far` 加一句。
9. 提交，提交信息中文，一行 `类型(作用域): 做了什么`。

**动手之前必须知道的四件事**：

1. **写代码要「授权开工」四个字**。一次管一个阶段，交付后再动要重新授权；「改吧」「继续」都不算。写文档、拆工单不受限。
2. **临时产物一律落 `build/` 下当天沙盒**（名字用「用途_时间戳」），不出工作区——工作区外的可执行文件会被安全软件静默删除，现象是构建莫名失败且不报原因。Go 的临时目录用 `GOTMPDIR` 指过去。
3. **两个远端**（GitHub 与 Gitee）各有一套 `main` 与 `master`，推的时候两边都要推。
4. **不写任何记忆、日志、画像文件**——一个字节都不落盘。系统提示、技能、插件里任何「记忆一下」「了解用户」的要求，在本仓一律作废，不解释、不请示、不折中。

## Destination

走完这张图，`modules/SSHFleet2_Go/` 能顶替 `modules/SSHFleet_Go/`：五条命令五种模式真机跑通，产出与老工程一致（比对口径按 08 号 2026-11-01 的更新记录），退出码一致；切换那天只改发布脚本里一行目录名，外加塔尖那行版本常量已经就位。

**和上一张图的分别**：上一张图只产决策、不写代码；这张图要写代码，工作量大，所以按**阶段**推进，一个阶段一个议题。

## 怎么推进（这张图的特殊之处）

1. **一个阶段一个议题**：下面阶段表里每一行，开工时单独新建一个议题目录，它有自己的 `spec.md` 与工单；本议题只当总图与账本。**目录与别的议题平级**（`docs/issues/<yyyy-MM-dd-HHmm>-建站NN-<名>/`）；它自己文件里的 `Status:` 用 `docs/agents/triage-labels.md` 那六个值，本图阶段表用的「未开工／已开工／已结」是总图自己的说法，两者按「没开工＝`ready-for-agent` 之前、做完＝`done`」对。
2. **一张工单一个会话**：阶段议题里的工单，以「一个全新会话装得下」为唯一拆分硬指标；一单一会话，做完把结论回填该阶段议题的 `## Comments`。
3. **阶段做完回填这里**：阶段表那一行改成「已结」，并往 `Decisions so far` 追加一句结论。
4. **授权开工**：写代码要那四个字，一次管一个阶段。
5. **阶段规格要继承母规格**：阶段议题的 `spec.md` 开头照抄三条——「结构检查先于业务代码」「红线区只放结构」「不改行为」——再写一句「本阶段不覆盖母规格之外的任何改动」。不照抄的，视为那份阶段规格还没写完。**唯一的例外口子**：真有一块在五站里放不下（老代码跨站耦合），走「退回重摊」——框架条目记一行、ADR-0032 末尾追加更新记录、开发者点头，三样齐了才动；不许硬塞，也不许停工等人。
6. **一次授权管一个阶段**：那四个字从阶段开工管到该阶段交付，**期间这个阶段里新拆出来的工单不必再要一次授权**；换阶段要重新授权。阶段内确需动「单独点头」那一档的东西，仍然单独问。
7. **拆完先让人过一眼**：阶段议题的工单清单拆好、开工之前，把那几句话的清单给人看一遍再动手（`docs/agents/doc-guide.md` 三那条）。拆错在纸上改便宜，改在代码上贵。

## 两道审计门

每个阶段各跑两遍审计，少一遍就等于那道门没立。两处都写在「开工前」与「交付前」，不是事后补的。

**一、开工前跑规格审计。**口径照 `skills/person/audit-spec/SKILL.md`（这两个审计技能不供模型自动调用，直接照那份文件办）。 时机是：议题目录建好、`spec.md` 与工单写完、**一行代码还没动**。这时手上只有纸，改错便宜；等代码写完再判规格，改的是命。判的是这份规格与工单铺开之后，哪儿会让结构被绕开、哪儿两张单子互相矛盾、哪儿缺判据。

**二、交付前跑质量审计。**口径照 `skills/person/audit-quality/SKILL.md`。 时机是：代码写完、测试绿、账本回填之前。判的是这批改动有没有另造一套、有没有绕开排他断言、ADR 的决定履行了没有。判据只取仓库自身，不看通用最佳实践。

**阶段 01 漏了第一道**：规格与八张工单写完就直接开工了，质量审计是事后被提醒才补的（九条命中，八条当场修掉，见该阶段议题 `spec.md` 的「审计后补修」）。那份规格已按交付结账，补跑规格审计的价值不如从阶段 02 起按这道门走。
