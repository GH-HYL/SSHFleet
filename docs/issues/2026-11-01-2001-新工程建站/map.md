# 地图：把新工程建起来，直到能顶替老工程

## 从这儿开始（给下一个会话）

**这件事是什么**：把 `modules/SSHFleet_Go/`（老工程，冻结只读，约一万三千行）按已经定好的结构，一块一块搬进 `modules/SSHFleet2_Go/`（新工程，还没建）。**判据只有一条：跟老工程跑出来一样。** 不新增功能、不修缺陷、不改行为。

**先读哪三份**（按顺序，别跳）：

1. 这份地图——十个阶段、依赖、验收要点，以及下面「怎么推进」那四条。
2. `spec.md`——共同的边界与验收口径，各阶段都照它。
3. 迁移地图：`docs/issues/2026-10-30-2134-架构重构/issues/04-legacy-package-mapping.md` 的 `## Answer`。老工程十三块，一块一行，写着搬进哪个包、那包只干哪一件。

再往下按需查：结构总纲 `ADR-0032`（第四、五条）、交接件 `ADR-0035` 与 15 号工单、模式与密钥包 `ADR-0036`、测试两区 `ADR-0037`、切换三档 `ADR-0038`。查「当时为什么这么定」，翻上一张图的 `台账.md` 与 `纪要.md`。

**你的第一件事不是在这里动手**，而是给阶段 01 开一个新议题：

- 目录 `docs/issues/<yyyy-MM-dd-HHmm>-建站01-骨架与结构检查/`；
- 里面按同一套载体来：`spec.md` 写这一阶段做成什么样（开头照抄母规格那三条边界，见下面「怎么推进」第 5 条）、`issues/NN-*.md` 拆成工单（一单一会话）；
- 拆法现在不预写——那时才知道手上有什么。

**动手之前必须知道的三件事**：

1. **写代码要「授权开工」四个字**。一次管一个阶段，交付后再动要重新授权；「改吧」「继续」都不算。写文档、拆工单不受限。
2. **临时产物一律落 `build/` 下当天沙盒**（名字用「用途_时间戳」），不出工作区——工作区外的可执行文件会被安全软件静默删除，现象是构建莫名失败且不报原因。Go 的临时目录用 `GOTMPDIR` 指过去。
3. **两个远端**（GitHub 与 Gitee）各有一套 `main` 与 `master`，推的时候两边都要推。

## Destination

走完这张图，`modules/SSHFleet2_Go/` 能顶替 `modules/SSHFleet_Go/`：五条命令五种模式真机跑通，产出与老工程逐字一致，退出码一致；切换那天只改发布脚本里一行目录名。

**和上一张图的分别**：上一张图只产决策、不写代码；这张图要写代码，工作量大，所以按**阶段**推进，一个阶段一个议题。

## 怎么推进（这张图的特殊之处）

1. **一个阶段一个议题**：下面阶段表里每一行，开工时单独新建一个议题目录，它有自己的 `spec.md` 与工单；本议题只当总图与账本。
2. **一张工单一个会话**：阶段议题里的工单，以「一个全新会话装得下」为唯一拆分硬指标；一单一会话，做完把结论回填该阶段议题的 `## Comments`。
3. **阶段做完回填这里**：阶段表那一行改成「已结」，并往 `Decisions so far` 追加一句结论。
4. **授权开工**：写代码要那四个字，一次管一个阶段。
5. **阶段规格要继承母规格**：阶段议题的 `spec.md` 开头照抄三条——「结构检查先于业务代码」「红线区只放结构」「不改行为」——再写一句「本阶段不覆盖母规格之外的任何改动」。不照抄的，视为那份阶段规格还没写完。

## 不能碰的东西

- **老工程**：冻结只读。真要修紧急缺陷，先开一个议题（冻结期的账本就是议题列表，切换前对账）。
- **老工程目录名**：`.gitignore` 里 `modules/*_bak*/` 那条会把它吞出仓库。
- **发布脚本与版本号**：两套并存期间只打老工程；改它留到切换那天，且只改目录名那一行。
- **老测试**：51 个测试文件不搬，纯算的按横切包的口子重写。
- **`docs/个人开发规范.md`、`AGENTS.md`、`docs/agents/` 下的约束文件**：要改得单独点头，不走「授权开工」那道门。
