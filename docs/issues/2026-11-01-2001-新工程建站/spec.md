# 规格：新工程建站（`sshfleet2`）

## Problem Statement

使用者（运维人员）对这次改造没有任何诉求——他们只要求手上的工具照旧：同样五条命令、同样的参数、同样的屏幕上那几行、同样的一份 `report.txt`、同样的退出码。所以这件事的风险不在「做不出来」，在「做出来了但和以前不一样」：漏一个模式、错一个退出码、报告少一段、中断之后少了收尾，都会在他们当场跑的时候变成事故。

而这套新结构要顶替的，是一个两年、一万三千行、由 AI 一批批写出来的老工程。它结构已经被磨掉了，但没有现成的对照物告诉你「搬对了没有」——除了老工程本身。

## Solution

照已经定好的五站结构与迁移地图，把老工程一块一块搬进新工程，**每搬一块当场验一块**，验的判据是「跟老工程跑出来一样」。搬到五条命令五种模式全能跑，就算建站完成；再走一遍切换判据，把它换成默认源。

搬的顺序不是按包的顺序，是按**一条能跑通的路径**：先让骨架立住，再让第一条命令从入口走到报告，先把一个模式做通，再把剩下的模式补齐，最后补那些只在特定时刻才用到的东西（中断、归档、密钥命令）。

## User Stories

1. 作为运维人员，我照旧敲 `sshfleet -h`，看到的帮助与版本跟以前一样，不多一行也不少一行。
2. 作为运维人员，配置写错、参数用错时，我拿到的是与以前同一句话、同一个退出码。
3. 作为运维人员，我用命令模式对一批机器执行，屏幕过程、每台一行、最后统计、`report.txt` 与以前逐字一致。
4. 作为运维人员，脚本、上传、下载、批量改密四种模式也能跑通，结果与以前一样。
5. 作为运维人员，跑到一半按 Ctrl+C，得到的是「提前收工」而不是硬杀：已完成的落盘、没跑的不造行、统计里写「未执行：N（执行被中断）」、退出码 130 或 0 按既定口径。
6. 作为运维人员，每次跑完的归档目录里，脚本、代填、清单副本都在，清单里的密码是遮过的。
7. 作为运维人员，主密钥相关三条命令与 `[locale]` 开关照旧能用。
8. 作为维护者，我要能在新工程里一眼看出每个包只干一件事：包的头注释一句话说清，判据指向 ADR 的对应条。
9. 作为维护者，结构被人破坏时（谁写终端、依赖反向、契约里塞函数、测试站错位置），跑测试就红，不靠人盯。
10. 作为维护者，切换那天只改脚本里的一行目录名，别的事情一件不碰。

## Implementation Decisions

**已定的决策不再讨论，直接照办：**

- 五站与塔尖：见 `docs/adr/0032-按五站分层重构工程结构.md`（第四条权限表、第五条塔尖）。
- 老工程每一块搬到哪个包：见 `docs/issues/2026-10-30-2134-架构重构/issues/04-legacy-package-mapping.md` 的迁移地图，一行一块；建包时那句话原样成为头注释。
- 交什么、装几格：见 `ADR-0035` 与 15 号工单。三张纸、四次交接；运行上下文是密文，只给报告站解。
- 五种模式怎么分文件、密钥命令住哪个包：`ADR-0036`。
- 结构与测试怎么拦：`ADR-0032` 第四条、`ADR-0037`。
- 切换判据：`ADR-0038` 与 09 号工单。

**本轮建站才定的事：**

- 新工程模块名 `sshfleet2`，目录 `modules/SSHFleet2_Go/`；配置原样搬一份，字段名与出厂值一字不改。
- **包清单以 04 号迁移地图为准**：五站 + 八个横切叶子包 + 凭据包 + 密钥管理包 + 契约包 + 塔尖。多的少的都要在工单里说清为什么。
- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **A/B 逐字比对不是常驻测试**：它是切换前的一次验收，抹什么、比哪几份按 08 号定的归一化规则。

## Testing Decisions

- **接缝只有三处**：塔尖的进程出入口（argv 进、屏幕与退出码出）、每个站的入口（递一张纸、收一张纸）、每个横切包的那一件事。红线区只许站这三处。
- **红线区**：只断言纸的形状与流向（字段在不在、谁填的、下一站读不读得到）、依赖方向、写终端、契约纯净。跑 `go test ./...` 就红，不另加命令。
- **自定义区**：跟着被测包走，怎么顺手怎么写；不许与红线区共用假件包。
- **配置对账**：新工程里一条测试，比两份 `config/` 的字段名集合（见 10 号工单）。
- **环境类失败不进两区**：机器没起、网络不通这类先修，修不掉就打标跳过，跳过不算绿。

## Out of Scope

- **任何功能新增与缺陷修复**：撞见了记下来，另开议题。
- **任何行为改动**：老代码怎么跑，新工程就怎么跑。觉得该改的（比如把备份挪到开工前）先记着，建完站再单独提。
- **改老工程**：冻结只读，只修紧急缺陷，且每动一次开一个议题（10 号工单的账本约定）。
- **改发布脚本与版本号**：切换那天才动，且只动目录名那一行。
- **改 `.gitignore`、不改老工程目录名**：`modules/*_bak*/` 那条规则会把改名后的老工程吞出仓库。
- **搬老测试**：51 个测试文件不迁移，纯算的按横切包的口子重写。

## Further Notes

- **临时产物一律落 `build/` 下当天那个沙盒**，不出工作区（工作区外的可执行文件会被安全软件静默删掉，现象是构建莫名失败且不报原因）。Go 的临时目录用 `GOTMPDIR` 指过去。
- **验证机器**：见 `docs/测试环境使用指南.md`；Podman 镜像要用已重新封装的，非必要不用 root。
- **两个远端**（GitHub 与 Gitee）各有一套 `main` 与 `master`，推的时候两边都要推。
- **现状与决策索引**：`docs/issues/2026-10-30-2134-架构重构/README.md`；过程与坑在 `纪要.md`，审计处置在 `台账.md`。
