# 02 改密参数：原值改名 + 新密码形态检查

Status: 待开工（ready-for-agent）
Blocked by: 无

## 要做什么

一条命令能独立验证：明文模式下给带首尾空白、或带换行的新密码，工具在开跑前报错退出；给中间带空格的密码则照原值设置。同时把装命令行原值的字段改名，让「这是原样值、不一定是密码」进到名字里。

## 为什么

两种给法现在两套规矩：清单第 4 列的密码会去首尾空白，命令行给的新密码一个字节都不动。带尾空格的密码能设上去而屏幕上看不见；带换行的值会被远端当回车，提交半截密码，报错指不到原因。字段名 `ChangePassword` 又在往「这就是密码」上引，加密时它装的其实是路径。

决策见 `docs/adr/0027-改密新密码拒收首尾空白与换行.md`。

## 边界

- **值一律不改写**：明文照原值当密码，加密当路径原样交 OS。不 trim、不删换行。
- **拦三条**：开头或结尾有空白（空格、制表符）；任意位置有 `\r` / `\n`；加密模式解出来的明文同口径。
- **中间的空格放行**（`我的 密码 2026` 是正常写法）。
- **报错用「问题 / 原因 / 提示」三行**，提示要求换一个密码，不是由程序替他清理。
- 空值仍走既有「内容为空」那条，不新造文案。

## 落点

- `internal/cli`：改密取值检查处，加在**读到明文之后、赋给解析后的新密码之前**——这样明文与密文两条路共用同一条判断。
- 同一包内字段改名，跟改 `batch` / `main` 的读取点；日志字段名 `change_password=` 属对外格式，不动。
- 测试：`cli` 改三条（原「保留首尾空白」那条的预期反过来）；`confirm` / `output` / `result` 里构造参数载体的字段名跟改。
- 使用者文档：`docs/1-使用手册.md` 的「批量改密」小节加一句限制；`CHANGELOG.md` 未发布段记一条（行为变更：从能设上去变成当场报错）。

## 验收

- [ ] 明文 `--change-password ' NewPass '`：报错退出，退出码 1，输出含「开头或结尾有空白」，且不进入执行
- [ ] 明文 `--change-password` 传含换行的值：报错，输出含「换行符或回车」
- [ ] 明文 `--change-password 'New Pass 2026'`（中间空格）：通过，参数屏与报告显示的都是原串的脱敏形态
- [ ] 加密模式：密文文件里解出的密码首尾带空白时报同样的错
- [ ] 全仓不再出现 `ChangePassword` 这个字段名（只剩带「原值」字样的新名）
- [ ] `go vet ./...` 干净、`go test ./...` 全绿
- [ ] 五个执行模式各跑一次：参数屏、报告、日志、归档目录名与改前一致
- [ ] 手册与 CHANGELOG 已按上面「落点」写完
