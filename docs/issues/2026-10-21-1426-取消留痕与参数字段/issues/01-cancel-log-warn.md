# 01 取消路径补一条日志留痕

Status: 已完成（done）
Blocked by: 无

## 要做什么

解释器回退确认答「否」、本次执行终止时，往工具日志写一条 warn：

```
[WARN] 执行已取消（脚本后缀没有配置解释器）
```

只加这一行。屏幕文案、退出码、`[ERROR]` 前缀一律不动。

## 为什么

同一次运行里，屏幕说了「已取消：脚本后缀 ".ps1" 没有配置解释器，本次执行终止」，日志却停在「解析结果」——事后翻日志的人分不清是使用者自己取消的，还是程序半路出了问题。危险命令确认答「否」那条取消是留了 `[WARN]` 的，两条同类路径不该两种待遇。

## 落点

- `internal/cli/`：解释器回退确认（答否时返回「使用者取消」的那个口子）——**不改**，它返回的取消语义已经够用。
- 主干：拿到该取消时补写 warn。原因文案在主干这处写，因为「是哪一个确认取消的」只有调用点知道。

不放进入交互器，也不改 `fatal` 的统一分支——理由见 spec 的「Implementation Decisions」。

## 复现（改前，2026-10-21 实测）

沙盒里跑一次，答 `n`：

```
cd build/atest-1021-repro1-plain          # 任一可用沙盒；本机另有 atest-1021-audit-1
printf 'echo hi\n' > demo.ps1
./SSHFleet -s demo.ps1 -f nodes.csv       # 提示「继续用 bash 作为解释器吗？ [y/N]:」→ 答 n
tail -4 history/SSHFleetTools.log
```

改前日志末尾（屏幕上「已取消：…」在，日志里没有）：

```
[INFO   ] 工作路径：…
[INFO   ] 原始选项/参数：./SSHFleet -s demo.ps1 -f nodes.csv
[INFO   ] 日志目录：history，工具日志文件名：SSHFleetTools.log
[SUCCESS] 选项/参数解析成功，解析结果：Namespace(…)
```

## 验收

同一条命令再跑一次，日志最后一行应为：

```
[WARN  ] 执行已取消（脚本后缀没有配置解释器）
```

另外两条不得变：

- 屏幕仍打出「已取消：脚本后缀 ".ps1" 没有配置解释器，本次执行终止」；
- 退出码仍为 `1`，输出里不出现 `[ERROR]`。
