# 取消路径留痕与参数字段语义 · 规格

Status: 待开工（ready-for-agent）—— ① 已完成；② 的范围于 2026-10-27 重新裁定，见文末「Comments」

> 来源：2026-10-21 对提交 `3febb0c`（改密显示面修正）的五轴审计。两件事都由那次审计翻出，按开发者当日裁定合在这一份里：① 当场修；② 先记录、另择一轮。

## Problem Statement

**一、取消之后，日志不说它为什么停。**

脚本后缀没配解释器时，工具会在开跑前问一句「继续用 bash 作为解释器吗」，默认否。使用者答「否」即终止：屏幕上有「已取消：脚本后缀没有配置解释器，本次执行终止」，**工具日志里却一个字都没有**——最后一行停在「选项/参数解析成功，解析结果：…」，看不出这是使用者自己取消的，还是程序半路出了事。

同一份日志里，另一条取消路径（危险命令确认答「否」）是留了 `[WARN] 执行已取消，SSHFleet工具已退出` 的。同类的事，两种待遇。

**二、改密的新密码，两种给法两套规矩。**

改密的新密码只有一个，命令行给法有两种：打开加密时写的是**密文文件的绝对路径**，不加密时写的就是**新密码本身**。两种都合法，但收到的值怎么处理不一致：

- 清单第 4 列的登录密码会去掉首尾空白；
- 命令行给的新密码一个字节都不动。

于是两件事：

- 首尾多打一个空格，它会被当成密码的一部分设上去。参数屏与报告按前 2 后 2 脱敏显示，看不出那个空白；事后使用者自己也敲不出同一个密码。
- 值里带换行或回车时，改密是把字节喂进远端终端——换行等于回车，半截密码被提交，远端重问或直接失败，报错指不到原因。

另外，装命令行原值的字段名为 `ChangePassword`，读起来像「这就是密码」。加密时它装的其实是路径，2026-10-21 那次显示缺陷正是三处把它当密码用造成的（已改用解析后的值）；名字本身的误导还在。

---

## Solution

**一、答「否」终止时，工具日志里留一条 `[WARN]`**，与危险命令取消同一口径：`执行已取消（脚本后缀没有配置解释器）`。屏幕文案、退出码、`[ERROR]` 前缀的处置一律不动。

**二、值不改写，改为在检测阶段拦。**

- 两种模式都不改值：加密模式的值当路径原样交给系统，明文模式的值原样当密码。程序不做去空白、不删换行。
- 明文模式的原值、加密模式解出来的明文，命中下面任一条就当场报错退出，本次不执行改密：
  - 开头或结尾有空白（空格、制表符）；
  - 任意位置有换行符或回车。
- 中间的空格不拦。
- 报错写清「哪里错了 / 为什么 / 怎么改」，提示要求**换一个密码**，而不是让程序替他清理。
- 装命令行原值的字段改名，让「原样值、不一定是密码」进到名字里。

## User Stories

1. 作为运维，我答「否」终止一次运行之后，翻开工具日志就能看到「执行已取消（原因）」，不必再猜是不是程序出了问题。
2. 作为维护者，我希望工具里每一种「因为使用者取消而终止」的路径都在日志里留下原因，而不是有的留、有的不留。
3. 作为使用者，我把密码打成 `' NewPass '` 时，工具当场告诉我首尾有空白、让我换一个，而不是悄悄把它改成 `NewPass` 设上去。
4. 作为使用者，我把带换行的值粘进命令行时，工具在开跑前就拦下，不让我等一轮失败、看一堆指不到原因的报错。
5. 作为维护者，我看到字段名就知道它是命令行原值，不会顺手把它当密码显示。
6. 作为使用者，这次改动除新增的三条拦截之外，不改任何屏幕文案、退出码或既有行为。

## Implementation Decisions

**一、留痕落点：主干调用「解释器回退确认」处就地写 warn。**

- 不塞进 `fatal` 的统一分支：各取消站点有自己的原因文案，参数确认屏那条取消已经自己写过 warn，统一处理会出现重复行。
- 不放进入交互器（`Notice` 只上屏、非交互下静默，是它既定的职责），也不改 `Interactor` 的对外形态。
- 文案口径沿用既有那条：「执行已取消（<原因>）」，原因写「脚本后缀没有配置解释器」。
- 取消仍属非致命终止：退出码 1、不加 `[ERROR]` 前缀、屏幕文案不变。这是 2026-09-14 的既有裁定，本次不动。

**二、拦截落在改密的取值检查里，只此一处。**

- 落点是既有的那条改密取值检查（互斥校验 → 取值 → 读凭据 → 赋给解析后的新密码）。检查加在**读到明文之后、赋值之前**：作用于「最终要设的那个值」，明文模式的原值与加密模式解出来的明文因此走同一条判断。
- 不改写值：不做 `TrimSpace`、不删换行；命中就返回错误，不进入执行。
- 报错沿用本仓库「问题 / 原因 / 提示」三行形态（`docs/agents/doc-guide.md` 五·5.2）。提示写「换一个不带首尾空白（或换行）的密码」，不写「已为你去掉」。
- 空值判定在拦截之前，沿用既有「内容为空」那条，不新造文案。
- 字段改名：装命令行原值的字段由 `ChangePassword` 改为带「原值」字样的名字，同包与 `batch` / `main` 的读取点、以及各处构造该结构的测试跟改。日志里的字段名（`change_password=`）属对外格式，不动。
- 模式判定仍看原值有没有内容（`ModeName` 一处推导），本次不做「模式独立取值」——理由见 ADR-0027《理由》最后一条。

## Testing Decisions

- **接缝只有一处，且是既有的**：cli 层的改密取值检查。不新增接缝、不测私有函数。改密链路既有用例已覆盖「明文原值直通」与「密文解出明文」两条；本次只改前者的预期，并加两条。
- 三条行为各一条用例：首尾空白报错、中间换行报错、中间空格通过。
- 加密链路那条既有用例（造真实密文、经环境变量注入主密钥）继续保留：它钉的是「解出来的就是新密码」。本项若误拦正常值，它会红。
- 参数屏 / 报告 / 日志那三处显示仍取解析后的值，既有用例不动，它们不因本项而改。

---

## 本次不做

- **模式判定改显式取值**（原 02 的第 1 条）：2026-10-27 起不做，理由见 ADR-0027《理由》。
- **清单第 4 列的处理**：仍去首尾空白，那是书写约定，与当场输入不是一回事。
- **加密模式的值**：仍当路径原样交 OS，不新增形态检查。
- **屏幕文案、退出码、`[ERROR]` 前缀的任何调整**。
- 其他取消路径的留痕审查（本次只补解释器回退这一条，其余路径已在改前各自留痕）。
