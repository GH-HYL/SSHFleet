## 【判断题】

### J1 远端形态检查漏掉「以 `//` 开头」的形态

- **位置**：`internal/cli/check.go:330` `case strings.Contains(p[1:], "//"):`
- **证据**：`p = "//x"` 时 `p[1:] == "/x"`，不含 `"//"`；`!strings.HasPrefix(p,"/")` 为假、`hasDotSegment("//x")` 为假 → **整条检查放行**。而 A3 写的是「不含 `//`」，`//x` 字面上就是含 `//`。`p[1:]` 的写法是为了避开绝对路径开头那一个 `/`，代价是把「开头两个 `/`」一起放过了。
- **理由/代价**：`//host/share` 在 POSIX 里是实现定义（部分系统当 UNC），交给远端后落点不确定；`-d //x` 现在能过参数阶段，违反 A3 的本意。要覆盖只需在 `p[1:]` 那一支之外补「去一个前导 `/` 后仍以 `/` 开头」，即 `rest := strings.TrimPrefix(p, "/"); strings.HasPrefix(rest, "/") || strings.Contains(rest, "//")`（单用 `Contains(p[1:], "//")` 是修不掉的，`"//x"[1:]` 就是 `"/x"`）。代价是 `//` 开头的合法写法（极少）被拦。**与轴三「遗漏的判定」重叠，供主 Agent 合并。**

### J2 下载目录分支自己造出 `//`，与 A3 禁止用户写 `//` 的口径相抵【待裁】

- **位置**：`internal/ssh/sftp.go:374` `remoteFilePath = remotePath + "/" + file.relativePath`（上传侧对应处用 `path.Join`：`sftp.go:132`）。
- **证据**：`-d /var/log/`（结尾带 `/`，A3 允许，因为不含 `//`）→ 实际请求的远端路径是 `/var/log//app.log`。检查侧的理由写的是「含 `//` 多半是拼接时多写了一段分隔符」（`check.go:317`），程序自己却在拼接时多写了一段。
- **理由/代价**：A8 明说「传输层落到目标目录时的路径合成维持现状」，所以这一行**不该按缺陷改**；但「程序产出的远端路径一定干净」这条不变量因此不成立，远端若对 `//` 敏感（个别 sftp-server / `find` 实现）用户会看到一个自己没写过的路径失败。**要 A3 严格、还是维持 A8 的现状，需开发者裁。**（本条只报「合成与检查口径不一致」，不判下载失败怎么记）

### J3 「只留系统那一句」有两份独立实现

- **位置**：`internal/cli/check.go:366` `systemReason` 与 `internal/credential/credential.go:157` `systemReasonOf`。
- **证据**：两份逐行同构（取 `PathError.Err` / `LinkError.Err`，否则 `err.Error()`）；目前行为等价（`os.PathError` 是 `fs.PathError` 的别名）。没有测试断言两者一致。
- **理由/代价**：这条规则是 A7 的公共地基，两份实现之间没有引用关系——将来任一侧多剥一层（例如加 `*os.SyscallError`、Windows 上再削 `The system cannot find the file specified.` 之类），参数层的报错与清单行的报错就会对同一种 errno 给出两种原文，而「一屏一套体系」正是本轮要立的规矩。共用没有障碍（`cli` 已 import `credential`，或下沉到 `internal/common`）；代价是一次很小的搬迁。**建议收成一处，但不影响本轮验收。**

### J4 配置文件展示路径有三个名字、两份字面量，且新导出落在 cli（层级偏高）

- **位置**：`internal/cli/interpreter.go:20-26`、`main.go:88-89`、使用点 `internal/nodelist/precheck.go:229`。
- **证据**：`ConfigShown` 与 `configPathShown` 是同一串字的两份定义；`configShown` 只是 `ConfigShown` 的包内别名（注释自述「包内旧名，保持既有调用点不动」——为省两次改名而多留一个名字）。
- **理由/代价**：`config` 是叶子包且三方都依赖（见第二节），把展示路径放 `config`（例如 `config.PathShown`）能让 `main` / `cli` / `nodelist` 共用一份，也把常量从「解释器」这个不相干的文件里挪走。现状的代价是：改配置路径形态时要同步 `main.go:89` 与 `cli/interpreter.go:23` 两处，漏一处就会出现「让你去改一个实际不叫这名的文件」这种最难自查的报错。另外 `nodelist → cli` 这条逆向依赖从此又多一条理由，而它本来只是借 `cli.Args`。**属可权衡的收敛，不是本轮的错误。**

### J5 「哪一边的路径」这条映射没有单一落点，仍是四处 if/switch

- **位置**：`internal/cli/check.go:67-99`（校验分支）、`internal/batch/batch.go:202/206`（取值）、`internal/confirm/confirm.go:181-185`（屏上标签）、`internal/output/report.go:59-64`（报告标签）。
- **证据**：四处各自按 `a.Upload != ""` / `a.Download != ""` 重述「上传时 `-p` 是远端、下载时 `-p` 是本机」；`cli.ModeInfo`（`args.go:167-205`）是现成的「模式 → 属性」表，但没有承载这个属性。
- **理由/代价**：四处**目前一致**（这是 A2 能站住的原因），但一致性靠人记，不靠结构——本轮只能靠注释在 `args.go:443-444`、`check.go:69`、`sftp.go:369-370` 各提醒一次。加第 6 档模式或改 `-p` 语义时要记得同步四处。这是结构性建议，不是本轮缺陷。

### J6 `checkInlineValue` 依赖一个只在注释里成立的「statErr 必非 nil」契约

- **位置**：`internal/cli/source.go:97-104`（`checkInlineValue(raw, form, statErr)`）、`:102` `systemReason(statErr)`。
- **证据**：`systemReason(nil)` 会走到 `return err.Error()`（`check.go:375`）→ nil 接口取方法，**panic**；而 `resolveSource` 只在 `os.Stat` 出错时返回非 nil（`source.go:32-37`），唯一调用点 `source.go:78` 保证了这一点。契约只写在注释（`source.go:94-96`：「此处必非 nil……不为可能是 nil 再补兜底分支」）。
- **理由/代价**：注释里那句「不补兜底」是对的（补了就是不可达分支），但把「一个 error」当字符串容器传，随后在别的包里解引用，等于把「非 nil」这个前提交给下一个人记。更窄的写法是让 `resolveSource` 直接返回已经取好的原因串（`(source, reason string)`），或在 `systemReason` 开头对 nil 返回空串。当前无可达缺陷，代价也只是接口形状；列出来是因为它是本轮新引入的接口。
