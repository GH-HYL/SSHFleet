## 五、异常、环境事实与待定性观察

1. **WSL 发行版闲置会被 `Stopped`，`127.0.0.1:22` 的转发随之消失。** 本轮第一次跑 D1（21:03:40）时 `wsl -l -v` 显示 `Stopped`，程序报 `sshfleet.connect.refused: … actively refused it`，`Test-NetConnection -ComputerName 127.0.0.1 -Port 22` 回 `False`；随后用一条长驻 `wsl.exe … sleep 3600` 顶住，端口即回 `True`，重跑 D1 才连上并拿到 `auth_failed`。**复核者若照 `audit.md` 复现，需先确认 distro 处于 Running 且转发在。**
2. **`/tmp` 被清空两次**：本轮开工前造好的两个文件在 distro 一次去 Stopped 后消失（`ls: cannot access '/tmp/app.log': No such file or directory`），D4/D5 前重建；跑完 S5 时 `/tmp/cli-linux-test.log` 又一次不在。与 `audit.md` 5.3 脚注的成因一致。
3. **【待定性】参数阶段的两条形态报错只有两行，没有 `原因：` 行。** E1 / X1 / X2 的终端输出结构是「问题 + 提示」，`原因：` 缺位（A7 的三行套里中间那行）。这三条都是纯字符串形态判定，背后没有系统错误可引。归属按提示词分给轴四，本轴只记现象。
4. **【待定性】终端与日志都有固定宽度折行，折行处会插入空格或把词切开**：`必须是绝 对路径`（E1）、`上传目录不干净： 不能含`（X1）、`-d 参` 换行接 `参数指定的远程路径`（X2 日志）。控制台直接看是断在词中间的空白，写进 Excel/txt 的报告里没有这个空格（`report.txt` 的「远程路径： /tmp/a\b.log」干净）。与 `audit.md` 5.5 第 9 条（`--help` 经管道黏行）像是同一类显示层问题。**不影响本轮的取值判据**，但会让人以为值里带了空格。
5. **D5 的 `r='a_b.log'` 不是原名，`\` 被替换成了 `_`**，而同一行的 `d=` 是原值 `/tmp/a\b.log`；明细行与错误详情里用的是原名 `a\b.log`。三处形态不同源，照抄不解释。
6. **D1/D2/D3 用的是 `nodes-dummy.csv`（`127.0.0.1,22,root,x`）**，本轮 WSL 已起，所以终态是「身份验证失败」而不是 5.3 的「连接被拒」。判据只看 `r=`/`s=`/`u=`/`p=`，日志行在合规检查通过后照样打出，`audit.md` 4.2 的说法成立。
7. **`dl\` 的落点仍带 IP 子目录**：`dl\127.0.0.1\app.log`。与第六节 D4 一致，即传输层路径合成维持现状（A8 前半）。
8. **S3 的 `go test` 失败原因不是编译错误**：`%1 is not a valid Win32 application` 是试图执行 linux ELF。想在这一侧拿到判据，只能走 S4+S5 那条路。
9. **未做的项**：无。D1–D5、E1–E2、X1–X2、三道构建/静态检查、替身证据链全部跑到；唯一跑不动的 S3 已给出原因并补了 S4/S5。
