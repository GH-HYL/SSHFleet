## 1. 我设计的框架

### 1.1 出发点：这个议题的病根不是「某条规则写错」

ADR 自己在「理由」里写了病根：**同一形态的路径造出第二个事实来源**。这句话决定了漏洞的形状——它们不会长在单个函数里，而会长在**两次解读之间**、**库与系统的缝隙里**、**删了代码没删说法的地方**。五条轴按「文件 / 包」切，正好三处都够不着。

### 1.2 四个切面（与五轴正交）

| 切面 | 问法 | 抓什么 | 怎么执行 |
| --- | --- | --- | --- |
| **C1 值生命周期** | 八个收路径的值，从 `argv` → `Parse` → `CheckArguments` → 日志 → 执行 / 传输 → 报错，**每一跳有没有第二次解释它** | 同一值两口径（H1） | 按值逐跳走读，不看包边界 |
| **C2 锚-落点-证据矩阵** | 每条锚 A1–A11：代码落点在哪、有没有能失败的测试、文档承诺是否同一句；**三列缺一列就是洞** | 锚说了代码没做（H2）、代码做了锚没说、证据是 SKIP 却当通过 | 列 11×4 的表，逐格填 |
| **C3 平台语义** | 每个 OS 库调用问一句：**库说「行」，系统是不是也只做这一件事** | `filepath.IsLocal` 为真但 Win32 另有动作（H3） | 读 Go 运行时源码 + 在真机上探一次 |
| **C4 残留扫描** | 被删的概念（`normalizePath` / 补齐 / `~` 展开 / 空格拦）在**符号、注释、用户可见文案**里还有没有活口 | 代码删净但话说反（J4、J5） | 全仓 grep 符号与动词，再逐条看文案 |

### 1.3 为什么这么切

- C1 只在「同一个字符串被两处读」时才有输出，正好绕开「按文件分域」——H1 就长在 `passwd.go` 与 `credential.go` 的接缝上，两边的负责人都可以说「我这段没错」。
- C2 把「锚」当成需求条目做覆盖表，能同时回答两个方向：锚要求而代码没有（H2），以及代码做了而锚没授权（J10）。
- C3 是本次议题的**结构性风险**：整个 ADR 的立论是「交给系统」，那么「系统到底怎么处理」就是判据本身。库函数只是系统的近似，二者不等的地方就是洞。
- C4 对应 ADR 的「撤净旧概念」，但扫的是**用户能看见的字**，不是函数调用图。

## 3. C1 值生命周期：3 条发现

### H1【硬伤】`--change-password` 在同一个阶段被解读两次

**位置**
- `modules/SSHFleet_Go/internal/cli/passwd.go:27-34`（新增的前置检查，用原值）
- `modules/SSHFleet_Go/internal/credential/credential.go:83`（`text := strings.TrimSpace(value)`，下游用去空白后的值）

**证据**
```go
// passwd.go:29
if a.credentialEncrypted {
    if _, err := os.Stat(a.ChangePassword); err != nil {   // ← 原值
```
```go
// credential.go:83（改前就在，本轮未动）
text := strings.TrimSpace(value)
```
改前（`git show 0da83af:modules/SSHFleet_Go/internal/cli/passwd.go`）该函数**没有**这个 `Stat`，只有 `credential.ReadCredential(...)`，而后者内部先 trim 再 `os.Stat`。所以：

- 改前：`--change-password ' /k/new.sec '`（加密开）→ trim 成 `/k/new.sec` → 打得开，正常。
- 改后：先 `os.Stat(' /k/new.sec ')` → 失败 → `--change-password 的值读不到： /k/new.sec \n原因：The system cannot find the file specified.`

**为什么算硬伤，不是措辞**：ADR-0025 §四最后一条明写「`--change-password` 的值在凭据读取处还会被去一次首尾空白……**本轮不为它加任何处理，也不把它算作问题**」。这行 `Stat` 正是「加的处理」，而且加在了 trim 的**上一层**，于是同一条值在同一个合规检查里有两种事实。ADR 的立论是消灭「第二个事实来源」，这里把它原样搬回来了。

**同一文件的注释已经自相矛盾**：`passwd.go:17` 还写着「它的值也不进路径参数循环（**含空格不报错**、不做 `\`→`/`）」，十行之后就对含空格的值报错。

**测试为什么没拦住**：`passwd_test.go:113 TestCheckPasswdChangeTrimsOuterSpace` 用的是 `Args{ChangePassword: " NewPass123 "}`，`credentialEncrypted` 为零值 false——走的明文分支，新 `Stat` 根本不执行。加密分支没有一条带首尾空白的用例。

**修法（给出代价）**：把 `Stat` 的参数改成 `strings.TrimSpace(a.ChangePassword)`，或干脆不前置 `Stat`、让 `readCredentialCore` 的 `CodePathMissing` 分支出那条三行文案（它内部已经 trim，且已经带系统原文）。前者的代价是多一次 trim 调用，后者要动 `ReadCredential` 的返回形态——两者都比现在「两个值并存」便宜。

### J1【判断题】`Stat` 与 `ReadCredential` 各自问一次盘

即便修掉 H1，仍是「同一值两次问盘」：中间文件被换掉 / 权限变化，两处会给出不同答案。这不值得单独立项，但 H1 修的时候顺手合并更好——`readCredentialCore` 已经是唯一读盘点，前置检查只是把它的错误提前了一层。

### H2【硬伤】`//` 检查写成了 `p[1:]`，开头正好两个斜杠的路径整条漏过

**位置**：`modules/SSHFleet_Go/internal/cli/check.go:330`

```go
case strings.Contains(p[1:], "//"):
```

**证据与推演**（静态走读，逐行可复现）：

| 输入 | `p[1:]` | 命中 `//`？ | 后续 | 结果 |
| --- | --- | --- | --- | --- |
| `/opt//app/` | `opt//app/` | 是 | — | 拦下（对） |
| `///opt/app/` | `//opt/app/` | 是 | — | 拦下（对） |
| **`//opt/app/`** | `/opt/app/` | **否** | 绝对 ✓、无空白 ✓、无 `.` 段 ✓ | **放行** |
| **`//var/log/app`** | `/var/log/app` | **否** | 同上 | **放行** |

`p[1:]` 的本意应是「跳过路径自身那一个前导 `/`」，但一个前导 `/` 本来就不可能构成 `//`——`strings.Contains(p, "//")` 只会多拦「开头正好两个」这一种，而那种恰恰是该拦的。`///` 被拦、`//` 被放，说明这不是「故意放行 POSIX 的 `//` 特殊前缀」（真要放行，`///` 也该放），而是下标差一位。

**后果**：A3 与 `CHANGELOG.md:15`（「不含 `//`……`-p /opt//app/` 现在都在参数阶段报错」）都承诺拦；实现放行，值原样送到远端。Linux 远端通常把 `//opt` 解释成 `/opt`，所以多数时候**看不出错**——这比报错更糟：检查形同虚设，而使用者以为已经挡住了。

**测试**：`args_test.go TestRemotePathMustBeAbsoluteAndClean` 有 `/var//log`（中间双斜杠），**没有**开头双斜杠的用例。

**修法**：`strings.Contains(p, "//")` 即可；补一条 `-p //opt/app/`、一条 `-d //var/log/app`。

### J2【判断题】「空白」只认空格与制表符

**位置**：`check.go:326`（`strings.ContainsAny(p, " \t")`），文案却写「不能含空格或制表符」。

A3 的用词是「不含空白（含两端）」。实现排除了 `\r`、`\n`、`\v`、`\f` 与 Unicode 空白（U+00A0、U+3000 等）。代价与理由：

- 支持「只判空格 / Tab」的理由成立：这两者是 shell 按 IFS 切词的主要字符，「漏引号」确实长这样；`\n` 进 argv 只能在引号 / 粘贴里发生，不是漏引号的信号。
- 但既然把 Tab 也算进来（Tab 同样不会把参数切开），那就是按「空白字符」而不是「切词字符」划的线，`\n` / `\r` 被排除就没有内在理由。从文档粘贴一条带换行的路径，正好会落进这个缝。
- 判据层面：A3 是作者明示的锚，实现比锚窄。**要么把锚改成「空格或制表符」，要么把判据改成 `strings.ContainsFunc(p, unicode.IsSpace)`**，二者取一，别让文案继续宽于代码。

### J13【判断题】`--change-password` 还有两条两行报错

**位置**：`passwd.go:36-38`（`值读不出新密码\n原因：%v`）、`passwd.go:39-41`（`值有问题：%s`）。

A7 把「`--change-password` 凭据读不到」明确纳入三行套。新增的 `Stat` 覆盖了「文件不存在」，但主密钥缺失 / 解密失败 / 密文格式不对这三条仍走老形态，没有「提示：」。它们确实在参数与前置检查阶段。**代价**：不补也不影响可用性，但「三行套」就不是这套报错的统一形态，而是「大部分三行」。建议至少给 `ReadCredential` 的 fatal 分支补一句去路（提示：检查 `SSHFLEET_KEY` 是否与加密时一致）。

## 5. C3 平台语义：A8 的边界比库函数宽

### H3【硬伤】Windows 会静默剥掉名字尾部的空格与点，`localRelUsable` 挡不住

**位置**
- `modules/SSHFleet_Go/internal/ssh/sftp.go:22-37`（`localRelUsable`：只查本机分隔符 + `filepath.IsLocal`）
- `modules/SSHFleet_Go/internal/ssh/sftp.go:381-386`（单文件名字过 `localRelUsable` 后直接 `filepath.Join` 落盘）

**证据 1：Go 的 `IsLocal` 不管这一层**（读 `go1.27.0` 源码，`internal/filepathlite/path_windows.go:23-53`、`:93-108`）：`isLocal` 只拒绝盘符 / 冒号 / 前导分隔符 / `.` `..` / **保留设备名**；`isReservedName` 的注释自己写着「It does not detect names with an extension」。没有尾随空格 / 点的判据。

**证据 2：Win32 会替它改**（本机实测，`%TEMP%` 下建完即删）：

```powershell
[System.IO.File]::WriteAllText("...\a.log ", 'x');  [System.IO.File]::WriteAllText("...\b.log.", 'y')
Get-ChildItem → [a.log] [b.log]
```

写的是 `a.log `，落的是 `a.log`；写的是 `b.log.`，落的是 `b.log`。`os.Create` 返回 nil，`localRelUsable` 返回 true，`success++`——**一切按成功计**。

**后果**：远端（POSIX）合法文件名 `report.csv `（尾随空格是真实字符）在本机会落成 `report.csv`。这正是 A8 与 `CHANGELOG.md:15` 说的「不改名、不静默落成别的名字」要禁止的事——只是触发字符从 `\` 换成了空格 / 点。更隐蔽的一种：远端同一目录里同时有 `a.log` 与 `a.log `，Windows 上两个名字折叠成一个，后一个覆盖前一个，成功数 2、文件 1。

**与 A8 的关系**：A8 的原文是「远端取到的名字**在本机写不下去**时按下载失败报出」。`a.log ` 严格说「写得下去」，只是写成了别的名字——但 A8 紧接着的限定语「不改名、不换目录、**不静默落成别的名字**」把它包含进去了。所以是 A8 的后半句被破坏，不是前半句的解释问题。

**修法（按代价从低到高）**
1. 在 `localRelUsable` 里对 `elem` 加 Windows 专属判据：`runtime.GOOS == "windows"` 时拒绝「以空格或点结尾」的段。改动 4 行，覆盖 `a.log `、`b.log.`、`c. ` 三类。
2. 落盘后用 `os.Stat(localFilePath)` 回读一次真实名字（`os.ReadDir` 比对），不一致按失败报。更彻底，但每个文件多一次系统调用。
3. 什么都不做，把 A8 收窄成「只挡分隔符与保留名」，并写进 ADR。**不推荐**：本轮刚用 `localRelUsable` 建了「名字能用才落盘」的承诺。

**测试**：没有任何一条用例覆盖尾随空格 / 点；`nodelist` / `ssh` 两侧都没有 Windows 专属的名字用例（issue 02 的实测只用了 `a\b.log`）。

### J3【判断题】`systemReason(nil)` 会空指针

**位置**：`check.go:93-98`

```go
} else if !info.IsDir() {
    _, dirErr := os.ReadDir(a.Path)
    return fmt.Errorf("...原因：%s...", systemReason(dirErr))
}
```

`systemReason` 的三条分支最后是 `err.Error()`（`check.go:375`）。`dirErr` 只有在「`Stat` 说不是目录、`ReadDir` 却成功」时才为 nil——两次调用之间路径被换成目录，或某些特殊文件系统。概率极低，但这个兜底本身是假的：真走到那条路，程序 panic 而不是报错。

**代价**：加一行 `if dirErr == nil { dirErr = errors.New("not a directory") }` 即可，但那是**编一句系统没说过的话**，与 `check.go:94-95` 的注释（「我们不去编一句 not a directory 冒充它」）冲突。更一致的做法是：这一支不做 `ReadDir`，直接把 `!info.IsDir()` 当形态结论、只写问题 + 提示两行（没有系统原文可给）。取舍留给作者。

### J10【判断题】绝对路径也被 `filepath.Clean`

**位置**：`credential.go:241-242`

```go
if filepath.IsAbs(p) {
    return filepath.Clean(p), nil
}
```

A9 的原话是「**拼完**用 `filepath.Clean` 复解析一次」。绝对路径这一支没有「拼」，所以 `Clean` 超出了字面授权；工单 07 的验收项写的是「绝对路径：`filepath.IsAbs` 为真则**原样用**，不拼 `secret_dir`」，与代码直接冲突（issue 07 的 Comments 承认了这一点，改判为「延伸」）。

**实际影响**：清单位于第 4/6 列写 `/keys/../keys/db.sec` 会被改成 `/keys/db.sec`。这与 A1「不做 `path.Clean`」的精神相反，但 A1 管的是命令行、A9 管清单，两者不直接冲突。**这是个需要作者一句话的点**：清单第 4/6 列的绝对路径，是「原样交给 os」还是「交 os 前先规范一次」。现在代码选了后者，文档两处说前者。

## 6. C4 残留扫描：代码删得干净，话没删干净

### 6.1 明确「未发现问题」的部分（证据）

```text
grep -rn "normalizePath"        → 只有 args.go:436 的一句历史注释 + dangercheck 的另一个函数
grep -rn "pathWithoutSpace"     → 只有 args_test.go:623 的历史注释
grep -rn "pathFlagWhat"         → 无
```

- `dangercheck/text.go:112 normalizePathFragments` 是危险检测的文本整备，与本轮无关，保留是对的。

### J4【判断题】配置侧报错仍教用户「`~` 只在清单里能用」

**位置**：`internal/config/config.go:401-406`

```go
if strings.HasPrefix(p, "~") {
    return "", fmt.Errorf(
        "%s 不支持 ~，当前值：%s\n"+
            "原因：~ 只在清单里能用，配置里要写全路径\n"+
```

本轮（工单 07 / A9）把清单第 4/6 列的 `~` 展开也取消了，于是这句话现在是**反的**：清单里也不能用。触发场景很具体——用户把 `~/.keys/id_rsa` 写进 `credential.key`，得到「`~` 只在清单里能用」，照着改去清单第 5 列写 `~/.keys/id_rsa`，仍然失败（A5 早就规定第 5 列不展开）。一句话把人引到第二个坑里。

**因果链**：工单 07「`~` 展开取消」→ `expandHomeTilde` 删除 → `config.go:404` 的说明没跟着改 → 使用者按提示改仍然失败。

**修法**：改成「`~` 在这里没有特殊含义（配置与清单都不展开），请写全路径」。一行。

### J5【判断题】`CredErrorLabel` 的「必须写绝对路径」已经过时

**位置**：`internal/credential/credential.go:187-189`

```go
case CodePathMissing:
    // 只出自密码 / 口令类位置（开了加密时那些位置写的应是一个文件路径），故这句解释对得上
    label = "不存在（打开加密时这里填的是凭据文件的绝对路径，不加密时才是密码本身）"
```

A4 / A9 之后，第 4/6 列在配了 `secret_dir` 时**写相对名是合法的**。这条文案只在「文件确实找不到」时出现（`credential.go:99-103`），也就是**最需要正确指引的时刻**，却告诉用户「这里填的是绝对路径」。user 按它改成绝对路径能解决，但会把「相对名 + `secret_dir`」这条本轮刚立起来的规则读成不成立。

ADR §四只预料到「`secret_dir` 未配置」那一种会换文案（现在由 `relativeColumnError` 接管），没预料到**配了 `secret_dir` 但拼出来的文件不存在**也走这条 label。

**修法**：去掉括号里的绝对路径说法，改成「打开加密时这里应是凭据文件（可写相对名，拼 `secret_dir`）」。一句。

### J6【判断题】同一个常量两个名字

**位置**：`internal/cli/interpreter.go:20-26`

```go
const ConfigShown = "config/SSHFleet.conf"
// configShown 包内旧名，保持既有调用点不动。
const configShown = ConfigShown
```

新增导出的唯一调用方是 `nodelist/precheck.go:229`；包内两个老调用点（`interpreter.go:79/118`）保留旧名。结果是同一个值在仓库里有三个事实来源（`main.go` 的 `configPathShown`、`ConfigShown`、`configShown`）。

**代价**：把 `interpreter.go:79/118` 改用 `ConfigShown`、删掉别名，是两行改动。**必要性**：导出本身成立（跨包真需要），别名不成立。

### J7【判断题】`ReadCredentialPEM` 成了无人调用的导出

**位置**：`credential.go:123-126`（保留）、`:132-134`（新增 `ReadCredentialPEMProblems`）

`grep -rn "ReadCredentialPEM("` 现在只命中定义行本身——全部调用点都改成了 `Problems` 版本。于是 `credential` 包对外暴露两个同源函数，一个无人使用。

**代价**：直接把 `ReadCredentialPEM` 的返回类型改成 `[]CredError`（唯一调用方本轮已经改走新函数），或删掉旧函数。留着两个的理由只能是「别的仓库在用」，而这是 `internal/` 包，不成立。

### J8【判断题】「只留系统那一句」有两份逐字相同的实现

**位置**：`cli/check.go:361-376`（`systemReason`）与 `credential/credential.go:153-167`（`systemReasonOf`）

两份代码除了变量名完全一致（`errors.As` → `*fs.PathError` / `*os.PathError` → `LinkError` → 兜底）。本议题的另一半主题是「同一条规则只有一处定义」，这里却因为不想让 `credential` 反向依赖 `cli`（方向是对的），复制了一份。

**代价**：挪到 `internal/common`（两个包都已依赖它）是唯一正确的落点。不挪的风险是可预期漂移：下一轮有人给「权限不足」加一条特判，只会改其中一份。这是**判断题**而不是硬伤，因为两份现在确实一致。

### J9【判断题】用中文文案当分支键，`-d` 的示例还给成了目录

**位置**：`check.go:337`

```go
if reason == "必须是绝对路径，当前值：" {
```

分支条件是刚刚赋进去的**用户可见字符串**。改一个字（比如加个「的」）就会静默落到下面的「不干净」分支，输出变成「-d 参数指定的远程路径不干净：必须是绝对路径，当前值：var/log」——仍然能看懂，所以不会有测试红，也就没人会发现分支失效。

同一处还有一个小回退：`-d` 原来给的示例是 `/var/log/app`（文件），合并进 `checkRemotePath` 后统一成 `/opt/app/`（目录，还带尾斜杠）。A3 允许 `-d` 指向目录，但最常见的用法是单个文件；示例形态会把人往「目录 + 结尾 `/`」上带。

**修法**：把四类做成枚举 / 常量，分支用 `switch` 而不是比较文案；`-d` 与 `-p` 各给各的示例（`hint` 已经按 `what` 参数化了，再加一个 `example` 参数即可）。

### J11【判断题】一个坏名字会终止整批，与工单 02 的描述不一致

**位置**：`sftp.go:387-398`（`badName` 分支末尾 `break`）

`break` 退出的是整个 `for _, file := range files`，同批剩余文件不再处理。这是**既有模式**（`sftp.go:400-409` 的 `MkdirAll` 失败、`:415-429` 的传输失败也都 `break`），不是本轮新造的；但工单 02 的 Comments 写的是「`/tmp/dltest` 里同时有 `a\b.log` 与 `ok.log`——`a\b.log` 按『本机写入失败』报出，`ok.log` 正常落地」。这句只在 `ok.log` 恰好排在 `a\b.log` 之前时成立（`files` 按 `find` 的枚举顺序，没有排序）。按字典序 `a\b.log` 在前，那一次实跑大概率是 `find` 的目录顺序帮了忙。

**后果**：使用者读到的是「一个名字坏了，其余也不传了」，而工单文档让人以为是「跳过坏的、传好的」。同时 `result.TotalFiles = N` 与 `SuccessFiles + FailedFiles = 1` 不自洽（汇总首行会显示「总数 5 / 成功 0 / 失败 1」）。

**修法**：这一支改成 `continue`（坏名字是**单文件**的局部问题，没有共享状态需要中止；`MkdirAll` / 传输失败保留 `break` 有理由——那是环境级失败）。若作者要「首错即停」，那就把工单 02 的那句改成「按失败报出，其余不再处理」。

### J12【判断题】新用例把模板文件的字面行当夹具

**位置**：`config_test.go:95-106`

```go
conf := strings.Replace(string(raw), `secret_dir   = "/opt/SSHFleet/keys"`, `secret_dir   = "keys"`, 1)
conf = strings.Replace(conf, "encrypt      = true", "encrypt      = false", 1)
```

`Replace` 没命中不会报错：模板一旦改了对齐空格，这条用例就变成「原样加载模板 + 断言 `SecretDir == "keys"`」，红；但如果哪天模板的默认值恰好变成 `keys`，它会**静默地不再测任何东西**。用 `strings.Contains` 先断言「替换确实发生了」两行就能封住。属脆性，不是反向锁。

## 7. 锚质疑（按共用件体例另起，不改写锚）

### Q1 A7 说「`main` 的三处 fatal」，源码里是 7 处

- **哪条锚**：A7 的末句「`main` 的三处 fatal 外层改成冒号收尾，一屏只留一个「原因：」」。
- **证据**：
  ```text
  grep -n "fatal(" main.go
  208 config / 233 cli-parse / 242 cli-exclusive / 280 cli-check / 302 danger / 317 danger / 404 log
  ```
  改前沿用 `fmt.Errorf("...\n原因：%v")` 的正是这 7 处（`git show 0da83af:modules/SSHFleet_Go/main.go`），本轮 7 处全改成 `wrapFatal`。`issues/05` 的 Comments 也记了「规格写三处，实际改了 7 处」。
- **按什么判**：A7 的**意图**（一屏只留一个 `原因：`）在 7 处都成立，且比只改 3 处更彻底；问题在锚的**数量描述**与源码不符——如果后来的执行者严格照「三处」做，会漏掉 4 处，屏幕上仍会出现两个「原因：」。
- **建议（由开发者定）**：把 A7 的「三处」改成「`main` 里所有带 `原因：` 的 fatal 外层」。这不是实现缺陷，是锚的计数描述需要跟源码对齐；ADR 的 10-26 更新记录里没写这一条。
