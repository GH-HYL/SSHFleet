# 命令行路径原样交给系统：八个选项收口 · 规格

Status: ready-for-agent

> 决策依据：`docs/adr/0025-命令行路径原样交给系统.md`（为什么不再加工、补齐只服务清单、报错分两层）。本文只写「做成什么样」，不重复取舍理由。

---

## Problem Statement

同一个路径，换个选项写就换个结局，使用者只能靠试：

- **写反斜杠**：在 Linux 上把脚本写成 `docs\a.sh`，`-s` 会替他把 `\` 换成 `/` 从而打开（指的不是他写的那条路径）；同样的写法给 `-f` 却报「文件不存在」。
- **两端带空格**：`-s " a.sh"` 会被当成 `a.sh`，两个文件都在时打开的是另一个；远端目录名末尾真有空格时，反而永远找不到。
- **远端路径被本地规则加工**：上传的 `-p`、`-d` 是目标机上的路径，却按本机习惯被改写（换分隔符、压掉 `..`、补结尾 `/`）。
- **配置与清单的凭据路径说法不一**：手册一处说「清单第 4 列也必须是绝对路径」，另一处说「相对路径只在清单里能用」，`secret_dir` 到底服务谁看不出来；关掉加密时它明明没有用途，配错了却照样拦人。

## Solution

命令行给的路径，程序一个字节都不改，直接交给对应的系统：

- **规则覆盖八个收路径的选项**：`-s` `-u` `-p` `-d` `-f` `-a` `--convert-secret`，以及打开加密时的 `--change-password`。后四个已经是原样，本轮要改的是前四个。

- **本地路径**（`-s`、`-u`、下载的 `-p`、`--change-password`）交给本机文件系统。
- **远端路径**（上传的 `-p`、`-d`）原样交给远端，程序只当字符串传。
- 同一个 `-p` 随执行模式换归属：上传是远端目录，下载是本地目录。
- 远端两个值保留「中间含空格就拦」这一条检查；本地路径不走它，能不能打开由系统回答。
- `secret_dir` 只服务清单（CSV 第 4/5/6 列与 `-f` 的内联记录），且只在打开加密时用得上；配置里的凭据路径必须写本机绝对路径，不参与补齐。
- 参数与前置检查阶段的报错＝我们写一句「怎么改」+ 系统原文；`sshfleet.<环境>.<环节>` 那套报文只服务执行阶段。

## User Stories

1. 作为在 Linux 上敲命令的人，我希望 `-s /opt/a\b.sh` 就是去找这个名字的文件，而不是被改成另一个路径。
2. 作为用 Tab 补全的人，我希望文件名里的括号、空格、中文照原样传进去，不需要我再手工加反斜杠。
3. 作为路径里带空格的人（本地），我希望程序别替我去掉两端的空格——它可能真是文件名的一部分。
4. 作为上传的人，我希望 `-p` 在两种模式下各按各的规则解析：上传时是目标机的目录，下载时是我本机的目录。
5. 作为只想临时写个短凭据名的人，我希望在清单里写 `A` 就能指向 `secret_dir` 下的 `A`，不用写全路径。
6. 作为写配置的人，我希望配置里的凭据路径必须写绝对路径，规则简单、不用猜它会被拼到哪。
7. 作为关掉加密的人，我希望 `secret_dir` 这时不被检查——我没用到它，配错了也不该拦我。
8. 作为写错了路径的人，我希望报错里有系统给的原因，并且告诉我下一步该怎么改。
9. 作为看清单报错的人，我希望它明确指出是哪一行、哪一列，以及要不要去配置文件的 `[credential]` 里配 `secret_dir`。
10. 作为接手这个仓库的人，我希望「路径由谁解析」只有一条规则，不再有第二个解析器。

## Implementation Decisions

- **删掉命令行的字符串规范化环节**：不去两端空白、不换分隔符、不归一盘符、不做路径压平、不拼前缀。解析出来是什么就是什么。
- **`-p` 按模式交给不同语义**：上传走远端语义，下载走本机；`-d` 恒为远端，`-s` / `-u` / `--change-password` 恒为本机。凡取文件名、取后缀这类动作，一律用与路径归属一致的那套（远端用 POSIX、本地用本机），现有用反的几处一并纠正——否则「原样」在备注与解释器识别上会退化成另一条路径。
- **远端两个值不做任何加工**，只保留「中间含空格则拦」的检查；本地路径不参与这条检查。
- **用户给的值不做转义**：拼远端命令时由程序整体用单引号包住（括号、空格都在引号里），这层保持现状。
- **`secret_dir` 补齐只留一处**：清单第 5 列恒为路径；第 4/6 列在打开加密时是「装了密文的文件」路径，可写相对名；不开加密时那两格是密码 / 口令本身，没有路径可补。命令行与配置都不经过它。
- **配置文件不再走补齐**：凭据路径必须本机绝对；配置侧现有那条「也会拼一次」的调用去掉（它本来就只是原样返回）。
- **`secret_dir` 的校验跟着开关走**：加密关着时既不补齐也不校验（现在仍按「必须绝对路径」拦，随本规格改）。
- **参数与前置检查阶段的报错**：本地路径出错时，我们那一句只写「怎么改」，原因用系统原文；清单第 4 列缺 `secret_dir` 时点名去配置文件的 `[credential]` 段配。
- **第 6 列（私钥口令）保持不检查**：本地判断不了私钥要不要口令，只能交给远端，执行前检查也拦不住。既有决策，不动。
- **传输层把文件落到目标目录时的路径合成不动**：它作用于程序自己算出来的路径，不是解析用户给的路径。
- **版本档位**：不抬主版本，记进当天那一段（修订档）。

## Testing Decisions

- **接缝**：只用命令行入口这一层——选项/参数解析 + 参数合规检查。不新增接缝，不测私有函数。
- **要钉住的行为**：
  - `-s` / `-u` / `-p` / `-d` 反斜杠、`..`、重复分隔符、两端空白，进入后续环节的值与命令行给的**逐字相同**；
  - 远端两个值中间含空格 → 拦；本地值含空格（含两端）→ 不拦，交给系统判；
  - `-p` 上传要求绝对且以 `/` 结尾、下载要求已存在目录，两条断言照旧；
  - 加密关着时 `secret_dir` 写相对路径不报错；加密开着且清单写相对名、`secret_dir` 为空 → 报错点名 `secret_dir`；
  - 清单第 4 列缺 `secret_dir` 的报错点名配置文件；第 6 列取不到仍不报错。
- **既有用例随行为一起改**：把旧文案（「密码文件不存在」那条）写成预期的用例按新行为改写，**MUST NOT** 为旧写法留兼容用例。
- **期望值**取字面量（手写的路径字符串、手写的错误片段），不用被测代码同款算法重算。

## Out of Scope

- `-r`（归档目录名，不是路径）与它的字符替换。
- 配置文件里路径的归一规则（`\` 与 `/` 通用、盘符大写、必须本机绝对）。
- 产物目录结构与归档命名。
- `sshfleet.<环境>.<环节>` 报文体系本身（本轮只界定它管哪一层）。
- 第 6 列（私钥口令）的检查。
- 为旧写法留兼容层。
- 议题里「审计追加」那五条中与本规格无关的（`--convert-secret` 空值、就地改写先截断再写、两个同名解析函数）。
- `GLOSSARY.md` 里其余过期条目的全面审计（另开一轮）。
- `-a` 过期探测的结构整理（把中止词改成「输出流 + 一组订阅者」）：讨论过，作者定「现在这个结构能探测到就行」，不立项。

## Further Notes

- **这是行为变化，但不抬主版本**（作者定）：三类旧写法会开始报错——Linux 上 `-s 'docs\a.sh'`、Windows 上把远端路径写成 `-p '\opt\app\'` 或 `-d '\var\log'`、任何路径两端带空白。落地时记进 CHANGELOG 当天段（`[12.0.1]`）。
- **手册有两处要改**：第 1 节正文与 2.1 的表格写「清单第 4 列也必须是绝对路径」，与第 3 节「相对路径只在清单里能用」冲突——以第 3 节为准，改前两处。
- **实测支持**（Ubuntu 26.04 与 CentOS 7 两套真机）：Tab 补全的反斜杠由 shell 剥掉，程序收到的是裸名；单引号里的 `\` 现在被改写成 `/` 因而指错；远端括号靠单引号保护，加反斜杠必失败。空格同理——`os` 按字节精确区分，程序 trim 反而指错文件。
- **与 ADR-0002 的关系**：上传 `-p` 必须绝对、以 `/` 结尾，这两条断言不变；变的只是不再替使用者换分隔符。
