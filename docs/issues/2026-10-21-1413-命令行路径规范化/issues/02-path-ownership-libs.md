# 02: 取文件名与后缀改用与路径归属一致的规则

**要做的**：路径不再被改写之后，「从路径里取一段」的地方必须与路径归属对得上：本机路径按本机规则取，远端路径按远端规则取。涉及三处——自动备注（脚本名、上传名、下载名）、脚本后缀的解释器识别、下载时落到本机的文件名。现在这三处混着用：本机路径按远端规则切，远端路径又按本机规则切。差别只在 Windows 上显形（那一边的规则同时认 `\`），Linux 上两种切法结果一样——所以下面的验收大多写着「Windows 上」。**只负责「名字取对」**：取出来的名字在本机写不下去时，按下载失败报出来，不许改名换地方落盘；怎么拼目录不在本轮（见 Out of Scope）。

Status: ready-for-agent
Blocked by: 01（取值先变原样，Windows 上才看得出切法对不对）

- [ ] Windows 上 `-s D:\a\b.sh` 的自动备注是 `b.sh`（看参数确认屏的「备注」行）
- [ ] Windows 上 `-u D:\a\b.txt -p /opt/` 的自动备注是 `b.txt`
- [ ] Windows 上 `-s D:\dir.v2\deploy`（没有后缀）：解释器提示里显示的后缀是空，不是 `.v2\deploy`
- [ ] Windows 上 `-d /var/log/app.log` 落到本机的文件名是 `app.log`
- [ ] Windows 上 `-d /var/log/a\b.log`（远端那个文件的名字里带反斜杠）：明细里显示的文件名是整段 `a\b.log`，不是 `b.log`。**本机写不下去就按「下载失败」报出来，不许悄悄改成 `b.log` 落盘**——`\` 在 Windows 上不是合法文件名字符，这条钉的是「名字不被偷偷换掉」
- [ ] Linux 上同样下载 `a\b.log` 仍落成 `a\b.log`（回归：两边本来就一致，不能改坏）
- [ ] 全量 `go test ./...` 除开工前就红的那条（清理归 06）外无新增红
