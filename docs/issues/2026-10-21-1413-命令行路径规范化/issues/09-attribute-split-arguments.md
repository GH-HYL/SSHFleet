# 09: 参数被 shell 切开时点出是哪个选项

**要做的**：使用者在路径值里漏了引号、被本地 shell 按空格切开时（`-p /opt/my dir/` → `-p` 收 `/opt/my`，`dir/` 变成多余参数），工具在**参数解析阶段**就报出「哪个选项的值后面还多出一段」，并给出加引号的写法。八个收路径的选项全适用：本地路径同样要报——`os` 拿到 `/opt/my` 只会说「不存在」，它无从知道原本是一整个，所以这条提示只能由我们在交给 `os` 之前发。

Status: ready-for-agent
Blocked by: 无（可立即开工）

- [ ] `-p /opt/my dir/`（未加引号）报错里同时出现选项名 `-p` 与多出的那一段 `dir/`
- [ ] 八处逐一验：`-s`、`-u`、`-p`、`-d`、`-f`、`-a`、`--convert-secret`、`--change-password` 各跑一条被切开的写法，报错都点得出自己的选项名
- [ ] 提示给的是双引号写法（`-p "/opt/my dir/"`），并写明 bash / Git Bash / cmd / PowerShell 都认双引号；**不提单引号**（cmd 与 PowerShell 不认它分组）
- [ ] 通配符被终端展开（`-u /x/abc/*` 变多个路径）走同一条报错，文案里「被展开」与「被切开」并列，不硬猜是哪一种
- [ ] 切开后的后半段以 `-` 开头时，仍按「不认识的选项」报错，两种文案指向同一件事，都不出现「请重试」这类空话
- [ ] 现有的「出现多余的参数」用例保留不删，新增断言覆盖「选项名出现在报错里」
- [ ] 两平台 `go test ./...` 全绿；手动跑一遍 `-p /opt/my dir/` 贴原文进 Comments

## Comments

- 2026-10-26：审计追加。现有拦截在 `internal/cli/args.go:366`，只列多余的段、不归属到选项，使用者看不出是哪一条被切开的。作者 2026-10-26 定：这块单独建工单；识别必须发生在交给 OS 库之前，因为 OS 只会把它当成一个值，判不出原本是一整串。
- 抓不到的两类，不属本条：① 切开后的后半段恰好是另一个选项的合法值，被人家吃掉；② 引号已被 shell 消费，我们看到的只是切片——这两类只能靠「必须是绝对路径」那条兜。
