# 08: 清单凭据报错不再回显原值

**要做的**：加密打开、清单第 4/6 列还写着明文密码或口令时，这一列的报错会把原值整段印在终端与工具日志里，而那份日志常常要发给别人看。做完之后，报错照样点出行号、IP、列名，并说清「加密时这一格该写凭据文件的路径」，但**不再把原值整段念出来**——只留够辨认的那几位（前后各两位，或只留长度），形态在终端与工具日志里一致。第 5 列是私钥**路径**，按原样回显，不在本条范围内。

Status: ready-for-agent
Blocked by: 无（可立即开工；与路径整改无关）

- [ ] 加密开启 + 第 4 列写一个不像路径的短串（如 `hunter2`，会被当相对名去拼 `secret_dir`）→ 终端与 `history/SSHFleetTools.log` 里都不出现完整原值
- [ ] 同一条报错仍含行号、IP、列名，以及两条去路：在 `config/SSHFleet.conf` 的 `[credential]` 段配 `secret_dir`，或这一格改写本机绝对路径
- [ ] 第 6 列（私钥口令）同样不回显完整原值
- [ ] 第 4/6 列写的是真路径且文件存在时，正常流程不受影响（该读到的仍读到）
- [ ] 脱敏形态在终端与工具日志两处一致，不出现一处脱敏、一处原样
- [ ] 新增断言覆盖「报错文本不含完整原值」；既有用例不因脱敏改期望值而静默放松
- [ ] 两平台 `go test ./...` 全绿（Windows 本机 + WSL2 Ubuntu）
