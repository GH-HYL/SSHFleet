# 下载枚举按 NUL 切，开传之前先查本机重名

- **Status**：done
- **日期**：2026-11-23
- **关联**：ADR-0063 决定 4（枚举走 NUL，不追求协议原生）、决定 7（下载前查本地重名）、决定 8（判重与创建之间的时间窗不处理）

## Problem Statement

下载有两处会让使用者拿到错的结果。

一处是名字：远端枚举现在按行切，文件名里带换行时，一个文件会被拆成两三条记录。拆出来的碎片要么变成一个不存在的路径、下不下来，要么把后面那个文件的名字吃进前一条的路径里。使用者看到的是一台机器「成功 3 个、失败 1 个」，而远端目录里根本没有这四个名字。这类文件在运维脚本自动生成的报表里并不罕见。

另一处是本机重名：下载直接以「覆盖」的方式写本机文件（建文件就截断）。同一个远端目录下第二遍，上次取回来的文件被悄悄改掉；而那一次如果中途失败，留下的是被截断的半截——使用者手上同时失去了旧的那份和新的那份。这与工具对上传定的「不覆盖」不是同一个口径。

## Solution

枚举改成按 NUL 切记录：一条远端 `find` 打印「类型 大小 相对路径」，每条以 NUL 收尾。名字里有什么字符都不影响切分。

目标机不认 `-printf` 时（BusyBox 一类）走退路：`find -print0` 只拿名字，大小与「是不是软链接」由同一条 SFTP 会话逐个问一次。慢，但那是少数机器上的事。

开传之前，先把每个文件的本机落点查一遍：已经存在同名文件就整批拦下——报出是哪些名字、这台终止、一个字节都不写（连落地目录都不建）。分类名是「本机文件已存在」，与上传的「远程文件已存在」对称。

## User Stories

1. 作为运维，远端报表里名字带换行的文件，我希望照原样取回来，而不是被拆成几个不存在的路径。
2. 作为运维，目标机是 BusyBox 那种不认 `-printf` 的机器时，我希望下载照常能用，而不是报一条看不懂的枚举失败。
3. 作为运维，本机已经有同名文件时，我希望工具停下来告诉我是哪个文件，而不是直接把它截断重写。
4. 作为运维，本机重名被拦下时，我希望分类名一眼看出「要先清本机」，而不是笼统的「本机写入失败」。
5. 作为运维，被拦下时我不希望本机多出一堆空目录或半截文件——一个字节都不该写。

## Implementation Decisions

### 枚举主路：NUL 记录

一条命令同时枚举真文件与软链接：

```sh
find '<路径>' \( -type f -printf 'F %s %P\0' \) -o \( -type l -printf 'L %P\0' \)
```

`sudo` 时在这条命令前面加 `sudo `。解析只认 NUL：按 `\x00` 切，最后一段为空丢掉；每条以 `F ` 开头的是真文件（后面是大小、一个空格、相对路径），以 `L ` 开头的是软链接（后面是相对路径）。

`%P` 给的是相对起始点的路径，所以路径里带不带引号、名字里有没有空格换行，都不影响「哪一段是名字」。不以 `F `／`L ` 开头的记录跳过——那是远端在 stdout 上说了别的话。

### 枚举退路：`-print0` 加逐个 `Lstat`

主路那条命令退非 0 时，改用：

```sh
find '<路径>' \( -type f -print0 \) -o \( -type l -print0 \)
```

同样按 NUL 切，但拿到的名字是起始点的完整路径。剥掉起始点前缀（起始点结尾的 `/` 先去掉）得到相对路径；大小与类型由同一条 SFTP 会话 `Lstat` 逐个补：`ModeSymlink` 置位算软链接，其余算真文件、大小取 `Size()`。

`Lstat` 报错（枚举与 `Lstat` 之间文件被删了、路径突然不可读）按枚举失败收场，报文带那条路径与原因——那时不知道它多大，接着传只会在核大小那一步对不上，不如当场说清。

退路也退非 0 时，报退路那条的原文：主路的失败多半只是「不认 `-printf`」，那是预期内的，没有信息量。

主路与退路都只发一次，不重试（枚举失败不是可重传的失败，ADR-0063 决定 10 的名单里没有它）。

### 本机重名：开传之前整批查

位置在「枚举完、`totalFiles` 判定之后」，**建落地目录之前**。逐条算出本机落点 `本地目录/<IP>/<相对路径>`，用 `os.Lstat` 看名字是否已被占用。

- 用 `Lstat` 不用 `Stat`：断掉的符号链接也算「名字被占用」，`Stat` 会当它不存在，然后 `os.Create` 顺着链接写到别处去。
- 名字在本机落不下的那些（含本机分隔符、保留设备名）跳过这一查——它们会在逐文件那一段按「本机文件不可用」报出来，两条判据不重叠。
- 命中任意一条即整批拦下：本机一个字节都不写、落地目录不建、远端不读。

### 环节名与分类

新环节名 `local_exists`，报文一行：

```text
sshfleet.transfer.local_exists: already exists locally: <相对路径>, <相对路径>
```

冲突的路径全部列出来，不只报第一个：使用者要逐个清，报一个就得回来跑第二遍。

分类名「本机文件已存在」，关键词 `sshfleet.transfer.local_exists`，tip：

> 本机下载目录里已经有同名文件，工具不覆盖——要覆盖先把它清掉再下载

位置：`config/keywords_error.conf` 第一组，排在「远程文件已存在」之前。两条说的是同一类事（工具不覆盖），按方向分开认；新条目带的是自己那条报文前缀，不写 `file already exists` 这种会被对面吃掉的通用串。

### 四个数

整批拦下时按 `failTransfer` 记账：`TotalFiles` 是枚举出来的个数，`FailFiles` 与它相等，`SuccessFiles` 为 0。与空间不足、本机读不了那几条早退同口径——一个文件都没开始传，就都算失败。

### 使用者可见面

`docs/1-使用手册.md` 的下载一节补一句：本机已有同名文件时工具不覆盖、整批停下，先清掉再下。

## Testing Decisions

**接缝**：`execute.Run`——执行站入口，递一张纸收一张纸。用例只断言那张纸与假目标机、本机临时目录上的文件。

**假目标机加两个开关**（同一个假件上加，不新造）：

- 拒绝 `-printf`：命令里带 `-printf` 就退 1 并在 stderr 说一句「unrecognized」，退路那半照常应答。这样一条用例就能钉住「不认 `-printf` 的机器仍下得下来」。
- 多吐一条记录：在真实枚举结果后面追加一条带换行的记录，例如 `F 4 weird\nF 4 ghost.txt`。用它钉住「NUL 记录不按换行拆」——按换行切这一条会变成两条记录，按 NUL 切仍是一条。

**用例**：

1. 退路：开关打开后下载照样成功，四个数与内容对得上，`Steps` 里枚举那条仍是 0。
2. 带换行的记录：`TotalFiles` 是「真文件个数 + 1」。按换行切会多出一条（碎片被当成第二个文件），这个数就是判据。
3. 本机重名：预置一个同名文件（内容与远端不同），跑完分类是「本机文件已存在」，本机那份内容一个字节没变，落地目录下没有多出别的文件，远端那个文件仍在。
4. 判据：`internal/execute/verdict_test.go` 的 `classifyTables` 里按随包顺序补上「本机文件已存在」，再各加一条用例——只含 `sshfleet.transfer.local_exists` 的归它，只含 `remote_exists` 的仍归「远程文件已存在」。

**造不出来的那条**：Windows 上文件名不许带换行，假目标机跑在真实文件系统上，所以「名字带换行的**真**文件」造不出来。第 2 条用多吐一条记录代替——它判的是解析，不是落盘。

**真机**：`-tags integration` 的既有下载用例走 GNU find，主路天然覆盖；`find -print0` 的退路只在假目标机上验，真机上没有 BusyBox 样本。
