## 一、现状（实测抓取）

`pathWithoutSpace` 被 `-s`/`-u`/`-d`/`-p`/`-f` **五个选项共用**，且跑在**存在性检查之前**。
后果是它把七条**本来更准的报错**全部截胡：

| 选项 | 被截胡的真错（拿掉检查后才会露出来） |
| --- | --- |
| `-s` | `-s 参数指定的脚本文件不可读：cat /etc/os-release` |
| `-s` | `-s 参数指定的路径是目录，不是脚本文件` |
| `-u` | `-u 参数指定的上传文件或目录不存在` |
| `-u` | `-u 参数指定的上传文件或目录是符号链接` |
| `-f` | `-f 参数指定的文件不存在` |
| `-f` | `-f 参数指定的 CSV 文件为空` |
| `-d` 的 `-p` | `下载模式：-p 参数指定的本地路径必须是已存在的目录` |

**对照实测**（同一个错误：想跑命令、敲了 `-s`）：

```bash
cd build/atest-4
./SSHFleet -f csv/nodes.csv -s 'cat /etc/os-release'
# 现在：  原因：-s 的取值中间不能有空格
#         提示：-s 收的是本地脚本文件路径，不是一条命令或一整行文本
# 拿掉后：原因：-s 参数指定的脚本文件不可读：cat /etc/os-release

```

后者**自带答案**——`a.Script` 存的是完整值，整串命令原样摆在报错里，
使用者一眼看出「把命令当文件了」。前者要拐三个弯（空格？引号？`-u` 是什么？）。

## 二、为什么收窄（作者 2026-10-15 裁定）

### 2.1 本地路径根本不需要这条检查

| 参数 | 值的性质 | 能验存在性 | 空格检查的作用 |
| --- | --- | --- | --- |
| `-s` | 本地文件 | ✓ | **无**，纯截胡 |
| `-u` | 本地源 | ✓ | **无**，纯截胡 |
| `-f` | 本地文件 | ✓ | **无**，纯截胡 |
| `-d` 的 `-p` | 本机目录 | ✓ | **无**，纯截胡 |
| **`-u` 的 `-p`** | **远端目录** | ✗ | **有用**——验不了，只能靠匹配拦 |
| **`-d` 的值** | **远端路径** | ✗ | **有用**——同上 |

**正确的分类不是「路径参数」一类，而是「本地路径」与「远端路径」两类。**
现状把它们混在一张表里过同一个检查，这正是分类错的根子。

### 2.2 这是最初写代码的人划过的线

原始 Python 版 `SSHFleet_py/src/core.py:96` 的注释原文：

```python
# 路径中间不能包含空格,不是路径不能包括空格,不能以空格开头
```

**「不是路径不能包括空格」**——当初就划了这条线：这条检查只对「真的是路径」的东西成立。
代码里没实现这个条件，只留了注释；Go 重写时连注释一起丢了。

### 2.3 代价可控

真忘了加引号时（`-u /opt/my dir/app`），shell 会把参数拆成两截，`-u` 拿到半截路径。
此时报的是「文件不存在：/opt/my」，**不再是「空格」**。

覆盖面没丢：`args.go:360` 那条「出现多余的参数（未被使用）」本来就会拦下后半截
`dir/app` 并明说「路径含空格但没加引号」。**两处配合，比现在多一层而非少一层。**

## 三、要做的事

1. **把空格检查的范围收到两个远端参数**：`-u` 的 `-p`、`-d` 的值。
2. **`-s`/`-u`/`-f`/`-d 的 -p` 不再过这条检查**——交给各自的存在性验证。
3. 收窄后，第一节表里那七条真错会自然露出来；**逐条核对它们能给出正确指引**。

**MUST NOT** 顺手改那七条真错的文案（它们本就在正确形态上）；
**MUST NOT** 扩大范围到检查逻辑本身的其他部分（红线 4）。

> **2026-10-15 订正（实施中）**：本条原有一条「`-f` 那条提示要补上『路径带空格时加引号』这个可能」，
> **已删除**。作者的判据：「`-f` 这种本地路径，不管是什么办法，只要本地能识别它存在就可以，
> 跟是否引号没关系——能识别就行，不能就不行。」
>
> 复核判定链：`-f` 的值 → `os.Stat` 一查 → 找到就用（**不管里面有没有空格**）、
> 找不到就报「文件不存在」。**空格从头到尾不参与判定**；引号是 shell 层面的事
> （防止 shell 把路径拆成两段），与工具侧的判定无关。把 shell 的问题写进工具的提示里，
> 等于重新提出一个工具已经不关心的问题。

## 四、验收

逐条实测，改前/改后对照：

```bash
cd build/atest-4

./SSHFleet -f csv/nodes.csv -d '/var/my log' -p ./adir/   # 远端 -d 应仍报「空格」
./SSHFleet -f 'my list.csv' -c uptime                     # 应报「文件不存在」且提示提到空格
```
