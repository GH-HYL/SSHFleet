Status: done（2026-10-15 审计完成；三条工单均已实施，本文件是该批的事实底本）

## 一、审计范围怎么收的

### 1.1 第一步：按「参数确认屏之前」切

参数确认屏在 `main.go:364`（`confirm.Confirm`）。**这个位置之前，使用者还没见过任何确认界面**，所有报错都是他敲完命令立刻撞上的——正是「使用错误」最集中的地带。

全工具的致命错误出口共 **25 个**（`main.go` 里的 `fatal()` 调用），按此线切：

| 位置 | 数量 |
| --- | --- |
| 确认屏**之前**（`main.go:364` 以前） | **18** |
| 确认屏之后 | 7 |

### 1.2 第二步：按「使用错误 vs 工具故障」再筛

对 18 个出口逐条判「触发原因是不是使用者可以做对的事」：

| 出口 | 位置 | 归属 | 处置 |

## 二、审计单位怎么切的

**审计单位 = 使用者屏幕上看到的一次完整输出**，不是代码里的一行 `Errorf`。

依据：`pathWithoutSpace` 只是 `args.go:462` 一行，但使用者看到的是 `main.go:222` 拼出来的四行（`[ERROR]` 前缀 + 原因 + 提示 + 日志行）。统计代码行会把「一个出口展开成几十条」这件事漏掉。

## 三、实测枚举

**实测方式**：全部在沙盒 `build/atest-4/` 里跑真实可执行文件，输入构造到「报错即停」（报错都发生在连网之前，不需要真实节点）。命令与输出逐条留档，下面是摘录。

### 3.1 模式错配矩阵（本次核心）

主题：**使用者想用某个模式，却敲成了另一个**。五个模式选项 `-c -s -u -d --change-password` 穷举。

| # | 想做的事 | 实际敲的 | 实际输出 | 提到正确选项？ |
| --- | --- | --- | --- | --- |
| 1 | 执行命令 | `-s 'cat /etc/os-release'` | 路径参数中间不能包含空格（举例 `-u`） | ✗ |
| 2 | 执行命令 | `-s 'uptime'` | -s 参数指定的脚本文件不可读：uptime | ✗ |
| 3 | 执行命令 | `-u 'cat /etc/os-release' -p /opt/` | 路径参数中间不能包含空格（举例 `-u`） | ✗ |
| 4 | 执行命令 | `-d 'cat /etc/os-release' -p ./adir/` | 路径参数中间不能包含空格（举例 `-u`） | ✗ |
| 5 | 执行命令 | `--change-password 'cat /etc/os-release'` | **不报错**，当新密码收下（屏显 `ca****se`） | ✗ |
| 6 | 跑脚本 | `-c 'good.sh'` | **不报错**，确认屏显示"执行命令: good.sh" | ✗ |
| 7 | 跑脚本 | `-u good.sh -p /opt/` | **不报错**，确认屏显示"上传模式" | ✗ |
| 8 | 跑脚本 | `-d good.sh -p ./adir/` | 下载模式的远程路径必须是绝对路径 | ✗ |
| 9 | 上传 | `-c 'afile.txt'` | **不报错**，确认屏显示"执行命令: afile.txt" | ✗ |
| 10 | 上传 | `-s afile.txt` | 问"继续用 bash 作为解释器吗？"（`.txt` 没配解释器） | ✗ |
| 11 | 上传 | `-d afile.txt -p ./adir/` | 下载模式的远程路径必须是绝对路径 | ✗ |
| 12 | 下载 | `-c '/var/log/app'` | **不报错**，确认屏显示"执行命令: /var/log/app" | ✗ |
| 13 | 下载 | `-s '/var/log/app'` | -s 参数指定的脚本文件不可读 | ✗ |
| 14 | 下载 | `-u /var/log/app -p /opt/` | -u 参数指定的上传文件或目录不存在 | ✗ |

**14 格里没有一格提到正确选项。** 5 格静默通过（只靠确认屏让使用者自己看出不对），9 格报了错但对错因零提示。

**最典型的两格**：

- 第 1 格就是本轮开头那个真实案例：想跑 `cat /etc/os-release`，敲了 `-s`，工具报"路径参数中间不能包含空格"，提示举例还是 `-u`——**答非所问，且给出的出路是假的**（加引号也没用，空格在值里面，引号早在 shell 层被剥掉了）。
- 第 10 格：想上传 `afile.txt`，敲了 `-s`，工具问他"继续用 bash 作为解释器吗"。

### 3.2 跨选项举例（点名要查的）

全量扫描 `internal/` 与 `main.go` 里所有含「例如」的报错文案，核对**举例的选项是不是报错主体**：

```
internal/cli/check.go:69   举例=-p   全条文案只含 [-p]     ← 一致

```

**`args.go:462` 是唯一一条举例跨选项的**，且它的杀伤面被放大了五倍——见下。

### 3.3 `pathWithoutSpace` 的五个影响面

`args.go:460` 的 `pathWithoutSpace` 被 **5 个选项共用**（`-s`/`-u`/`-d`/`-p`，加 `-f` 的文件分支）。逐面触发，**输出完全一致**：

```
▓ -s  值=my script.sh   →  路径参数中间不能包含空格 / 举例 -u "D:/my dir/app"
▓ -u  值=my file.txt    →  路径参数中间不能包含空格 / 举例 -u "D:/my dir/app"
▓ -d  值=/var/my log    →  路径参数中间不能包含空格 / 举例 -u "D:/my dir/app"
▓ -p  值=/opt/my dir/   →  路径参数中间不能包含空格 / 举例 -u "D:/my dir/app"
```

四个选项出问题，**举例永远只给 `-u`**。

**另有一处两条检查互相打架**：`-f 'my list.csv'` 因为先走 `resolveSource` 判定路径存在性，根本走不到空格检查，报的是：

```
原因：-f 参数指定的文件不存在：my list.csv
提示：要临时传几台机器，可以直接写一行以 IP 开头的节点信息，例如 192.168.1.1,22,root,密码
```

同一个问题（路径带空格），`-f` 报一种、其余四个报另一种。

### 3.5 检查得不错的对照组

为免一边倒，实测确认**表现良好**的那批（都点名了具体选项、说清了语义、给了可行出路）：

## 四、问题清单

### A. `args.go:462` —— 一条文案、五个面、举例永远错（最该改）

- 报错主体是「路径参数」，**没点名是哪个选项**
- 举例固定给 `-u`，`-s`/`-d`/`-p` 出问题也照给
- **给的是假出路**：值里的空格加引号也没用，真正的原因多半是他把命令写进了路径选项
- 五个面输出一字不差

### B. 模式错配无识别（本次最大面）

`-c` 与 `-s` 的区别、`-c` 与 `-u`/`-d` 的区别，**系统从没在任何一处告诉过使用者**：

- `-s` 拿到命令（带空格）→ 报"空格"
- `-s` 拿到命令（无空格）→ 报"文件不可读"
- `-s` 拿到非脚本文件 → 问"用 bash 吗"
- `-c` 拿到任何东西 → **一律照单全收**，只在确认屏显示

同一个错误报出四种不同的话，没有一种提到 `-c`。

### C. 静默通过（比报错更危险的一类）

5 格实测**完全不报错**，其中 `-c` 那三格要等确认屏、`--change-password` 那格把命令当密码收下了。~~确认屏是唯一的兜底。~~

> **2026-10-15 更正**：「确认屏是唯一的兜底」这句**是未经验证的结论，已作废**。
> 本审计的边界是「参数确认屏之前」（见 1.1），审的是**屏之前报什么**；
> 确认屏本身**没做过枚举**——那 5 格只是跑模式错配矩阵时顺带看到「它走到确认屏了」，
> 屏上完整长什么样并没记录。**顺带看见不等于枚举过。**
> 故此句不成立，确认屏相关的结论全部撤销（见 `spec.md` 更新记录）。
> 观察部分（5 格不报错）仍然有效。

### D. 不点名选项的文案

10 条（见 3.4），集中在「值有问题」这类——文件名塞在 `%s` 里，丢掉了选项名这个上下文。

### E. `-f` 与其余四个选项口径不一致

同一个空格问题，`-f` 报"文件不存在"、其余报"空格"。
