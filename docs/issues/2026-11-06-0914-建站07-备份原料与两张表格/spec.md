# 规格：阶段 07——备份原料、脱敏副本与两张表格

**Status**：done

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

**例外只有一处**：遮收成「一种算法、一个出口」，撞第三条「不改行为」——开发者 2026-11-06 明示「遮蔽只有一种方法，而且只能从这个横切包去遮蔽」。见 `Implementation Decisions` 第六节，并记成与老版的已知差异。为让它机械成立，`guard` 加一条判据，属改检查本体（开发者同一句话即点头）。

## Problem Statement

运维人员跑完一次，回头要查「那天到底对哪几台做了什么」。老版给了四条路：`history/` 下那一次的目录自动就是全套证据——脚本与代填的原件在 `assets/` 里，清单那份副本密码已经遮过，`results.xlsx` 一行一台十五列，`terminal-output.xlsx` 把终端上那些行拆成三列能筛能搜，工作目录下 `latest_history` 一点就是最新那一次。

新版跑到今天，这四条路只通了一条半：目录建出来了，`report.txt`、`terminal-output.txt`、执行期日志都在，可是 `assets/` 是个空壳、两张表格根本没有、`latest_history` 不存在。运维人员想回答「上周那批用的是哪个脚本」只能自己翻本机路径，而那个路径可能早被改过；想按 IP 筛一遍只能拿文本去搜。

阶段 05 的 A/B 把这件事量出来了：同一次运行，老版归档目录比新版多出三个实体——`assets/u1.csv`、`results.xlsx`、`terminal-output.xlsx`。那是推迟，不是漏。

## Solution

跑完之后，那一次的目录与老版一样是**能独立回答问题的**：脚本与代填原件在 `assets/` 里、清单副本里的密码已经遮掉、两张表格在目录里（关掉开关就不生成）、工作目录下的 `latest_history` 指向最新那一次。老版盘上有的，新版盘上也有，内容逐格对得上。

## User Stories

1. 作为运维人员，我跑完一次之后，`assets/` 里能找到这次用的脚本与代填文件的原件，不受本机路径后来被改动的影响。
2. 作为运维人员，清单副本也能找到，但里面的密码与私钥口令是遮过的——把归档目录整个拷走不会顺带把凭据带走。
3. 作为运维人员，我用 `-f` 直接在内联记录里写节点（没有文件）时，`assets/` 里不会凭空多出一个清单文件。
4. 作为运维人员，我上传目录跑完，`assets/` 里不会多出被上传的那批文件——它备份的是「我给了工具什么」，不是「我传了什么」。
5. 作为运维人员，我打开那一次的 `results.xlsx`，一行一台，字段与老版那张表一样（序号、IP、端口、用户名、连接成功、退出码、两张耗时、传输四个数、分类、报错原文、输出内容）。
6. 作为运维人员，我打开 `terminal-output.xlsx`，能按 IP 与事件类型筛——连接、执行、错误、输出逐行、分类各占一行，与 `terminal-output.txt` 里看到的是同一批话。
7. 作为运维人员，我在配置里关掉 `output_to_xlsx` 或 `results_to_xlsx`，对应的表格就不生成，其余产物照旧。
8. 作为运维人员，某一张表没生成出来时，屏幕上有一句说清是哪一张、为什么、这次跳过了，这次执行的结果与退出码不受影响。
9. 作为运维人员，我在工作目录下点 `latest_history` 就进到最新那一次的目录；它不是快捷方式而是真能当目录用的入口。
10. 作为运维人员，工作目录里本来就有一个叫 `latest_history` 的普通文件时，工具不去删它，只警告一句就跳过。
11. 作为维护者，两张表格里的每一个字都出自 `message`，报告站不自己拼句子——表格与终端对不上时只有一个地方要改。
12. 作为维护者，结构检查仍然拦得住越界：多加一个第三方库要在白名单里记一行，别处不能随手 import。

## Implementation Decisions

### 零、今天的盘面（核查过的事实）

| 样东西 | 今天的状况 |
| --- | --- |
| `assets/` 目录 | 建了、空的（`archive.Create` 建根时一起建） |
| 脚本、代填原件 | 没复制；纸三上连原路径都没有（`Resources` 只有 `Manifest`） |
| 清单脱敏副本 | 没写；`mask` 只会遮单个值，不认列、不写文件 |
| 两张表格 | 没有；`go.mod` 里没有 `excelize`，`report` 站只写 `report.txt` |
| `latest_history` | 没有；`history/` 下只有工具日志与本次目录 |
| 报告站手上的东西 | 只有纸三：总账、逐台明细（`NodeResult`）、判据表、密文、资源格 |
| 报告站缺的东西 | 脚本与代填的原路径、每台的端口与用户名、两个 xlsx 开关 |

### 一、报告站是收尾的编排点，写盘按结构决定分派

老版由一个 `output.Render` 一次做完五件事（报告、备份、两张表、链接）。**编排点不变，写盘归属照 ADR-0032 决定四「写盘的归属：谁产内容谁写」分派**，报告站不越俎：

| 这一摊里的哪一件 | 谁写 | 依据 |
| --- | --- | --- |
| `report.txt`、两张表格 | 报告站 | ADR-0032 决定四（原文点名「报告文件与两张表格归报告站」） |
| 脚本与代填的原样复制 | `archive` | 同条（「备份脚本与代填文件（原样复制）归 `archive`」）——所以 `archive` 出一个「把这几个原料复制进 `assets/`」的整件事，报告站收尾时调它 |
| 清单的脱敏副本 | `mask` | 同条；报告站把「源路径 + 目标目录」交给它（`mask` 不自己向 `archive` 要目录——横切包之间不许互相依赖） |
| `latest_history` 链接 | `archive` | 作者 2026-11-01：备份执行资源与「最新一次」链接归归档包 |

同一条里还有一句「`archive` 不代写——代写就得懂所有格式，那是抽屉」。**本阶段按「原样复制不算代写」读**：复制一份脚本没有格式可懂，懂格式的是报告与两张表格——那两样仍归报告站。`archive` 的硬规矩照旧收在「不替别人写它们该产的内容」这一层。

报告站只做三样：**调这三家、自己写那两样、把失败收成事实**。它不读配置、不拼路径——要的东西全从参数与纸上来。

`report.Run` 的入参从「账 + `report.txt` 落点」长成「账 + 落点组（`archive.Paths`）」：落点已经有现成的结构，这一轮只为两张表多两格，直接递那一组，不把五个路径摊成五个参数；两个 xlsx 开关走密文（见第四条），不占参数。

### 二、纸二加两格端口与用户名，纸三原样带

`results.xlsx` 那十五列里有「端口」「用户名」，纸三的逐台明细里没有（`NodeResult` 只有 IP）。老版每台那行本来就从节点表抄了这三样。

**加在 `NodeResult` 上，执行站建行时从纸一的节点上抄。** 不另在纸三加一张节点表，因为那会让纸三比纸二宽——ADR-0035 决定三（后一张除本棒结论外不比上一张多一格）挡着。加在逐台那一行里，纸二、纸三一样宽，规矩不破。

「序号」不加：它就是逐台明细的次序（从 1 起），报告站按下标算。

### 三、脚本与代填的路径不新开纸上的格，走密文

阶段 05 把 `Resources.Script`、`Resources.Answer` 删掉时留了话：「没人读就不加，07 真要用时再说」。现在有人读了，但**不必把两格加回纸上**——运行上下文里已经有脚本路径（`ScriptPath`，报告站印「脚本：」那一行就用它），加第二份就是同一份原值两个来源，正是 05 删它们的那条理由。

所以只补一格：**`-a` 的原值进密文**（可能是一份代填文件的路径，也可能是内联代填）。报告站备份时按「是不是一个存在的普通文件」现判，判不出来就跳过——与清单那份同一处判据，也与老版 `copyFile` 同一口径（空串、目录、找不到，一律跳过）。

**清单不动**：它的原值已经在资源格里（`Manifest`），报告站印「节点清单：」与备份都读它。

### 四、两个开关走运行上下文的密文，不给塔尖多一样东西

`enable.output_to_xlsx`、`enable.results_to_xlsx` 是解析站读配置得到的原值。它们**进运行上下文（密文）**，报告站解开才用——与 `ShowCategoryTips`、`ErrorKeywordsPath` 同一族：报告站要、纸上没有别的来路、也不该由塔尖抽出来单递。

两条规矩在这儿同时成立：

- 报告站不回头读配置（ADR-0014、ADR-0015：执行侧与站都不读配置）；
- 塔尖不许把某一项从信里抽出来当另一个参数递过去（ADR-0035 决定八），它手上除信封、结论、入口常量之外不该有第四样。

先例是 04 阶段那两格（`ShowCategoryTips`、`ErrorKeywordsPath`），同一条理由、同一个落点。**不进 `RunParams`**：执行参数那一格服务的是执行站，报告站不读它，装了就是同一份原值两个来源。

### 五、备份原料：脚本与代填原样，清单遮列，上传的不备份

| 原料 | 怎么备 | 谁写 | 为什么 |
| --- | --- | --- | --- |
| 脚本（`-s`） | 原样复制一份，文件名不变 | `archive` | 脚本里没有凭据 |
| 代填（`-a` 给的是文件） | 原样复制 | `archive` | 代填内容按已定的「留痕优先」口径明文记录，与 `report.txt`、工具日志同一口径 |
| 清单（`-f` 给的是文件） | **脱敏副本**：第 4 列密码、第 6 列口令各遮成「前 2 + `****` + 后 2」，其余列与注释行原样 | `mask` | 明文密码写在清单第 4 列，原样复制等于把凭据又存了一份 |
| 清单（`-f` 是内联记录） | 跳过 | —— | 没有文件可备份 |
| 上传的源文件 | 不备份 | —— | 备份的是「我给了工具什么」 |

三条路径由报告站取：清单从资源格来，脚本与代填从解开的密文来（见第三条），再递给 `archive` 与 `mask`；它自己不动这几份文件。

- **遮只有一种形态**（开发者 2026-11-06 定）：一个秘密遮成「前 2 + `****` + 后 2」；四个字符以内整个换成 `****`。清单副本、`--change-password` 的值、`-f` 内联记录里的那两段、屏幕上与 `report.txt` 里贴出来的命令行，**全是这一种**。见第六节。
- 读列按 CSV 规则走：值可能整段带引号、引号里可能包着逗号，按裸逗号切会把段号切错、把密码漏在外面。表头、注释行、认不出是节点的行一律原样。
- **按行原样保留**：换行符、结尾空行、注释行都在，用户拿副本当清单用也能直接跑。

### 六、遮只有一种算法，且只有 `mask` 能遮

**两条一起成立**（开发者 2026-11-06：「遮蔽只有一种方法，而且只能从这个横切包去遮蔽」）：

1. **一种算法**：`Secret` 那条——前 2 + `****` + 后 2，四个字符以内整段抹。别的算法一律不认。
2. **一个出口**：认秘密、算遮法、替换明文，全部住 `mask`；任何别的包只许把**已经遮好的值**拿去用，不许自己截字符、自己拼星号。

**今天的四处各走各的**（核查过）：

| 哪一处 | 今天怎么遮 | 本阶段之后 |
| --- | --- | --- |
| `--change-password` 的值、屏幕上与 `report.txt` 里的命令行 | `mask.Secret`：前 2 后 2 | 不变 |
| `-f` 内联记录里的第 4、6 段 | `mask.InlineRecord`：整段 `****` | 换成 `Secret` |
| 改密的采集输出里出现明文密码（远端 PTY 关回显前可能回显一次） | 执行站自己 `strings.ReplaceAll(text, 明文, "****")`，硬编码星号 | 改成调 `mask` 的那件事：把已知明文从一段文本里擦掉，算法仍只有一条 |
| 清单副本的第 4、6 列 | （还没有） | `Secret` |

`mask` 对外仍是几件**整件事**，不是一个遮值函数外加一堆零件：遮一个值、遮一条内联记录、遮命令行、把已知明文从一段文本里擦掉、照源文件写脱敏副本。五件内部都调同一条算法、用同一个 `****` 常量。

**机械保障**：`guard` 加一条判据——除 `mask` 包与 `_test.go`，任何源码文件里出现 `****` 字面量即报；检查本体自己那一份文件不扫自己，因为它要认得那个记号才找得到它。这是**改检查本体**，属「单独点头」档；开发者 2026-11-06 上面那句话即点头。落点与 ADR 配套（ADR-0032 第四条要记一类）写进对应工单。

**这条改的是已经交付的显示行为**：确认屏、`report.txt`、工具日志上那条命令行都会变，改密失败时的输出里也会出现「前 2 后 2」而不是整段星号。因此记成**与老版的已知差异**（老版这两处都是整段抹）：09 的逐字比对要认这条；切换判据那三条哨兵不涉及它。

**清单脱敏副本也归 `mask`**：`mask/doc.go` 已经写着「清单的脱敏副本也由它写」，`report/doc.go` 也写着「向 archive 要 assets 路径，交 mask 算与写」，只有 `mask/mask.go` 顶上那句还写着「不在本包，随阶段 07」——同一件事两处说法，本阶段收成一处（改表述，不改决策）。据此 `mask` 收「源路径 + 目标目录」写出脱敏副本；报告站只把路径递过去、把错误收上来。横切包不认识站，方向不倒。

### 七、两张表格的字只能出自 `message`

这是本阶段最容易走偏的一处：老版 `output.WriteOutputXlsx` 自己拼「连接: 成功 - 0.123s」「分类: xxx」这些字，与终端那几行是两套代码。新版不许这样——**话只能由 `message` 造**。

`message` 对一台结果出一份**行表**：每行三列（IP、事件、详情）+ 一个「进不进终端文本」的标志。两个读者：

- `terminal-output.txt` 与屏幕：按现有版式从行表拼出来，**输出逐字节不变**（06 的 A/B 已经把这份文本钉死了）；
- `terminal-output.xlsx`：三列直写。

事件那一列的取值照老版：`连接: 成功 - 0.123s`、`执行: 成功 - 0.456s`、`错误`（详情是报错原文）、`标准输出和错误输出`（详情是输出的一行）、`分类: 分类名`，结果之间一条浅蓝分隔行。

老版有一处两版不一致：连接失败那台，`terminal-output.xlsx` 照样印一行「执行: 失败」，而 `terminal-output.txt` 不印。这处照老版——标志位就是为它设的，别为了「两边一致」去改终端的文本。

### 八、`results.xlsx` 的十五列照老版，取值逐格对

列序与表头一字不改：序号、IP、端口、用户名、连接成功、退出码、连接耗时、执行耗时、传输字节、文件总数、成功文件数、失败文件数、分类、报错原文、输出内容。

- 「报错原文」列只在失败那台填（成功那台不显示服务端提示，D34 口径）；未送出的代填已在 `ErrorText` 里还原成触发词原文，报告站不再算一遍。
- 「分类」列印展示名（与屏幕、`report.txt` 同一套名字），不印内部字段。
- 列宽：A–M 按内容自适应（内容宽 + 2），N 与 O 固定（30 / 50）。读写进 xlsx 的每一格都要过一遍清理（非法 UTF-8、ANSI 转义、控制字符、行首 `=` 前补空格）——远端输出是任意字节流，不清会把文件写坏。
- 有自动筛选，表头蓝底白字带边框，数据格带细边框：照老版样式，不重新设计。

### 九、失败怎么收场：照老版分三档

| 哪一步 | 老版 | 新版 |
| --- | --- | --- |
| `report.txt` 写不出来 | 起不来（退 1） | 不变 |
| 备份原料失败 | 起不来（退 1） | 不变 |
| 某张表生成失败 | 屏幕一句 + 工具日志一句，**跳过、不中断** | 报告站自己上屏（`message` 造、`console` 打），并把「哪张表、什么原因」交回塔尖落日志 |
| `latest_history` 建不起来 | 警告一句，不中断 | 同上一条的形状 |

**上屏由报告站自己打**：ADR-0032 决定四列的「调终端的地方」四处里本来就有报告站（结论与报告上屏），它已经在打统计块——把它再绕回塔尖，同一个动作就有两条路。**留痕（日志）才交回塔尖**：报告站不持日志句柄，与闸门把「非交互放行」那句话交上来落盘同一个形状。

「跳过不中断」的理由照老版注释：终端一关，只有工具日志能说明这次的表格为什么没生成。第 8 条 User Story 说的就是这一句。

**那三句是使用者可见文本，措辞逐字照老版，由 `message` 收成构造点**（塔尖只转手，不持字）：

| 场合 | 老版原句 |
| --- | --- |
| 某张表没生成 | `生成 %s 失败：%v（本次跳过，不影响执行结果）`——`%s` 是那张表的文件名 |
| `latest_history` 撞上同名普通文件 | `当前目录已存在同名文件 latest_history，跳过链接创建（如需快捷入口，删除该文件后重跑）` |
| 链接建不起来 | `创建 latest_history 目录链接失败：%v` + 换行 + `提示：Windows 使用目录联接（需目标位于本地 NTFS 卷），POSIX 使用符号链接` |

前两句老版走 `[ERROR]` / `[警告]` 两个前缀，新版照旧带——标签与配色由呈现那一侧给，句子本身不进 `report.txt`。

### 十、`latest_history`：软链接与目录联接各一份实现

**这件事归 `archive`**（作者 2026-11-01：备份执行资源与「最新一次」链接归归档包），报告站收尾时调它一次；成不成交回报告站、再按第九条那句警告走。

- 扫 `history/` 下的目录，字典序即时间序，取最后一个，建链接指向它的绝对路径。
- POSIX 用符号链接；Windows 用目录联接（junction）——老版有这份平台实现，照搬，不另造。
- 已经是指向别处的链接：先删再建（只删链接本身，不动目标）。
- 同名普通文件：警告一句跳过，**不删**。
- 判「是不是链接」只用 `os.Readlink` 试一次：Go 1.23 起 Windows 的目录联接不再被标成 `ModeSymlink`（是 `ModeIrregular`），拿 `ModeSymlink` 判会漏。
