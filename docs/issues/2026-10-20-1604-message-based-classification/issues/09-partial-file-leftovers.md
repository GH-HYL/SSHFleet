# 09: 半成品残留要照实说

**要做的**：上传或下载某个文件中途失败时，工具会删掉写到一半的那个文件；删失败（或 sudo 路径的临时文件清不掉）时，现在**一声不吭**，使用者只看到「失败原因」，看不到目标机/本机还留着一个半成品。这条做完之后，这类残留会以一条报文出现在报错原文里，统计块能看出「还有东西要手工清」。

**被谁阻塞**：无，可立即开工（ADR-0022 已立，只补「回滚失败照实说」的边角）。

**状态**：done

- [x] 非 sudo 上传：写失败后 `Remove` 半成品失败 → 报文 `sshfleet.transfer.partial_left: half-written file left: <远端路径>`
- [x] sudo 上传：临时目录 / 临时文件清理失败 → 同一条报文，列出临时路径；`mv` 到最终位置失败时先 `Stat`，确认最终路径真的存在才报（不误报）
- [x] 下载：本地半成品 `os.Remove` 失败 → 报文 `sshfleet.transfer.local_partial_left: half-written file left: <本机路径>`
- [x] 报文追加在回滚报文之后，不覆盖已有原文（ADR-0021 追加纪律）
- [x] 判据表：`partial_left` 归「上传回滚未清干净」，`local_partial_left` 归「本地文件错误」
- [x] 语料：一条 `partial_left` 用例，期望「上传回滚未清干净」
- [x] `go vet` / `go test ./...` 通过

## 为什么单独一条工单

ADR-0022 决定第 3 条要求「回滚失败照实说」，但只覆盖了「本次已写成功的文件删不掉」。**写到一半的文件**不在 `writtenPaths` 里，删除失败就被 `_ =` 吞了。补它要动上传/下载函数的返回形状（把残留路径带出来），不是改一行的事，所以单独记。

## 与 04/08 的关系

- 04（传输报文）建立了 `rolled_back` / `rollback_partial`；本条补的是「半成品」这一档，报文名不同，避免把「没写成功」混进「写成功但没删掉」的计数里。
- 08（部分成功计数口径）已随 ADR-0022 撤掉，与本条无关。
