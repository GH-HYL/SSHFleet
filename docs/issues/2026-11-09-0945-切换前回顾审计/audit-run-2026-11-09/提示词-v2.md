3. **红线 40 条**：名单与指纹是否对得上（对不上 `go test` 就红）；指纹钉的是不是「测试名＋直接引用的生产符号」；有没有删掉／改名／收窄引用面却没走 ADR 的。**A16 那条指纹换样本是走过 ADR 的，别当成未走程序的例子。**
4. **A2 正向破坏试验**：在 `build/` 副本里**把结构改坏**——五站反向 import 一条、往契约里加一个函数、在站里写一句自拼的话——看 `go test` 是不是真红。**每类破坏一处，记红／不红。这是本轴最硬的一条证据。**
5. **红线用例站哪儿（A14）**：有没有红线用例被挪进自定义区、或与自定义区共用假件包、或让红线测试 import 了第二个被测包（出口／import 白名单破了）。
6. **台账 0 条**：是核过的 0（逐条查了没有放行）还是没核的 0（没看台账机制）；台账机制本身有没有第二个入口能让检查闭嘴（改规则表、改检查本体、环境变量开关这类）。
7. **结构上抓不到哪些形状**：检查按语法树数，那么注释、字符串、`go:build`、`_test.go` 豁免、`//go:linkname`、反射调用——**只列抓不到的形状清单**，不列修法，也不与轴 01 报的实例重列。

**回执里要有的分母**：九项各造了几个样本（共几个）、29 次改动看了几次、40 条 fingerprint 核了几条、破坏试验做了几类几处、抓不到的形状几个。
