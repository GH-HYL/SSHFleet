## §0 给分发审（只读设计，不读代码）

你的任务**只有一件**：看这包提示词把地盘切全了没有。

**审计目标（一句话）**：一个把老工程按五站重排的新工程建完了，要回头判「架构站不站得住、检查器可不可信、等价证据的边界在哪」——本轮先发三条轴：结构边、检查本体、等价口径。

**给你的东西**：

- 被审对象三圈：见 `交接清单.md` 第一节（改动面 18 个包／符号级引用表／一条跳邻域／边界）。
- 本轮提示词包：`§1` ＋ `§2` ＋ `§3` ＋ `§4`。
- 本轮**不派**的轴（后面轮二才派）：04 腐蚀度、05 `execute` 包内、06 `parse` 包内、07 `message` 包内、08 其余十三包、09 塔尖、10 真机、11 规范面（`/code-review`）、12 切换面；另有一个复核员与一个反证员（轮三）。

**不给你的东西**：主 agent 的推理与预判、被证伪的历史、具体技术论证。**也不要自己去读代码或跑命令**——你审的是设计，不是内容。

**四类必查，逐条给结论**（不成立就写不成立）：

| # | 查什么 | 判据 |
| --- | --- | --- |
| 1 | 轴间缝隙 | 三条轴的文件域并起来，覆盖「三圈」里的**改动面**了吗？邻域里的下游／上游／同构兄弟，有没有哪块谁都没认领？**本轮没派的轴不算缝**——但要说清哪块留给哪条轴，别留成「谁都不碰」 |
| 2 | 轴间重叠 | 有没有两轴审同一块？同一文件的不同面不算重叠，前提是白名单写清了各读哪一面 |
| 3 | 预设污染 | 提示词里有没有夹带主 agent 的判断？「注意 X 可能有问题」已经是替子 agent 下结论 |
| 4 | 边界与产出 | 每轴的文件域、回执要写什么、硬伤与判断题的区分、分母，写清了吗 |

**产出**：只写 `分发缺口-轮一.md`，每条写清「缺什么、补哪个轴或补哪条约束」。**不写修法以外的评价，不写代码结论。**

## §1 公共件（每份轴提示词都带）

> 以此为准。议题文档里的具体修法是被审对象，不要被它带偏；发现实现与锚不符，报锚，不要报工单。

### 1.1 你在干什么

你在给一个已经建完的新工程做**回顾审计**：老工程按五站重排，代码 100% 落地、逐阶段验收过了，现在回头判它**站不站得住**。你审的是**代码**，不是文档。文档（ADR、规格、工单）是线索——去哪看、当初为什么这么定——**不是判据**。

### 1.2 锚（判据只有这一处）

**层 1（最高，压住下面两层）**：`../spec.md` 的 A1–A3——老版行为等价（五命令、五模式、屏幕、`report.txt`、退出码）；结构被破坏时跑测试就红，不靠人盯；切换只改一行目录名。

**层 2**：`ADR-0032` 的 A4–A9——五站单向；契约独立、只放类型与常量、零函数；交接件必须新造；横切叶子包＋权限表＋终端只出 `console`＋拼句只出 `message`；塔尖只搬不做；老工程冻结。

**层 3**：`ADR-0033`–`0043` 的 A10–A20——施工决定，**它们自己也在被审范围里**：

```text

A11 拒绝与起不来分两种失败；拒绝只住闸门、起不来住契约；各站不许自己退；危险检测只出判断；闸门不写话（0034，混合）
A12 交接件按「棒」定形状：一个信封、三次口径、五种装法；载荷五份不合并；除本棒结论不许加格（后两棒改「只装下一站要用的」）；契约不放函数；塔尖只搬不装；结果侧＝通用格＋一个带标签附加格＋随行件密文（0035，混合）
A13 五模式不聚成包、站内按模式分文件；载荷用带标签的一格；密钥管理独立包、凭据读取叶子包，五站与它互不 import（0036，混合）

A16 红线 ask 指纹样本换 message.ConfirmPrompt，指纹改三个符号（0039，明示＋推导）

A18 改密分类表不合并、按模式选表专用表在前、呈现侧只认名字、keywords_error.conf 节名改单数（只管新工程）（0041，明示＋推导）
A19 中断信号只登记一次不撤；两段只是状态位；信号层收进横切包（第九个）；重复按一律忽略；连按单独手工验（0042，明示＋推导）
A20 报告站入口收改「第三张纸＋archive.Paths」，交回 warnings＋error（0043，推导）
```

**A1–A9 的原文有两处作废**，按 `交接清单.md` 第三节那张 13 条更新记录表读（横切包现为**九个**、检查**七类九项**、`time` 按调用点判、`parse.Run` 四种结局……）。

**锚质疑出口**：发现某条锚与源码、实测或上游 ADR 对不上——**不许改写锚，也不许并进普通发现**，另起一节「锚质疑」，写清哪条锚、哪份证据、按什么判。改不改锚由开发者定。
**反过来**：「实现没守住锚」是**代码发现**，不是锚质疑。前者进回执正文，后者单列。

### 1.3 重心

只审**代码质量与架构**。文档问题顺带记一句（写进回执末尾「顺带」），**因文档导致实现跑偏的着重记**。

**判据只取仓库自身**（ADR／`GLOSSARY.md`／`docs/个人开发规范.md`／既有导出符号）。**不许拿通用最佳实践当判据。**

### 1.4 授权

**只做只读分析，不得修改任何文件。** 唯一可写的是你自己那份回执：`audit-run-2026-11-09/回执/NN-<轴>.md`。

- 不改代码、不改检查面与红线、不改文档、不补测试。
- 要跑构建／测试的：**临时产物只落 `build/` 下**，`GOTMPDIR` 一并指过去，不许 `/tmp`。

### 1.7 回执写什么

落 `audit-run-2026-11-09/回执/NN-<轴>.md`，一节一条：

1. **位置与证据**：`file:line` ＋ 一条能翻回原处的证据。
   - **行为类**（跑起来不一样）：要一条**跑过的命令与它的输出**。
   - **腐蚀类**（站里自己拼了一份本该 `message` 出的句子）：没有命令可跑。给 `file:line`、同一形态出现了几处、可复算的计数。**不许因为跑不出命令就不报。**
2. **分两档**：【硬伤】＝事实错误、边界被破坏；【判断题】＝可权衡，写清理由与代价。
3. **每条先判它伤哪一条**：腐蚀架构／行为变了／只是架构取舍——三格分开写，不混。
4. **末尾给分母**：本轴核了 N 处（依赖边／检查项／用例／断言），报了 M 条。**分母对不上，说明你抽查了一段就交。**
5. 没发现问题就**明说「未发现问题」**，不要凑条数。
6. **只报问题，不给修法，不排优先级。**

回执写完即只读，不再改。

## §2 轴 01：结构边

**文件域**：`modules/SSHFleet2_Go/` 全部（含 `internal/guard/` 的规则表与检查本体**读**，不评它好坏）；`modules/SSHFleet_Go/` 只作对照；`docs/adr/0032`–`0043` 只查「权限表怎么写的」。
**不碰**：`cmp.py` 与 09 的归一化口径（轴 03）；`guard` 判据可不可信（轴 02）；`execute`／`parse`／`message` 包内质量（轮二的 05／06／07）。

**要回答的**：五站单向、塔尖唯一编排、契约零函数、横切三条边、话只从 `message` 出、闸门只许造拒绝——这些在代码里是**守住了**，还是**只写在文件里**？

**判据是拿真实改动走一遍**：边界挡不挡得住、绕不绕得开。

要查的绕法，一种一种来：

1. **依赖边本身**：实际 import 边 vs `ADR-0032` 第四条权限表（按 13 条更新记录改后的口径）。`交接清单.md` 第一节有现成的包级边表，`符号级引用表.md` 有逐符号的下游。
2. **三种 import 绕法**：`_test.go` 的依赖方向豁免；`go:build` 标签；检查器读不到的写法。
3. **每站至少造一条「本包内合法却省事」的写法**，看它拦不拦——**这是本轴的重点**：
   - 自己拼一份本该由 `message` 出的话；
   - 回读上游的字段（同一站内合法 import、但绕过了交接件）；
   - 按老版特判（`if mode == ...` 这种只有老版才需要的分支）。
   **每站一条，五站都要**。造法用 `build/` 下的模块副本，不改原件。
4. **塔尖**：`main.go` 的符号面与 import 面是否只做分叉／搬／退；五种结局是否都在；有没有自己判断的痕迹（读配置、看文件在不在）。

**回执里要有的分母**：核了几条包级边、几处跨站符号引用、五站各造了几条省事写法、其中几条被拦。

## §3 轴 02：检查本体

**文件域**：`internal/guard/` 全部（检查本体、规则表、红线名单、放行台账、`testdata/`）；`git log --since=2026-10-30 -- modules/SSHFleet2_Go/internal/guard`。
**不碰**：被检查的代码本身是否违规（轴 01 判「有没有绕」）；等价口径（轴 03）；规范符合度（轮二的 11）。

**要回答的**：`guard` 七类（九项）与红线 40 条是不是**真判据**？

1. **正负样本**：七类逐类造一个违规样本（报告不报？）与一个合规样本（不该报？）。样本落 `build/` 下的副本里，不改原件。九项要逐项对，别把「类」当「项」。
2. **29 笔 `guard/` 提交逐笔看**：什么时候改的、改了什么、为什么。**检查本体被改过的地方一条一条看**——是补判据，还是为了过关放宽了名单／收窄了指纹／把断言挪去了别处／把红线测试挪出了自定义区。判据是 `docs/个人开发规范.md` 与 ADR-0032 那份「凡是能让检查闭嘴的东西，改它都等同改约束类文件」。
3. **40 条红线指纹**：名单与指纹是否对得上（`go test` 直接红就是没对上）；指纹钉的是不是「测试名＋直接引用的生产符号」；有没有删掉／改名／收窄引用面却没走 ADR 的。
4. **放行台账 0 条**：是不是真 0，还是台账被绕过（有 `nolint` 式的旁路口子吗）。
5. **检查读不到的写法**：检查按语法树数，那么注释、字符串、`go:build`、`_test.go` 豁免、`//go:linkname`、反射调用——哪些是它结构上抓不到的。**只列抓不到的形状，不列修法。**

**回执里要有的分母**：七类各造了几个样本、九项各判过没有、29 笔提交看了几笔、40 条指纹核了几条、抓到／没抓到的形状各几个。

## §5 下发给子 agent 时的最后一句

每份提示词末尾原样加这一句：

> 回执只写你这一轴，别替别的轴下结论；写到「未发现问题」也要给分母。
