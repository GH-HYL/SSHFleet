# 卡点：这场审计里技能不顺手的地方

**写于** 2026-11-09，轮四。只记「换下一次也会撞上」的，不记一次性故障。

---

## 一、限流与中断：任务的颗粒度没有上限

**现象**：轮二 12／07／08 三路在 19–29 分钟处被中断，回执未落盘；轮三第一路 4 分钟处撞 429 被杀，无产出，重派三遍才成。
**不顺手在**：技能按「一轴一路、一次跑完」设计，但没有「跑到一半怎么落盘」的规定——三份被中断的回执全靠续跑自己补「先落盘、未做完的写进未覆盖面」，这规矩是主 agent 临场加的。
**代价**：重派一次的成本 ≈ 一轮的时间；轮三实际花了三倍。

## 二、任务书自相矛盾，要到下发那一刻才发现

**现象**：轮三提示词 §1.4 写「轮二不上真机」，§11 整节要求上真机跑 ssh；两句同时在一个文件里，子 agent 只能自己猜哪句作废。另一处是 v4 首段自述与正文不符（自述说只装两节，正文里轮二九节全在）。
**不顺手在**：分发审（技能 2.3）是在**写完提示词之后**才跑的，所以它只能「事后抓矛盾」，不能阻止矛盾被写进去。
**代价**：一次下发前返工；如果分发审漏了，子 agent 会按错误的 §1.4 不碰真机，整轮白跑。

## 三、条数记账没有机械口径，总数会漂

**现象**：三张问题清单各报 40／67／3，交接清单最后写成「67＋3＝70」，漏了轮一 40 条；报告写到全量单时才发现，三张清单的编号实数是 110。同一件事还有：旧名命中数在提示词（14）、交接清单（32）、扫描表（15）三处不同；包级边在交接清单写 14、实际 46（14 只是塔尖一家）。
**不顺手在**：技能要求摊平成清单，但没要求「一条一个编号、用脚本数总数、跨表引用只认编号」。
**代价**：轮四写报告时先怀疑自己的加法，再逐表重数一遍；这类错一旦进了报告第一段，整份报告的可信度就没了。

## 四、工具的产出不能直接用，但没有校验环节

**现象**：`符号级引用表.md` 按裸符号名聚合「下游」列，`execute.Run` 的下游写着 `gate(82)`／`parse(73)`，而这几个包生产代码根本不 import `execute`；「84 个无下游」出自同一个脚本。
**不顺手在**：1.3 那步要求机械产出，技能没说「产出要拿一个已知答案反验一次」。
**代价**：轴 01 只能自己复算 46 条边才发现表不能用，然后在交接清单里加缺陷警告；后续所有轴都被交代「只当粗筛」。

## 五、回执冻结，但并账要补记，补记没有家

**现象**：轮二收账后有 5 条口报追加（`05-F11` 不推翻 A17、报文格式待裁、`answersOf` 补记为第 12 组、「跨包共享的判据没有家」单列、两处措辞更正），回执已冻结不能改，只能写进 `问题清单-轮二.md` §七。
**不顺手在**：技能只说「回执写完即只读」，没说「收账时发现的新事实落哪」。
**代价**：这些补记散在清单的第七节，报告写的时候要专门回去找一遍；下一次翻回执的人看不到。

## 六、分发审只审设计，分母的两种读法它抓不到

**现象**：轮三的分母写「12 格 × 2 形态 ＝ 24」，两种读法（新老两头比／新版自己两头比）都能满足；分发审抓到了，但它靠的是人读设计文本，不是对账。
**不顺手在**：技能里分发审的输入是「提示词 ＋ 交接清单 ＋ 规格」，不含「回执里已有的口径」——所以「这个分母和已收账的某条数是不是一回事」这类跨轮问题，它结构上看不见。
**代价**：轮三靠临场把格子改成「12 格 × 3 头 ＝ 36 个观测」，事后才补进回执；如果没抓到，回来时「做了几格」这句话没法核。

## 七、复核员与十二轴的边界，派发时要写死

**现象**：90 复核员与 11 规范面在「红线 import 白名单」上撞了一次——11 一度拟报硬伤，查实有 ADR 背书后自降为顺带；90 那边也登记了同一处。
**不顺手在**：技能说复核员「只补几轴覆盖不到的部分」，但「覆盖不到」是按面算还是按条算，没说。
**代价**：本轮靠 11 自纠解决，没有变成报告里的重复条目；但这是运气。

## 八、规格里指路指空

**现象**：`交接清单.md` §九 要求「合格／不合格各一句，分档按 spec『判据与分档』」，而 `spec.md` 没有这一节；实际能用的分档只有 `ADR-0038` 的三档（建站门槛／可切门槛／切换当天五步）。轮四按 A15 的三档写。
**不顺手在**：交接文档是跨会话唯一的入口，它指错一处，下一个会话就要花时间确认「这一节到底存不存在」。
**代价**：半小时的核对；更坏的情况是照着不存在的一节另立一套档，那报告就跟锚脱钩了。
