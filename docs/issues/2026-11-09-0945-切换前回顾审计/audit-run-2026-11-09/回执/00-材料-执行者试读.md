## 一、轮一执行者

### 1. 接手第一轮，第一件事是什么

**1.1【硬伤】两份材料都不给顺序，也不说 1.3 做没做。**

**1.3【硬伤】交接清单第 1 节没有按 1.3 做完，却计为「六节填完」。**
`交接清单.md:9`「一跳邻域（只读，不审）：老工程 `modules/SSHFleet_Go/`（对照物）；两份 `config/`（字段名对账）；`docs/adr/0032`–`0043`（被审决策）与 `0013`–`0031`（等价性参照）；`tools/release/release.py`」。这是「哪些东西在附近」的种子清单，不是 `PHASE-1-SURVEY.md:29` 要的「谁在引用它（下游）、它引用谁（上游）、同结构的兄弟实现在哪个包。只一跳，不递归；按『被改的符号』算」。第 1 节实际缺的是符号级引用表。

### 3. 必须停下来问人的地方，猜错会怎样

**3.1【硬伤】43 篇 ADR 的口径还没点头，而轮一要按新口径补锚。**
`spec.md:180`「待开发者点头的一件：说明把 43 篇 ADR 都算重构产出、都当被审对象；本规格只把 0032–0043 当被审对象，0013–0031 降为参照物。没点头之前，锚质疑按说明原口径报，其余照本规格取证」。同一份材料要求执行者同时跑两套口径：补锚按新口径（12 篇），锚质疑按旧口径（43 篇）。猜错会怎样：把 0013–0031 的行为冲突当锚质疑报上去，或反过来漏报；两种都会污染轮四第三段。

**3.2【硬伤】1.3 做没做，没人说。**
`交接清单.md:3` 说「底盘已落」，`PHASE-1-SURVEY.md:30` 的旧名残留扫描却全材料无产物。猜错会怎样：`PHASE-2-DISPATCH.md:47` 第 7 件固定件「旧名残留清单」没有内容可下发，每份提示词缺一件；分发审 `PHASE-2-DISPATCH.md:58` 只查四项（缝隙/重叠/预设/边界产出），不查这件，缺口会一路带到回执。

**3.3【硬伤】轮一是否派规范轴，材料两说。**
`SKILL.md:44` 段二出场清单「规范轴已派 `/code-review`」；`spec.md:63-74` 十轴里没有规范轴；`说明.md:9`「替代技能默认的轴切法」。猜错会怎样：漏派，段二出场清单核不过；多派，与「不重复 `/code-review`」边界（`SKILL.md:56`）和十轴的文件域重叠。

**3.4【硬伤】轮一要不要复核员，材料两说。**
`spec.md:79`「复核员……与各轴同时派，不等回执」；`PHASE-2-DISPATCH.md:99`「两个都要派」；四轮表 `spec.md:90-92` 只在轮二写「与复核员同时派出」。猜错会怎样：轮一 01/02/03 跑完没有独立框架兜底，轮二再补已是事后。

**3.5【硬伤】02 轴能不能跑 `go test`、用哪个账号，没写。**
`交接清单.md:63-64` 给了 Go 1.26.10、`-race` 可用、root 跑 `go build`／`go test` 的实测；`交接清单.md:72`「授权范围：只读」。`PHASE-2-DISPATCH.md:42` 只说「跑构建/测试的轴另写」，没说 02 是不是这种轴；`交接清单.md:70`「一轴一对（跑／目标）」也没说非真机轴要不要账号。猜错会怎样：02 要么不敢跑测试、只看代码（`guard` 的正负样本判不实），要么跑了但临时产物落错地方，触「只读」。

**3.6【硬伤】轮一执行者是不是摸底那个人，没写。**
`spec.md:97`「轮二起换新会话：本会话上下文已被摸底占掉大半」。意思是轮一与摸底同会话；但没写轮一执行者能否直接继承摸底时看到的东西。若换人接手，`交接清单.md:3` 的「底盘已落」没有清单说明落了什么、哪些只是看了一眼。

**3.7【判断题】这份 spec 的效力来自哪。**
`docs/个人开发规范.md:13`「谁的话算数：开发者说的决策才算数——他本轮对话里明说的话、本文件、工作区内的 `AGENTS.md`，只有这三处。其余一律只算输入」。`spec.md` 不在三处之内；它却规定了流程、唯一入口、甚至「工单按轮开」（见 4.9）。执行者若按规范第 13 行判，spec 只是输入，冲突时不能压过规范。材料没有交代开发者对本 spec 的授权。

### 4. 两条要求互相矛盾、会让人卡住的

**4.1【硬伤】「唯一入口三份，其余不读」与轮一必须读 12 篇 ADR 冲突。**
`spec.md:6`「唯一入口：本文件 + 当前那一轮的 `PHASE-N-*.md` + `audit-run-2026-11-09/交接清单.md`，三份，其余不读——不重读全量规格、不重读 43 篇 ADR」；`spec.md:55`「补锚只补 0032–0043 十二篇，每条抄一行」；`交接清单.md:53` 又要求真机轴读 09 议题 `交接.md`；`说明.md:42` 要求轴 03 读 09 `spec.md` 与 `build/建站09_AB_2026-11-06_1535/cmp.py`。四处都在这三份之外。

**4.2【硬伤】`guard` 六类与七类两说。**
`说明.md:12`「`guard` 六类与红线 40 条是不是真判据」；`说明.md:40`「`guard` 六条各跑一遍看报什么」；`spec.md:19`「`guard` 七类与红线 40 条」。代码里两说都有：`guard/report.go:14`「七类的名字」，`guard/check.go:19`「把六类跑一遍」，`guard/rules.go:3`「六类：五站、横切、契约、密钥管理、检查、塔尖」。`guard/report.go:22-30` 的 `allClasses` 有九项，且「类六」出现两次（`ClassTestSite`、`ClassHandoff`）。轴 02 的「七类正负样本」分母到底是 7、8 还是 9，材料没定。

**4.3【硬伤】`ADR-0032` 末尾不是七条更新记录，是十三条。**
`spec.md:32`「`ADR-0032` 五条决定 + 末尾七条更新记录」；`spec.md:95`「加 `ADR-0032` 末尾七条更新记录」。实读 `docs/adr/0032-按五站分层重构工程结构.md` 的「## 更新记录」，十三条（2026-11-01 四条、11-02 三条、11-05 一条、11-06 五条）。「七条」是从哪七条起算，材料没说。漏掉的六条里就有 2026-11-06「结构检查加第七类」，正好是 4.2 的类七。

**4.4【硬伤】改动面的提交数不是 166，是 63。**
`交接清单.md:7`「`modules/SSHFleet2_Go/` 全量，18 个包……2026-10-30 起 166 笔提交」。实测：

```text
git log --since=2026-10-30 --oneline | wc -l                     → 166（全仓）
git log --since=2026-10-30 --oneline -- modules/SSHFleet2_Go | wc -l → 63（改动面）
```

新工程第一笔提交是 `2026-11-01 01c3729`，10-30 时它还不存在。166 是全仓口径，被写进了「改动面」。轴 04 要答「最近一个月『一处改动牵动五个包』的提交有几笔」，分母用 166 会把比例压低约 2.6 倍。

**4.5【硬伤】A3 的判据文件被划成「不作发现对象」。**
A3「切换只改一行目录名」（`spec.md:45`、`交接清单.md:27`）。实现这一行的就是 `tools/release/release.py:54`：`MOD = ROOT / "modules" / "SSHFleet_Go"`。但 `交接清单.md:11`「`.gitignore`、发布脚本内容、老工程任何文件、`build/` 里的历史沙盒——都不改，也不作发现对象」；`交接清单.md:9` 又说 release.py「切换那天才动」。轴要判 A3，唯一证据被明令排除。

**4.6【硬伤】轴 03 必须读的 `cmp.py` 在「不作发现对象」的 `build/` 里。**
`说明.md:42`「与 `build/建站09_AB_2026-11-06_1535/cmp.py` 对一遍」；`说明.md:14`「`cmp.py` 从整份比 XML 改成逐格比就是这类改动，要看它放宽了什么」；`交接清单.md:11`「`build/` 里的历史沙盒——都不改，也不作发现对象」。读脚本算不算「发现对象」，两种读法：读不报，轴 03 交不出「口径有没有放宽」；读并报，违反边界。

**4.7【硬伤】「阶段 04/07/09 已审过不再审」会压掉轴 04/07/09。**
`交接清单.md:46`「已审过，不再审：阶段 03（`issues/16-audit-mustfix.md`）、阶段 04（质量审计 14 条全处置）、阶段 07（一轮质量审计）、阶段 09（37 场 A/B……）」。十轴编号同样是 01–10：轴 04 腐蚀度（本次重点）、轴 07 站内 `message`、轴 09 塔尖。`说明.md:51` 原话有范围限定——「04、07 各有一轮质量审计……这次只审它们没审的那四件事」；`交接清单.md:46` 把限定删了，只剩「不再审」。执行者可能把「阶段 04 已审」读成「轴 04 不审」。

**4.8【硬伤】「每个派发轮都要过一遍分发审」与四轮表只写轮一冲突。**
`spec.md:78`「分发审……每个派发轮都要过一遍，一轮就够，不循环」；四轮表 `spec.md:90-93`：轮一写「提示词过分发审」，轮二只写「按 `分发缺口.md` 改提示词」，轮三、轮四没有分发审。轮二派 04–09 与复核员、轮三派反证员与真机 10，都是派发轮。照四轮表走，轮二、轮三漏分发审；照 78 行走，四轮表欠三行账。

**4.9【硬伤】「工单按轮开，不在轮一之前建」与规范「跨轮 MUST 先落规格与工单」冲突。**
`spec.md:139`「工单按轮开，不在轮一之前建」；`docs/个人开发规范.md:110`「一轮对话干不完的（要跨会话、要分几次交付）→ MUST 先落规格与工单，再动手」；`:127`「工单 MUST 一条一个文件，编号从 `01` 起」。审计跨四轮、轮二起换会话，按规范必须已有工单；spec 明说不建。规范 `:317`「冲突以本文件为准」。

**4.10【判断题】「只做只读分析，不得修改任何文件」与「子 agent 直接写自己的回执」冲突。**
`PHASE-2-DISPATCH.md:42`「授权声明：『只做只读分析，不得修改任何文件』」；`PHASE-3-COLLECT.md:7`「子 agent 直接写自己的回执文件，落本次目录的 `回执/`」；`交接清单.md:17`「不改代码、不改检查面与红线、不改文档」；`spec.md:134`「`回执/NN-<轴>.md` 子 agent 原始结论，写完即只读」。若把「不得修改任何文件」按字面执行，子 agent 不敢建回执；若按「修改」不含「新建」读，又要它自己判断。每份提示词必须写明唯一可写的是自己那份回执，材料没写这句。

### 5. 一句话有两种读法的

**5.1【硬伤】「下层与上层冲突，以下层为准」——哪边是下层。**
`spec.md:27` 与 `说明.md:18` 同句。表里第 1 层在最上、第 3 层在最下。按「表的下方」读，施工 ADR（第 3 层，本身是被审对象）压过母规格 Destination（第 1 层）；按「地基在下」读，母规格压过施工 ADR。两种读法结论相反，且直接决定 A1–A3 与施工 ADR 谁大。

**5.2【硬伤】「末尾七条更新记录」——哪七条。**
`spec.md:32`／`:95`。实际十三条（4.3）。若取最后七条，从 2026-11-02 起算，2026-11-01 的四条（含「结构检查加第六类」）全漏；若取前七条，漏掉 11-06 的类七与三条权限表更新。两种取法都会让轴 01/02/08 少判据。

**5.3【硬伤】A5、A8 叫「推导项」，A7 同样授权来源却叫「混合」。**
`spec.md:53`「A5、A8 是推导项」；`spec.md:47` A5 授权来源「执行者提议、作者未反对」；`:50` A8 同；`:49` A7「混合」。实读 `docs/adr/0032` 的决策人一节：契约独立成包、横切分叶子包、塔尖只搬不做，三条同列「执行者提议、作者未反对（强度低于上一档，复审时请重估）」。按「授权来源决定重点」的口径，A7 的横切部分应与 A5/A8 同级；材料把它算「混合」，轴 08 可能不当重点。

**5.4【判断题】「每条抄一行『决定 + 授权来源』」——按 ADR 一条，还是按决定一条。**
`spec.md:55`。十二篇 ADR 里，单篇就有多条决定（如 0032 五条、0037 五条）。按 ADR 抄是 12 条（A10–A21），按决定抄会远多于 12。两种读法下提示词里的锚数量不同，分发审按哪个分母核也不清楚。

**5.5【判断题】「把红线测试挪出自定义区」——挪出还是挪进。**
`说明.md:12`「放宽名单、收窄指纹、把断言挪去别处、把红线测试挪出自定义区」。规范 `docs/个人开发规范.md:203` 说自定义区是红线区的豁免区，红线测试本来就不在自定义区；这里更像「挪进自定义区以取得豁免」。按字面「挪出」读，执行者会去找一个不存在的动作。

**5.6【判断题】「已审过，不再审」——整阶段不审，还是只不重审已审的那几点。**
`交接清单.md:46` 标题式写法无范围；`说明.md:51` 有范围「只审它们没审的那四件事」。`交接清单.md:46` 是被下发的那份，缺限定。

## 二、轴 02「检查本体」子 agent（非真机，轮一机械批）

选这一轴的理由：它同时压到材料最硬的三处——类六/类七、29 笔 `guard/` 提交、40 条指纹与台账；且它不需要真机，能把「提示词能不能写全」和「边界清不清楚」分开看。

### 6. 只凭材料能不能把提示词写全

按 `PHASE-2-DISPATCH.md:38-47` 七件固定件逐件对：

| # | 固定件 | 材料给了没有 | 缺什么 |
| --- | --- | --- | --- |
| 1 | 大方向锚 | 半给 | `交接清单.md:22-36` 有 A1–A9 速查，但 A5 写成「契约独立、零函数」，比 `spec.md:47` 少了「只放类型与常量」；A7 写成「横切权限表」，比 `spec.md:49` 少了「叶子包」。A10+ 未补；02 最需要的 0037（指纹钉法）还没有锚号。十轴表也没写哪条锚配哪一轴 |

### 7. 九条编号锚够不够判「这一处算不算越界」

**7.1【硬伤】「闸门只许造拒绝」没有锚。**
`说明.md:11` 把它列为架构成立的第一问六项之一；`spec.md:18` 同。A1–A9 里没有闸门这一条（A4 五站、A5 契约、A6 交接件、A7 横切/终端/拼句、A8 塔尖、A9 冻结）。ADR-0032 决定四有「拒绝只在闸门构造」，但它没有被抄成编号锚。轴 08 的核心问题「闸门是否只有一处能说『不』」在九锚里找不到判据。

**7.2【硬伤】A2 没有取证方法，且取证动作被只读禁止。**
A2「结构被破坏时跑测试就红，不靠人盯」（`spec.md:44`）。要判它，必须真把结构破坏一次；`交接清单.md:17`「只读」，`spec.md:159`「探针只落 `build/` 的模块副本」。副本怎么建、改副本里的代码后 `go test` 还算不算「这套测试」、guard 的路径假设在副本里成不成立，全没写。02 是唯一会碰 A2 的轴，材料没给它可执行的路。

**7.3【硬伤】A3 的证据文件被排除（同 4.5）。**
轴 01/02 都可能被要求顺带判 A3，但 `release.py` 明文「不作发现对象」。

**7.4【硬伤】A7「拼句只 `message`」与 ADR 的判据不是一回事。**
A7 写「终端只 `console`、拼句只 `message`」。ADR-0032 决定四的原话是「不必再加检查：别的包就算把字拼出来也送不到屏幕……判据是『拼了也没出口』，不是『有没有拼』。扫字符串拼接这类检查误报太多」。照 A7 字面，轴 05/06/07 会把站内每个 `fmt.Sprintf` 都算越界；照 ADR，拼了但送不到屏幕不算。两种判法结论相反，锚没带出这个区分。

**7.5【判断题】A5「零函数」、A6「新造」、A8「只搬不做」都没有边界定义。**
- A5：`var x = f()`（包级变量由函数初始化）、类型上的方法、`func` 类型别名，算不算「函数」？契约包现在只有 `const`（实测 `internal/contract/*.go` 无 `^func`/`^var`），但判据本身没写。
- A6：包一层、嵌入、类型别名、切片元素是上一站结构体，算不算「新造」？
- A8：`spec.md:50` 自己写「只搬不做，且自认『必要条件非充分』」——它自认不能当充分判据，却又被当结构判据用了十个阶段（`spec.md:53`）。「只」是程度词，规范 `:68` 要求「撞上程度词 MUST 调 `/my-grill`」，子 agent 没有对话通道，只能猜。

**7.6【判断题】A7 的「横切三条边」没有落到锚里。**
`说明.md:11`「横切包只三条依赖边」；A7 只写「横切叶子包与权限表」。「三条」是哪三条、权限表在哪（`guard/rules.go` 的 `Rule` 表，材料没点名），轴 08 判「横切有没有长出业务判断」要靠它。

## 三、单独判：没有上下文的人读完就动手，材料拦不拦得住走偏

**9.1 拦住的部分**：四件事都有明文。逐条挑文档错——`spec.md:153`「审成文档对账」与 `:154`「逐条挑文档错」；重跑对照——`:155`「重跑 A/B」；改被审的东西——`:159`「动被审对象」；把逐阶段结论拼成整体——`:158`「把逐阶段结论拼成整体结论」。这四条是这次最容易被带偏的方向，材料都写了。

**9.2【硬伤】「把每阶段审过当整体结论」拦住了，但反向的坑没拦：把「阶段已审」当成「不必再看」。**

**9.3【判断题】「改被审的东西」拦住了，但「在副本里改」的许可不清（8.3）。**
02 要造负样本、01 要验证边界挡不挡得住，最自然的动作是改一份副本；材料只给「探针只落模块副本」，没给副本的建法与可改性。执行者可能因为怕越界，只读不试，最后把「没验证」写成「未发现问题」——正好撞 `spec.md:160`「把没验证写成没问题」。

**9.4【判断题】「逐条挑文档错」拦住了，但轮一本身就是文档工程。**
`spec.md:55` 要抄 12 篇 ADR 的决定，`spec.md:6` 又说「其余不读」；`spec.md:55` 自己承认「抄全 43 篇会让轮一变成一次文档工程」。材料给了刹车（`spec.md:154` 另起「顺带」节），但没给「抄到什么程度算够」的停止条件。轮一执行者很容易在 ADR 措辞里耗掉一轮。

**9.5【硬伤】数字错觉会把人带偏：166 与 63、七条与十三条。**
