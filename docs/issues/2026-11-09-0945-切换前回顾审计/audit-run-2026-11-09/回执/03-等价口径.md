### E1【硬伤】`results.xlsx` 的 G、H 两列整格不参与比较，却被记成「归一化耗时的两种写法」

- **位置与证据**：`cmp.py:75-78`
  ```python
  # 结果表 G、H 两列是连接／执行耗时：两侧每场都不同，整格不参与比对。
  if col in ("G", "H"):
      continue
  ```
  实测两张表列范围：`results.xlsx` 为 A–O（G=连接耗时、H=执行耗时，表头见 `out/b1-command/old.history/results.xlsx`），`terminal-output.xlsx` 只有 A–C，所以这条实际只作用于 `results.xlsx`，但是**按列名屏蔽、不按 sheet 名限定**——以后任何一张表出现 G/H 列都自动不比。
  实测同场两侧的差异就在这两列：`old G2=0.070695699 / H2=0.0075137`，`new G2=0.060923199 / H2=0.006555499`（`out/b1-command/{old,new}.history/results.xlsx`）。
- **登记**：`audit.md:105` 写「归一化多了一样……归到规格第二节『耗时的两种写法』，不是新开一类」；`audit.md:18` 写「两张表里的耗时——G、H 两列数值格」；`cmp.py:5-6` 的 docstring 同样写「含两张表里的耗时格」。
- **问题**：实现不是「把写法归一化」，是「整格不比较」。两者代价不同：归一化后仍比，整格不比则这一格的一切都不可见——耗时格从数值变成文本、或变成一个别的数、或该格消失，都不会报。09 自己的历史里就有同型前例（E2 的端口那一格）。
- **伤**：行为变了（这一类差异从此不可判，不是已发现差异）。
- **档**：硬伤（判据被放宽，且登记写的是另一件事）。

### E2【硬伤】逐格比「最终显示值」，单元格类型不参与——07 抓到的端口那一类差异从此不可见

- **位置与证据**：`cmp.py:72-89`。字符串格走 `t="s"` 按下标查回原文（`:86-88`），数字格留 `<v>` 原文（`:81-83`），最后都变成同一个 `str`；`attrs` 除判断 `t="s"` 外不用，样式索引 `s=` 丢弃。
  也就是说 `<c r="C2" s="2"><v>2201</v></c>` 与 `<c r="C2" s="2" t="s"><v>NN</v></c>`（查回 `2201`）比出来相等。
- **前例**：`audit.md:99`「端口那一格：老版写数字，新版写文本」——07 阶段把它判成**真差异**并改了代码（`addb301`、`e21a783`），理由是「文本格在 Excel 里按字符串排序、左对齐，使用者按端口筛会看出来」。当前比法对这一类盲。
- **登记**：`audit.md:137` 只写「原来比 XML，字符串去重结果不同就误报，改成逐格比最终值（字符串按下标查回原文再比）」，理由是去重副作用；**没有写「单元格类型不再参与比较」**。
- **伤**：行为变了。
- **档**：硬伤（判据被放宽且未如实记录）。
