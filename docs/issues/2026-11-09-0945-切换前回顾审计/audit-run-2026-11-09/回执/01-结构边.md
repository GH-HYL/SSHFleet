## 三、一条一条

### S1【硬伤】站间反向依赖用空白 import 写，类二完全看不见

- **位置与证据**：`guard/scan.go:204` 建 `Imports` 表时把 `_`／`.` 的 import 整个跳过；`guard/check_deps.go:81` 只遍历这张表。于是**同一条边，写法不同，一个红一个绿**：
  ```go
  // build/…/SSHFleet2_Go/internal/settle/zzprobe_blank.go
  import _ "sshfleet2/internal/gate"
  ```
  实测：`go build ./...` OK；`go test ./internal/guard -run TestProjectIsClean` → `--- PASS`（零违规）。
  对照组（同一条边、普通 import，`zzprobe_ctrl.go`）→
  ```
  internal/settle/zzprobe_ctrl.go:11 [类二 依赖方向] settle 依赖了 gate。站之间单向：…
  ```
- **后果**：站与站之间可以存在真实的编译依赖与 init 顺序，而「五站单向」的机械判据说没有这条边。空白 import 不需要引用任何符号就能建边，比普通 import 更省事——正好是省事写法。
- **伤**：腐蚀架构。

### S2【硬伤】`console.Print` 的调用点没有边界，结算站可以自己上屏

- **位置与证据**：类一只认 `fmt.Print` 族／内建 `println`／`os.Stdout`／`os.Stderr`／`console.Writer`（`guard/check_terminal.go:42-86`）。`console.Print` 本身一个判据都没有。
  ```go
  // internal/settle/zzprobe_print.go
  func probeSay() { console.Print(message.InterruptLine()) }
  ```
  实测：`go build ./...` OK；`TestProjectIsClean` → PASS。
  对照：同包 `fmt.Println` → 类一红：`internal/settle/zzprobe_ctrl.go:15 [类一 写终端] 调了 fmt.Println 直接往标准输出写字。…`
- **后果**：`ADR-0032` 第四条那两句「调终端的地方有四处，按文件列……解析、闸门、结算三个站一个字都不许写」只对 `fmt` 与 `os.Stdout` 成立。三个站都能经 `console.Print` 自己出屏：屏幕次序、拒绝前的提示、「跑完才出统计块」这些由塔尖与报告站共守的次序，结构上可被任何一站插队。
- **伤**：腐蚀架构。

### S3【硬伤】「拼了也没出口」这条前提不成立——`message.Fatal` 收自由文本，站能把自拼句子送上屏

- **位置与证据**：`message/screens.go:46` `func Fatal(where, body, logPath string) Line`——`body` 是裸 `string`，只加一层 `[ERROR]` 外壳。
  ```go
  // internal/settle/zzprobe_raw.go
  func probeRawLine(what string) message.Line {
      return message.Fatal("settle", "这次 "+what+" 没收齐", "")
  }
  ```
  实测：`go build ./...` OK；`TestProjectIsClean` → PASS。
- **后果**：`ADR-0032` 第四条判据原文是「别的包就算把字拼出来也送不到屏幕……判据是『拼了也没出口』，不是『有没有拼』」。这一条对 `message.Fatal` 不成立：站自己拼的正文有出口，且是现成的。凡「起不来」那一屏（塔尖在用）、闸门造拒绝（`gate/run.go:105` 同一个函数）都走这条通道。字从站里出，`message` 只当字符串模板。
- **伤**：腐蚀架构（判据的前提是假的）。

### S4【硬伤】`os.Exit` 存成函数值再调，类三看不见

- **位置与证据**：`guard/check_exit.go:24,39` 只认「`CallExpr` 的 `Fun` 是 `SelectorExpr` 且 `sel.X` 是 `os`」这一种形状。
  ```go
  // internal/report/zzprobe_exit.go
  var probeDie = os.Exit
  func probeQuit() { probeDie(3) }
  ```
  实测：`go build ./...` OK；`TestProjectIsClean` → PASS。
  对照组（同包直调，`zzprobe_ctrl.go`）→
  ```
  internal/settle/zzprobe_ctrl.go:17 [类三 退出动作] 在 settle 包里调了 os.Exit。…
  ```
- **后果**：报告的 `Run` 已经在 `os` 里（`report/report.go:16` 引 `os` 写文件）。只要包里有 `os`，退出动作就能取到函数值绕过去；退出时 `finish` 的两件收尾（关日志、还码页）都不跑。
- **伤**：腐蚀架构。

### S5【判断题】类六之二在真工程里 0 对，交接件宽度没有判据在岗

- **位置与证据**：`guard/project_test.go:17` `Pairs: nil`；同一文件第 5 行注释「交接件对账表本阶段 0 对——三张纸随阶段 04 落地」。三张纸（`Plan`／`ResultPaper`／`Ledger`）随 04／05／07 已落地，表仍是 0 对。`ADR-0035:154` 的理由是「等宽的这一棒没有可判对象，所以它最后一次对账推到**全部阶段落完**，不是欠账」——两处说法不一致（一处「阶段 04」，一处「全部阶段」）。
  机制是活的：在副本里加一条 `-run TestZZProbeHandoff` 的探针、把 `Plan`→`ResultPaper` 配成一对，`CheckHandoff` 报 **14 条**「多了这一格」。所以不是坏了，是没接。
- **代价**：现行口径下「同一口径」只有一条，且它被钉成等宽不造新纸（见 Q1）；另两棒换口径，宽度判据（`to = from + Conclusion`）不适用。**按这套口径，这张表可能永远凑不出一对**——「交接件不许变宽」这一条因此没有可判对象，只能靠人读。
- **伤**：腐蚀架构（明示锚 A6 的宽度那一半无判据）。

### S6【判断题】`go:build` 文件被多扫：方向是更严，不是绕过

- **位置与证据**：`guard/scan.go:145-157` 按目录读全部 `.go`，不按 build 约束筛。
  ```go
  // internal/settle/zzprobe_windows.go
  //go:build windows
  import "sshfleet2/internal/gate"
  ```
  实测：`go build ./...` OK（Linux 上这份文件不参与编译）；`TestProjectIsClean` → **FAIL**：
  ```
  internal/settle/zzprobe_windows.go:6 [类二 依赖方向] settle 依赖了 gate。…
  ```
- **代价**：平台分文件（`console/width_*.go`、`archive/remark_*.go` 都是这个形状）里，任何一条按当前平台不合法的边都会在**任何**平台上报红——含那些在目标平台上根本编译不进去的边。走「加台账」那条路就等于给不存在的边记账。方向是安全的一侧（不会漏），代价是误报与台账被稀释。
- **伤**：只是架构取舍。

### S7【判断题】`_test.go` 的依赖豁免是真豁免，站间单向只是生产属性

- **位置与证据**：`guard/report.go:39-45`（类二不扫测试）。探针 `internal/settle/zzprobe_test.go` 引 `sshfleet2/internal/execute`，`TestProjectIsClean` → PASS。这不是只反映在探针上——真代码里已有同形：`internal/execute/it_setup_integration_test.go` 引 `parse.Run` 1 处（借解析站造集成场景）。
- **代价**：`ADR-0032` 明示给了这条豁免（「`_test.go` 只在写终端、依赖方向两条上豁免」），A14 只把红线测试挖出来。所以测试可以把任意两条站边连起来，而「一侧红线测试」只按文件名 `redline_*.go` 认（`guard/scan.go:191`）：站里写一条事实上的红线测试、名字不带前缀，就既不进类六的 import 白名单、也不进红线名单。
- **伤**：只是架构取舍（覆盖边界写在 ADR 里，但不是「结构上做不到」）。

### S8【判断题】`gate.Refusal` 的「包外实现不了」不成立（内嵌接口），但实际不通

- **位置与证据**：`gate/refusal.go:19-30` 用「接口 + 不导出方法」防外部实现。
  ```go
  // main_zzprobe.go
  type probeFakeRefusal struct{ gate.Refusal }
  var probeRefusal gate.Refusal = probeFakeRefusal{}
  ```
  实测：`go build ./...` OK。（Go 的接口内嵌会把 `refused()` 提升上来，`fake{}` 即满足 `gate.Refusal`。）
- **代价**：注释里那句「别的包实现不了这个接口，也就造不出一个非 nil 的 `Refusal`」与事实不符。实际不可达：只有塔尖与 `guard` 的测试能 import `gate`（站 import 它先撞类二，S1），而塔尖本来就持有退出权。所以现在的「拒绝只住闸门」靠的是**调用图**（只有 `gate.Run` 返回 `Refusal`），不是类型。
- **伤**：只是架构取舍（说明与事实不符，能力上没有新增出口）。

### S9【判断题】出口白名单只数函数与类型，变量／常量不数

- **位置与证据**：`guard/check_testsite.go:72,79` 只判 `len(funcs)`／`len(types)`；`exportedNames`（:91）只收 `FuncDecl` 与 `TypeSpec`。
  ```go
  // internal/settle/zzprobe_export.go
  var ProbeDefaultTimeout = 30
  ```
  实测：PASS。
- **代价**：站可以往外露任意多个包级变量与常量，「一个函数加一个类型」只对两类成立；而 A14 这一条本身的强度就低（作者明示交执行者定、强度更低）。
- **伤**：只是架构取舍。

### S10【判断题】`Secret` 同名两义且语义相反（`credential` 取明文 / `mask` 遮住）

- **位置与证据**：`credential/credential.go:90` `Secret(value string, encrypted bool) (string, error)`——解密取出明文；`mask/mask.go:26` `Secret(s string) string`——遮成 `****`。一个把秘密**还原**，一个把秘密**遮掉**，同名。
  同组还有一对：`contract.Answer`（代填条目的值+触发词）／`ask.Answer`（答是／答否／没答完的枚举）——两处都叫 `Answer`，`ask` 那份被 5 个包引用。
- **代价**：按 A13 该分（不同包、不同事，不合并）；代价在指称：调用点只靠包名区分，读错一次就是「把明文当作已经遮好的值」或「把枚举当条目」。这一轴里我只报指称风险，不主张合并。
- **伤**：只是架构取舍。

### S11【判断题】`SystemReason` 两份已经漂了：`message` 那份多认 `os.LinkError`

- **位置与证据**：`message/system.go:16` 认 `*fs.PathError` **与** `*os.LinkError`；`credential/value.go:114` 只认 `*os.PathError`。两处注释都写着「开发者 2026-11-06 定，两处认下不合并，**改这里要一起改那边**」。
- **代价**：这是「不许 import」逼出来的重复（`credential` 不能 import `message`），重复本身有授权；但两份已经不一致，说明「一起改」这条约定没有机械支撑——同一句系统原因经凭据包与经消息包出来会不同（链接类错误的 `GetFileAttributesEx <路径>:` 前缀只在 `message` 那份被剥掉）。
- **伤**：腐蚀架构（同一事实两个产出，已分叉）。

### S12【判断题】「字只从 `message` 出」只守住了外壳与出口；正文句子大量在站里成形

- **位置与证据**（腐蚀类，给可复算计数，无命令可跑）：
  - `parse`：带中文的 `fmt.Sprintf` **40 处**、中文字面量拼接 **21 处**（`internal/parse/*.go`，排除 `_test.go`，`grep -rn 'fmt.Sprintf("[^"]*[一-龥]'` 与 `"[^"]*[一-龥][^"]*"\s*+\|+\s*"[^"]*[一-龥]`）。例：`parse/collect.go:39`「-u 参数指定的上传文件或目录读不到：%s」、`parse/material.go:30-47` 一组四句。
  - `execute`：29 处 / 25 处（`execute/log_node.go:54-81`、`log_session.go:37-40`），多数进工具日志。
  - `settle`／`report`／`gate`：0 处（`gate` 的危险表排版在 `message/danger.go`，闸门只做取注释、补空格这类文本预处理）。
  - 字进屏的合法通道是「纸上的自由文本格」：`contract.CannotStart.Body`、`contract.Problem.Detail`（`contract/plan.go:132`，注释自陈「一句事实说明」，`message/refuse.go:78` 直接用它拼报错）、`contract.ResultRow.Detail`。塔尖把 `Body` 原样交给 `message.Fatal`（`main.go:64`），因此那 40 处 Sprintf 的产物直接是屏幕上的一段正文。
- **代价**：措辞、标点、数字写法有第二个可改处；改一次口径要扫站（与「改一处口径只改十二处包注释」那条省事相反）。按 ADR 原文「拼了也没出口」的判据，这算认下的取舍；但与 S3 叠起来就不再是「没出口」。
- **伤**：腐蚀架构。

### S13【判断题】闸门握有 `archive`（权限表允许），「闸门不读文件」没有结构支撑

- **位置与证据**：规则表给站的依赖是 `contractAndCrosscut`（`guard/rules.go:33-36`），`archive` 在其中；闸门实际只用 `archive.ToolLogPath`（`gate/run.go:106`）。

  实测：`go build ./...` OK；`TestProjectIsClean` → PASS。
- **代价**：`gate/run.go:13` 的包注释写着「它不读文件、不读配置」——这句靠人守。闸门可以在判之前建目录、发路径、读工具日志，权限表一条都挡不住（这一格是「站可以依赖全部横切包」的自然结果，不是谁写错了）。
- **伤**：只是架构取舍。

### S14【判断题】执行站能拿 `console.Writer()` 直接写任意字节——这是「话只从 message 出」最大的一个口子

- **位置与证据**：`console.Writer()` 直接返回 `os.Stdout`（`console/writer.go:20-22`）；类一只限制「谁拿」（`writerHome = "execute"`，`guard/check_terminal.go:13`），不限制写什么。
  ```go

  func probeBytes(s string) { _, _ = console.Writer().Write([]byte(s)) }
  ```
  实测：PASS。
- **代价**：这是 2026-11-02 为进度界面开的、点名授权的一格（`guard/check_terminal.go:8-15` 引用原话）。代价是执行站这一段屏幕**完全不受字源约束**：进度条、刷屏、任何文本都能自造，而它正好是屏上字最多的一段。
- **伤**：只是架构取舍（授权明确，代价没写在权限表里）。

### S15【判断题】「按老版特判」没有任何判据，五站里造一处全绿

- **位置与证据**：
  ```go
  // internal/parse/zzprobe_oldname.go
  func probeOldName(argv []string) bool {
      return len(argv) > 0 && strings.HasSuffix(argv[0], "SSHFleet")
  }
  ```
  实测：PASS。`if mode == contract.ModePasswd` 这类站内按模式分叉同理——A13 明示「站内按模式分文件」，所以分支本身合法，判不出来也不该判；真正的风险是**按老版程序名／老版路径／老版阈值**那种只有老版才需要的特判，它长得和合法分支一样。
- **代价**：`ADR-0032` 的代价一节自己写着「站内仍可能长抽屉……结构上挡不住，只能靠规格审计与人读」。这一条属于那一段，属明示空白；我把它记成判断题而不是硬伤，是因为现有代码里没有实例（见 §五）。
- **伤**：只是架构取舍。
