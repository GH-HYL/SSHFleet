# 00 材料·核心三：审的是代码，不是文档

**结论：方向大体一致，但有 9 处会把执行者推回文档对账。** 其中 4 处是硬推（说明:34、PHASE-2:94、说明:18、PHASE-1:19），3 处是半推（说明:42、旧名残留、PHASE-4:19），2 处是口子没留全（层 3 ADR 与代码不符、验收说法与代码不符）。

**怎么读的**：只读。四份指定材料 + 技能五份全文；为核对行号跑了 `grep`／`ls`。未审新工程代码，未改任何既有文件。行号以本次读取为准（材料仍在改，引用时以原文句子为准）。

**与另三份回执的分工**：`三源对差` 判三份来源打架、`执行者试读` 判可执行性、`预设污染` 判断言真伪。本份只判一件事：**按这份材料跑完，交上来的是代码的结论还是文档的结论**。与它们重合的点会注明，不重复计数。

## 一、产出是「代码的结论」还是「文档的结论」

逐条看产出要求：

| 产出 | 判据落在哪 | 判定 |
| --- | --- | --- |
| 轮一：锚补到 A10+ | 抄 ADR 的「决定」，是**造尺子** | 文档，但必要 |
| 轮一：旧名残留清单 | `grep` 全仓非代码位置（`docs/`、`*.md`） | **纯文档发现**（见 D4） |
| 轮一：交接清单六节 | 事实与账 | 过程件 |
| 各轴回执 | 位置与证据（命令或原文）、硬伤/判断题、末尾分母 | 代码取证 |
| 报告第一段 | 一句：达成到什么程度、能不能切 | 代码结论 |
| 报告第二段 | 四问各一节，每条 `file:line` + 「怎么查的」+ 三格分类；抗腐蚀要有数字 | **代码结论**，全材料最硬的一条 |
| 报告第三段 | 锚质疑（文档↔文档）、两轴打架（代码）、`/my-grill` | 混合，锚质疑在前 |
| 报告末尾·参照物缺陷 | 0013–0031 的 ADR 句子 | 纯文档，但单列 |

**判定**：**最终交付的判据落在代码上**——`file:line`、「怎么查的」、数字三件硬要求都在，第二段的结构直接压住了「交文档结论」这条路。真正的问题不在产出格式，在**过程件**：轮一三件产出里两件是文档活，整轮不产生任何代码证据；另有一个旧名残留清单被制度化成每轴固定件（D4）。

## 二、把执行者推去做文档对账的指令

### D1【硬推·最重】说明:34 —— 亲手指令「另起一节『顺带』，按严重度排」

> 原文：「**不要**：逐条挑文档错（发现的另起一节「顺带」，按严重度排序，只提报不改）；重跑 A/B……」

**与 spec:186 逐字撞车**：

> `spec.md:186`：「2. **逐条挑文档错**——另起「顺带」一节，按严重度排，只提报不改。」

同一句「另起一节『顺带』，按严重度排」，在说明里是**要做的动作**，在 spec 里是**要停下的审歪**。而 `spec.md:179` 又写「**三段以说明为准**」——执行者写报告时会回到说明，读到的是「要做」。

**推到哪里**：报告里长出第四个文档错节，按严重度排序，与四问的账并列。
**会导致什么**：这一节天生比代码账好写（文档错好找、可排序、不用取证），一定更长；报告主体从「架构与腐蚀的账」变成「文档错清单」。这正是核心三说的「文档当判据」。

### D2【硬推】PHASE-2:94（配 2.5:82）—— 复核员的靶子写的是「代码与文档」

> `PHASE-2-DISPATCH.md:94`：「| 靶子 | **审计设计**（提示词包） | **审计内容（代码与文档）** |」
> `PHASE-2-DISPATCH.md:82`：「1. 读锚（ADR 决定）、读改动面、**读议题文档**；」

**推到哪里**：复核员自建框架时把 ADR／议题文档当被审内容，产出一轮文档一致性结论。
**会导致什么**：**这不是执行偏差，是结构必然后果**。2.5 要求它「只补几轴覆盖不到的部分」，而 01–11 各轴已经把代码面分完了，**剩下的残余集正好是文档**。按材料派下去，复核员几乎必然做一轮文档互校——而且它被授权「自己设计框架」，最容易把「ADR 与规格/工单/交接说法对不对得上」设计成框架。这与 `SKILL.md:14`「文档不是审计目标」正面冲突。

### D3【半推】说明:42 —— 03 轴的取证写成「两份文档对一遍」

> 原文：「**等价边界**：`docs/issues/2026-11-06-1510-建站09-逐字比对/audit.md`、`spec.md` 第二节的归一化清单，与 `build/建站09_AB_2026-11-06_1535/cmp.py` 对一遍。」

**推到哪里**：把「audit.md 与 spec 归一化清单」当成互相校验的两份文本，回答「报告与计划一致吗」。
**会导致什么**：03 轴要答的是「口径有没有被放宽」——这只有 `cmp.py`（实际比法）与 37 场实际输入能证。两份文档互校只能得出「字面一致」，**字面一致恰恰是放宽后的状态**（归一化多一条、场景少一场，报告与规格可以一起错）。`spec.md:115` 与 `交接清单.md:18` 补了 `cmp.py`，但**没有否掉「两份文档对一遍」这个动作**，执行者会两件都做，然后把文档差异当结论。

### D4【半推】旧名残留清单 —— `PHASE-1:30`、`PHASE-2:47`、`spec.md:139`、`spec.md:144`

> `PHASE-1-SURVEY.md:30`：「在全仓**非代码位置**（`config/`、`docs/`、`*.md`、测试断言里的字符串）grep 旧名，列出残留的 `文件:行号`。」
> `PHASE-2-DISPATCH.md:47`：「7. **旧名残留清单**：1.3 扫出来的残留按域切分随提示词下发……本条只作事实，判不判由该轴自己定。」
> `spec.md:139`：轮一要交「旧名残留清单」；`spec.md:144`：进门要核「1.3 的旧名残留扫描做过」。

**推到哪里**：每份回执都会出现「`docs/xxx.md:12` 旧名未改」这类条目；轮一必须交一份文档残留表。
**会导致什么**：把文档卫生**制度化地铺进每一轴**，还给了一个「进门条件」的地位。它机械、不判断对错、`config/` 与测试断言那部分确是代码面，危害小于 D1／D2；但方向是反的——旧名留在 `docs/` 里不影响任何行为，按核心三不该占回执篇幅，更不该当轮一的交付物。

### 未发现问题（本节）

- **ADR↔ADR 对账被明确禁止**：`说明.md:34` 后半「把『ADR 之间措辞不一致』当发现——那是纸面摩擦」、`spec.md:185` 同义。这两处是真拦得住的。
- **规格↔工单对账没有口子**：`spec.md:6` 不读规格与工单，`说明.md:49` 不追对话。这两类没有被推去做。

## 三、「锚从 ADR 抄」与「审代码不审文档」说清了吗

### 说清了的部分（未发现问题）

`spec.md:25` 是全材料最准确的一句，尺子／被测分得干净：

> 「锚仍从 ADR 抄，那是**「要守什么」**；代码是**「守没守住」**。前者是尺子，后者是被量的东西，别把尺子当被测对象，也别拿文档的措辞去判代码的错。」

`spec.md:33` 也守住了：「那四条是说明列的候选，不是结论」——没让「站不住的样子」变成预设答案。

### D5【硬推】说明:18 反着说，且说明没有「尺子／被测」这句

> `说明.md:18`：「这一次锚要分三层，**下层与上层冲突时以下层为准**：」下接 1 母规格 → 2 `ADR-0032` → 3 各阶段 ADR。

**推到哪里**：层 3 是「各阶段 ADR 的决定」，而 `spec.md:53` 明写层 3「**本身是被审对象**」。按「表的下方＝下层」读，被审对象成了最高尺子；按「地基在下」读才对。材料没定（`三源对差` 03 已记这处方向冲突，本节只补它的**出口**）。
**会导致什么**：`spec.md:179` 说「三段以说明为准」，执行者写报告时回到说明，**尺子／被测的区分只剩 spec:25 一句，而说明里没有这句、还给了反向的一句**。具体两种翻车：
1. 代码与施工 ADR 不符 → 判代码错，而不是判「ADR 层 3 过期」。
2. 母规格 A1（老版等价）与施工 ADR 冲突 → 判施工 ADR 赢，**A1 反而成了可疑项**——等价性是这次审计的第一锚。

### D6【硬推】`PHASE-1-SURVEY.md:19` —— 把两种「不符」合成一句

> 原文：「**发现实现与锚不符，报锚，不要报工单。**」

**推到哪里**：任何代码偏差都往「锚质疑」里放。
**会导致什么**：「实现与锚不符」有两种，材料的别处是分开的：
- **锚 vs 上游／规格冲突** → 锚质疑（`spec.md:85`，且只收「施工 ADR 与第 1、2 层冲突」）。
- **实现没守住锚** → 这是**代码发现**（行为变了），该进第二段四问，不是锚质疑。

这句话把后者也送进前者。后果具体：A1 没守住，执行者会写成「A1 这条锚要不要改」交开发者拍板，而真正该报的是「行为变了」；反过来，施工 ADR 过期也会写成锚质疑，因为 ADR 就是锚。**这就是「把尺子当被测对象」的落地形态**，而且写死在每份提示词的固定句里。

## 四、文档与代码不一致时，判谁错、记在哪

### 有口子的两处（未发现问题）

- `spec.md:65`：参照物与实现冲突 → 先判「行为漂了」还是「老版决策本来就错」，落两格之一；并明说「参照物错了不等于新工程错了，反过来也一样」。这是标准答案，直接可用。
- `spec.md:85`：施工 ADR 与层 1／2 冲突 → 锚质疑，只抄证据，改不改由开发者定。

### D7【口子缺一半】层 3 ADR 与代码不符、且不与层 1／2 冲突——没有规则

**推到哪里**：按 `spec.md:25`「ADR 是尺子」默认判代码错；但层 3「本身是被审对象」。
**会导致什么**：如果是 ADR 过期、代码是对的，执行者只有两条路，都错：
1. 写成代码缺陷 → 混进第二段，开发者会去改没错的代码；
2. 塞进末尾「参照物缺陷」→ 越界，那节只收 0013–0031（`spec.md:177`）。

**「记在哪」只有一格，容不下层 3**。这是第四问最实的缺口：不是没想清楚谁对，是**没有第三个落点**。

### D8【口子缺一半】验收／交接／说明说「已做、全绿、这样跑」，代码不是——没有规则

**推到哪里**：`交接清单.md:47` 给了「已审过的（**按证据，不按说法**）」，这句方向对；但它只教「别信」，没教「发现它说错时记哪」。
**会导致什么**：这类不一致要么被当文档错（`spec.md:186` 禁止），要么被当证据缺口（报告没有这一格）。而它直接决定第一段「能不能切」——「09 收口 18 包全绿」若只在文档里成立，这是**结论级**的发现，不是纸面摩擦。归到「顺带」会被严重度排序埋掉，归到参照物缺陷又越界。

**小结**：口子留了一半。`spec.md:65` 那套「先判行为漂还是老版错」的判法是对的，但只对 0013–0031 开了；同样的判法没有推广到层 3 与验收说法，落点也只有一格。

## 五、报告结构：文档发现会不会喧宾夺主

### 分得清的部分（未发现问题）

`spec.md:177` 是整份材料对核心三执行得最好的一条：

> 「**末尾·参照物缺陷**：只看不判……**不写进前面三段**，也不当成新工程的发现——它只等后面更新 ADR 时用。」

文档发现被物理隔离，且明说「不算新工程的发现」。这一段照抄就对。

### D9【混装】说明:34 + `PHASE-4-REPORT.md:19` —— 文档错被拉回主表

> `PHASE-4:19`：「执行者自己能拍的：事实错误、**引用了不存在的东西**、边界被破坏。**逐条编号**、列全……」

**推到哪里**：「引用了不存在的东西」是文档型缺陷（ADR／规格引了不存在的符号、文件、章节），却和「事实错误、边界被破坏」并列进**第二段的编号缺陷表**。
**会导致什么**：文档错与代码缺陷共用一张编号表，读者分不出哪条要改代码、哪条要改 ADR。这与 D1 是一套：说明开一个「顺带」节，PHASE-4 开一个「已定缺陷」表，两处都收文档错，只有 spec:186 说不许。**三处开、一处关**，关不住。
（`三源对差` 10 已记「PHASE-4 第二段与说明第二段内容相反」，本节只补「文档与代码混装」这一面。）

### 喧宾夺主是结构性的，不是文风问题

文档错好找、好写、可排序；代码账要 `file:line` + 怎么查的 + 分母数字。给文档错一个「按严重度排序」的独立节，它一定比四问的账长、比四问的账先写完。`spec.md:186` 自己就是这么判的——它把「另起『顺带』一节，按严重度排」整句定义为审歪，说明作者知道这个形状会赢。

**另一处压力（不算发现）**：锚质疑「排最前」（`spec.md:85`、`:176`）。细看是在**第三段内**排最前，不是全文最前，没有混。但它是全报告唯一的文档↔文档节，且最容易产出（12 篇 ADR 对 17,857 行代码），实际会占掉第三段的大头。这是设计允许的例外，提醒排期时别让它挤掉第二段的取证时间。

## 六、三个角色读的是代码还是文档

| 角色 | 材料让它读什么 | 会不会变文档互校 |
| --- | --- | --- |
| **分发审** | 提示词包 + 三圈清单，**不读代码**（`spec.md:127`、`PHASE-2:49-67`） | **不会**。它读的是审计设计，不碰文档内容。未发现问题 |
| **规范轴**（`/code-review`） | 这批代码；spec 基准被明确关掉（`spec.md:123`、`PHASE-2:17,23` 的固定句） | **不会**。判据是仓库存写法与 smell 基线，被测是代码。方向对。未发现问题 |
| **反证员** | 只对 01 结构边造反例（`spec.md:129`） | **不会**。纯代码。未发现问题 |
| **复核员** | 「读锚、改动面、**议题文档**」（`PHASE-2:82`）；靶子「审计内容（**代码与文档**）」（`PHASE-2:94`） | **会**，见 D2 |

**按材料派下去的实际形状**：分发审判设计、规范轴与反证员审代码、**复核员审剩下的那块**。因为 2.5 把它定义成「只补几轴覆盖不到的部分」，而代码面已被 01–11 分完，**残余集必然偏向文档**——它会自己设计出一套「锚／规格／工单／交接说法是否互相自洽、是否与实现叙述一致」的框架。这不是它跑偏，是材料把它放在了那个位置。
