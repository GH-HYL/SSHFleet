## 一、硬伤

### 08-1【硬伤】包外可以伪造 `gate.Refusal`：`refused()` 那道封口被「内嵌接口」绕过

- **位置**：`internal/gate/refusal.go:19-25`（接口 + 不导出方法 `refused()`）、`:27-34`（唯一实现）、`:39-41`（不导出构造点）。
- **代码自己怎么说**：`refusal.go:9-13`「接口里那一个不导出的方法，别的包实现不了，于是跨包换不出一个非 nil 的 `Refusal`」；`refusal.go:23`「本包之外实现不了这个接口」；`ADR-0034` 2026-11-03 更新记录（`docs/adr/0034-拒绝与起不来分成两种失败.md:138`）同句。
- **反证**（探针在 `build/audit08/probe/`，整模块副本）：
  ```go
  // probeout/fake.go
  type fake struct{ gate.Refusal }
  func (f fake) Say() message.Line { return message.CancelLine() }
  func Make() gate.Refusal { return fake{} }
  ```
  ```text
  $ go build ./probeout/          # exit 0
  $ go run ./cmdprobe
  非 nil: true
  要说的话: "\x1b[33m操作已取消\x1b[0m\n"
  ```
- **为什么成立**：Go 里内嵌一个接口类型会把它的**全部**方法（含跨包的不导出方法，按 `gate.refused` 的身份）提升到外层结构体；外层再覆写 `Say()` 就能交回任意 `message.Line`。接口没有字面量语法这一点只挡「`gate.Refusal{}`」，不挡「内嵌 + 覆写」。于是「拒绝权只有闸门一处」在编译期没有兜住：任何包都能造一个非 nil、带话、塔尖会照 `!= nil` 打屏并以 1 退出的「拒绝」。
- **检查面看不见这种写法**：类五只找 `gate.Refusal{…}` 形态的复合字面量（`internal/guard/check_failure.go:64-76` 的 `*ast.CompositeLit` 判据），本探针里没有该字面量。此句只作证据补充，检查器本身归 02，不在此定它的账。
- **档与伤**：硬伤；**腐蚀架构**（边界被破坏）。
- **分母**：闸门对外只导出 `Run` 与 `Refusal` 两个符号；对「包外造拒绝」试了 3 种写法（`Refusal{}` 字面量＝编译失败、本包实现 `refused()`＝编译失败、内嵌接口＝**编译通过**）。

## 三、三问的正面回答（未发现问题的部分也给分母）

### 3.1 闸门是不是只有一处能说「不」
