## 二、反证一：五站之间零反向边——试 5 条路，**成 2 条**

01 的复算是 **import 边计数**（46 条仓内边、站→站 0 条）。我的探针全部不经过 import 语句。基准：副本先 `go build ./...` 过、`TestProjectIsClean` PASS（零违规），实测过。

### P1 点 import（`import . "…"`）——死

- **为什么试**：01-S1 引用的扫描缺陷（`guard/scan.go:204` 跳过 `_`／`.` import）里，`.` 形状它只写了代码事实，**没有实造探针**。
- **做法**：`internal/settle/zzfdot_gate.go` 写 `import . "sshfleet2/internal/gate"`。
- **死因**：编译错误——`internal/settle/settle.go:27:6: Run already declared through dot-import of package gate`。五站每站导出入口函数 `Run`（A14 出口白名单），点 import 任何站必撞名。**A14 的出口白名单反而天然堵死了点 import 这条绕法**。guard 未及审判。
- 定性：反例未成，但结论有价值——「每站一个 `Run`」这条设计在这里起了它自己都不知道的防御作用。

### P2 `go:linkname` 拉符号——**成**

- **做法**：`internal/settle/zzflink_gate.go`——`import _ "unsafe"`（标准库放行）＋ `//go:linkname probeGateRun sshfleet2/internal/gate.Run`，包级 map 装住函数值防裁剪。**不 import gate**。
- **实测**：`go build ./...` 过；`TestProjectIsClean` → **PASS（零违规）**。
- **绑定真实性的判别测试**：把 linkname 目标改成不存在的 `gate.RunNotExist`，链接器报 `relocation target sshfleet2/internal/gate.RunNotExist not defined`——证明正常符号下绑定**真实发生**，不是被静默丢弃。改回正确符号即全绿。
- **后果**：settle 对 gate.Run 存在链接层符号依赖，import 表为空。类二只认 import 语句（`guard/check_deps.go:81` 遍历 `Imports` 表），linkname 指令在注释里、不在任何一类的判据里。这与 01-S1 不同：S1 是扫描缺陷（边进了表但被跳过），P2 是**根本不产生可扫的表项**。

### P3 go.mod replace 别名 module——死

- **为什么试**：`guard/scan.go:248-251` `IsStdlib` 按「首段不带点」判标准库——若把 gate 挂到无点路径 `import "gate"` 上，guard 会当标准库放行。
- **做法 A**：go.mod 加 `require gate` ＋ `replace gate => ./internal/gate`。**死**：Go 1.26 不许把主模块内子目录当替换目标（报 `reading internal/gate/go.mod: no such file`）。
- **做法 B**：把 gate 源码 `cp` 出主模块、挂 `module gate` 再 replace。**死**：Go 的 internal 可见性规则——gate 源码 import `sshfleet2/internal/...`，importer 前缀不是 `sshfleet2/` 就被工具链拒绝（`use of internal package sshfleet2/internal/archive not allowed`）。
- **死因定性**：两步都死在 **Go 工具链**，不是 guard。工具链替守了这道——「首段无点即标准库」的判据洞暂时够不着：要利用它，得先把依赖源码搬出主模块，而搬出就撞 internal 规则。反例未成。

### P4 经交接件偷运回调——死（静态核实）

- **为什么试**：若 contract 的纸上有 `func`／`chan`／接口类型字段，上游站可以往纸里塞闭包，下游站调用即成真实调用边，且完全合法（边藏在数据流里）。
- **核实**：`grep -rn 'func)|func (|chan |interface {' modules/SSHFleet2_Go/internal/contract/*.go` → **零命中**。契约里没有任何可执行类型字段。
- **定性**：反例未成——纸的结构本身就是这道防线。这也说明 01 复算依赖边时可以补一句：站间数据流同样载不动行为。

### P5 汇编 `.s` 引用符号——**成**

- **为什么试**：guard 的扫描面按目录读 `.go` 文件（`guard/scan.go:145-157`），`.s` 文件不在扫描面；汇编器不检查 import 关系，符号按链接器全局名解析。
- **做法**：`internal/settle/zzfasm_gate.s`——`MOVQ $sshfleet2∕internal∕gate·Run(SB), AX`（Go 汇编跨包符号转写：`/`→U+2215、`.`→U+00B7），`zzfasm_stub.go` 声明无体函数、`init()` 保活。
- **实测**：`go build ./...` 过；`TestProjectIsClean` → **PASS（零违规）**；`go tool nm` 见 `sshfleet2/internal/settle.probeGateAddr.abi0`；`go tool objdump -s "sshfleet2/internal/settle\.init"` 见 `CALL sshfleet2/internal/settle.probeGateAddr.abi0(SB)`——链接器为 gate.Run 生成了 `.abi0` 包装（`808940 T sshfleet2/internal/gate.Run.abi0`），settle 的 init 真调用它。
- **后果**：settle 里存在一段每次进程启动都会执行、直接引用 gate 站代码地址的机器码；import 表、语法树、全部九类判据都看不见它。

### 反证一裁决

- **读法甲（01 的字面判断）**：「五站之间生产 import 边 0 条」——**未被推翻**（import 表确实零）。
- **读法乙（这条判断实际守的东西）**：「站间不存在真实依赖，单向有检查器在岗」——**被推翻**。两条路（P2 linkname、P5 汇编）都造出了编译过、guard 零违规、链接产物里绑定真实的 settle→gate 依赖。与 01 的五条绕法探针互补：01 证明的是「有边但检查器看不见」，我证明的是「**有不产生 import 表项的边**，检查面连可跳过的表都没有」。
- **一句要紧的**：类二的判据形状是「读 import 语句」，凡不经 import 语句的依赖（linkname、汇编、以及 1.8 表外任何符号级机制）在九类里没有落点——这不是扫描缺陷，是**判据覆盖面的缺口**。

## 三、反证二：旧名 15 个都不构成「用老实现」——试 3 条路，**名单内未成、名单外实锤**

### B1 验 `Results`（15 个名单内的 #9）——死

- **做法**：对照老工程源码（对照物允许）：老 `modules/SSHFleet_Go/internal/output/xlsx.go:271` `const sheet = "Results"`，新 `modules/SSHFleet2_Go/internal/report/xlsx.go:225` 同字面量。
- **裁决**：01 的「照老版保留、属 A1 等价要求」与代码事实相符。反例未成。

### B2 `PasswdStep` 同形重抄深查——死

- **为什么试**：01 §七自认 `contract.PasswdStep` 与老 `config.PasswdStep`「字段名、类型、顺序完全一样」。若老版的方法也跟着抄过来了，就是「用老实现」。
- **核实**：老版有方法 `validate()`（`config/passwd.go:86`：keywords 非空、value 枚举、max 正整数三段校验）；新版 `contract.PasswdStep` **零方法**（`grep 'func (.*PasswdStep)'` 零命中，契约本来就不许有）；对应校验逻辑在新版 `parse/tables.go` 里重写——句子走 `message`、报文措辞不同、结构不同（如 `maxMustBePositive`／`passwdIssue`）。
- **裁决**：字段布局同形、行为零复用。反例未成。

### B3 同名排除的盲区（30 个交集抽查）——**成（在名单外）**

- **做法**：自己求交集——老工程 181 个导出符号 ∩ 新工程 301 个 = **30 个同名符号**，这正是旧名扫描按「同名排除」从 190 名单里剔除的全部。逐个判「同名同物？」抽查 4 个：
  - **`FormatSpeed`——逐字节同体**。老 `internal/output/terminal.go:58-67` 与新 `internal/message/stats.go:362-371`：三支 `switch`、三个 `fmt.Sprintf` 格式串、阈值 `1024*1024`／`1024`，**函数体逐字节相同**，同签名同导出名。新工程调用点 `execute/transfer_view.go:237,253`。**这就是老实现的整体搬移**。
  - **`SanitizeRemark`——unix 版逐字同体**。老 `cli/remark_unix.go:28-35` 与新 `archive/remark_unix.go:19-26` 的 `strings.Map` 函数体逐字相同；`remarkInvalidChars` 常量值两边同（unix `"/"`、windows `"<>:\"/\\|?*"`）；windows 版同构加保留名判定。**同为直接搬移**。
  - `DisplayWidth` 系——**部分照搬**：`unicode.In(r, unicode.Mn, unicode.Me, unicode.Cf)` 零宽判据与 `isBreakAfter` 断点字符表逐字同；EAW 宽度判定换实现（新自建区间表＋二分，老用 `golang.org/x/text/width` 库）。算「重新实现但判据字面量照搬」。
  - `Judge`——同名不同物（新版只在 `guard/testdata` 违规样本里，非生产代码）。死。
- **裁决**：**反例成了——但不在 15 个分母内**。分两个读法说清：
  - **读法甲（严格按分母）**：「15 个命中名单内的名字都不构成用老实现」——**反例未成**（B1 验证成立、B2/B3 在名单内查不到反例）。这条判断按它的字面范围站得住。
  - **读法乙（作为证据面）**：这条判断的构造方法（同名排除）有盲区，且盲区**真的有货**：30 个被排除的同名交集里，`FormatSpeed` 与 `SanitizeRemark` 是老实现的逐字搬移。01 §七那句「独立 module、0 条跨模块 import，**结构上不可能直接复用**」被实锤推翻——**不能 import 不等于不能复制**。凡是把这条判断读成「新工程没有一处照搬老实现」的地方（如交接清单 §一「代码侧 15 个里没有一处是新代码还在用老实现」的外推读法），都不再成立。

## 五、未覆盖面

1. **只对 01 的两条判断**。六组兄弟与七个交接件（闸门棒除外）未造——理由见 §一，属挑题裁量，不是查过没查着。
2. **30 个同名交集只抽查 4 个**：`FormatSpeed`／`SanitizeRemark`／`DisplayWidth` 系／`Judge`。其余 26 个（`ActionName`／`Category`／`Rule`／`MatchOptions`／`KeySource`／`Load`／`Init` 等）没有逐个做同物比对——其中可能还有搬移实例，本回执不排除也不担保。
3. **P3 只试了两种 replace 形态**（主模块内子目录、模块外副本）。`go.work` 工作区模式、vendor 目录注入这两条变体没试——预计同样撞 internal 可见性，但未实测，不下结论。
4. **探针都停在「编译过＋guard 零违规＋符号绑定实证」**，没有真跑探针路径（P2 的 linkname 声明与 gate.Run 真实签名不匹配，真调会崩；P5 只取地址未按 ABI 传参调用）。运行时行为面不在本轮。
5. **汇编探针只在 linux/amd64 验证**。Windows 侧（cross-compile 或 `.syso`）未验。
6. **linkname 判别测试顺带暴露的一个形状未深挖**：`gate.Run.abi0` 包装是链接器为汇编／linkname 引用自动生成的——依赖这个生成机制的其他绕法（如 `.syso` 目标文件、cgo）没试。
7. 判断乙的 B3 若要收全，需要把剩下 26 个交集符号按「同物」标准过一遍——那是统计活，超出「只造反例」的规矩，本轴止步于实锤两个实例。

## 顺带

- **D-F2**：30 个同名交集是旧名扫描（190 名单）的构造性盲区。若后续轴要收全「搬移实例」，从这个交集入手比再扫一遍旧名便宜。
