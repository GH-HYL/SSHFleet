## 三、发现（硬伤 5 条、判断题 7 条）

### H1【硬伤】类四只认 `FuncDecl`：契约里放函数值不报

- **位置与证据**：`guard/check_contract.go:17-20` 只对 `*ast.FuncDecl` 判；包级变量／常量是 `GenDecl`，直接跳过。
  ```go
  // internal/contract/audit_bad.go（副本）
  var AuditLeak = func() {}
  ```
  实测：`go build ./...` OK；`go test ./internal/guard/ -run TestProjectIsClean` → `--- PASS`（零违规）。对照组 `func AuditLeak() {}` → 类四一条（见 D2）。
- **为什么算硬伤**：`check_contract.go:7` 的话术是「契约包里出现函数就报」，`ADR-0032` 第二条是「契约零函数」。函数值变量就是函数，判据只看声明形态。契约里现在没有这种写法（现役 `contract/` 0 个 `FuncDecl`、0 个函数值变量），所以这是**判据的缺口**，不是现役违规。
- **伤**：腐蚀架构（A5 的机械防线比锚窄）。

### H2【硬伤】类五只认复合字面量：`new(T)` 与零值变量造「起不来」不报

- **位置与证据**：`guard/check_failure.go:64-67` 只把 `*ast.CompositeLit` 当构造点；`isTypeOf`（:97-109）只认 `T{}` 的两种写法。
  ```go
  // internal/gate/audit_shapes.go（副本）
  var _ = new(contract.CannotStart)

  func auditZero() *contract.CannotStart {
      var c contract.CannotStart
      c.Body = "前提缺了"
      return &c
  }
  ```
  实测：`--- PASS`（零违规）。对照 `contract.CannotStart{Body: "x"}` 在闸门里 → 类五一条（九项样本第五项）。
- **为什么算硬伤**：`ADR-0034` 决定三要防的是「闸门里造起不来」，而 `parse.Run` 的返回类型就是 `*contract.CannotStart`（`parse/run.go:22`），`new(contract.CannotStart)` 与「零值变量 + 填字段」产出的正是同一个值。判据只看「有没有写 `T{}`」。
- **伤**：腐蚀架构（A11 的机械防线比锚窄）。

### H3【硬伤】闸门的唯一入口可以整个删掉，没有人报

- **位置与证据**：真工程只有一处调用 `CheckAll`——`guard/project_test.go:29`。`CheckRedline`（会报「名单里的测试已经没有了」，`redline.go:160-168`）自己也只在 `CheckAll` 里跑。把 `internal/guard/project_test.go` 移走后：
  ```
  $ go test ./internal/guard/
  --- FAIL: TestRedlineTipCannotStart …（位置绑定，见 J6）
  --- FAIL: TestRedlineTipRefused …
  --- FAIL: TestRedlineTipRunsHelp …
  ```
  **没有任何一条「名单里的 TestProjectIsClean 已经没有了」**，也没有「真工程应当零违规」。整张名单的第一行被删掉，静默。
  在真目录里那三条本来会绿（见 J6），所以真目录上这一跑会是**全绿**——这一句是推断：副本里同时验证「位置绑定必红」与「全绿」做不到。
- **为什么算硬伤**：`ADR-0037` 决定五把「删掉一条红线测试」列为需走议题加 ADR 的动作，`CheckRedline` 的报错话术写的也是「删一条红线测试就算改红线」。但这道判据的触发器就是被删的那条测试本身——自反失效。按「拆闸门最省事的那一步」看，它恰好不红。
- **伤**：腐蚀架构（A2 的自反性）。

### H4【硬伤】红线指纹钉不住断言强度：抽掉断言、符号面一字不动，全绿

- **位置与证据**：`guard/redline.go:176-207` 的 `fingerprint` 只收集函数体里出现过的名字（同名标识符 + `pkg.Sym`），不看断言结构。把 `redline_exitcode_test.go` 的循环体改成
  ```go
  for _, c := range cases {
      _ = exitcode.Code(c.kind)
      _ = c.want
  }
  ```
  （`exitcode.Code`、`exitcode.Kind`、四个种类常量都还在，指纹不变）后：
  ```
  --- PASS: TestProjectIsClean   （红线 40 条）
  --- PASS: TestRedlineExitCodeTable
  --- PASS: TestCheckRedline
  ```
- **为什么算硬伤**：`ADR-0037` 决定五要求「删掉、改名、缩窄引用面算改」，目的是让「把闸门拆了」这件事留下痕迹。**掏空断言**既没删、没改名，也没缩窄引用面，效果与删掉这条红线相同（这条测试从此永远绿），而名单、指纹、`go test` 三处都看不出来。这是本轴找到的、绕开红线程序最短的一条路。
- **伤**：腐蚀架构（A14 决定五的程序被绕开，且不留痕）。

### H5【硬伤】台账放行不校验「为什么放／谁批的」：空签名行照样生效

- **位置与证据**：`guard/ledger.go:54-59` 把四列读进 `Exception`，不校验任何一格非空；`Apply`（`ledger.go:106-127`）只按「类名 + 路径前缀」命中。在副本 `exceptions.md` 末尾加一行四格空两格：
  ```
  | 类一 写终端 | internal/report |  |  |
  ```
  同时在 `report` 放一句 `fmt.Println("x")`，实测：
  ```
  project_test.go:30: 包清单 18 个；当前放行 1 条；红线 40 条；交接件对账 0 对
  --- PASS: TestProjectIsClean
  ```
  删掉台账那一行、保留同一句 `fmt.Println` → 类一红。所以放行确实生效，生效时不问「谁说放、为什么放」。
- **为什么算硬伤**：`exceptions.md:3-12` 写的是「这是让检查闭嘴的地方，动它等同改约束类文件」「一行一条，四样都要写」。判据只用了四样里的两样（规则、位置），另外两样是纯装饰；而 `ADR-0037` 决定五的全部重量都压在「改它要单独点头」这件事上——四格能不能写空，决定了这道门有没有留痕。
- **伤**：腐蚀架构（台账的权力没有对应的判据）。

### J1【判断题】红线区混着值断言与措辞断言，与 A14 决定二「一条行为断言都不放」不符

- **位置与证据**：`ADR-0037:30` 明写「红线区只放结构，一条行为断言都不放……断言只碰纸的形状与流向，不碰值算得对不对」。实际有 **7 个文件 8 处**在判值／版式：
  | 位置 | 判的是 |
  | --- | --- |
  | `redline_exitcode_test.go:16-19,22` | 四个写死的码（0／1／1／130），注释自己写「与老版逐项一致」 |
  | `redline_settle_test.go:30-31` | `Total/Done/NotRun == 2/2/0` |
  | `redline_settle_test.go:36` | `SuccessCounts + FailCounts == Done`（算得对不对） |
  | `redline_message_test.go:22` | 第二行必须以字面量 `版本: vTEST` 开头——同一文件第 11 行却写「一个字的措辞都不判」 |
  | `redline_tip_test.go:61` | 第二行必须以 `版本: v` 开头 |
  | `redline_result_line_test.go:41` | 分隔线恰好 50 个 `=`、恰好一条 |
  | `redline_execute_test.go:37` | `ErrorText` 必须以 `sshfleet.connect.` 开头 |
  | `redline_tip_endings_test.go:26,43` | 退出码必须恰好 1 |
- **为什么是判断题**：这一条锚的强度是「执行者提议、作者采纳」（`ADR-0037:13`），不是作者明示；而且方向是**更严**（红线比锚更死），不是放水。代价明确：`ADR-0037:30` 的理由是「混进行为，改一个小需求就得改红线」，上面这 8 处里至少 4 处（措辞前缀、分隔线条数、退出码表、错误串前缀）一改版式或一调话术就红，正好触发它自己说的那种「被需求拖着改」。另外 `redline_message_test.go` 的注释与断言自相矛盾，是事实层面的不一致。
- **伤**：腐蚀架构（红线区纯度；不是行为变了）。

### J2【判断题】指纹按「同名标识符」收符号：3 条 entry 里有伪符号，且有测试为躲它放弃了自然断言

- **位置与证据**：`redline.go:182-200` 的 `ast.Inspect` 把函数体里**所有** `*ast.Ident` 与 `pkg.Sel` 都数一遍；`productionNames`（:209-237）给出 guard 包全部顶层名字（含 `Kind`）。于是：
  - `redline.go:65` `TestRedlineGateRefusesBadCombination` 的 `Kind` 来自 `contract.Problem{Kind: …}` 这个**字段名**；
  - `redline.go:68` `TestRedlineExitCodeTable` 的 `Kind` 来自 `exitcode.Kind` 这个**类型名**；
  - `redline.go:79` `TestRedlineMessageRendersHelp` 的 `Kind` 来自 `message.HelpEntry{Kind: …}` 这个**字段名**。
  三处都与 guard 自己的 `type Kind string` 无关。这个机制 ADR 自己记过一次：`docs/adr/0043:20` 写「旧断言用 `reflect.Kind()`……那个方法不再被引用，指纹因此变了这一格」——`reflect.Type.Kind()` 也被当成 guard 的 `Kind` 记进过名单。同一条代价在代码里留了注：`redline_archive_test.go:16-18` 说「这里刻意不取 `paths.Report`……指纹按名字数符号，取它会把一个不相干的名字带进指纹（实测过）」。
- **为什么是判断题**：指纹钉「名字集合」是 `ADR-0037` 决定五的原文，误抓同名不同物是这套做法的固有代价；代价是名单里 3/40 条含不实符号，且写测试的人会为了躲误抓而少判一件事（`archive` 那条少判了 `report.txt` 那个落点，注释说交给自定义区）。
- **伤**：只是架构取舍（机制代价），但名单数据有 3 条不实。

### J3【判断题】出口白名单只数名字，不查「那一个类型是不是替身插口」

- **位置与证据**：`check_testsite.go:71-85` 只判 `len(funcs) > 1`、`len(types) > 1`；`exportedNames`（:91-114）只收导出函数与导出类型，不看类型的形状。`ADR-0037:37,43` 的原文是「一个函数加一个类型——入口函数，和替身插口的类型（它是入口的参数，**字段只许是函数**）」。
  现役唯一一个「站的那一个类型」是 `execute.MatchOptions`（`internal/execute/interactive.go:37-40`）：两格 `bool`，不是 `execute.Run` 的参数（`execute/run.go:33` 的签名里没有它），只在站内 `newKeywordRule`／`newPasswdMatcher` 之间传。
- **为什么是判断题**：「替身插口」可以读成「入口参数的配置类型」，也可以读成「函数字段的假件接口」；ADR 括号里那句「字段只许是函数」只有一种读法。判据只数个数，所以两种读法都不会红。若按字面读，这是一个现役的「站多露了一个公开类型」。
- **伤**：腐蚀架构（出口白名单的形状那一半没有判据；01-S9 报的是变量／常量不数，本条是类型形状不查，两处不同）。

### J4【判断题】红线 import 白名单只数个数，不校验被钉的包是不是「三种口子」之一

- **位置与证据**：`check_testsite.go:36-46` 把「内部包、非契约、非 message」统统收进 `pinned`，只判 `len(pinned) <= 1`。`ADR-0037:32` 的三种口子是「塔尖的进程出入口／一个站的入口／一个横切包的那一件事」。现役 15 个红线文件都只钉 1 个（见 §六），但一个红线测试 import `keytool`（密钥管理包，不属于三种口子）也只会算 1 个、不报。
- **为什么是判断题**：现役没有 `keytool` 的红线测试，所以没有实例；但白名单的语义比 ADR 宽一格。
- **伤**：只是架构取舍（覆盖空格）。

### J5【判断题】三类判据的数据面由调用方传，零值＝静默少判

- **位置与证据**：`scan.go:20-35` 的注释自己写「除 Dir 与 ModulePath 外，其余字段都可以是零值——零值就是那一类还没东西可判」；`check.go:20-26` 的导出入口 `Check` 直接把这些零值传下去。`Failures` 空 → 类五判 0 处；`Pairs` 空 → 类六之二判 0 对；`Redline` 空 → 名单判据整条不跑（`redline.go:122-125` 建的空 `listed`，循环不产生任何违规）。
  现役唯一调用方 `project_test.go:12-20` 三项都传了，所以真工程不受影响。
- **为什么是判断题**：这是库接口的取舍（检查器不替调用方选判据），但后果是「少传一个字段，那一类就静默通过」，与 `check_failure.go:48` 那句「删掉它等于让这条检查闭嘴」的立意相反。
