# 回执 00：材料预设污染核查

**结论**：**有 10 处污染（P1–P10）**；另有 11 处数字／出处与事实不符（E1–E11）、7 条被写成前提但没验的条目（U1–U7）。原样下发，一个没有上下文的子 agent 会把其中至少 6 条推断当事实继承。

**核查方式**：只读。跑了 `git log`、`find`/`wc`、`grep`、`ls`；未改任何既有文件，未审新工程代码（只为核对断言数了行数、目录数、条目数）。复核命令附在每行「我复核」里。

## 二、写成了前提、其实没验的条目

### U1（最重）`交接清单:38` 的整块标题：「已核的事实，不要重验」

下面五条里，只有第一条（老工程零改动）附了命令；其余四条**都没有命令、没有落盘**：

- `guard/` 29 次、台账 0、红线 40 —— **可数但没给数法**，子 agent 无法判断你数的是「碰过 guard 文件的提交」还是「改过检查逻辑的提交」。
- 「09 收口时 `go test -race ./...` 18 包全绿」——**本文没有命令、没有沙盒路径、没有输出**。`map.md:68` 是同一件事的二手自述，不是证据。这条一旦是假绿（例如某包被 skip、或只在 root 下跑），遵从度与抗腐蚀两轴的「基线绿」全塌。
- 09 的 37/35/`b12`/`d8` —— 有出处，但**本条没指路**，要到 `:46` 才给 `audit.md`。

**怎么核出来的**：只有第一条能看出核法。其余四条是「我读过、我记得」。材料没有留下「在哪台机、哪条命令、哪份输出」。**这就是把结论写成前提**。

### U2 `交接清单:46`：「阶段 07（一轮质量审计）」

- **怎么核出来的**：核不出来。`docs/issues/2026-11-06-0914-建站07-备份原料与两张表格/` 下只有 `spec.md` 与 6 张工单，全文 `grep 质量审计` 为 0，`spec.md` 连 `## Comments` 节都没有。
- 说明 `:51` 还补了一刀：「命中条数与处置在各自 Comments」——对 07 而言这句是空的。
- **后果**：子 agent 会跳过 07。而 07 正是「遮只有一种形态」「`mask` 唯一构造点」这两条类七判据落地的阶段，也是说明 `:41` 自己点名要数「07 的遮」的阶段。**一边说 07 审过了别再看，一边又要拿 07 当腐蚀样本。**

### U3 `交接清单:43`：「18 包全绿」

见 U1。补一句：这条在材料里是「已核」，在仓库里只能找到 `map.md` 的一句自述；`-race` 是否覆盖了 `guard/testdata/` 那些假模块、是否 18 个包全 ok，材料没写。

### U4 `交接清单:53`：「09 议题 `交接.md`」

- **怎么核出来的**：`find docs/issues -name 交接.md` 全库只有一份，在 `2026-11-01-2001-新工程建站/`。09 议题（`2026-11-06-1510-建站09-逐字比对/`）只有 `audit.md`、`spec.md`、`issues/`。
- **后果**：真机轴按这句去读，会扑空或读错文件；说明 `:43` 指的才是对的那份，两份材料**对同一份文件给了两个不同位置**。

### U5 `spec:12`：「每阶段一道质量审计」

- **怎么核出来的**：全库 `grep 质量审计`，命中只落在 01（事后补）、03（审计+复核）、04（14 条）。02、05、06、08、09 **一条都没有**。
- **后果**：这句话是「现有证据为什么不够」的前提——「逐阶段都审过，但拼不成整体」。前提本身不实：多数阶段**根本没跑过**质量审计。子 agent 会高估既有证据的底子，把「整件事站不住」归因到「拼装方式」，而不是「有些阶段压根没审」。

### U6 `spec:95`：「三样已经答过，不要再问」

- **怎么核出来的**：核不出来，答复没有落盘。三样里最危险的是第三样「有没有没落文档的口头约定（无，决策以 ADR 为准）」——这正是「口头约定」本身，用一句「无」把它关掉了。
- **后果**：子 agent 遇到「ADR 没写但行为是这样」时，只能判成「漂了」，不能判成「口头约定」。而 U1 的 `b12`/`d8` 恰恰是「开发者 2026-11-09 那句『差异要评估过、确因更优』」这种口头口径在兜底（见 `交接.md` 第 35 条）。

### U7 `交接清单:63-68`：「已核实测（每条子 agent 指令原样复述，不许重摸）」

- **怎么核出来的**：仓库里没有凭据。`Ubuntu-26.04`、`Go 1.26.10`、`127.0.0.1:2201`、两个账号、`MSYS_NO_PATHCONV=1`、`reg.exe` 被拦——全部只能上机验。
- **后果**：这不算错，但它是**不可复核的强断言**。子 agent 会把环境事实照抄进回执，一旦机器换过（`交接.md:58` 写着「2026-11-05 换机后重写」），它不会怀疑。

## 三、夹带结论的地方（P1–P10）

> 判据取 `PHASE-2-DISPATCH.md` 2.3 第 3 条：「提示词里有没有夹带主 Agent 的判断（『注意 X 可能有问题』已经是替子 agent 下结论）」。

### P1 `spec:12` —— 四种「站不住的样子」

> 原文：「站不住的样子很具体——结构只在文档里成立、**检查器被悄悄放宽**、加一样东西要动五个包、A/B 口径宽到看不出差异。」

- **类型**：预设方向。四个短语是四个结论，其中「检查器被悄悄放宽」直接等于「注意检查器可能被放宽」。
- **后果**：子 agent 会带着「去找放宽的证据」进场。`guard/` 29 笔提交里任何一次调整都会被读成「放宽」；反过来，如果真实问题是「检查器一直没覆盖某类」，它不会往那看。
- **加重**：这句话把它写成「很具体」，等于告诉子 agent 这四样是**高概率**，不是四个假设。

### P2 `spec:53` —— A5／A8 的重点与定性

> 原文：「A5、A8 是推导项，却当结构判据用了十个阶段——按技能口径是重点审对象。」

- **类型**：先给结论再让找证据。「却当……用了」是责备句式，已经判了「不该这么用」。
- **后果**：子 agent 会把 A5（契约零函数）、A8（塔尖只搬不做）当**待定罪对象**，而不是「授权强度较低、需要重估」的对象。ADR-0032 的原话只是「复审时请重估」，没有说「用错了」。
- **附带**：「十个阶段」本身不实（见 E6），会连带把时间跨度说大。

### P3 `spec:80` —— 「唯一能一票否决」

> 原文：「它是唯一能一票否决的结论，值得两判。」

- **类型**：预设权重。把 01 结构边抬成唯一 veto 项，其它九轴自动降级。
- **后果**：反证员只会背靠背打 01；如果真正的致命项在 04 腐蚀度（例如「加一个选项要动五个包」已经成立），它按设计不会被两判。

### P4 `说明:11` —— 「绕法就三种」

> 原文：「绕法就三种，挨个查：`_test.go` 的依赖方向豁免、`go:build` 标签、检查器读不到的写法。」

- **类型**：封闭搜索空间。这是一道「答案只有三个」的填空题。
- **后果**：子 agent 会把「三种都查了、都没有」当成「结构成立」。但 `go list` 看不到的绕法不止三种（例如生成代码、`//go:linkname`、把依赖藏在 `internal` 之外的 module、`testdata` 里的假模块被生产代码 import）。材料已经把「查全」定义成「查完这三种」。

### P5 `说明:12` —— 四种「改检查面」的手法

> 原文：「有没有为了过关改了检查面——**放宽名单、收窄指纹、把断言挪去别处、把红线测试挪出自定义区**。」

- **类型**：预设手法 + 预设动机（「为了过关」）。
- **后果**：四种手法成了 checklist；不在四种里的改动（例如把一条判据拆成两条、让它对某类输入不再命中）不会被当成「改检查面」。而 29 笔 guard 提交里，这类「拆判据」的改动是存在的（类六拆成两个名字就是一例）。

### P6 `交接清单:38` —— 「已核的事实，不要重验」

- **类型**：用一句话取消复核权。这是 2.3 最典型的污染形态：不是「注意 X 有问题」，而是「X 没问题，别查」。
- **后果**：见 U1。且它与 `spec:160`「把没验证写成没问题」是同一条禁令的两面——材料自己在第 8 条禁令上犯规。

### P7 `交接清单:46` —— 「已审过，不再审」

- **类型**：用未验证的结论关闭审查（07 无据，见 U2）。
- **后果**：07 的类七判据、遮算法、清单副本全部落在「不审」区；而说明 `:41` 又把「07 的遮」列为腐蚀取样点。**两个指令互相打架，子 agent 只能二选一。**

### P8 `交接清单:48` —— 「已否的方向：43 篇 ADR 全是重构产出——否」

- **类型**：把**待开发者点头**的事写成**已否**。
- **后果**：`spec:180` 明写「**待开发者点头的一件**……没点头之前，锚质疑按说明原口径报，其余照本规格取证」。交接清单却说「已否」。子 agent 读到「已否」就不会再报这条锚质疑，等于替开发者拍了板。

### P9 `交接清单:53` —— 「三十七条原样可用」

- **类型**：预设「可用」，免去判断；外加路径错（E7）。

## 五、判定：原样下发，会不会继承推断

**会，至少 6 条。**

1. **166 笔提交** → 子 agent 会把它当新工程的改动量，写进抗腐蚀那一节的「分母」。真实分母是 63，差 2.6 倍；「一处改动牵动五个包」的密度会被系统性低估。
2. **ADR-0032 末尾七条** → 子 agent 只补/只审 7 条更新记录，漏掉 6 条。其中「类七」「`interrupt` 独立成包」「凭据包权限表改写」「`message` 对凭据包开口」四条都直接改结构判据；漏掉它们，锚的三层优先级就是残的。
3. **阶段 07 已审过** → 子 agent 跳过 07，同时又被要求拿 07 当腐蚀样本；结果只能凭印象写，且不会标「未验证」。
4. **43 篇 ADR「已否」** → 子 agent 不再报这条锚质疑，尽管 spec 自己说「待开发者点头」。这是**替开发者拍板**。
5. **`guard` 六类 / 七类** → 两句话都在包里，子 agent 读哪份信哪份；若信「六类」，类七（遮的构造点）整条判据在它眼里不存在。
6. **「每阶段一道质量审计」** → 子 agent 会假设 02/05/06/08/09 都有审计兜底，从而把「整件事站不住」的原因归到「拼装」，而不是「有些阶段没审」。这正好绕开 spec 自己列的第 6 条歪法（「把逐阶段结论拼成整体结论」）——它是被材料**喂**进去的。

另外还有一个**结构性**问题，会放大以上全部：

> `spec:6` 说「唯一入口……三份，其余不读」，但 `spec:16` 说「照说明第一节」、`spec:147` 说「三段以说明为准」。**说明不在三份里。** 子 agent 要么违规去读说明（于是继承 E3「六类」、E4「一个多月」、M1「43 篇」），要么不读（于是不知道「交什么」的三段格式）。两条路都错。
