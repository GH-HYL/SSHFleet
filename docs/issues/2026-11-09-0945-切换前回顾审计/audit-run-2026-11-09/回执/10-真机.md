- 目标机：WSL2 `Ubuntu-26.04` 本机 sshd `127.0.0.1:2201`，账号 `sshfleet` / `Sshfleet#2026`。sshd 开跑前 `systemctl is-active ssh` → **active**。
- **自然列宽实测**：`script -qec "stty size" /dev/null`（stdin 接 /dev/null、无控制终端）→ **`0 0`（0 行 0 列）**，机器：WSL Ubuntu-26.04（root），宿 Windows 11 控制台 80×30。nat 格即在此 0×0 伪终端下跑；80/120 格用 `stty cols W rows 40` 设宽。
- **宽度控制定性**：`COLUMNS=120` 环境变量**不生效**（`out/help-nat-tty/new.clean` 与 `out/help-120-envcols/new.clean` 逐字节相同）；`stty cols` **生效**（80/120/nat 三种 tty 折行互不相同）。两版同此。
- 比对法：照 03 的思路——剥 ANSI/OSC、去 `\r`、耗时数字归一（`<T>`/`<ELAPSED>`），归一化文本逐行 diff（`clean.py` + `diff_report.txt`，均在沙盒）。原始屏文按格存 `out/<格>/<side>.<form>.screen`。

- **波及格**：`upload-nat`／`upload-80`／`upload-120`／`download-nat`／`download-80`／`download-120` 全部六格，三头比对同一形态。

- **关键行摘录**（`out/upload-nat/`，归一化后；download 六格同型）：
  - 新版真终端 `new.tty.clean` 的「节点进度」行**只有一帧**：
    `    节点进度  ───────────────────────────   0.0%  <ELAPSED>  0/1  成功 0  失败 0`
    节点行停在中间帧，之后面板直接以「总进度 100%」收：
    `    ━━━━━━━━━──────────────────  33.3%  0B/s  127.0.0.1  共 3 个文件  成功 0  失败 0`
    `    总进度  ━━━━━━━━━━━━━━━━━━━━━━━━━━━ 100.0%  已完成 1/1  <ELAPSED>  成功 1  失败 0`

    `    节点进度  ───────────────────────────   0.0%  <ELAPSED>  0/1  成功 0  失败 0`
    `    节点进度  ━━━━━━━━━━━━━━━━━━━━━━━━━━━ 100.0%  <ELAPSED>  1/1  成功 1  失败 0`

  - 收尾屏（`═══` 块）三头逐字节一致，本条不涉及。
