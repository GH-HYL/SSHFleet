# 回执 00 · 材料方向：核心一（AI 走最短路径）

**结论**：方向一致——核心一在 `spec.md` 是主轴（Q3 明标「重点」、站内并入第三问），但有 **6 处会带偏**（另有 2 处轻度），其中第 1、2 条足以让「腐蚀审计」交出好看但不对的结论。

**尺子**：核心一判的是「省事那条路**还通不通**」，不是「已经有人走了没有」，更不是「好不好看」。逐条按这把尺子量。

本回执只读材料；除本文件外未改动任何文件。为核对「大站有没有人查」，另跑了只读的 `wc -l`（结果在第 4 条，与材料给的数一致）。

## 一、逐条

### 1【高】Q1 的判据被落地成「import 边不越界」，核心一自己的四种走法有三种没有对抗测试

- **位置**：`spec.md:39`、`spec.md:113`、`spec.md:129`
- **原文**：
  - `spec.md:39`「判据是拿真实改动走一遍：边界挡不挡得住、绕不绕得开。」
  - `spec.md:113`（轴 01）「实际依赖边 vs 权限表；三种绕法（`_test.go` 豁免、`go:build`、检查器读不到的写法）」
  - `spec.md:129`「反证员……只对 01 结构边做背靠背两判……造一个绕过它、它没拦住，这一条就倒了」
- **为什么带偏**：核心一列的省事走法是四种——就地取数、自己拼一份、绕开已经抽好的那层、复制一段改改。这四种里，前两种和第四种**都不必违反 import 方向**：`execute` 合法地 import `credential`，然后自己再拼一遍提示语，依赖边完全正确。轴 01 只查边，对这三种走法天然免疫。Q1 那句「走一遍」在材料里唯一可执行的落点，就是轴 01 的三种 import 绕法。
- **带成**：报告写「架构成立、边界无越界」，实际只证明了 import 没越界；站内已经各自拼了三份，结论仍然是绿的。这正是核心一描述的「每处都对、合起来烂」的形状，而材料把它记成「结构成立」。
- **加重因素**：全材料唯一「造一条省事路、看它拦不拦」的取证设计，就是反证员那一处，且只给 01。`spec.md:39` 同一句里列出的另外五条（塔尖唯一编排、契约零函数、横切三条边、话只从 `message` 出、闸门只许造拒绝），没有任何一条安排过「造一次试试」，只有 07／08／09 的抽样观察——抽样只能看「有没有人走过」，看不出「路还通不通」。
- 与 `00-材料-预设污染.md` 的 P4（`说明:11`「绕法就三种」）同源；这里不重复论证那句话凭什么成立，只补它的后果：三种绕法覆盖的是 import 面，不是腐蚀面。

### 2【高】「遵从度」一个词给了两个东西，轴 11 的风格发现无处安放，最省事的落点是填进 Q2

- **位置**：`spec.md:40`、`spec.md:123`、`说明:12`
- **原文**：
  - `spec.md:40`「**遵从度**——`guard` 七类（九项检查）与红线 40 条是不是真判据；检查本体被改过的地方一条一条看。」
  - `spec.md:123`「| 11 | 规范面 | 按 `个人开发规范` 与仓库既有写法判这批代码的**遵从度**。**派 `/code-review`**，只用它的两轴切分与 smell 基线……」
- **为什么带偏**：同一个词，在 Q2 指「检查器是不是真的」，在轴 11 指「代码合不合个人开发规范」（命名、注释、格式、长度）。报告第二段只有四节（Q1–Q4），轴 11 的产出没有归属；执行者只能按词找位置，最省事的落点就是 Q2。
- **带成**：Q2 那一节变成「命名不一致 7 处、注释格式 3 处、函数过长 2 处」，而「`guard` 的指纹有没有被收窄、红线断言有没有被挪出自定义区、放行名单有没有加宽」被挤成一两句。核心二里「检查器被放宽」是最重的腐蚀入口——省事路之所以能走，常常是先有人把闸门放松——这里恰好被风格条目挤掉。
- **附（为什么没人拦）**：`PHASE-2:60` 的分发审第 1 条只查「几轴的文件域并起来，覆盖**三圈**了吗」，查的是文件域覆盖，不查「这一轴的判据是不是在测省事路」。这个错位过不了任何一道关。

### 3【中】「长抽屉」被点名为腐蚀主要形态，却没有可操作判据，最自然的量化就是行数

- **位置**：`spec.md:44`、`spec.md:117-119`
- **原文**：
  - `spec.md:44`「**站内质量并入第三问**，不另立第五问：`execute`／`parse`／`message` 占生产代码六成，站内长抽屉就是腐蚀的主要形态。」
  - `spec.md:117-119` 轴 05／06／07 的判据分别是「另造一套、回读源头、站里拼话、特判」／「同上」／「同上，另加「字是不是真只在这一处成形」」
- **为什么带偏**：「长抽屉」字面指向长度，三个轴没有定义它的单位。执行者最省事的落法就是数函数行数、嵌套层数、文件行数——正是任务里说的「看着相关其实无关」。
- **带成**：「`execute` 有 3 个 200 行以上函数」「`parse` 单文件 579 行」这类风格条目进报告；真正要问的「这句提示语为什么不是 `message` 出的」没人问。

### 4【中】抗腐蚀是「重点」，取证面却是全表最薄的一档

- **位置**：`spec.md:44`、`spec.md:117-119`、`spec.md:120`、`PHASE-2:44`
- **材料原文**：轴 05／06／07 各一行，判据合计 12 个字；`PHASE-2:44` 要求「末尾给分母：本轴核了 N 处（依赖边／配置条目／用例／断言）」。
- **复算（`wc -l`，只读）**：execute 4,087／parse 3,594／message 3,027，三站合计 10,708 行，占生产 17,857 的 60%，与材料一致。**三站各有一轴，不是没人查**——问题 4 前半问，答：不成立。
- **但取证面对不上「重点」**：
  - 01 有「三种绕法 + 反证员背靠背两判」，02 有「29 笔提交 + 40 条指纹 + 放行台账」，03 有「归一化/场景表/比法/覆盖空格」；
  - 三个四千行的大站，合计：一条判据、12 个字、一个 agent、无抽样方案、无分母单位。`PHASE-2:44` 给的分母单位是「依赖边／配置条目／用例／断言」，对「站内重复／回读源头／站里拼话」都不适用——这一类轴交上来的分母无法互比，也无法判断它是不是只抽了一段。
  - 15 个小包共 7,149 行（去掉 guard 2,160 后约 4,989），只有轴 08 一轴，判据只点名「闸门 / 契约 / 横切」三样；`credential` 872 行、`report` 469、`archive` 414 没有被任何判据点名，算不算「横切」要靠执行者自己猜。
- **带成**：大站抽查两三处即交；小包按三问扫完就算完。「重点」那一节反而最像走过场，而报告第二段的数字要求（`spec.md:175`）又逼着它必须交出数字——见第 7 条。

### 5【中·判断】跨包提交计数可以反着读，材料没给「该动」与「漏了」的区分

- **位置**：`spec.md:116`、`说明:13`
- **原文**：`spec.md:116`「四把尺子；重复密度；按老版特判；**跨包提交（分母 63，不是 166）**」；`说明:13`「最近一个月「一处改动牵动五个包」的提交有几笔？」
- **为什么带偏**：一个改动动五个包，可能是「必须穿过五站」（结构在起作用，正确），也可能是「层漏了、每站各补一处」（腐蚀）。材料只给计数，不给判读规则。
- **带成**：数字天然被读成「越低越好」；于是把改动压在单包内的一个特判，会被记成好。这与核心一正好相反——特判本身就是省事那条路。轴 04 另外单独数「按老版特判几处」只能部分抵消：两个数字并列而没有关系说明，读者会挑好看的那个。

### 6【中】「先复现、指得出一条跑过的命令」会把静态腐蚀挡在门外

- **位置**：`说明:50`（与 `spec.md:175` 冲突；`spec.md:179` 又说「三段以说明为准」）
- **原文**：`说明:50`「**发现缺陷先复现**：指得出一条跑过的命令才算数。」；`spec.md:175` 只要求「每条带 `file:line` 与「怎么查的」」。
- **为什么带偏**：腐蚀的典型证据是静态事实——「这里又拼了一份本该由 `message` 出的句子」——它没有命令可跑；能跑出命令证明的，多半已经是行为差异（核心二）。要求命令，等于要求把结构问题翻译成行为问题才准报。
- **带成**：抗腐蚀那节只收到「能复现」的少量条目，其余被丢；或者条目被改写成「疑似行为不一致」，跑去和 09 的等价性证据打架。`spec.md:179` 说「三段以说明为准」，这句冲突因此不会被自动消解。

### 7【低·判断】要求「有数字」，而可数的全是计数型判据，会诱导用计数代替判断

- **位置**：`spec.md:175`「抗腐蚀那节要有数字」
- **为什么带偏**：审计者本人也会走省事路。全部可数项就是重复密度、特判处数、跨包提交数，报这三个不用回答「路还通不通」。
- **带成**：「重复 3 处、特判 2 处、跨包 11 笔」——形式满足，结论悬空。材料的重点轴，恰好是审计者自己最省事的那条路。

### 8【低】说明的取样计划没被 spec 收口

- **位置**：`说明:41`、`spec.md:105`
- **原文**：`说明:41`「**腐蚀**：挑十处最近的改动（09 的收账、07 的遮、08 的密钥、09 的清单副本与引号），逐处数「改对一件事要动几处」。」；`spec.md:105` 只记「写「挑十处最近的改动」后只列五项」，未给替代。
- **后果**：轴 04 到底取五处还是十处、取哪几处，没有定；分母不可比，第 4 条的分母问题再叠一层。

## 二、五个问题逐个答

| # | 问 | 答 |
| - | -- | -- |
| 1 | 能不能真审出「挑省事那条路」 | **部分能**。真在查的：04（四把尺子，最贴核心一）、05/06/07（现存实例）、01（依赖边）、02（闸门有没有被放松）。看着像在查的：11（规范面，量风格）、`spec:44` 的「长抽屉」（量长度）、09 的「164 行」（量行数）。四种走法里只有「绕开抽好的那层」能被判据直接测到；就地取数／自己拼一份／复制改改只能靠撞见，撞不见就报「未发现」。 |
| 2 | 有没有把腐蚀偷换成别的东西 | **有 3 处**：轴 11 的规范符合度（命名/注释/格式）、`spec:44` 长抽屉→行数、`spec:116` 跨包提交→耦合计数。前两处是偷换，第三处是可反读。 |
| 3 | 哪个环节会把「通不通」判成「好不好看」 | 轴 11→Q2 的落点错位（第 2 条，最直接）；「长抽屉」无判据（第 3 条）；09 用 164 行描述塔尖（低，事实基线，尚无大碍）。 |
| 4 | 取证面够不够、有没有大站没人查 | 三站**都有人查**，「没人查」不成立。但一轴一站、判据「同上」、无抽样方案、无适用分母；15 个小包里 `credential`／`report`／`archive` 未被任何判据点名（第 4 条）。 |
| 5 | 有没有反过来鼓励腐蚀 | **没有直接条文**：`spec:19` 明禁「为逐字一致往新工程里塞绕路判断」，`spec:18` 的例外口是「可不严格对齐」，压力方向正确。**间接两处**：跨包计数可反读（第 5 条）、数字要求诱导计数（第 7 条）。 |
