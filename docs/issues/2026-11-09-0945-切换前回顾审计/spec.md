## 三个核心（忘了就会曲解整场审计）

**一、重构要解决的：AI 走最短路径，把架构磨掉。**

AI 干活挑省事那条——就地取数、自己拼一份、绕开已经抽好的那层、复制一段改改。单看每处都对，合起来架构就烂了。重构是让这些走法**在结构上不成立**，架构因此活得久。判据不是好不好看，是省事那条路还通不通。

**二、实施要守的：AB 对齐是根基，行为不能动，架构可动。**

- 根基是 AB 对齐：具体行为不能动。
- 能动的只有架构：拆包、换交接件、移函数都允许。
- 例外一种：新架构与老版代码冲突、必须取舍时，**评估后**可不严格对齐，写清理由。
- 实施过程自身也不许腐蚀架构——不许为逐字一致往新工程里塞绕路判断。

**三、审的是代码，不是文档。**

判据落在**源代码与最终交付的代码**上。文档有局限：写得再细也描述不全实现；实施也会被注意力分散，文档与代码早晚有出入。文档只当线索——去哪看、当初为什么这么定——不当判据。

锚仍从 ADR 抄，那是**「要守什么」**；代码是**「守没守住」**。前者是尺子，后者是被量的东西，别把尺子当被测对象，也别拿文档的措辞去判代码的错。

**用法，四条**：

- 每条发现先判它伤哪一条——腐蚀架构 / 行为变了 / 只是架构取舍。三格分开写，不混。
- **例外要凭据**：行为上的不一致，只有「有评估、有理由、有点儿头」三样齐了才算取舍；缺一样就按「行为变了」报，不当取舍放过。
- **37 场是分段证据**：只证明它口径内没变，不证明 A1 全局成立。不许写成「行为等价已验证」。
- **文档错只进末尾「顺带」**，不占三格，也不当四问的结论。

## 这件事要回答什么

三句：重构目标达成到什么程度、现在能不能切、卡在哪一条。

现有证据是**逐阶段**审出来的（每阶段一道质量审计、09 三十七场对照），它们回答「这一段没做错」，回答不了「整件事站不站得住」。说明列了四种站不住的样子——结构只在文档里成立、检查器被放宽、加一样东西牵动五个包、对照口径宽到看不出差异。**那四条是说明列的候选，不是结论**；每一条都要拿证据判，判不成立就写不成立。

## 方向：四个问题

四个问题是三个核心的落地，不是另立一套。照说明第一节，不改：

1. **架构成立吗**——五站单向、塔尖唯一编排、契约零函数、横切三条边、话只从 `message` 出、闸门只许造拒绝。判据是拿真实改动走一遍：边界挡不挡得住、绕不绕得开。**绕法不止 import 方向**：同一站内合法 import、却自己拼一份话、回读上游的字段、按老版特判，都是省事路，依赖边全对也照样是腐蚀。每站至少要造一条「本包内合法但省事」的写法，看它拦不拦。
2. **检查器可信度**（说明里叫「遵从度」）——`guard` 七类（九项检查）与红线 40 条是不是真判据；检查本体被改过的地方一条一条看。**「遵从度」本议题只指这一件事**；代码合不合 `个人开发规范` 是轴 11，两者不是一回事，不许混着写。
3. **抗腐蚀性（重点）**——加一个选项、一条报文、一种模式、一个字段，各要动几个包几处；重复密度；按老版特判几处。三个最大的包的四件事固定为：另造一套、回读源头、站里拼话、按老版特判，**每个都要给分母**（读了几处、其中几处可疑）。跨包提交只作线索：判它是「必须穿过五站」还是「层漏了各补一处」，**数字本身不判好坏**。
4. **等价性的边界**——两个面：口径有没有被放宽（归一化、场景、比法）、适用范围到哪里（哪格没场景）。另加一条：09 的四条已知差异**逐条判授权**——有评估、有理由、有开发者点头的算取舍；只有「各自认下」的按行为变了报。

**包内质量并入第三问**，不另立第五问：`execute`／`parse`／`message` 是最大的三个包（占生产代码六成），包内长抽屉就是腐蚀的主要形态。**注意 `message` 不是站**，它是拼句那一个横切包——它块头大，说明「字只在一处成形」这条本身有分量，不等于它变成了第六站。

## 基准

**优先级，上压下的三条**：

| 层 | 是什么 |
| --- | --- |
| 1 | 母规格 `spec.md` 的 Destination 与判据（A1 等价、A2 可持续、A3 切换一行） |
| 2 | `ADR-0032` 五条决定 + 末尾 **13** 条更新记录 |
| 3 | `ADR-0032`–`0043` 的施工决定——**本身是被审对象** |

**读法：上压下，不是「越靠下越硬」。** 说明那句「下层与上层冲突时以下层为准」是按表格方位写的，容易读反——以本条为准。

**参照物，不在锚序里、不参与定锚、也不是绝对正确**：`ADR-0013`–`0031` 十九篇是重构**之前**的行为决策，只用来说明「老版本来怎么跑」。开发者 2026-11-09 定：这批不审，但有参考意义；它们体量大、生成时点早，**注定不是条条正确**——有明显错误的照收，留着后面更新。

**三类发现分开放，别混**：

| 发现 | 落哪 | 为什么 |
| --- | --- | --- |
| 施工 ADR 与母规格／`ADR-0032` 冲突 | 「锚质疑」，报告最前 | 改不改锚由开发者定 |
| 参照物（0013–0031）明显错 | 报告末尾「参照物缺陷」一节 | 不属本次审计范围，只收集，后面更新 ADR |
| 代码与施工 ADR 不符、又不与层 1／2 冲突 | 先按层 1／2 判代码；ADR 没跟上记「顺带」 | 施工 ADR 是被审对象，不是尺子 |

**技能 1.2 那句「发现实现与锚不符，报锚，不要报工单」要拆开用**：实现没守住锚＝**代码发现**，进三格；锚本身与上游冲突＝**锚质疑**。前者不许写成「这条锚要不要改」。

参照物与实现冲突时，先判是行为漂了、还是老版决策本来就错——判完落进上面三格之一。「参照物错了」不等于「新工程错了」；反过来也一样。

## 交什么

- **第一段·结论**：一句——达成到什么程度、能不能切；不能就写卡在哪一条。
- **第二段·架构与腐蚀的账**：四个问题各一节，每条带 `file:line` 与「怎么查的」，并标它伤的是哪一条——腐蚀架构 / 行为变了 / 架构取舍；抗腐蚀那节要有数字。
- **第三段·要开发者定的事**：锚质疑排最前；两轴打架的原话并排；`/my-grill` 问过的清单记进报告。
- **附一·规范面**：轴 11 的产出单独一节。**不许并进四问的第二问**——那是检查器可信度，不是代码风格。
- **附二·顺带**：文档错、ADR 措辞不一致、引用了不存在的东西。按严重度排，只提报不改，**不占四问的位置**。
- **末尾·参照物缺陷**：只看不判。哪条 ADR（0013–0031）、哪一句、错在哪、依据是什么。**不写进前面三段**，也不当成新工程的发现——它只等后面更新 ADR 时用。

**证据门槛分两类**，别拿一把尺子量：

- **行为类**（跑起来不一样）：要一条跑过的命令与它的输出——说明那句「指得出一条跑过的命令才算数」只管这一类。
- **腐蚀类**（站内自己拼了一份本该 `message` 出的句子）：没有命令可跑。给 `file:line`、同一形态出现了几处、可复算的计数即可。**不许因为「跑不出一条命令」就不报**——那会让抗腐蚀那节整个空掉。

**三段以说明为准**，不用技能 4 的默认三段。只把技能第一段要的东西补成开头一小节：**这一轮怎么跑的**（派了哪几路、分发审报了哪些缺口、补没补），凭据是 `提示词.md` 两版对照。

## 审歪的样子

**任何会话撞上任一条，停下报主 agent，不要自己找补。**

1. **审成文档对账**——拿「ADR 之间对不对得上」当发现。纸面摩擦不是重构质量问题。
2. **把文档错当主结论**——文档错只能进末尾「顺带」，不占四问。它一旦出现在第二段，这一轮就歪了。
3. **重跑 A/B**——除非怀疑证据本身。
4. **拿规格与工单当基准**——它们是被审对象。基准只有上面三层。
5. **拿通用最佳实践当判据**——判据只取仓库自身。
6. **把逐阶段结论拼成整体结论**——「每阶段都审过」不等于「整件事站得住」，而后者恰恰要验。
7. **动被审对象**——改代码、改检查面、改红线、补测试。
8. **把没验证写成没问题**——推断就地标成推断；换台机器可能变的，写明在哪台测的。
9. **一轴一轮**——把多轮变成每轮重来：重读全量规格、重写锚、结论只在对话里不落盘。
10. **把待定写成已定**——开发者没点头的，一律写「待定」，不替他拍。
11. **把 37 场当 A1 已成立**——它只证明口径内没变，不证明行为等价整体成立。
12. **审计者自己走省事路**——抗腐蚀那节只数几个容易数的数（行数、跨包数、特判数）就交；要判「省事的路还通不通」，得造一条去撞。

## 不做

- 不改被审对象；修复另开授权。
- 不重开旧决策（要推翻走议题加 ADR）。
- 不追对话（决策以 ADR 为准）。
- 不审老工程（冻结、零改动，只当对照物）。
- 不评「代码好不好看」。
