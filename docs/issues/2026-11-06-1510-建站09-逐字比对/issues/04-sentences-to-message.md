## Comments

**2026-11-06：四笔落了，第一笔卡住。**

- `[警告]` 改走 `tagLabel(ansiYellow, "警告")`，与另外两处警告（链接、表格）同一个成形处。
- 两处来源那三行拆成 `envSourceLine`／`persistSourceLine`／`otherSourceLine` 三个小函数：状态屏一次要三行，预检查的「没读到」与「未持久化」两档各只要其中一行——原先这两档各拼一遍，现在都从这里取，输出一字未变。

- 两份 `SystemReason` 各加一句「另一处也有一份、改一处要一起改」，不合并。

**第一笔为什么没做**：那三句是随错误值走的（`cannotStart(err.Error())`），要让 `message` 成形，得先让 `message` 知道「加密在哪一步塌的」——而它不许 import 凭据包，凭据包也不许 import 它。**唯一的路是给凭据包加一个区分类型**（哪种失败），再由密钥包认它、向 `message` 要句子。代价是凭据包多导出一个类型，而换掉的三句走的是 AES／GCM／随机数构造失败——标准库这三处不会失败，屏幕上永远看不到。

**这一笔要不要做，等开发者定**：做，就是为一个不可达的路径加一个导出类型；不做，就在 `cipherErr` 那儿写清楚「句子随错误值走，暂时住这里」。两种都不是「为一致绕路」，是一个真实取舍。
