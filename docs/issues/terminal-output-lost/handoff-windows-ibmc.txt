一、背景：一句话
========================================================================

  你的那批 iBMC 任务，终端上每台只显示「连接 / 执行 / 分类」三行，
  命令输出是一片空白；可是同一次运行的 terminal-output.txt、xlsx
  里，输出来得好好的。

  我的判断：输出「到了」终端，但里面夹了回车符（CR，一个看不见的
  字符），终端把它当成「回到行首」的指令，把字覆盖掉了。

  已经在本机用可控字节复现：一条带 CR 的输出，在终端上确实会整行
  消失、只剩分隔线；不带 CR 的，正常显示。

  现在缺的只有一件事：确认 iBMC 那两条命令回的字节里，到底有没有
  CR。实验 A 就是为这一件事准备的，一条命令、几秒钟。


========================================================================
二、准备条件
========================================================================

  需要：
    · 任意一台能 SSH 到 iBMC 的机器（Windows / Linux 都行）
    · 一个能跑 ipmcget 的 iBMC 账号
    · 全程只连一台 iBMC 就够，不需要 13 台

  不需要：
    · 不需要改 iBMC 的任何配置
    · 不需要碰生产节点
    · 不需要安装任何东西（下面给的都是系统自带的命令）

  只用读操作，唯一的写是实验 C 里工具自己生成的历史目录。

三、实验 A：看远端到底回了什么字节（必做）
------------------------------------------------------------------------

  目标：把那条出问题的命令的输出，按「原始字节」显示出来，
        看清楚行尾是 \n、\r\n 还是孤立的 \r。

  ------ A-1  Linux / macOS / 有 ssh 的 Windows（Git Bash、WSL） ------

    在命令行里执行（<账号> <地址> 换成你的）：

      ssh <账号>@<地址> "ipmcget -d health" | od -c | tail -30

    od -c 会把每个字节显示成 Symbol：
      \n   换行
      \r   回车      ← 这个就是关键
      \t   制表     （无害）
      其余字面字符原样显示

  ------ A-2  只有 Windows 的 cmd / PowerShell ----------------------

    第一步，把输出存成文件：

      ssh <账号>@<地址> "ipmcget -d health" > out.txt

    第二步，在 PowerShell 里看每个字符的编号：

      $s = [IO.File]::ReadAllText("out.txt")
      $s.ToCharArray() | Select-Object -Last 60 | ForEach-Object {
          "{0}`t{1}" -f [int][char]$_, $_
      }

    对照表：
      10 = \n（换行）
      13 = \r（回车）   ← 这个就是关键
       9 = \t（制表）

    或者更省事：用十六进制查看器打开 out.txt（如 Notepad++ 的
    「视图 → 显示符号 → 显示所有字符」），直接看行尾有没有小箭头。

  ------ A-3  连 out.txt 都不方便（最小方案） ----------------------

    直接数字节：

      ssh <账号>@<地址> "ipmcget -d health" | wc -c

    然后在记事本里打开 out.txt，数一下可见字符（不含换行）有多少。

      · 两数相等              → 没有 \r，这条命令回的是普通 LF
      · 字节数 = 可见字符数 + 行数 × 2
        （每行多出一个字节）  → 每行行尾都是 \r\n，即 CRLF
      · 字节数 = 可见字符数 + 行数 × 1
        （正常）              → 只有 LF

    实测例子（同等内容的两个文件）：

      内容 "System in health state." + 换行
        CRLF 版：25 字节        LF 版：24 字节    ← 正好差 1


========================================================================
四、实验 B：对照组（建议做，一条命令）
------------------------------------------------------------------------

  目标：证明「差别在命令回了什么」，而不是工具或网络。

      ssh <账号>@<地址> "uname -a" | od -c | tail -10

  预期：看不到 13（\r），或者只在行尾成对出现。
  如果对照组也满屏 \r —— 那说明差异不在命令，回来告诉我，方向要改。


========================================================================
五、实验 C：用修好的版本复跑（验证修复，建议做）
------------------------------------------------------------------------

  前提：拿到修好的 SSHFleet（版本号不变，看帮助信息里的构建标识）。

  用你原来那套参数跑一次：

      SSHFleet.exe -f bmc.csv -c "ipmcget -d health" --no-sudo --no-shell --yes

  看终端明细里：

    情况 1  输出正常显示出来了
             → 这条命令这次没回 CR，或者已经归一掉了，问题不复现。

    情况 2  输出正常，且没有冒出 ␍ 之类的记号
             → 同上。

    情况 3  输出里出现了 ␍（或 ␈、␀）这种方框符号
             → 回显里确实有会捣乱的控制字符，工具已经把它标出来了。
               把带这个记号的那行原样发回来，那就是物证。
               （这种情况说明修复按预期工作：不再是空白，而是看得见。）

六、判断标准：看到什么，说明什么
------------------------------------------------------------------------

  实验 A 结果                     结论
  ------------------------------------------------------------------
  行尾是 \r\n                    根因确认：远端回 Windows 风格换行
  行中间夹着孤立 \r              根因确认：回显里有回车刷新
  完全没有 \r                    不是我推断的这个根因 → 方向要改，
                                 请把 od -c 全文发回来重新分析
  有 \r，但修好后仍为空          → 另有原因（例如远端回的是别的
                                 控制序列），同样请发全文

八、风险与边界（给要审批的人看）
========================================================================

  · 全程只读：A、B 两节只是「执行一条查询命令，并把输出存到本地」。
  · 不改任何配置：iBMC 侧、SSHFleet 配置都不动。
  · 唯一的写操作：实验 C 会跑一次工具本身，产物在工具自己的历史
    目录下（history/ 下新建一个时间戳目录），这是它正常运行的结果。
  · 不带密码进日志：od -c 的输出按字节展示，但 ipmcget -d health
    只回「系统健康状态」，不含凭据；如果那条命令的回显里含密码，
    请不要粘回明文，遮掉即可。
  · 不需要连着 13 台：只连 1 台就能得出结论，不占用整批任务时间。
