# 01: 路径空格报错参数化（点名当前选项，去掉假出路）

Status: resolved（2026-10-15 实施——接缝走 `Parse`，先红后绿）
Blocked by: 无

**对应规格**：`../spec.md` 第三节（第 2 类）。

**这是本轮的第一条，也是性价比最高的一条**——它一处文案被 5 个选项复用，改一处消掉五个误报面。

---

## 现状（实测抓取，非代码推断）

`internal/cli/args.go:460` 的 `pathWithoutSpace` 被 `-s`/`-u`/`-d`/`-p` 四选项共用，
文案里**没有选项名**，举例写死 `-u`。实测四个面输出一字不差：

```bash
cd build/atest-4
./SSHFleet -f csv/nodes.csv -s 'my script.sh'
./SSHFleet -f csv/nodes.csv -u 'my file.txt' -p /opt/
./SSHFleet -f csv/nodes.csv -d '/var/my log' -p ./adir/
./SSHFleet -f csv/nodes.csv -u afile.txt -p '/opt/my dir/'
```

四条全部输出：

```
原因：路径参数中间不能包含空格
提示：路径里有空格时用引号包起来，例如 -u "D:/my dir/app"
```

**两个毛病**：

1. 报错主体是「路径参数」，**没点名是哪个选项**；举例固定 `-u`，`-s`/`-d`/`-p` 出问题也照给。
2. 给的是**假出路**——值里的空格加引号也没用（引号在 shell 层已被剥掉）。

---

## 要做的事

### 1. 参数化取值来源

照 `internal/cli/args.go:179` 的 `modeTable` 惯例（「同一件事的多个名字收在一处，用时按 key 取」），
建一张「路径选项 → 它是什么」的小表，报错时按**当前传进来的那个选项**取。

- 由调用方把「当前是哪个选项」传给检查函数
- **MUST NOT** 在报错文案里写死选项名
- 提示里的举例 **MUST** 用当前这个选项，**MUST NOT** 出现别的选项

### 2. 去掉假出路

「加引号」对「值里带空格」是做不到的出路，**MUST NOT** 作为唯一出路给出。
提示要说的是**这个选项本来该收什么**（对齐范本 `check.go:71-74` 的写法）。

### 3. 验收（改前 vs 改后，逐条实测）

| 输入 | 改前 | 改后要求 |
| --- | --- | --- |
| `-s 'cat /etc/os-release'` | 报空格，举例 `-u` | 点名 `-s`；不给「加引号」这条假出路 |
| `-u 'my file.txt'` | 报空格，举例 `-u` | 点名 `-u` |
| `-d '/var/my log'` | 报空格，举例 `-u` | 点名 `-d` |
| `-p '/opt/my dir/'` | 报空格，举例 `-u` | 点名 `-p` |

**证据要求**：交付时贴四条命令的改前/改后实际输出（规范第五节）。
