实测例：

```bash
cd build/atest-4
./SSHFleet -f csv/nodes.csv -s s_bad.sh

```

使用者看到的是文件名，**不知道是哪个参数带进来的**。

## 要做的事

- **MUST** 让每一条都说清「是哪个参数 / 哪个文件」出的事。
- `%s 是二进制文件` 在 `-s`、`-f`、`-a` **三处复用**，只有提示段不同——
  **MUST NOT** 留三份无从分辨的相同首行。
- **一条一条改，不建机制**（规范第二节：不为「以后可能要用」预留抽象）。

---

## 验收

逐条触发，改前/改后对照。触发方式（沙盒 `build/atest-4/` 已备好素材）：

```bash
./SSHFleet -f csv/nodes.csv -s s_bad.sh    # 非 UTF-8
./SSHFleet -f ./SSHFleet -c uptime         # 清单是二进制
./SSHFleet -f csv/nodes.csv -s sdir        # 脚本是目录
```

**判据**：只看这段输出，能说出「是哪个参数出的事」。
