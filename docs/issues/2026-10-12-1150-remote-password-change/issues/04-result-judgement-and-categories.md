# 04: 结果判定与分类

Status: done
Blocked by: 02

**要做的**：让三种机器在统计块里各归各的类，读得懂。

| 会话结束形态 | 判定 |
| --- | --- |
| 从未出现过期信号（未过期机器） | 跳过改密：`error` 写「密码未过期，跳过改密」、退出码置 `nil`，**计入失败数** |
| 出现过期信号 + 退出码 0 | 改密成功：退出码 0 照旧，归「执行成功」 |
| 退出码非 0 | 改密失败：`error` 写会话输出原文，走判据文件第二组 |
| 远端反复重问（无话可给）或 `-t` 到点 | 失败：`error` 写固定文案、退出码 `nil`，归「改密未完成」 |

判据文件三处改动：「密码修改失败」加进 `[[exit_code_categories]]`（第二组，退出码非 0 时匹配）；**同一组关键词也加进第一组 `[[categories]]`**——早收场/超时的退出码是 `nil`，走的是第一组，得让它按远端的原话（「密码未被更改」等）分类；「密码未过期」加进第一组。第一组的「密码修改失败」「改密未完成」都必须**排在「密码过期」之前**——改密的机器本来就带着那句服务端提示，不先拦一道就会被它抢走分类（真机实测，见 spec 的 B5）。

`internal/result/` 的判定逻辑**不动**（改密不新立成功分类，失败走配置分类）。

- [x] 三类各归各的类：未过期 → 「密码未过期」、改成 → 「执行成功」、新密码被拒 → 「密码修改失败」（真机验过，分类抓的是远端那句「密码未被更改」）
- [x] 未过期机器计入失败数、`error` 文案正确（真机验过）
- [x] 统计块里不再出现"未归类"的提示与原文分类名
- [x] 修掉两处：① 服务端提示行的关键词让「密码过期」先命中，超时被误判成「密码过期」；② 早收场那条事件不带文本、收尾却按「文本非空」判中止，失败被报成**成功**（真机验过，见 spec B5/B5′）
- [ ] 退出码非 0 走第二组「密码修改失败」——本机 PAM 不校验强度、也没造出其它非 0 场景，这条仍是纸面
- [x] `go vet ./...` 干净、`go test ./...` 全绿
