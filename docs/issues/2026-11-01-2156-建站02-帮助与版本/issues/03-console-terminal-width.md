# 03: `console` 量终端宽度——两平台各一份，零第三方

**要做的**：终端包能报出「这个终端有多少列」。做完之后，帮助那一屏在宽终端里折行、在管道里不折行，而量宽度的代码只住终端包（类一：只有它碰 `os.Stdout`）。

老工程借的是 `golang.org/x/term`，本工程不许引。要自己写：Windows 取控制台缓冲区信息，Unix 取窗口大小；不是终端、句柄拿不到、调用失败，一律返回 0（0 的含义是「不折行」）。

**Blocked by**：无，可立即开工。

**Status**：ready-for-agent

## 判据

- 两平台各一份实现，用构建约束分开；对外只有一个「报宽度」的函数，不做「是不是终端」这类第二次判断——0 就是「问不到」。
- 失败一律退 0，不报错、不中断：显示得难看总比跑不起来强（老工程同一条口径）。
- 不引入任何第三方包；系统调用走标准库那一层，不自己封 DLL 加载器。
- 只碰输出端，不读输入、不改模式、不动码页——码页适配随阶段 03。

## 验收

- [ ] `go test ./...` 绿；`gofmt -l .` 干净；`go build ./...` 与 `GOOS=windows go build ./...`、`GOOS=linux go build ./...` 都能过
- [ ] `go.mod` 无新增 `require`
- [ ] 管道场景：把标准输出接到管道再问宽度，返回 0（测试里用真管道验，不 mock）
- [ ] 真终端场景：在终端里跑一次、宽度大于 0，把实测的列数贴进 `## Comments`——**跳过不算绿**（这条要人或有终端的机器）
- [ ] Windows 与 Unix 两个文件各有构建约束，交叉编译时不互相打架
