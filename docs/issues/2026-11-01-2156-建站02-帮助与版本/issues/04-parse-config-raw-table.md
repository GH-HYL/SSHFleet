# 04: 解析站把配置读成「节 → 键 → 原文值」，先取帮助要用的四格

**要做的**：解析站读得了 `./config/SSHFleet.conf`，能按节与键取出原文值；帮助要用的四个数（`sudo` 与三个超时）从它来。做完之后，`-h` 里那三行标记值与配置一致，读不到配置则是一句「起不来」而不是半屏帮助。

这一单只到「读成原文表」为止：**类型化与校验不在这单**——必填项、未知字段、路径规则、取值非法，都随阶段 03（那时才第一次有「配置空／格式错／必须项缺」这三类验收）。老工程借的是 BurntSushi 的 TOML 库，本工程不许引，所以这一层自己写。

**Blocked by**：无，可立即开工。

**Status**：ready-for-agent

## 判据

- 只认这份配置真用到的形态：`[节]` 与 `[a.b]` 两种节名（点号原样留在节名里）、`键 = 值`、`#` 注释、空行、双引号字符串、整数、布尔。
- **引号里的 `#` 不是注释**——密码、备注里带 `#` 是常事，截在那儿会读出一个短了的密码。
- 节名与键名两侧空白裁掉；值保留原文，字符串去掉外层引号后原样留着（不转义、不去内部空格）。
- 只取出 `[execution]` 四格：`sudo`、`timeout_connect`、`timeout_execute`、`timeout_transfer`；取不到就是「起不来」。
- 读文件用标准库直接读，**不设注入点**：配置路径是包内一个常量，与老工程同一个相对位置（当前目录下的 `config/SSHFleet.conf`）；报错里展示的形态不带 `./`。
- 读取失败（文件不在、读不动）就是「起不来」，带一句话；不是空表、不是 panic。
