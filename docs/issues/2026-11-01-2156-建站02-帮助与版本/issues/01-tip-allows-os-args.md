# 01: 塔尖能读 argv——把 `os.Args` 补进符号白名单

**要做的**：塔尖拿得到命令行原文而不被结构检查判红。做完之后，`main` 里可以写 `os.Args`，其余三处（`os.Exit`、`signal.Notify`、`errors.As`／`Is`）照旧只许在塔尖。

这一单改的是**让人闭嘴的那张白名单**，属「单独点头」那一档——动手前要先拿到开发者的明确同意，不能靠本阶段的「授权开工」顶过去。

**Blocked by**：无，可立即开工（但要单独点头）。

**Status**：done

## 判据

- 白名单里 `os` 那一行从 `Exit` 变成 `Exit` 与 `Args` 两项；其余不动。
- 判据本身不动：仍然是「塔尖只许用点名的符号」，不是「`os` 随便用」。
- 改这一格要留痕：ADR-0032 末尾追加一条更新记录，写明——原第五条漏了这一格、加它的理由（argv 是塔尖「搬」的那件事的输入，不是判断）、代价（`os` 在塔尖多了第二个可用符号）。判读是「同一个决策补漏」，不是新决策，因此只追加更新记录，不另开 ADR。
- 阶段议题目录里没有第二个「加符号」的工单：本阶段只加这一格。

## 验收

- [x] `go test ./...` 绿；`go vet ./...`、`gofmt -l .` 干净
- [x] 坏样本：塔尖里写 `os.Args` **不**产违规；样本里塔尖写 `os.Getenv` 仍产违规（证明白名单没被放宽成「`os` 全放开」）
- [x] 坏样本：别处（非塔尖）不因这条改动而放行——本判据本来就只裁塔尖，样本里站包用 `os.Args` 不报，这一点在工单 `## Comments` 里写明「不是漏判，是这条判据只管塔尖」
- [x] 21 条红线名单与指纹不变
- [x] ADR-0032 末尾有那条更新记录，日期与理由齐

## 不在这单

起不来与拒绝的类型、解析站与终端包的任何代码。

## 做完之后

结论回填阶段议题 `## Comments`；08 号单接线时直接用。
