# 02: `message` 自带宽度表——按显示宽度量、截、折

**要做的**：拼句包能量出一个字符串在终端占几列、按给定宽度折成几行。做完之后，帮助那一屏的列对齐与折行只依赖这一个实现，新工程仍然一条第三方依赖都没有。

老工程这两件事借的是 `golang.org/x/text/width`，本工程不许引（类二「零第三方依赖」）。表要自己带：**东亚宽与全角算 2 列，组合记号与零宽字符算 0 列，其余 1 列。**

**Blocked by**：无，可立即开工。

**Status**：ready-for-agent

## 判据

- 判据与老实现同一套：东亚宽度属性为 W 或 F 的字符占 2 列；`Mn`／`Me`／`Cf` 与空字符占 0 列；其余 1 列。
- 折行规则照老实现：宽度小于等于 0 表示不折；能在一行内放下就一行；优先在空格与常见全角标点（`、，。；：）」】》)]｜|`）之后断，行内没有断点就按宽度硬断；单个字符比宽度还宽时每行至少推进一个字符；行首行尾的空白裁掉。
- 表用区间写，不逐字符列；只覆盖终端里真会出现的字符类别即可（中文、全角标点与字母数字、日文假名、韩文、常见符号与 emoji、组合记号）。
- 这三件事（量、截、折）都住在拼句包，**且都不导出**——对外只出「一整件事」的构造函数，零件留在包里。老工程把它们当公共小件用（`common.DisplayWidth` 那一族），那正是 ADR-0032 要治的「抽屉」；谁要折行，就调这里的一整件事。

## 验收

- [ ] `go test ./...` 绿；`go vet ./...`、`gofmt -l .` 干净；`go.mod` 里没有新增 `require`
- [ ] 宽度：写死的字面量断言各一条——`"abc"` 3、`"中文"` 4、`"（」"` 4、`"a\uFE0F"` 1（变体选择符算 0）、空串 0
- [ ] 只导出量、截、折之外的东西为零：`go doc` 看导出面，只有构造函数，没有零件
- [ ] 截断：`TrimToWidth` 给定上限时返回能放下的最长前缀，且不切在多字节字符中间
- [ ] 折行：宽度 0 不折；宽度 80 下一条长中文说明在可断处断开；行内没有断点时硬断；行尾空白被裁掉；单字符超宽不死循环
- [ ] 与老实现的同结果证据：把老工程帮助里的二十条说明逐条过一遍，两边折出来的行数与每行内容一致（一次性比对，结果贴 `## Comments`）

## 不在这单

帮助那一屏的排版（07 号单）、数字写成大小、截断之外的美化。

## 做完之后

07 号单直接拿这三个函数排版；`message` 的头注释补一句「表是自带的，判据同老实现」。
