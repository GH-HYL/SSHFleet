# 06: 解析站交出选项表与版本串

**要做的**：解析站能一次交出两样事实——**这张表里有哪些选项、各是什么**，以及**版本行那一串**。做完之后，帮助屏上的每一个选项名、每一句说明、每一条标记，与老版同一个来源；版本串也只有一个来源。

这一单不认命令行、不算取值——只把事实摆出来。将来认取值（阶段 03／04）用的还是这张表，不另立一份。

**Blocked by**：07（选项事实的类型由拼句包定义，解析站照着填）。

**Status**：ready-for-agent

## 判据

- **20 条**：13 条带值、7 条开关。分五组——模式（五选一）、清单与目标路径、执行选项、密钥与凭据、密钥管理。
- 每条装四样：短名、长名、标记（`[默认: …]`／`[当前配置: 开／关]` 这类，无则空）、说明；另带「带不带值」与「属哪一组」「是不是分组前的空行」。
- **文字逐字照老版**：组标题、说明、标记的措辞一个不差；标记的值来自配置那四格（`sudo` 决定「开／关」，三个超时进 `[默认: …]`）。
- **版本串**：`v` + 号 + `+` + 七位短提交号 + ` (` + 提交时间本地化 + `)`；工作区有未提交改动时短提交号后加 `-dirty`；取不到构建信息时按老版退化（只有号，或有号加时间），不造第三种写法。
- 号本身不在这单产生：它由塔尖那行常量递进来，解析站只管拼。
- **构建信息不设注入点**：生产路径由包内一个私有函数取运行期构建信息；拼串那一步另是一个纯函数，收「号 + 构建信息 + 有没有改动」三个值。自定义区测试直接喂假值给纯函数，红线区不碰这一层。

## 验收

- [ ] `go test ./...` 绿；`go vet ./...`、`gofmt -l .` 干净
- [ ] 表里正好 20 条，按组数得出来 5／2／9／1／3；带值的正好 13 条
- [ ] 逐字对照表：新表每一条与老工程 `helpEntries` 的对应条并排贴进 `## Comments`，说明与标记一字不差；不一致的地方当场改
- [ ] 版本串四档各一条断言（写死期望）：有提交号与时间、只有提交号、只有时间、都没有；外加一条「有改动」带 `-dirty`
- [ ] 版本串里不出现塔尖的行号、也不从别处读号——号只从入口参数来

## 不在这单

拼成句子、缩进与折行（07 号单）、认命令行取值（阶段 03／04）。

## 做完之后

07 号单拿这张表排版；08 号单把它接到塔尖上。
