# 05: `config/` 整个目录搬进新工程，并落一条字段名对账

**要做的**：新工程目录下有一份自己的 `config/`，跟着出包走；`go test` 一跑就能证明它跟老工程那份**字段名不差一个**。

出包脚本查三份配置、打包时另拷两份关键词表，所以老工程目录里实际是**六个文件**（图里「五份」是旧话，以目录为准）：`SSHFleet.conf`、`SSHFleet-for-linux.conf`、`SSHFleet-for-windows.conf`、`keywords_dangerous.conf`、`keywords_error.conf`、`keywords_passwd.conf`。

**Blocked by**：无，可立即开工。

**Status**：done

## 判据

- 六份文件**原样复制**：一个字节不改，注释、对齐空格、行尾都照原样；不重排、不删「暂时用不到」的段。
- 不搬老工程的 `config` 包代码（那是 04 号单自己写的那一层）。
- 对账测试比的是**每个文件的「节名 + 键名」集合**，逐条相等；**值不比**——值随环境配，比了就天天红。
- **认键的规则只有一份**：这条测试复用 04 号单那套切分（同包，直接调），不另写一套正则——两套认法迟早不一致，那时对账绿而解析器读不到。
- 对账测试要能找到老工程那份：从测试所在的位置回溯到仓库根，再定位老工程的 `config/`；找不到就**红**（它一定在，找不到说明谁把目录挪了）。
- 这条测试住**解析站的自定义区**——它是唯一懂「配置长什么样」的包；不进红线区（它比的是值以外的键名，属需求侧，不是结构）。
- 两份目录里**文件清单也要相等**：多一份少一份都红。
