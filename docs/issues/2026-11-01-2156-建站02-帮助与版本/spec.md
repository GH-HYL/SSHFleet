# 规格：阶段 02——帮助与版本

**Status**：done

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

使用者敲 `sshfleet -h`，是为了在动手之前确认「这条命令该怎么写」：有哪些选项、超时默认多少、这次是 root 还是登录用户、示例长什么样。这一屏是他与本工具唯一的说明书，也常常是他判断「这版是不是同一个工具」的第一眼。

新工程现在敲下去什么都不出——十七个包只有注释，塔尖是个空函数。也就是说，从阶段 01 交付到本阶段结束之前，新工程连一句能给人看的话都产不出来。

## Solution

把最外圈那条路打通：**塔尖从命令行拿到 argv → 解析站认出「这是要看帮助」并给出事实（选项表、版本串）→ 拼句包把这一屏排出来 → 终端包打到屏幕上 → 塔尖以 0 退出**。

做完之后，新工程运行 `-h`（以及不带任何参数）打出的那一屏，与老工程**逐行相同**；`config/` 目录整个搬进新工程，出包时那几份配置跟着走。这一屏之外，本阶段一律不出手。

## User Stories

1. 作为运维人员，我敲 `sshfleet -h`，看到的那一屏与老版一字不差：首行、版本行、用法两行、五组选项、示例八行、结尾一行。
2. 作为运维人员，我什么参数都不给，也看到同一屏（老版就是这个行为）。
3. 作为运维人员，版本行告诉我「这是哪一次代码」：号、七位短提交号、提交时间；工作区有未提交改动时那一串后面带 `-dirty`。
4. 作为运维人员，我在宽终端里看，说明列不会串到别的列；我把输出重定向到文件时，长行不折，方便我 grep。
5. 作为运维人员，帮助里的 `[当前配置: 开/关]` 与三个超时默认值，跟我 `config/SSHFleet.conf` 里写的一致。
6. 作为运维人员，我把 `config/SSHFleet.conf` 删了再敲 `-h`，拿到的是「配置文件读不到」那句话，退出码非 0——不是一屏半截的帮助。
7. 作为维护者，帮助里的选项名、说明、示例与老版同一个来源：我不必在两处各改一遍。
8. 作为维护者，新工程的 `config/` 与老工程字段名集合相等，`go test` 一跑就知道有没有漏搬一份、改错一个键。
9. 作为维护者，有人把帮助的排版搬到解析站去写、或让别处自己 `fmt.Print`，`go test` 立刻红。
10. 作为维护者，新工程仍然一条第三方依赖都没有——宽度表、终端宽度、读配置都是自己写的。

## Implementation Decisions

### 这一条链的三段分工（ADR-0032 第四条、14 号工单答案）

| 段 | 谁 | 给什么 |
| --- | --- | --- |
| 事实 | 解析站 `parse` | 程序名、版本串、选项表（短名／长名／标记／说明／是否带值）、配置里那四个数 |
| 句子 | `message` | 一整屏文本：缩进、列对齐、标记列、说明列折行、示例块、结尾一句 |
| 打屏 | `console` | 把 `message` 造出的类型写到标准输出 |

**塔尖一个字的句子都不拼**：它把 argv 交给解析站，把拿回来的那句话交给终端，再给退出码。

### 版本

- 号只有一个出处：塔尖那行顶格 `const appVersion`（发布脚本按这一行改号，没有它出包时直接停）。
- 串的拼装归解析站：`v` + 号 + `+` + 七位短提交号（工作区有改动时加 `-dirty`）+ ` (` + 提交时间的本地时间 `2006-01-02 15:04:05` + `)`。
- 取不到构建信息时的退化形态照老版：只有号，或有号加时间，不作第三种写法。
- 归一化口径：比对时把 `v<号>+<短提交号> (<时间>)` 整段当作一格，不逐字比。

### 帮助

- **20 条选项**（13 条带值、7 条开关），分五组、组间空行；文字逐字照老版。选项表是解析站的事实，将来认命令行取值时用的还是这张表——不另立一份。
- **触发**：`-h`、`--help`、一个参数都不给，三种都出同一屏。认法是「按表里『是否带值』跳过值」，所以 `-c "-h"` 不会被当成要看帮助。
- **排版照老版**：组标题缩进 2、选项行缩进 4、短名与长名之间 1 个空格、其余列间 2 个空格；说明列起始列按四列最大宽度算；终端宽度大于 0 时说明列按剩余宽度折行、保底 24 列，宽度为 0（管道／重定向）时整行不折。
- **示例与结尾**：示例八行、标签列右补空格对齐；结尾一句指到 `docs/`。

### 零第三方依赖之下的三处自建

新工程要求包里一条 `require` 都没有（类二那条检查管着），所以老工程借的三样东西都要自己写：

- **显示宽度**：东亚宽／全角算 2 列，组合记号与零宽字符算 0 列，其余 1 列。判据与老实现同一个（东亚宽度属性 W／F），只是表自己带。
- **终端宽度**：Windows 取控制台缓冲区信息，Unix 取窗口大小；不是终端或取不到时返回 0。**只有 `console` 碰终端**（类一），所以量宽度归它。
- **读配置**：只到「节 → 键 → 原文值」这一步，够取 `[execution]` 四格即可。类型化、必填校验、未知字段、路径规则随阶段 03——那时才第一次有「配置空／格式错／必须项缺」。

### 配置目录

- `modules/SSHFleet2_Go/config/` 从老工程**按目录原样搬**：六份 `.conf`（`SSHFleet.conf`、`SSHFleet-for-linux.conf`、`SSHFleet-for-windows.conf`、`keywords_dangerous.conf`、`keywords_error.conf`、`keywords_passwd.conf`），一个字节不改，含注释与对齐空格。
- 图里写的「五份」是旧话（出包查三份、打包另拷两份关键词表），**以目录为准**：六个文件。
- 一条对账测试比两份目录里**每个文件的节名与键名集合**，逐条相等；值不比——值随环境配。

### 站起来之前会撞的两道门

- **塔尖的符号白名单**：ADR-0032 第五条只点名 `os.Exit`、`signal.Notify`、`errors.As`／`Is`，而塔尖要读 `os.Args`。这一格要在本阶段补上，属「会让检查闭嘴」，**单独点头**；补的行与理由记进 ADR-0032 的更新记录（原决策漏了一格，不是新决策）。
- **解析站的出口白名单**：每站只许导出「至多一个函数加一个类型」（ADR-0037 决定三）。所以解析站对外只有**一个入口函数，两个参数：argv 与版本号**；本阶段一个类型都不导出。
  - **不设替身插口**：读配置文件用标准库直接读（配置路径是包内常量，与老工程同一处相对位置），终端宽度问 `console` 要（站依赖横切包是允许的那条边，老代码就是在这个位置量的）。红线区靠「在哪个目录下跑」控制配置读到读不到，不靠注入假件——为测试开一个注入口，等于给生产方式多一条路。

### 本阶段的结局只有两种

解析站递回：**一句要打给使用者的话**（帮助，含版本那一行），或**起不来**。签名是「一句话 + 一个 `*contract.CannotStart`」，为零表示不是起不来。

- 结局的整张表（信封、一条小命令、拒绝）随阶段 03／04；本阶段不预留空壳类型。
- 起不来在本阶段只服务「配置文件读不到」这一种，话术与退出码表随阶段 03 定；**这是过渡形态，不是本阶段的行为口径**（见 Out of Scope）。
- 本阶段没接上的用法（给了别的选项、要进流水线）也走「起不来」，文案明说还没接上——同样随 03 被真正的解析与合规检查取代。**这句话也由 `message` 出**，解析站只交事实（哪一种没接上），不自己拼字。

### 红线要长出来的三条

- **塔尖的进程出入口**：起二进制、喂 `-h`、看退出码与首行下方那一行。
- **解析站的入口**：递 argv 与一个版本号，收一句话与一个「是不是起不来」。配置读得到与读不到两种形状各一次（靠切换工作目录，不靠注入）。
- **`message` 的那一件事**：选项表与版本串进去，一屏文本出来。

三条按 `redline_` 前缀加进名单与指纹。**新增不算改**（规范三.3），删、改名、收窄引用面才算；本阶段只新增，不动已有 21 条。

## Testing Decisions

- **接缝三处**（ADR-0037 决定三，不多不少）：塔尖的进程出入口、解析站的入口、`message` 的那一件事。`console` 与 `parse` 内部一律不测。
- **红线区只判形状**：`-h` 退出码为 0，且**首行下一行**以 `版本: v` 开头（只判这一行在不在、以什么开头，不判号对不对）；解析站收到空参时「不是起不来」、收到读不到配置时「是起不来」；`message` 交回的不是空串。**一句都不判措辞对不对**——措辞一变红线就废，那正是要避免的。
- **自定义区跟着被测包走**：
  - `message`：宽度与折行的判据用**写死的字面量**（中文 2 列、ASCII 1 列、全角标点 2 列、变体选择符 0 列）；帮助整屏在宽度 0 与 80 两档下逐字断言，期望串从老工程跑出来录，不用被测代码自己算。
  - `parse`：选项表逐条对老版文字；版本串用假构建信息跑四档退化；配置原文表用 `testdata/` 下几份小样本（空行、注释、全角空格、缺节）。
  - `config/` 对账：回溯到仓库根找老工程那份，逐文件比键名集合。
- **A/B 比对不进两区**：本阶段结束在 `build/` 下起一个沙盒，把新老两个二进制各跑一遍 `-h` 与空参，`diff` 结果贴进阶段议题的 `## Comments`。这是一次性验收，不是常驻测试。
- **环境类失败不进两区**：本阶段不涉及机器。「终端下宽度大于 0」这一条要在真终端里手工跑一次，结论写进工单 `## Comments`——跳过不算绿。

## Out of Scope

- **全量选项解析**：认值、默认值、互斥检查、内联清单判定，随阶段 03／04。本阶段只认「要不要看帮助」。
- **`起不来` 的完整语义**：`contract.CannotStart` 的字段、构造函数与话术、退出码表，随阶段 03。本阶段只有一句话加退出码 1。
- **本阶段期间，帮助之外的那条路与老版不同**：别的用法会看到「还没接上」，配置读不到时也只有一句话（老版那句带颜色与前缀的完整报错归 03）。这是**阶段切分造成的，不是要落到版本里的行为**——切换前由 03 补齐，09 的逐字比对在那之后做。
- **配置的类型化与校验**：必填项、未知字段、路径规则、`keywords_*.conf` 与 `SSHFleet-for-*.conf` 的读取，随阶段 03／05。
- **写终端的其余三处**：执行站刷屏、`ask` 的问句、报告站的结论，随 03／04。
- **颜色与码页**：帮助这一屏不上色；Windows 码页适配归塔尖的步骤 0，随阶段 03。
- **`-version`**：不做（老工程没有这个选项，14 号工单已定）。
- **语言开关（`[locale]`）**：随阶段 08。
- **老工程**：一个字不动。
- **约束类文件**：不动（塔尖白名单那一处例外，按「单独点头」办）。

## Further Notes

- **过渡形态清单**（03 接手时逐条替掉，别当口径抄）：起不来的话术与退出码、没接上的用法一律走起不来、配置只读到四格。
- **`-h` 的边界**：`-c "-h"` 这种「值恰好是 -h」的形态靠「带值选项跳过下一个 token」处理；值里带空格的引号由 shell 负责，本阶段不碰。
- **示例块里那八条**用的都是本阶段的选项名，没有一条依赖流水线；改文案等于改使用者可见面，须先问。
- **临时产物落 `build/` 下当天沙盒**，Go 的 `GOTMPDIR` 一并指过去。
- **提交**：中文，一行 `类型(作用域): 做了什么`；两个远端都要推。
- **CHANGELOG 本阶段不增条目**：使用者能体验到的一样没变（帮助逐字相同、配置跟着出包），记进去反而让人以为有变化。
