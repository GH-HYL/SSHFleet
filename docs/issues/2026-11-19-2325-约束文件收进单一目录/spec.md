# 约束文件收进 docs/agents：交接文档

- **Status**：ready-for-agent
- **日期**：2026-11-19
- **性质**：一次性交接文档。改约束文件本不该开议题；这份只为把「怎么干」写清楚，干完连目录一起删。它的 `Status` 不做更新，随目录一起消失。

## 先记这一条：原始诉求

**这不是改一批文档，是把整套约束当成一个东西重构：一个入口，一片规则。**

入口只有 `AGENTS.md`，它不承载规则，只负责把人指到该读的那一份；规则各说一件事，平铺在入口指过去的地方。拆的是承载，不是结构——整套约束仍然是一个框架，只是从一份长文摊成了 21 份短文。

拆的过程里最容易被带偏：读到某一条觉得别扭，就地改起来，一份接一份，最后成了 21 份互不相干的稿子——每份都通顺，合起来不是一个框架。注意力被一份份文件分走时，回到这句上：**原始诉求是让入口指得准、规则找得到，不是把每一条都改漂亮。**

- 每份文件可以有自己的写法：必读的四份要能一口气读完，按需的可以带命令与场景。风格自由不等于自成一体——它讲的那件事，是站在整套约束里的某个位置上说话，术语、编号、判据与别处必须是同一套。
- 发现某条规则本身有问题，记下来，不在拆的时候改。这次是搬迁，改了就没有可比对的基准。
- 判据：把这 21 份连 `AGENTS.md` 一起给一个没看过的人，他能不能说出「入口在哪、什么动作读哪几份、规则之间谁管谁」。说不出来就是写歪了，哪怕每份都通顺。

## 允许质疑这份文档

粒度是规划时定的，不是铁律。实施中若发现某几份耦合强到分开写会各说各的，可以提合并。门槛不低：

- **先测量，再开口。** 指出是哪几份、合了受益在哪、代价是什么（要改几处引用、入口表怎么变、以后按主题找会不会更难）。这四样说不清，就是没评估过。
- **由开发者定，不在当场拍板。** 他不同意就按原粒度做完，不许多议。
- **不许把它当快速否决口。** 整份规划不因一句「我觉得太碎了」作废；要否决一条，必须同时给出替代方案，否则照原样执行。

同一门槛也管清单归属的调整：觉得某一节该换一份文件，照上面三样摆出来再说。

## 四步怎么做

### 一、硬拆

按清单把对应节原样搬进新文件：不改字、不调序、不增删；标题除外，标题在这一步先沿用源文，第二步再改成主题名。清单点明要合并的行按清单合；同一段正文分给两个新文件的（如规范·四·3 的创建入口分给 ADR、spec、工单三份），各取与该文件相关的那一句。旧四份不动。

验收两向都做：

```bash
grep -n '^#' docs/个人开发规范.md docs/agents/doc-guide.md docs/测试环境使用指南.md
diff <(grep -oE '(必读|按需)-[^ |]*\.md' docs/issues/2026-11-19-2325-约束文件收进单一目录/spec.md | sort -u) \
     <(ls docs/agents/{必读,按需}-*.md | xargs -n1 basename | sort)
```

第一条出源文件全部标题，逐行勾到新文件的某一节；第二条拿清单表第一列与磁盘上实际建出来的文件对，两边一致才算齐。这一步不判文字是否通顺，也不判行数。

### 二、润色

一份一份过，判据是 `personal/约束文档检查经验/约束文档检查经验.md`：删废话、去沿革、去过程、去位置指路、术语统一。

- 术语沿用源文的叫法，不造新词。确需统一的（源文里「口子」与「接缝」混用之类），把每一对旧新叫法记在一处，全部改完再全量回扫一遍，别改到一半换口径。
- 自称：源文里的「本文件」「本规范」逐处改成「这套约束」，指向具体文件的改成文件名。四份的自称各不相同，指南叫「这一页」、交流方式叫「这套东西」，取值一次列全：

  ```bash
  grep -n '本文件\|本规范\|这一页\|这套东西' docs/个人开发规范.md docs/agents/doc-guide.md docs/测试环境使用指南.md docs/交流方式.md
  ```

- 不再出现「第 X 节」这类位置指路。文件之间互指写文件名；指代码、工具、目录仍写完整路径——约束类文件要指名道姓落在哪，这是零节给的例外。
- 每润完一份，回到「先记这一条」的判据回看：它是站在整套约束的哪个位置上说话，术语与判据有没有跟别处各走一路。

### 三、接入口

- `AGENTS.md` 重写成一页索引：一句说明全貌，必读表（时机 → 文件），按需表（触发场景 → 文件）。`## Agent skills` 段原样保留；文里那两句正文按「未列节的处理」最后一条安置。
- 清全仓指针，位置与条数按下面这张单子走，别凭印象：
  - `tools/check.sh` 三处——过滤名单里那条为旧规范留的排除项（旧文件删掉后就是死条目）、两处带 `docs/agents/doc-guide.md` 的提示、以及第 42 行只说「零节」的那处注释；「零节」的新落点是 `按需-文档通用纪律.md`。
  - `tools/hooks/commit-msg` 两处、`tools/test.sh` 一处注释、`.gitignore` 三行注释。
  - `modules/SSHFleet2_Go` 下五处代码注释：路径与节号一起换成文件名，只换路径等于没换。
  - `modules/SSHFleet_Go_bak` 是只读区，不动。
- 写 ADR 并补 `docs/adr/0000-索引.md` 的一行。ADR 里提到旧文档时写篇名、不带 `docs/` 前缀——旧文件随后几笔就删，带路径的引用撑不过去；带「决策人」段就必须带「是证据，不是要求」那句标注。
- 删旧四份的前置条件：第一步两条验收都绿，且按空行切段逐段勾过归属（标题齐不等于正文齐）：

  ```bash
  awk 'BEGIN{RS="";ORS="\n"} {gsub(/\n/," "); printf "%d: %s\n", NR, substr($0,1,36)}' docs/个人开发规范.md
  ```

  四份各跑一遍（把文件名换掉），逐段指到新文件的哪一节。指不出的段就是漏了。
- **删除单独一次提交**，放在索引重写、指针清账、ADR 都提交之后。删是唯一不可逆的动作，单独成笔才回滚得动。
- 这一段要开发者单独点头。

### 四、检查

全量复查 21 份与 `AGENTS.md`，按检查经验逐条。

闸门对这批产出是豁免的——`tools/check.sh` 的过滤名单里就有 `docs/agents/` 与 `AGENTS.md`——所以另跑；但 ADR 不在豁免里，它会照常被查。

```bash
PAT='共[[:space:]]*[0-9]+[[:space:]]*条|第[[:space:]]*[0-9一二三四五六七八九十]+[[:space:]]*节|详见|依据见'
grep -nE "$PAT" docs/agents/*.md AGENTS.md
grep -ohE 'docs/[^[:space:]`，。；、（(）)"]+\.md' docs/agents/*.md AGENTS.md | sort -u |
  while read -r p; do [ -e "$p" ] || echo "悬空 $p"; done
```

第一行命中的若是正文在讲这两个词本身（纪律里点它们不该用），不算，判的是它后面跟着路径的形态。

- 索引、清单表、磁盘三者对齐：

  ```bash
  diff <(ls docs/agents/{必读,按需}-*.md | xargs -n1 basename | sort) \
       <(grep -ohE '(必读|按需)-[^ `|]*\.md' AGENTS.md | sort -u)
  ```

  左边只取前缀文件，上游那三份不参与；这条空即对齐。
- 旧路径检索改用 `git grep`（只扫已跟踪的文件，工作区里的历史产物与个人目录自动排除），允许命中只剩：本文件、新写的 ADR、`docs/adr/` 下的历史文档、`modules/SSHFleet_Go_bak` 只读区。

  ```bash
  git grep -n "个人开发规范\|doc-guide\.md\|测试环境使用指南\|交流方式" -- '*.md' '*.sh' '*.go' '*.yml' '*.json'
  ```

- 第四步自己也要覆盖 `tools/` 与 `modules/SSHFleet2_Go`：上面那条已含，另看一眼注释里的旧节号有没有换成文件名。

## 迁移口径

- 只搬家、合重、删废话；不改任何一条的实质含义，不重排红线七条的编号。
- 标题用主题名，不背原节号；标题的改动统一放在第二步，第一步只搬。
- 旧文里按节号的指代不再自动对应，靠关键词对上。
- 现场事实（账号口令、版本号、日期）原样保留，但一处文件里只出现一次，不散在多份；标清是本机现场。

## 授权

三道门，缺一不可：

- 这是约束类文件，动手前要一次明确同意，覆盖第一、二步与第四步的复查，也覆盖第四步查出问题后的回写。
- 第三步要改 `tools/` 下的脚本与代码注释，那属于改代码，须开发者说出「授权开工」四个字。这次没有工单，不走 `/implement`，四个步骤本身就是执行顺序。
- 删旧四份单独一次点头，与上一条分开。
