# 02: 提示词表加载与匹配喂入

Status: resolved
Blocked by: 01

**要做的**：让改密真正改得动一台机器。加载 `config/passwd_keywords.conf`（随包提供，缺失即报错），按表认出远端的提问并按序喂值，直到会话自己结束。

提示词表只配两样：**提示原文**与**这条该喂哪个值**。值不进配置——`current` = 清单里那台机器的登录密码（从客户端配置取，不另传一份），`new` = `--change-password` 的参数。表按顺序走，匹配口径随 `[interactive]` 段（子串 / 正则、大小写）。

加载即校验，非法就地报错：至少一条 step、`value` 只能是 `current`/`new`、`max ≥ 1`、`keywords` 非空。它是一份规则文件，与 `error_keywords.conf` 同待遇——`CheckConfigFiles` 要认它。

匹配器**新写一个**，只复用关键词查找那一件（`keywordRule`）：代填的游标匹配器是"一条规则只送一次"，改密要重复送，两者语义不同，改造共用件会让刚验收的代填路径一起受牵连。匹配器是纯逻辑，**先写单测**再写实现。

**入场信号作真门**：没出现过期信号之前，三条提示规则一律不参战。信号的关键词取判据文件里「密码过期」分类——不在这份配置里另配一遍，两处同时能配就是两份真相。

- [ ] 一台真·过期机器改密成功：会话跑完、退出码 0、原命令不执行
- [ ] 提示词表缺失 / 字段缺失 / `value` 写错 / `max` 为 0 / `keywords` 为空 → 各自明确报错
- [ ] 未过期机器全程不喂（入场信号没出现，任何提示都不匹配）
- [ ] 改密会话里**没有**中止词：过期信号只开喂，不终止会话
- [ ] 匹配器单测覆盖：多条规则并行取最先出现者、命中后游标推进、正则与大小写两个开关
- [ ] `go vet ./...` 干净、`go test ./...` 全绿
