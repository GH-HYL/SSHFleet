# 03: 可重复消费与上限

Status: done
Blocked by: 02

**要做的**：让远端重问时还能把答案再送一次。每条 step 带自己的 `max`（默认：当前的密码 1 次，新的密码与重新输入各 4 次），远端重问就再喂一次，**喂满即止**。

上限是**护栏不是判据**：它的作用是防止某个提示反复出现时无限喂，不参与成败判定。所以**用不满不算失败**——root 改密根本不问「当前的密码」，那一条从不被消费，改密照样成功（真机验过）。

**不是"换个更强的再试"**：一条 step 只有一个值，重喂永远是同一个值。所以它买的是**时序容错**（远端重问时答案还能再送一次），不是强度救回——弱密码救回要一条 step 挂多个候选值，而那需要用户给出第二个新密码，没有意义（2026-09-29 真机复测后纠正）。

**喂满而远端又问 = 无话可给 → 立刻收场**，不干等到 `-t`（真机实测：不这么做会白等满 60 秒）。

- [x] 同一个提示重问能再喂，最多 `max` 次（匹配器单测 + 真机「密码未被更改」反复重问）
- [x] 喂满之后远端又问 → 立即收场：真机从 60.21s 降到 0.26s
- [x] 用不满 `max` 不影响判定：root 改密「当前的密码」一条未消费，仍判成功
- [x] 改 `max` 的取值能立刻改变行为（真机把 `max` 改成 0，启动即报「第 1 条：max 必须是正整数」）
- [ ] **弱密码被 PAM 拒后救回**——**做不到**，见上文；本机 PAM 也没开强度校验（B4），无从复现
- [x] `go vet ./...` 干净、`go test ./...` 全绿
