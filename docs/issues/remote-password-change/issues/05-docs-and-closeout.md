# 05: 文档与收口

Status: resolved
Blocked by: 03, 04

**要做的**：把改密写成用户能自己用起来的样子，并做完整收尾。

文档按各册自己的分工放，别互相抄：`docs/使用手册.md` 选项表加一行并写用法说明；`docs/配置手册.md` 的进阶配置段加一节（提示词表是新增的配置文件，得告诉用户它在哪、能改什么）；`docs/示例.md` 加一条；`docs/常见问题.md` 加一问（"一批机器密码过期了怎么批量改"）；`README.md` 只在能力表点一行、不展开。

用户可见的说明里必须写清三件事：新密码怎么给（明文 / 密文文件路径随加密开关）、**不过期的机器会被算作失败**（这是刻意口径，不写清楚会被当成 bug）、提示词表撞到新措辞时怎么补。

收尾四项：`go vet ./...` 干净、`go test ./...` 全绿、`build/` 下开临时沙盒跑一遍真实执行路径（用完删掉）、提交。CHANGELOG 当天段定稿 + 入口版本常量复核。

- [ ] 使用手册、配置手册、示例、常见问题、README 五处齐备且不互相重复
- [ ] 说明里写明「未过期机器计入失败数」
- [ ] 说明里写明提示词表的位置与补措辞的办法
- [ ] `go vet ./...` 干净、`go test ./...` 全绿
- [ ] `build/` 沙盒实跑一遍后已删除，工作区无残留
- [ ] CHANGELOG 段内条目是最终形态（不留修改过程），版本号两处一致
