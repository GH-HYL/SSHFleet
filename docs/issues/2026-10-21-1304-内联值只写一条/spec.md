# 内联值只写一条：`-f` 与 `-a` 取消一切换行写法 · 规格

Status: done（2026-10-21 实施，三张工单全部完成）

> 决策依据：`docs/adr/0023-内联值只写一条.md`（为什么 `\n`、`;;`、真换行三条路都不留，以及二义性为什么无解）。本文只写「做成什么样」，不重复取舍理由。

---

## Problem Statement

内联清单与内联代填，使用者现在面对的是三种说法并存、且没有一种被完整兑现：

1. **手册说能写多台，照抄就失败。** 手册里那条三台示例（`-f "192.168.1.10;;192.168.1.11;;192.168.1.12" -c "uptime"`）是真示例，照抄报「`-f` 参数指定的文件不存在」。
2. **同一个位置上到底什么算分行，讲不清。** 字面 `\n` 曾经是分隔、现在只是普通字符；`;;` 是分隔；直接回车（bash 的 `$'…'`）也能写进内联且被当成多行。三者混在一个取值里，使用者没有判断依据。
3. **代填内容里要回车，内联没有可指望的写法。** `-a` 的内联值可以用 `;;` 写多条，但内容里要回车，只能靠 shell 把真换行传进引号里——cmd 下写不出这种写法，手册里也没有这条路。

结果是：文档教的写法与实现不是一回事，使用者照着写一次失败，之后只能靠试。

## Solution

`-f` 与 `-a` 的取值只剩两种：一个 CSV 文件，或内联的一条记录。

- `-f` 的内联值是一台节点：`192.168.1.10` 或 `192.168.1.10,22,root,密码`。
- `-a` 的内联值是一条代填：`y,是否继续`。
- 判定次序固定：值先**原样**按路径交给系统；不是已存在的文件，再看它能不能当一条记录读；两者都不是，报「文件不存在」并给出该侧那一句写法提示。
- 字面 `\n`、`;;` 都只是普通字符：不识别、不给提示、也不改变报错内容；内联值里出现**真换行**直接拒绝，原因只说一句「内联值里不能有换行：内联只写一条」，去路放在提示行（指向 CSV 文件）。
- 多台节点、多条代填、内容里要含回车的代填，一律写进 CSV 文件；文件侧的注释、空行、BOM、引号、变长列口径保持不变。
- `-f` 与 `-a` 共用同一处判定，报错同形。

## User Stories

1. 作为临时测一台机器的运维人员，我希望 `-f 192.168.1.10` 与 `-f 192.168.1.10,22,root,密码` 照旧能用，这样临时操作不用先建文件。
2. 作为要代填一条内容的人，我希望 `-a "y,是否继续"` 照旧能用。
3. 作为照着旧示例写了一次多台的人，我希望报错不把我引向「再加个什么记号就能写多台」——内联只写一条，多台只能写文件。
4. 作为想知道内联到底支持哪些写法的人，我希望手册、帮助和报错说的是同一件事。
5. 作为要把带回车的内容代填进去的人，我希望文档把我引到 CSV 文件，而不是让我在内联里找转义记号。
6. 作为 Windows 用户，我希望路径里的 `\n`（如 `D:\new\pw.bin`）永远不会被当成换行，`D:\nodes\a.csv` 也不会被替我换成别的形态。
7. 作为接手仓库的人，我希望内联识别只有一处实现，不会在 `-f` 与 `-a` 之间各自错一次。

## Implementation Decisions

- **识别收口到一处，次序固定**：`-f` 与 `-a` 共用同一个判定与同一份报错。判据三段——① 值原样交给系统当路径（只探测存在性，不做 `\`→`/`、去空白、拼前缀这类加工）；② 不是文件时，值必须能当一条记录读（`-f` 看首字段去掉成对外层双引号后是不是 IPv4，`-a` 看值里有没有列分隔符，含逗号才可能同时给出内容与触发词）；③ 都不满足，报「`-f` / `-a` 参数指定的文件不存在」并给出该侧提示。两侧只提供各自那一条判据，不各自写一套判定与话术。判据只剥引号、不预解析整行——预解析会把引号不配对这类真语法错误吞成「文件不存在」。
- **命中文件后路径原样使用**：判定用的是哪个字符串，后续读的就是哪个，不再过一遍规范化。
- **不做装载期替换**：内联值不再有任何整备步骤，直接按单行 CSV 解析；字面 `\n` 与 `;;` 原样进入字段。装载侧原来「把 `;;` 换成分行」那一步整个删除，不保留成恒等函数。
- **真换行必须拒绝**：内联值里出现换行（`\n` 或 `\r`）时明确报错，不静默当记录分隔，也不静默丢弃后半截。报错给出去路（写文件），且只说这一件事。
- **`;;` 与字面 `\n` 不构成语法，也不触发提示**：报「文件不存在」时提示的是该侧固定的那一句写法示例，不因值里出现 `;;`、`\n` 或看起来像几台而变化。`-f` 那句提示里的「几台」改成「一台」，与「只写一条」对齐。
- **帮助与使用者文档**：程序帮助与手册、常见问题、示例、进阶手册、README 里，`-f`、`-a` 的取值说明只保留单条形态；「多台 / 多条怎么写」指向 CSV 文件。任何地方都不得再出现内联多行的示例。CHANGELOG 已封口的旧段不动，实施当天在新段按最终形态记一句。
- **不设转义、不设第二个记号、不为旧写法做兼容**。

## Testing Decisions

- **接缝**：沿用既有接缝——命令行参数入口（解析 + 合规检查）与清单 / 代填装载的公开入口。不新增接缝，不测私有函数。
- **要钉住的行为**：
  - `-f` 单条裸 IP、单条四列都能通过识别并进入执行；
  - `-f` 首字段带成对外层双引号（`"10.0.0.1",22,root,pw`，Excel 导出的单行 CSV 就长这样）→ 仍认得出是 IP，按一条节点进执行；
  - `-f` 值含换行（裸 IP、带完整列两种写法；含 `\r\n` 与孤立 `\r`）→ 拒绝，文案说明内联值里不能有换行并指向文件；
  - `-f` 值写成 `ip;;ip` → 不切成两台，报「文件不存在」，与路径打错同一个样，不出现任何只针对 `;;` 的提示；
  - `-f` 值里含字面 `\n`（Windows 路径）→ 当普通字符，按一条记录通过识别；
  - `-a` 单条 → 通过；`-a` 值含真换行 → 拒绝；
  - `-a` 把不存在的路径当内联 → 报「文件不存在」，与 `-f` 同形；
  - `-a` 内联值只解析出一列（如 `"a,b"` 这种引号里才有逗号的写法）→ 仍按「第 1 行不合规」报列数问题，不落到「文件不存在」；
  - 路径只按原值探测：Windows 风格分隔符在 Linux 上不会因为被改写形态而找到；
  - 给文件路径、文件里多行 → 照旧解析（回归既有能力，确认没被内联侧改动波及）。
- **既有用例随行为一起改**：钉住 `;;` 分行、真实换行等价、Windows 路径经规范化被找到的那几条，按新口径改写或删除；**MUST NOT** 为旧写法留兼容用例。
- **期望值**取自字面量（手写的 IP、行数），不用被测代码同款算法重算。

## Out of Scope

- 文件方式的解析口径与换行规则（不变）
- 代填内容里表达真换行的内联写法（走文件）
- 失败分类、退出码、报文
- 为内联另立选项（如 `-F`）
- **`-a` 代填内容里的明文凭据检测**：第 1 列是任意文本，没有固定位置可认，不设检测（开发者 2026-10-21 定「拦不住、也就没有可识别的列」）
- **`-s` / `-u` / `-p` / `-d` 的路径规范化**：它们仍走既有的字符串规范化，与「命令行输入的路径原样交给系统」还没统一；本议题只动 `-f` / `-a` 的判定，其余登记在 `docs/issues/2026-10-21-1413-命令行路径规范化/`（只登记、未分析，择期集中处置）。
