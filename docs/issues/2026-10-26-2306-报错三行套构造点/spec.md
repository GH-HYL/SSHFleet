# 报错「问题 / 原因 / 提示」三行套收敛到构造点 · 规格

Status: ready-for-agent

> 决策依据：ADR-0025 决定 6（报错分两层、参数与前置检查阶段的三行套形态）与
> `2026-10-21-1413-命令行路径规范化/audit-run-2026-10-26/报告.md` 判断题 D26。
> 来源：回顾审计发现同阶段报错的形状不齐（`--change-password` 有两条只有一行），
> 且全仓 28 处手写拼接、没有一个可调用的构造点。作者 2026-10-26 定：单独开议题，不在路径议题里搭车。

## Problem Statement

同一阶段（参数与前置检查）的报错，形状不该由写的人现场拼：

- `--change-password 的值有问题：…` 只有一行，没有「原因：」也没有「提示：」，使用者不知道下一步做什么；
- 隔壁同是这个选项的「值读不到」却是完整三行。

新增一个报错点的人只能去抄别的报错再改，抄漏了「原因」或「提示」没有任何东西拦着——上面那两条漏网就是这么来的。

## Solution

在 `internal/common` 提供两个构造点，全部报错点改走它：

- `ErrUser(problem, reason, hint)`：三行齐——有系统原文可引的；
- `ErrUserShort(problem, hint)`：纯形态判定、没有系统原文可借的（远端形态检查、`-p` 不是目录那支）。

清单侧的逐行汇总（原因写在行内的那段）不在此列——它不是独立报错，是行内的一段文字。

## User Stories

1. 作为新增一个报错点的人，我希望填几个参数就把行凑齐，而不是去抄别的报错再改。
2. 作为复查的人，我 grep 构造点就能数出全部报错点，不用搜中文字符串。
3. 作为下一次要改报错格式的人，我只改构造点一处，不用碰 28 个文件。

## Implementation Decisions

- 构造点放 `internal/common`：现状 28 处横跨 11 个包，`common` 是唯一大家都在下面的包。
- 逐处迁移，**第一行的拼法原样保留**——本议题只动「怎么拼」，不动「说什么」。
- `main` 的外层包装 `wrapFatal` 不动（它拼的是另一层）。
- 迁移完成后，`internal/` 下除构造点外不得再出现 `\n原因：` 字面量（grep 判定）。
- 两处只有一行的（`--change-password 的值有问题`、`值读不出新密码`）一并迁成 `ErrUserShort`；缺的那句「提示」在实施时起草，写进工单 Comments 给作者过目——那是唯一的措辞新增。

## Testing Decisions

- 既有断言全部是子串匹配，迁移后**一条都不该变**；两平台 `go test ./...` 全绿即通过。
- 新增一条对构造点本身的断言：产出串含 `\n原因：` 与 `\n提示：`（ErrUser）/ 不含 `\n原因：`（ErrUserShort）。

## Out of Scope

- `sshfleet.<环境>.<环节>` 报文体系（执行阶段）。
- 清单侧逐行汇总的形态。
- 任何文案措辞的改动（上面那两句新「提示」是唯一的例外，且要过目）。
