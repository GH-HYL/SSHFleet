# 报错三行套收进构造点 · 规格

Status: done

> 决策依据：ADR-0028（拼法收进构造点、射程按受众切、内部错误单列、只抽格式）、ADR-0025 决定 6（三行套形态）、ADR-0021（执行阶段报文）。
> 来源：`2026-10-21-1413-命令行路径规范化` 议题回顾审计的判断题 D26。

## Problem Statement

同一个阶段的报错，形状不一样。同样是 `--change-password` 的值写错：一处完整三行（哪儿错、系统原话、怎么改），一处只有一行「值有问题」，一处第二行干脆没标签。使用者看到「值有问题」，不知道该改什么。

维护者这边：36 处报错各自打字符串，七种写法并存。新增一个报错点只能去抄一段最近的，抄漏一行没有任何东西拦——那两处一行报错就是这么漏出来的。

## Solution

把「怎么拼」收进一处构造点，现有 36 处逐条迁过去，**迁移不改一句话**，形状保持原样；缺「提示」的那两处补上一句怎么办。执行阶段的单机失败、日志、报告正文仍各走各的载体，不进构造点。

迁完之后：改一次标签只改一处；复查时报错点能靠 grep 数清；漏拼一行有机器判据能查出来。

## User Stories

1. 作为使用者，我希望报错把「哪儿错了、为什么、怎么改」给全，这样我不用猜下一步做什么。
2. 作为使用者，我希望同一类错误在哪儿出现都是同一形状，这样我不用重新判断该看哪一行。
3. 作为新增报错点的人，我希望填几个参数就把形状凑齐，而不是去抄别的报错再改。
4. 作为新增报错点的人，我希望构造点的注释直接告诉我「这种形态用哪个名字」。
5. 作为复查的人，我希望 grep 构造点就能数出全部报错点，不用搜中文字符串。
6. 作为复查的人，我希望漏拼一行的报错能被一条命令查出来，而不是逐条读中文。
7. 作为下一次要改报错格式的人，我希望只改构造点一处，不用碰 36 个位置。
8. 作为维护者，我希望「这是内部错误，请把本次命令反馈给作者」只在一处维护，各调用点不各写一遍。
9. 作为维护者，我希望执行阶段的报文不被中文三行套污染，按 `sshfleet.` 前缀识别失败的判据继续有效。
10. 作为作者，我希望这次迁移的 diff 里只有「换拼法」、没有「改说法」，复查时一眼能判。

## Implementation Decisions

- 构造点落在所有报错点共同的下游包里（该包不依赖任何内部包），避免成环。
- 按**现成形态**分几个语义化名字，不用「一个函数 + 空参数」（空参数在调用点看不出意图，也数不清分布）：
  - 问题 + 原因 + 提示：有系统原文可引；
  - 问题 + 原因：没有合适的「提示」可写（19 处走这个，**不新增文案**）；
  - 问题 + 提示：纯形态判定，没有系统原文可借；
  - 问题 + 原因 + 固定内部错误说明：第三行恒定，调用点只给前两行。
- 构造点只负责标签与换行：不 trim、不加句号、不改写任何一句内容。
- 迁移**逐字节等价**。唯一新增文案是那两处一行报错的「提示」，措辞实施时起草、作者过目后落。
- 「常见原因：」那一条（多余参数）保留它的特殊形状，不当作模板推广，只把拼法换成构造点。
- `main.go` 的执行前守卫（改密入场信号）与 8 个包一并迁。
- **新增一项检查（作者 2026-10-27 定）**：`--change-password` 收到的是密文内容本身（不是密码、也不是文件路径）时，按模式各给一句提示——没开加密说「这一格要写新密码本身」，开了加密说「这一格要写密文文件的路径」。这是一项新行为，不在原工的「只抽格式」范围内，属作者当场追加。
- 不新增抽象、不引依赖、不动报文。

## Testing Decisions

- **接缝只有一个**：构造点本身是公开函数，测它产出的串（哪种形态有几行、标签顺序、该缺的行缺没缺）。这是本议题唯一新增的测试面。
- 迁移的验证靠既有断言：绝大多数是子串匹配，`internal/cli/answer_test.go` 与 `internal/cli/source_test.go` 是整串比对——迁完一条都不许改，必须全绿。
- 那两处一行报错现在零覆盖，用既有公开入口 `CheckArguments` 覆盖（`internal/cli/passwd_test.go` 已在用同一入口）；不另开接缝、不测包内私有函数。
- `internal/batch` 没有测试文件，它那 3 处只能靠构造点断言 + 人工触发一次上传核对输出，写进对应工单的验收项。
- 门（交付前必跑，无命中即通过）：

  ```bash
  grep -rnE --include='*.go' '\\n原因：|"原因：' internal/ main.go \
    | grep -v _test | grep -v '^internal/common/'
  ```

  三个坑：只搜 `\n原因：` 会漏 5 处拆行拼接（`"…\n" + "原因：…"`）；按文件名过滤 `common` 会把迁移后的行全滤掉（它们都写着构造点调用），必须按目录过滤；带缩进的 `"  原因：`（`--key-status` 的状态输出）不在本口径内，不能算进去。多余参数那处的「常见原因：」是它自带的小标题，不属本口径。
- 两平台 `go test ./...` 全绿（Windows 走 WSL2、Linux 走 Podman，见规范·验证环境）。

## Out of Scope

- 执行阶段单机失败的提示形态（报文 + 分类提示块维持现状）。
- 日志、panic、内部断言的措辞。
- 报告正文、Excel 导出、清单逐行汇总（行内文字，不是独立报错）。
- 「提示」是否必须出现——19 处缺提示保持两行，本议题不补。
- 文案口吻统一、提示语集中管理。
- 「出处 / 出路」那套标签是否收编。
- 报文体系 `sshfleet.<环境>.<环节>`。

## Further Notes

- 时机：与「改报错文案」的轮次分开，避免格式重构与口径变更混进同一个 diff。
- 计数口径（2026-10-27 实测，仓库 HEAD）：带「原因：」标签的报错构造点 36 处，含 5 处拆行拼接，已排除 `credential` 里那处 `--key-status` 状态输出（它不是报错）。分布：cli 11、config 6、credential 4、dangercheck 4、output 4、batch 3、verdict 2、ssh 1、main.go 1。
