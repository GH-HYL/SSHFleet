# 上传前的空间预检与「哪一侧满了」的归类 · 规格

Status: 待执行（ready-for-agent）

> 决策依据：ADR-0026（为什么用 SFTP 的 `StatVFS` 而不是跑 `df`、两侧判据为什么不同、硬比为什么不留余量）。
> 本节只写「要做成什么样」。范围的由来：本议题原本是「摸清磁盘满在目标机上长什么样」（`issues/01-find-ground-truth.md`），
> 回滚议题（ADR-0022）完工后，「传一半留下残留」这个诉求已经不存在，剩下的只有「别白传」与「说清是哪一侧」。

## Problem Statement

上传一个目录到目标机时，如果空间装不下，今天的使用者会遇到两件事：

1. **白传**。工具从第一个文件开始写，写到装不下才失败，然后按 ADR-0022 把本次已写的全部删掉。目标机恢复了原样，但已经花掉的传输时间收不回来——一个几 GB 的目录，可能是几十分钟。
2. **不知道是哪一侧、差多少**。失败的分类落在「目标机写入失败」，提示语把「磁盘满或配额用尽、目标目录没有写权限、传输中途连接断了」三种原因写成一句。使用者拿不到任何数字，只能自己登上去 `df`。

`--sudo` 上传还有第二个位置：文件先进登录账号的暂存目录（`/tmp` 下的临时目录），再以 root 移到目标目录。**两侧任何一侧不够都传不成**，而今天两侧都没有任何事前判断。

SFTP 协议本身帮不上忙：写失败时服务端只回一个通用码 `SSH_FX_FAILURE`，分不出磁盘满还是权限。所以「失败后告诉使用者是满了」这条路走不通——只能在**传之前**问，以及在**失败之后**再问一次。

## Solution

上传开始前，先问目标机两侧的可用空间，和本次要传的量比：

- 不够 → 当场说清**是哪一侧**、**需要多少、可用多少**，一个文件都不传；
- 够 → 照常传。

传的过程中失败了，再问一次，把这次失败归到「目标磁盘分区已满」或「暂存目录分区已满」；两处都够，就维持原来的分类（说明满不是这次的原因）。

分类按两侧分开，使用者一眼能看出该清哪块盘；两种情况目标机都不会留下本次的文件。

## User Stories

1. 作为使用者，我要在开始传之前就知道装不下，而不是传了半小时才发现。
2. 作为使用者，我要知道**差多少**——报文里给出「需要多少、可用多少」两个数，而不是一句「空间不足」。
3. 作为使用者，我要知道**是哪一侧**不够：目标目录所在分区，还是 `--sudo` 用的暂存目录所在分区，否则我会去清错盘。
4. 作为 `--sudo` 上传的使用者，我要两侧一起检查，因为任何一侧不够我都传不成。
5. 作为使用者，我要预检判满时目标机上没有任何残留——一个文件都不该被写进去。
6. 作为使用者，我要失败后的分类落在具体那一侧，而不是笼统的「目标机写入失败」。
7. 作为使用者，我要在「两处都够、失败另有原因」时看到原来的分类，不要把权限问题说成空间问题。
8. 作为使用者，我要在服务端不支持这个探测时照常上传——预检失效可以，挡住上传不行。
9. 作为使用者，我要同一次上传只在开头探一两次，不要在循环里每传一个文件就停一下。
10. 作为使用者，我要清理之后再传时行为不变（回滚照旧、撞名照旧不覆盖）。
11. 作为排查问题的人，我要能从报文里看出这次判据用的是「需要多少」和「可用多少」这两个数，而不是一个结论。
12. 作为维护者，我要判据只有一处实现，预检和失败后再查用的是同一套，不会两处说法不一致。
13. 作为使用者，我要在手册里查到「空间不够」时该做什么（清哪块盘、或换目标目录）。

## Implementation Decisions

**探测方式**

- 用 SFTP 的 `statvfs@openssh.com` 扩展（`pkg/sftp` 已封装为 `StatVFS`，依赖已在，不新增库）。
- **不给命令通道 `df` 留兜底**：它要 exec 权限（sftp-only / scponly 账号直接不可用）、要解析文本与单位、要自己匹配挂载点，多一条会自己出错的路径。服务端不支持时静默跳过。
- 探测点：目标目录本身；`--sudo` 时再加暂存目录的父目录（即 `/tmp`——暂存目录要到第一个文件才建，预检时它还不存在）。
- 一次上传只在同一时刻探（`--sudo` 时是两处：目标目录与 `/tmp`），进循环之后不再重复探。

**判据**

- 两侧各按自己的峰值比，**不是同一个数**：
  - 目标侧：需要量 = 本次总量（文件在目标目录里逐个累加；`--sudo` 跨分区时 `mv` 退化为复制，也是累加）。
  - 暂存侧：需要量 = **最大单个文件**（传一个就移一个，暂存区任何时刻只压着一个文件）。
- 可用量按「谁在写」取：目标侧在 `--sudo` 下以 root 写，读 `Bfree`（含保留块）；非 sudo 读 `Bavail`；暂存侧是登录账号写，读 `Bavail`。
- **硬比，不留余量**：`可用 < 需要` 即判满。判错时靠回滚兜底（本轮作者定的口径）。
- 不判断两侧是否同一分区：同区时暂存侧的需要量（最大单文件）天然小于目标侧（总量），不会多拦一次。

**归类**

- 分类拆两条：**目标磁盘分区已满**、**暂存目录分区已满**。后者只在 `--sudo` 且登录账号不是 root 时可能出现（非 sudo 直接写目标，没有暂存这一步）。
- 报文（只陈述事实）：`sshfleet.transfer.target_space_short` / `sshfleet.transfer.tmp_space_short`，各自带**自己那一侧**的两个数——目标侧给「本次总量 / 可用」，暂存侧给「最大单个文件 / 可用」。报文名说「空间不够」而不是「已满」，因为判据是 `可用 < 需要`，未必真到 0。
- 排序照既有先例：回滚那两条排在所有传输失败原因之前（ADR-0022 的「顺序规则」），空间不足排在其后。预检判满不产生回滚报文——没有文件被写过，回滚本来就没动作。
- 预检判满与现有前置检查失败（「上传目标不是目录」）走同一出口：只写报错原文，不进入逐文件循环；成功/失败计数也沿用那一档的形态（两个都不设），不另造新值。

**失败后再查**

- 只在**写失败**这一个出口加探测；撞名、本地读不了、取消这三个出口不加——它们的原因已经说清了。
- 判据同一套：`可用 < 剩余未传量` 则归到对应那一侧，否则维持原分类。「剩余未传量」= 本次总量 − 已写成功的字节数（失败的当前文件已写的那部分不算，它会被删掉）。
- 探测本身失败（不支持、超时、路径不可达）→ **静默降级**：不给结论、不新增分类、不改变上传结果。

## Testing Decisions

好测试的判据：只从外面看行为——给这台机器一个真实的空间状况，看工具报什么分类、目标机上有没有留下文件；不测「调了几次探测」「内部用的哪个字段」。

两条接缝（**作者 2026-10-26 已确认**：可以自建临时账号在 WSL2 上直接测）：

1. **判据纯函数**（包内测试）：输入「可用 / 需要 / 是否 sudo」，输出「判满与否 + 该发哪条报文」。期望值用算出来的字面量（例如 64MB 卷、40MB 已有、要传 30MB → 判满），不拿被测代码自己再算一遍。
2. **真机集成用例**（`-tags integration`，先例：`internal/ssh/upload_rollback_test.go` 的八场景）：造一块有容量上限的真实块设备，跑「装不下」「刚好装得下」「暂存侧装不下」三种，断言分类与目标机残留。

另外在分类语料（`testdata/error_classification_cases.toml`）里补两条，锁住报文到分类的映射。

**真机环境怎么造（2026-10-26 实跑通的配方）**：

```sh
# 目标机上（root）：64MB ext4 镜像 + loop，得到一块真实块设备，不是 tmpfs
dd if=/dev/zero of=/var/tmp/small64.img bs=1M count=64
mkfs.ext4 -q -F /var/tmp/small64.img
losetup /dev/loop0 /var/tmp/small64.img   # 用固定设备名，别用 -f --show 再回填变量
mount /dev/loop0 /mnt/small64
mkdir -p /mnt/small64/w && chmod 777 /mnt/small64/w   # 非 sudo 用例要一个可写子目录
```

两条踩过的坑写在这里，省下一个人再撞一次：

- **`losetup -f --show` 的输在本机 Git Bash 里回填不到变量**（`L=$(losetup -f --show …)` 得到空串，`mount` 就报 "bad superblock on "）。用固定设备名，或写好再读。
- **非 sudo 往 700 的 root 目录写会是 `permission denied`**，不是空间问题。所以「目标侧判满」这条用例要么走 `--sudo`，要么把目标指到那个 777 子目录。

## Out of Scope

- **失败后另开命令通道探 `df`**：见 ADR-0026 的备选方案，代价大于收益。
- **逐文件探测**：只买到「早一步知道」，白传的时间已经花掉；且每个文件多一条会失败的分支。
- **同区/异区判断**（`Fsid` 比较）：本设计不需要，见「判据」最后一条。
- **给暂存目录加配置项**：暂存目录是硬编码的 `/tmp/.SSHFleet_tmp/`，一旦出现「暂存目录分区已满」，使用者手上没有可调的东西。本规格只把它报出来，不解决。
- **配额（quota）**：`StatVFS` 报的是分区级可用量，用户/组配额不在其中。配额满而分区还有空间时，预检说够、传输中途失败——这一档仍由回滚兜底。
- **让工具说出「写失败是因为满了」**：协议层只回通用码，做不到；本规格的结论来自探测，不来自解析写失败。
- **下载侧**：下载动的是本机自己的产物（ADR-0022 决定第 5 条），且预检的收益是「别白传」，与下载的失败成本不对称。

- **旧摸底工单作废**：`issues/01-find-ground-truth.md` 要做的三件事里，「半成品是否留存」已由 ADR-0022 的真机八场景答过，「让工具说出磁盘满」已被本规格的结论取代（探测而非解析），所以不再按原样摸底；真实磁盘上的实测转入本规格的集成用例。
