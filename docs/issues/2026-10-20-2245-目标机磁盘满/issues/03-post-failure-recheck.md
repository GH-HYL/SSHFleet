# 03: 传一半才失败时，把原因归到具体那一侧

**要做的**：上传写到中途失败时，工具再探一次两侧的可用空间——确实是那一侧装不下，分类就落在「目标磁盘已满」或「/tmp 空间不足」；两处都够，维持原来的分类（说明满不是这次的原因）。探测本身失败一律降级，不改上传结果、不新增分类。

**被谁阻塞**：02（分类名、报文名与判据都在 02 里建好）。

**状态**：待执行（ready-for-agent）

**依据**：`../spec.md`「失败后再查」；决策理由见 ADR-0026

## 验收

- [ ] **卷只够放下第一个文件**：第二个文件失败 → 分类「目标磁盘已满」，同时回滚报文照旧出现（目标机干净）
- [ ] **失败另有原因**：目标目录不可写而空间充足 → 分类仍是「目标机写入失败」，不被改判成空间不足
- [ ] **探测本身失败**（服务端不支持、路径不可达、超时）→ 分类与没有这次探测时完全一致
- [ ] **撞名失败时的错误详情里不出现空间报文**（撞名、本地读不了、取消这三个出口都不探测）
- [ ] **需要量用「剩余未传量」**：已写过又会被回滚的部分不算进去；报文里不出现「没写过文件」那句
- [ ] 既有回滚八场景照旧全过（回滚范围与顺序未被改动）
- [ ] `go build ./...`、`go vet ./...`、`go test ./...` 全绿
