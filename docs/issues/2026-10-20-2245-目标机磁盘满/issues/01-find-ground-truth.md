# 01: 摸清失败全貌与「分出磁盘满」的代价

**要做的**：在本机搭一个**有容量上限的真实块设备**，把上传在三种情形下跑一遍——一开工就满、写到一半才满、以及对照的权限失败——记下工具实际给出什么：终端上的分类、错误详情原文、目标机上的半成品文件。再评估「让工具说出磁盘满」有哪几条路、各要多少代价。做完停下来，由作者决定这个议题要不要继续。

**被谁阻塞**：无，可立即开工。

**状态**：明确不做（wontfix）—— 范围被 `../spec.md` 与 ADR-0026 取代（2026-10-26）；其中「真实磁盘上的实测」转进新规格的集成用例，另两项已有答案（见 spec 的 Further Notes）

## 验收

- [ ] **验证环境**：用一个**真实文件系统**造容量上限（例如一个小容量的 ext4 镜像挂到目标机上），不用 tmpfs；环境怎么搭、怎么拆写进 Comments，**用完清干净**。
- [ ] **三种情形各跑一次上传**，逐条记下：
  - 一开工就满；
  - 只余一点空间、写到一半才满（至少两个文件，先成后败）；
  - 对照：权限不足（目标目录不可写）。
- [ ] 每种情形都记下：**分类**（统计块那一格）、**错误详情完整原文**、**目标机残留**（半成品在不在、多大、属主是谁）、**成功计数是否与实际相符**。
- [ ] 核对：失败后目标机上的**半成品是否被删**；如果没删，记下它的文件名规律（是否像正常的文件名，会不会让下一次执行撞上「远程文件已存在」）。
- [ ] **评估「分出磁盘满」的路子**，每条写清代价与风险，至少覆盖：
  - 失败后另开一条命令通道探测目标机 `df`（多一次往返、依赖目标机有 `df`、探测本身可能失败）；
  - 用 SFTP 的扩展字段（先查目标机实现支不支持，很可能不支持）；
  - 预检时探测可用空间（写之前就知道不够，但空间随时会变）；
  - 不做，维持「SFTP失败」这个通用分类。
- [ ] 结论：**分得出 / 分不出、值不值得**，一句话给作者。
