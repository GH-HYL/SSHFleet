# 01: 上传前判满，分类落到具体哪一侧

**要做的**：按下上传之后、写第一个文件之前，工具先问目标机两侧的可用空间——目标目录所在分区，`--sudo` 时再加上 `/tmp`——不够就当场停下：统计块给「目标磁盘已满」或「/tmp 空间不足」，错误详情写清「需要多少、可用多少」并声明本次一个文件都没写。够就照常传。服务端不支持这个探测时静默跳过，照常传。

**被谁阻塞**：无，可立即开工。

**状态**：待执行（ready-for-agent）

**依据**：`../spec.md`「Implementation Decisions」；决策理由见 ADR-0026

## 验收

- [ ] **目标侧装不下**：造一块有容量上限的真实卷（配方在 spec 的 Testing Decisions），传一个比它大的目录 → 统计块显示「目标磁盘已满」，错误详情含 `target_space_short`、需要量与可用量两个数，并声明没写过文件；目标机上没有任何本次的文件
- [ ] **暂存侧装不下**：`--sudo` 上传、`/tmp` 的可用量小于最大单文件 → 统计块显示「/tmp 空间不足」，目标目录与 `/tmp` 都没有残留
- [ ] **两侧都够**：照常传成，不产生任何空间报文
- [ ] **目标目录是 700 的 root 目录时**，探测仍能给出空间判断（它不需要写权限）；同一目录下非 sudo 真去写才会 `permission denied`
- [ ] **判据纯函数单测**（期望值用字面量，不拿被测代码再算一遍）：目标侧比本次总量、暂存侧比最大单文件、`--sudo` 下目标侧取 root 可用量而普通用户取非 root 可用量、`可用 < 需要` 即判满、不留余量
- [ ] **分类表两条已登记**：`name` 为「目标磁盘已满」「/tmp 空间不足」，`keywords` 写报文全前缀，位置在两条回滚分类之后；语料补两条，锁住报文到分类的映射
- [ ] **服务端不支持探测时**：不上报、不阻断，结果与没有这条功能时一致
- [ ] **手册**上传一节写明「装不下会在开始前报出来，本次不写任何文件」「`--sudo` 时两块盘都算」
- [ ] `go build ./...`、`go vet ./...`、`go test ./...` 全绿
