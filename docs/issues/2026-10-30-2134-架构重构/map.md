## Decisions so far

开图前已定，不占工单：

- **只做结构，不动实现**：现有工具能正常使用，重构不夹带功能、不修缺陷、不改行为。
- **五站分层**：解析 → 闸门 → 执行 → 结算 → 报告，形状照上一轮教学骨架。
- **契约独立**：`contract` 包只放类型与常量，一个函数都不许有。
- **横切五个叶子包分开**：`console` / `log` / `ask` / `archive` / `exitcode`，不合成 `common`。
- **交接件规则**：阶段之间传新造的交接结构体，不许传上一站的原结构体；下站缺字段时去上游纵切加，不许跨阶段回取（作者 U10 原话：「一改改一条线，这是必须付出的代价，并不是拿它去衡量取舍，它就应该是这样」）。
- **新工程单开目录** `modules/SSHFleet2_Go/`，不改老目录名。
- **老工程冻结**：只修紧急缺陷，新功能一律进新工程。不拆仓库、不开长期分支，退路靠提交点。
- **配置原样搬一份**：新工程自带 `config/`，格式、字段、出厂值与老工程完全一致，切换时整目录拷过去即可跑。
- **走探路**：先画这张图，决策定完再落规格与工单。

工单已结：

- **横切包权限表**（06）。`console` 独占写终端；写盘谁产谁写、路径只从 `archive` 拿、`archive` 不代写；叶子包只依赖标准库与契约，唯一例外 `ask` → `console`；`exitcode` 只认种类不认错误，所以由塔尖认。越界靠脚本扫。见 ADR-0032 第四条。
- **塔尖薄不薄看依赖清单，不看行数**（05）。塔尖只做分叉、搬、退三件；它是编排不是横切。分叉的依据只能是解析递回来的东西。帮助文本归解析、版本拼装归报告、常量留塔尖。见 ADR-0032 第五条。
- **五种模式不聚成包**（02）。第一刀横着切站、第二刀竖着切站内文件，模式不汇成包。载荷用一个带标签的格子装五种内容，对不上由闸门验。密钥管理独立成包、自己读自己那块配置；凭据读取再单列一个叶子包，两边共用。塔尖留一个分叉：走流水线还是那三条小命令。见 `docs/adr/0036-五种模式不聚成包.md`。
- **交接件按「棒」定形状**（03）。信封只有一份，随站换三次口径：解析→闸门→执行讲「要做什么」（闸门原样递，只加结论）；执行→结算讲「发生了什么」，按模式五份；结算→报告讲「总共怎么样」。载荷五份不合并（认下重复）。**同口径往下传时后一张必须比前一张窄**，一样宽就不该造两次；换口径那两棒只装下一站要用的。单台归类留在执行、全体汇总归结算。判据表进第一张纸；契约不放函数、合法性由闸门验；塔尖只搬不装。见 `docs/adr/0035-交接件按棒定形状.md`。
- **闸门的拒绝权只覆盖「前提齐了之后」**（01）。分界不是走到哪一站，是**东西完备不完备**：前提缺一样（配置读不到、空的、格式错、必须的那份没配）就叫「起不来」，齐了只是不放行才叫「拒绝」。**判断按「懂不懂这份材料」分**：校验（材料本身对不对）归懂它的那一站，裁量（这件事该不该做）全在闸门——判断散着不怕，能说「不」的才必须只有一处。归闸门三类：参数不合规、危险命令、人当场喊停。**判断散着、话走报错构造点、停只一处**；闸门不写话也不打屏，拒绝的话随「拒绝」一起交回塔尖，由塔尖交给终端再退。起不来与拒绝用两种类型，**起不来放通用类型包谁都能造，拒绝只住闸门**。判据表不归闸门，归解析的必须项清单；表里没有的那一条不造「未分类」，归类取原话。见 `docs/adr/0034-拒绝与起不来分成两种失败.md`。
- **老代码摊进五站，一块一句**（04）。五站定名**解析 / 闸门 / 执行 / 结算 / 报告**。跑的过程里的显示与实时定分类归执行站，报告站只管跑完之后（屏幕统计、报告文件、两张表格）；备份原料与「最新一次」链接归归档包；危险警告整件事归闸门管、但闸门不写字——不许跑时「拒绝 + 那张表」交回塔尖打，要提醒时交给 `ask` 摆出来再问，表只由 `message` 排。**不单设打印站**：打印不产数据、且五处时刻一个站占不住。`console` 只收 `message` 造得出来的类型，想打印连字都构造不出——编译挡住，不靠检查。清单脱敏副本由遮秘密叶子写（第 4 列是密码是清单的格式知识），归档只发路径、只做原样复制。见 `issues/04-legacy-package-mapping.md` 的 `## Answer`。
- **四张纸的格子摊开了，结果侧靠「通用格 + 附加格 + 随行件」**（15）。执行站对上只有一个口子：交进闸门那张纸，交回「发生了什么」，中途刷屏不经过塔尖。结果侧每台分两块——通用格（五种模式都有的事实）与带标签的附加格（模式多出来的东西）；**结算只算通用格，附加格原样递给报告**，同一条算法只写一遍。判据表与运行上下文（执行命令、模式与各模式参数）是**随行件**：数据格越往下越少，上下文形状固定、从头跟到尾，中间站不许打开、连类型都不许 import，只有报告站能读。加一格按 2–3 处算（契约定义 + 填 + 读），要回头从解析拿就是改一整条线。见 `issues/15-handoff-fields-and-execute-entry.md` 的 `## Answer`。
- **结构靠一个跟着 `go test` 跑的检查拦住，规矩以包注释点名**（07）。检查本身是测试，扫四类越界（写终端、依赖方向、退出动作、契约纯净），不另加命令、不改 `/implement`（它是上游副本）；`_test.go` 文件按后缀除外，不按目录除外。判据唯一出处是 ADR-0032 第四、五条，每个包的头注释只写「这包只干哪一件 + 判据在第几条」，规范与 `AGENTS.md` 都不动。**分档的界线是「能不能机械判」**：扫得到的是红线，扫不到的是取向。放行留一份台账，改它等同改约束类文件，每次跑测试先报「当前放行 N 条」。暂缓两条：塔尖不许拼字符串、相邻两棒比宽窄。见 ADR-0032 第四、五条。
