# 地图：前端流水线架构重构

## Destination

走完这张地图，手上要有四样东西，**代码一行未动**：

1. **结构定义**——五站各管什么、收什么、交什么；五个横切包各自能做与不能做；塔尖薄到什么程度。
2. **迁移地图**——老工程 13 个 internal 包与 `main.go` 的每一块搬到哪个新包，一行一块，搬完能对账。
3. **切换判据**——到哪一步算新工程能顶替旧工程，切换前要跑哪些验收。
4. **一篇 ADR**（`docs/adr/0032-*`）——为什么这么切、否掉了什么、代价在哪。

**动工是这四样之后的事，不在本图范围内。**

- **载体与格式**：`docs/agents/issue-tracker.md`（本图与子工单的落点）、`docs/agents/doc-guide.md`（ADR 与 spec 模板）、`docs/agents/triage-labels.md`。

## Decisions so far

开图前已定，不占工单：

- **只做结构，不动实现**：现有工具能正常使用，重构不夹带功能、不修缺陷、不改行为。
- **五站分层**：摄入 → 闸门 → 执行 → 整理 → 呈现，形状照上一轮教学骨架。
- **契约独立**：`contract` 包只放类型与常量，一个函数都不许有。
- **横切五个叶子包分开**：`console` / `log` / `ask` / `archive` / `exitcode`，不合成 `common`。
- **交接件规则**：阶段之间传新造的交接结构体，不许传上一站的原结构体；下站缺字段时去上游纵切加，不许跨阶段回取（作者 U10 原话：「一改改一条线，这是必须付出的代价，并不是拿它去衡量取舍，它就应该是这样」）。
- **新工程单开目录** `modules/SSHFleet2_Go/`，不改老目录名。
- **老工程冻结**：只修紧急缺陷，新功能一律进新工程。不拆仓库、不开长期分支，退路靠提交点。
- **配置原样搬一份**：新工程自带 `config/`，格式、字段、出厂值与老工程完全一致，切换时整目录拷过去即可跑。
- **走探路**：先画这张图，决策定完再落规格与工单。

## Not yet specified

雾里的东西，现在说不清，等前沿推进到这里再拆成工单：

- **五站与横切包的最终命名**——`ingest` / `gate` / `execute` / `appraise` / `present` 是骨架的临时叫法，等闸门那条（01）定完才知道叫不叫得准。
- **ADR 的篇数与切法**——一篇总纲，还是每站一篇，取决于 01–08 定完之后还剩多少互相独立的判断。
- **迁移期两份配置会不会走样**——老工程冻结但配置若因缺陷修改变字段，新工程那份要跟着改；怎么跟、记在哪。
- **冻结期缺陷修了怎么回放到新工程**——需不需要一份补丁台账，还是等切换前一次性对齐。
- **词表补词**——「塔尖」「站」「交接件」「横切片」这几个新词，等命名定下来一次性补进 `GLOSSARY.md`。
- **旧规格 D21 的「更新记录」**——依赖 ADR-0032 先存在。
- **切换那天 `.gitignore` 与 `tools/release/release.py` 的具体改法**——依赖第 12 条定完。

## Out of scope

- **任何具体实现代码**：本图只产决策与文档，不产可运行的东西。
- **新功能与缺陷修复**：重构不夹带；撞见了另开议题。
- **老工程的改名、迁仓、移走**：那是切换那天的事，且改名会撞上 `.gitignore` 的 `*_bak*/` 规则。
- **发布与版本号**：两套并存期间 `release.py` 仍只打老工程，不改。
- **AI 编码流程、技能体系、规范本身的改造**：与本图无关，另开。
