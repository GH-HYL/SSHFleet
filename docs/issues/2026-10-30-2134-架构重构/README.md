# 架构重构：把 SSHFleet 的工程结构按五站重画

## 这是什么

给 `modules/SSHFleet_Go/`（Go 写的 SSH 批量运维工具，两年、约一万三千行）重新规范工程结构，落点是 `modules/SSHFleet2_Go/`。

**这一轮只重画结构，不动实现**——老工程冻结只读，仍是当前发布版的唯一源码；新工程从零建，功能、配置格式、出厂值、输出都照旧。

## 为什么做

工具本身已经够用了，毛病在结构：半年里每遇到一个小问题就地改一点，改完看着都对，架构却在一点点被磨掉（architecture erosion）。于是趁有闲、有现成代码，把结构按行业经验重新规范一遍。

**目标不是「代码更好看」，是「把不该做的事变成做不到的事」**——哪怕以后还是 AI 写代码，也要让它在结构上没地方乱发挥。

## 结构长什么样

一句话：**五站一条线，站与站之间递纸；横切的事归叶子包；塔尖只分叉、搬、退。**

- **五站**：解析 → 闸门 → 执行 → 结算 → 报告。前提不齐叫「起不来」，齐了不放行才叫「拒绝」，两种失败是两种类型。
- **塔尖**（入口那个包）只做三件：分叉走哪条路、把信封交给下一站、按种类给退出码。不做业务判断。
- **三张纸、四次交接**：讲「要做什么」→ 讲「发生了什么」→ 讲「总共怎么样」。闸门那一棒不另起一张纸，它只给上一张加一格结论。
- **五种模式不聚成包**：命令、脚本、上传、下载、批改密各是各的类型，装在一个带标签的格子里，对不上由闸门验。
- **横切八个叶子包**：`console`（唯一写终端）、`log`、`ask`、`archive`、`exitcode`、凭据、`message`（唯一拼句）、`mask`（遮秘密）。再加一个独立的密钥管理包，五站谁也不许依赖它。
- **契约包只有类型与常量**，一个函数都不许有。

## 几条最容易踩的硬约束

- **交接件只装下一站要用的**；加一格是两到三处（契约定义 + 填 + 读），要回头从解析拿就是改一整条线。
- **运行上下文是原值通道**：报告要贴的「执行命令 / 执行参数」必须是使用者敲的原值，重新打包就不是原样了。所以它单立一类、不算数据格、不参与「后一张不许更宽」的计法；内容是密文，只给报告站解，别的站要什么由纸上的数据格给。
- **成败不由退出码判**：有的模式压根没有退出码。执行站只交事实（分类、退出码、超时、取消、原文），「到底是不是失败」由结算站解释。
- **结构靠一个跟着 `go test` 跑的检查拦**：写终端、依赖方向、退出动作、契约纯净、测试站位，扫得到的是红线，扫不到的是取向。
- **测试分两区**：红线区只放结构、不断言值，改它要走议题加 ADR；自定义区跟着包走。
- **切换分三档**：建站门槛（能编译、红线绿）、可切门槛（命令模式一台跑通、五模式真机跑过、逐字比对通过）、切换当天五步。切换只改脚本里那一行目录名。

## 不在本图范围

- **任何实现代码**：本图只产决策与文档。
- **新功能与缺陷修复**：重构不夹带；撞见了另开议题。
- **改行为**：老代码怎么跑，新工程就怎么跑；觉得该改的地方先记下来，建完站再单独提。
- **老工程的改名、迁仓、移走**：切换那天的事。
- **发布与版本号**：两套并存期间 `release.py` 仍只打老工程。
