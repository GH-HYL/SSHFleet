# 14: 只出一句话、不做事的东西归谁管——`-version`、帮助、放行前的提醒

**Type**：grilling
**Status**：open
**Blocked by**：无，可立即开工

## Question

**本工单管一类东西，不是一个东西**：它们不产业务数据、不阻断流程、只要求「往外出一句话」，而现在三张表都没有给它们留位置。已撞见两个：

- **不进流水线、只回一句话的请求**：`-version`。
- **进了流水线、不阻断、只在某一刻提醒一句**：主密钥没配（ADR-0034 决定六：警告后照跑）。闸门那三个出口里「放行但要跟使用者说一句」只有名字，没有载体——结论格只有「过了 / 要人点头 / 不让走」，闸门不许写屏，塔尖只认五种结局，这句提醒没有出路。

**先摆清 `-version` 这一件**。塔尖只认递回来的结局，现在一共五种：信封（进流水线）、一条小命令（交给密钥管理包）、一句要打给使用者的话（帮助之类）、起不来、拒绝。`-version` 不在这五种里的任何一种，可它明明是个要回话的请求。

两处已经定下来的话，合起来把这个口子留出来了：

- 塔尖那篇说「版本拼装归报告站，塔尖只把入口那个常量传下去」——版本这句话是**报告站**产的。
- 可版本请求**不进流水线**：进了流水线就要走执行、结算，`-version` 没有任何要对机器做的事。报告站在流水线尽头，不进流水线就到不了它门口。

于是三条路，各有代价：

1. **当「一条小命令」**——那条路的去处是密钥管理包，版本跟密钥无关，去处不对。
2. **当「一句要打给使用者的话」**——帮助走的就是这条，但帮助的文本由解析产；版本若也由解析产，就与「版本拼装归报告站」打架，版本从两个地方出。
3. **加第六种结局**——塔尖多认一种，它本来就只该认结局、不该判断；这一种与「一句话」的区别只在于**谁产这句话**，值不值得单列，是个真问题。

**再摆「放行但提醒一句」这一件**：ADR-0034 决定二给了三个出口，15 的结论格只装得下两个半；这句提醒要说给使用者听，可是能调终端的四处名单里，闸门不在其中。要么给结论格加一个值，要么让它走别的路。

要定的：

- `-version` 上面三条选哪条，或者有第四条。
- 「谁产这句话」与「谁打这句话」要不要分开看：产的一方是报告站（它会拼版本）、打的一方是塔尖（它交给终端）。若分得开，第二、三条的冲突就没那么硬。
- 帮助与版本是同一类还是两类。05 号把帮助归解析，理由是「与选项定义同源，分开就有两个来源」；版本的来源是编译期常量，那条理由对版本成不成立。
- **主密钥那句提醒**：由谁产（`message`？）、由谁打（塔尖？执行站刷屏那一处？）、要不要在闸门的结论格里加一个值。加值会动 15 那张纸，不加就得另找路。
- 版本常量住在入口、由塔尖往下传——这条要不要跟着动。

**这一条多半收不成一句判据。** 场景各不相同：有的在流水线之前（帮助、版本），有的在闸门（危险提醒、拒绝的话），有的在跑的过程里（进度、每台一行），有的在跑完之后（报告）。所以先列场景再收规则——**能收成一两条就收，收不成就按场景点名，不许硬凑一句听起来漂亮的话把四种情形糊过去。**

答案要能落到两处：`-version` 这一敲由哪一站产那句话、塔尖按哪种结局接；「放行但提醒一句」走哪条路、要不要动那张纸。

**已知边界**：本工单不碰版本号怎么定、怎么发布（那是 `tools/release/` 的事），不碰帮助文本的内容，也不碰「拒绝的话怎么出字」（ADR-0034 已定：随拒绝交回塔尖）。
