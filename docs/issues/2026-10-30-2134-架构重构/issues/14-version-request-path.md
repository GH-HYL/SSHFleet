# 14: 敲 `-version` 算哪一种结局——一种小命令、一句话，还是第六种

**Type**：grilling
**Status**：open
**Blocked by**：无，可立即开工

## Question

塔尖只认递回来的结局，现在一共五种：信封（进流水线）、一条小命令（交给密钥管理包）、一句要打给使用者的话（帮助之类）、起不来、拒绝。**`-version` 不在这五种里的任何一种**，可它明明是个要回话的请求。

两处已经定下来的话，合起来把这个口子留出来了：

- 塔尖那篇说「版本拼装归呈现站，塔尖只把入口那个常量传下去」——版本这句话是**呈现站**产的。
- 可版本请求**不进流水线**：进了流水线就要走执行、整理，`-version` 没有任何要对机器做的事。呈现站在流水线尽头，不进流水线就到不了它门口。

于是三条路，各有代价：

1. **当「一条小命令」**——那条路的去处是密钥管理包，版本跟密钥无关，去处不对。
2. **当「一句要打给使用者的话」**——帮助走的就是这条，但帮助的文本由摄入产；版本若也由摄入产，就与「版本拼装归呈现站」打架，版本从两个地方出。
3. **加第六种结局**——塔尖多认一种，它本来就只该认结局、不该判断；这一种与「一句话」的区别只在于**谁产这句话**，值不值得单列，是个真问题。

要定的：

- 上面三条选哪条，或者有第四条。
- 「谁产这句话」与「谁打这句话」要不要分开看：产的一方是呈现站（它会拼版本）、打的一方是塔尖（它交给终端）。若分得开，第二、三条的冲突就没那么硬。
- 帮助与版本是同一类还是两类。05 号把帮助归摄入，理由是「与选项定义同源，分开就有两个来源」；版本的来源是编译期常量，那条理由对版本成不成立。
- 版本常量住在入口、由塔尖往下传——这条要不要跟着动。

答案要能落成一句判据：`-version` 这一敲，产那句话的是哪一站，塔尖按哪一种结局接。

**已知边界**：本工单不碰版本号怎么定、怎么发布（那是 `tools/release/` 的事），也不碰帮助文本的内容。
