# 14: 只出一句话、不做事的东西归谁管——`-version`、帮助、放行前的提醒

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工

## Question

**本工单管一类东西，不是一个东西**：它们不产业务数据、不阻断流程、只要求「往外出一句话」，而现在三张表都没有给它们留位置。已撞见两个：

- **不进流水线、只回一句话的请求**：`-version`。
- **进了流水线、不阻断、只在某一刻提醒一句**：主密钥没配（ADR-0034 决定六：警告后照跑）。闸门那三个出口里「放行但要跟使用者说一句」只有名字，没有载体——结论格只有「过了 / 要人点头 / 不让走」，闸门不许写屏，塔尖只认五种结局，这句提醒没有出路。

**先摆清 `-version` 这一件**。塔尖只认递回来的结局，现在一共五种：信封（进流水线）、一条小命令（交给密钥管理包）、一句要打给使用者的话（帮助之类）、起不来、拒绝。`-version` 不在这五种里的任何一种，可它明明是个要回话的请求。

两处已经定下来的话，合起来把这个口子留出来了：

- 塔尖那篇说「版本拼装归报告站，塔尖只把入口那个常量传下去」——版本这句话是**报告站**产的。
- 可版本请求**不进流水线**：进了流水线就要走执行、结算，`-version` 没有任何要对机器做的事。报告站在流水线尽头，不进流水线就到不了它门口。

于是三条路，各有代价：

1. **当「一条小命令」**——那条路的去处是密钥管理包，版本跟密钥无关，去处不对。
2. **当「一句要打给使用者的话」**——帮助走的就是这条，但帮助的文本由解析产；版本若也由解析产，就与「版本拼装归报告站」打架，版本从两个地方出。
3. **加第六种结局**——塔尖多认一种，它本来就只该认结局、不该判断；这一种与「一句话」的区别只在于**谁产这句话**，值不值得单列，是个真问题。

**再摆「放行但提醒一句」这一件**：ADR-0034 决定二给了三个出口，15 的结论格只装得下两个半；这句提醒要说给使用者听，可是能调终端的四处名单里，闸门不在其中。要么给结论格加一个值，要么让它走别的路。

要定的：

- `-version` 上面三条选哪条，或者有第四条。
- 「谁产这句话」与「谁打这句话」要不要分开看：产的一方是报告站（它会拼版本）、打的一方是塔尖（它交给终端）。若分得开，第二、三条的冲突就没那么硬。
- 帮助与版本是同一类还是两类。05 号把帮助归解析，理由是「与选项定义同源，分开就有两个来源」；版本的来源是编译期常量，那条理由对版本成不成立。
- **主密钥那句提醒**：由谁产（`message`？）、由谁打（塔尖？执行站刷屏那一处？）、要不要在闸门的结论格里加一个值。加值会动 15 那张纸，不加就得另找路。
- 版本常量住在入口、由塔尖往下传——这条要不要跟着动。

**这一条多半收不成一句判据。** 场景各不相同：有的在流水线之前（帮助、版本），有的在闸门（危险提醒、拒绝的话），有的在跑的过程里（进度、每台一行），有的在跑完之后（报告）。所以先列场景再收规则——**能收成一两条就收，收不成就按场景点名，不许硬凑一句听起来漂亮的话把四种情形糊过去。**

答案要能落到两处：`-version` 这一敲由哪一站产那句话、塔尖按哪种结局接；「放行但提醒一句」走哪条路、要不要动那张纸。

**已知边界**：本工单不碰版本号怎么定、怎么发布（那是 `tools/release/` 的事），不碰帮助文本的内容，也不碰「拒绝的话怎么出字」（ADR-0034 已定：随拒绝交回塔尖）。

## Answer

**依据**：开发者 2026-11-01「那个 `-version` 其实我感觉不用加，我的 help 信息里有版本信息。我的 help 可以通过 `-h` 触发，也可以直接输入命令、不输入任何参数选项也能输出我的信息」；「密钥的这三个命令……我想给它单独提炼个包，直接纵切……它独立于那 5 个模式」。

### 一、`-version` 不做

**老工程没有这个选项**——选项表里没有它，短的长的都没有。版本只在帮助那一屏的首行下方出现一次，帮助有两个触发口：`-h`，以及一个参数都不给。

要做就是新增功能，而这次重构不夹带。所以「版本请求进不进流水线」这个问题不存在，塔尖不用加第六种结局。

### 二、版本拼装归解析站（纠正 05）

05 说「版本拼装归报告站」，但**报告的产出里一个版本字都没有**，版本只在帮助里出现。所以版本和帮助同源，都归解析站拼；塔尖仍旧只把那一个常量传下去，不拼。

### 三、一句话分三步，不是归一个包

一句话要变成屏幕上的字，中间有三个动作，各归各处：

- **产事实**：谁懂这份材料谁给——有哪些选项、版本是多少（解析站），哪一条没过（出判断的那一处），主密钥齐不齐（凭据包）。
- **拼句子**：只有 `message`。它是唯一拼句处，别的包连句子都造不出来。
- **打屏**：只有四处——塔尖、执行站刷屏那一处、`ask`、报告站。

判据：**不属于任何一站的话，只有「打」这一步归塔尖**；内容仍归懂它的站，句子仍归 `message`。

所以「帮助归解析」与「帮助由塔尖打」不矛盾：解析给内容，`message` 拼句，塔尖打。**帮助仍走解析递回的那一种结局（「一句要打给使用者的话」），版本随帮助一起出，不另设结局**——这就是「`-version` 这一敲由哪一站产、塔尖按哪种结局接」的答案：产在解析（版本与帮助同源），接在那种结局上。

**塔尖的话有四类，不是三件活。** 打屏本来就只有一处，帮助、拒绝、起不来、开工前那句提醒都从那儿出；塔尖做的仍是分叉、搬、退，只是「递出去之前顺手把手上那句话交出去」。

### 四、主密钥那句提醒：塔尖的第三类话

它服务的是批处理那条路（加密开着就得用主密钥），跟三条密钥命令不是一回事。**位置在闸门之前**——现在它就在参数合规检查与确认屏之前打，打的是警告、然后照跑。

所以**打由塔尖**：**事实由凭据包给**（它说「不齐」就是不齐，不判断该不该说），**`message` 拼成句**，**塔尖交给终端**。塔尖一个字的句子都不拼。

**问的时机**：解析已经递回信封、塔尖分完叉、选了流水线那条、信封递给闸门之前问一句。**塔尖不许自己去看配置、看文件在不在**（ADR-0032 五）——它只问凭据包要一个状态，不自己判。

由此，04 那张摊派表里「查主密钥在不在」不归解析，归塔尖这一问——解析不碰凭据。

塔尖手上一共四类话：帮助（含版本那一行）、拒绝、起不来、开工前那句提醒。

### 五、闸门回到两个出口：放行 / 拒绝

「放行但要说一句」这个出口，**唯一想塞进去的用例不成立**——主密钥提醒根本走不到闸门。危险命令只有两档：禁止（直接退）、警告（摆出来问人，走 `ask`），没有「警告但不问、照跑」。

把它挪进闸门也不成：那会改行为（参数写错时不再先看到那条警告，顺序变了）。按「不动行为」优先，只剩一条路——**删掉这个出口**。

代价：以后真冒出「警告但不问、照跑」的档，得回头加。等事实出现再加，现在留着就是塔尖认一个永远不来的结果。

**15 号那张纸不动。** 结论格本来就只装两个半（过了 / 要人点头 / 不让走），删掉一个出口不改这三个值——那句话从来不是结论格里的值，它是要往外说的话。所以 15 的答案不用跟着改。

这一段改 ADR-0034 决定二，按规范四.3 追加更新记录。

### 六、密钥管理包：与五站并列的第二条路

三条密钥命令（生成主密钥、看状态、转凭据）独立成包，**不受五站那套约束**：不切解析/闸门/执行/结算/报告，不造交接件，不过闸门。

**但约束不是没有，是换了两条**：

- **只许往下依赖**：契约、横切包、凭据包。
- **五站谁也不许 import 它**，它也不许 import 任何一站。两条路并列，塔尖在分叉点上看一眼选一条。

这样它出问题波及不到流水线；流水线也不会偷偷长出一条「顺手把密钥生成了」的分支。07 的依赖检查加这一条。

**「这次是那三条里的哪一条」仍由解析站认出来**（ADR-0036 决定三）——解析是唯一读命令行的地方，塔尖只按解析递回来的结果分叉，不自己看参数。三条命令跑完各自把结论交回塔尖：正常结束就正常退，起不来就走「起不来」那条，退出码仍由塔尖从表里换，不另造一种结局。

**它在测试那边也归一种口子**：08 的红线区许站三种口子，密钥包按「站的入口」那种测——递一条命令、收一个结论，不按横切包那种测。

### 七、四种场景各有站主，本条只收没主的

题干要求「先列场景再收规则」，四种场景分别是：

- **流水线之前**（帮助、版本）：解析给内容，`message` 拼，塔尖打。
- **闸门**（危险提醒、拒绝的话）：闸门下判断，话随结论交回塔尖打；要问人的走 `ask`。
- **跑的过程里**（进度、每台一行）：执行站自己刷屏，不经过塔尖。
- **跑完之后**（屏幕统计、报告、两张表格）：报告站出。

前两处的「打」都在塔尖、后两处各在自己站——**打屏四处就是这么来的**。本工单真正新增的判断只有一处：**没有站主的那些话，打由塔尖**。落到具体就是 `-version` 与主密钥提醒这两件。

### 八、这条不覆盖什么

- 三条密钥命令在包里怎么分文件——ADR-0036 已定「哪一条由解析认出来、独立成包」，包内怎么拆留给动工时的工单。
- 版本号怎么定、怎么发布——`tools/release/` 的事。
- 帮助文本的内容——不碰。
