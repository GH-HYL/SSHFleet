# 03: 站与站之间那份交接件怎么定——宽结构一份，还是每种模式各一份

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工

## Question

作者已把规则定死：阶段之间传**新造的交接结构体**，不许传上一站的原结构体；下站缺字段就去上游纵切加，不许跨阶段回取。这条不占工单，工单要定的是**那份交接件的形状**。

教学骨架在 `modules/SSHFleet_Go_bak/internal/contract/` 里做了一次尝试，并标了「这个决定留给你」：`contract.Body` 用了**宽结构**——五种模式的字段全塞在一格里，靠 `Mode` 决定看哪几格。代价是会存在「上传模式下 `Command` 却有值」这种非法状态。防它得改成接口加五个实现，那执行站的入口就变成一堆类型断言。

要定的：

1. 交接件用宽结构还是窄结构（接口 + 每种模式一个实现）？判据是「非法状态能不能被编译期挡住」值不值那堆类型断言。
2. 契约包 `contract` 里能放什么——骨架的硬规矩是只许类型和常量、一个函数不许有。这条要不要破例（比如允许一个校验函数）？
3. 整理站要用的判据表（老工程里是配置的一部分），由摄入站读进来后单独递给整理站（骨架 `main.go` 第 99 行就是这么干的）。这算不算塔尖「干了活」？若不算，判据的传递怎么才算合规？

答案要能落成一句判据：新增一种执行模式时，交接件要改几处、会不会产生非法状态。

## Answer

**判据一句话**：信封按「棒」定、不按模式定；新增一种模式只动两类落点——契约那一格多一种装法、五个站各加一块（合计六处，与 02 号一致）。信封本身不改。会产生一种非法状态（纸上写的模式与载荷对不上），只在闸门验一次。

**信封只有一份，随站换三次口径**：摄入交闸门、闸门交执行用同一张（闸门不改数据，原样递，只加结论）；执行交整理换口径讲「发生了什么」，按模式分五份；整理交呈现再换口径讲「总共怎么样」。「三张」按口径数，不是三套结构。

**载荷一格、装五种**：信封上是**一个格子**，里面按标签装五种内容之一（命令原文 / 脚本内容 / 上传的本地路径 / 下载的远端路径 / 改密的提示词），各是各的类型、不合并。命令与脚本、上传与下载共用的段落各写一遍——现在没有事实支持合并，是预判；以后真出现「改了一处不得不改另一处」再合。作者认下这笔重复。

**新造的那份必须比上一份窄**：除本棒自己产出的结论（放行、归类、统计）外，其余格子必须来自上一棒且不得多出来。两张纸一样宽 = 这一棒没过滤任何东西，不该造两次，直接递上一份。这条主要给闸门立——它不许加结论以外的格子。**它只管同一口径的两棒**（摄入交闸门、闸门交执行）；换口径那两棒不受管，改由「只装下一站要用的」约束。

**判据表跟着走，不是只放到第一张就不管**：后面换口径时，下一站还用它就跟着带（整理侧要看分类规则），不用就不带。

**执行与整理的界线**：只依赖一台的整理放在执行里；要依赖全体才能算的，等跑完再算。归类只依赖「这一台的输出 + 判据表」，所以留在执行；执行交整理那张纸装的是「一台的结论」（原文、退出码、归类），不是原始返回。**判据表里没有的那一条，不造「未分类」这个类别**——归类就取远端原话本身，老工程已经这么处理。

**判据表进第一张纸**：执行侧要认「密码过期」这类提示，整理侧要看分类规则，而它只能由摄入站读一次。塔尖单独递等于塔尖在编排，会长肉。**流水线外的密钥管理不受这条管**——它不进五站，自己读自己那一小块配置。

**契约不放函数**：信封合法性（模式与载荷对不上）归闸门验。破例放校验函数，就是给抽屉开第一道门。

**核对补记（02 落定后）**：整理交呈现那张纸虽然是一张，但**必须带模式标签**——呈现站要按模式写不同报告（命令贴输出、传输列文件、改密列出哪台要人工）。不带标签，它就认不出该写哪种。塔尖那个「流水线 / 小命令」的分叉不算「装东西」，见 ADR-0036。

**依据**：`docs/adr/0035-交接件按棒定形状.md`；载荷怎么摆在代码里落地、模式怎么分文件，见 `docs/adr/0036-五种模式不聚成包.md`（02 号）。

**留给别处**：

- **五份载荷在代码里怎么摆**——已由 02 号定下：一个带标签的格子 + 五份类型，标签决定看哪格。
- **「更窄」由谁验、什么时候验**——不落到 07 就等于没写，归 07。
