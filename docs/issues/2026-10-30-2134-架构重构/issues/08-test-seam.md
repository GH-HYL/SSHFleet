# 08: 测试接缝定在哪儿——五站之间测，还是只测塔尖这一头

**Type**：grilling
**Status**：open
**Blocked by**：01, 03

## Question

《个人开发规范》三.3 写死：「测试只写在预先说定的接缝上。接缝＝从外面调用就能观察到的那个口子。动手前先把『这回测哪个口子』跟开发者说定，没说定不写测试。」还有一条反向判据：**重构后行为没变、测试却红了——那说明测错了地方**。

这次重构天生是「行为不变、结构全变」，所以接缝选错，测试会集体变红，然后被当成噪音删掉——那等于没有测试。

老工程现有 51 个测试文件散在 12 个包里（`ssh` 15、`output` 7、`common` 7、`cli` 5、`dangercheck` 4、`credential` 4、`verdict` 3、`config` 2、`result` / `nodelist` / `confirm` / `batch` 各 1；`log` 包没有测试），全是包内测试。

要定的：

1. 接缝取在哪儿——**进程出入口**（起一个二进制、喂 argv、看 stdout 与落盘产出）？还是**五站之间的函数调用**（每站入口一个）？还是两者都要，各管一段。
2. 若取进程出入口，覆盖面够不够挡得住 07 说的「自己单写一套」——那种违规不改变外部行为，测不出来。
3. 老工程那批包内测试怎么处理：搬过来、重写、还是丢弃只留行为级。
4. 这次重构的验收要不要先建一套「重构前后输出逐字比对」（老工程 ADR-0013 做过一次：两个二进制、同一份配置与清单，归一化后逐字比对 stdout 与六项归档产出）。这套做法要不要成为本次的默认验收。

答案要能落成一句判据：新工程的测试该长在哪个口子上，以及重构期间怎么判断「行为真的没变」。
