# 08: 测试接缝定在哪儿——五站之间测，还是只测塔尖这一头

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工（01、03 已解）

## Question

《个人开发规范》三.3 写死：「测试只写在预先说定的接缝上。接缝＝从外面调用就能观察到的那个口子。动手前先把『这回测哪个口子』跟开发者说定，没说定不写测试。」还有一条反向判据：**重构后行为没变、测试却红了——那说明测错了地方**。

这次重构天生是「行为不变、结构全变」，所以接缝选错，测试会集体变红，然后被当成噪音删掉——那等于没有测试。

老工程现有 51 个测试文件散在 12 个包里（`ssh` 15、`output` 7、`common` 7、`cli` 5、`dangercheck` 4、`credential` 4、`verdict` 3、`config` 2、`result` / `nodelist` / `confirm` / `batch` 各 1；`log` 包没有测试），全是包内测试。

要定的：

1. 接缝取在哪儿——**进程出入口**（起一个二进制、喂 argv、看 stdout 与落盘产出）？还是**五站之间的函数调用**（每站入口一个）？还是两者都要，各管一段。
2. 若取进程出入口，覆盖面够不够挡得住 07 说的「自己单写一套」——那种违规不改变外部行为，测不出来。
3. 老工程那批包内测试怎么处理：搬过来、重写、还是丢弃只留行为级。
4. 这次重构的验收要不要先建一套「重构前后输出逐字比对」（老工程 ADR-0013 做过一次：两个二进制、同一份配置与清单，归一化后逐字比对 stdout 与六项归档产出）。这套做法要不要成为本次的默认验收。

答案要能落成一句判据：新工程的测试该长在哪个口子上，以及重构期间怎么判断「行为真的没变」。

## Answer

### 一、判据一句话：分红线区与自定义区

**一条测试红了，先问一句：是「结构被人动了」，是「需求变了」，还是「环境没起来」。** 前两者进两区；第三者两区都不进，也不许按需求变更归档。

**第三桶是测试层的桶，不是程序的失败类型。** 它指「跑测试的那台机器/那套环境」没起来——容器没开、网络不通、超时抖动。程序自己遇到远端连不上，那仍按 ADR-0034 算一台的连接失败、算执行结果，与本桶无关。本桶的处置只有一条：**能修就修；修不掉，说明这条测试本来就不该要机器。** 进程级红线测试一律打标，无机器时按 `-short` 跳过，跳过不算绿也不算红。

分两区而不是定一个接缝，是因为两件事的目标相反：红线要**熬得住重构**（结构随便动它不许动），自定义要**跟得上需求**（改一次就得改它）。钉在同一个口子上，必然有一头坏死——要么红线被需求拖着改，要么自定义测试把结构钉死。

作者 2026-11-01 的判断：老工程那 413 个测试「日积月累……现在看来不一定对，也不一定具有长期存在的价值」；而「每一次改动都要搞一次测试，因为测试成本最低」是必然的，不该管。

### 二、红线区：只放结构，一条行为断言都不放

**装什么：** 只收机械判得出来的结构约束。今天装得下的是 07 那五类（写终端、依赖方向、退出动作、契约纯净、失败类型的构造点），加上「测试站在哪儿」这一类。

**断言什么：** 只断言**纸的形状与流向**——字段在不在、谁填的、下一站读不读得到、能不能编译通过；**不断言值算得对不对**（总数对不对、分类对不对）。值归自定义区，理由见下。

**不装什么：** 任何「跑起来对不对」的断言。红线一旦混进行为，改一个小需求就得改红线，几次之后它就成了谁都能动的普通测试。**红线越纯，越不用动。**

**站哪儿：** 新工程里单独一个包，与 07 那个结构检查同住，不塞进任何一站——它要把全工程摊开数，住进某一站就破了那一站的单向。

**只许站三种口子：**

| 口子 | 怎么测 |
| --- | --- |
| 塔尖的进程出入口 | 起一个二进制、喂参数、看屏幕输出与落盘产出（**唯一允许看内容的地方**，也只有它归 A/B） |
| 站的入口 | 递一张纸进去，看它收下的动作、交出的那张纸的**形状与流向**；站内怎么拆文件都不动它 |
| 横切包的那一件事 | 叶子包只有一件事，公开面就是它的口子。测它时 import 的就是那个叶子包 |

**判据：第六类，两半，都按文件讲。**

- **import 白名单**：一个红线测试文件只许 import 标准库、契约包，以及**被它钉的那一个包**——站包或横切包，二选一。import 第二个被测包、或者 import 任何两区共用的假件包，即报。
- **出口白名单**：每个站包只许导出**一个函数加一个类型**（见第七条），多一个即报。

**红线测试不享 `_test.go` 的依赖方向豁免。** 07 给 `_test.go` 开豁免，本意是让检查自己能把全工程摊开；这条顺带盖住了所有红线测试，等于红线区成了全工程唯一不被依赖检查看的代码——有人在里面按序调五站，就是一个第二个 `main`，还全绿。所以豁免只管「写终端」一条，依赖方向照样查。

> 原判据「测试里出现被测包的私有符号即报」**作废**：红线区住单独包，跨包引私有符号本来就编译不过，这条从第一天起报不出任何东西；而真正的越界方向是反的——为了让红线够得着，把站里的内部函数导出。

**改它怎么管：** 等同改约束类文件，而且比它更重——默认不能改；确需改，先单开议题、再写 ADR，写明是哪个条件变了（工程设计变了，还是代码复杂度变了），两样齐了才动手。只问一句「能不能改」不算。已写进《个人开发规范》一.1 第七条与三.3。

**留痕：** 红线名单与每条的指纹同住一处；对不上 `go test` 直接红。**指纹钉两样，不钉字节**：测试名，加这条测试**直接**引用到的生产符号集合——经测试文件内的 helper 间接引用的不算（否则 helper 一动一片红），`gofmt`、改注释、重排语句也都不算。**新增一条不算改；删掉、改名、缩窄引用面算改**，要走议题。

### 三、自定义区：跟着被测包走，怎么顺手怎么写

包内测试，伸进内部也行、mock 自己也行，只一条硬规矩：**不许与红线区共用假件包**——红线区自己要用的假连接、假时钟放在红线区自己的目录里，各写一遍，认这笔重复。两区共用一个假件包，改一条自定义测试就能把红线带红，那正是这条要防的。

> 原话「不许被红线区引用」**作废**：Go 里 `_test.go` 不能被 import，这条永远无法违反，等于没写。

它真正的价值不是「测得好」，是**把代价挪开**：它烂到底的结果是「改坏了自己那一轮不知道」，这个账落在返工上，不落在框架上。

老工程 51 个文件、413 个测试、11688 行**不搬**。重写时按被测对象找口子，不按「纯算的一律进横切包」一刀切：显示宽度怎么截、秘密怎么认归横切包的公开面；**危险规则归闸门站**（04 的摊法），测试站闸门的入口。伸进包里的那些搬不过去，硬搬等于把老的分包边界一起搬进来。

### 四、进程出入口挡不住「自己单写一套」

**挡不住，也不该它管。** 那类违规不改外部行为，怎么起程序都看不出来。它归 07 那个结构检查——但**07 只数形状**（依赖方向、契约纯净、构造点、导出面），「绕过站自己另写一套业务」它照样数不出来，那一层归规格审计与人读。两处都不接的部分，就认。

### 五、A/B 逐字比对不进两区，它是切换那天的一次验收

两个二进制、同一份配置与清单，归一化后逐字比 stdout 与六项归档产出（ADR-0013 做过一次，五条模式路径全一致）。

它不常驻，理由：慢、要机器、且**归一化本身会掩盖一类变化**——ADR-0018 已经吃过这个亏（把时间数值抹掉，漂移就看不见了）。所以**归一套规则先落在这里，跑由 09 发起**：

1. **抹掉什么**：时间数值（起止、耗时）、本次运行目录的绝对路径、二进制自身的路径、远端 tty 回显那几行的重复次数。逐条写在清单里，抹一条登记一条。
2. **比哪几份**：stdout 全文，加六项落盘产出（`report.txt`、`terminal-output.txt`、`SSHFleetExec.log`、两张表格的文本、脱敏副本）。
3. **留一条哨兵**：帮助、版本、参数错这三条路径**不归一化也应当逐字一致**——它们不碰机器、不带时间，任何漂移都说明真的变了。

**中段是认下的空白，写在明处。** 从建站第一行代码到新工程能整条跑起来之前，**没有任何东西能证明行为没变**：红线区不管行为，自定义区是跟着新代码长出来的，A/B 没东西可比。这段只能靠「一站一站照老代码摊、摊完读一遍」——它是这次重构的已知盲区，不是谁漏了。09 拿到可跑的二进制就把 A/B 补上。

### 六、这套盖不住什么（先说清楚）

- **站内攒抽屉、塔尖塞逻辑、跨半步拼接**：数不出来。07 五类扫不到，红线区也测不到，规格审计看见一半，剩下靠人读。作者 2026-11-01：「即使上了这三种也盖不住，但咱们也要奔着能约束住的方向。」
- **自定义区的质量**：不管。一个测试写歪了不影响业务，这是作者明示不管的那一档。
- **四层里没有一层管得住站内**：最硬的是「够不着」（类型收口，编译期就过不去），其次 `go test` 直接红，再次规格审计（事前看纸面），最软是人读。红线区站的是第二层。这四层是本条与 ADR-0037 一并定的排序，不是别处的引用。
- **这套东西对「行为没变」几乎没有贡献**。行为对不对只有 A/B 与自定义区管；红线区管的是「结构不许变样」。别指望它顺手把行为钉住。

### 七、站包的出口白名单（2026-11-01 定：走 A）

**每站只许导出「一个函数 + 一个类型」：入口函数，和替身插口的类型。** 替身插口是入口函数的一个参数，字段只许是函数；纸的类型在契约包，不算站的导出。其余名字一个都不许多，多了就红——这是第六类的第二半。

**出口仍然只有一个。** 15 说「执行站对外只有一个口子」，这里不冲突：替身插口是**往里递**的东西（测试塞假连接、假时钟），不是往外给的东西；往外交的只有入口函数返回的那张纸。

**一个例外，由本条规定：ADR-0034 要塔尖认出「拒绝」，所以闸门包必须导出拒绝的类型。** 白名单里点名放行它，其余站不适用。

**为什么非要白名单**：一个入口保证「只从正门进」；一个替身插口保证测试能造假（假连接、假时钟、假终端），否则红线测试只能要真机器，一要机器就落进「环境没起来」那一桶。两条是同一个洞的两面。

**代价**：站内想给别处一点只读信息（比如解析站把选项清单交给帮助文本），得从入口递出去或塞进纸里，绕一条线；每加一个导出名都要走审批，容易演成「先加上再说」。这两条认下。

**为什么否掉 B（只钉替身插口、导出面不管）**：那样「一个口子」仍然只是纸上的一句话，AI 想加第二个入口随时能加，第六类抓不到——正是这次重构要消灭的那类「纪律上不该做」。

### 站包的出口白名单：两条路

**A. 钉死出口，加白名单检查。** 每站只许导出「入口函数 + 一个注入结构体（字段只许是函数）」，其余名字一个都不许多，多了就红；纸的类型本来就在契约包，不算站的导出。

- 拿到：「一个口子」从散文变成结构，AI 想加第二个入口当场红；测试造假只有注入结构体一个地方，第 2 条那个洞一并堵上。
- 代价：站内想给别处一个只读查询（比如解析站把选项清单交给帮助文本），就得塞进入口参数或纸里，绕一条线；每加一个导出名都得走审批，容易演成「先加上再说」。

**B. 只钉注入结构体，不钉导出面。** 每站收一个只许有函数字段的注入结构体，测试靠它造假；导出几个名字不管。

- 拿到：不碰 04、15 的地盘，建站成本低，测试也能造假了。
- 代价：「一个口子」仍是散文，AI 想加第二个入口随时能加，第六类抓不到——这正是这次重构要否掉的那种「纪律上不该做」。

**执行者倾向 A**，理由：这次重构的全部价值是「不该做的变成做不到」，B 属于 ADR-0032 开头否掉老工程的那个理由本身。
