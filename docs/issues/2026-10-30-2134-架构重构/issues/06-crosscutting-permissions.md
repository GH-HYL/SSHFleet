# 06: 五个横切包里谁能写终端、谁能写盘——权限表怎么定

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工

## Question

骨架定了五个横切包分开：`console`（终端输出，唯一有写终端权的地方）、`log`（运行日志）、`ask`（问人）、`archive`（本次运行的落盘根，只发路径字符串）、`exitcode`（error → 退出码）。

这些「谁能干什么」的话散在骨架注释里，还没成文，也没判据。要定的：

1. **写终端的权力**：`console` 是唯一出口——这条要不要硬到「其余包一律不许 `fmt.Print`」？若硬，怎么核（靠人读还是靠 lint）。
2. **写盘的权力**：`archive` 只发路径字符串、不返回目录句柄（骨架的理由是句柄是可变共享物）。那真正的文件写入归谁——`present`？还是每个站自己写？
3. **谁可以 import 谁**：骨架说这五个是「叶子包，只依赖标准库，谁都能 import，不会成环」。但 `ask` 要借 `console` 出字，严格说它不纯（`ask.go` 全文没有 import 任何内部包，追问与出字的分工还没在骨架里落下来）。这条依赖方向要不要画出来、写进结构定义。
4. **`exitcode` 的边界**：骨架写「不提供 Exit」——只做 error → 码的换算，退出动作归塔尖。这条与 05 联动。

答案要能落成一张权限表：每个横切包能调什么、不能被谁调。

## Answer

完整权限表写在 `docs/adr/0032-按五站分层重构工程结构.md` 第四条。四问的答案：

**一、写终端：硬，而且靠一个跟着 `go test` 跑的检查核。** `console` 是唯一出口；其余包一律不许自己打印、不许直接写标准输出与错误。核法不是人读——07 定的那个结构检查扫到 `console` 之外往终端写字就报（`_test.go` 除外，见 07 号工单）。

**二、写盘：谁产内容谁写，路径只能从 `archive` 拿。** 日志归 `log`，报告与 xlsx 归呈现站，目录本身归 `archive`。**`archive` 不代写**——代写就得懂所有格式，那正好长成抽屉。它只发路径字符串、不返回目录句柄，理由照骨架：句柄是可变共享物。

**三、依赖方向：画出来，只留一条叶子之间的边。** 六个横切包只依赖标准库与契约；`archive` 只依赖标准库（它只发路径，用不到契约）。唯一例外是 `ask` 可以依赖 `console`——「问人」本质是「出字 + 收字」，强行拆成两次调用，每个调用方都得自己写次序。其余横切包之间不许互相依赖，横切包不许依赖站。核法：扫依赖清单。

**四、`exitcode` 只认「种类」，不认错误类型。** 「认这是拒绝、那是起不来」要认识闸门里的拒绝类型，`exitcode` 一认就得依赖站，叶子就破了。所以由塔尖认（它本来就依赖站），认完把种类交过去查表——退出码的规则仍然只有一处。

**种类的清单**（就这五种，加一种要改这里）：成功、使用者用错、起不来、被取消、执行有失败。

**「拒绝」不是第五种之外的一种码，它按「谁的错」落位**：参数不合规、危险命令 → 使用者用错；人当场喊停 → 被取消；判据表不全、配置缺失这类 → 起不来（见 01 号工单的分界：前提缺一样就是起不来）。**语法错（不认识的选项、缺值）由摄入发现、闸门下结论，也给「使用者用错」**——码认的是谁的错，不是哪一站发现的。退出码认的是谁的错，不是哪一站拒的。

**留档与刷屏的归属**：塔尖拒绝时**把话交给终端输出包打给使用者**，另在日志包「记一笔」留档——日志不能代替那句话说给使用者。执行过程中每台刷一行由执行站直接交给终端输出包，**不经过塔尖**——塔尖只做三件，不接旁路。**因此调终端的地方只有两处：塔尖、执行站刷屏那一处**；检查的白名单按文件列，就这两个。

**与环境的关系（联动 05）**：塔尖只调 `exitcode` 换码、自己执行退出；`exitcode` 不提供 Exit。

**第六个包（凭据）**：只干「读主密钥、解密」；不碰业务，不判断该不该跑。

**依据**：ADR-0032 第四条（本次补写，含权限表）；退出动作与塔尖的边界见 ADR-0032 第五条与 05 号工单。
