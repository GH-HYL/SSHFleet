# 06: 五个横切包里谁能写终端、谁能写盘——权限表怎么定

**Type**：grilling
**Status**：open
**Blocked by**：无，可立即开工

## Question

骨架定了五个横切包分开：`console`（终端输出，唯一有写终端权的地方）、`log`（运行日志）、`ask`（问人）、`archive`（本次运行的落盘根，只发路径字符串）、`exitcode`（error → 退出码）。

这些「谁能干什么」的话散在骨架注释里，还没成文，也没判据。要定的：

1. **写终端的权力**：`console` 是唯一出口——这条要不要硬到「其余包一律不许 `fmt.Print`」？若硬，怎么核（靠人读还是靠 lint）。
2. **写盘的权力**：`archive` 只发路径字符串、不返回目录句柄（骨架的理由是句柄是可变共享物）。那真正的文件写入归谁——`present`？还是每个站自己写？
3. **谁可以 import 谁**：骨架说这五个是「叶子包，只依赖标准库，谁都能 import，不会成环」。但 `ask` 要借 `console` 出字，严格说它不纯（`ask.go` 全文没有 import 任何内部包，追问与出字的分工还没在骨架里落下来）。这条依赖方向要不要画出来、写进结构定义。
4. **`exitcode` 的边界**：骨架写「不提供 Exit」——只做 error → 码的换算，退出动作归塔尖。这条与 05 联动。

答案要能落成一张权限表：每个横切包能调什么、不能被谁调。
