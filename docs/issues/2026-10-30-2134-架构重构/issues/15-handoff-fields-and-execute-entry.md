# 15: 执行站对外露几个口子、四次交接各装哪些格子

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工

## Question

五站定名之后（解析 → 闸门 → 执行 → 结算 → 报告），三张纸的内容还只有口径、没有格子（交接有四次，闸门那一棒是同一张纸加一格结论）。这张工单把它们一次摊开，同时回答作者 2026-11-01 问的那句：**交接件以后加一格贵不贵。**

要定的：

1. **执行站对外露几个口子。** 塔尖把信封交给执行站，执行站交回什么；它在跑的过程中要往外递的（进度事件、每台结果）走哪条路，和「交回结算」的那张纸是不是同一条。
2. **四次交接各装哪些格子。** 解析交闸门讲「要做什么」、闸门交执行只加结论、执行交结算讲「发生了什么」（按模式五份）、结算交报告讲「总共怎么样」。逐格列出来，一格格对老代码能对上。
3. **结算交报告那张纸，怎么把五种模式的结果合成一份。** 命令、脚本、上传、下载、改密的结果形态不同，报告站要按模式写不同东西；这张纸是带模式标签的五份，还是合成一份带标签的总账。
4. **加一格的代价写清楚。** 作者问的是「以后好不好改」：加一格要动哪几处、哪几处必须一起改、哪一处改不动。答案要能落成一句话，写进 ADR-0035 的《代价》。

**约束**（已经在别处定死的，不要再翻）：

- 同一口径往下传时，后一张除本棒结论外不许比上一张多一格（ADR-0035 决定三）。
- 换口径那两棒只装下一站要用的，用不上的不许带（同条）。
- 归到一台的归类留在执行里，要全体才能算的等跑完再算（ADR-0035 决定四）。
- 判据表进第一张纸，塔尖不单独递（ADR-0035 决定五）。
- 契约包只放类型与常量，函数与方法一律没有。

**别在这里重开的口子**：五站叫什么（04 已定）、报告站只管跑完之后（04 已定）、危险警告怎么出字（ADR-0032 第四条已补）。

## Answer

### 一、执行站对外只有一个口子

塔尖交进来：闸门加过结论的那张纸。交回去：一张「发生了什么」的纸（第三节），或者「起不来」。跑的过程中要上屏的（进度、每台一行）**不经过塔尖**，由执行站直接交给终端输出包。

理由：执行站对上要回答的只有「跑完了没有、跑成了什么」。中途细节只给人看，不参与后面的判断，不许它顺便长成第二个出口。

### 二、三张纸的格子（交接四次）

**纸按口径数：三张。** 交接有四次——解析交闸门、闸门交执行、执行交结算、结算交报告；其中**闸门那一棒不另起一张纸**，它是第一张纸加一格结论往下递（ADR-0035 决定一）。

**第一张：解析交闸门**（讲「要做什么」）

| 格子 | 谁填 | 后面谁读 |
| --- | --- | --- |
| 这次干什么：模式 + 载荷（五份带标签，不合并；各模式参数、代填明细在这儿） | 解析 | 闸门、执行 |
| 对谁做：节点清单（IP、端口、用户、凭据） | 解析 | 闸门、执行 |
| 执行参数：并发、超时 | 解析 | 执行 |
| 判据表 | 解析 | 执行、结算、报告 |
| 执行资源：脚本文件、代填文件、清单文件的路径 | 解析 | 执行（拿去跑）、报告（收尾备份原料时用） |
| 运行上下文：执行命令、执行参数、备注——**密文** | 解析封 | 只有报告站解得开；其余站收下、原样传 |
| 解析时发现的问题（只列事实，不下结论） | 解析 | 闸门 |

**闸门交执行**：上面全部 + 一格结论（过了 / 要人点头 / 不让走）。加结论，不加数据。

**第二张：执行交结算**（讲「发生了什么」）

| 格子 | 内容 |
| --- | --- |
| 通用格（每台一行） | IP、连接成败、连接耗时、执行耗时、分类、退出码、超时、取消、错误原文、原文 |
| 附加格（一个，带标签，五种模式各装各的） | 标签是五种模式之一；按标签装对应那一份类型——命令与脚本：输出的解读；上传下载：文件数、字节数、目标；改密：每台走到哪一步、哪台要人工 |
| 全局格 | 总台数、开始与结束时间、是否中断（这三样是**事实**：总台数来自计划，时间与中断来自执行；「汇总」只由结算算，两者别混） |
| 随行件 | 判据表；运行上下文（密文，只许报告站解，其余站收下原样传） |

**「成败」不在这张纸上**：它由结算站解释——把每台的分类对回本模式的成功分类，才算得出成功几台、失败几台。每种模式的成功分类名不同，有的模式压根没有退出码（连接没建起来、上传下载失败），所以「是不是失败」不能由执行站拿退出码去猜。执行站交的是事实：分类、退出码、超时、取消、原文。

**中途按停怎么记**：每台那一行带两个事实标志——**超时**、**取消**，老代码里本来就有这俩（执行、代填、传输四条通道同一个口径），报告据此写「未执行：N（执行被中断）」；分类仍由判据表认领。压根没开跑的不造行，只在总数里以缺额出现，全局格记一笔「是否中断」。

**第三张：结算交报告**（讲「总共怎么样」）

| 格子 | 内容 |
| --- | --- |
| 总账 | 总台数、跑完台数、没跑台数、是否中断、跑没跑齐的结论、成功与失败台数、连接成败台数、各分类多少台（带退出码）、每类下面的 IP 清单、成功分类名、全局起止与总耗时 |
| 逐台明细 | 表格要用；原文跟着走，报告要贴 |
| 附加格 | 原样传来，结算没打开过 |
| 随行件 | 判据表（报告要贴提示语）；运行上下文（密文，报告解开，写第一段「执行命令 / 执行参数」） |

**随行件是第二类格子，不是例外。** 它存在，是因为两条规矩打架：站与站之间的交接件必须新造、只装下一站要用的（「最窄」）；可报告第一段要的「执行命令 / 执行参数」必须是使用者敲的**原值**，重新打包一遍就不叫原值了。原值若一路直传，中间站就成了「拿到了、不用、也不处理，原样转手」——正是「最窄」要禁的样子。所以不叫哪条让步，而是**单立一类**：运行上下文（run metadata）不算数据格，不参与「后一张比前一张宽」的计法。解析站放进去，一路原样传，**只有报告站打开**。**别的站不许用**：它只服务 `report.txt` 那一段；别人要什么，闸门那张信里给什么——并发、超时、代填明细都在信的数据格上，跟这一格没有关系。

**怎么封（作者 2026-11-01 提的法子，他自己说「这是野路子」）**：解析站把上下文加密成一段字节放进纸上，报告站解开才用；密钥写死在加密与解密两处各一次，不留变量、不往下传。别的包拿到那格只是一段看不懂的字节——**拦的是顺手，不是存心的**；要真去抄密钥，那已经是在故意绕，跟改一行 import 是一回事。字段旁用备注写清用意：这一段就是防旁人从上下文里取值的。

**落到代码上**：契约包里那一格就是一个字节串，跟旁的数据格没有区别。加密、解密两段代码住哪个包，建站时按横切包权限表定：单独立一个小包、依赖白名单里只放解析与报告进来，连抄密钥都得多写一行 import（扫得出来）；或者两边各写一遍，省一个包，但改算法要改两处。报告站多一次解密，调试时看不见明文——这是这套法子要付的账。

判据表不封：执行站拿它定分类、结算站看退出码分类，各站本来就该读；「随行」对它只意味着中转站不改它。

### 三、五种模式在结算那儿合成一份

**执行交出来的纸 = 通用格 + 一个带标签的附加格。** 结算只算通用格，附加格一个字段都不打开、原样递给报告。五套结果因此在结算这一步合成一份总账，而且同一条算法只写一遍。

否掉的两条：先分五份纸、结算各写一套（同一条算法写五遍，改一处要改五处）；先归一成一种通用结果（模式特有的东西塞不进去，要么丢、要么报告缺一块）。

### 四、加一格到底贵不贵（作者 2026-11-01 问）

契约包是这张纸的定义唯一出处，所以「贵不贵」按改几处算：

| 加在哪 | 要改几处 | 是哪些 |
| --- | --- | --- |
| 通用格 | 定义 1 + 适配 3 | 契约包、执行填、结算算、报告读 |
| 附加格 | 定义 1 + 适配 2 | 契约包、执行填、报告读 |
| 得回头从解析拿 | 定义 1 + 适配 3，但改的是整条线 | 契约包、解析填、中转站原样带、报告读 |
| 删一格 | 同加一格 | 删了没跟上编译就报，**删比加安全** |

一句话：**加一格是两到三处，不是满仓库找；但加在「得回头从解析拿」那一档，就是改一整条线——ADR-0035 记的那个代价，就是这一档。**
