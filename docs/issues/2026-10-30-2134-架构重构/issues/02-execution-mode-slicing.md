# 02: 五种执行模式怎么进执行站——站内分文件，还是每种模式各自成包

**Type**：grilling
**Status**：open
**Blocked by**：无，可立即开工

## Question

五种执行模式（命令 / 脚本 / 上传 / 下载 / 批量改密）互斥，每次只选一种，这是词表里「执行模式」的定义。老工程里它们摊在 `internal/ssh`（3589 行，全工程最大）与 `internal/batch`（698 行）两处；批量改密另有五处散件：`internal/ssh/passwd*.go`、`internal/cli/passwd.go`、`internal/config/passwd.go`、`internal/verdict/keywords.go`、`internal/output/report.go`。

教学骨架做了个决定并标了「留给你」：**站＝一个包，垂直切片＝包内文件，不建子包**。好处是站内共享不用开门（同包文件互相全可见）；代价是切片之间没有硬墙，加一种模式仍是在同一个包里加一个文件。

要定的：

1. 「加一个功能只动几个目录」这个初衷，在这个形态下还剩多少——加第六种模式时，实际要动几处？
2. 要不要为每种模式建独立包（硬墙）？代价是每条切片都得导出自己的入口，执行站的入口就变成一堆类型断言或一个分派表。
3. 密钥管理（`internal/credential`，三条子命令：生成主密钥、查状态、转凭据）不走五站，是独立垂直切片；它跟执行站里那四种模式毫无关系，但老工程里它与**批量改密**共用同一批凭据读取代码。这一分层会不会把那批代码劈成两半，两边各留一份。

答案要能落成一句判据：新增一种执行模式时，改动应该收敛在哪几个目录内。
