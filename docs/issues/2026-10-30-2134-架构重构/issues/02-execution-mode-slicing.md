# 02: 五种执行模式怎么进执行站——站内分文件，还是每种模式各自成包

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工

## Question

五种执行模式（命令 / 脚本 / 上传 / 下载 / 批量改密）互斥，每次只选一种，这是词表里「执行模式」的定义。老工程里它们摊在 `internal/ssh`（3589 行，全工程最大）与 `internal/batch`（698 行）两处；批量改密另有五处散件：`internal/ssh/passwd*.go`、`internal/cli/passwd.go`、`internal/config/passwd.go`、`internal/verdict/keywords.go`、`internal/output/report.go`。

教学骨架做了个决定并标了「留给你」：**站＝一个包，垂直切片＝包内文件，不建子包**。好处是站内共享不用开门（同包文件互相全可见）；代价是切片之间没有硬墙，加一种模式仍是在同一个包里加一个文件。

要定的：

1. 「加一个功能只动几个目录」这个初衷，在这个形态下还剩多少——加第六种模式时，实际要动几处？
2. 要不要为每种模式建独立包（硬墙）？代价是每条切片都得导出自己的入口，执行站的入口就变成一堆类型断言或一个分派表。
3. 密钥管理（`internal/credential`，三条子命令：生成主密钥、查状态、转凭据）不走五站，是独立垂直切片；它跟执行站里那四种模式毫无关系，但老工程里它与**批量改密**共用同一批凭据读取代码。这一分层会不会把那批代码劈成两半，两边各留一份。

答案要能落成一句判据：新增一种执行模式时，改动应该收敛在哪几个目录内。

## Answer

**判据一句话**：新增一种模式，改动收敛在**契约包的一格 + 五个站各一块**；不新增包，不动塔尖。

**「不动塔尖」怎么算**：不新增分叉、不加参数。既有的那一个分叉（流水线 / 那三条小命令）照旧，加一种模式不许碰它。

**「加一个功能只动几个目录」这个初衷还剩多少**：剩下大半。改动落在六个目录内，但每一处都是**新加一块**，不是去改别的模式——老工程里加一种模式要动到别人已经在用的分支，那种牵连没有了。

**模式不聚成包**：第一刀横着切站，第二刀竖着切站内的文件。一个模式的文件散在五个站里——解析负责把它读进来填格，闸门负责看它要不要查危险，执行负责跑，结算负责归类，报告负责出成品。不汇成一个包。

**为什么不聚**：五个包不会住在执行站下面，而是从解析穿到报告的五条纵切，每个站要开五个口子，越拆越浅。作者的「深模块一路深到底」靠的是站薄而深，不是把线切细。

**「同包会互相借参数」不成立**：一次只跑一种模式，它们不同时在场。真正会出的事是共用件被顺手改、另一种模式跟着变——拆包也挡不住，只会把那段公共件挪到另一个包，让五个包都依赖它。

**载荷用一个带标签的格子装五种内容**：标签说清是哪种，五种内容各是各的类型、不合并；标签与内容对不上由闸门验，契约里不放校验函数。

**密钥管理独立成包**：三条小命令不进流水线，需要配置就在自己包里读自己那一小块，不经过解析站。**凭据读取再单列一个叶子包**（读主密钥、解密），密钥管理和批量改密都从它取——不复制，也不让执行站反过来依赖工具包。

**塔尖留一个分叉**：这次走流水线，还是那三条小命令。这是塔尖唯一被允许的分支——站都在流水线里面，看不见「这次根本不进流水线」。

**依据**：`docs/adr/0036-五种模式不聚成包.md`。信封形状、判据表怎么走那几条来自 `docs/adr/0035-交接件按棒定形状.md`（03 号先定，本条照用）。

**留给别处**：五站与横切包的最终命名、执行站入口的形状、结算站怎么把五种结果合成一份报告——都归 04 号。
