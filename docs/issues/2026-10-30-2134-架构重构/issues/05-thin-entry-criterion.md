# 05: 塔尖薄到什么程度算薄——判据是一句话还是一行数

**Type**：grilling
**Status**：resolved
**Blocked by**：无，可立即开工（01、02、03 均已解）

## Question

骨架给的判据是一条**规约**：塔尖只许搬，不许做——任何一行「自己干活」的代码（拼字符串、判断业务规则、读写文件）都说明有一站漏了东西出来。还给了个**观测量**：老 `main.go` 512 行，骨架 124 行。

判据好写，难在它没法被机械核对。要定的：

1. 判据要不要落成**可机械核对的硬指标**（比如「塔尖里出现的全部调用，必须是五站或横切的导出函数」），还是就留成一句规约、靠人读。前者能挡住下一个 AI，后者挡不住。
2. 塔尖的分派（`plan.Kind` 分批量与子命令）算不算「做」？骨架认为算「搬一格」，不算「做一件事」，但承认这条线有灰。
3. `os.Exit` 只许出现在塔尖——这条要不要也写进结构定义。
4. **帮助与版本放哪儿**：`usageText` 现在在 `internal/cli`（642 行那个文件），版本常量 `appVersion` 在根目录 `main.go`。规范要求「版本号只从入口常量取」。那帮助信息归解析站（它本就管命令行解析）、归闸门（帮助也算不合规参数时的出口）、还是归塔尖？这一问跟「塔尖该知道多少」是同一件事，所以并在这里谈，不单开工单。

答案要能落成一句判据：塔尖里出现什么，就算破了这个问题。

## Answer

**判据一句话**：塔尖开头的依赖清单里，出现任何不属于「五站 + 横切包全体 + 契约 + 密钥管理包」的东西，就算破了；`os` / `os/signal` / `errors` 只许用**点名的几个符号**（退出、订阅信号、认错误类型），不是随便用。

**不拿行数当判据。** 512 行对 124 行只是观测量——塞十行字符串拼接，行数照样好看。依赖清单是一眼扫得到、也能机械扫的。

**但它只是必要条件**：清单干净，仍可能有人在塔尖用 `+` 拼字符串，那不进清单。充分条件要靠 07 再加一条（塔尖不许出现字符串字面量与拼接），或者靠审批。

**塔尖只做三件**：分叉（走哪条路）、搬（把信封交给下一站）、退（给退出码）。不下任何业务判断，判断全在站里。它是**编排**，不是横切——横切是那几个叶子包。

**分叉只认递回来的结局，一共五种**：解析递回四种——信封（进流水线）、一条小命令（交给密钥管理包）、一句要打给使用者的话（帮助之类）、起不来；加上闸门退回的一种——**拒绝（连同那句话）**。塔尖各交各的去处，自己不判断该不该；不许自己去看配置、看文件在不在，那就从搬变成做了。

**第五种为什么走塔尖**：闸门不碰屏幕（见 01 号「停只在闸门」那条），话由闸门产、塔尖搬——与帮助那条是同一个动作，不必给塔尖添新的职责。代价是塔尖认的结局从四种变五种，来源变成两处（解析、闸门）。

**`os.Exit` 只许出现在塔尖**：ADR-0032 第五条与 ADR-0034 第四条已定，这里是确认，不新增。

**帮助与版本**：帮助文本归解析站产（与选项定义同源，分开就有两个来源），塔尖把那段话交给终端输出、退 0；版本拼装归报告站，塔尖只把入口那个常量传下去——**那个常量是编译期定死的，不算「手上的东西」**。老塔尖现在自己在拼这一行，那行代码就是「做」。

**依据**：`docs/adr/0032-按五站分层重构工程结构.md` 第五条（本次补写）。不另开 ADR——这四条全长在「塔尖该多薄」一个点上，拆出去就有两个出处。
