# 13: 实时进度怎么从执行站走到报告站——过不过结算站，走事件还是轮询

**Type**：grilling
**Status**：resolved
**Blocked by**：无，02 与 03 已解，04 已把显示归执行站

## Question

老工程里进度这条链跨好几个包：`internal/ssh` 的进度读写器（包裹 SFTP 读写的 `io.Writer` / `io.Reader`，按 500ms 节流）、`internal/batch/progress.go` 的进度聚合器（跨调用保存状态、与 worker pool 同生命周期）、`internal/output` 负责渲染。

按五站分法，这三块要拆开：采集归执行站，聚合归谁？渲染归报告站。**难点在聚合器**——它跨调用保存状态，是五站里唯一「有状态」的东西，而五站其余部分都是「入 → 出」的纯函数形状。

骨架对这个问题的答案是写一句「Hooks 是事件上报通道，不是反向驱动——它只能收进度，改不了主流程走向」，并给了判据：回调里能不能让程序少走一站？不能，所以合规。但**这条只说了「可以收」，没说进度怎么送出去**。

要定的：

1. **进度走哪条路**：① 执行站直接调报告站的渲染函数（等于执行站 import 报告站，方向倒着）；② 执行站发事件、塔尖转交（塔尖就厚了）；③ 走回调（骨架的 Hooks 方案，但回调要由谁注入）；④ 报告站定时去问执行站要快照（轮询）。
2. **聚合器归谁**：它有状态。放执行站，那执行站要对外暴露「当前进度」；放报告站，那报告要 import 执行站的数据类型。
3. **结算站要不要参与**：结算站的职责是把「事实」变成「结论」；进度是过程不是结论。若不过结算站，那五站的单向性在这里就破了一个口——这条口子要不要明确写进结构定义。
4. **节流放在哪一层**：现在 500ms 的节流在数据采集侧，渲染侧还有一层。重构后合并到一处还是各留一层（各留一层会互相抵消）。

答案要能落成一句判据：执行到一半时，屏幕上那行进度数字是从哪条路径走到终端的。

**已知（2026-11-01 补，谈之前先看）**：04 号已把「跑的过程里的显示与实时定分类」归执行站——进度界面的渲染在执行站，不在报告站。所以本题只剩「聚合器归谁、节流放哪一层、要不要过结算站」三件，题干里「渲染归报告站」那句不再约束。

## Answer

**依据**：开发者 2026-11-01「我是想边跑边写日志的……唯一的理由，就是防止各种破坏性的停止，能留下痕迹。这是我能想到的唯一优点」；「日志也不会传给别人，就是一个终端输出……让用户感受一下我在执行，感受一下刷屏，感受一下速度。它就是一个特殊的输出，不归咱们什么『塔尖』才有什么输出的权利」。

### 一、一句话判据

执行到一半时，屏幕上那行数字从哪条路走到终端？——**它没跨过任何一道站门**：在执行站里拼好，交给终端输出包画到屏幕上。而同一行，那一刻也已经落在盘上。

### 二、这条链不出执行站

采集（传文件时量一次进度）→ 聚合（记住跑了几台、多少字节、算速度）→ **交给终端输出包画**。前三步与出字都在执行站，最后一步只调 `console`；执行站自己不碰 stdout（ADR-0032 第四条：`console` 是往终端写字的唯一出口）。04 号已把「跑的过程里的显示」归执行站，15 号说中途刷屏不经过塔尖，两条夹下来只剩这个形状。

所以题干那四条路——调报告站的渲染、塔尖转交、回调注入、报告站轮询——**一条都用不上**。不是选了哪条，是「把它送出去」这个需求不存在。

**「要不要把这条口子写进结构定义」的答案是：不写，因为没有口子。** 这里说的「口子」专指**跨站**的东西——一份数据从上一站递给下一站。进度没有跨站：它从采集一路到屏幕，没经过任何一座站门。五站的单向性说的是「站与站之间只往下走」，它压根没在站与站之间走。要写进结构定义的只有一句，而那句 04 已经写了：**跑的过程里的显示归执行站。**

### 三、聚合器：执行站里一个不对外露的文件

它是五站里唯一有状态的东西，但它只服务执行站。立成包，就是把一个格子升级成一道墙；而它说不清「我这一件事」——它干的是「记住跑到哪儿了」，那本来就是执行站的一部分。

**「不对外露」怎么核**：按 ADR-0032 第四条的出口白名单——每个站包只许导出「入口函数」与「替身插口」两个名字。聚合器两个都不是，所以它不许被导出；红线那条测试正好盯这个。

### 四、边跑边写：这是目的，不是副作用

**每收到一条结果就出这一行，立刻落盘。** 要的是被强杀、断电、关窗口时，盘上已经有痕迹——这是这条唯一的理由。所以它不能攒到最后一次性写，攒着写就把这个理由抹掉了。

**那一行只拼一次，三个去处**：屏幕、那份终端输出、执行期日志。拼句的只有 `message`（ADR-0032 第四条：唯一拼句处）；执行站拿着这一行交 `console` 打屏、写进那份输出文件；运行日志另交 `log` 包写。所以「谁产谁写」要说细——**内容归执行站，句子归 `message`，打屏归 `console`，运行日志归 `log`**，执行站自己不拼字、不碰 stdout。路径都从归档包拿。

### 五、结算站不重写那几份

它只算总数与结论。跑完之后报告站出屏幕统计、报告文件、两张表格——那是另一件事，**不复用进度的数字**（15 号的总账来自结算，不来自聚合器），免得同一个数两个来源。

**界线：同一条事实可以有两种摆法（一行文字、一行表格），但不许把一种摆法的文字再解析回去当输入。** 那两张表格吃的是结构化结果，不是屏幕上那段字——老工程正是重新过一遍结果拼表，那是因为列不同，不是要抄屏幕。**逐行那份不许在整理阶段重写一次**：它边跑边写，写下的就是最终形态。

**怎么核**：那份输出文件的名字只在执行站那一处出现。结算站与报告站的代码里出现它，就是有人在重写。

### 六、节流只节屏幕，不节落盘

**留着的是「毛数据进聚合器之前」那一层**：传文件时字节级事件太密，压到 500ms 一次再说。**渲染那侧那层删掉**——快照进来时已经被压过，再压一次只是多一道空转。阈值仍是 500ms。

落盘那条线不经过节流：一条结果一行，来一条写一条。

### 七、这不是「输出的特权」

屏幕只有一个，所以「往屏幕上写」这件事只在四处发生：塔尖、执行站那一处、`ask`、报告站（ADR-0032 第四条）。**每一处是那一站的唯一出口**，不是全工程只许一处——四处本来就是四个不同的站，各自只留一个口。

这份名单记的是「哪几处在写屏幕」，不是谁能写、谁不能写。往盘上写则各写各的，谁产内容谁写。

### 八、取消时

执行站收手：画到一半的那屏收掉，已经写下的行留着不动（12 号留的口子）。**收手不是收摊**——照 12 号，取消之后仍要走完结算与报告，只是统计里单列「未执行 N 台」。

**留着**这件事正是边跑边写的价值：按停之后，盘上那段就是这次跑到哪儿为止的证据。

### 九、代价

界面与落盘同在一个包，将来若想让别处也吃这份进度（比如另开一个监视窗口），得在执行站开一个口。那时才有依据开，现在开是猜。
