# 规格：检查与提示的先后（建站 0x）

**状态**：done
**决策**：`docs/adr/0052-检查与提示按根因分层定序.md`
**底本**：`audit.md`（78 条 argv 实测，2026-11-13，HEAD `8927738`；分类与逐条输入都在那份里）。结论的依据见 ADR-0052《背景》。

## Problem Statement

使用者把参数写乱、写错、把命令塞进 `-s` 时，工具只报一句就停。现在那句常常不是他真正的问题：`-p` 配了 `-c`，屏幕上说的是「清单读不到」；命令被禁止，屏幕上还是「清单读不到」；`-c` 只有一个空格，屏幕上仍然是「清单读不到」。他照着第一句去建清单，建完重跑，还是错——第一句没说对他的毛病，只是先撞上了另一件事。

他要的只有一件：**第一句说清到底是哪一格错了，而且改完它，下一句不该再是同一件事**。值合法、只是用法怪的命令，工具判不出他的意图，那就不判，照跑，但要把「哪一格」说清。

## Solution

把「谁先说」与「谁负责判」分开：判定归属不动，报出的先后按七层——词法、结构、搭配取值必填、判决、材料可达、材料内容、人点头。上一层没判清，下一层的现象不许开口；材料照样先读（判决要用正文、屏要用节点），但读失败要等到它那一层才报。

结果：`-p` 配 `-c` 报 `-p`；危险命令报危险；清单坏了等前面全过再说；缺清单有一句自己的话，不再把空串交给系统报 `open :`。提示也不再抢在结论前——被拒绝的一次运行，屏幕上不该先冒出「已移除表头」。

## User Stories

1. 作为使用者，我把两个模式同时给了，希望第一句就说「互斥、只能留一个」，而不是叫我去修清单。
2. 作为使用者，我把命令塞进了 `-s`，希望它说清「`-s` 要一个脚本文件，`ls -l` 不是文件」，并告诉我执行命令用 `-c`。
3. 作为使用者，我给的命令命中禁止规则，希望第一句就是禁止框，而不是先让我去准备清单。
4. 作为使用者，我没给 `-f`，希望它直接说「没有给节点清单」，而不是报一句 `open : 没有那个文件`。
5. 作为使用者，我同时写错了 `-t` 和清单路径，希望先报 `-t`——修好它之后，清单那句才是下一件要说的事。
6. 作为使用者，我用 `--yes` 跑自动化，希望它别问我，但**要告诉我它动了我的输入**（比如移除了表头行）。
7. 作为维护者，我加一条新判据时，只答「它是不是另一条的前提」，就知道它该排在哪一层。
8. 作为审计者，我看期望表就知道「这一句该不该先说」，不必回头猜老版是怎么写的。

## Implementation Decisions

**一、七层与归属。** 报出顺序即 ADR-0052 决定二那张表。落点：一至三层与第四层判决在闸门；第五、六层在解析站（照旧读；失败不进纸，另交给塔尖）；第七层在闸门；报由塔尖按两种递回物执行。

- 第三层顺序（同层固定次序，对位老版）：模式 → `--no-shell` 用法 → 改密五条（`-a`、`-p`、`-k`、`--no-shell`、身份开关） → `-p` 形态与「不能配 `-c`/`-s`」 → `-d` 必配与远程形态 → `-u` 必配 → 身份开关冲突 → `-c` 空白 → `-n`/`-t`/`-T` → 缺清单 → 解释器回退那一问。
- 第四层之前确认判据表齐不齐（工具自带的那三份，不是使用者给的材料）；「齐不齐」仍由解析站判，只是要排在判决之前报。不齐时按 ADR-0034 决定七那句口径报「工具没能力判断」。
- 危险提醒档那一问在第四层：这次带延后项时**照问**，答完再报延后的失败。

**二、延后项不进纸。** 解析站把第五、六层的失败包成「起不来」，不当场报、不退出；它**不装进纸**，与纸一起交给塔尖。纸仍然只装「计划已成形」的东西——ADR-0034 决定四那条不动。没有失败时，这一样为空。

**三、闸门多收一个参数。** 塔尖把「这次别出屏」递进去：闸门判完一至四层后据此**跳过第七层确认段**直接放行。失败必然发生在确认之前，屏不该出，`--yes` 那行与上传并发建议也不该出。闸门不知道失败是什么，也不需要知道。

**四、塔尖按三种情形收场。** 拒绝 → 报拒绝；放行且带延后项 → 报它、按「起不来」退；放行且不带 → 照旧往下走。塔尖仍不判断，只认这三样。

**五、提示随纸走、由确认段印。** 表头移除、私钥配了没加 `-k` 这两类提示，不再由解析站当场打，改为随纸带下来，由闸门在确认段开头交给 `ask.Show` 印——参数屏今天也走这条路，所以它自然排在屏之前，闸门一个字都不拼。被拒绝、或这次根本不出屏的那次运行，确认段整段走不到，屏幕上不出现这些提示。

**六、缺清单有自己的话。** 属第三层必填，主语是 `-f`，内容说清「这次没有给节点清单」与「下一步补一份或写一条内联」；不再把空串交给系统报 `open :`。（「没给 `-f`」是**参数缺失**，不是清单校验——那时清单还不存在，谈不上校验；这一句只界定这一类，不动 ADR-0032 决定一「清单的校验留在解析」。）

**七、`--yes` 分两类。** 陈述「工具对这次输入做了什么、没做什么」的是事实，照说；陈述「你以后该怎么做」的是教学，`--yes` 下不说。这两类的判据进 `message` 的说明，样例先收表头与私钥两条。

**八、验收是期望表。** 见下节。它钉「该先报哪一格」，不钉整句措辞；措辞归 `message` 的自定义区与 A/B 逐字比对。

**九、退出码不动。** `exitcode` 那四格不因顺序变化而变：拒绝仍 1、起不来仍 1、被中断 130。

## Testing Decisions

- **接缝只有一个：进程入口。** 起二进制、喂 argv、读合并输出，断言「这一格的说法出现在其余各格之前」。第二个接缝不新开——顺序是屏幕的性质，站内测试看不见它。
- 现有先例是同一种接缝（`internal/guard` 里那两条起二进制的测试），但那是红线区、只判形状；本次断的是值（哪一句先说），**住自定义区**，跟塔尖走，不进红线名单，不动任何红线指纹。
- 断言写法：每行给一组「输入 + 该先出现的那一格的特征串 + 不许比它更早出现的其余特征串」。一次跑完，逐行报差异。
- 测试要自带 `config/`：三份判据文件、一份主配置；加密关（避免主密钥干扰）；环境里关掉 Git Bash 的路径改写（`MSYS2_ARG_CONV_EXCL`），否则 `/opt/app/` 会被换成本机路径，测的就不是这件事。
- 既有 37 场 A/B 照旧跑；期望表不替代它，两样不互相替代（ADR-0038 可切门槛第三条不变）。

## 使用者可见面的变化

这次动的是「哪句先说」，但有三处使用者能感觉到，切换时要在 CHANGELOG 写一句：

- **多一句新的**：没给 `-f` 时报「没有给节点清单」，不再报 `open : 没有那个文件`。
- **少两处刷屏、又多两处**：被拒绝、或这次根本不出屏的那次运行，屏幕上不再先冒出「已移除表头」「私钥配了没加 `-k`」；而 `--yes` 跑成功的那次，这两类事实会照印（原先静默）。
- **换先后**：禁止档命令与读不到的清单同时给时，先看到禁止框（原先先报清单读不到）。

退出码不动（拒绝 1、起不来 1、被中断 130），配置字段一个没动。

## Out of Scope

- **具体措辞**：「同时给了 -c、-r」里那个影子 `-r`、`-s` 塞命令时的方向句原文。ADR 立了规则（第六条），句子落在措辞迁移那一批（4.2），不在本议题。
- **`--yes` 的完整样例表**：本轮只给两类判据与两条样例；新提示出现时再补。
- **危险规则本身**：命中规则、归一与大小写口径都不动，本轮只动它排在哪。
- **4.2 措辞迁移、4.8 规范债、4.7 同名多份口径差**：各自有归属，不并进来。
- **切换当天五步**（ADR-0038 三档）：期望表是切换之前的一道验收，不替代逐字比对。
- **A/B 的 `KNOWN_EXPECT` 怎么处置**：撤掉「登记差异」这一用法，具体删哪几行留给执行时按表逐条核对。
