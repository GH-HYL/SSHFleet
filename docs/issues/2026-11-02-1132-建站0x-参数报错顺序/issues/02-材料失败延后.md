# 02: 材料失败延后，不再顶掉前面的层

**要做的**：脚本读不到、上传源读不到、清单坏了这一类失败，不再抢在「参数搭配不对」「命令被禁止」前面。同一条命令里两处都错时，第一句报的是靠前的那一层；靠前的全过完之后，才轮到那句材料失败，退出码仍是「起不来」的 1。

落地三样（ADR-0052 决定五）：

- 解析站照旧读（判决要用正文、屏要用节点），失败包成一条延后的「起不来」，**不装进纸**，与纸一起交给塔尖；没有失败时这一样为空。
- 闸门多收一个「这次别出屏」的参数，判完一至四层据此跳过确认段；它不知道失败是什么，也不需要知道。
- 塔尖三种收场：拒绝 → 报拒绝；放行且带延后项 → 报它、按「起不来」退；放行且不带 → 往下走。塔尖仍不判断。

**Blocked by**：01（车架要先能跑）。

## Comments

- 2026-11-13：解析站多交一条延后项。`parse.Run` 由四样变五样，最后一个是「延后的起不来」；`buildPlan` 的第三个返回值改作延后项（`plan == nil` 时才可能是密钥命令自己的那条错）。塔尖由此有第五种情形：放行但带延后项 → `fatal` 收场，排在建归档目录之前。
- **闸门签名宽一格**：`gate.Run(p, skipConfirm)`。跳过的只是第七层确认段——一至三层与第四层判决照判，信封校验照做（它不是第七层，是「纸被造错」）。带延后项时危险提醒那一问照问（第 38 行钉住）。
- **延后项只有一条，取层序最早的**：判据表（第四层）先于材料（第五、六层）。`loadTables` 从材料之后提到材料之前，读不成时纸照样交上去、表是零值——闸门拿空表判，危险检测不会命中，塔尖报那一条（第 39 行的底子，05 才翻）。
- **第五层内部的次序一并改掉**：脚本 → 上传源 → 下载目录 → 清单。原来上传源采集排在读清单之后（第 42 行红在这里），改法是把 `checkMaterial` 拆成 `materialScript`／`materialDownloadDir`／`materialManifestFile` 三个，采集与清单都挪进新的 `materials()` 里按层序走。
- **并发建议挪出采集**：`collect` 原来顺手算建议，而建议按节点数封顶、节点在清单之后才有。拆成 `applyUploadAdvice(p, cfg)`，由 `materials()` 在读清单之后调用；`collect_test` 的两条用例跟着调一次。
- **代填表改在 `materials()` 里读**（原来在 `proceed` 之外无条件读）：`-c ls -a /nope.csv -n abc` 现在先报 `-n` 而不是「代填文件读不到」，与层序一致。这一处没有表行钉着，属顺带对齐。
- **动了两个红线测试文件的调用形状**（`redline_parse_test`、`redline_gate_test`）：只补实参个数，测试名、钉住的符号、失败断言点数一个没变，指纹未动（`go test ./internal/guard` 全绿即证）。依据是 ADR-0052 决定五「解析多交一条」「闸门签名宽一格」——接口宽度变了，调用点只能跟着改。
- 验：`go build ./...`、`go vet ./...` 干净；`go test ./...` 全绿；期望表 55 行里 17 行由「留给 02」翻成断言并通过（14–25、31、33、34、38、42）。
- 2026-11-13（质量审计后回补）：**上一段那句「只补实参个数」说得不全**——红线夹具 `redlinePaper` 还补了一格 `Resources.Manifest`（不补的话「缺清单」那条判据会把那张干净纸也拒掉）。它在 helper 里，按 ADR-0037 决定五「经 helper 间接引用的不算」，指纹看不见。
- 同一次回补改了三处结构：①上传源的「根在不在」（第五层）与「逐个清点」（第六层）拆成两步，中间隔着下载目录、清单与节点——原来清点失败能顶掉还没判的清单；②清单的「是文件吗／读得到／非空／非二进制」收进 `readManifest` 一处，`materialManifestFile` 删掉；③「给没给 `-f`」收成 `Resources.HasManifest()` 一处判据，解析站与闸门都走它。
