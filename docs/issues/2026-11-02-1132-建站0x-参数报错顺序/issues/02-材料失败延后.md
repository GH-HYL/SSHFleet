# 02: 材料失败延后，不再顶掉前面的层

**要做的**：脚本读不到、上传源读不到、清单坏了这一类失败，不再抢在「参数搭配不对」「命令被禁止」前面。同一条命令里两处都错时，第一句报的是靠前的那一层；靠前的全过完之后，才轮到那句材料失败，退出码仍是「起不来」的 1。

落地三样（ADR-0052 决定五）：

- 解析站照旧读（判决要用正文、屏要用节点），失败包成一条延后的「起不来」，**不装进纸**，与纸一起交给塔尖；没有失败时这一样为空。
- 闸门多收一个「这次别出屏」的参数，判完一至四层据此跳过确认段；它不知道失败是什么，也不需要知道。
- 塔尖三种收场：拒绝 → 报拒绝；放行且带延后项 → 报它、按「起不来」退；放行且不带 → 往下走。塔尖仍不判断。

**Blocked by**：01（车架要先能跑）。

**Status**：ready-for-agent

- [ ] `-c "ls" -p /opt/app/ -f /nope.csv` 先报「`-p` 不能搭配 `-c`」，不出现清单读不到
- [ ] `-c "rm -rf /" -f /nope.csv` 出禁止框，不出现清单读不到
- [ ] `-c "rm -rf /opt" -f /nope.csv` 先出危险提醒并问一句；答「是」之后报清单读不到，退出码 1
- [ ] `-c "ls" -f /nope.csv`、`-f empty.csv`、`-f bin.csv` 仍各报自己那一句（延后不等于不报）
- [ ] `-u .`、`-d /etc/passwd`、`--change-password pw -p /opt/app/`、`--sudo --no-sudo -c "ls"` 各报自己那一格，不被材料失败顶掉
- [ ] 期望表里属于这一批的行全绿：14、16、19、21–25、31–37、40–48
- [ ] 纸不加格：`contract.Plan` 一格没加；ADR-0034 决定四「起不来不进信封」仍成立
- [ ] 不出屏的那次，参数屏、`--yes` 那行、上传内容树、并发建议一起不出
- [ ] `go build ./...`、`go vet ./...` 干净；`go test ./...` 除已知的环境类假红外全绿
