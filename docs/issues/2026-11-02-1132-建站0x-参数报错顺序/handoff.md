## 一句话

使用者的参数乱序、怪用法，决定「两份都错时先给看哪一句」——老版两年的积累磨出了一个次序，新版重排成五站之后跨站的判断先后变了样。A/B 全量矩阵里 **15 条**真差异，全是这一类。

---

## 为什么单独拎出来

开发者 2026-11-02 原话：

> 用户各种稀奇古怪的参数选项、奇怪的用法、前后顺序，影响咱们工具的报错顺序，影响代码是先写后写判断，这个极其复杂，而且只能靠经验积累，这个单开一个议题，而且整个议题得开发者一直在提供信息。

三条推论：

1. **它不认阶段。** 判据散在解析站与闸门，往后执行站（`-u` 与 `-s` 同时给怎么报）、结算站（中断与缺额哪个先说）也会碰到。挂在阶段 04 会变成「04 做完就结账」，可它结不了。
2. **判据没有文档可查。** 老版那套先后是试出来的，源码里只有结果、没有理由。能判「使用者实际会怎么敲」的只有开发者。
3. **它是「一条一条」的活。** 一条案例就是一条命令；不是拆十张工单一次做完。

## 根：站序反了

老版 `modules/SSHFleet_Go/main.go`：

| 次序 | 做什么 | 行号 |
| --- | --- | --- |
| 1 | `CheckArguments`：参数搭配、互斥、取值 | 313 |
| 2 | 危险检测 + 危险确认 | 366 |
| 3 | 读清单 | 393 |
| 4 | 确认屏 | 414 |

新版：解析站（解析 argv → 材料自检 `-s`／`-u`／`-d` 的 stat → 读清单）→ 闸门（合规 → 危险 → 信封 → 确认屏）。

**材料自检与读清单跑在闸门之前**，所以闸门本来要报的那句会被「起不来」顶掉。最典型：

```
sshfleet2 -c "ls" -p /x

老版：选项/参数合规性检查未通过：-p 参数不能搭配 -c 或 -s 使用
新版：读取内容时发生错误: open : no such file or directory
```

两句都对，但使用者拿到第二句会去建一份清单，而他真正的问题是多给了一个 `-p`。

## 三条改法，各自的代价

**一、把「起不来」延后到闸门之后。** 解析站读清单或材料自检失败时不中断，把那个 `CannotStart` 挂在纸上（契约加一格），塔尖先走闸门，闸门放行后再报。
- 代价：动契约一格、塔尖加一个分支；ADR-0035「交接件不许比上一份宽」要为这一格写一句解释（它不往后递，只给塔尖）。**不破五站分工。**

**二、闸门里读清单。** 解析站只装 `-f` 原值与解析时判出的问题，真读文件与建节点挪到闸门「合规 → 危险」之后。
- 代价：闸门从「只裁量」变成「又读又判」，正撞 ADR-0032 第一条「校验归最懂那份材料的那一站」；闸门要多依赖归档包与文件系统，依赖表跟着改。

**三、解析站拆两个出口。** `parse.Run` 只出纸，另出一个 `parse.Manifest` 在闸门放行后调。
- 代价：撞出口白名单「至多一个函数」（ADR-0037 决定三，红线判据），要改检查本体。

**四、认下这 15 条。** 写进 A/B 的 `KNOWN_EXPECT`，等 09 逐字比对再统一处理。
- 代价：09 一定再撞一次，那时改的是已经通了的路。

**倾向第一条**：不破分工，代价只是一格纸与塔尖一个分支。没定。

## 怎么复跑

沙盒 `build/建站04_sudo_2026-11-02_1108/`，里面新老两个二进制、`run/` 现场、`ab.sh` 副本都在。

```
cd build/建站04_sudo_2026-11-02_1108
./ab.sh                      # 全量矩阵
```

**坑**：两份二进制要命名成 `sshfleet_old.exe` 与 `sshfleet2.exe`——脚本的程序名归一写死了那个后缀，Linux 上也照这个名跑，不然会多出一堆假差异。

重编新版：在 `modules/SSHFleet2_Go` 下 `GOTMPDIR=<沙盒> go build -o <沙盒>/sshfleet2.exe .`
