# 03: 代填文件的两种错误说清是哪一列出了事

Status: done（2026-10-18 实施）
Blocked by: None（可立即开工）

**要做的**：用 `-a` 代填时，如果某一行只有一列、或者某个触发词是空的，使用者看到的说明要**说清楚是这一行的哪一列有问题、该怎么改**，不出现一句看起来像在重复外层信息的话。

**被谁阻塞**：无，可立即开工。

---

## 现状

外层报错已经把「`-a`、哪个文件、第几行、这一行原文」带上了，所以使用者知道是代填出的事。问题在内层那句太省：

```
-a 参数指定的代填文件 xxx.csv 第 3 行不合规：a
只有一列：缺触发词（第 1 列是代填内容，第 2 列起是触发词）
```

- **只有一列**：内层把列的含义解释了一遍，但没说是「这一行缺了什么」。
- **触发词为空**：内层只有「触发词不能为空」，没说这一行该怎么补。

## 要做的事

1. **只有一列**：内层不再重复解释列的用途（外层已经有提示语），改成说清**缺的是什么**、**这一行至少要几列**。
2. **触发词为空**：说清是第几列的空，以及触发词不能留空的理由（留空等于无条件盲填）。

两处都只改文案，不改判定逻辑。

## 验收

- [x] 造一行只有一列的代填 → 报错里能看出「这行缺触发词、至少要两列」，且不重复外层的列说明
- [x] 造一行触发词为空的代填 → 报错里能看出是第几列为空
- [x] 两处报错仍带 `-a` 与文件名、行号（外层没有变化）
- [x] `go test ./internal/cli/` 全绿
