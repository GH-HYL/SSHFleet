# 规格：红线区第二轮

**状态**：done
**底本**：审计 11-J1（红线区里的行为断言）、11-H3（红线钉「50 个等号」）
**决策**：`docs/adr/0050-红线区清掉两处值断言.md`

## Problem Statement

红线区只该放结构：它红了，意思是「有人把结构动了」。现在混着两处「值算得对不对」「版式多宽」的断言，红的原因就变了味——改一次分隔线宽度、改一次结算的数字口径，红线当场红，而结构一个字没动。红线一被拖下水，就没人再信它。

## Solution

两处都改成判形状与流向：结算那条只判「跑完的加没跑的等于总数」，数对不对归结算站自己的自定义区（它已经在判）；分隔线那条只判「整行都是等号的那种行出现了一次」，宽度归 `message` 的自定义区。

## User Stories

1. 作为维护者，我希望改 `message` 的版式宽度时红线不动。
2. 作为维护者，我希望红线红的时候，原因是「结构被动了」。
3. 作为审计者，我希望红线区的每一条断言都能被外人判成「这是形状」，而不是「这是值」。

## Implementation Decisions

- **结算那条**：`Total`／`Done`／`NotRun` 三个具体数换成守恒关系（`Done + NotRun == Total`）加一条「`Total` 不为零」。台数对不对由 `settle_test.go` 判（它已经在判 3／2／1）。
- **分隔线那条**：数「整行都由 `=` 组成的行」出现几次，不钉宽度、不钉字符。宽度是版式，归 `message` 的自定义区与 A/B 比对。
- **版本行那两处不动**：`版本: v<号>+<短提交号> (<时间>)` 是规范四.2 写死的格式，属契约；判它是判形状。

## Testing Decisions

- 改的是两条既有红线，判据强度只降「值」那一维：形状与流向的断言一条不少。
- 指纹会变，逐条记进 Comments。
- 改完真工程整跑（`TestProjectIsClean`）仍零违规，两条红线本身绿。

## Out of Scope

- 红线区的其他文件（今天扫过，没有别的值与版式断言）。
- `message` 自定义区与 A/B 比对的口径。
