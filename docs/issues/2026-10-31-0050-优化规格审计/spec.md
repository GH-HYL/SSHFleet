# 规格审计补堵：把已定的方向逐条对账，看审计封不封得住

**Status**：ready-for-agent
**日期**：2026-10-31
**来源**：`docs/issues/2026-10-30-2134-架构重构/` 01、03 两张决策工单谈完之后

## Problem Statement

作者不读代码，架构有没有被磨掉全靠审计兜着。五个审计里，最要紧的是规格审计——**ADR 只是决策，规格才是 AI 自由发挥的地方**；ADR 写得再对，规格里一句「顺手在这里也判一下」，架构就塌了。

现状是：规格审计的判据来自十五条形状（`skills/person/audit-spec/SKILL.md`），而这十五条是在 2026-10-30 定下来的，当时结构还没谈几条。今天结算了 01、03 两张工单，新定了六条方向，其中一部分**十五条里没有任何一条接得住**——审计跑过去会一句话收尾，作者以为干净。

最典型的一条：**交接件跟上一棒一样宽**。那是最容易发生的形式主义（抄一份一模一样的，抄完还显得很守规矩），而现有第十五条只管「一个函数十个参数」，不管交接件的字段集合。

## Solution

把已定的方向逐条对账：每条问一句「照这条写歪了，现有哪条形状报得出来」。

接得住的，只记一笔；接不住的，在技能里补一句**形状**（不补判据——判据留在 ADR，技能只存「按什么形状去找」）。补完之后拿一份故意踩坑的样例规格跑一遍，确认真的报得出来，而不是补完自己以为能报。

## User Stories

1. 作为不读代码的作者，我希望规格审计能报出「交接件抄了一份一模一样的」，这样我不用靠人盯也能发现这一层被磨掉。
2. 作为作者，我希望看到一张对账表——哪条方向审计封得住、哪条封不住、封不住的补到哪一条形状上，这样下次谈新方向时知道该往哪儿加。
3. 作为写规格的执行者，我希望审计报出来的每一条都指得回某篇 ADR，而不是「通用最佳实践」，这样我知道该改哪儿、不该改哪儿。
4. 作为作者，我希望补形状这件事不把判据抄进技能——技能里只放「形状」，判据留在 ADR，改了口径只改一处。

## Implementation Decisions

**一、只补形状，不搬判据。** 技能里出现「交接件比上一棒宽」这种形状可以；出现「因为 ADR-0035 决定三」这种判据本体不行——抄一遍就有两份。每条形状后面指向对应 ADR 与工单，让人自己去读。

**二、对账表**（现有十五条按 `ADR-0033` 的分组编号）：

| 方向 | 出处 | 现有形状 | 结果 |
| --- | --- | --- | --- |
| 五站分层、单向 | 0032 一 | 丙·加站劈站并站、反向依赖 | 接得住 |
| 契约只放类型常量 | 0032 二 | 乙·契约长出行为 | 接得住 |
| 交接件必须新造 | 0032 三 | 甲·穿站回取 | 接得住 |
| **交接件必须比上一棒窄** | 0035 三 | —— | **接不住** |
| **信封按棒定，不按模式劈** | 0035 一 | 丙·加站劈站（不贴） | **接不住** |
| 横切五包各干一事 | 0032 四 | 乙·横切长出业务 | 接得住 |
| 塔尖只搬不做 | 0032 五 | 乙·塔尖变厚 | 接得住 |
| 闸门拒绝权只覆盖计划成形之后 | 0034 一 | 乙·自己退场（部分） | **部分** |
| **闸门三个出口** | 0034 二 | —— | **接不住** |
| **起不来与拒绝的构造权不同** | 0034 三 | —— | **接不住** |
| 退出只在塔尖 | 0034 四 | 乙·自己退场 | 接得住 |
| 危险检测只出判断 | 0034 五 | 乙·自己出字 | 接得住 |
| **主密钥预检查不进拒绝（行为不变）** | 0034 六 | —— | **接不住** |
| 闸门不写话 | 0034 八 | 乙·自己出字、塔尖变厚 | 接得住 |
| 载荷五份不合并 | 0035 二 | —— | 不适用（是「不做」，不是腐蚀） |
| **单台归类留在执行** | 0035 四 | 甲·同一件事算两遍（部分） | **部分** |
| 判据表进信封 | 0035 五 | 乙·塔尖变厚 | 接得住 |
| 契约不放函数、合法性由闸门验 | 0035 六 | 乙·契约长出行为 | 接得住 |

接不住的五条，加一条落得下的形状比补五条窄管用：**一个值、一件事、一个结论，被搬到了它不该在的那一站**——这是共同形状，「变宽」「错位」「出口不够」都是它的变体。

**三、样例放 `build/`。** 造一份故意踩坑的规格（在同一个场景里同时踩三条），不进版本库——它是过程产物。

## Testing Decisions

**接缝只有一个：直接读审计的输出。** 不测技能的内部措辞、不测它读了几次文件。

判据：拿样例规格跑一遍，被踩的三条坑里**至少两条要被点名列出来**，且每条都指得出对应 ADR。跑不出来就说明形状没补到位，或者补得太抽象听不懂。

## Out of Scope

- 不改十五条的判据本体（那在 ADR 里，不是技能里的事）。
- 不动其余四个审计。
- 不写机器检查脚本——那是 07 号（机械挡住）的事，与本议题不重叠：审计靠人记得跑，脚本不靠。
- 不改 `docs/adr/` 下任何一篇。

## Further Notes

- 议题的起因是一次对话：01、03 谈完之后发现审计接不住，作者决定单开。
- 这张表是「当时判断」，以后谈出新的方向，往表里加行，别删。
