# 规格：老新交集收全

**状态**：ready-for-agent
**底本**：`docs/issues/2026-11-09-0945-切换前回顾审计/修复面盘点.md` §4.7 与 §五丙批；事实底本 `audit-run-2026-11-09/回执/91-反证员.md`（91-B）
**边界**：只做机械比对与结论表；「逐字同体」的那些怎么处置由开发者定，本议题不自作主张删老工程、也不改新工程。

## Problem Statement

A9「老工程冻结」防的是「改老工程」，防不住「抄老工程」。91 求老新交集的 30 个同名符号，抽查 4 个里就有 2 个是逐字搬移（`FormatSpeed` 函数体逐字节同、`SanitizeRemark` unix 版逐字同）。剩下 26 个没判。这不动功能，动的是「新工程是重写而非搬运」这个说法——那是这场重构正当性的一半，要写进切换公告就不能留着 26 个未知。

## Solution

脚本化机械比对：老新各扫一遍导出符号，取交集，按两个口径判——**逐字同体**（去空白与注释后 token 流相同）与**判据字面量同**（函数体里的字符串字面量集合相同）。出一张表，26 个未知变已知；判出「同体」的那些逐条记在哪、要不要处置，交开发者定。人工不逐个读代码。

## User Stories

1. 作为维护者，我希望交集的每个符号都有一条结论，而不是「抽了 4 个，2 个是抄的」这种抽样印象。
2. 作为维护者，我希望「逐字同体」由机器判，不靠人眼比对两个文件。
3. 作为维护者，我希望「判据字面量同」单独成一列——正则、关键词这类字面量被抄过来，即使函数体重排过也算搬移。
4. 作为维护者，我希望结论表给出函数体哈希，别人重跑一次能复现，不用信任我的说法。
5. 作为维护者，我希望「同体」的处置（留着、改写成新结构、或写进 ADR 说明为什么可以照搬）有明确落点，而不是留一张表就完事。
6. 作为使用者，我希望这件事不改变任何行为——它只是把未知收成已知。

## Implementation Decisions

- 比对脚本放 `build/交集比对_<时间戳>/`，Go 写、只用标准库（`go/parser`、`go/scanner`），跑法是一条 `go run .`：两个参数是老工程与新工程的根目录。
- 符号面：导出的顶层函数（不含方法）、常量／变量、类型；不扫 `_test.go`、`testdata`、`cmd_scratch`。
- 「同体」判据：取该声明在源文件里的字节区间，用 `go/scanner` 取 token 流（跳过空白与注释），拼成串取 sha256 前 16 位；两份哈希相同即同体。
- 「字面量同」判据：同一区间里所有 `token.STRING` 字面量排序去重后逐项相同。
- 结论表落本议题 `audit.md`：每个交集符号一行（符号、类别、同体否、字面量同否、两侧字面量条数），表后跟一段「哪些要处置」的清单。

## Testing Decisions

- 接缝是脚本的命令行口子（两个目录参数、stdout 表格、退出码）。不测脚本内部函数。
- 判据：造一对小样本目录（一个同体符号、一个改过一格的符号、一个只有一侧有的符号），跑一次看三行结论对不对。
- 先例：09 沙盒的 `selftest.sh`（比对脚本自检）、本轮 4.4 沙盒的 `selftest_cmp.py`。

## Out of Scope

- 不改新工程、不改老工程；「同体」的处置另开单。
- 不重跑 A/B、不动红线区、不碰 4.1／4.2／4.3／4.6／4.8。
- 不判「语义等价」（那要靠人判），只报机械可比的两类。

## Further Notes

- 91 报的 30 个交集是抽样口径下的数；本议题以脚本实扫结果为准，若与 30 不符，在 `audit.md` 里写清差在哪（多半是「方法」与「包级变量」算不算的差别）。
- 结论表要能在切换公告里引用，所以每个「同体」都要给出可核对的哈希。
