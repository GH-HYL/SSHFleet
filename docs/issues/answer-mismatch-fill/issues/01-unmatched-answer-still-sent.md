# 01: 代填未命中，却像是送出了内容（1 秒多就报错退出）

Status: resolved（2026-10-07 定性并修复——脚本靠自身文件名取信息，而工具下 `$0` 不是路径）
Blocked by: 无

**现象**（用户 2026-10-07 报，现场在另一台节点上，只提供截图与日志）：

1. 触发词未命中属预期——工具里放的触发词是英文，目标机上是**中文 RPM 安装包**的提示；
2. 但终端输出里出现了「ENV」「line 1820」「line 1822」「sorry 不支持这些内容」这类内容，与脚本真实输出（截图一）的格式对不上；
3. 执行时间只有 1 秒多。按「未命中就等 `-t` 超时」的原有逻辑不该这么快——像是**有内容被送了进去**，脚本立刻报「不识别」而退出。

---

## 结论（2026-10-07 复核，代码 + 真机实跑）

第 3 条的推断**不成立**：未命中时工具一个字节都不会写进远端。收场时间与「有没有喂内容」无关，
只由**远端命令何时结束**决定。1 秒多结束，说明**脚本自己跑完（或被它自己中断）了**，
不是被工具喂了东西。

**证据一：写入口只有一处。** 全工具往交互会话 stdin 写的只有 `internal/ssh/interactive.go:165`
（`io.WriteString(stdin, text+answerEOL)`），它由 `outputHook.match`（同文件 332-342）驱动，
而 `match` 只在 `cursorMatcher.feed` 返回命中时才发 `eventSend`（`matcher.go:149-170`）。
无命中 ⇒ 无事件 ⇒ 无写入。设计稿也早写明这条（`remote-interaction/spec-已闭环.md` 四·4：「代填用尽后不做任何动作」，
五·「输入通道的关闭时机」：不关通道、不投 `^D`）。

**证据二：收场是「脚本退出 / `-t` / 中断」三者先到先得。** `driveSession`
（`interactive.go:222-271`）的 `select` 里，`done`（`session.Wait()` 返回）与 `ctx.Done()`（`-t` 到点）
是两条独立通道。脚本自己退出 ⇒ `done` 先到 ⇒ 立即收场，**根本不会走到超时**。
`verdict.go:64-67` 的分支与注释正是为这种形态写的：

```go
if res.SessionBegun && !res.Canceled && len(res.AnswersMissed) > 0 {
    res.Category = catTriggerMiss
    res.ExitCode = res.CommandExitCode // 脚本自己跑完了：定论退出码照实给（0 也是它）
```

**证据三：那几行是脚本自己的输出，且原样打印。** 明细块的 `Output` 段落直接取
`Result.Output`（`terminal.go:118-119`），而 `Output` 是采集侧（`outputtap.go`）把
会话 stdout/stderr 合并、只做了「去行尾 `\r` + 去首尾空行」后的**原始字节**，呈现层不再加工
（`terminal.go:94-95`）。工具不会往这段里写任何自己的东西。

### 真机实跑（2026-10-07，节点 = WSL2 Ubuntu 26.04，非 root 账号）

沙盒：`build/atest/`（已删），Windows 版二进制，`-t` 显式给值，两次跑都用英文触发词制造未命中。

| # | 远端脚本 | `-t` | 实测耗时 | 分类 | 明细里的 Output |
| --- | --- | --- | --- | --- | --- |
| A | `read -p "请选择架构…" arch`（阻塞等输入） | 6 | **6.0s（等满）** | 触发词未命中 | 只有脚本自己的提示一行，无任何多余内容 |
| B | 打印几行后 `exit 3`（自己提前退出） | 30 | **0.07s** | 触发词未命中 | `ENV` / `checking line 1820` / `checking line 1822` / `sorry 不支持这些内容` |

A 证明「未命中就等 `-t`」只在**脚本确实卡在等输入**时成立；B 把用户看到的现象
（一秒内结束 + 脚本自己的报错行）**原样复现**，且 `-t 30` 完全没等——说明那 1 秒多是脚本自己退的。

### 顺带确认的一件事：`-A` 不是有效开关

短选项是小写 `-a`（`args.go:288`，`StringVarP(..., "answer", "a", ...)`）。写成 `-A` 会被 pflag
判为未知短选项、直接报错，跑不起来。用户括注的「-A」按 `-a` 理解；若当时真的敲了 `-A`，
那这次运行根本没进到执行阶段，需另做确认。

## 已定性（2026-10-07）：就是「脚本靠自身文件名取信息」

开发者给出的关键线索：那个脚本**文件名本身带信息（IP）**，且脚本内部从文件名取它，再拿它做数值比较。
工具两条路径都不落盘、也就没有文件名（`$0` 是 `bash`、`BASH_SOURCE` 为空），取值落空 ⇒ 后面那句
没加引号的数值比较立刻报 `[: -eq: unary operator expected` ⇒ 脚本判「系统不支持」自行退出。
—— 这解释了「1 秒多结束 + 脚本自己的报错行」，也解释了为什么**手工跑文件正常**。

**复现（脱敏形态）**：造一份同型脚本（文件名形如 `(1.2.3.4).sh`，自己从文件名取 IP 再比较首段）：

| 跑法 | `$0` | 取到的 IP | 结果 |
| --- | --- | --- | --- |
| 当文件跑 | `(1.2.3.4).sh` | `1.2.3.4` | 正常 |
| 工具 · 无 `-a`（经 stdin） | `bash` | 空 | `[: -eq: unary operator expected` |
| 工具 · `-a`（经命令行） | `bash` | 空 | 同上 |

**三个待查方向的结案**：方向 1（脚本自定位失败）**命中**；方向 2（`isatty` 翻转）、方向 3（强制 locale / `TERM`）
**不是本病因**——现象由方向 1 单独解释即可。

| 项 | 工具 · 普通路径（无 `-a`） | 工具 · `-a` 交互路径 | 手工跑文件 |
| --- | --- | --- | --- |
| `$0` | `bash` | `bash` | 脚本真实路径 |
| `BASH_SOURCE[0]` | 空 | 空 | 脚本真实路径 |
| `TERM` | `dumb` | `xterm` | `xterm-256color` |

| stdin 是否 tty | 否 | **是** | 有 PTY 时是 |
| PTY | 无 | **200×50 有** | 有 |

其中**只有 PTY 这一列是 `-a` 引入的**（`RequestPty` 全仓只在 `interactive.go:144` 与
`passwdsession.go:72` 两处，普通路径没有）；`$0` 无路径、强制英文 locale 两条对两条工具路径**都一样**，
所以它们解释不了「只有带 `-a` 才出问题」，除非该脚本从不带 `-a` 跑过。

**三个待查方向**（按可能性排序，均需脚本或日志才能定）：

1. **脚本自定位失败**：`$0` 不是路径、`BASH_SOURCE` 为空 ⇒ `dirname "$0"` / `basename "$0"` /
   `readlink -f "$0"` / 自读自解压 / `exec "$0"` 全失效。这是「手工能跑、经工具就崩」最经典的一种。
2. **`isatty` 翻转**：普通路径 `isatty(0)=no`、`-a` 路径 `=yes`（PTY）。脚本若按
   `[ -t 0 ]` 分支，两条路会走进**不同分支**——原本不问的变成要问，或反之。
3. **强制英文 locale / `TERM=xterm`**：脚本按 locale 或 `TERM` 分支时走岔；目标机若没生成
   `en_US.UTF-8`，还会额外触发各程序的 locale 警告。

**需要的材料**（任一份都能大幅推进）：

- 当时的 `-a` 值原文（含触发词写法），以及 `[interactive]` 的 `regex` / `case_sensitive` 取值；
- 那次运行的 `terminal-output.txt` / `SSHFleetExec.log` / `results.xlsx`——**重点看「分类」与
  「未送出的代填」两行**：若有「未送出的代填：第 N 条…」，则确证一个字节都没送（假命中可排除）；
- 那个 RPM 安装脚本本体（或它的头部 100 行，看有没有 `$0`/自定位/locale 判断）。

## 修复（2026-10-07）

脚本模式把**脚本文件名交回去当 `$0`**：

- 无 `-a`（正文经 stdin）：`<解释器> -c '. /dev/stdin' '<脚本名>'`；
- 有 `-a`（正文经命令行）：`<解释器> -c "$(…base64…)" '<脚本名>'`。

两条路都让脚本里的 `$0` 等于脚本文件名，靠自身文件名取信息的脚本不再落空。提交 `b6e545f`（首次补名，
用 `exec -a`）与 `cac636a`（改用 `. /dev/stdin`，抹平 dash/ash 不认 `exec -a` 的短板）。
真机实测：`bash` / `sh` / `dash` 下 `$0` 都等于脚本名。
