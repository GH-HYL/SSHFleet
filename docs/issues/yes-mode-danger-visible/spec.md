# `--yes` 下高危档危险命令不上屏 · 规格

Status: needs-triage

> **来源**：2026-10-17 核对全仓文档时实测发现。作者反馈「印象里 `--yes` 是上屏的」，实测确认 `forbidden` 档上屏、高危档不上屏；代码上两者走的是不同分支。两档的不同见「补充说明」。

---

## 问题陈述

使用者用 `--yes` 跑无人值守的批量作业。此时工具不提问、直接执行，所以终端上看到什么，就是他**事后唯一能看到的现场**。

危险命令检查分四档。实测下来：

- `forbidden` 档（如 `rm -rf /etc`）：打印完整的禁止命令警告框，然后退出。**看得见。**
- 高危 / 中 / 低档（如 `rm -rf /var/log/app`）：**终端上什么都不出现**，只有一句「[非交互模式] 跳过执行选项/参数确认环节，直接执行」。提示只写进了日志。

也就是说：跑完一批作业，如果中间放行过一条高危命令，屏幕上没有任何痕迹。要查只能翻日志，而且得先知道有日志这回事。

`CHANGELOG.md` 里也没有任何一条交代过这个差异——使用者无从知道 `--yes` 会让高危提示消失。

| 方向 | 做法 | 代价 |
| --- | --- | --- |
| 甲 | `--yes` 下高危档也上屏一行摘要 | 无人值守场景的屏幕输出会多出提示，可能被当噪声 |
| 乙 | 维持现状，但在手册与 CHANGELOG 里写清「`--yes` 下高危提示进日志」 | 行为不变，但使用者至少知道去哪查 |
| 丙 | 给 `ConfirmReq` 补 `SkipLine`（机制已具备，见证据） | 改动最小，但要想清楚这一行写什么、会不会刷屏 |

**本 spec 不替开发者选。**

## 使用者故事

1. 作为用 `--yes` 跑无人值守的运维人员，我想在放行高危命令时屏幕上有痕迹，这样事后回看终端记录能发现「这批准过危险的命令」。
2. 作为运维人员，我想知道 `--yes` 会让哪些提示消失，这样我不会误以为屏幕上没有就是没发生。
3. 作为运维人员，我不想让无人值守的输出被大量提示刷屏，这样我抓关键结果时不用在噪声里筛。

## 实现决策

**未定。** 方案选定后填写。

已知的实现事实：

- `forbidden` 档在 `main.go:304` **无条件**调 `output.PrintDangerWarning`，所以一直上屏。
- 非 `forbidden` 档在 `main.go:310-312` 只在 `!in.Disinteractive` 时上屏。
- `Confirm` 机制里**已经有**「非交互时上屏一行」的能力：`internal/common/interactor.go:96` 的 `SkipLine` 字段。参数确认屏与 `--sudo` 被忽略两处已在用它（`confirm.go:54`、`confirm.go:123`），危险命令这处没接。
