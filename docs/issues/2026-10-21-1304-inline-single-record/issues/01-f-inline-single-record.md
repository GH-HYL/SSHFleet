# 01: `-f` 的内联值只能是一条

**要做的**：`-f` 后面给一个 CSV 文件路径、或者一行节点信息，两者由同一处判定认出来。值是路径就原样交给系统去找，不是文件才看首字段是不是 IP；`ip;;ip` 这种写法不再被当成两台机器，含真换行的值不再被当成多行，两者各有明确说法。

**被谁阻塞**：无，可立即开工。

**状态**：done（2026-10-21 实施）

- [x] `-f 10.0.0.1` 与 `-f 10.0.0.1,22,root,pw` 照常进执行，运行记录里是 1 台
- [x] 首字段带成对外层双引号（`-f '"10.0.0.1",22,root,pw'`，Excel 导出的单行 CSV 就长这样）仍认得出是 IP，按 1 台进执行；判据只剥引号，不预解析整行（引号不配对仍要报语法错，不能变成「文件不存在」）
- [x] `-f '10.0.0.1;;10.0.0.2'` 报「`-f` 参数指定的文件不存在」，运行记录里 0 台；报错里不出现任何只针对 `;;` 的说明
- [x] `-f` 的值含真换行（裸 IP 一条、带完整列一条）→ 明确拒绝，文案说清「内联值里不能有换行，多台请写成 CSV 文件」
- [x] 值里的字面 `\n`（如 `10.0.0.1,22,root,D:\new\pw.bin`）原样进字段，不被当作换行
- [x] 文件判定只按原值探测：不再把 `\` 换成 `/` 之后再试一次
- [x] 命中文件后，后续读的就是判定时那个路径字符串，不再过一遍规范化
- [x] `-f` 的报错提示里不再出现「几台」，与「只写一条」一致
- [x] 多行清单文件照旧解析（回归：文件里的多台、注释行、空行、BOM、引号都不受影响）
- [x] `go test ./internal/cli/ ./internal/nodelist/` 全绿
