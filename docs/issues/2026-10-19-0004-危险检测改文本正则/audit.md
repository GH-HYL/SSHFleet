## 二、证据 1：日常运维命令的命中率

拿 31 条**生产批量运维里正当、天天都做**的命令过现引擎，**24 条会弹警告**（77%）。

| 命令 | 现判定 | 规则名 |
| --- | --- | --- |
| `systemctl restart nginx` | low | 普通服务重启 |
| `systemctl stop nginx` | high | 强制停止服务 |
| `systemctl disable telnet` | medium | 禁用系统服务 |
| `yum update` | low | 软件包更新 |
| `yum remove telnet` | low | 软件包删除 |
| `rpm -i --force ./pkg.rpm` | low | 强制安装软件包 |
| `rpm -e --nodeps oldpkg` | high | 强制软件包删除 |
| `chmod 777 /tmp/upload` | medium | 权限修改 |
| `chmod u+s /usr/local/bin/mytool` | medium | 设置SUID权限 |
| `chown root:root /etc/myapp/conf` | medium | 修改文件所有者 |
| `sysctl -w net.ipv4.ip_forward=1` | medium | 修改内核参数 |
| `iptables -F` | high | 清空防火墙规则 |
| `passwd -l olduser` | medium | 锁定用户账户 |
| `userdel -r tempuser` | high | 删除用户账户 |
| `groupdel tempgroup` | medium | 删除用户组 |
| `rm -f /tmp/cache.lock` | medium | 强制删除 |
| `rm -rf /tmp/build_cache` | high | 递归强制删除 |
| `rm -f /var/log/app.log` | high | 强制删除配置或日志文件 |
| `history -c` | low | 清空命令历史 |
| `shutdown -r +10` | **forbidden** | 系统关机 |
| `reboot` | **forbidden** | 系统重启 |
| `init 6` | **forbidden** | 运行级别6 |

**不响的 7 条**：`systemctl start` / `enable` / `daemon-reload`、`yum install`、`chmod 775`、`chown -R www:www`、`find -delete`。

**结论**：现规则把大量**正当运维动作**判成危险。使用者每批作业都会被弹一次，几次之后就会对提示整体脱敏——包括真正该看的那几条。

## 三、证据 2：`forbidden` 档的代价是「整批作废」

`modules/SSHFleet_Go/main.go:302-307`：`forbidden` 命中即打印警告框、`os.Exit(1)`，**不看 `--yes`**。

实测（`--yes` 下）：

```
$ ./bin/SSHFleet.exe -c "reboot" --yes
✕  发现禁止命令  ✕
    规则: 系统重启
    级别: 禁止
[退出码 1]        ← 命令未执行，整批作业终止
```

而 `shutdown -r +10`、`init 6` **同样落 forbidden**。这三条在滚动重启、内核升级后重启、按计划重启里都是**正当操作**。

**结论**：`forbidden` 档的一条误报 = 使用者整个批量作业作废。这个档位只配留给「执行了就真会毁机器、且几乎不可能是本意」的命令。

## 四、证据 3：非 shell 语言的漏报与误报（实证 spec 原判断）

spec「问题陈述」原先标注「未经探针实证」。现已在包内实证：

| 输入 | 现引擎判定 |
| --- | --- |
| `rm -rf /etc`（bash） | forbidden / 递归删除系统目录 |
| python `os.system("rm -rf /etc")` | **不响（漏报）** |
| python `subprocess.run([...])` | **不响（漏报）** |
| python `shutil.rmtree("/etc")` | **不响（漏报）** |
| perl `system("rm -rf /etc")` | **不响（漏报）** |
| node `execSync('rm -rf /etc')` | **不响（漏报）** |
| php `shell_exec('rm -rf /etc')` | **不响（漏报）** |
| lua `os.execute("rm -rf /etc")` | **不响（漏报）** |
| ruby 反引号 `` `rm -rf /etc` `` | forbidden（**唯一侥幸命中**） |
| python `print("reboot")` | **forbidden / 系统重启（误报）** |

**同一台机器、同一条 `rm -rf /etc`**：写成 bash 拦得住，写成 python / perl / node / php / lua **整条溜过去**。

`print("reboot")` 那一行同时实证了 ADR-0019 记下的「误伤明示为可接受」。

## 八、证据 6：现存规则的实际失效面

除了「该弹的不该弹」，还有「该弹的弹不出来」。以下**全部实测**：

### 8.1 反向误伤：救火动作反被 forbidden 拦死

| 命令 | 判定 | 问题 |
| --- | --- | --- |
| `shutdown -c` | **forbidden / 系统关机** | **撤销**已计划的重启，是救火动作，却被整批拒绝 |
| `shutdown +0 -c` | **forbidden / 系统关机** | 同上 |

`regex = '\bshutdown\b'`（配置第 63 行）只要见到 `shutdown` 就判，不给任何参数区分。**这是现规则里最荒诞的一处**：想取消误发的重启，工具反而不让取消。

### 8.2 漏报：切断自己管理通道的动作没规则

| 命令 | 判定 | 说明 |
| --- | --- | --- |
| `systemctl stop sshd` | **不响** | 停了 sshd 就再也连不上这批机器 |
| `systemctl stop network` | **不响** | 停网络同理 |
| `systemctl stop mysql` | high / 强制停止服务 | **反而有规则** |

现规则「强制停止服务」的正则是 `(?:mysql|nginx|apache)`（配置第 140 行）——**枚举恰好反了**：列上了业务服务，漏掉了会切断管理通道的 `sshd` / `network`。

### 8.3 漏报：现代云主机盘符不在覆盖内

| 命令 | 判定 |
| --- | --- |
| `dd if=/dev/zero of=/dev/nvme0n1` | **不响（漏报）** |
| `dd if=/dev/zero of=/dev/sda` | forbidden / 销毁系统数据 |
| `mkfs.ext4 /dev/nvme0n1p1` | high / 格式化文件系统（**靠兜底规则侥幸命中**） |

盘符正则只认 `(?:sd|hd|vd)`。**现在大多数云主机是 NVMe**，抹盘规则对它们是空的。

### 8.4 漏报：旗标夹在中间（部分成立）

| 命令 | 判定 |
| --- | --- |
| `rm -R -f /var/log/app` | high / 递归强制删除（**命中**） |
| `rm --recursive --force /var/log/app` | high / 递归强制删除（**命中**） |
| `chmod -R 777 /var/www` | **不响** |
| `chown -R root:root /var/www` | **不响** |

rm 那两条没问题（旗标归一在工作）。**只有 chmod / chown 的正则不接受中间夹 `-R`**——所以「`-R` 递归改权限」这件事整个没被覆盖。

### 8.5 漏报：Debian 系包管理整体缺席

| 命令 | 判定 |
| --- | --- |
| `apt-get remove nginx` | **不响** |
| `apt-get upgrade` | **不响** |
| `dpkg -P nginx` | **不响** |

规则里只有 `yum` / `rpm`（CentOS 系）。**目标机是 CentOS + Debian 混布，Debian 那一半完全没有包管理检测。**

### 8.6 漏报：其他高危动作没有规则

全部实测**不响**：`fdisk /dev/sda`、`wipefs -a /dev/sda`、`shred -u /etc/shadow`、`> /etc/fstab`（截断关键文件）、`rsync -a --delete`、`iptables -P INPUT DROP`、`systemctl stop firewalld`。

## 九、逐条删减范围（结论）

### 9.1 定案判据

**判据只有一条**：这条规则防的，是不是「生产批量作业里**绝无正当形态**」的动作？

- **是** → 可留 `forbidden`（因为误报几乎不存在，而后果是整批作废，全档只留给它）
- **不是、但后果重且难回滚** → `high` / `medium`，用**一次确认**兜住
- **是日常正当操作** → **删**

**`low` 档整体取消**，理由：`main.go:301-337` 里 `high` / `medium` / `low` 走**同一条**确认路径，`output/danger.go:45-50` 里 `low` 只换颜色和措辞——三档**没有任何行为差异**。留着 `low` 只是「看起来提醒过」。

> 注意：`--yes` 下三档**都会打印完整警告框**（证据 4），只是不阻断。所以删 `low` 丢掉的不是「视角」，而是「一条穿了却不合身的衣服」——使用者照样从框里看见内容，只是不再被一个不承担任何后果的分类搅乱视线。

### 9.2 结果：38 条 → 19 条（→ 17 条，见文末「更新记录」）

**`forbidden` 6 条**（原 10 条）

| 保留 | 变化 |
| --- | --- |
| 递归删除根目录 | 吞并 `--no-preserve-root` |
| 递归删除系统目录 | 保留 |
| 格式化主盘 | 原「格式化系统盘」 |
| 抹盘 dd | 原「销毁系统数据」 |
| 关机停机 | 原「系统关机」，**重写正则**：只认 `shutdown -h` / `-P` / `now` / `poweroff` / `halt` / `init 0`，**排除 `-c`** |
| 杀光进程 | 原「杀死所有进程」，保留（误报≈0） |

**`high` 7 条**（原 9 条）

| 保留 | 变化 |
| --- | --- |
| 系统重启 | **由 forbidden 降档**，吞并「运行级别6」；正则含 `reboot` / `shutdown -r` / `init 6` |
| 递归删除 | **由 medium 升档**，吞并原「递归强制删除」 |
| 屏蔽关键服务 | 保留，**`firewalld` 移出名单**（CentOS 习惯性 mask firewalld 是日常）；移出后它的 `mask` 与 `disable` **统一归 medium 的「停止·禁用服务」**——两者是同一件事的两种强度，不能一个 forbidden 一个 medium（实测：`mask firewalld` 现为 forbidden、`disable firewalld` 现为 medium，自相矛盾） |
| 清空防火墙 | 原「清空防火墙规则」，保留 |
| 强制删包 | 原「强制软件包删除」，保留 |
| 格式化非主盘 | 原「格式化文件系统」，保留 |
| dd 覆盖非主盘 | 原「数据覆盖操作」，保留 |

> **`shutdown -c` 的处置（开发者 2026-10-19 第二次定）：不新增规则，只在「关机停机」里过滤掉**。`shutdown ... -c` 是撤销已计划的关机/重启，不该被判成关机（现规则 `\bshutdown\b` 会把它拦成 forbidden，救火动作反被整批拒绝——见 8.1）。
>
> **怎么过滤**：Go 的 `regexp`（RE2）**不支持负向断言** `(?!...)`（沙盒实测：`Compile` 报 `invalid or unsupported Perl syntax`），所以不能写「shutdown 但不含 -c」。可行写法是**整行锚定 + 字符类排除**：`shutdown` 起、行内出现停机语义（`-h` / `-P` / `now`）、且**一直约束到行尾都不出现 `-c`**。
>
> 沙盒实测 10/10 通过——`shutdown -h now`、`shutdown now`、`shutdown -h +10`、`shutdown -P now`、`shutdown -h now -t 5` 全命中；`shutdown -c`、`shutdown +0 -c`、`shutdown -h +10 -c`、`shutdown -r +5`、`reboot` 全不命中。
>
> **两个坑，实施时别再踩**：① 不能省掉行尾锚定——只写到 `(?:-h|-P|\bnow\b)` 就早退，后面的 `-c` 看不见（首版实测漏了 `shutdown -h +10 -c`）；② 「先匹配再过滤」那种两层写法在规则层没有钩子（`rules.go` 的 `match` 只有 `MatchString`），所以过滤必须编进正则本身。

**`medium` 6 条**（原 13 条）

| 保留 | 变化 |
| --- | --- |
| 删除关键路径文件 | **合并原 4 条** rm 规则（删除日志文件 / 删除系统文件 / 强制删除配置或日志文件 / 强制删除），只认 `/etc`、`/var/log`、`/boot` 这类关键路径 |
| 停止·禁用服务 | **合并**「强制停止服务」+「禁用系统服务」，**名单改为会切断管理通道的**（sshd / network），不再枚举业务服务 |
| 删除账户·用户组 | **合并**「删除用户账户」+「删除用户组」 |
| 权限修改 | 保留（others 可写） |
| SUID·SGID | **合并**「设置SUID权限」+「设置SGID权限」 |
| 清空系统日志 | 保留 |

**`low` 0 条**——档位整体取消。

### 9.3 原 38 条的逐条去向

38 条去向必须闭合。**闭合式：19 条保留 + 9 条净删除 = 28**；但保留的 19 条里，有 10 条是由两条原规则合并而来，于是 `19 + 10（被吞并）+ 9 = 38`。

#### (1) 保留的 19 条：各自承载哪些原规则

| 递归删除根目录 | 递归删除根目录 + 使用 --no-preserve-root 危险旗标 | forbidden |
| 递归删除系统目录 | 递归删除系统目录 | forbidden |
| 格式化主盘 | 格式化系统盘 | forbidden |
| 抹盘 dd | 销毁系统数据 | forbidden |
| 关机停机 | 系统关机 + 运行级别0 | forbidden |
| 杀光进程 | 杀死所有进程 | forbidden |
| 系统重启 | 系统重启 + 运行级别6 | high（原 forbidden） |
| 递归删除 | 递归强制删除 + 递归删除(medium) | high（原 medium，升档） |
| 屏蔽关键服务 | 屏蔽关键服务 | high |
| 清空防火墙 | 清空防火墙规则 | high |
| 强制删包 | 强制软件包删除 | high |
| 格式化非主盘 | 格式化文件系统 | high |

| 删除账户·用户组 | 删除用户账户 + 删除用户组 | medium |
| 权限修改 | 权限修改 | medium |

**被吞并造成的净减少是 10 条**：上表 19 条保留规则一共承载了 **29 条**原规则，29 − 19 = 10。拆开看：`删除关键路径文件` 是四合一（净减 3），`递归删除根目录`、`关机停机`、`系统重启`、`递归删除`、`停止·禁用服务`、`删除账户·用户组`、`SUID·SGID` 这 7 条各是二合一（各净减 1，合计 7），其余 **11 条**是一对一保留——3 + 7 = 10 ✓，11 + 7 + 1 = 19 ✓。

#### (2) 净删除：9 条，判为日常正当操作

| 删除的原规则 | 原档 | 理由 |
| --- | --- | --- |
| `修改文件所有者` | medium | `chown root:root /etc/myapp/conf` 是部署家常动作，每次都弹没有信息量 |
| `修改内核参数` | medium | `sysctl -w` 是调优日常；持久化配置在 `/etc/sysctl.d/`，不走它 |
| `锁定用户账户` | medium | `passwd -l` 是封账号的日常动作（离职、应急） |
| `软件包更新` | low | `yum update` 是例行运维 |
| `软件包删除` | low | `yum remove` 是例行包管理 |
| `强制安装软件包` | low | `rpm -i --force` 是装包的常规手段 |
| `清空命令历史` | low | 与危险无关——只影响追溯，不影响系统状态 |
| `运行级别切换` | low | 与 `reboot` / `shutdown` 语义重复；`init 3` 在生产里罕见 |
| `普通服务重启` | low | `systemctl restart nginx` 是最高频运维动作，弹它就是纯噪音 |

#### (3) 闭合校验（以本表为准）

| 项 | 条数 |
| --- | --- |
| 原规则总数 | 38 |
| 保留为独立规则 | 19 |
| 其中「两条并一条」造成的原规则减少 | 10 |
| 净删除 | 9 |
| **合计** | 19 + 10 + 9 = **38 ✓** |

分档闭合：`forbidden` 10 → 6；`high` 9 → 7；`medium` 13 → 6；`low` 6 → 0。**6 + 7 + 6 + 0 = 19 ✓**

> **9.3 之后的变化**（2026-10-19 开发者定案 J、K）：`格式化非主盘` / `dd 覆盖非主盘` 两条**删掉**，`mkfs` / `dd` 一律 forbidden 并不分主次盘符；规则新增 `reason` 说明字段。这两处改动**不否定**上表的合并与删除判决，只把 high 档再减 2 条、最终落到 17 条。详见文末「更新记录」。

### 9.4 与独立分析的差异（保留分歧）

另有一份独立只读分析（子 agent），结论同为「38 → 19、forbidden 10 → 6、取消 low」，逐条判决与本文高度吻合。**两处差异按本文口径**：

## 十、落地时必须处理的技术约束（均已定，不是待定）

> 本节标题原为「遗留待定」，但四项在 2026-10-19 都已定死，改标题以免实施者以为还有未决项。四项分别承接在哪条工单里，见各小节末尾。

### 10.1 旗标写法归谁吃 → **已定，见 spec 定案 H**

配置头注释第 23-24 行向使用者承诺过「**不用管用户怎么写旗标：工具会先归一化**（`-rf` / `-r -f` / `-R` / `--recursive` 都算 `-r`）」。**这个承诺随旗标归一退役而失效**，两条路：

1. **每条规则自己吃下全部旗标变体**——一条规则挂多条正则（定案 A 已支持数组）；配置头注释改写为「旗标写法要自己列全」。
2. **保留一道轻量旗标归一**——与「判定对象是原始文本」的原则拉扯，且定案 C 已明确「rm 旗标归一」退役。

**已定：走第 1 条**（spec 定案 H）。承接工单：**05**（递归删除的六种旗标写法）、**08**（配置头注释改写）。

### 10.2 `Match.Line` 的形态要变 → **已定：改为可承载多个行号**

定案 B 要求「同规则多命中合成一条、行号处列出全部（如 `行号: 3, 7, 12`）」。但现状：

- `judge.go` 的 `Match.Line` 是**单个 `int`**；
- `output/danger.go` 按 `%d` 渲染单个行号；
- `main.go` 的日志也按单值取。

**实现时必须把行号改成可承载多个值的形态**，并同步改 `danger.go` 的渲染与 `main.go` 的日志。这是一处**跨包的字段变化**，`internal/output/danger_test.go` 也要跟着改。承接工单：**01**（引擎产出多行号）。

> 这与 spec「测试决策」的接缝约定不冲突——接缝管的是 `Analyze` 的**入口**；`Match` 的**字段形态**不在那条约束里。

### 10.3 覆盖缺口要不要补进新规则 → **已定：本轮只删不增，三个例外**

证据 8 列出的漏报里，**NVMe 盘符、`sshd` / `network` 名单、`shutdown -c` 过滤**属「把既有规则改对」，本轮做（spec 定案 G 的三条例外，承接工单 **04**、**06**）；**Debian 系包管理、`fdisk` / `wipefs` / `shred`、`> /etc/fstab`、`iptables -P DROP`** 属新增，本轮不做，另开议题。

### 10.4 `minRules = 10` 的下限 → **已定：本轮不动**

`rules.go` 的 `minRules = 10` 是「防整份文件被误删」的下限。删减到 17 条**仍安全**（17 > 10）。本轮不动；若日后把规则再砍到 10 条附近，必须重新评估这个下限。
