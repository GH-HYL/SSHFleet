# 规格：阶段 05——另外四种模式

**Status**：ready-for-agent

## 边界（照抄母规格三条）

- **结构检查先于业务代码**：它要在骨架建好的第一时间就能跑，后面每搬一块才有判据。
- **红线区的测试只放结构**，不断言值；它的名单与指纹集中一处，改它要走议题加 ADR。
- **不改行为**：老版怎么跑，新版就怎么跑。

**本阶段不覆盖母规格之外的任何改动。**

## Problem Statement

运维人员要的不止「跑一条命令」。真实的一天是这样：把一个部署脚本推到几十台机器上跑（`-s`）、把构建产物传到 `/opt/app/`（`-u`）、把日志收回来（`-d`）、把一批密码过期的账号改成同一个新密码（`--change-password`）；跑之前还会期望工具在遇到 `[Y/n]` 那种提问时按他写好的表自动填（`-a`）。

新工程今天这五件事里只做成了一件：解析认得出五种模式、闸门判得出该不该跑，可**确认屏只摆得出命令与脚本两行**，执行站的入口只实现了命令那一支，报告也只会印「执行命令」。也就是说，除 `-c` 之外的四种，敲下去要么在屏幕上看到一份信息不全的确认屏，要么跑到一半停在一个与它无关的地方——**这个工具今天还只服务一种用法**。

## Solution

把另外四支补齐，一条一支，各自端到端跑通：

- **脚本**：按脚本后缀选解释器（没配到就问一句是否回退），正文经 stdin 送下去执行。
- **上传**：确认前把本机要传的东西严格采集一遍（软链接过滤、FIFO/设备/套接字拒收、逐项可读），屏幕摆出内容树与按大小给出的并发建议；执行站走 SFTP 传，sudo 时经远端暂存目录落位，装不下就在写第一个文件之前停下，中途失败把本次写进去的全部删掉。
- **下载**：按远端路径枚举文件（软链接过滤但列出），按 IP 建子目录、保留远端相对层级，半成品就地删掉。
- **批量改密**：分配 PTY 下发一条空命令，按提示词表认出远端在问什么、喂当前密码与新密码；整场有没有出现过「密码过期」的信号、有没有早收场、喂进去过没有，都记成事实。
- **代填**（命令与脚本模式下的 `-a`）：正文 base64 编进命令行，会话 stdin 整条让给代填；命中触发词就填、命中中止词就停，没送出去的条目在结果行里点名。

做完之后，五种模式各自的屏幕、`report.txt`、`terminal-output.txt` 与执行期日志与老版对得上；`-a` 的下发行有一个写死的字节上限，超了在连机器之前就报。

## User Stories

1. 作为运维人员，我用 `-s deploy.sh` 跑一个本地脚本，屏幕上的确认屏告诉我脚本路径与这次用的解释器，跑完与命令模式同一个样子。
2. 作为运维人员，脚本后缀没在配置里登记时，工具当场问我一句「继续用 bash 吗」，答否就退出、不留痕。
3. 作为运维人员，我用 `-u ./dist -p /opt/app/` 上传，确认屏先列出这次要传的东西（一层树）与总大小，按大小建议的并发数问我要不要采纳。
4. 作为运维人员，上传源里有软链接时它们被跳过并在结果明细里点名；有 FIFO 或不可读文件时在确认之前就报出来，不会出现「点了 y 才失败」。
5. 作为运维人员，上传中途某一台失败，那台目标机上不会留下本次写进去的任何文件。
6. 作为运维人员，我用 `-d /var/log/app -p ./logs/` 收日志，文件落在 `./logs/<IP>/...` 下，层级与远端一致；软链接被跳过但能看到跳过了哪些。
7. 作为运维人员，我用 `--change-password` 把一批过期账号改密，屏幕上看到的是脱敏后的新密码；没到期的机器不报错，报「密码未过期」。
8. 作为运维人员，我用 `-a "y,是否继续"` 跑一个会问话的脚本，工具替我答；有哪条没送出去，结果行里点名。
9. 作为运维人员，我给的脚本配上 `-a` 之后太长（正文超七万字节）时，工具在连机器之前就告诉我太长、并说清上限。
10. 作为维护者，`report.txt` 的「执行参数」段在五种模式下印的是各自该印的那几行（脚本路径 / 上传的本地与远程 / 下载的远程与本地 / 新密码脱敏形态 / 代填明细）。
11. 作为维护者，执行期日志在五种模式下各印各的：传输类是「上传完成：成功 3/3 个文件（共 12.3KB），耗时 0.4s」，改密是「改密失败，耗时 0.2s」，命令与脚本带退出码；连接那一级补齐「登录方式」。
12. 作为维护者，五种模式各自的「成功」都只有一条判据（分类 = 本模式的成功分类），执行站一个「成功/失败」的字都不写。
13. 作为维护者，`go build`／`go vet`／`gofmt -l .`／`go test ./...`／`go test -race` 全绿，真工程仍报「17 包零违规」。

### 二、纸上补什么（这一节是 Q3 的落法）

**先定口径**：下面这些格子**不算加格**。加格是给后续割接扩容用的；这一批不是扩容，是**当初定不了内容的格子把内容补上**——五份载荷当初只落了命令模式那一支，`-a` 与改密根本没进讨论，`PasswdTask` 里那行「解密码随阶段 05」就是当时立的字据。所以照「补既定载荷」办，不单独点头；留痕在 `map.md` 框架条目加一行。

| 位置 | 补什么 | 谁读 |
| --- | --- | --- |
| `Task.Passwd.NewPassword` | 解析后的明文（加密开着时从密文文件解出来） | 执行站喂 |
| `Task.Upload.Files`、`Task.Upload.Skipped`、`Task.Upload.TopEntries`、`Task.Upload.TotalBytes` | 采集后的可传文件表（路径、相对路径、大小）、被过滤的链接、**上传根下一层的条目**（名字 + 是不是目录）、**总大小** | 执行站传；闸门摆树与印「上传总大小」。总大小由解析站算一次放纸上——它是建议并发所依据的那个数，闸门再求和一遍就是同一个数两个产出地 |
| `Task.Command`／`Task.Script` 增 `Answers` | 代填表（内容 + 触发词，顺序即命令行顺序） | 执行站喂、报告印明细 |
| `Resources.Script` | 脚本路径；报告「执行参数」段要印 | 报告 |
| `RunParams.SudoGiven` | 命令行上到底给没给身份开关（`--sudo` / `--no-sudo`）——改密那两条互斥要靠它，纸上原来只有结论 | 闸门 |
| `RunParams.MatchRegex`、`RunParams.MatchCaseSensitive` | 配置 `[interactive]` 的两格原值：代填与改密认触发词时按不按正则、区不区分大小写 | 执行站匹配（它不读配置） |
| `RunParams.ConcurrencyAdvice` | 按上传总大小与配置阈值算出的建议并发，0 表示没有建议 | 闸门（问那一句） |
| `RunParams.FallbackExt` | 脚本后缀没配到解释器时那个后缀，空串表示配到了 | 闸门（回退确认） |
| `NodeResult.AuthMethod` | 握手实际用上的登录方式（密码 / 密钥 / 密钥+密码） | 执行期日志（老版有这一句，04 因纸上没这格宁缺不猜） |
| `NodeResult.Steps` | 中间步骤的退出码（下载的 `test -e` 与 `find`、改密的 `:`） | 结果行与日志的「中间步骤」 |
| `ResultPaper.Extra` 的 `Transfer` | 传输类的四个数：总文件、成功、失败、字节 | 判定、结果行、日志、07 的表格 |
| `ResultPaper.Extra` 的 `Answer` | 未送出的代填序号、表已空仍超时（代填发生在命令与脚本两种模式下，这一格在两种模式下都可能非空） | 结果行（点名哪几条没送出去） |
| `ResultPaper`／`Ledger` 的 `Concurrency` | 这次**实际生效**的并发数——执行站开工时从纸上抄一格带下来 | 报告（`report.txt` 的「并发数」那一行） |
| 运行上下文（密文）增 `ScriptPath`、`UploadSource`、`UploadTarget`、`DownloadRemote`、`DownloadLocal`、`NewPassword`、`Answers` | 报告「执行参数」段要印的原值 | 报告 |

**并发数为什么从密文挪到第三张纸**：闸门那一问可能把它改掉（第四节），而密文在解析站返回前就封好了，闸门碰不到它。留在密文里，报告印的会是**改之前**那个数，而老版印的是采纳之后的值。所以这一格由执行站按纸上生效值带进第二、三张纸，密文里不再装并发；三个超时不会被改，仍留在密文。

**新密码为什么装明文而不是装遮好的形态**：`mask` 那条结构决定是「谁要谁现算，不产生字段、不往下传——把已经遮好的值装进纸里等于凭空多一格」。所以密文里装明文，报告站印之前自己调 `mask` 算一次（04 的报告站本来就在遮命令行与清单）。代价是这份凭据在 `Task` 与密文里各携一份，但产出地只有解析站一处。

**代填明细那一份怎么到报告站**：`Task.Answers` 给执行站喂，报告要印的那份由解析站**同一次成表**后再封进密文——不是让报告站回源头把 `-a` 重读一遍（那是解析站已经做过的活）。

**为什么报告那几件走运行上下文**：15 号单开过先例（报告站缺的两样进 `RunMetaBody`、`RunParams` 一动没动）。报告要印的那几件属于「这次要干什么」，进密文那一段最省，纸上因此一格都没变宽。

**唯一的例外是并发数**：它会被闸门改，而密文封在改之前——所以它走第三张纸（见上面那条说明），别顺手往回加。

### 三、代填的下发与长度：一个常量，不住执行站

**这一节定的是原来那处打架**：ADR-0010 的 2026-10-09 补充要求「参数合规检查阶段拼一次、存起来，量的串＝发的串」；而新工程把下发行的拼装收进执行站一处（`execute/build.go` 的 `downCommand`，ADR-0015 末尾「envPrefix 落点全归 execute」）。

**开发者 2026-11-03 定**：「执行站量是没必要的，因为不需要准确值，咱们给个经验值的常量就行，如果一个脚本都超了，也不在乎那一点抠细节抠出来的空间大小了。」

落法：

- **拼装仍只在执行站一处**（结构不动）。
- **上限判据改成正文的字节数**：`answerBodyLimit = 70000`，常量写死在解析站。老版的上限是整条下发行 98304 字节，它自己的报错文案里写的就是「请把正文控制在 7 万字节以内」——这个常量不是新拍的数，是那句文案回推出来的。
- **判在解析站**（它手上有正文，读脚本时一并量），报「起不来」，外壳仍是「选项/参数合规性检查未通过」。
- **文案少一格**：「下发 N 字节」那一格给不出来了（没有下发行可量）。新文案：`-a 参数下发的命令太长：正文 %d 字节，上限 %d 字节` + 提示。**记一条已知差异**：这一条报错与老版不逐字相同，只在正文超七万字节时可见。
- 上限之外，`-a` 的其余四条检查（与 `-u`／`-d`／`--no-shell` 互斥、来源判定、解析、触发词校验）照老版原样。

**同一类的第二处差异：表外解释器**。老版在解析阶段就拦下「`-a` 配了一个不会按程序文本接正文的解释器」并列出支持范围。那条判据要一张「解释器 → 程序文本参数」的表，而这张表**只有一处主人**：执行站（它决定下发行怎么拼）。解析站拿不到它，硬判就要抄第二份表。

落法：**表住执行站一处**，判也在执行站（拼下发行那一步），判不过返回「起不来」。**表里只放机器要的东西**（程序文本参数、是不是 shell 家族、`$0` 怎么补），不放句子、也不放显示顺序——「目前支持：…」那句由 `message` 按名单拼，执行站只交「哪个名字不在表里」这条事实。代价与上一条同类——报错从确认屏之前挪到之后，只在「`-a` + 表外解释器」这种组合下可见，记成已知差异。

### 四、闸门可以在原纸上改值（这一节是 Q2 的落法）

**先答那句问**：**改值不是造新纸。** 纸还是同一张，格子还是原来那几格，改的是一个已有格里装的值。造新纸指换一张纸、加格子，或把某一格的口径换掉。

**调查结果（老版这一棒只有一处改值）**：

- `confirm.Confirm` 里 `args.Number = nodes.Len()`（未给 `-n` 时补默认）与 `suggestUploadConcurrency`（采纳建议后改并发）——**改值**。
- `CheckArguments` 里 `a.Path`／`a.Download` 的去空白——老版在 `Parse` 里就先 trim 过一次，属解析站的事，本阶段落在解析站，**不进闸门**。
- 其余（`FIsInline`、`Answers`、`Downlink`、`NewPassword`、节点字段补全）都由解析/凭据产出，闸门只是判。

所以全工具只有**一处**：上传并发建议。

**开发者的落法**（2026-11-03 原话：「如果有，那个原样交接的决策就废弃，当时决策没有想到那么多，废弃后，也就等宽约束了，改值这算不算造新纸」）：

- 「闸门这一棒等宽」那条**不再约束「不改数据」**那一半——它当时没想到闸门会遇上「问一句就可能改一个执行参数」的场合。**不造新纸**那一半继续有效。
- 闸门准改的**只有 `RunParams.Concurrency` 这一格**，而且只在「这次是上传、解析站算出了建议、且建议值不同于当前生效的并发数」这一种情形下（没给 `-n` 时当前生效值就是节点数——老版在问之前已经把它补成节点数了）。改完把参数屏重显一次、并发数那行加粗（老版同观感）。
- 留痕三处：`ADR-0035` 末尾更新记录、新开 `ADR-0040`、`map.md` 框架条目一行。

### 五、执行站按模式加文件，不给既有函数加分支

04 规格第四节那句继续算数：**加文件，不给既有函数加 `if 模式还不支持`**。

- 入口 `execute.Run` 已经按 `p.Mode` 走到 `visit`；`visit` 里那句「本阶段只有命令模式有下一步」换成一次按模式的分派，分派体各自一个文件：`run_script.go`、`run_answer.go`、`run_upload.go`、`run_download.go`、`run_passwd.go`。
- 每个文件只做「建连之后这一步」，建连、收尾、分类仍由 `visit` 收口——那是 04 定的，不动。
- 传输类不进结果行的屏幕那一路（老版：上传下载的明细只进 `terminal-output.txt` 与进度面板），入口处按模式分一次流，不散在各个结果里。

### 六、判定：四条成功规则与两组选组

照 `verdict.Judge` 的老口径逐条搬，**一条值断言都不进红线区**：

| 模式 | 成功规则 |
| --- | --- |
| 脚本 | 与命令同：会话起来了、退出码为 0、没超时没取消、报错原文里没有工具自己的报文（代填没送完那一类） |
| 上传 / 下载 | 连上了、失败文件数为 0、成功文件数 > 0、没超时没取消 |
| 改密 | 干净收场（没超时没取消、没早收场、报错原文为空、下发的 `:` 不是非 0）**且**整场出现过入场信号 |

**分类选组**：目的命令给了退出码 → 第二组；否则第一组；**改密且已见过入场信号时只拿报错原文匹配**（那句「密码过期」的提示是改密的前提，不是失败原因）。

**入场信号的关键词从哪来**：判据表里名为「密码过期」的那一类（分类名是常量，住 `message`）。那张表为空时，03 已经落成「启动即报」的行为例外，本阶段不动它，只让执行站取到同一份。

## Comments

### 2026-11-03：开工前三件要定的事，开发者当日定了

**一、代填下发行的拼装与长度**。原争点：ADR-0010 补充要求「参数阶段拼一次、量的串＝发的串」，ADR-0015 末尾把拼装落点整个判给执行站，两处对着干。开发者原话：

> 执行站量是没必要的，因为不需要准确值，咱们给个经验值的常量就行，如果一个脚本都超了，也不在乎那一点抠细节抠出来的空间大小了。

落法见第三节：拼装仍在执行站一处，上限改成正文 70000 字节的常量、判在解析站、报起不来，文案少「下发 N 字节」一格并记成已知差异。

**二、闸门要不要能改值**。原争点：上传并发建议要改 `RunParams.Concurrency`，而「闸门这一棒等宽、不造新纸、不加数据格」写在 04 的结账记录里。开发者原话：

> 你看看闸门还有没有类似的情况，他需要改格子值的，如果有，那个原样交接的决策就废弃，当时决策没有想到那么多，废弃后，也就等宽约束了，改值这算不算造新纸

**调查结果**：老版在闸门这一棒只有一处改值——`confirm.go` 里的上传并发建议（未给 `-n` 时补默认那处是同一个动作的另一半，本阶段由 `concurrencyValue` 算，不改纸）。远端路径去空白那处老版在 `Parse` 里先做过，属解析站。所以「改值」只有一个口子。

**据此定**：那条「原样交接、不动纸」不再约束「不改数据」，只保留「不造新纸」；**改值不算造新纸**（纸同一张、格子同一套、改的是一格的值）。准改的只有 `RunParams.Concurrency` 一格，且只在上传 + 有建议 + 建议值不同于当前生效值这一种情形。留痕：ADR-0035 末尾更新记录、ADR-0040、本图框架条目一行。

**三、纸上补格算不算加格**。开发者原话：

> 这个是之前没有考虑到了，所以严格上来说，不算加格，因为之前的格子内容就定不了，加格是给后面割接使用的，都没考虑 -a 个改密的情况，现在加上，怎么算加格行为呢

**据此定**：第二节那一批不算加格，是补当初定不了的内容，不单独点头；清单落在第二节与 `map.md` 框架条目一行。
