# 15: 改密会话把两个密码喂进去

**要做的**：给一台机器分配 PTY、下发一条空命令，按提示词表认出远端在问什么、喂当前密码与新密码；整场出现过「密码过期」的信号、有没有早收场、喂进去过没有，都记成事实。做完之后，一批过期账号能一次改完。

**Blocked by**：07（新密码）、01（纸与判据表）。

**Status**：已完成（done）

- [ ] 提示词表与匹配口径来自纸上的判据表；入场信号的关键词取「密码过期」那一类（分类名住 `message`）
- [ ] 采集到的输出里，本次喂进去的两个密码都抹成 `****`（远端何时关回显不由我们定，可能落在任意一处）
- [ ] 收尾三句各就各位：干净收场且没见入场信号 ⇒ 「密码未过期」；早收场、喂了不收、提示没认出来各一句；干净成功一个字不写
- [ ] 下发的 `:` 是中间步骤，退出码进「中间步骤」，**不顶成结果退出码**
- [ ] 集成用例：`chage -d 0` 的账号改密成功；未过期账号不报错；密码表缺关键词时启动就报（03 那条行为例外不回归）
- [ ] 判定：干净收场 + 见过入场信号 ⇒ 成功；超时／取消／早收场／`:` 非 0 ⇒ 失败
- [ ] `gofmt -l .` 空、四项检查与 `go test -race` 绿

**不在这单**：`no_prompt` 那一档（「会话建得起来、零输出、退出码 1」）按要求不单独立用例——它没有专属代码分支，分类由判据表认领；这一档没验到的情况记在 18 号单。

## Comments

2026-11-03：已结。真机两条：`chage -d 0` 的账号改密成功（分类「改密成功」、`:` 的退出码 0 进 `Steps`、输出里两个口令都抹掉、换上新口令能再登进去）、未过期账号报 `sshfleet.passwd.not_expired` 并立刻收场。

**修了两处，都是这轮跑出来的**：
1. **入场信号取错了表**：`enterKeywords` 原来查 `Tables.PasswdCategories`（改密那张表里**没有**「密码过期」这一类），拿到的永远是空表，于是整场不认信号、一句都不喂、60 秒超时。改成查错误分类表的第一组（与代填的中止词同取一份，与老版 `kw.PasswordExpired()` 一致）。
2. **干净成功被那句服务端提示拖成失败**：`You are required to change your password immediately` 作为提示进 `ErrorText`，而改密的干净判据里有「报错原文为空」一条，于是干净成功被归到「密码过期」。干净收场且见过信号时把那句撤掉——它在改密里是**前提**，不是失败原因（老版把提示单放一格、只在匹配时排除，口径相同）。

**改密失败分类表已接上**（同日，开发者点头后补做，口径见 `docs/adr/0041-改密分类表按模式接进判定.md`）：判定按模式选表（改密先查 `PasswdCategories`、认不出再退通用），呈现侧（提示语、是否未归类）按名字查三张表。真机上未过期那台的分类名因此从「那行报文」变成「密码未过期」，统计块里也取得到它那句提示。同一轮把 `keywords_error.conf` 的两个节名改成单数，与改密那份对齐。

**没跑到**：收尾另三句（早收场、喂了不收、提示没认出来）只有代码，没有用例——造它们要故意配错提示词表或让远端卡在读写 `/etc/shadow`，本阶段不造。「密码表缺关键词时启动就报」属 03 已结的行为例外，本阶段没回归。
