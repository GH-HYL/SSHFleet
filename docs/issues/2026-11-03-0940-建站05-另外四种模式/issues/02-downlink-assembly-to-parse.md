# 02: 把下发行的拼装从执行站搬回解析站

**要做的**：拼下发行这件事回到解析站一处——纸装好「这次要发给远端的那条命令行」与「沿 stdin 送下去的正文」，执行站只发不拼。做完之后，`-a` 的长度闸门量得到真正要发的那条串，解释器表与它的判据也只剩一处主人。

**Blocked by**：01（纸要先装得下）、04（脚本的解释器要先定出来）。

**Status**：ready-for-agent

- [ ] `execute/build.go` 整体搬进解析站（`downCommand`、`envHead`、`exportPrefix`、`localeFragment`、`sudoPrefix`、`shellQuote`、`quoteEnvValue` 一并搬），执行站不再有拼装；原文件与它的单测一起走
- [ ] 纸上多一格成品：一条下发行 + 一份要沿 stdin 送的正文（普通路径两者都有；`-a` 的正文已 base64 进命令行，stdin 为空）
- [ ] 解释器表搬进解析站（一行一个名字：程序文本参数、是不是 shell 家族、补 `$0` 的规矩）；**表里不放句子、也不放显示顺序**——「目前支持：…」那句与顺序归 `message`
- [ ] 解释器在表外时（只影响 `-a`）：解析站拼不出下发行，记一条事实（新 `ProblemKind`）交给闸门，本站不报错——判「不过」仍只归闸门
- [ ] 四种情形各一条用例：命令、`--no-shell`、脚本（正文走 stdin、`$0` 补名）、`-a`（base64 + 程序文本参数）
- [ ] 执行站两处调用点改读纸上那一格（发命令、写执行期日志里「交给 SSH 执行」那几段）；屏幕与日志**逐字不变**
- [ ] 命令模式 A/B 重跑：屏幕与 `terminal-output.txt` 与老版逐字节相同（下发行没变，动的只是它在哪拼）
- [ ] `gofmt -l .` 空、四项检查与 `go test -race` 绿；17 包零违规、红线 39 条不动

**不在这单**：`-a` 的长度闸门（08 号单，量纸上那条成品串）、代填会话（11 号单）、脚本执行（10 号单）。
