## 问题陈述

脚本模式与代填此前写死 `bash`：`.py` 脚本一律送 `python3`，目标机只有 Python 2 就跑不了；代填写死 `-c` 交付正文，可 `perl -c` 只做语法检查、正文根本不执行，也不报错。使用者拿到的结果是「配了也白配」。

下发外壳当时是 `bash -lc`，依赖目标机装了 bash。目标机没有 bash 时整个工具用不了，而这件事跟使用者的操作无关。

另有两处：脚本靠自身文件名取信息（`$0`）在部分解释器下拿不到；选项 `--no-bash` 的名字名不副实——外壳早已换成 `sh -c`。

---

## 方案

解释器改由配置文件决定，随包给出默认值，使用者可加后缀、换解释器或写绝对路径。代填按解释器自动适配「程序文本参数」。下发外壳改用 `sh -c`，环境由工具显式设好，不再依赖目标机有 bash。

`$0` 在脚本经 stdin 送达时补回脚本名；`--no-bash` 改名为 `--no-shell`，与自定义解释器互斥。

---

## 使用者故事

1. 作为运维人员，我想让 `.pl` 脚本自动交给 `perl` 跑，这样我不必为每种脚本手工指定解释器。
2. 作为运维人员，我想在配置里加 `.rb = "ruby"` 就让 `.rb` 脚本跑起来，这样新语言不必等工具发版。
3. 作为运维人员，我想在目标机只有 Python 2 时把 `.py` 配成 `python2`，这样老机器也能用。
4. 作为运维人员，我想让代填在 `perl` / `ruby` / `node` 脚本里也真的填进去，而不是静默不跑。
5. 作为运维人员，我想让目标机没装 bash 时工具照常能跑，这样我不必为了一个工具去装 bash。
6. 作为运维人员，我想让脚本里取自身文件名的那句能拿到真实文件名，这样我写的脚本不用绕开它。
7. 作为运维人员，我想让「配了没配到的后缀」在开跑前问我一句，而不是闷头用 bash 跑错。
8. 作为运维人员，我想让 `--no-shell` 这名字说的是它真正做的事，这样我不用猜它和「解释器」是什么关系。
9. 作为运维人员，我想在同时给 `--no-shell` 和自定义解释器时被明确告知两者不能一起用，而不是配置被悄悄忽略。

## 实现决策

**解释器配置**：配置新增 `[interpreter]` 段，含 `command`（命令模式用哪个解释器）与 `[interpreter.script]`（后缀 → 解释器的映射）。后缀键归一化为小写，匹配取最后一段扩展名、忽略大小写。

**代填的「程序文本参数」**：shell 家族与 `python` 用 `-c`，`perl` / `ruby` / `node` / `lua` 用 `-e`，`php` 用 `-r`。表外解释器在本地参数检查阶段就报错并列出支持范围，不连任何机器。

**下发行**：外壳由 `bash -lc` 改为 `sh -c`，环境段（locale 与 PATH）在解释器启动前显式设好。上传 / 下载 / 改密不经过可配解释器，行为不变。

**`$0` 补名**：无代填时走 `. /dev/stdin`；有代填时正文编进命令行，走 `-c '<正文>' '<名字>'`。只给 shell 家族补名。

**互斥**：解释器非 `bash` 时同时给 `--no-shell` 会报错说明原因；解释器本身是 `bash` 时不拦。

**不兼容点两处**：老配置需补 `[interpreter]` 段；`--no-bash` 旧名不再接受。故版本抬到 `9.0.0`。
