## 一、问题成因

SSH 会话**从不申请 PTY**（`internal/ssh/` 下无 `RequestPty` 调用），远端 `isatty()` 恒为假，远端程序于是自己走进非交互分支。所以不是工具"不支持交互"，是远端程序压根没问。

## 二、实测事实（2026-09-28，本机 bash）

| # | 命令 | 结果 | 结论 |
| --- | --- | --- | --- |
| F1 | `printf 'a\n' \| bash -c 'read -p "PROMPT_ARCH: " x; echo "GOT=[$x]"'` | 只输出 `GOT=[a]` | **`read -p` 的提示在 stdin 非终端时根本不打印** |
| F2 | `printf 'a\n' \| bash -c 'echo "PLAIN_ARCH:"; read x; echo "GOT=[$x]"'` | `PLAIN_ARCH:` + `GOT=[a]` | 先 `echo` 再 `read` 的写法，提示照常打印 |
| F3 | `printf '1\n' \| bash -c 'select a in one two; do echo "GOT=[$a]"; break; done'` | stderr 出现 `1) one 2) two #?` | `select` 的菜单照常打印（走 stderr） |
| F4 | `printf 'read x\necho "GOT=[$x]"\n' \| bash` | **无任何输出** | 脚本体与 `read` 抢 fd 0：`read` 把**脚本自己的下一行**当答案吃掉，后半段静默消失 |
| F5 | `printf 'echo BEFORE\nread x\necho "GOT=[$x]"\n' \| bash -lc 'export LC_ALL=en_US.UTF-8; bash'` | 只输出 `BEFORE` | 工具当前的形态（`bash -lc` 套壳 + stdin 送内容）同样中招 |
| F6 | 分节奏写入（脚本分段喂、中间各停 0.5s） | `BEFORE` + `GOT=[ANSWER]` | 分段可以避开，但**要求知道在哪一行分段** |
| F7 | base64 包裹 + `\| bash`（**`_bak` 旧 Py 方案的原形态**） | 只输出 `BEFORE` | **不解决 fd 0 冲突**：内层 bash 的脚本来源仍是管道，`read` 照样吃掉脚本行；代填进了外层 bash 的 stdin，无人读 |
| F8 | `bash <(… \| base64 -d)` | `BEFORE` + `GOT=[ANSWER-1]` | 脚本改由 /dev/fd 提供，stdin 空出 → 可用 |
| F9 | `… \| base64 -d > /tmp/x.sh; bash /tmp/x.sh` | 同上 | 脚本落文件再执行 → 可用 |
| F10 | `bash -c "$(… \| base64 -d)"` | 同上 | 解码结果作 `-c` 的参数 → 可用，且不落盘 |
| F11 | F10 再叠加 `export LC_ALL=… LANG=…;` 前缀 | 同上 | 与现有 env 前缀共存，无副作用 |

**F1 与 F4/F5 是两条地基：**

- **F1** → 不分配 PTY 时，用 `read -p` 写的提示**不存在**，内容匹配无从下手。要么分配 PTY，要么接受这类脚本必然归入失败。
- **F4/F5** → 命令/脚本体与代填**不能共用会话 stdin**。且失败形态是"后半段静默消失"，不是报错。

**F7 是本轮最重要的发现。** `_bak` 旧 Py 方案的形态是（`modules/SSHFleet_bak/modules/SSHFleet_Py/src/command/builder.py:47,51,73`）：

```
printf %s <base64> | base64 -d | bash
```

它就是 F7 —— **回归旧方案并不能让交互输入工作**。base64 解决的是"内容怎么传、怎么免引号转义"，与"stdin 归谁"是两件事。

**旧新两版的差别只有"最后一棒"这一处**（用户 2026-09-28 追问后逐行核对 `builder.py` 确认）：

```
旧（builder.py:47,51,73,86；即 F7）
  bash -lc 'export …; printf %s <base64> | base64 -d | bash'
                                                     └── 内层 bash 的命令内容来自管道 → fd 0 是管道

新（即 F10）
  bash -lc 'export …; bash -c "$(printf %s <base64> | base64 -d)"'
                       └────────┬─────────┘
                        内层 bash 的命令内容来自参数 → fd 0 继承会话 stdin
```

两点澄清，避免重复讨论：

- **内容早就在 `-c` 的参数里**：旧版 `bash -lc <整段>` 的 `-c` 参数里就含 base64 串。差别不在"用没用 `-c`"，而在**内层 bash 的命令内容是从管道来还是从参数来**。
- **`builder.py:41` 的注释"通过 stdin 通道交给 sudo bash 执行"是不准的**：它指的是**远端 shell 内部自建的那根管道**，不是 SSH 会话的 stdin。会话 stdin 在旧版里始终是空闲的（只是没人用——没有代填可喂）。这处措辞是"旧方案看起来已经在用 `-c`"这个疑问的来源。

**对"内容进 argv"这一代价的修正**：旧 Py 版同样把内容放在 `-c` 参数里，因此相对旧版**不是退步**；相对**当前 Go 版**（内容经 stdin，故不进 argv）才是。两版在这一点上本就不同。

要让它工作，内层解释器的**脚本来源必须是 `-c` 的参数或一个文件**，不能是管道。三条可用形态（F8/F9/F10）的共同点正是"脚本不占 fd 0"：

| 形态 | 优点 | 代价 |
| --- | --- | --- |
| F10 `-c` 形态 | 不落盘、无痕迹、无 fd 继承问题（`sudo` 也安全） | 受 Linux 单参数上限 `MAX_ARG_STRLEN`（128KB）约束；base64 膨胀 4/3，原始内容约 **96KB 封顶** |
| F9 落文件 | 无长度限制 | 落盘 + 清理；`/tmp/.SSHFleet_tmp/` 现成 |
| F8 `/dev/fd` | 不落盘 | `sudo` 默认关掉 3 号以上 fd，`sudo bash <(…)` 有风险 |

| --- | --- |
| 分支形态 | 在现有执行链上开分支、尽量复用既有代码；按《个人开发规范》二，落点为**新增实现文件**，不给 `RunCommand` 加 `if` |

| 内容承载形态 | 见"备查：已决案的评估依据"。命令与脚本**同形**，**不落任何介质**（不碰硬盘，也不碰 tmpfs） |
| 长度上限与检查 | 原文约 **96KB**（算术见 F7 段）。**不加 gzip**。判据为**最终下发行**的字节数，阈值**写死在代码里**（固定值，不开放配置），在**本地参数合规检查阶段**拦下并直接提示退出，不放到远端执行时才报错 |
| 集群差异 | 代填表**全局一份**，不支持按节点区分。答案因机而异（如混架构、混发行版）时，由运维**分批执行**（用户 2026-09-28 定） |
| 分支启用 | 交互分支**显式启用**；PTY 在该分支内默认分配 |
| 术语 | 一条代填 = **代填内容**（要填进远端输入通道的东西）+ **触发词**（认出提问的字串）。界面上统一用**「代填」**这个提法——它把"运维预知答案、让工具代填一下"说清了，触发词则是它的门控 |
| 触发词形态 | 一条代填挂**多个**触发词，任一命中即触发 |
| 参数形态 | 长 `--answer`、短 `-a`，**单值**。值是**一段 CSV 文本**（或一个 CSV 文件路径），列语义：第 1 列代填内容，第 2 列起触发词，列数自适应。发出时在内容**后补一个回车**（`\n`），故**第 1 列留空 = 只发一个回车**。取值形态、来源判定与解析口径**与 `-f` 完全一致**（同一份 `common.ReadCSVRows`）：判定只看路径存不存在、**不认后缀名**；内联值先把字面 `\n` 补成真换行；`#` 开头行与空行跳过。**值不进路径参数的规范化与空格禁令**（`cli.Parse` 里那段循环只服务 `-s/-f/-u/-p/-d`） |
| 触发词下限 | 每条代填**至少一个触发词**，否则报错——触发词是**唯一的门控**，没有它等于无条件盲填 |
| 逗号的直接后果 | 逗号是**列分隔符**；要写进代填内容或触发词里，用双引号把那一列包住（CSV 口径，与清单同一套）。帮助与文档须写明 |
| 匹配方式 | 默认按**子串包含**；正则由**配置文件开关**开启（默认关闭） |
| 大小写 | 由**配置文件开关**控制（默认**不敏感**，与现有分类判据口径一致） |
| 命中规则 | 多条代填**并行**参与匹配（不分先后），取输出里**最先出现**的那条。**不做**顺序门控（第 N 条须等前 N−1 条填完）——脚本会跳过提问（如那台本来就是 deb、脚本自己判断完没问包格式），顺序门控会让这类机器从第 2 条起全部失配 |
| 统计计数的呈现 | 失败分类的计数改为 **`分类名 ×5`**（`×` 紧贴数字，一眼看出是"个数"），告别 `分类名：5`，消除"计数"与"分类名内嵌数字"（如 `执行失败(退出码1)`）的混淆。改动面**仅两处格式串**：`internal/output/terminal.go:142` 与 `report.go` 内同一句 |
| 配置文件新增字段 | 新增 `[interactive]` 段（并列于 `[enable]` / `[upload]`）：`regex`（默认 `false` = 按子串）、`case_sensitive`（默认 `false` = 不区分大小写）。**必填字段**，故属不兼容改动 |
| 长度阈值 | 写死 **122880 字节（120KB）**，量的是**最终下发行**；错误文案里同时报原文大小。**仅 `-a` 运行检查**（普通路径维持 stdin 交付，无上限） |
| 帮助文案 | `-a, --answer   代填：看到触发词就自动填内容（值形如「代填内容,触发词,触发词」）` |
| `-a` 的两种来源 | 照 `-f` 的形状判定：**先 `os.Stat`**；文件不存在再按形态判——**含逗号 ⇒ 内联**，不含逗号 ⇒ 报"文件不存在"。文件内**每行一条**、与内联同构；空行与 `#` 开头跳过；**允许文件与内联混用**，条目顺序即命令行给出顺序 |
| PTY 尺寸 | **200 列 × 50 行**，**不继承本地终端尺寸**（本地窗口可能很窄，折行会切断触发词） |

| 输入通道的关闭时机 | **不做特殊动作**——原定"代填用尽后立刻关闭、让后续裸 `read` 拿 EOF 快速失败"已于 2026-09-28 实测**撤回**：PTY 下通道 EOF 传不到 pty，关了远端照样挂（M11）；改投 `^D` 只消一次 `read`、残留字节还会被 raw 模式的读取当字面输入（M12）。没配到代填的机器就挂到 `timeout_execute`——它本来就是"脚本卡在等输入"的时限 |
| 与既有开关 / 模式的互斥 | `--answer` 配 `--no-bash`、或配 `-u` / `-d` → **明确报错**并说明原因，不静默忽略 |
| 触发词未命中的定性 | **强约束为失败**。它是"工具内生"的判定（远端一个字都没说），须新立一个分类归拢，不与"命令报错"混用；细分交由运维 |
| 超时 | **不新增任何交互专用超时**，`timeout_execute`（`-t`）是唯一时限。见"超时：不设单独超时" |
| 触发词未命中的呈现细节 | 暂缓，后续单独讨论 |
| 中止词 | `-a` 分支内置的保险判据：关键词取判据文件「密码过期」分类（`KeywordsOf`，跨两块并集；该分类改名或删除即失效）。匹配口径随 `[interactive]`（子串/正则、大小写开关）。命中 → **立即终止该节点会话**，`error` 写命中的原文行，退出码置 `nil` → 分类归「密码过期」。不参与代填匹配、不占代填条目、每节点至多触发一次。依据：实测 M2/M4/M5——警告文本在会话开始第 0 秒出现，早于改密对话 |
| 未命中判定的前置条件 | 命令未能开始（会话建立或命令下发失败）时**不做**未命中判定，`error` 保留原值——真实的拒绝原因（密码过期、命令被拒等）不被「触发词未命中」覆盖。**用户主动中断（Ctrl+C）也不做**：中断有自己的分类（`error` 保留 `context canceled` → 「任务已取消」），不该被未命中盖掉 |
| 工具日志与报告的 `-a` 留痕 | `Summary()`（工具日志）与 report.txt【执行参数】**全量记录**代填（内容 + 触发词）。代填内容可能是密码，明文进归档——用户 2026-09-28 裁定接受（留痕优先）；拆分出的改密功能对自己传入的新密码复用 `common.MaskSecret` 既有脱敏（前 2 + `****` + 后 2，≤4 位整段 `****`） |
| 改密拆分 | 「用代填改密码」**拆分为独立功能**：独立参数（`--change-password`，无短选项）、流程内置（不需要用户配置触发词）、分类仅「更新成功 / 失败」。设计已定稿，见 `docs/issues/remote-password-change/spec-已闭环.md`。本功能不再承载改密场景 |
| 交付形态的范围 | base64 进命令行**仅交互分支**采用；普通 `-c`/`-s` 路径维持 stdin 交付、无长度上限（用户 2026-09-28 裁定不统一）。ADR-0010 范围同步修正 |

> **兼容性**：本功能要往配置文件里加**必填字段**（见第三节「配置文件新增字段」）。按配置文件"全字段必填、缺字段启动即报错"的现行口径，这会让**旧配置文件升级后直接不能跑**——属不兼容改动。按《个人开发规范》四，CHANGELOG 的当天段落须抬到**主版本**。

## 四、逻辑骨架（复用清单与循环）

**复用（一行不改）**：`newResult` / `connectFor` / `applyBanner` / `lockedBuffer` 合并 stdout+stderr / `trimOuterBlankLines` / `extractExitCode`。

**唯一替换**：`session.Run(cmd)` → `Start(cmd)` + 读写循环 + `Wait()`。原因：`Run` = `Start` + `Wait`，会占住调用方直到命令结束，没有机会边跑边聊。

**循环**：

1. 读线程持续读，**同一份字节既进 `lockedBuffer`（保证 `Output` 字段与现状一致），又推给匹配器**。
2. 匹配器持一个**游标**（已处理到的位置），只在游标之后找；命中即送出代填并推进游标。
3. 游标**只在命中时前进**——顺带解决"提示被读边界切成两半"（第一次读到半截匹配不上，游标不动，等后半截到了自然能对上）。
4. 代填用尽后**不做任何动作**（原"主动关闭输入通道"已按 M11/M12 实测撤回）：没配到代填的 `read` 就挂到 `-t`。
5. 总时长仍由 `ExecTimeout` 兜底；取消/中断语义复用现有那套。

**为什么必须有独立读线程**：不读会把 SSH 通道窗口堵死，远端阻塞 → 死锁。

**匹配的触发方式与匹配范围**（回答"按段还是按行"）：SSH 通道给的是**字节流**，`Read()` 一次返回的块边界是任意的——可能只拿到半个提示，也可能一次拿到两条提示。所以：

- **触发时机是"每个读块到达时"**，不是"每条输出到达时"（通道里没有"条"这个概念）。
- **匹配范围是游标之后的那一段字节**，**不按行切分**。理由：提示常常不带换行（`read -p` 的提示就没有），按行匹配会漏。
- 跨块的问题由"**游标只在命中时前进**"解决：一次只读到半个提示 → 匹配不上 → 游标不动 → 下次读块到齐后自然命中。

**为什么"时机"不需要判断**：SSH 协议层不存在"远端正在等输入"这种信号。时机只能从读到的数据推——看到提示 = 远端刚打印完问题 = 紧接着它就要阻塞读输入。答案不是按时间发的，是按事件发的。且提前发也安全：写进输入通道的字节排队等待，程序真正读时立刻取到。

**多条的处置（三条代填、第一条一直没命中时）**：并行语义下第 2、3 条**照常参与匹配**，不等第 1 条。实际后果是：脚本卡在第一个提问上就走不到第二个，所以第 2、3 条的触发词也不会出现，最终三条**都记未命中**，`error` 写「触发词未命中：第 1、2、3 条…」。

诊断规则（应写进帮助与文档）：**脚本是顺序提问的，所以未命中序号里最小的那个就是第一个出错点**——看到"第 1、2、3 条"就去查第 1 条的触发词，不必三条一起怀疑。而"乱序填错"的防线不是顺序门控，是**触发词要有区分度**（配置纪律）。

### 真机实测结论（2026-09-28，Ubuntu 26.04 / WSL2，UsePAM yes）

| # | 场景 | 结果 |
| --- | --- | --- |
| M1 | 无 PTY + 密码过期 | 认证通过、命令被拒：stderr 出 `WARNING: Your password has expired.` + `Password change required but no TTY available.`，退出码 1——现行「密码过期」（第二组判据）的来源与形态 |
| M2 | 有 PTY + 密码过期 | **改密对话在 exec 会话内真实出现**：警告行 t≈0 → 「当前的密码：」→「新的密码：」→「重新输入新的密码：」→「passwd：已成功更新密码」。固定节奏依次喂入即成功，代填/写死流程都能接 |
| M3 | 改密完成后 | **原命令不执行**：会话直接结束、退出码 0——改密与执行是两次运行，改密独立功能的直接依据 |
| M4 | 有 PTY + 过期 + 不喂答案 | 对话挂死直至超时——过期机器在 `-a` 批次里的形态；警告文本第 0 秒即出现，中止词即时有信号 |
| M5 | 警告期（未过期） | 命令照常执行，两种模式均**无任何警告文本**——中止词不误伤警告期机器 |
| M6 | 回显 | passwd 全程不回显（密码不进归档）；普通 `read` 回显（「接受现状」的暴露面实测确认） |
| M7 | 折行 | 240 字符长行原样到达、无中途 `\r\n`——tty 驱动不折行，折行是显示端行为；200 列 PTY 决策保留为防御（防程序按 `TIOCGWINSZ` 自排版） |
| M8 | `\r` | 行尾 `\r\n` 实锤（`onlcr` 生效），采集侧去 `\r` 的对策照做 |
| M9 | `read -p` + PTY | 提示正常打印、输入正常送达——功能地基（F1 的非 tty 抑制被 PTY 治好）端到端验证 |
| M10 | 提示文案 | 跟随目标机语言（中文机器出中文提示，触发词按目标机语言配置，同「登录被禁止」中英双条先例）；首个提示**不带换行**，印证「不按行匹配」 |
| M11 | PTY + 关输入通道 | **通道 EOF 传不到 pty**：`read x; echo "GOT=[$x]"` 在关掉输入通道后 8 秒无输出、会话不结束 → 「代填用尽立刻关」的收益不成立（2026-09-28 补测，撤回该决策） |
| M12 | PTY + 投 `^D`（VEOF） | 一个 `^D` 让 `read` **立刻**返回 `GOT=[]`；但**只消一次** read（两个 read 只投一个 `^D`，第二个照旧挂死；两个 `^D` 才都过）→ 数量不可知，且残留字节会被后续 raw 模式的读取（如 sudo / passwd 索要密码）当字面字符吃进去。**不采用** |
| M13 | 设计里的下发行端到端 | `bash -lc 'export …; bash -c "$(printf %s <b64> \| base64 -d)"'` 在 200×50 PTY 下跑通：喂 `1\n` → 远端取到 `1`、输出 `GOT=[1]`，会话正常结束、退出码 0 → **内容承载 + PTY + 喂入 + 收尾整套可行** |
| M14 | 远端 base64 与环境 | `/usr/bin/base64` 是 uutils coreutils 0.8.0（Rust 版），`-d` 正常；输出行尾 `\r\n`（`onlcr` 生效，去 `\r` 照做）；输入**有回显**（echo 开，与 M6 一致） |

### 触发词未命中的落地机制（三步合成，全部复用既有机制）

三步串起来，**不新增判定路径、不改 `classify` 的优先级逻辑**：

1. **命令已开始**的前提下，收尾时若"还有代填没被送出"，把一句固定文案写进结果的 `error` 字段（命令未能开始不做此判定，`error` 保留原值——真实的拒绝原因不被未命中覆盖）：
   `触发词未命中：第 1、2 条（"架构"、"deb/rpm"）未匹配到任何输出`
2. 同时把退出码置 `nil`（见第三节「触发词未命中的定性」）。这一举两得：既让统计的成功/失败计数（`result/statistics.go:78` **只认退出码**）把它算作**失败**，又让 `classify` 走**第一块**关键词匹配（那一块的触发条件正是"退出码为 nil"）。
3. 第一块**先匹配 `error`**；而配置文件 `[[categories]]` 的**末尾**就有一条
   `name = '触发词未命中'`、`keywords = ['触发词未命中']` → **必定命中**，不存在被其它分类覆盖的问题。

这与 **ADR-0005**（服务端提示并入 `error`，于是天然进入分类链路）是同一个手法：不碰分类逻辑，只把信号送进它本来就在读的字段。位置排在第一块**末尾**（2026-09-28 定）：具体原因由中止词在第 0 秒归因，未命中是纯兜底，按「具体在前、笼统在后」的既有口径垫底。

### 中止词（2026-09-28 定）

`-a` 分支内置的保险判据，与代填条目分通道：关键词取判据文件「密码过期」分类（`KeywordsOf`，跨两块并集；该分类改名或删除即失效），匹配口径随 `[interactive]`（子串/正则、大小写开关）。

命中即**立即终止该节点会话**：`error` 写命中的原文行、退出码置 `nil` → 第一块判据命中「密码过期」。不参与代填匹配、不占代填条目、每节点至多触发一次。

依据：实测 M2 / M4 / M5——警告文本第 0 秒出现、过期机器的对话必然挂死、警告期机器无警告文本（不误伤）。改密已拆分为独立功能，`-a` 运行里不存在"喂改密对话"的合法场景，立即终止没有误杀面。

### 超时：不设单独超时，完全靠 `-t`

**结论（用户 2026-09-28 定）**：不新增任何交互专用超时，`timeout_execute`（`-t`）是唯一时限。

理由是该判据本身不可靠——**"脚本在跑长活"和"脚本在等输入"在输出上可能同形**（都是没有新输出）。任何"等触发词命中"的时间判据都会误判前者：

| 变体 | 语义 | 误判对象 |
| --- | --- | --- |
| 一 | 从命令开始算，N 秒内必须命中第一条 | "先装依赖、后提问"的脚本（用户举的例子正是这种） |
| 二 | 输出安静 N 秒且仍有未命中 | 长时间完全无输出的长任务（`sleep`、静默编译） |
| 三 | 变体二 + "末段输出没有换行"（提示通常不带换行） | 仍是启发式，只是更准 |

改用"收尾静态判定"之后，超时不必单独处理。

### 触发逻辑（完整时序，无任何新时钟）

1. 命令下发后，读线程持续读远端输出。
2. 每读到一段，就在**游标之后**的那段里按顺序找触发词；命中 → 送出该条代填 → 游标推进。
3. **没有任何时钟参与**。脚本先跑 10 秒还是 10 分钟都无所谓——匹配器只是在等字节。
4. 何时结束由**既有的 `-t`** 决定，与本功能无关：脚本正常跑完、或卡在等输入直到 `-t`、或被中断。
5. **收尾时**统一做一次静态判定：代填表里还有没有被送出的条目？（**用户主动中断除外**——中断的机器保留 `context canceled`，归「任务已取消」；超时照判，"脚本卡在等输入"正是它的形态）
   - 有 → `error` 写「触发词未命中：第 N 条…」，退出码置 `nil`，分类归「触发词未命中」，算失败
   - 没有 → 一切照旧

**所以"超时"在本功能里不是新概念，只是"结束方式之一"**：「触发词没配上」与「`-t` 到点」是两件独立的事，最后在收尾处合流。**没有需要计时的东西。**

`-t` 该设多少：它本来就要容纳"整条脚本从开始到结束"的时间。脚本 10 秒后才交互、之后等人输入——配上触发词则第 10 秒就填进去了；没配上则一直等到 `-t` 结束并报「触发词未命中」。**不需要为交互单独调 `-t`**，除非整条脚本本身就超过默认 60 秒（那与有没有交互无关）。

### 「代填」：更优的表述，不是另一套方案

用户 2026-09-28 的提法：要的就是**代填**——什么时候遇到什么选项是他预知的，让工具代填一下；**触发词是为了防止"脚本没有触发交互时，直接填进去的内容反倒成了命令的输入"**。

这个表述更清晰，而且把触发词的性质说准了：**它是门控，不是可选的匹配便利**。落地形态与已定案完全一致（读输出 → 匹配触发词 → 填内容），差别在两处：

- **帮助文案与文档口径宜改用"代填"这个词**；
- 必须把"**触发词是唯一的门，不能省、也不能写得太宽**"写成硬话——触发词写得宽泛等于把门敞开，谁都能进（呼应本文档"宽泛子串比正则更危险"那条）。
- 可选加固（**暂不做**）：要求顺序也成立——第 N 条只有在第 1…N−1 条都已消费后才有资格命中。它防的是"一组宽泛触发词把两条提示都匹配上、导致乱序填错"；代价是"顺序必须与脚本一致"从建议变成硬要求。用户的"预知"前提使它可行，但它属于配置质量问题的另一道保险，先不引入。



### 分配 PTY 之后新引入的两件事（原方案没有，必须一并处理）

**一、折行会把触发词切断。** PTY 一旦分配，远端程序的输出会按**终端列宽**排版；提示串若长于列宽而被折行（远端自己按 `TIOCGWINSZ` 换行，或 tty 驱动做输出加工），触发词就会被 `\r\n` 从中间切开，**永远匹配不上**。给足够宽的尺寸可降低这个风险——这正是第三节「PTY 尺寸」定 200 列、且不继承本地窗口的原因。
（已实测（M7）：tty 驱动不折行，本条按防御保留）

**二、`\r` 会进入输出。** PTY 的 tty 默认开启 `onlcr`，远端输出的 `\n` 到了我们这侧会变成 `\r\n`。影响面：
- 分类的关键词匹配**不受影响**（子串包含，`\r` 在行尾）；
- 但 `output` 字段、明细、xlsx 里每行会多一个 `\r`，显示与比对都可能有噪声。

处理建议见第三节「PTY 的 `\r`」：**在采集侧去掉行尾 `\r`**（采集侧本来就做输出整备，符合"Output 是原始字段、整备只在采集侧做一次"的既有口径）。

### 备查：已决案的评估依据

**内容承载形态 = `-c` 形态（原 N1 的备选 ①）。** 正文 base64 编入命令行，远端解码后作内层解释器的 `-c` 参数（F10 已验）。命令与脚本同形，**不落任何介质**。三条被否的备选与理由：

| 备选 | 否掉的原因 |
| --- | --- |
| 旧 Py 原形态 `… \| base64 -d \| bash` | F7 实测：内层 bash 的 fd 0 变成管道，`read` 抢脚本体，代填拿不到。旧方案的注释自称"走 stdin 通道"，其实指的是远端 shell 内部那根管道 |
| 分场景（命令走命令行、脚本落 `/tmp`） | 用户否决：分场景不成立（命令也可能用代填）；且 `/tmp` 会碰硬盘，几千台里磁盘满是常态 |
| 落 `/dev/shm`（tmpfs）或 `<(...)` 进程替换 | 用户否决落盘；`<(...)` 另因 `sudo` 默认关掉 3 号以上 fd 而不可靠 |

**分隔符 = 逗号（原 N2）。** 按三条硬标准（不是正则元字符 / 裸写安全 / 提示文本罕见）先把竖线排掉——它既是 shell 管道符、又是正则的"或"运算符；冒号与斜杠则是出现率太高。逗号**通过前两条**，唯一残留风险是提示里出现数字列表（`1,2,3`），用户裁定接受。2026-09-28 起解析换成与清单同一套 CSV 口径：要写进代填内容或触发词里的逗号用双引号包住即可，不再是硬禁令。

实现硬约束：取值解析必须与 `-f` **共用同一份实现**（`common.ReadCSVRows`）。两处各写一份就是两套口径——`#` 注释行、BOM、双引号、变长列的容忍度会立刻开始漂移，而它们本该逐字一致。

### 备查：分隔符候选全表

前提一：值被 shell 引号包裹时分隔符不会被 shell 解释，"shell 冲突"只在裸写时存在。
前提二：分隔符不能是正则元字符（`\ . + * ? ( ) | [ ] { } ^ $`），否则正则模式下解析有歧义。

| 候选 | 是正则元字符？ | 裸写安全？ | 提示文本里出现率 |
| --- | --- | --- | --- |
| 逗号（**已定**） | 否 | 是 | 中（数字列表 `1,2,3`）→ 由帮助文字兜底 |
| at 符 | 否 | 是 | 低（`user@host`、dnf 的 `@module`） |
| 百分号 | 否 | 是 | 低（但进度输出 `45%` 常见） |
| 等号 | 否 | 是 | 中（`key=value`） |
| 冒号 | 否 | 是 | 高（`请选择:`），且与正则前缀标记冲突 |
| 斜杠 | 否 | 是 | 高（路径、`[x86_64/arm64]`） |
| 竖线 | **是** | 否（被当管道） | 极低 |
| 分号 / 井号 / and 符 | 否 | 否 | 井号会**静默吞掉后半段**，最危险 |

远端临时目录已存在：`internal/ssh/sftp.go:19` 的 `/tmp/.SSHFleet_tmp/`（本轮已定为不用）。

## 六、与既有决策的关系

- **错误分类**（`docs/issues/error-classification/spec-已闭环.md`）：本功能的失败走**同一套机制**——内生文案写进 `error`，再由 `[[categories]]` 的判据命中（见"触发词未命中的落地机制"）。因此**不改 `classify` 的逻辑、不给三个呈现端加字段**，与 ADR-0005 的手法同源。
- **ADR-0010**（已立，2026-09-28 用户授权）：**命令与脚本体不再经会话 stdin 交付**（范围仅交互分支，见该 ADR 的范围修正）。见 `docs/adr/0010-deliver-command-body-in-argv.md`。
