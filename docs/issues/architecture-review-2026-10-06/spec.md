### A1 · 候选二：三份「收场登记」收口 —— 已实施，提交 `77c9f29`

三份通道各自写「结束信号 → 退出码 / 报错原文 / 超时 / 中断」，差异只在 `SessionBegun` 的置法与各通道自己的尾巴。

**报告的方向要修正**：报告主打「`SessionBegun` 口径分歧」，但那条分歧当前对输出**零影响**——`SessionBegun` 全工程只被 `verdict.go` 三处读，且那三处要另两个只有交互通道会写的字段。所以本项真正的理由是**骨架三份同构** + 「顺序要紧」那条规则 2026-09-29 已踩过一次。

**做成什么**：`ssh/exec.go` 新增不对外暴露的 `endFactsOf(err, timedOut, canceled)`，独占「结束信号 → 退出码 / 报错原文 / 超时 / 中断」的映射；三条通道改调它。各自真正不同的尾巴原样保留。

**行为边界**：`SessionBegun` **未统一**。命令通道由本节信号推，交互与改密通道由 `outcome.begun` 给——两者语义本就不同，统一它属未经授权的行为改变，故保持现状。

### A2 · 候选三：脚本文件读三次、发送内容拼两份 —— 已实施，提交 `1b115f4`

**读点三处**：`cli/check.go`（判编码 / 空 / 二进制 / 后缀）、`dangercheck/check.go`（做危险分析）、`batch/batch.go`（整理后真正执行）。
**拼点三处**：`cli/answer.go` 的 `answerInputOf`（量长度用）、`batch/batch.go` 建任务（真发用）与 `commandDescription`（日志说明用），各写了一遍同一段材料。

**依据**：ADR-0010 的长度上限语义建立在「量到的字节 = 发出去的字节」之上。

**做成什么**：`cli/script.go` 新增 `ScriptMaterial`（正文 · 解释器）、`ScriptMaterialOf` 与 `ScriptInterpreter`，三处改调它。**只收「怎么拼」，不收「何时读」**——文件仍各阶段各读，这一档是实施时定的保守边界。

### A3 · 候选四②③ —— 已实施，提交 `a699f7e`

- **② 逐字孪生的状态行块**：`output/terminal.go` 与 `output/xlsx.go` 各写了一份加同一行格式化，一字不差 → 收成 `output.statusLine(r, mode)`。
- **③ 成功 / 失败的个数数了三遍**：`batch/progress.go`（进度条实时聚合，**保留**——与统计不是同一份）、`result/statistics.go`、`main.go`（主干收尾行）→ 删掉主干自己数的那段，`Statistics` 增 `ConnectSuccessCounts` / `ConnectFailCounts`，主干把统计的计算上移到收尾行之前。

**订正（审计发现，提交 `1d622fb`）**：那次上移把实参 `time.Now()` 也带到了前面，统计的「执行结束时间 / 总耗时」取样点比原来早（早出旧主干的计数循环 + 收尾行 + 两项检查，微秒级）。所以「无副作用」的说法**不成立**：这是一处**真实的、可观测的取值变化**（`report.txt` 的「执行结束时间」带六位小数）。当时的 A/B 把时间数值归一化掉了，**结构上看不见**这一类漂移。

未复原的理由：要严格回到原取样点，只能把收尾行移到 `fatal` 检查之后（代价是出错时执行期日志不再有收尾行），或二次取样回填；两者都比现状差，故只订正措辞。该取舍另见 `docs/adr/0018-accept-earlier-stats-sampling-point.md`。

### 本批验证（2026-10-07，A1–A3）

**方法**：把重构前（`14599b7`）与重构后（`a699f7e`）各编一个二进制，用同一份配置、同一份清单、同一组参数各跑五条路径（命令 / 脚本 / 上传 / 下载 / 改密），归一化后逐字比对 stdout 与归档全部产物。仅抹掉三类：时间数值、二进制自身路径、构建标识。

| 路径 | 归档目录名 | stdout | 报告 | 明细 | 执行日志 | 两张 xlsx |
| --- | --- | --- | --- | --- | --- | --- |
| 命令 | `_command_cmd` | ✅ | ✅ | ✅ | ✅ | ✅ |
| 脚本 | `_script_scr` | ✅ | ✅ | ✅ | ✅ | ✅ |
| 上传 | `_upload_up` | ✅ | ✅ | ✅ | ✅ | ✅ |
| 下载 | `_download_down` | ✅ | ✅ | ✅ | ✅ | ✅ |
| 改密 | `_passwd_pw` | ✅ | ✅ | ✅ | ✅ | ✅ |

**两条与改动无关的噪声**（审计时别误判）：

1. **`results.xlsx` 的列宽**随「耗时浮点的字符串长度」变化。列宽公式是 `DisplayWidth(内容)+2`，而 `%v` 对 float64 给最短往返表示，字符数会变。实测同一个二进制连跑 4 遍，G 列宽 10 与 11 两种都出现过——属数据相关噪声。
2. **改密的 `****` 行**条数不定。实测连跑 6 轮：重构前 `2 3 3 2 3 2`、重构后 `2 2 2 3 2 3`——两侧都会出 2 或 3，是远端 tty 回显与 `passwd` 关回显之间的竞态。

**测试环境**：WSL2 Ubuntu 上的非 root 测试账号，配置 `sudo = false`；凭据未写入任何文件。
