# 规格：切换前七处修正

**状态**：ready-for-agent
**底本**：`docs/issues/2026-11-09-0945-切换前回顾审计/修复面盘点.md` §4.5（2026-11-09 15:10 裁「有理有据即可」逐条判）与 §五乙批
**边界**：只改被审计判成「不合理」的七处；判「认下」与「合理」的不动。

## Problem Statement

切换门槛第三条要求「行为不能动」，而审计在 37 场之外实跑抓到九条行为差异，逐条判下来有七处站不住：新版把 `010.0.0.1` 当前导零的合法输入收下、把配置里的重复键静默取后值还退 0、危险命令答「是」之后留痕整条丢、`--yes` 放行不进归档执行日志、同一次运行里确认屏印一个并发数而报告印另一个、面板缺终帧、`--convert-secret` 报错少一截前缀让使用者看不出是哪个文件打不开。这些不是「换了个说法」，是使用者或维护者能感觉到的退步。

## Solution

七处各自改回或收严：三处恢复老版行为（留痕、归档日志、前缀），三处收紧判据（IP、重复键、并发数统一取实际生效值），一处补回终帧。改完每一处都要能指出「改前怎么跑出来、改后跑出来不一样」，不留「理论上应该好了」。

## User Stories

1. 作为使用者，我希望清单第一列写错了就当场告诉我「不是合法 IP」，而不是把它当内联记录收下、拿去连机器。
2. 作为使用者，我希望配置写重复了直接报错，而不是静默用后一个值——那会让我以为前一个生效了。
3. 作为维护者，我希望危险命令哪怕答了「是」，执行日志与工具日志里都得有这条留痕，事后能追。
4. 作为维护者，我希望 `--yes` 放行这件事进归档执行日志，而不是只躺在工具日志里、归档里查不到。
5. 作为使用者，我希望同一次运行里确认屏与报告印的是同一个并发数——实际起几个就印几个。
6. 作为使用者，我希望面板收场时落到 100%，而不是停在中间就不见了。
7. 作为使用者，我希望 `--convert-secret` 读不到文件时那句原因带上路径前缀，让我知道是哪个文件。
8. 作为维护者，我希望这七处各自有一条能重跑的复现路径，而不是只有一句「已改」。
9. 作为维护者，我希望改动不碰红线区、不新增绕路判断——该改的是判据本身错在哪，不是为对齐塞特判。

## Implementation Decisions

- **七处独立成单**，各改各的包；只有「并发数」与「面板终帧」同住执行链，仍分成两张单（一个改数值来源，一个改渲染收场）。
- **判据收紧靠既有落点**：IP 合法性回到「第一列必须是合法 IPv4」这一条，内联记录那条路只在第一列确实不是 IP 时才走；重复键在词法器里按「同名节内同名键出现两次即报错」处理，与注释所写一致。
- **留痕两处都写**：危险命令的放行留痕既进执行期日志、也进工具日志；`--yes` 的跳过确认同样进归档执行日志。凭据与命令行照既有遮法，不新开露出口。
- **并发数只留一个来源**：确认屏、`report.txt`、执行期日志三处印的都是「实际生效值」，不再出现「命令行上写了多少」。
- **面板终帧**：进度界面收场时补一帧「节点进度 100%」，不加新行。
- **前缀**：`--convert-secret` 读文件失败那句原因保留系统原文的 `open <路径>:` 部分，与日志里那句同形。

## Testing Decisions

- 接缝只用既有的：站入口（递纸收纸）与进程出入口。不测私有函数。
- 七处里六处能写成包内自定义区用例；发版与面板终帧那两处走进程出入口或既有面板测试。
- 先例：`gate` 的拒绝用例、`execute` 的日志用例、`message` 的 `report.txt` 用例。
- 红线区不动；若某条改动撞上红线指纹，当场停下报告，按「改红线要开议题写 ADR」办。

## Out of Scope

- 判「认下」的两处（失败那台少「中间进度」一行、`-f <目录>` 报错换口径）：只登记，不回改。
- 判「一半合理」的 `10-T1` 里「多出来的总进度行」：留着，不按老版整体改回。
- 4.1／4.7／4.2／4.3／4.8 与 4.4 的 07 号单（跑新基准）：本议题改完才是它们的前提。
- CHANGELOG：重建期不逐笔记，发布时一条「重构框架」。
