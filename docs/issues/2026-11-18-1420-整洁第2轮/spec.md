# 规格：整洁第 2 轮（测试临时根收一处、依赖检查拆开）

**状态**：done（done）
**底本**：交接 `handoff-20261118-1220-sshfleet-收尾.md` 的 C 节；ADR-0032 第四条（包清单与依赖方向）；ADR-0037（两区与共用假件的边界）。

## Problem Statement

两处重复与一处混装，都是「改一处要改十七处」那种账：

1. 十七份 `tmpdir_test.go` 逐字相同（各 48 行、合计 816 行），只有包名与目标目录不同。今天为躲 360 把沙盒路径从一层改到两层，同一个改动抄了十七遍。
2. `internal/guard/check_deps.go` 一个文件装着五条判据（import 边、包清单对账、塔尖符号、读时钟、不经 import 的边），而其余八个 `check_*.go` 都是「一个文件一条」。

## Solution

**一、临时根收进 `internal/testtmp`。** 它在一个 `init` 里按被测包的当前目录推出「模块根上两级/build/tmp/test/<包名>」，把 `TMPDIR`／`TMP`／`TEMP` 指过去；十七个包的同名文件各缩成一行空引用。取沙盒路径的那三处测试改读 `TMPDIR`，不再调一个包内的 `buildTmp`。

**二、`check_deps.go` 按判据拆开。** 入口 `CheckDeps` 留一个文件，五条判据各一个 `check_*.go`；两个以上检查共用的 `consolePkg` 挪到它主要的用处（`check_terminal.go`）。

两条都是机械活，验据是「全量用例绿」加上 `gofmt`／`go vet` 干净；行为一条没变。

## Implementation Decisions

**一、新增一个包，包清单十九行变二十行。** 共享只能靠一个包——每份 `tmpdir_test.go` 住在自己包的 `_test.go` 里，看不见别包的代码。开发者 2026-11-18 就这一条单独点头（「加 testtmp 包」），按检查器自己的口径记在 ADR-0032 的更新记录里。

**二、`testtmp` 的依赖栏空着。** 生产文件 import 它按依赖方向报红；`_test.go` 有类二的豁免，测试才进得来。于是它既是横切（不产数据），又不该出现在任何一行的依赖清单里——这条写进了规则表那一行的注释。

**三、沙盒按「当前目录的末一段」分。** `go test` 把工作目录设成被测包那一层，所以同一个文件在十七个包里各得其所。模块根那一份的沙盒名从 `root` 变成 `SSHFleet2_Go`，是这条规则的副作用，不影响任何断言（`build/` 不进版本控制）。

**四、拆分按判据切，不按行数切。** 五个 `check_*.go` 与既有八个同形；测试文件不动——它们测的是判据，不是文件布局。

**五、不碰 ADR-0037 决定六。** 那条禁的是「红线区与自定义区共用假件包」，`testtmp` 是测试基础设施、不造假件、只碰环境变量，不在它的射程内。

## Out of Scope

- **`internal/log` 的导出方法面。** 十个导出方法与 `*Logger` 的方法面不在任何白名单（检查器只数包级导出），那是上一轮 spec 里记着的缺口，不在这一轮。
- **`criterion`、`archive`、`interrupt` 的依赖为空。** 它们的测试靠类二豁免进 `testtmp`，不因此给它们加依赖。

## Further Notes

- 反证：把某一包的空引用删掉，那个包的临时根就落回系统默认——`tools/test.sh` 仍兜着（它 export 三个变量），所以这条不会当场红；这也是为什么「删掉十七份、只靠入口脚本」被否掉：有人绕开入口直接敲 `go test`，产物就回到 `%TEMP%`。
