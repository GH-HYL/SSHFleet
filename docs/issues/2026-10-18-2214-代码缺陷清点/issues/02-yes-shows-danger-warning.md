# 02: `--yes` 下的危险命令提示与交互时完全一致

Status: done（2026-10-18 实施）
Blocked by: None（可立即开工）

**要做的**：`--yes` 只做一件事——**替人回答「y」**。屏幕上的输出、日志里记的内容，与交互时**一模一样**。改完之后，`--yes` 跑一条高危命令，屏幕上照样出现完整的危险警告框，不再只剩一句「跳过确认」。

**被谁阻塞**：无，可立即开工。

---

## 现状

危险命令的警告框只在交互模式下打。`--yes` 下这一路被整个跳过，于是高危命令被放行时，屏幕上只有：

```
 [非交互模式] 跳过执行选项/参数确认环节，直接执行
```

**看不出刚刚放行了一条有风险的命令。** 事后只能翻日志。

禁止档（如删系统目录）不受影响——它那条本来就无条件打框然后退出。

## 已核过：不是确认函数把提示吞了

`--yes` 下确认函数会照常留痕、照常上屏它该上屏的那一行（参数确认、`--no-shell` 警告两处都在用这个机制）。这里的问题在**调用方提前跳过了打印警告框**，确认函数根本没收到要显示的东西。**不要改确认函数。**

## 要做的事

1. 去掉「只在非交互时才不打屏」这层条件，改成**不管 `--yes` 与否都打警告框**。
2. 同步改掉那行写着「非交互（--yes）下不打屏」的注释——改完就不是这样了。
3. 其余不动：禁止档照旧打完退出；非禁止档在 `--yes` 下照旧视为已确认、照旧留痕；取消路径不变。

## 验收

**判据：该让使用者看见的东西，`--yes` 一样不少。**

- [x] `--yes` 跑一条高危命令（现有复现：`rm -rf /var/log/app`）→ 屏幕上出现完整的「⚠ 发现危险命令」框，与交互模式下看到的那十几行**逐字一致**
- [x] 交互模式跑同一条并回车确认 → 屏幕上的框与上一条相同
- [x] 禁止档（现有复现：`rm -rf /etc`）行为不变：打框、退出码 1

**不要求一致的地方**（本来就该不同，不是缺陷）：

- 交互模式打完框会接着问「确定继续？」，`--yes` 跳过提问直接放行——这正是 `--yes` 的用途
- 两种跑法的日志各记各的：交互记「用户已确认风险继续执行」，`--yes` 记「非交互模式放行危险命令」——这两句区分了「有人把关」与「无人值守放行」，是信息不是差异
- 「[非交互模式] 跳过执行选项/参数确认环节」这类过程提示，留不留都行
