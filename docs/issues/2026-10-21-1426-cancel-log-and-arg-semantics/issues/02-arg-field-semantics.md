# 02 改密参数：把「模式判定」与「命令行原值」拆开

Status: 待排期（needs-triage）
Blocked by: 无

## 背景

`--change-password` 的取值装在一个字段里，它同时是两样东西：

- **模式判据**：非空即「这次是改密模式」——五选一的模式计数、归档目录名、超时默认值、批量管线分支都读它；
- **命令行原值**：装着使用者敲的那串字，而那串字在加密开关打开时是密文文件路径、关闭时才是密码。

2026-10-21 的显示面缺陷就是第二重含义造成的（三处显示点把它当密码显示，加密模式下落成 `/h****xt` 形态）。那次已把三处各自改成取解密后的值，混淆源仍在。

## 要做成什么样

1. 模式判定改由一个显式取值回答（本次是哪一种执行模式），不再靠「某个参数字段非空」间接推论。
2. 命令行原值改名为一眼能看出「这是原值、不一定是密码」的名字。
3. 十来处判定点与对应测试跟着改（模式计数、模式名、默认超时、批量管线分支、日志回显等）。

## 开工前要先定的一件事

要不要做**编译期护栏**：让「把旗标原值传给显示凭据的地方」编译不过（例如凭据显示只收一个专用类型）。做的话收益最大（这一类错再也写不出来），代价是跨包签名与 import 一起动。

## 本轮不做的理由

不是修 bug，是给下一个人装护栏：三处显示点已各自取对值，不修也不会再错。属宽重构，需独占一轮。
