# 规格：检查器按语义补判据

**状态**：done
**底本**：`docs/issues/2026-11-09-0945-切换前回顾审计/修复面盘点.md` §4.1（五条绕法、四件机械可判的＋linkname 单列）
**决策**：`docs/adr/0048-判据按引用面判不按写法判.md`

## Problem Statement

「结构被破坏时跑测试就红」是切换之后唯一的防线，而现在这条防线只认一种写法。同一件事换个写法就全绿：

- import 一条包、名字写成 `_` 或 `.` ——这条依赖边根本没被记下来；
- 把 `os.Exit` 先存进一个变量再调——类三只认「当场调用」；
- 在契约里把函数写成 `var F = func(){}`——类四只认 `func` 声明；
- 用 `new(T)` 或一个零值变量造失败类型——类五只认复合字面量。

这不是判据被改松了（`guard` 29 笔提交逐笔看过，没有一笔放宽），是它一开始就只认形状。存心拆的人不必改检查器，换个写法就够了。

## Solution

判据改成回答「这个东西被引入了／被引用了／被构造了没有」，而不是「它写成了哪一种样子」。四条判据各补一处，覆盖面从「一种写法」变成「写法无关」。

真工程现在这四条全是空的（无空白 import、`os.Exit` 只在塔尖、契约无函数值、无 `new`），所以改完仍是绿的——红的是样本。

## User Stories

1. 作为维护者，我希望有人用一种我没见过的写法拆结构时，跑测试就红。
2. 作为维护者，我希望判据说的是「不许引入这条边」，而不是「不许用这种写法写这条边」。
3. 作为审计者，我希望这四条都是「判据本身变强」，不是「新开一类」——类号与台账结构不动。
4. 作为维护者，我希望样本本身就演示绕法：看一眼样本就知道判据在防什么。

## Implementation Decisions

- **类二：import 的边与写法无关。** 解析 import 时把 `_` 与 `.` 的路径也记下来（现在直接 `continue` 掉了），判依赖时一并过规则表；`_` 与 `.` 只影响「这个名字能不能被引用」，不影响「这条边存在」。
- **类三：判引用，不判调用。** `os.Exit`（以及 `log.Fatal` 那一族）只要在这个包里被取用就报，写成 `var f = os.Exit`、`exit := os.Exit`、`defer os.Exit` 都一样。
- **类四：契约里的函数值也是函数。** 包级 `var` 的值是函数字面量或对函数的引用，按「声明了函数」报；`var 哨兵 = errors.New(...)` 这类仍放过——判据是「值是不是函数」，不是「有没有 `var`」。
- **类五：构造的三种写法都算。** 复合字面量、`new(T)`、零值变量（`var x contract.CannotStart` 这类直接声明）都算构造点。
- **linkname 与汇编另立一单。** 它要换的是「怎么读」，不是「判什么」——读链接产物要动构建，禁机制只要一条指令／文件扫描。开发者 2026-11-12 定了「禁掉这两样」（`docs/adr/0049-不经import的边一律禁.md`），落成 05 号单。
- **不新开类号**：四条都在原类里补，台账四格与类号不动（加一类要开发者点头）。

## Testing Decisions

- 四个样本各在既有的假模块里加一处绕法，一个都不用新建模块。
- 既有测试的期望值会跟着变（判据变强，样本多一处违规）：这些属于「改红线区的断言」，已在 ADR-0048 里写明是哪个条件变了。
- 每条都要反向验证：加绕法样本 → 报且只报这一条 → 去掉 → 绿。
- 真工程整跑（`TestProjectIsClean`）必须仍为零违规。

## Out of Scope

- `linkname`／汇编：不在这四条里，由 05 号单按 ADR-0049 落地（禁机制，不读链接产物）。
- 类一／类六／类七的判据（本轮不动）。
- 判据的报错措辞（沿用原类的话术模板）。

## Further Notes

- 这一轮改的是「判据强度」，不是「判据对象」：类号、台账、包清单都不变。
