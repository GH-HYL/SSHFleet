# 目标机输出语言：出厂 locale 改 `C`，拼接形态不变 · 规格

Status: ready-for-human

> **决策依据**：`docs/adr/0024-env穿过sudo边界.md`。本文只写「做成什么样」，取舍理由不在这里重复。
> **现状**：决策已定（ADR 已接受），工单未拆，代码未动。
> **来源**：2026-10-21 报「`-a` 代填运行时脚本输出的中英混排，中文触发词没匹配上」，怀疑 `[env]` 的语言设置没生效。排查底本见 `findings-2026-10-21.md`。

---

## 问题陈述

同一份 `[env]` 配置、同一份代填表，在 CentOS 7 与 Ubuntu 上表现不一样：**CentOS 上脚本读到的是配置里的 locale，Ubuntu 上读到的是目标机自己的（常常是 `C`）**。

脚本按 locale 输出不同文案时，代填触发词只写了一种语言，于是出现「一半命中、一半等超时」或「整批失配」；输出本身还中英混排，看原文排查会被带偏到「脚本写错了」上去。

## 结论（2026-10-28）

| 项 | 取定 |
| --- | --- |
| 语言目标 | 整批稳定英文——可判定、可逐字比对 |
| 落点 | **三份**出厂配置模板的 `[env]` 段：`LANG` 与 `LC_ALL` 两行 `"en_US.UTF-8"` → `"C"` |
| 拼接形态 | **不变**。仍是 `sh -c 'export …; [sudo ]解释器 …'` |
| 取值 | `C`——glibc 内置，不依赖 `locale-gen`，零告警 |
| 目标机探测 | 不做。取值一次定死，全量下发 |

## 已核实的事实

1. **工具没有丢配置**。`-a` 的下发行与非 `-a` 的 `export` 段逐字相同，`-s`、`-c` 两种模式都带。
2. **语言不丢在 sudo 这一层**（2026-10-28 改口）。旧文说「`export` 拼在 `sudo` 之前，过不了 `env_reset`」——该立论已被 ADR-0024 第五节推翻。现有实测：Ubuntu 26.04（classic sudo 1.9.17p2，sudoers 无 `env_keep`）下 `env_reset` 确实执行（自定义变量被丢、`PATH` 换成 `secure_path`），而 `LANG` / `LC_ALL` 靠 `env_check` 存活；CentOS 7.9 另有预置 `env_keep`。**问题不在穿透，在取值。**
3. **`C.UTF-8` 不是通用值**。CentOS 7 是 glibc 2.17，没有它；而且它只是「UTF-8 编码的 C locale」，gettext 在 C/POSIX 下不翻译，解决不了「要中文提示」。
4. **同一个 locale 下也能混排**。提示语语言 = f(目标机有没有该程序的翻译包, locale 是什么, 该 locale 有没有生成)。实测 `LC_ALL=zh_CN.UTF-8` 下 `dpkg` 出中文、`ls` 出英文。
5. **`PATH` 在 sudo 下被 `secure_path` 替换**（同源，不在本议题范围）。
6. **失败分类的关键词全是英文原话**。`config/keywords_error.conf` 里中文只出现在分类名与提示，远端关键词一条中文都没有——目标机出中文提示，分类就整批落到「未归类」。这条支持取值 `C`。
7. **旧值在真实目标系统上会吐告警**。容器（Ubuntu 26.04，`locale -a` 只有 `C` / `C.utf8` / `POSIX`）里跑 `LC_ALL=en_US.UTF-8 bash -c 'echo hi'` 会多一行 `bash: warning: setlocale: LC_ALL: cannot change locale`；改 `LC_ALL=C` 后干净。
8. **三份模板的 `[env]` 段逐字一致**；发布时 `tools/release/release.py:235` 按平台把 `SSHFleet-for-{linux,windows}.conf` 改名成包内的 `config/SSHFleet.conf`。工作区那份 `config/SSHFleet.conf` 不随包发布。

## 影响

- **代填（`-a`）**：`C` 只固定「系统程序的翻译」——脚本自己 `echo` 的中文不受影响。所以触发词仍可能中英都要写，但「系统提示那一半」从此稳定为英文。
- **输出可比对**：失败分类走英文关键词，locale 一旦出中文就整批失配；固定成 `C` 才让分类跨机器成立。
- **字符语义**：`C` 下按字节。`awk length/substr`、`cut -c`、`${#s}`、`grep -o .`、`wc -m` 处理中文会出偏差；`sort`（不带 `-n`）与 `ls` 的顺序会与 `en_US.UTF-8` 不同。
- **python 脚本**：没有 UTF-8 模式时（≤3.13 且关掉 `PYTHONUTF8`，或连 `C.UTF-8` 都没有），`LC_ALL=C` 下 stdout 是 ascii，打印中文抛 `UnicodeEncodeError`、退出码 1。这是净退化，要在手册里点明。
- **日志**：下发行形态不变，`DescribeCommand` 不用改。

## 存量配置

**不处理。** 老配置里写着 `en_US.UTF-8` 就照旧生效——值由配置决定，代码不写死。不给迁移脚本、不给手工改法、不在启动时检测提示。理由：目标机群五花八门，工具走通用配置，不按机群做差异化；改动只在出厂值这一格，不产生负面效果。

## 不做

- 不改拼接形态（不引入 `sudo env`、`sudo -E`）。
- 不改目标机的 `/etc/sudoers`、不代跑 `localedef`。
- 不在工具里做码页检测或转码。
- 不在下发时探测目标机环境再配套传变量。
- 不处理 `-a` 的 PTY 丢字符（另议）。
