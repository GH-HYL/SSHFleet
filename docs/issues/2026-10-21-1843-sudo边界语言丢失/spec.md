# 目标机输出语言在 sudo 边界丢失，代填触发词按语言配就失配 · 规格

Status: needs-triage

> **性质**：只登记现象、已核实的事实与待决问题，**不含实施方案**。语言目标（全英文 / 跟随目标机）、落点（`sudo env` 后置 / 正文自设 / 只改配置）、取值（`C` / `en_US.UTF-8` / 留空）都还没定，等开发者排期时再定。
>
> **来源**：2026-10-21 开发者报「`-a` 代填运行时，脚本按环境语言输出的内容中英混排，中文触发词没匹配上」，怀疑配置文件里的语言设置没生效。排查记录与全部证据见同目录 `findings-2026-10-21.md`。

---

## 问题陈述

同一份 `[env]` 配置、同一份代填表，在 CentOS 7 与 Ubuntu 上表现不一样（开发者观察）：**CentOS 上脚本读到的是配置里的 locale，Ubuntu 上读到的是目标机自己的（常常是 `C`）**。

脚本按 locale 输出不同文案时，代填触发词只写了一种语言，于是出现「一半命中、一半等超时」或「整批失配」；输出本身还中英混排，看原文排查会被带偏到「脚本写错了」上去。

## 已核实的事实

1. **工具没有丢配置**。`-a` 的下发行与非 `-a` 的 `export` 段逐字相同，`-s`、`-c` 两种模式都带（下发行原文见 findings）。
2. **语言丢在 sudo 这一层**。工具的 export 拼在 `sudo` **之前**；sudo 默认 `env_reset`、默认不保留 `LANG` / `LC_*`（文档证据见 findings 第五节），这段 export 过不了 sudo。按 RHEL 系发行版的默认 `/etc/sudoers`（预置 `env_keep`：`LANG` `LC_ALL` `LC_*` 等），CentOS 那边能穿过去——**这条本轮没在 CentOS 上验证**，是解释「两系统不一样」的假设，验法见 findings 第五节末尾那两行自查命令。
3. **`C.UTF-8` 不是通用值**。CentOS 7 是 glibc 2.17，没有 `C.UTF-8`（上游 glibc 2.35 才有）；`en_US.UTF-8` 需要目标机生成过。另外 `C.UTF-8` 只是「UTF-8 编码的 C locale」，gettext 在 C/POSIX 下不翻译，**它解决不了"要中文提示"**。
4. **同一个 locale 下也能混排**。程序提示的语言取决于目标机装没装该程序的翻译包：实测 `LC_ALL=zh_CN.UTF-8` 下 `dpkg` 出中文、`ls` 出英文（本机没有 `coreutils.mo`）。
5. **`PATH` 在默认配置下一直没生效**（同一条原因，顺带查出）。`sudo` 默认会保留调用者的 `PATH`，但 sudoers 里 `secure_path` 有值时直接替换它（本机 Ubuntu 默认 sudoers 设了；RHEL 系同款，未验证），而工具的 `export PATH` 拼在 sudo 之前，等于没生效。这条只登记，不在本议题范围内处置。

## 影响

- **代填（`-a`）失配**：触发词是唯一门控，语言一变就整条命中不了，最终落到「触发词未命中」或等到 `-t`。
- **输出可比对的前提不成立**：失败分类走关键词匹配，目标机语言不同，同一类错误在两批机器上归到不同类。
- **日志说了假话**：日志的「命令行」一行打印了 `export LANG=… LC_ALL=…; sudo bash …`，在 Ubuntu 上这段实际不生效，事后按日志排查会被误导。

## 待定（开工前必须定）

1. **语言目标**：要「整批稳定英文」，还是「跟随目标机语言」？前者可判定、后者贴合本意但产出不可比对。
2. **落点**：见 findings 的候选方案表——`sudo env` 后置（推荐）、env 塞进正文、`sudo -E` 类、只改配置、只作文档兜底。
3. **取值**：`C`（各系统都存在、提示恒英文、中文内容不受影响）、`en_US.UTF-8`（需目标机生成过）、或留空（跟随目标机）。
4. **兼容性口径**：下发行形态一旦从 `export …; sudo` 变成 `sudo env …`，日志与报告里的「命令行」跟着变；按《个人开发规范》四·2 判它是「修 bug 修的是错的行为」还是「输出结构变了」，决定 CHANGELOG 抬不抬主版本。
5. **使用者可见面**：要不要在手册里写清「locale 由谁决定、为什么跨发行版不一致」，以及代填触发词「中英各挂一个」这条诊断建议。

## 不做

- 本节不选定方案、不拆实施工单、不改代码。
- 不要求使用者去改目标机的 `/etc/sudoers`（批量不可维护），这条最多作为兜底文档提一句。
