## 2. 固定件（每条提示词都含）

**锚（判据基准）**：

- A1 `[env]` 出厂值里的 `LANG` 与 `LC_ALL` 改为 `C`（授权来源：助手推导）
- A2 拼接形态不变：非 sudo 与 sudo 两条路径都维持 `sh -c 'export …; <sudo ><解释器> …'`（助手推导）
- A3 不收窄、不废除 ADR-0015 与 ADR-0016 的正文，只各加一行更新记录指向本 ADR（助手推导）
- A4 `PATH` 与 `TERM` 保持出厂值不变（助手推导）
- A5 乱码不作为本决策的处置对象（助手推导）

**固定话**：以上五条是本次审计的共同基准。**你判断的对象是被审文件与这五条锚的差异**：发现被审对象与锚不符，只报与锚的差异，不改写锚，也不替议题 spec 出修法。

**锚质疑出口**：锚本身不是免检项。任一轴若发现某条锚与实测或源码冲突，**单列一节「锚质疑」**，写清哪条锚、什么证据、冲突在哪。它**不并入**你的普通发现，也不许因此改写锚。

**「够格」四判点**（每条发现须回指其中之一）：①每条决定能否落成可验收的工单（有判据、有落点、无悬空承诺）；②理由链里有没有全称化过头的事实主张；③承重的量化结论有没有产物可追；④标注是否诚实（实测／源码推断／未验证；作者明示／助手推导）。

**判定门槛**：【硬伤】= 事实错误或边界被破坏，须附命令实际输出或原文引用；【判断题】= 可权衡，须写清选项与代价。两类都不是就写「未发现问题」。

**作答要求**：按你的问题编号**逐条作答**；某问没有问题就写「该问：未发现问题」，不许漏答、不许凑数。

**授权**：只做只读分析，本轮未授权开工，不得修改任何文件。**唯一允许写的是你自己的回执文件**；需要实测的轴，临时探针与输出落各自沙盒（映射见下）。**不 `git add` / `git commit`，不恢复工作区里已删除的三个旧审计文件，不动那些未提交删除。**

**产出**：回执文件 = 完整版（不限字数，含证据原文与命令输出）；**回传给我的是 ≤1200 字结论摘要**（逐条列编号结论）。

**沙盒映射**：轴 1 `build/audit-2026-10-22-axis1/`、轴 2 `…-axis2/`、轴 3 `…-axis3/`、轴 4 `…-axis4/`、轴 5 `…-axis5/`、复核员 `…-reviewer/`。除轴 3 外，其余各轴不要读别人的沙盒；轴 3 只读 `build/` 既有内容，**排除** `build/audit-2026-10-22-axis*/`。
