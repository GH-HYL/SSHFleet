## 4. 必须知道的背景

**已被证伪的方向（不要再走）**：「`sudo` 套 `sudo`、变量在外层 sudo 之后才读」这种实验形态测的是另一件事，结论与事实相反（ADR 2.2 记录了这个坑）。凡判断「变量能不能穿过 sudo」，变量必须在 sudo **之前**设置、只经过**一层** sudo，且其余形态（PTY、shell、外层 `sh -c`）与工具下发逐字对齐。

2. 「复审」一节的设计；

**开发者给的三条线索（只给线索，不给结论，必须回源头自核；以下三条本轮均未核）**：

## 5. 环境事实（本轮已核）

- `locale -a` 只有 `C` / `C.utf8` / `POSIX` / `zh_CN.utf8` / `zh_SG.utf8`——**没有 `en_US.UTF-8`**，天然可复现「未生成 locale」的机器。
- 可用解释器：`bash` / `sh`(→ dash) / `dash` / `python3`(3.14.8) / `perl`(5.42.3) / `node`(v24.21.0)；**缺** `ruby` / `php` / `lua` / `luajit`。
- `sudo -n` 在本机可用（当前用户 `hyl` 免密）。没有真实目标机、没有 CentOS / Ubuntu-26.04 环境。
- `build/` 按天清理，ADR 第十一节所称的沙盒产物能否找到，由审计员自己查。
