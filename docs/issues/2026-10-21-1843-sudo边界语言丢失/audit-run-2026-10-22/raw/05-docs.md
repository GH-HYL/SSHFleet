## 二（问 2）第七节「须写进配置手册」能否指到具体一册一节

**【硬伤（产物缺失）】** 指不到。原文（`0024:304`）：

> **字符语义**：`awk` / `cut -c` / `${#s}` / `sort` 在处理中文时按字节（3.7、3.8），**须写进配置手册**，否则下一个写 `cut -c1-4` 切中文的人会踩到。

- 文中只有「配置手册」这一册级说法，**没有册号、没有节号**。仓库里有四册带"配置/知识"字样的手册（`2-基础配置手册`、`3-进阶配置手册`、`4-进阶知识手册`、另有一册《1 使用手册》），单凭这句话无法唯一落点。
- 事实上目标是唯一的、可定位的：`[env]` 全仓只有一节 —— `docs/3-进阶配置手册.md` 的「**## 6 远端环境变量**」（`:282-311`）；机理段在 `docs/4-进阶知识手册.md` 的「**## 2 为什么要统一远端环境**」（`:72-94`）。ADR 既未点名，也未说明"配置手册"指 3 册还是 4 册（4 册自称"全部手册的附属手册"，不是配置手册）。

**现有 `[env]` 一节的承接能力**（逐项对照要求的结构 / 示例值 / 留空语义）：

| 要素 | 现状 | 能否承接 |
| --- | --- | --- |
| 结构 | 表格（名字 / 值 / 作用）+「怎么改」三条（加一条 / 留空 / 一条都不要）+ 名字合法字符 + 值按双引号落地 + 与 `--no-shell` 的关系 + `--sudo` 提示（`:284-311`） | **够**：挂在"作用"列或"怎么改"之后加一段即可，不需要新结构 |
| 示例值 | 表格里是 `en_US.UTF-8`（`:288`）；无任何 `cut -c` / `awk` / `sort` 的中文示例 | **不够**：值需同步改，且「按字节」目前**零示例**——`cut -c1-4` 切中文这个具体坑，§6 一个字都没有 |
| 留空语义 | 「把它的**值留空**……被当作不存在、不导入」（`:297`） | **够，但缺反向出口**：A1 后若要按字符处理中文，**不能靠留空**，必须显式写回 `en_US.UTF-8`（ADR `:305` 给了这个出口，§6 没有）。这正是"下一个切中文的人"要读到的那一句，而它现在只存在于 ADR 里，不存在于手册里 |

**【判断题】** 承接落点两个选项（ADR 未指定，派生工单必须先定这个）：

- **选项 A：全部写进 `3-进阶配置手册` §6。** 在表格"作用"列改口，加 3 行「按字节」短例 + 一句"要按字符处理中文就把这两行显式写回 `en_US.UTF-8`，代价见 4 册 §2"。
  代价：§6 面向"怎么配"，`C` 的代价机理（未生成 locale 的告警、GNU 与 uutils 排序差异）塞不进去，只能一句带过；好处是改一处、读者路径最短。
- **选项 B：§6 只留一句 + 指路，机理与代价重写进 `4-进阶知识手册` §2。**
  代价：改动面翻倍——§2 现有 `:82` 整段是反向理由（"钉死成 `en_US.UTF-8`……更普遍、行为更稳"），必须**重写**而不是加句；同时 `3:288` 表格与 `4:86` 那句「统一字符集与排序」都要改。好处是与手册既有的"同一主题只在一处详述"分工相容（`CHANGELOG.md:139` 记的重排原则）。

（本轴不判哪个选项对，只指出：ADR 现在两个选项都没选，`须写进配置手册`这一句派不出可验收的工单。）

## 三（问 3）第四节末段的「手册责任 → 第七节」是否认领到具体一册一节

**【硬伤 H1（指针悬空）】** 原文（`0024:224`）：

> 因此本 ADR 对乱码的处置是：**不修改工具的字节链路**（实测支持），并把**手册责任**放在「**告诉使用者往哪看**」（**见第七节**）。

第七节（`:299-305`）全文五条，逐条核对：

1. 配置（`config/SSHFleet.conf` 的 `[env]` 两行 + 注释）——配置侧，非手册；
2. 老配置（不自动迁移）——配置侧；
3. 下发形态（不变）——实现侧；
4. 字符语义（须写进配置手册）——**这是唯一涉及手册的一条，讲的是"按字节切中文"，不是"乱码往哪看"**；
5. `en_US.UTF-8` 仍可用——配置侧。

**第七节通篇没有出现「乱码」「方块」「码页」「字体」任何一个词**，也没有任何一句认领"告诉使用者往哪看"。第四节这条指针指向了一个不存在的内容——不是"指得不够细"，是"指过去没有"。同时第五节决定 5（`:239`）只写"乱码不作为本决策的处置对象"，也未承接手册落点。结果：A5 在 ADR 内部是成立的（不处置），但它指定的外部承接（手册）在 ADR 里**没有任何具体指向**，派生工单时这一段无法开工。

## 四（问 4）CHANGELOG 档位：A1 算不算不兼容

**判据原文**（`docs/个人开发规范.md` 四·2，`:273-276`）：

> **「不兼容」怎么判**：只问一句——**升级之后，使用者拿着他原来的配置、原来的命令，还能不能照旧跑起来？** 判的是**使用者的东西**（配置文件、命令行参数、脚本／清单），改代码内部结构不算
> - **算的**：……**某字段取值语义变了；默认行为变了、旧命令跑出不同结果**；……
> - **不算的**：……新增选项或新增可选配置字段；只改报错文案……；补文档
> - **拿不准就按不兼容算**——代价不对称：多抬一次主版本只是号大一点，漏抬一次则**使用者的东西坏了却没有任何提示**

**【判断题】** A1 落在"算"与"不算"的交界上，取决于一件本轴无权核实的事实：

- **选项 A：判不兼容 → 主版本。**
  依据：A1 改的是**默认行为**（出厂值），且后果正是判据列举的「默认行为变了、旧命令跑出不同结果」——`sort`（无 `-n`）在大小写混合数据上 85% 结果不同、`cut -c` 会切出半个汉字（ADR 3.7/3.8）。ADR 自己也写明「**不提供自动迁移**」（`:302`），意味着使用者不会收到任何提示。
  代价：若新出厂配置只在首次安装时铺设、不覆盖存量配置，则对存量使用者是虚抬（号大一点，代价可接受，但会在 CHANGELOG 里写出一条他们根本没经历过的"不兼容"）。
- **选项 B：判兼容 → 修订（无新增）。**
  依据：ADR 第七节明写「使用者的既有配置里若仍写着 `en_US.UTF-8`，本 ADR 不影响其行为——取值由配置决定，不是代码写死」（`:302`）。若该句成立，则使用者的配置文件字节不动、照旧能跑，判据问的那一句答案是"能"；`[env]` 是可选段、无必填校验，与 `CHANGELOG.md:241` 那次「`[interactive]` 段新增必填 → 判不兼容」的情形不同（那次旧配置**直接报错**）。
  代价：若打包实际会覆盖或合并配置，则属漏抬——正是判据 `:276` 说的"使用者的东西坏了却没有任何提示"，`sort` 结果变了没人告诉他。

**本轴倾向不表态**，但需指出：`0024` 全文没有任何一句交代"新出厂配置如何到达存量使用者"（第七节只说"取值由配置决定""不提供自动迁移"），所以这个问在 ADR 侧**本身就缺一条事实**；按 `:276` 的"拿不准按不兼容算"，默认动作是主版本，而 ADR 未提 CHANGELOG 档位一个字。

**CHANGELOG 全文检索（命中段落只引这些）：**

- `CHANGELOG.md:134`（`## [9.1.0] - 2026-10-09`，Added）：「**远端环境变量写在配置文件里**……出厂给了 `LANG` / `LC_ALL` / `PATH` / `TERM` 四条（**统一字符集与排序**、补一组标准目录、抑制彩色与转义序列）」——值 + 作用表述均需在新段改口；此段**已封口**（`个人开发规范:278`「已封口段落 MUST NOT 再改（含号与日期）」），不得回改。
- `CHANGELOG.md:172`（`## [9.0.0] - 2026-10-07`，Added）：「目标机没装 bash 也能跑……改由工具显式设好 locale 与 PATH」——形态描述，A2 下仍成立，无需改。
- 其余命中行（`:265` `:273` `:294` `:296` `:303` `:405` 等）均为"乱码"作为普通词的其它语境（界面文案、BOM、发布包文件名、截断），与 A1/A5 无关，逐条看过，不引。
