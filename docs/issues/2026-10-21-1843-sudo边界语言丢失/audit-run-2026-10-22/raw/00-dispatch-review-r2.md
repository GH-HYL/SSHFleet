## 三、预设污染

### 污-1【中】锚质疑出口只收"实测或源码"，A3 / A5 实际免检

L27："任一轴若发现某条锚与**实测或源码**冲突，单列一节「锚质疑」"。

- A1 / A2 / A4 是值或形态，能被实测与源码挑战，出口有效。
- A3（"不收窄、不废除 ADR-0015 与 0016 的正文，只各加一行更新记录"）与 A5（"乱码不作为本决策的处置对象"）是范围与授权判断，**与实测、源码都没有交集**，永远触发不了这个出口。

这正是"给了出口但出口开在墙的另一侧"。A3 还会被轴 4 Q2 从"实际改动是否只加一行"侧面验证，A5 则只剩轴 4 Q6 的自洽检查——两条锚的"可质疑性"不对等，而包内没有说明这种不对等是有意的。

**建议**：出口改为"与实测、源码、上游 ADR 正文、议题 spec 任一冲突"，或给 A3/A5 单列可质疑来源（0015/0016 正文、`spec.md` 待定项）。

### 污-2【中】轴 1 Q4 把 `secure_path` 当既定事实，而本轮无法实测

L58："`PATH` 在 sudo 下被 `secure_path` 替换，与「`PATH` 保持出厂值」是否冲突？出厂的 `PATH` 在 sudo 下是否实际生效？"

前半句是断言，不是待证命题；后半句要实测，而 L45 明说"`sudo` 当前不可用……需要 sudo 才能做的验证，标「未验证」"。问法像可验证，条件却把验证封死——子 agent 大概率把 ADR 9.2 的原文复述一遍，当作"已核"。

**建议**：改为"9.2 关于 `secure_path` 的陈述依据是什么？在 sudo 不可用的本轮，`PATH` 是否生效只能判为未验证，请写明依据来源"。

### 污-3【中】"只报与锚的差异"窄于四判点，与轴 3 的任务直接冲突

L25："你判断的对象是被审文件与这五条锚的差异：发现被审对象与锚不符，**只报与锚的差异**"。

但 L29 判点②要判"理由链里有没有全称化过头的事实主张"、判点③要判"承重的量化结论有没有产物可追"——3.2 / 3.3 / 3.8 的毛病与锚无关。按 L25 字面执行，轴 3 的大部分发现都不属于"与锚的差异"，要么被压掉，要么被迫改写成锚的语言（"锚 A1 与 3.8 的数字不符"这种扭曲句式）。

**建议**：改为"只报与锚**或四判点①–④**相关的差异"，并注明"锚质疑"与"产物缺失"不受此句限制。

### 污-4【轻】轴 4 Q6 是有罪推定式问法，缺对称出口

L114："第二节的叙述与后文结论**有没有**互相矛盾、**或把「当时怎么测的」写成了「结论」**？更新记录**有没有**记全本轮改动？"

### 污-5【轻】轴 4 Q4 预设"决策人栏 ↔ prep §3"可逐条对应

## 四、边界与产出

### 界-1【硬伤】轴 5 的白名单里没有 ADR，但它的五问全要读 ADR

- 白名单 L136：6 份手册 + `README.md` + `CHANGELOG.md` + `GLOSSARY.md` + `个人开发规范.md`——**没有 ADR**。
- 禁令 L138："不碰：ADR 正文的事实主张（归轴 2/3/4）"。
- 但 Q2（L131）要读第七节，Q3（L132）要读"决定 5"，Q1 要判手册表述与 A1 的关系；§3 覆盖表 L169 又写"轴 5 | **七、决定 5**"。

白名单、禁令、覆盖表三方打架。子 agent 照白名单跑，Q2/Q3 第一步就无源；照 Q2/Q3 跑就违白名单。它还得自己决定"读第七节算不算碰 ADR 正文的事实主张"——这恰好是每个子 agent 会做出不同选择的地方，回执格式就会不齐。

**建议**：白名单加"`docs/adr/0024-…md` 第五、七节（只读定位，不判事实主张）"，并把 L138 改成"不判 ADR 正文的事实主张"。

### 界-2【硬伤】轴 4 Q4 依赖 prep §3，而 `prep.md` 不在任何轴的白名单

L112 要"逐条比对 prep §3 的授权来源"；全包提到 prep 的只有两处：L41（§5.1 环境事实，已转述）与 L112（§3 授权来源，未转述）。六轴白名单（L62 / L80 / L97 / L118 / L136 / L155）都没有 `build/audit-2026-10-22/prep.md`。

→ 这一问**不可执行**。子 agent 要么跳过（违 L33"不许漏答"），要么越界读（违授权）。

**建议**：把 prep §3 原文抄进固定件，或把 `prep.md` 加入轴 4 白名单并注明"只读 §3"。

### 界-3【硬伤】轴 2 Q3 要的 `interpreterTable` 没有定位，且大概率在域外

L76 要"与 `interpreterTable` 的交集有多大……给一张覆盖矩阵（行 = 解释器，列 = 是否被 3.5 / 3.7 / 6.1 的结论覆盖）"；轴 2 白名单（L80）只有"ADR 第三、六节"与"`command.go` 315–464"。

`interpreterTable` 是代码符号（驼峰），它的定义处若在：

- `internal/config/*` → 属轴 1 的域（L62），轴 2 不能读；
- `command.go` 21–105 → 无人认领（缝-1），轴 2 同样不能读；
- 恰好在 315–464 → 才能读。

包内从未给出该符号的路径，还专门在轴 1 的"不碰"里写了"ADR 三、六节与**解释器表**（归轴 2）"（L64），说明它被当成一个独立对象——但轴 2 的白名单里没有它。

→ 保证不了"表外解释器有没有对应结论"能被回答。子 agent 只能按 ADR 里的解释器列表硬凑，矩阵会失真；更糟的是它不会在回执里说"我没看到表"。

**建议**：给出 `interpreterTable` 的确切文件与行区间并加入轴 2 白名单；若它就在 315–464，明写"表在 315–464 内"。

### 界-4【硬伤】没有"域外依赖 / 问题不可答"的上报通道

固定件只给两条出路：与锚不符走「锚质疑」（L27）；其余按 L33 逐条作答且"不许漏答、不许凑数"。同时 L35 禁止越界写、白名单逐轴限定、L39 还管住了沙盒互读。

子 agent 遇到"问题要的文件不在域内"时（界-2、界-3 是实例；轴 1 Q1 问"有没有第二来源"也可能落在 `internal/config/*` 之外），只剩两条路：**静默编**或**越界读**。两条都会污染整轮结论，而且从回执上看不出来。

**建议**：在固定件加第三个小节「域外依赖」——写清问题编号、缺哪个文件、为什么白名单不够；**停在此处、不自行扩域**，该问结论记"不可判（域外依赖）"，允许主 Agent 据此二次派发。这一条能同时兜住界-2/界-3 的最坏情况，成本最低、收益最高。

### 界-5【中】判定门槛缺"无法判定"档，也没有每轴总判与答题台账

L31 只有【硬伤】/【判断题】/「未发现问题」三态。环境受限（sudo 不可用、缺解释器）与域外依赖都无处安放——按字面，一个"因环境测不了"的问题既不是硬伤也不是判断题，只能写"未发现问题"，这是**假阴性**。

另外没有要求每轴末尾给"本轴 N 问、已答 M、不可判 K、硬伤 X、判断题 Y"的台账 → 主 Agent 无法判断某轴是否真的逐条答完，L33 的"不许漏答"没有检查口。

**建议**：加第四态【不可判】（须写原因：环境 / 域外依赖 / 无产物），并要求回执首部一行台账。

### 界-6【轻】摘要无模板

L37 只给"≤1200 字结论摘要（逐条列编号结论）"。给定 5–8 问的轴，1200 字塞不下"逐条 + 证据"，实际会退化成一句一问。

**建议**：给三行模板：硬伤数 / 判断题数 / 不可判问题编号；详细结论留在完整版。

### 界-7【轻】轴 1 的脚本路径没写全

L62 写 `build-linux.sh`、`build-windows.bat`，实测都在**仓库根**；包内其余路径都是全路径。子 agent 可能去 `modules/SSHFleet_Go/` 下找。

### 界-8【轻】轴 3"曾产出但已清理"这一档常常不可判

L93 要求该档给 `git log` / `git show` 证据，但同一句自己说"`build/` 被 `.gitignore` 忽略且按天清理"——被忽略的产物通常不进 git。于是这一档在最常见的情况下没有证据来源。

**建议**：补一句"查 `git log --all -- build/` 仍为空时，记『无 git 证据』，不得据此升格为『从未产出』"。

## 五、明确判断

**这包现在不能直接发。** 阻断项 6 条：**缝-1、缝-2、界-1、界-2、界-3、界-4**。

其余 20 条不阻断，但建议本轮一起改；其中 **缝-3、缝-5、重-1、重-2、污-1** 若不改，合并阶段大概率出现"同一节两个相反结论"或"某条决定无人认领"，主 Agent 又不能裁谁对（L192），最后只能再开一轮。

这几条的共同病根是：**用"整节 / 全文 / 自由域"代替行区间与文件清单**（缝-1、重-2、重-3、界-1），以及**用锚代替判据来源**（污-1、污-3、缝-3）。改法不用重写包，把域改成行区间、把锚的出口放宽、加一节「域外依赖」即可。
