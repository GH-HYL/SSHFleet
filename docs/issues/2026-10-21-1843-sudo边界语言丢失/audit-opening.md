## 开场白正文

开始之前先看这份文件（同目录，是旧版审计，**只作参考不算依据**）：
`docs/issues/2026-10-21-1843-sudo边界语言丢失/audit.md`

它开头有一段「这是一份旧审计，只作辅助参考用」的说明，按那里的要求用它——
是独立第三方意见，不是派生工单的依据；它的每条发现都要回源头自己核。

用 `/audit-retrofit` 对 `docs/adr/0024-env穿过sudo边界.md` 做一次回顾审计。

**这次的处境**：

- 这个 ADR **还没有落地**。代码一行没改，`config/SSHFleet.conf` 里仍是 `en_US.UTF-8`。所以是「阶段 A：只有 ADR」——审的是**这份 ADR 够不够格拿去派生 spec 与工单**，不是审已实现的代码。
- 不要硬凑实现轴、复现轴，那些没东西可审。

**必须从源头核实的三件事**（旧审计发现了，但都要自己重核，不许直接采信）：

1. **打包模板**：ADR 第七节写「改 `config/SSHFleet.conf`」，但 `build-linux.sh` / `build-windows.bat` 实际是把 `config/SSHFleet-for-*.conf` 复制成包内的 `SSHFleet.conf`。照 ADR 写工单，可能做出「本地变了、发出去的包没变」。**这条在 Linux 环境下最容易验证，请先查。**
2. **解释器失败形态**：ADR 说「`C` 的失效形态是『不存在』」。旧审计实测 python 在 `LC_ALL=C` 下写中文会 `UnicodeEncodeError`。这句结论到底对哪些解释器成立？`interpreterTable` 里那些（perl / ruby / php / node / lua）各自是什么形态？
3. **缺产物的量化表**：ADR 3.8 的「0% / 85% / 12 行」、9.3 的 uutils 结论，在仓库里都找不到脚本与输出。要么补出来，要么这些数不许承重。

**不要重复审**：这份 ADR 此前已经审过三轮（对话忠实度、复审一节的设计、旧版回顾审计）。再审「说法是否与对话一致」没有意义。

## 分工

按技能来：

1. **摸底**：判阶段、定锚（ADR 的决定逐条，标清是作者明示还是助手推导）、查既往审计记录、写交接清单。
2. **切轴**：按这一轮的实际风险切，不套模板。
3. **分发审**：提示词写好后先别发，派一个只审设计的，查轴间缝隙、重叠、预设污染、边界与产出。**这轮等待是设计内的，不要跳过。**
4. **并行审计**：各轴跑，文件域隔离。
5. **复核员**：另派一个不接现成轴、自建框架的。
6. **落档**：等全部回执到齐 + 自己梳理完，写 `report.md`。**只做结构合并，不写见解**——禁止排优先级、禁止判断谁对、禁止合并相似条目。写完拿技能 7.6 的清单自查一遍。

## 附：为什么这份开场白这么短

详细的背景（这份 ADR 的历史、三轮审计的结论、被证伪的方向）**不写在这里**。

原因：那些内容在 `audit.md` 与 ADR 本文里都有，让新会话自己读会比你转述更准。而开场白只需交代三件事——**处在哪个阶段、哪几条必须从源头重核、不要重复审什么**。

其余交给技能与摸底。
