## 一、议题未结束

### 1. `locale-across-sudo` —— needs-triage（本目录，2026-10-21 立）

只登记了现象与证据，方案一个没定。开工前必须定的五项：

1. **语言目标**：整批稳定英文，还是跟随目标机语言。
2. **落点**：findings 的候选方案表里推荐 `sudo env` 后置；其余是 env 塞进正文、`sudo -E` 类、只改配置、只作文档兜底。
3. **取值**：`C` / `en_US.UTF-8` / 留空。
4. **兼容性口径**：下发行一旦从 `export …; sudo` 变成 `sudo env …`，日志与报告的「命令行」跟着变——按《个人开发规范》四·2 判这是「修 bug 修的是错的行为」还是「输出结构变了」，决定 CHANGELOG 抬不抬主版本。
5. **使用者可见面**：手册要不要写清「locale 由谁决定、为什么跨发行版不一致」，以及代填触发词「中英各挂一个」这条诊断建议。

已知空白：sudo 的行为没有实测（本会话起不来），RHEL / CentOS 侧的 `env_keep` 全是未验证的假设。另有一条同源事实只登记不处置——`PATH` 在 sudoers 设了 `secure_path` 时同样过不了 sudo 边界。

### 2. `cli-path-normalization` —— needs-triage（2026-10-21 立）

`--convert-secret` 与 `-f` / `-a` 已改成「原值交给系统」，`-s` / `-u` / `-p` / `-d` 仍过 `normalizePath`（去首尾空白、`\`→`/`、盘符归一、`path.Clean`），同一路径形态两种结局。开工前五个待查问题：口径边界怎么划、远端路径该不该本地加工、去掉规范化后 Windows `\` 与盘符怎么办、与空格检查的关系、要不要给迁移说明。

同目录还有一张「审计追加」表，是四轴审计时翻出的相邻路径问题，**都不在 `-s`/`-u`/`-p`/`-d` 范围内**，排期时要一并看。

### 3. `remote-disk-full` —— 工单 01 为 `ready-for-agent`，议题无 spec

议题刚立，八个验收框全空。摸底工单要做的是：搭带容量上限的真实块设备（不用 tmpfs），把「一开工就满」「写到一半才满」「权限不足」三种情形各跑一次上传，记下分类、错误详情原文、目标机残留、成功计数；再评估「让工具说出磁盘满」的四条路（失败后探 `df`、SFTP 扩展字段、预检探空间、不做）各值多少代价。

按 README 的约定，摸底之后**要么以结论结案、要么立 spec**——现在停在前一步，没有后续载体。

### 4. `cancel-log-and-arg-semantics` / 工单 02 —— 待排期（needs-triage）

刻意搁置的一条。spec 写的是「已完成（done）」，那是就 01（取消留痕）而言；02 要把改密参数字段按含义拆开——「模式判定」与「命令行原值」现在装在同一个字段里，加密开关打开时它装的是密文路径，所以下一个改代码的人仍要自己分辨。

开工前要先定一件事：要不要做**编译期护栏**（凭据显示只收一个专用类型，让「把旗标原值当密码传」编译不过）。做的话收益最大，代价是跨包签名与 import 一起动；十来处判定点与对应测试也要跟着改。
