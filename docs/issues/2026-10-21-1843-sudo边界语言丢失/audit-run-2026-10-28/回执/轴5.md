## 【硬伤】

### H1 0030 的决定 1，正是 0024「明确不做」里点名禁止的那件事，两份 ADR 都没处理

- `0024:369`（第八节）：**「不在下发时探测目标机环境再配套传变量。** 作者 U12 原话：「还是尽量别去检测当前是什么环境，然后给它做一个配套的环境变量传进去。**别干这种活**。」——包括「先探 `locale -a` 再决定传哪个值」这类只读探测。**取值一次定死，全量下发。**」
- `0024:10`（决策人·作者明示栏）：「别再开单独分支、**别去检测目标机环境再配套传变量**（U12）」
- `0030:44-47`（决定 1）：「问机器：`locale charmap` 是不是 `UTF-8`；…不是 → 在 `C.UTF-8` / `en_US.UTF-8` 两个中性名里挑一个**确实存在**的…挑到就**只** `export LC_CTYPE=<挑到的>`」
- `0024:471`（更新记录末条）只释放了「五、决定」第 1 条、6.1 的论证、第七节两条；**第八节不在释放清单里**。而 `0024:3` 状态行写「其余仍有效」。

判：0030 决定 1 做的事与 0024 第八节点名禁止的事字面相同——先 `locale -a`，再据此决定设不设、设哪个。差别只在执行位置（这段跑在目标机上，0024 那句话针对的是下发前的探测）。这个差别 ADR 里一个字都没写，于是两份 ADR 现在同时声称「作者禁止探测」和「作者要求内建判断」，读者无法判断哪句还有效。

### H2 0024 状态行「其余仍有效」把两条已被推翻的句子判成有效，更新记录的释放范围也不全

- `0024:3`：「**状态**：部分作废（partially superseded by ADR-0030）—— 决定 1 与 6.1 的立论不再约束，**其余仍有效**」
- `0024:359`：「**下发形态**：**不变**。日志与报告里的「命令行」一行形态不变，`DescribeCommand` 不用改。」
- `0024:360`：「**字符语义**：`awk` / `cut -c` / `${#s}` / `sort` 在处理中文时按字节（3.7、3.8），须写进配置手册」
- 现在的形态：`0030:66`「片段本身 **162 字节**」恒进下发行；`0030:59` 只设 `LC_CTYPE`，字符语义不再恒按字节。
- `0024:471` 的释放清单只列了第七节「配置」与「`en_US.UTF-8` 仍然可用」两条，没有「下发形态」「字符语义」。

判：状态行与更新记录互相打脸（状态行说其余有效，更新记录承认第七节已被挖掉两块）。更要紧的是这两条被漏掉的句子给的是一条**行动结论**——「`DescribeCommand` 不用改」，谁照它办事就会漏改。

### H3 「出厂只留 `PATH`」与同页的「`TERM=dumb` 保留」互斥，也与三份出厂配置不符

- `0030:52`：「**`[env]` 收缩**：出厂只留 `PATH`；`LANG` / `LC_ALL` 从出厂配置里删除」
- `0030:53`：「**`TERM=dumb` 保留**，理由与代价见第五节。」
- `modules/SSHFleet_Go/config/SSHFleet.conf:45-47`（另两份同）：`[env]` / `PATH = "…"` / `TERM   = "dumb"`
- `0015:69`（更新记录）：「`[env]` 出厂只留 `PATH` 与用户自定义变量」

判：同一份「决定」列表里第 3 条与第 4 条互斥；出厂三份配置都是两行。按 决定 3 字面执行会删掉 `TERM`，而 决定 4 要求保留。同一句话在 `0015:69` 也写了一遍，等于把矛盾复制到第二份 ADR。
（这句话与锚 3 同字，见「锚质疑 4」。）

### H4 「`[env]` 里的旧键会被新语义接管或忽略」——既没接管，也没忽略

- `0030:71`：「**存量配置**：工具尚未发布，不考虑兼容；`[env]` 里的旧键会被新语义接管或忽略。」
- 证据：全仓 Go 无任何 `LANG` / `LC_ALL` 特判（`grep -rn '"LANG"\|"LC_ALL"' --include=*.go internal/` 只命中两处注释）；`ExportPrefix`（`modules/SSHFleet_Go/internal/ssh/command.go:27-48`）对 map 里每个键一律导出；`[env]` 的校验只管键名是不是合法 shell 名，不认具体键（`internal/config/config.go:218` 那条必填项只要求段存在）。

判：旧 `LANG=en_US.UTF-8` 会照原样 `export` 下去，随后片段里 `locale charmap` 读到 `UTF-8` 就什么都不做——用户的旧值反而**优先于**新机制。这与 决定 1「编码不让用户配」字面冲突，也让 决定 3「`LANG`/`LC_ALL` 从出厂配置里删除」读起来像是工具不再接受这两个键。

### H5 0015 的状态值漏了「部分作废」，自 2026-10-09 起就不是全篇有效

- `0015:3`：「**状态**：已接受（accepted）」
- `0015:71`（2026-10-09 更新记录）：「上文「决定」第 3 条里“值按需加引号（shell 安全字符裸拼，含空格等才包单引号）”…均**不再约束**；替代见 ADR-0016。」
- `0015:69`（2026-10-28）又收窄了 locale 一类。

判：0015 有两次「部分不再约束」，状态却仍是 `已接受`。读者只看状态行会以为整篇有效，进而按 决定 3 的引号规则去核对实现。

### H6 「本机没有这两个程序」——`whiptail` 在，且当场可测

- `0030:77`：「**代价**：依赖终端能力的程序会失败。实测 `clear`、`tput cup` 返回 1；ncurses 类交互安装器（dialog / whiptail）预期也会失败——**本机没有这两个程序，未测**。」
- `0030:84`（第六节·没证实的）：「dialog / whiptail 在 `TERM=dumb` 下的确切行为。」
- 证据：`dpkg -l whiptail` → `ii  whiptail  0.52.25-1ubuntu3  amd64`；`ls -l /usr/bin/whiptail` → 存在（`dialog` 确实没有，`command -v dialog` 无输出）。
- 实测（`script -qec` 造 PTY）：`TERM=dumb whiptail --title t --msgbox 'hello' 10 40` → 退出码 1，stdout 首行 `Your terminal lacks the ability to clear the screen or position the cursor.`；`TERM=xterm` 下同一条命令正常画框（ESC 序列满屏）。

判：这条把「装着的程序」说成「没有」，并把一条当场能测的项列进「没证实的」。§五 的「预期也会失败」这条推断其实是对的——但 ADR 用「未测」把它降级，读的人会以为这条结论悬着。
（若「本机」指另一台机器，见 J4：全文没有一处指认「本机」是哪台。）

### H7 「每次执行多 2–3 个进程」——UTF-8 机器上只多 1 个

- `0030:70`：「**开销**：每次执行多 2–3 个进程（`locale charmap`、`locale -a`、`grep`），毫秒级。」
- 证据（沙盒 stub 记录每次调用，`build/audit_run_2026-10-28/轴5/bin/{locale,grep}`）：
  - `CHARMAP=UTF-8` → 日志只有 `locale charmap` 一行，**1 次**；
  - `CHARMAP=ANSI_X3.4-1968` → `locale charmap` / `grep -Eixm1 …` / `locale -a`，**3 次**。
- 决定 1 第 2 步明写「是 → 什么都不做（不多此一举）」，那批机器（§一 说的「已 UTF-8 的机器」）只付 1 个进程。三项清单也默认三条都跑，实际后两条只在非 UTF-8 时发生。

判：数值覆盖的区间错了。代价不大，但这是「影响」节里唯一一个成本数，写宽了会让「这项开销可忽略」的论证变成空话。

### H8 决定 2 的授权来源在「决策人」两栏里没有对应项

- `0030:6-11` 作者明示 5 条：交换机/小型机、编码不给用户配、`-a` 算在内、`PATH` 留着、`TERM` 交助手判断。
- `0030:12-17` 助手推导 5 条，其中只有「语言只设 `LC_MESSAGES=C`、不清 `LANGUAGE`」——是**手段**。
- `0030:24` 原话块里才有「他只管英文」；锚 2 也把「提示语要能统一英文」记为作者明示。

判：决定 2 的**目标**（要英文）是作者明示，**手段**（`LC_MESSAGES=C`）是推导。现在两栏里只见手段不见目标，读者会读成「整个语言开关都是助手自选」。doc-guide 一 要的是「谁定的写清」，方向反了也同样失效——按这份分类去复审，作者给的需求会被当成可推翻的推导。

### H9 「默认 `false`」与实现的必填校验不符

- `0030:48`：「**语言只留一个开关**：新开 `[locale]` 段，键 `english`，默认 `false`。」
- `internal/config/config.go:219`：`{"locale.english", definedStr(md, "locale", "english")}` 在必填表；`config.go:232` 缺则 `配置缺少必填字段：…`；`config_test.go:153-155` 断言「整行删掉应报缺少必填字段 locale.english」。

判：没有「默认」这一说——不写就启动失败。读者会把「默认 false」理解成可以省略这个键。
（与轴 4 第 2 条同一处文本，判据不同：那边判「默认 false / 必填 / 不考虑存量」三者能否同时成立，这里只判描述与 schema 是否一致。）

## 【判断题】

### J1 「92KB 减约 200 字节」这个减法找不到算法

`0030:66`。拆开看：
- 「约 92KB」可核对：`answerLimit = 122880`（`internal/cli/answer.go:28`）× 3/4 = 92160 字节 = 92.16 kB（十进制）。但它把外壳开销按 0 算——非正文部分实测至少 101 字节（命令形态 263 − 片段 162；`-a` 还多一层 base64 外壳，只会更大），所以正文上限 ≤ (122880−101)×3/4 ≈ 90.9 kB，92KB 是理论最大值。
- 「减约 200」对不上任何一个：片段进下发行 162 字节（english 开 184），正文经 base64 进 argv（4/3），所以正文上限只减 162×3/4 ≈ **121** 字节（开 english ≈ 138）。200 比两者都大约 45%。

代价：偏保守 80 字节，没人会因此出错；但它出现在一个自称「可复现」的数字段里，而 `spec.md:67` 已经原样抄走。

### J2 0030 没有回应 0024 用来否掉「按发行版分档」的那条理由

`0024:398`：「按发行版分档… → 同一批机器上会出现多种行为，**破坏「逐字可比」这个初衷**」。
0030 的形态恰恰是每台机器按自己的 `locale -a` 决定设不设、设哪个，`0030:61`「已经 UTF-8 的机器上不产生任何副作用」正是「每台不同」的自述。§三 只论证了「挑不到不设是安全的」，没回答「同批机器行为不同、逐字可比怎么办」。
理由：如果那条理由能否掉分档，它同样能否掉「按机器挑名」，得说明为什么这次不算。这不是错，是理由链缺一环——将来有人拿 0024 第十节来推翻 0030 时，0030 里没有可引的答复。

### J3 「只动 `LC_CTYPE`」是全局口径的写法

`0030:59`：「**只动 `LC_CTYPE`**：它只管「一个字符算几个字节」，不碰语言（`LC_MESSAGES`）…」
`0030:49`：「开 → `export LC_MESSAGES=C`」。
粗体句只在 `english=false` 时成立，但没有任何「仅指编码片段」的限定。它同时被写成锚 7（见「锚质疑 2」），会被别的轴当不变式逐条验。改成「编码片段只动 `LC_CTYPE`」即消除，代价为零——所以列判断题而不是硬伤。

### J4 全文的「本机」没有一处指认，且引用的版本与本审计机对不上

- `0030:77`「本机没有这两个程序」、`0024:224`「本机 mawk 1.3.4」、`0024:225`「本机 uutils 0.12.0」、`0024:180`「本机 perl 5.42.3」、`0024:159`「实测两台机器上 `C` 与 `POSIX` 均 0 行警告」。
- 本审计机：`ls --version` → `ls (uutils coreutils) 0.10.0`；`perl -v` → `v5.40.1`。

判：版本对不上，说明 ADR 里的「本机」不是这台（或数字另有来源）。doc-guide:64 要的正是「这条结论是在哪台机器、什么形态下测出来的」——全文没有一处交代，于是这些结论既不可复核，也无法判断是否已过期。
（与 H6 相邻但不同：H6 是 whiptail 那条事实，本条是全文的指认方法。）

### J5 0015 的更新记录把实现手段写成了开关名

`0015:69`：「语言只留一个 `LC_MESSAGES=C` 开关」。真开关是 `[locale] english`（布尔），`LC_MESSAGES=C` 是它打开后的效果。照这句话去配置里找，找不到叫 `LC_MESSAGES` 的键。
代价：0015 是「配置驱动」这条线的上游 ADR，用词混一层，后面的人会把「加个 `LC_MESSAGES` 键」当成现行做法。

### J6 0029 把 92KB 挂在了 `MAX_ARG_STRLEN` 上

`0029:19`：「从 argv 的 `MAX_ARG_STRLEN`（正文约 92KB）」。`MAX_ARG_STRLEN = 131072`，×3/4 = 98304 字节 = 96 KiB（`docs/adr/0010-命令体改走命令行.md:22` 记的正是 96KB）。92KB 出自工具自己的 `answerLimit = 122880`（`cli/answer.go:28`）×3/4 = 92160。两个数差 8192 字节，正好是 131072 与 122880 之差。
代价：把「工具自设的 120KB 闸门」说成「内核上限」，读者会以为余量 8192 是内核给的——那条余量的真实用途（sshd 自己还会往 argv 里加东西）就没地方写了。`0029:40` 又说「`-a` 的 92KB 正文上限…都留着」，同一个数换了个名字。

### J7 挑名的优先级没写

`0030:46`「挑一个**确实存在**的」，代码是 `grep -Eixm1`（`command.go:78`），取 `locale -a` 输出里的第一条。两个候选都在时用哪个，ADR 没写；实现给的是 `locale -a` 的排列顺序（本机 `locale -a` 是 `C` / `C.utf8` / `POSIX` / `zh_CN.utf8` / `zh_SG.utf8`，`C.utf8` 会先中）。
判：两个候选的字符分类同为中性（§三 已论证），实际无差；但「决定」没写清到足以据此判断实现对不对——这一条无法用来验收。

### J8 「25 行」缺条件，也没带实现名

`0030:75`：「`TERM=xterm` 下 `ls --color=auto` 25 行带转义，`TERM=dumb` 下 **0 行**」。25 取决于目录里有多少个会被着色的条目，目录状态没写；实现名也没写——而 `0024:230` 自己立的规矩是「手册里写这条、工单里做验收，都必须带上实现名，否则换了发行版就翻案」。
本机（uutils 0.10.0，`script` 造 PTY，25 个普通文件 + 1 目录 + 1 可执行 + 1 软链）复现出同向差异：`TERM=xterm` 7 个 ESC、`TERM=dumb` 0 个。方向成立，数字不可复现。

### J9 第六节第 2 条是源码推断，不是「未证实」

`0030:83`：「**`locale` 命令被裁掉的系统**：`charmap` 为空 → 判为「不是 UTF-8」→ 去挑 → 也挑不到 → 不设。安全退化，只是不生效。」
这是对着片段逐句推出来的，不是一条待验的观测。列在「六、没证实的」里，读者会读成「还没测过，可能不是这样」。doc-guide:62 要求推断就地标注、与「未验证」分开（§六 的第 1、3 条才是真的未验证）。

## 【未能验证】

1. **§一「三条实测（两个容器）」本身**。要验的是 CentOS 7.9 与 Ubuntu 26.04 的 `locale -a` 与 `locale charmap` 实际输出。造不出来的原因：本会话 `NoNewPrivs: 1`，`sudo -n` 被内核挡（`sudo: The "no new privileges" flag is set…`）；rootless `podman images` 报 `newuidmap: write to uid_map failed: Operation not permitted`。所以 §一 第 1 条的两台机器差异，我只能读到 ADR 的转述，核不了。
2. **`-a` 的真实 PTY 下发**（`0030:75` 的「25 行」、决定 5「片段进 argv」的端到端）。本机能用 `script` 造 PTY 验 `ls` / `whiptail` 的分类行为，但造不出「sshd + 分配 PTY + 真下发行」这条链：本机无 2222/2223 监听、无 `sshpass`。
3. **122880 边界附近的真实行为**。能算、能在本地验闸门（`len(line) ≤ 122880`），验不了超限后 `execve` 与 sshd 的反应——与 J1 的「外壳开销」直接相关，需要一台真 sshd。
4. **AIX / HP-UX / SLES / 信创**（`0030:82`、`0024:445`）。无环境，与 0024 12.2 的既有结论一致，本轮同样造不出。
5. **「本机」到底是哪台**（J4）。ADR 引用的 `uutils 0.12.0` / `perl 5.42.3` 与本机 `0.10.0` / `5.40.1` 不符，我无法确认原测量环境，也就无法判断 §五 / 0024 3.7 那些「本机实测」是否还适用于当前代码。

**本轮我复核成功、可以当已验的**（写在这里免得被当成未验证）：片段 162 字节、english 开 184 字节（`printf '%s' … | wc -c`）；`sh -c '<片段> bash'` = 175；带出厂 `[env]`（PATH+TERM）的命令形态 = 263、english 开 = 285、sudo 形态 = 268；`TERM=dumb clear` 退出 1、`TERM=dumb tput cup 1 1` 退出 1；`LANGUAGE` 在 `C` 下被忽略（`LC_ALL=zh_CN.UTF-8 dpkg -l nosuchpkg` → 中文；`LC_ALL=C LANGUAGE=zh_CN.UTF-8` → 英文）。

## 锚质疑（单列）

### 锚质疑 1 —— 锚 8 的「整条 174 字节」在任何真实形态里都落不到
- 证据：`command.go:78` 的片段 162 字节成立；`sh -c ` 6 + `'` 1 + 162 + ` bash` 5 + `'` 1 = **175**。174 只有把「`sh -c`」后面的空格数漏掉（或数漏一个分隔符）才成立。带出厂 `[env]`（`config/SSHFleet.conf:46-47`）的完整下发行是 **263**（english 开 285、sudo 268）。
- 判据：锚是六轴判实现的基线，所以「整条」必须指一个真实下发串。175 是「外壳 + 片段 + 解释器」的最小串，263 是出厂配置下的真串；174 不对应任何一个。
- 影响：`0030:66` 与 `spec.md:67` 都抄了 174 并标「2026-10-28 实测」——这半句里「实测」是 ADR 自己的标注错误（任何实测都给不出 174），单独记在硬伤里会与这条重复，故一并归此。轴 3 已独立量到 175 / 263（`回执/轴3.md` J9）并声明「数字归轴 5」。

### 锚质疑 2 —— 锚 7 的「只动 `LC_CTYPE`」与锚 2 的「`export LC_MESSAGES=C`」在同一张表里并列，没有范围限定
- 证据：`command.go:85-89`，english=true 时片段后追加 `export LC_MESSAGES=C;`。
- 判据：按锚 7 字面判（只动 `LC_CTYPE`），english 开的形态必然违规；按锚 2 判则合规。两条锚同为最高优先级，没有「锚 7 仅约束编码片段」的限定。
- 影响：轴 2 的第 2 条要求逐条验锚 7 的三条不变式，照字面跑会把正确实现记成「碰了 `LC_MESSAGES`」。ADR 同一处措辞见 J3。

### 锚质疑 3 —— 锚 1 的四步形态越过了 ADR-0024 里作者的明示禁令
- 证据：`0024:10`（作者明示）、`0024:369`（第八节点名禁止「先探 `locale -a` 再决定传哪个值」）、`0024:471`（释放清单不含第八节）。
- 判据：锚 1 标注的授权是「编码不给用户配」作者明示 + 四步形态助手推导。四步形态里的「先查 `charmap`、再从 `locale -a` 里挑」正好是 0024 记的作者禁令所禁止的动作，而锚 1 把它当成了本轮基线。
- 影响：六轴按锚 1 判实现是对的，但没人被要求回答「这条锚有没有越过作者的禁令」。ADR 侧的同一处证据见 H1，此处不重复。

### 锚质疑 4 —— 锚 3 的「出厂只留 `PATH`」与锚 4 的「`TERM=dumb` 保留」不能同时成立
- 证据：三份 `config/SSHFleet*.conf:45-47` 都是 `PATH` + `TERM` 两行。
- 判据：按锚 3 判，出厂多一行 `TERM` 就是违规；按锚 4 判，锚 3 的措辞错。
- 影响：轴 4 第 1 条要逐字比对三份配置，如果拿锚 3 当判据，会把「保留 `TERM`」记成出厂配置缺陷。ADR 侧的同一句话见 H3。
