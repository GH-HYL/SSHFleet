## 【硬伤】

### H1 「说明」行只认 `[env]`，恒在片段进来之后这句话变成假的

`modules/SSHFleet_Go/internal/ssh/command.go:265`（`hasEnv := spec.EnvPrefix != ""`）、`command.go:285-290`（`envNote`）。

`envNote(false)` 的原话是「未配置环境变量，**直接**把 stdin 送来的命令…」。这句话在 `e317145` 之前成立：那时 `[env]` 空 → 下发行就是 `sh -c 'bash'`，解释器前面确实什么都没有。片段改成恒在之后，同一份配置下真下发的是：

```
$ go run ./probe        # [env] 留空，english=false
### 命令，无 env  english=false 下发
  line(175 字节): sh -c 'if [ "$(locale charmap 2>/dev/null)" != UTF-8 ]; then n=$(locale -a 2>/dev/null | grep -Eixm1 "c\.utf-?8|en_us\.utf-?8"); [ -n "$n" ] && export LC_CTYPE="$n"; fi; bash'
### 同一 spec 的 DescribeCommand：
  |  说明：   未配置环境变量，直接把 stdin 送来的命令交给登录用户的 bash 执行
```

解释器前面有 162 字节的 `if … fi;`，`export LC_CTYPE` 可能会执行，日志却说「未配置环境变量，直接」。这是 `e317145` 引入片段时漏改 `envNote` 造成的**新错误**（`git log -S"未配置环境变量"` 显示这一行最后一次改动是 `4690fc5`，本轮没碰），不是历史遗留。

同一句话在 `english=true` 时也有半句不对：`envNote(true)` 说「先导入**配置文件里的**环境变量」，而 `export LC_MESSAGES=C` 来自 `[locale]` 段、不是 `[env]` 里的变量；日志读者会去 `[env]` 里找一条并不存在的 `LC_MESSAGES`（`config/SSHFleet.conf` 的 `[env]` 只有 `PATH` / `TERM`）。命中的是 `command.go:271` 与 `command.go:278` 两处拼接。

### H2 `--no-shell` 在 `-u` / `-d` 两条分支没有守住：屏上说不带 sudo，实际带了

- 判定：`internal/cli/args.go:137-141`——`if !a.Sudo || a.NoShell { return IdentityLogin }`，即「`--no-shell` 一律算登录用户」。
- 提示：`internal/confirm/confirm.go:43-47` 只要 `NoShell && Sudo` 就打「本次将以【登录用户】身份执行，**命令里不会带 sudo**」；参数屏 `confirm.go:159` 进一步显示「登录用户（--no-shell 忽略 sudo）」。
- 日志：`internal/batch/batch.go:93-94` 打的是 `a.Identity().Label()`。
- 实际：`internal/batch/batch.go:203`、`batch.go:209` 给上传 / 下载任务填的是 `useSudo: a.Sudo`，`NoShell` 根本没参与；`internal/ssh/sftp.go:56-58` 与 `sftp.go:528`、`sftp.go:581`、`sftp.go:605` 据此下发 `sudo rm -rf …` / `sudo mkdir -p …` / `sudo mv …`。

探针复现判定分支（`go run ./probe2`）：

```
上传 --sudo --no-shell   Identity=登录用户 ScreenLabel="登录用户（--no-shell 忽略 sudo）"  batch 侧用 task.useSudo=a.Sudo=true（NoShell 没参与）
```

即：同一次运行里，屏上说「不带 sudo」、执行日志说「执行身份 登录用户」，而目标机上跑的确实是 `sudo mv`。命令 / 脚本两条路是守住的（`command.go:146-153` 与 `command.go:245-257` 各自在 `NoShell` 分支提前返回，且 `innerCommand` 根本拿不到 `AsRoot` 之外的开关），漏的正是这两条不拼 `sh -c` 的路——恰好是轴 3 第 3 条要查的「每一处分支」。

**归属说明**：`useSudo: a.Sudo` 的 blame 是 `f3e0b5c`（上传，2026-10-08）与 `36f75270`（下载，2026-09-14），不是本轮引入；`Identity()` 那条 2026-10-14 的修（`args.go:135` 注释）只统一了「日志 / 参数屏」，没蔓延到传输分支。我按第 3 条的覆盖要求照报，是否算本轮返工请复核员裁。

### H3 `-s --no-shell` 时参数屏说「解释器本次不生效」，实际生效

`internal/confirm/confirm.go:163-169`：命令 / 脚本模式且解释器非 bash 时占一行，`NoShell` 下把值改写成「原样下发，本次不生效」。但脚本模式的 `--no-shell` 分支是 `command.go:150-151` → `scriptInvocation(spec.Interpreter, spec.ScriptName)`，解释器**就是**这条下发的第一个词。探针（`./probe`）：

```
### no-shell 下发（脚本）
  line(29 字节): bash -c '. /dev/stdin' 't.sh'
```

配成 `python3` 时就是 `python3`（`scriptInvocation` 对非 shell 家族返回裸解释器，`command.go:473-478`）。命令模式那一半是对的（原样下发，解释器确实不参与），错的是脚本模式这一半。同理属「本轮之前就有」（该行 2026-10-08 加），列在此处是因为它是 `--no-shell` 分支里唯一一处可见面与实现说反话的地方。

## 【判断题】

### J1 第 6 条的答案：`CommandSpec` 的「单点」只在 Build/Describe 之间成立，跨 `-a` 没有统一

`e8c47a7` 把 `BuildCommand` / `DescribeCommand` 的入参收成一份 `CommandSpec`（`command.go:495-503`），`batch.go:281-295` 是唯一填充点——这部分做到了。但 `-a` 走的是另一个平行结构 `DownlinkSpec`（`interactive.go:56-64`），字段与 `CommandSpec` 前 7 项逐一同名，填充点是另一处 `cli/answer.go:207-220`。

代价可量化：本轮加 `english` 一个开关，实际改了 4 个点——`ssh.Options`（command.go）、`DownlinkSpec`（interactive.go:63）、`batch.commandSpec`（batch.go:292）、`cli.downlinkSpecOf`（answer.go:213）。`git show 41022a2 -- internal` 里 `batch.go` / `answer.go` / `interactive.go` 的 5 行改动就是这 4 个点。下次再加一个「所有下发行都要带」的开关，仍然要改 4 处，且漏一处不会编译报错（零值 = 关）。这不是本轮的错误，但第 6 条问「是否真做成单点」，答案是：**同一条路内是单点，两条路之间不是**。

### J2 `DescribeCommand` 自己重造了一份 `Options`，是日志侧的第二处填字段

`command.go:259`：`opt := Options{AsRoot: spec.AsRoot, English: spec.English}`。它不能直接传 `spec.Options`，因为 `NoShell` 在函数开头已经提前返回处理掉了。今天两者等价（`innerCommand` 只读 `AsRoot` / `English`），但这是**结构性的**：以后往 `Options` 里加第四个开关、并在 `innerCommand` 里用上，`BuildCommand` 会带上、`DescribeCommand` 不会——「日志的串 = 发的串」会静默破掉，且没有测试能自然发现（现有断言都在 `ssh` 包内自己传 `Options`）。风险不高、修起来也就一行，但它是第 6 条想找的那类「第二处」。

### J3 `"sh -c " + shellQuote(inner)` 这个形态串写了三遍

`command.go:158`、`command.go:160`、`command.go:264`、`interactive.go:103`。四处当前逐字一致（我用 `strings.Contains(desc, cmd)` 对 5 种形态各验过，全 true），但外壳形态是「本包的格式」（`command.go:241-242` 自己的注释就这么说），却由四个 return 各拼一次。属于可权衡：合并成一个 `wrapShell(inner)` 能消掉一处漂移点，代价是多一层几乎无内容的间接。

### J4 第 5 条的余量：闸门量的确实是同一条串，片段吃掉的是 162/8192

`cli/answer.go:190-192`：`line := ssh.InteractiveCommand(downlinkSpecOf(...))` → `a.Downlink = line` → `len(line) <= 122880`；`batch.go:240` 下发的是 `a.Downlink`，没有第二处重拼。所以「量的串 = 发的串」成立。

用 `cli.CheckArguments` 真跑合规检查二分出的通过边界（`./probe3`，出厂 `[env]` + 脚本模式 + 内联 `-a`）：

```
english=false 最大可通过正文 = 91929 字节；此时下发 122879；再 +1 → 「下发 122883，上限 122880」
english=true  最大可通过正文 = 91911 字节；此时下发 122877
```

即：开关把正文上限压掉 18 字节（下行串 +22 字节，按 base64 4/3 折算）；片段占 122880 预算的 0.13%，距离内核 `MAX_ARG_STRLEN` 还有 8192 字节。ADR 的「约 92KB」按十进制对得上（91929 B）。数字本身归轴 5 判，这里只提供对账。

### J5 上传 / 下载的辅助命令拿不到 english，而它们的 stderr 正是进分类的那部分

`sftp.go:528`、`sftp.go:534`、`sftp.go:581`、`sftp.go:605` 用 `runCommand` 直接执行 `sudo mkdir` / `sudo chmod` / `sudo mv` / `sudo rm`，不经 `envHead`，因此既没有 `[env]`、也没有 `LC_MESSAGES=C`。这些命令的错误原文被塞进 `result.Error`（如 `sftp.go:588` 的 `transferSudoFailed`），随后进 `verdict.Judge` 的英文关键词匹配。也就是说：**开关想解决的那个问题（中文提示语落「未归类」）在这三条路上依然存在，只是锚 2 只约束「下发行」，按锚不算违规**。要不要覆盖是设计取舍：覆盖就得给 `runCommand` 也套外壳，那会把 `--no-shell`「不附加任何东西」的语义再撕开一道口子。

### J6 改密模式完全没有下发行，english 开关覆盖不到

`batch.go:178-190` 的改密分支只构造 `PasswdInput`，不发任何命令行；「密码过期 / 新密码」这类提示语由目标机 PAM 用自己的语言输出，`LC_MESSAGES=C` 无处施加。按锚 2（只讲下发行）不算违规，但使用者会照「统一英文」去理解这个开关，实际只有命令 / 脚本 / `-a` 三种跑得到。是否要在手册里点明，归轴 4。

### J7 空白脚本：下发了串，日志却是空的

`cli/check.go:142` 只拦「0 字节」的文件，一个只含空白/Tab 的脚本能通过；`ssh.ScriptBodyOf`（`interactive.go:111-113`）把正文 trim 成空 → `BuildCommand` 的 `spec.ScriptBody == ""`，落到「命令模式」那条 return（`command.go:160`），下发 `sh -c '<env><片段> bash'` + 空 stdin；同一份 `CommandSpec` 给 `DescribeCommand` 时因为它既没有 `Command` 也没有 `ScriptBody`，走 `command.go:280` 返回空串，`batch.indentLines` 直接 `nil`。实测：

```
  下发(263 字节): "sh -c 'export PATH=… TERM=\"dumb\"; if [ … ]; then … fi; bash'"
  stdin: ""
  DescribeCommand: ""
```

这一次「发的串 ≠ 日志的串」是硬违反，但触发条件（只含空白的脚本）很偏，且是本轮之前就有的结构（`batch.go:270-274` 的 body 取自 stdin）。列在判断题里，不占硬伤。

### J8 开关状态在工具日志与参数屏上都看不见

`cli/args.go:250-286` 的 `Summary()`（写进工具日志的 `Namespace(...)`）只列 `c/s/u/d/f/p/sudo/t/T/n/r/no_shell/yes/k/answer/change_password`，没有 `[locale] english`；参数屏（`confirm.go:156-213`）也没有这一行。事后只能从执行日志那条下发行里有没有 `export LC_MESSAGES=C` 反推。之所以只是判断题：执行日志确实逐字给了整条下发行，「同源」没破；缺的是「一眼看出这次开了没」。

### J9 `174` 这个数在本轴的下发形态里对不上（数字归轴 5，此处只给对账）

`./probe` 实测：`LocaleFragment(false)` = 162 字节（与锚 8 一致）；`LocaleFragment(true)` = 184；`sh -c '<片段>'` = 170；`sh -c '<片段> bash'`（无 `[env]`）= 175；带出厂 `[env]` 的命令形态 = 263。锚 8 的「整条 174 字节」在我能造出的任何形态里都落不到，最接近的是 175（差 1，可能是数漏了收尾引号）。按提示词的分工，这组数字由轴 5 判，我不另立锚质疑。

## 【未能验证】

1. **五种形态的整串在目标机上被 sshd 二次解析后的样子**。本轴能证明「拼出来的串」逐字同源（探针已打全 5 种），但证明不了 `sshd` 用 `$SHELL -c "<整条>"` 交给 kernel 时那条串还是同一条——尤其 `-a` 那条内含 `"$(printf %s … | base64 -d)"`，是整包里唯一一处**双层**引号嵌套。造不出来的原因：本机无 sshd 监听 2222/2223、无 `sshpass`，且 `sudo -n` 被 `NoNewPrivs: 1` 挡死，`podman` rootless 也因 `newuidmap: write to uid_map failed` 起不来（公共段已实测，未重跑）。
2. **`-a` 超限后 `execve` 的真实反应**。本地只能验到 `len(line) <= 122880` 这条闸门（J4 的边界已实测）；122880 与 `MAX_ARG_STRLEN=131072` 之间那 8192 字节余量到底够不够（比如 sshd 自己还会不会往 argv 里加东西），需要一台真 sshd 才能测。
3. **`sudo mv` / `sudo mkdir` 的 stderr 在中文 locale 目标机上到底是不是中文、会不会真落「未归类」**（J5）。需要一台 `LANG=zh_CN.UTF-8` 的目标机；本机 `locale -a` 只有 `C` / `C.utf8` / `POSIX` / `zh_CN.utf8` / `zh_SG.utf8`，且没有能执行远端命令的通道。
4. **`-u --sudo --no-shell` 的实际 sudo 行为**（H2）。代码路径上能确证 `useSudo=a.Sudo`，但「真机上确实以 root 落盘」需要目标机与免密 sudo；本机 `sudo -n` 被 `NoNewPrivs` 挡死，不声称跑过。
