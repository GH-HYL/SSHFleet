# 轴 2 回执：片段语义（`ssh/command.go` 的 `encodingFragment` / `LocaleFragment` / `envHead`）

审计对象：`modules/SSHFleet_Go/internal/ssh/command.go:78`（片段字面量）、`:85-90`（`LocaleFragment`）、`:94-100`（`envHead`）。
沙盒：`build/audit_run_2026-10-28/轴2/`（`frag.txt` 由 `extract.py` 从源码原地取出，未抄文档；`out/` 下是各矩阵日志；`bin/` 下是 stub `locale` / `grep`）。
片段字节数由脚本自算：`printf '%s' "$F" | wc -c` → `162`（English 关）；加 ` export LC_MESSAGES=C;` → `184`。
shell 覆盖：`/bin/sh`（dash）、`/usr/bin/bash`、`/usr/bin/busybox ash`（BusyBox v1.37.0）；GNU grep 3.12。

## 【硬伤】

### 1. `grep` 的 stderr 没被抑制，命令缺席时把字漏进 Output（违反「永不告警」）

`command.go:78`：

```
if [ "$(locale charmap 2>/dev/null)" != UTF-8 ]; then n=$(locale -a 2>/dev/null | grep -Eixm1 "c\.utf-?8|en_us\.utf-?8"); [ -n "$n" ] && export LC_CTYPE="$n"; fi;
```

两处 `locale` 都带了 `2>/dev/null`，`grep` 这一环没有。沙盒里把 `grep` 从 `PATH` 拿掉（stub 目录只有 `locale`）：

```
$ env -i PATH="$PWD/bin/nogrep" /bin/sh -c "$F printf 'LC_CTYPE=[%s]' \"\${LC_CTYPE-unset}\""
LC_CTYPE=[unset]  rc=0
stderr> /bin/sh: 1: grep: not found

$ env -i PATH="$PWD/bin/nogrep" /usr/bin/bash -c "$F printf 'LC_CTYPE=[%s]' \"\${LC_CTYPE-unset}\""
LC_CTYPE=[unset]  rc=0
stderr> /usr/bin/bash: line 1: grep: command not found
```

同一沙盒里 `locale` 缺席（`PATH=bin/empty`，locale 与 grep 都没有）反而一声不吭——两处 `2>/dev/null` 生效。即「缺 `locale` 静默、缺 `grep` 出声」，行为不对称。

片段是恒在的（`LocaleFragment` 没有开关），所以这条漏字发生在**每一次** `locale -a` 结果需要过 `grep` 的执行上；工具把 stdout/stderr 合并采集，这行会进 `Output`、进日志、并参与失败分类。轴 2 覆盖 2 点名的「某条命令缺席」场景，实测就没守住。

### 2. 临时变量 `n` 会改写用户在 `[env]` 里导出的同名变量（越出「只动 `LC_CTYPE`」）

`command.go:78` 用 `n=$(…)` 直接赋值。`sh` 没有 `local`，且**变量若已被 `export` 过，赋值会连带改掉导出值**并传给后续解释器。实测（`e2b.sh` 先 `export n="用户自己配的值"` 再跑片段）：

```
候选为空：
$ env -i PATH="$PWD/bin/nocand:/usr/bin:/bin" /bin/sh e2b.sh
shell内 n=[]
n=
（子进程 env 里 n 被置空）

有候选：
$ env -i PATH=/usr/bin:/bin LC_ALL=C /bin/sh e2b.sh
shell内 n=[C.utf8]
n=C.utf8
```

未导出 `n` 时不留痕（实测 `env | grep '^n='` 无输出），所以触发条件是用户 `[env]` 里恰好有 `n` 这一条。锚 7 第一条是「只动 `LC_CTYPE`」，这里多动了一个用户变量，且置空这一支连值都不留。

## 【判断题】

**先立锚 7「永不降级」的判据（本回执自定，按它判）。**
判据 D：记 `c0 = locale charmap`（片段前）、`c1 = locale charmap`（片段后）。若 `c0 == UTF-8`，必须 `c1 == UTF-8`；若 `c0 != UTF-8`，`c1` 只允许等于 `c0` 或 `UTF-8`，不得落到第三种非 UTF-8 值。
按 D 跑六组（`m3_sem.sh` C 段）：

```
LANG=C.utf8                before=[UTF-8] after=[UTF-8]
LANG=zh_CN.utf8            before=[UTF-8] after=[UTF-8]
LC_ALL=C                   before=[ANSI_X3.4-1968] after=[ANSI_X3.4-1968]
LC_CTYPE=C LANG=zh_CN.utf8 before=[ANSI_X3.4-1968] after=[UTF-8]
LC_ALL=C.utf8              before=[UTF-8] after=[UTF-8]
空环境                      before=[ANSI_X3.4-1968] after=[UTF-8]
```

六组全过 D。**D 看不到的部分要说明**：把 `zh_CN.utf8` 换成 `C.utf8` 这类「同档替换」，charmap 都是 `UTF-8`，D 判不出差别；`[[:alpha:]]` / `tr` 的类别差异本轮造不出可观测样本（见【未能验证】3）。所以「不降级」目前只在 charmap 档位上成立，不是全语义成立。

1. **`LC_ALL` 一有值，编码段和英文开关一起静默失效。** `[env]` 里放 `LC_ALL="C"`：
   ```
   export LC_ALL="C"; → LC_CTYPE=[C.utf8] LC_ALL=[C] charmap=ANSI_X3.4-1968
   ```
   `export LC_CTYPE` 确实执行了（rc=0），但 `LC_ALL` 优先级更高，实际 charmap 没变。`LC_MESSAGES=C` 同理被吃：`LANGUAGE=zh_CN LANG=zh_CN.utf8 LC_ALL=zh_CN.utf8` 下加 `LC_MESSAGES=C` 后 `dpkg` 仍输出中文（对照：去掉 `LC_ALL` 后输出 `dpkg: error: need an action option` 英文）。锚 6 明确不设 `LC_ALL`，所以这是「用户/存量配置里留了 `LC_ALL`」的代价，实现本身按锚做；代价是**零告警地不生效**，看起来像成功。要判的是这个代价接不接受。
2. **片段对 `PATH` 是自指的。** `envHead` 先 export `[env]` 的 `PATH`、再跑片段，所以片段找 `locale`/`grep` 用的是刚设的那条 `PATH`。实测 `PATH=/usr/local/bin` 时 `locale` 静默缺席、`grep` 报错（见硬伤 1），`LC_CTYPE` 不设。出厂 `PATH` 含 `/usr/bin`，正常路径无碍；用户把 `PATH` 收窄就会顺带废掉编码段。
3. **片段在「挑不到候选」时退出码是 1。** 落单测：`charmap=UTF-8 → rc=0`、`非UTF8+有候选 → rc=0`、`非UTF8+候选空 → rc=1`、`grep 缺席 → rc=1`。当前外壳没有 `set -e`，下一个命令（解释器）照跑，整条 `sh -c` 的退出码仍由解释器决定（实测 `exit 7` → `rc=7`）。但若外层哪天带上 `set -e`，`locale` 缺席的场景下解释器根本不会启动：
   ```
   $ env -i PATH="$SB/bin/empty" /bin/sh -c "set -e; $F echo REACHED"   → 无输出，rc=1
   ```
   这条我只当风险记，本轮路径不构成故障。
4. **纯 busybox 目标上片段恒为空转。** BusyBox 1.37 没有 `locale` applet（`busybox locale` → `locale: applet not found`，rc=127），但**有 `grep` applet**。实测 `busybox ash` + 只有 stub `locale` 的 `PATH` 时，`grep` 被 applet 兜住、仍挑到了 `C.utf8`；`locale` 缺席时则整段空转。锚 1 ④ 明文允许「`locale` 不存在 → 一个变量都不设」，所以这是锚授权的行为；要判的是它意味着这套「编码由工具内建」在 Alpine/musl 一类目标上不产生任何效果。
5. **`grep -Eixm1` 的 `-m` 不是 POSIX 选项。** 本机 GNU 3.12 与 busybox 1.37 都认（实测 `-E`/`-i`/`-x`/`-m` 全部生效）。老 busybox 与非 GNU grep 上会退化，退化路径正好是硬伤 1 那条漏字。
6. **候选都在时取哪一个是 `locale -a` 的输序，不是固定偏好。** stub 实测：`C.utf8` 在前 → `LC_CTYPE=C.utf8`；`en_US.utf8` 在前 → `LC_CTYPE=en_US.utf8`。锚 1 没规定偏好，ADR 说两者等价，所以不算错；代价是同一批机器运行时的 `LC_CTYPE` 字面值可能不一致（下发行本身仍逐字一致）。
7. **`-i` 放行了大小写变体，回填值却取 `locale -a` 原样。** 实测 glibc 认 `C.utf8` / `C.UTF-8`，**不认**小写 `c.utf8`（`locale: Cannot set LC_CTYPE to default locale: No such file or directory`，随后回落 `ANSI_X3.4-1968`）。实际安全，因为回填值一定来自 `locale -a` 自己的输出；风险只在于「`locale -a` 若印出非规范大小写」，概率低，但一旦发生会同时踩「降级」和「告警」两条不变式。
8. **`[env]` 里显式配 `LC_CTYPE` 会被覆盖，配 `LC_ALL` 不会被覆盖。** 实测 `export LC_CTYPE="C"` → 被改成 `C.utf8`；`export LC_ALL="C"` → 原样保留、片段空转。同样是「用户显式配置」，待遇相反——这是锚 1/锚 6 的直接后果，只记录不判错。
9. **片段确实能拿到注释里说的收益。** `LANG=C` 下 `printf '中文' | cut -c1` 切出 `e4`（半个汉字）；片段之后切出 `e4 b8 ad`（整个汉字）；`LC_ALL=C` + 片段又回到 `e4`。`command.go:77` 的取舍描述与实测一致。

## 【未能验证】

1. **`LC_CTYPE` 能不能穿过 `sudo` 的 `env_reset` 到达 root 解释器。** 这是议题的核心，但本会话 `sudo -n` 被内核挡死（公共段已实测），本轮也禁止跑 `sudo`；`sudoers` 的 `env_keep` 里有没有 `LC_CTYPE` 也无从查。只能确认「变量设在 `sudo` 之前、只经一层」这个形态（`command.go:320` / `:463` 的 `envHead + sudo + 解释器`），穿不穿得过去未实测。背景②已把这方向标为「证伪、不要再走」，此处只登记未验证，不重开结论。
2. **两台的 `locale -a` 差异（CentOS 7 / Ubuntu 挑名）。** 本机 `locale -a` 只有 `C`、`C.utf8`、`POSIX`、`zh_CN.utf8`、`zh_SG.utf8`，**没有 `en_US.*`**，所以「`en_US.utf8` 回填后 glibc 认不认」只造出了「不装即拒绝」这一半证据；CentOS 7（glibc 2.17，无 `C.utf8`）与 Ubuntu（有 `C.utf8`）上候选集怎么落，造不出来。
3. **「同档替换」的可见差异（`C.utf8` vs `zh_CN.utf8` 的 `[[:alpha:]]` / `tr` 行为）。** 判据 D 只看 charmap，看不到这一层；本机 `zh_CN.utf8` 在、但没能造出「同一条命令在两个 UTF-8 名字下输出不同」的样本，所以「不降级」在类别语义上仍是未验区。
4. **精确的 fork 数。** `strace` 在（`/usr/bin/strace`），但 ptrace 被挡：`strace: do_test_ptrace_get_syscall_info: PTRACE_TRACEME: Operation not permitted`，`bpftrace` 同理用不了。能实测的只有**外部命令执行次数**：UTF-8 路径 1 次（`locale charmap`），非 UTF-8 路径 3 次（`locale charmap`、`locale -a`、`grep`，pid 各不相同）。`$( )` 与管道的 fork 数按 shell 语义推最短 2 个、最坏 5 个进程，**这一段是推的不是测的**。ADR 影响节那句「多 2–3 个进程（`locale charmap`、`locale -a`、`grep`）」与实测对不上（最短路径 1 次 exec、最坏 3 次 exec），但该句在 ADR 正文（`docs/adr/0030*:70`），判它归轴 5，这里只把实测数字交出去。
5. **真实 SSH 会话语境。** 本机无 2222/2223 监听、无 `sshpass`、不许联网，`sshd` 的 `AcceptEnv` 会不会把本机 `LANG`/`LC_*` 带过去、目标机默认 locale 是什么，全部造不出来；上面所有矩阵都是 `env -i` 手工构造的环境。
6. **老 busybox / 非 GNU grep 对 `-m` 的反应。** 只有 GNU 3.12 与 busybox 1.37 两个版本可用，拿不到会拒绝 `-m` 的旧实现，所以「退化时报什么、`n` 是不是空」只能由硬伤 1 的缺席路径类推，未直测。

## 锚质疑

**锚 8 的「整条 174 字节」在我能复现的形态下对不上。**

锚 8 原文：「片段 162 字节、整条 174 字节」，并在 ADR 里点明「含 `sh -c '` 与 ` bash'`」。实测（片段的 162 字节已自算核对；整条按 `sh -c '<片段> <解释器>'` 原样拼）：

```
片段 off=162 on=184
sh -c bash     off=175 on=197
sh -c sh       off=173 on=195
sh -c ash      off=174 on=196
sh -c ksh      off=174 on=196
sh -c zsh      off=174 on=196
sh -c python3  off=178 on=200
```

拆开是 `sh -c `(6) + `'`(1) + 片段(162) + 空格(1) + 解释器名 + `'`(1)。`174` 只在解释器名恰好 3 字节（`ash`/`ksh`/`zsh`）时成立；ADR 自己举的 `bash` 是 175。片段本身 162 是对的，错的是整条。

按什么判：片段字面量从 `command.go:78` 原地取出（不经文档），`shellQuote` 对该片段是恒等变换（片段里没有单引号，`has_single_quote=False`），所以「片段 + 一个空格 + 解释器名」就是实际下发的那段。除非「174」量的是另一个形态（例如 `-a` 那条、或英文开关关且解释器名三字节），锚与 ADR 都没写这个条件。

同一事实在 ADR 影响节里也出现（`docs/adr/0030*:66`），按去重规则只写在这里，不重复进【硬伤】。
