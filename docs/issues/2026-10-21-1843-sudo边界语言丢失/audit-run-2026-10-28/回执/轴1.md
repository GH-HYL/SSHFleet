**锚 7「永不降级」的可判形式（我定的）**：对任一起点 `S`，跑完片段后比较五个变量（`LANG` / `LC_ALL` / `LC_CTYPE` / `LC_MESSAGES` / `LC_COLLATE`）：
(a) `S` 是 UTF-8 → 五个变量逐字不变；
(b) `S` 非 UTF-8 且机器上有候选 → 只允许 `LC_CTYPE` 改成「`locale -a` 里确实出现过的 UTF-8 名」，其余四个不变，且不得把已能按字符算的 `LC_CTYPE` 换成按字节算的；
(c) `S` 非 UTF-8 且无候选 → 五个变量一个都不动。
「降级」= (b) 里的反向替换，或 (c) 里擅自动手。按此式判，三条都成立（实测见【判断题】J5）。

## 【硬伤】

### 1. `ExportPrefix` 的文档注释整段过时，讲的是本轮已被删掉的机制

`modules/SSHFleet_Go/internal/ssh/command.go:9-23`（本轮未改这段注释，但它描述的行为本轮被删）：

> 出厂配置给的是「统一 locale + 一组标准 PATH + 哑终端」几条……locale（LC_ALL / LANG）：……强制成同一个 UTF-8 才可比、可归类。

同一轮里的事实：

- `modules/SSHFleet_Go/config/SSHFleet.conf:45-48`（另两份同）只有 `PATH`、`TERM`，没有 `LC_ALL` / `LANG`（`grep -n -A8 '^\[env\]' config/*.conf`）；同一轮改的 `config.go:119-120` 写的是「出厂只给 PATH 与 TERM 两条」——与本注释的「统一 locale + PATH + 哑终端」三样对不上；
- 实现改成「只在目标机不是 UTF-8 且确有候选时设 `LC_CTYPE`，挑不到就一个都不设」（`command.go:58-78`），这正是注释里「强制成同一个 UTF-8」的反面。

同一文件里 `envHead`（`command.go:92-100`）的注释已按新形态改写过，只有这一处没跟上——是漏改，不是有意保留。

代价：这一段是 `export` 段的唯一设计说明，维护者照它读会得出两个错结论——「`[env]` 仍承担 locale 强制」「工具的目标是强制统一 UTF-8」。后者与锚 1 第④步（挑不到一个都不设）与锚 7（永不降级）直接相反。

### 2. 锚 7「永不告警」在 `grep` 缺席时被破坏

`command.go:78`：

```sh
if [ "$(locale charmap 2>/dev/null)" != UTF-8 ]; then n=$(locale -a 2>/dev/null | grep -Eixm1 "c\.utf-?8|en_us\.utf-?8"); [ -n "$n" ] && export LC_CTYPE="$n"; fi;
```

`locale` 两处都给了 `2>/dev/null`，`grep` 没有。沙盒实测（`build/audit_run_2026-10-28/轴1/bin/` 只放一个 stub `locale`，PATH 里没有 `grep`）：

```
$ env -i PATH="$PWD/bin" /bin/sh -c 'if [ "$(locale charmap 2>/dev/null)" != UTF-8 ]; then n=$(locale -a 2>/dev/null | grep -Eixm1 "c\.utf-?8|en_us\.utf-?8"); [ -n "$n" ] && export LC_CTYPE="$n"; fi;'
/bin/sh: 1: grep: not found
rc=1
```

对照：同一形态下 `locale` 缺席是静默的（PATH 里只放 `grep`，输出为空、无 stderr，`rc=1`）。所以不是「没法消」——是漏给了 `grep` 那一处重定向。

这与 `command.go:62-63` 自己写的「挑不到、`locale` 不存在、输出为空，一个变量都不设」和锚 7「永不告警」都不符：那行字会进工具合并采集的 `Output`、进日志、并可能参与失败分类。注释 `command.go:69` 还把「永不告警」的理由写成「候选只在确实存在的名字里挑，不设 `LC_ALL`」——只覆盖了「名字设错」这一种告警来源，没覆盖「命令不在 PATH」。

判据说明：这是我造的 stub 场景，真实的 CentOS/Ubuntu 出厂机都带 `grep`，现实发生率极低。我按锚 7 的可观测形式判（有告警输出即不成立），不按发生率判；发生率见【未能验证】。

### 3. `LocaleFragment` 注释里的理由「关键词是英文原话」与分类表不符

`command.go:83-84`（本轮新增）：

> 加一句 `export LC_MESSAGES=C`，目标机上所有程序的提示语统一说英文——失败分类的关键词是英文原话，语言一变就整批落「未归类」。

分类表里有两处中文关键词，且注释明写「中英两套都要留」：

```
$ grep -nE "^\s+'" config/keywords_error.conf | grep -P "[\x{4e00}-\x{9fa5}]"
169:    '您的帐户已过期',
474:    '此帐户目前不可用。',
```

`config/keywords_error.conf:163-165` 更直接：「RHEL 系 / openEuler 的 pam 包带中文译文，中文环境下是「您的帐户已过期；……」……所以中英两套都要留。」

所以「关键词是英文原话」这句是事实错误，它把「分类表只认英文」当成了前提。真正的分界是：远端 `pam`/`sshd` 的报文由**服务端** locale 决定，`export LC_MESSAGES` 改不到它（所以那两条必须留中文）；会被改到的只有目标机命令自己的输出（那部分关键词才是英文）。这不推翻锚 2 的决定，但这段注释给出的理由不成立——按它读，会以为中文关键词是多余的。

**J5. 锚 1/2/6/7 的实现侧符合度：按我给的判据全部成立。**

## 【未能验证】

1. **`LC_CTYPE` 过 sudo 后是否真对 `sudo bash` 生效。** 要验的是 `sh -c 'export LC_CTYPE=C.utf8; sudo sh -c "echo \$LC_CTYPE"'` 在 CentOS 7.9 / Ubuntu 26.04 上的实际取值（sudoers 的 `env_keep` 是否保留 `LC_*`）。造不出来：本会话 `sudo -n` 被内核挡死（`NoNewPrivs: 1`），rootless `podman` 报 `newuidmap: write to uid_map failed`，本机无 2222/2223 监听、无 `sshpass`。提示词已把「`export` 过不了 sudo 边界」列为被证伪方向，我未复验，也没有据此判锚 7。
2. **真实目标机上 `locale -a` 的输出形态没验到。** 要验：CentOS 7.9（glibc 2.17）与 Ubuntu 26.04（glibc 2.4x）上 `C.utf8` / `en_US.utf8` 到底列不列、大小写与连字符形态、有无尾随空格。造不出来：本机 `locale -a` 只有 `C`、`C.utf8`、`POSIX`、`zh_CN.utf8`、`zh_SG.utf8`，没有真实 CentOS 的那套；stub 能造「带尾随空格」这类输入，但造出来的不是真实实现，判不了真机行为（挑名逻辑本身归轴 2 第 4 项）。
3. **`grep` 缺席在真实目标机上的发生率。** 已在沙盒造出行为（见【硬伤】2），但造不出「哪一类目标机真的没有 `grep`」这个事实——本机路径固定、无容器。所以【硬伤】2 只判「锚 7 的形态被破坏」，不判「现场会踩到」。
4. **`go 1.26.0` 下的 `go test ./...`。** 只跑了 `go build ./...`（rc=0）。跑测试属轴 6，我没跑，所以「降指令后测试仍全绿」这件事我这边是空着的。

## 锚质疑（单列，不并入上面三节）

**锚质疑 1：锚 3 与锚 4 互斥，实现只能满足其中一条。**
- 锚 3：「`[env]` 收缩：出厂**只留 `PATH`**；`LANG` / `LC_ALL` 删除」；锚 4：「`TERM=dumb` 保留」。
- 证据：三份出厂配置都留了 `PATH` + `TERM`（`config/SSHFleet.conf:45-48` 等三份逐字一致）；`config.go:120` 的注释也写「出厂只给 PATH 与 TERM 两条」；提交 `41022a2` 标题直接写「出厂 `[env]` 收缩为两行」。
- 按什么判：两条锚都自称来源是作者明示，字面上不能同时满足。实现取「留 TERM」，与锚 4 一致、与锚 3 字面不一致。我不改写锚，只报冲突：请开发者裁一次「只留 PATH」是不是「只留 PATH 与 TERM」。

**锚质疑 2：锚 8 的「整条 174 字节」与实测差 1，且缺解释器前提。**
- 锚 8：「片段 162 字节、整条 174 字节」。
- 证据（片段取自 `command.go:78`，`printf '%s' … | wc -c` 等价物）：片段 162 B ✓；`sh -c '<片段> bash'` = 7 + 162 + 1 + 4 + 1 = **175 B**；换成 `sh` 解释器 = 173 B；带 `[env]` 段（出厂 PATH 那行）= 251 B；`english` 开 = 197 B。
- 按什么判：`sh -c '` 7 B + 片段 162 B + ` bash'` 6 B = 175 B，与 174 差 1 字节；换个解释器名这个数就变（`sh` → 173）。「整条」随解释器名与 `[env]` 长短变，锚没写前提，不可执行。ADR-0030 第 66 行是同一个数字（含「` bash'`」的说明），按去重规则只记在这里，不另写进【判断题】。
