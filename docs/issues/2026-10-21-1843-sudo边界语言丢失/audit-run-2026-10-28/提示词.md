> **只报问题，不给修法，不排优先级。**
>
> **授权**：只做只读分析，不得修改仓库任何文件。允许在 `build/audit_run_2026-10-28/<你的轴名>/` 下建沙盒、写临时脚本、跑命令、造 stub——**stub 只准落在沙盒里**（例如在沙盒 `bin/` 放假的 `locale` / `grep`，或用 `env -i` 造干净环境），不许改仓库、不许往系统路径写东西。本轮**未**获「授权开工」。
>
> **范围（两个，别混）**：
> - **实现面**：`git diff dbcb797 e8c47a7`（26 文件 +445/−165）。`dbcb797` 是拆工单那次提交，之前无实现改动。
> - **文档面**：`git diff d91d2ec e8c47a7 -- docs/ README.md CHANGELOG.md`。ADR-0030 的 88 行主体写在 `f7e6ab8`、`9848280`，ADR-0024 的状态行与更新记录、ADR-0015 的更新记录同样出自这两次提交——**它们都不在 `dbcb797..` 这个范围里**，只给实现范围会把 ADR 主体关在门外。
>
> **环境（已实测，不必再摸一遍，也不要推翻）**：
> - `sudo -n` 在本会话被内核挡死：`sudo: The "no new privileges" flag is set, which prevents sudo from running as root.`；`/proc/self/status` 里 `NoNewPrivs: 1`，关沙盒重试同样失败。
> - 因此 `Podman测试环境.md` 的变通（`sudo -n podman --root … --runroot …`）**本轮跑不了**——它第一步就是 `sudo -n`。rootless 亦断：`podman images` 报 `newuidmap: write to uid_map failed: Operation not permitted`。本机无 2222/2223 监听、无 `sshpass`。
> - **不许声称跑过容器或真机。** 造不出来的场景（CentOS/Ubuntu 两台挑名差异、`LC_CTYPE` 过 sudo、目标机缺某条命令）**写进回执第三节「未能验证」**，写清「造不出来」的具体原因，不要跳过。
> - 可用：Go 1.26.8；`/bin/sh` → dash；`/usr/bin/bash`；`busybox`（含 ash / grep / cut）；GNU grep 3.12；本机 `locale -a` = `C`、`C.utf8`、`POSIX`、`zh_CN.utf8`、`zh_SG.utf8`；本机 `charmap` = `UTF-8`（造「非 UTF-8」得用 `env -i`）。
> - 禁：`sudo`、`podman`、改仓库文件、`git` 写操作、联网。
>
> **回执三节，缺一节不算交付**：
> 1. **【硬伤】** 事实错误、边界被破坏——每条给 `file:line` + 证据（命令原文与输出，或引文）。
> 2. **【判断题】** 可权衡的——写清理由与代价。
> 3. **【未能验证】** 你有意要验、但本轮环境造不出来的，写清要验什么、为什么造不出来。
> 三节都可以是「无」。**不要为了凑条目把未能验证的事写进前两节**；也不要把「没发现问题」写成一句话交差——三节都要出现。

### 锚（以此为准）

**锚质疑（单列，不许并进普通发现）**：发现某条锚与源码、实测或上游 ADR 对不上，**不许改写锚**——另起一节，写清哪条锚、哪份证据、按什么判。**同一事实若既构成锚质疑又是 ADR 缺陷，只写进锚质疑**，【判断题】里留一句「见锚质疑 N」，不复述两遍。

### 背景（被证伪的方向与踩过的坑）

被证伪、**不要再走**：①「`-a` 没把 `[env]` 带下去」；②「`export` 过不了 sudo 边界」（源自「sudo 套 sudo」的错误实验形态）；③「换成 `C.UTF-8` 就解决」；④「任何静态取值能覆盖两类机器」；⑤「正文落 `/dev/shm`」；⑥「设对 locale 就整批统一语言」。

只传方法：判断「变量能否穿过 sudo」时，变量设置须在 sudo **之前**且只经一层；「提示语语言」与「字符按字节/按字符」是两个正交轴，分开判。

## 轴 2：片段语义（`ssh/command.go` 的片段 + 本地 shell 实测）

轴的切法来自代码结构：这一段是整个下发行里**唯一一处跑在目标机 shell 上的逻辑**，其余都是拼字符串。

覆盖：

1. `encodingFragment` 与 `LocaleFragment` 的逐字行为：在 `dash`（`/bin/sh`）、`bash`、`busybox ash` 下各跑一遍；分别造「charmap 是 UTF-8」「不是 UTF-8 且有候选」「不是 UTF-8 且无候选」三态。
2. 锚 7 三条不变式逐条验：`LANG` / `LC_ALL` / `LC_MESSAGES` / `LC_COLLATE` 有没有被碰；会不会降级；**有没有往 stdout / stderr 漏字**（工具把两者合并采集，漏出去的字会进 `Output`、进日志、参与失败分类）——漏字要在「候选不在」「某条命令缺席」等场景下逐个看。
3. 副作用面：片段里用到的变量名在 `sh -c` 这一层留下的痕迹；片段的退出码与后面解释器的关系；`set -e` / `set -u` 有没有影响（外层是我们自己的 `sh -c`，用户脚本可能自带 `set -e`）。
4. 挑名逻辑：`grep -Eixm1 "c\.utf-?8|en_us\.utf-?8"` 对各类 `locale -a` 输出（`C.utf8`、`C.UTF-8`、`en_US.utf8`、`EN_US.UTF-8`、带尾随空格、两个都在）的取舍；挑到的名字回填 `LC_CTYPE` 能不能被 glibc 认。
5. 字节与进程：实测片段字节数、`sh -c '<片段> <解释器>'` 整条字节数（锚 8 的数字对不对、条件写没写清）；每次执行多起几个进程（ADR 影响节写「2–3 个」）。
6. 片段在 `envHead` 内部的顺序（与 `[env]` export 段的先后），以及这个顺序对「判断的是最终生效的 locale」这件事成不成立。

**文件域**：`modules/SSHFleet_Go/internal/ssh/command.go` 的片段与 `envHead`、`LocaleFragment` 相关部分。`command_test.go` 里的断言可以读，但**测试质量归轴 6**，你只在「断言与实测不符」时记一条。**不碰** `cli/`、`batch/`、`config/`、手册、ADR。

## 轴 3：拼装链路与覆盖面（跨模块不变量）

轴的问题：这个包的全部约束是「**量的串 = 发的串 = 日志的串**」，而本轮给下发行加了一段恒在的片段、一个开关。覆盖：

1. 开关与片段的值从配置到下发**逐跳**走一遍：`config.Locale.English` → `cli.Args.English` → 各拼装入口 → `CommandSpec` / `DownlinkSpec` → `BuildCommand` / `InteractiveCommand` / `DescribeCommand`。逐跳列出，看有没有跳漏、有没有哪条路拿不到这个开关。
2. **五种形态**（命令 / 脚本 / sudo+命令 / sudo+脚本 / 代填 `-a`）逐一对照；另看**上传 / 下载 / 批量改密**这三条不拼 `sh -c` 的路：受影响没有、按锚该不该受影响。
3. `--no-shell`：锚 8 说它不生效，代码里每一处分支（含日志侧）是否都守住。
4. **日志与下发同源**：`DescribeCommand` 打印的「命令行」与真下发那条是不是同一个值；「说明」几行（`envNote` / `commandWho` / `scriptWho`）与命令行做的是不是同一件事。
5. `-a` 的下发行在解析/合规阶段拼好存进 `Args.Downlink`，那条串现在多了 162–184 字节：长度检查量的还是同一条串吗，上限余量多少。
6. `CommandSpec` / `Options` 两次重构（`a3dee5e`、`e8c47a7`）是否真把「执行与日志共用一份」做成单点，还是留了第二处填字段的地方。
7. `envHead` 与 `sudo` / 解释器之间的拼装顺序（片段在 `envHead` 内部的顺序归轴 2）。

**文件域**：`internal/cli/*`、`internal/batch/batch.go`、`internal/ssh/interactive.go`、`command.go` 的 `BuildCommand` / `DescribeCommand` / `innerCommand` / `scriptStdinInner`、`internal/output/*` 里引用「命令行」的文案。**不碰** 片段内容（轴 2）、`config/*.conf` 内容（轴 4）、ADR（轴 5）、测试质量（轴 6）。
