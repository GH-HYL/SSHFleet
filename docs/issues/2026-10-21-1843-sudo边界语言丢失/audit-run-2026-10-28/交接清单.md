## 四、必须知道的背景

**被证伪的方向（不要再走）**

1. 「`-a` 没把 `[env]` 带下去」——否。三种下发行的 `export` 段逐字相同（`findings-2026-10-21.md` 第三节）。
2. 「`export` 过不了 sudo 边界」——否。那组实验是「`sudo` 套 `sudo`」、变量在**外层 sudo 之后**才设；改用真实形态重测后 `LANG`/`LC_ALL`/`TERM` 都能穿过（ADR-0024 2.2、3.1）。
3. 「换成 `C.UTF-8` 就能解决」——否。CentOS 7.9 没有这个名字（ADR-0024 3.4）。
4. 「任何静态取值（`C` / `C.UTF-8` / `en_US.UTF-8`）能覆盖两类机器」——否。Ubuntu 26.04 与 CentOS 7.9 的 `locale -a` 没有交集（ADR-0030 第一节）。
5. 「正文落 `/dev/shm` 再执行」——否（ADR-0029）。
6. 「设对 locale 就会整批统一语言」——否。翻译包按程序缺失（ADR-0024 3.3）。

**踩过的坑（只传方法，不传结论）**

- 判断「某变量能否穿过 `sudo`」时，变量的设置必须发生在 `sudo` **之前**，且只经过**一层** `sudo`；否则测的是另一件事。
- 判断「提示语说哪种语言」与「字符按字节还是按字符算」必须分开，两个轴正交。

## 六、环境与授权

**本会话实测（2026-10-28，主 Agent 亲自核过）**

- `sudo -n true` → `sudo: The "no new privileges" flag is set, which prevents sudo from running as root.`；`/proc/self/status` 里 `NoNewPrivs: 1`。**沙盒外重试同样失败**。
- 因此 `Podman测试环境.md` 那套变通（rootful 引擎读用户库）**本轮用不了**：它自己第一步就是 `sudo -n podman`。
- `podman images`（rootless）报 `newuidmap: write to uid_map failed: Operation not permitted`。
- 本机没有 2222 / 2223 监听，没有 `sshpass`，两台测试容器不存在。

**可用的事实**

- Go 1.26.8；`/bin/sh` → dash；`/usr/bin/bash`；`busybox`（含 ash/grep/cut）；GNU grep 3.12。
