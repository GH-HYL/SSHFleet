# 失败原因统一为报文，分类名一律由配置匹配决定 · 规格

Status: ready-for-agent

> 实施入口见同目录 `README.md`（从哪开始、什么顺序、坑在哪）。
> 决策依据：`docs/adr/0021-message-based-classification.md`（报文格式、中文只留配置一处、不考虑兼容、执行侧与判定层的界）。本文只写「做成什么样」，不重复 ADR 的取舍理由。

## Problem Statement

跑完一批机器，统计块把失败分成两类：`>>>` 后面是认得出来的分类，缩进的是认不出来的——后者直接显示报错原文。判定「认不认得」依靠两套并行的来源：远端与系统说的话交给配置文件匹配；工具自己编的话（`建立连接失败 - …` 这类中文前缀、以及「部分成功」「任务已取消」这类写死的中文分类名）**由代码直接给**，不走配置。

于是使用者面对的情况是：

1. **有些分类改不动、删不掉。** 改密卡住时的「没等到提示」、传输时的「部分成功」，名字写在程序里。配置文件里那份同名条目只管提示语，改名或删除都不生效——文件头写着「整组删掉即可（该分类从结果里消失）」，对这几个名字不成立。
2. **同一个坑要踩两次。** 程序里新增一种失败形态，要记得在配置里补名字、还要记得在代码白名单里补名字；漏一处，那个分类就在屏幕上落到「未归类」里。2026-10-18 漏补过一次，四个分类被当成兜底原文显示了几天。
3. **配置文件里有些关键词匹配的是工具自己编的中文**（`打开本地文件失败` 一族、`创建会话失败` 一族、`握手超时`、`命令执行超时`）。用户不会想到这些是程序里的字面量，改程序措辞就会让这些分类静默失效。
4. **错误行里中文前缀和英文原始错误混在一起**（`建立连接失败 - dial tcp …: connection refused`），既不像系统消息，也不像工具消息。
5. **有些分类的判据是「文本」，有些是「结构字段」，两套规矩。** 「连不上」查文本，「部分成功」看文件计数——使用者要学两套。

## Solution

所有失败原因（不论是远端说的、系统说的、工具自己编的、还是工具从结构事实上看到的）统一成一种固定格式的英文报文（`sshfleet.<环境>.<环节>: <英文描述>`），与远端、系统说的话放在同一条通道里交给判据文件匹配；**分类名从此只有一个来源：配置文件匹配到什么就是什么**。

报文原文就是使用者看到的文本：终端明细、`output.txt`、`report.txt`、`results.xlsx` 与执行日志一律原样呈现，**不存在译文层**；给人看的中文只有配置里的分类名与提示语。

**分层规矩（ADR-0021 决定第 8 条）**：每一层只许做无损翻译——执行侧把库已有的分类翻成报文、把看见的结构事实说成一句话，**不替使用者下结论**；判定层只查表，**不自己定义分类名**。

## User Stories

1. 作为运维人员，我希望配置文件里登记了名字的分类就是统计块里显示的分类，没有第二个地方能推翻它，这样我照着文件头说的「删掉整组即可停用」去操作时，它对每一类都成立。
2. 作为运维人员，我希望把「没等到提示」改成「远端不吭声」，屏幕上就显示新名字，这样措辞能按我们团队的叫法来。
3. 作为运维人员，我希望删掉「部分成功」这一条之后，这一类结果回落成显示报文原文，这样我能确认它确实被停用了。
4. 作为运维人员，我希望工具自己报的失败原因（建连失败、申请终端失败、远端路径不存在）与远端说的话用**同一种方式**归类，这样我写关键词时不用先分辨这条是工具说的还是机器说的。
5. 作为运维人员，我希望在配置文件里看到 `sshfleet.` 开头的关键词就知道那是工具自己报的，这样不会把它和远端报文混淆。
6. 作为运维人员，我希望能在判据文件里写 `sshfleet.transfer.` 这样的前缀词，一次认领一整摊工具报文，这样不用逐条列。
7. 作为运维人员，我希望终端、输出文件、xlsx 里看到的是同一份报文原文，不再「屏幕一种说法、归档另一种」，这样我截屏和翻归档时说的是同一件事。
8. 作为运维人员，我希望 `results.xlsx` 与执行日志里保留英文报文原文，这样出问题时能把原文贴出去、或者拿去比对。
9. 作为运维人员，我希望工具自己不认识的失败原因照旧直接显示原文，这样我不会因为配置没写全而看不到真实报错。
10. 作为运维人员，我希望报错原文里 Go 与系统给出的那部分（`dial tcp …: connection refused`）原样保留，这样信息不丢。
11. 作为运维人员，我希望改密仍然认得「密码过期」这个入场信号，而且这个判据就写在我能改的配置文件里，这样调整提示措辞不必改程序。
12. 作为运维人员，我希望代填的中止词跟入场信号用同一批关键词，两处不会各说各话。
13. 作为运维人员，我希望提示语（tip）仍然跟着分类名一起在配置文件里维护，行为不变。
14. 作为维护者，我希望新增一种「程序能自己判断出来的失败」时，只需要写一条报文并让它出现在配置里，不需要另外维护一份名单，这样就不会再出现「漏补名单导致上屏成未归类」。
15. 作为维护者，我希望报文格式在代码里写明并只在一处定义，这样以后新增报文不用重新发明写法。
16. 作为维护者，我希望报文与中文各有主人：报文在代码与配置里，中文只在配置的 `name` / `tip` 里，这样改措辞不必动程序逻辑。
17. 作为维护者，我希望判定层对「这条结果失败了」只产出一个分类名，且它一定来自查表或原文，这样代码里不存在第二条给分类名的路径。
18. 作为审查者，我希望分类语料测试仍然覆盖全部既有分类，这样这次改动不会悄悄改变任何一类失败归属。
19. 作为维护者，我希望所有模式在归档报告里都能看到并发数，因为它描述的是这次执行本身，与选的是哪种模式无关。
20. 作为维护者，我希望执行侧只陈述「哪一步、什么现象」，不陈述「这算什么分类」，这样判定层不会因为执行侧擅自定性而出现两份结论。

## Implementation Decisions

### 报文

- **格式**：`sshfleet.<环境>.<环节>: <英文描述>`，定案见 ADR-0021「决定」第 1、2 条。环境取值固定七种：`connect` / `session` / `run` / `transfer` / `passwd` / `answer` / `abort`。
- **格式只在一处声明**：放在最底层的公共包 `internal/common`，与环境取值清单一起写在代码注释里；判定包、`ssh`、`batch` 都引用它，不各自手拼前缀。
- **原始错误原样跟在后面**：`sshfleet.connect.refused: dial tcp …: connection refused`。原始错误字段不修改，只加前缀。
- **报文不入库**：不在结果结构里新增「报文」字段。报文就写在报错原文那一格里；判定层无状态地从原文里取前缀匹配。
- **一格里可以有多条文本**：报错原文只有一格。报文与已有原文之间、报文与报文之间，一律**按行追加**，谁都不覆盖谁：传输部分成功时那一格已经放着最后一条逐文件失败原因；建连被中断时那一格已经放着 `dial tcp …` 原文。顺序固定为**原文在前、报文在后**（原文是权威原文，报文是对这次收尾的陈述）。判定层对整格做包含匹配，命中哪一条由判据文件里的条目顺序决定。**MUST 追加、不许覆盖**——盖掉就是吞信息，与 ADR-0021 第 6 条相抵。
- **环节名只陈述事实，不下结论**：用 `finished`（传完了）、`canceled`（被取消）这类陈述现象的写法，**不用 `partial` / `failed`**。「部分成功」这个词只存在于配置的 `name`。

### 判定

- **「形态」指的是什么**：一次执行收尾时那组布尔与计数所描述的情形——成了几个、有没有超时、有没有被中断、代填喂进去过没有。它描述「这次是怎么结束的」，**不是分类名**，也不是给人看的句子。
- **所有失败原因都走报文**，包括两类：
  1. **工具自编的错误文本**：建连失败、申请终端失败、文件不可读等，直接换成报文；
  2. **结构事实**：由看见该事实的一处在收尾时生成一条陈述事实的报文（`sshfleet.transfer.finished: 6 of 10 files transferred`、`sshfleet.passwd.not_expired: no password-expiry prompt seen`、`sshfleet.abort.canceled: interrupted after session established` 等）。
- **结构事实的报文由执行侧发，发报点按摊各一处**：`sftp.go` 的传输收尾（`finished`，上传 / 下载 / 取消早退三条路径共用同一个收尾函数）、`interactive.go` 的代填收尾（`answer.missed` / `answer.exhausted_timeout`）与中断（`abort.canceled`）、`passwdsession.go` 的改密收尾（`passwd` 五条）、`exec.go` 的建连收尾（`abort.connect_canceled`，追加在 `dial tcp …` 原文之后）、`endFactsOf` 一族（`run.timeout` / `abort.canceled`）。判定层不认识这些字段组合。
- **「形态 → 报文」抽成导出的纯函数**：每摊一个，入参只是该形态要用的几个布尔与计数（不是整个 `Result`），产出一行报文文本；由调用点写进报错原文。导出是为了满足「不测私有函数」这条约定——它同时就是这个映射的测试接缝。
- **改密形态里，远端说过话就不补报文**：`提示词没认出` 与 `改密未完成` 今天靠「报错原文为空」区分「远端一句话没说」与「远端给了原因」。改造后如果远端已经说了原因，就不再补 `passwd.*` 报文，让判据表按远端原话认——与今天的让位口径一致。
- **报文只在「不该算干净成功」的形态下写**：干净收场（各模式的成功规则全部成立）一个字都不写。这条不变量让下面那条成功规则得以成立。
- **判定层不存在中文分类常量**：`Judge` 不给任何分类名，只把文本交给判据表。原先由常量承担的 11 个分类名，10 个改由报文经判据表认领（哪 10 个、各叫什么，见《预算：全部报文清单》）；「密码过期」按 ADR-0021 决定第 9 条处理——它的分类来自远端原文查表，入场信号与中止词保留按名查表（`keywords.go` 里的字面量）。
- **判定层只有一个分类来源**：`Judge` 读到的文本（报文 + 远端报文 + 服务端提示 + 输出）交给判据表，命中即该分类，未命中即原文。**判定层没有任何「按结构字段直接给分类名」的分支。**
- **成功规则只多一条，且只加在命令 / 脚本 / 代填上**：这三条今天只看退出码 0、未超时、未中断，**另加一条——报错原文里出现报文（以 `sshfleet.` 开头）即不算成功**。必须加，否则「代填没送完但命令退出 0」会被判成成功：今天它靠一级分支抢在成功规则之前。传输的成功规则本来就要求失败数为 0（那时不会有 `finished` 报文），改密的 `cleanStop` 本来就要求原文为空（报文一写进去它自然不成立），两处都不必改。
- **「报错原文是不是空的」不再是挑分类名的依据**：`verdict.go` 里 `提示词没认出` / `改密未完成` 那两条分支整体消失，改由执行侧在收尾时写好 `passwd.no_prompt` / `passwd.give_up` 让判据表认领。**`cleanStop` 里保留 `Error == ""`**——它现在读作「没有事实要陈述」，与上面那条不变量等价，不是第二条给名字的路径。
- **兜底判定函数与豁免名单删除**：一个分类名是否「已知」，只由判据表决定。
- **「密码过期」按远端原文归类**（ADR-0021 决定第 9 条）：它没有报文——从连接、认证到执行，整条链路上只有远端的输出（改密向导那几行），工具只是把它读了回来。三种走法指向同一批关键词：
  - **命令 / 脚本**：连接与认证全成功，会话以非 0 收场（那个码来自 PAM 改密对话，**不区分它属于谁**），于是走第二组，按输出原文查表；
  - **代填**：输出里出现中止词 → 中止会话、提前结束；`AbortLine` 只作为「会话为何提前结束」的事实保留，**其原文并入待匹配文本**，分类由第一组查表给出，不再由代码写死名字；
  - **改密**：那批提示是入场信号，取 `Keywords.PasswordExpired()`（按分类名「密码过期」去判据表里取关键词）。换 `keywords` 两个用途一起跟着变；改 `name` 会让查表落空，得同步改代码里的字面量——这条限制本次不改。
- **不为密码过期加探测命令**：密码过期时连 `:` 都会被 PAM 切成改密对话并以非 0 结束，探测拿到的信息与之后真执行命令时完全相同，而在正常节点上纯属多一次往返。改密模式的那条 `:` 是它本来就需要的步骤，不是探测。

### 预算：全部报文清单

下文清单是「出厂报文有哪些」的唯一来源，也是判据文件里那些条目该挂什么词的依据。**工单 01 负责逐条核实并补全**，本表给的是框架与已确认的条目。

| 环境 | 环节 | 报文示例 | 由谁发 |
| --- | --- | --- | --- |
| `connect` | `refused` / `timeout` / `handshake_timeout` / `auth_failed` / `key_parse_failed` / `key_passphrase_missing` / `no_route` / `dns_failed` | `sshfleet.connect.refused: dial tcp …: connection refused` | `client.go` |
| `session` | `create_failed` / `pty_failed` / `channel_failed` / `exit_missing` | `sshfleet.session.create_failed: ssh: session rejected` | `exec.go` / `interactive.go` / `passwdsession.go` |
| `run` | `timeout` / `rejected` | `sshfleet.run.timeout: exceeded 30s` | `exec.go` / `interactive.go` / `passwdsession.go` |
| `transfer` | `client_failed` / `remote_missing` / `remote_not_dir` / `remote_unreachable` / `list_failed` / `no_files` / `local_unreadable` / `finished` | `sshfleet.transfer.finished: 6 of 10 files transferred` | `sftp.go` |
| `passwd` | `not_expired` / `no_signal` / `no_reply` / `no_prompt` / `give_up` | `sshfleet.passwd.no_signal: no password prompt seen before timeout` | `passwdsession.go` |
| `answer` | `missed` / `exhausted_timeout` | `sshfleet.answer.missed: 2 answers not delivered` | `interactive.go` |
| `abort` | `canceled` / `connect_canceled` | `sshfleet.abort.canceled: interrupted after session established` | `exec.go` / `sftp.go` / `passwdsession.go` / `interactive.go` |

**`transfer.finished` 的两个口径**：描述统一用 `files transferred`（上传下载同一句，不按方向分两种说法）；**总数取枚举后要传的文件数**（结果里记的就是它），不是「成功数 + 失败数」——逐文件失败会中断该节点剩余传输，失败数最多 1，后面那些是「没轮到」，仍应算在这批总数里。

**表里是框架，不是终稿**：01 逐条核实时会补上缺的环节——例如下载侧的「创建本地目录失败」现在不在表里，而 `sftp.go` 确实会产这句。

### 配置

- **判据文件**：两份配置里那 10 条结构性分类改为挂报文当关键词；「密码过期」那条不动它的远端关键词（它本来就不是报文），但要核实关键词语料里同时覆盖**改密向导的原话**（`Password change required but no TTY available`、`You must change your password now…`、`Current password:` 一类），因为代填中止后走的是第一组、只看这批词。
- **23 条中文关键词要撤掉**：它们都以工具自己编的中文当匹配串——`SFTP失败` 8 条、`本地文件错误` 4 条（`打开本地文件失败` / `创建本地文件失败` / `写入本地文件失败` / `文件不可读`）、`无法建立会话` 3 条（`创建会话失败` / `创建输入通道失败` / `申请终端失败`）、`远端没有文件` 2 条，`握手超时`、`执行超时`、`远程路径不存在`、`远程文件已存在`、`sudo失败`、`密钥解析失败` 各 1 条。改成报文关键词后，这些中文串既不该留着当兜底（改一个字就静默失效，正是要消灭的形态），也不该让两条规则认同一件事。**漏掉任何一条，那个分类从此再也认不到东西**——这是 01 要逐条落表的原因。
- **报文在各包生成，格式只有一份**：`ssh` 与 `batch` 生成报文时不能引用判定包（那会破坏「`ssh` 不认识参数载体」的既有边界，也会在底层与判定层之间绕出依赖环）。所以**格式的唯一定义放在最底层的公共包里**，判定包与各生成方都只引用它，谁家都不自己拼前缀。
- **`code_defined` 字段删除**：它对应的合法性判断随之消失；分类条目写不写关键词、写什么，只由匹配语义决定。
- **顺序与选组规则不变**：两块（有无退出码）与块内先后次序照旧，报文只是关键词的一种。

### 呈现

- **不做译文层**：报文原文就是使用者看到的文本。终端明细、`output.txt`、`report.txt`、`results.xlsx`、执行日志（含 `SSHFleetDiagnose.log`）一律原样呈现，前缀不摘、术语不翻。
- **给人看的中文只有一处来源**：配置里的分类名（`name`）与排查提示（`tip`）。统计块里那一列始终是分类名；分类名没匹配上时，那一格回落成报错原文——今天回落的是一句中文，改造后是报文原文。
- **除既有截断外不做任何美化**：错误详情里保留端口、路径与原始错误，它们正是排查要用的东西。

### 并发数

- **归档报告的执行参数段，并发数在所有模式下都显示**（今天只对命令 / 脚本显示），因为并发数是这次执行的属性，与模式无关。

## Testing Decisions

**接缝**（尽量少，1–4 都是既有接缝，5 是这次唯一新增的）：

1. **失败归属**：判定入口（结果 + 模式 + 判据表 → 分类名）与既有分类语料（`testdata/error_classification_cases.toml`）。语料是既有的最高接缝，覆盖全部分类，改造后必须逐条仍然通过。
2. **配置加载**：判据文件加载入口（既有测试形态：写一份临时配置 → 断言加载结果或报错）。
3. **呈现**：`PrintStatistics`（统计块 → 断言分类名落在哪一行、提示语跟得上）与 xlsx 生成入口（断言「报错原文」列里是报文原文）。
4. **并发数**：报告生成入口（断言改密模式下也出现并发数那一行）。
5. **形态 → 报文**：执行侧每摊那个**导出**纯函数的包外测试（入参给布尔与计数，断言产出的报文文本）。这是原本挂在 `verdict_test` 里那批「结构字段 → 中文分类名」断言的新家；之所以要导出，是因为「不测私有函数」这条约定不给包内私有口子留位置。

**好测试的判据**（照既有约定）：

- 只测外部行为：给一个输入，看输出；**不测私有函数、不断言内部是否调用了某函数、不检查内部名单存不存在**。
- 期望值独立于被测代码：分类语料的期望值是**已知的正确分类名**（人写的），不是拿被测代码跑一遍抄下来的。
- 报文格式本身断言它**长什么样**（前缀、分隔、环境段），不以「被测代码产出的字符串」作为期望。

**既有测试的处理原则**：

- 断言分类**语义**的（语料、统计块里落在哪一行）必须全部保持通过——这是本次改动「不改变任何一类失败归属」的证明。
- 断言**字符串措辞**的（错误行、日志行）按新的呈现形态更新期望值，同一次提交里完成。凡以中文错误文本作为**输入**的用例（例如 `error = "创建会话失败 - ssh: rejected"`），改为以报文作为输入，期望分类保持不变。
- 断言 `code_defined` 或报文未改时期的那几条用例（2026-10-20 当天新增的校验类用例）随之删除，并在工单里记明去向。
- **结构形态的断言要搬家，不能就地删**：`verdict_test.go` 里那批「给一组布尔 → 期望一个中文分类名」的表格（改密四档、触发词未命中、部分成功、改密未过期、取消两档）改造后不再属于判定层，改为「给一组布尔 → 期望一条报文」的纯函数测试（接缝 5），分类归属再由语料或配置断言兜住。**语料里真正走结构字段的只有「部分成功」一条**（`success_files` / `failed_files`）；「任务已取消」那条是靠 `error = "context canceled"` 命中判据表的关键词，验的不是结构判定——语料的结构体里根本没有「被取消」这个字段。其余九条形态眼下只有单测守着，而「代填用尽后超时」连单测都没有；搬家时一并把缺的形态补进语料（先给语料结构体加上缺的字段），并给这一条补测试。

## Out of Scope

- **报文的中文翻译（译文层）**：本次不做。报文原文直接给使用者看，中文只存在于配置的分类名与提示语里。
- **Go 库与系统原始错误的翻译或改格式**：`dial tcp …: connection refused` 这类原样保留。
- **远端报文的二次加工**：远端说什么就记什么，不改写。
- **`ssh` 包「不认识参数载体」的既有边界**：报文由执行侧生成，不因此把 `cli` 引入 `ssh`——需要模式信息时按现有做法在调用方给了再传进来。
- **成功分类的措辞**（「执行成功」「传输成功」「改密成功」）来自模式名字表，不属本次报文体系。
- **退出码自动分类**（`执行失败(退出码N)`）的形态不变，仍由判定层按退出码给出，不产出报文。
- **参数校验与启动期日志里的中文**：`触发词不是合法正则：…`、`未提供有效的认证方式…`、启动期诊断提示——它们既不当失败原因匹配、也不是给人看的失败原因，保持中文，不套报文壳子。
- **逐文件的成功 / 跳过行**（`a.txt: 已跳过（符号链接）`）进的是输出明细而不是报错原文，保持中文。
- 审查报告里的其它候选（结果流水线、参数屏与报告字段清单、`buildTasks` 拆计划、模式开关收进模式表）。
