# 04: 传输一摊改用报文，「部分成功」改由配置认领

**要做的**：上传十个文件成了六个时，屏幕上显示的分类仍然是「部分成功」；但这次它**是配置文件认领出来的**——这份认领靠的是传输收尾时那一句 `sshfleet.transfer.finished: 6 of 10 files transferred`。把配置里那一条删掉，这一类就回落成显示这句报文原文（终端上就是英文原文，不翻译）。这是「程序定性的分类改由配置匹配」第一次真正落到用户可见面。

**实施入口**：`docs/issues/message-based-classification/README.md`。

**被谁阻塞**：03（前两摊已迁完，格式与发报点稳定）。

Status: ready-for-agent

## 验收

- [ ] `transfer` 一摊：SFTP 客户端创建失败、远程路径不存在、远程目标路径不是目录、远程路径不可访问、获取远程文件列表失败、本地文件不可读、创建本地目录失败等中文前缀改为报文（措辞以 `internal/ssh/sftp.go` 现状为准，上面列的是来源位置）。
- [ ] `本地文件错误` 一族的 4 条中文关键词改为报文前缀；**传输侧其余以工具自编中文为关键词的条目一并改挂报文**：`远程路径不存在`、`远端没有文件`（2 条）、`远程文件已存在`、`SFTP失败`（8 条）、`sudo失败`——漏一条，那个分类从此认不到东西。
- [ ] 传输收尾处（上传与下载各自的 `buildTransferOutput` 之前）在「有成功也有失败」时写一条 `sshfleet.transfer.finished: <成功数> of <总数> files transferred`。**总数取枚举后要传的文件数**，不是「成功数 + 失败数」——逐文件失败会中断该节点剩余传输（失败数最多 1，后面是「没轮到」）。**两句必须同源**（同一个纯函数产出），不是上传写一份、下载再写一份；取消早退那条路径也走同一个收尾。
- [ ] **写报文用追加、不覆盖**：这一格此时已经放着最后一条逐文件失败原因，`finished` 追加在它后面（换行分隔），两条都留着——盖掉就是吞信息。
- [ ] `SFTP 客户端创建失败` 在上传与下载两条路径各写了一遍——同一个环节名（`transfer.client_failed`），两处不得各起名字。
- [ ] 判据文件补上认领这些报文的条目，`name` / `tip` 与今天一致。
- [ ] **删掉判据文件里为「程序定性」开的豁免**：一个分类是否「已知」只由「登记与否」决定，与它有没有关键词无关（02 起就已不再要求关键词，这里确认配置侧没有残留说法）。
- [ ] **验收演示**（三条都要跑）：
  1. 删掉配置里认领「部分成功」的条目 → 该类结果回落成显示报文原文（终端、输出文件、xlsx 都是原文）；
  2. 把它改回并改 `name` → 屏幕显示新名字；
  3. 把它整组搬走、只在别处写一条 `sshfleet.transfer.` 前缀词 → 一次认领整摊传输报文。
- [ ] 分类语料与呈现层分类归属断言全绿。
