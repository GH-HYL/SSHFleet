## 验收

- [ ] **核对残留**：判定层不再有兜底判定函数、豁免名单、11 个中文分类常量（「密码过期」的入场信号与中止词保留按名查表的字面量，不算常量）；`code_defined` 在代码、配置、注释里一处不剩；判据文件头注释按报文口径写清楚「一个分类怎么算认得」。
- [ ] 归档报告的执行参数段，并发数对所有模式显示。
- [ ] **核对报文没有重复定义**：同一种失败只能产出一条报文，同一种情形只能有一个环节名。逐个环境扫一遍，重点看：
  - 命令超时（`exec.go` 与 `interactive.go` 两处）；
  - `SFTP 客户端创建失败`（上传与下载两条路径）；
  - `创建会话失败` / `申请终端失败` / `创建输入通道失败`（命令 / 代填 / 改密三条通道）。
- [ ] **报文清单与发报点核对**：spec《预算：全部报文清单》里的每一条都能在代码里指到一处发报点，且每一条都只有一处；代码里也没有清单外的报文（用户自写的分类关键词不算）。
- [ ] 全量测试与 `go vet` 通过；分类语料全绿。
- [ ] **端到端验收**：命令 / 脚本 / 上传 / 下载 / 改密五种模式各跑一次（本机搭测试环境：不可达端口造 `connection refused`、空目录造「远端没有文件」、只读文件造「本地文件错误」、普通账号造改密场景），确认：
  - 统计块显示的是配置里的分类名；错误详情那几行、`results.xlsx`、执行日志都是同一份报文原文（不残留「建立连接失败 - …」这类旧中文前缀）；
  - 报告里的并发数在每个模式下都在；
  - **删掉配置里某条分类 → 该类结果回落成报文原文**（至少在一类上演示）。
- [ ] 更新 CHANGELOG（按不兼容改动抬主版本；`code_defined` 按从未存在处理，不留「现已下线」的痕迹）与使用手册里涉及失败原因措辞、分类配置的段落——至少含 `docs/1-使用手册.md` 与 `docs/4-进阶知识手册.md`；后者有一句「先按结构事实分开的几类（不经文案表，直接定性）」在改造后不再成立，必须改掉。
