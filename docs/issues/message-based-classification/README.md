## 这是什么

工具自己编的中文错误（`建立连接失败 - dial tcp …`）与写死的中文分类名（「部分成功」「任务已取消」），现在由代码直接给分类名，使用者改配置改不动它们。这件事把它们统一成 `sshfleet.<环境>.<环节>: <英文>` 报文，交给判据文件匹配——**分类名从此只有一个来源：配置匹配到什么就是什么**。

## 五条最容易走偏的口径

1. **报文长什么样**：`sshfleet.<环境>.<环节>: <英文描述>`，环境固定七种（`connect` / `session` / `run` / `transfer` / `passwd` / `answer` / `abort`）；Go 与系统给的原始错误原样跟在冒号后面，不吞不改。
2. **结构事实由谁发**：部分成功、改密四档、取消两档这些是**结构事实**，由**看见它的那摊在执行侧收尾时**发一句陈述事实的报文（`sshfleet.transfer.finished: 6 of 10 files transferred`），每摊抽成一个**导出的纯函数**。判定层不认识这些字段组合。**「密码过期」是唯一的例外**：它是远端说的话，不发报文（ADR 决定第 9 条）。
3. **不做译文层**：终端明细、`output.txt`、`report.txt`、`results.xlsx`、执行日志**一律报文原文**。给人看的中文只有配置里的 `name` 与 `tip`。分类名没匹配上时，统计块那一格回落成报文原文。
4. **报错原文只有一格**：报文与已有原文之间、报文与报文之间一律**追加**，顺序「原文在前、报文在后」，谁都不覆盖谁（传输部分成功、建连被中断都会撞上「已经有一句原文」）。
5. **唯一的例外是 `执行失败(退出码N)`**：名字里带数字，配置的 `name` 写不了变量，做不成报文，仍由判定层按退出码拼。除它之外，代码里不许再有任何一处给分类名。

## 三个坑

- **别把「结构性分类」当成报文**。它是结构事实，报文只陈述事实：**用 `finished` 不用 `partial`，用 `canceled` 不用 `failed`**——叫不叫「部分成功」是配置里 `name` 的事。
- **判定层不许自己给分类名**。判定入口只查表；除 `执行失败(退出码N)` 这个例外，代码里不存在第二条给名字的路径。
- **「远端说了话就别补报文」**。改密那两档今天靠「报错原文为空」区分「远端一句话没说」与「远端给了原因」；改完之后如果远端已经说了原因，就让判据表按原话认，不要再补一句 `passwd.*`。

## 验收的硬标准

- 分类语料（`testdata/error_classification_cases.toml`）**33 条全绿，期望分类一个都不许变**。其中 **17 条**的 `error` 字段是工具自编的中文，要换成报文输入。
- `go build ./...`、`go test ./...`、`go vet ./...` 全过。
- 07 的端到端验收：五种模式各跑一次，统计块是配置里的分类名、错误详情与 xlsx / 日志是同一份报文原文。

## 开工前要知道的两件事

- **端到端要用的机器**：我那次是 Windows 主机上的 WSL2 Ubuntu，`sshd` 自带、systemd 正常，建几个账号就能造出五种场景（不可达端口、空目录、只读文件、密码过期账号）。换机器或换会话要先确认这个条件还在。
- **结构形态的测试护栏比看上去薄**：语料里只有「部分成功」一条真的走结构字段；「任务已取消」那条是靠 `error = "context canceled"` 命中关键词；「代填用尽后超时」连单测都没有。02 把断言搬到纯函数接缝时，要一并把这些形态补进语料。
