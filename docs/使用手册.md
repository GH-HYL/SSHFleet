## 节点清单

清单就是一份纯文本，**一行一台服务器**，英文逗号分隔。用记事本或任何编辑器都能写。

```csv
# 以 # 开头的是注释，空行会被跳过
192.168.1.10
192.168.1.11
192.168.1.12
```

**只写 IP 就够了**——端口、用户名、密码都从配置里取（见 [配置手册](配置手册.md)）。

如果某台机器要用不一样的值，往后接着写。总共 6 列，按顺序：

| 列 | 内容 | 必填 | 不写时取哪里的值 |
| --- | --- | --- | --- |
| 1 | IP 地址（**必须是标准 IPv4**，域名不行） | 是 | —— |
| 2 | SSH 端口 | 否 | 配置里的 `port` |
| 3 | 登录用户名 | 否 | 配置里的 `user` |
| 4 | 密码 | 否 | 配置里的 `password` |
| 5 | 私钥路径 | 否 | 配置里的 `key` |
| 6 | 私钥口令 | 否 | 配置里的 `key_password` |

第 4 列和第 6 列**同一套规则**：默认（不加密）时填**明文**，打开加密之后填**文件的本机绝对路径**（见 [加密与密钥](加密与密钥.md)）。

中间某列不用、但后面那列要写时，留空即可（逗号不能少）：

```csv
# 第 3 列留空（用配置里的用户名），第 4 列单独给密码
192.168.1.10,,,node10pass

# 用私钥登录：前面留空，第 5 列给私钥
192.168.1.11,,,,/home/ops/.keys/id_rsa

# 私钥本身带口令：第 6 列给口令
192.168.1.12,,,,/home/ops/.keys/id_rsa,口令明文
```

**清单里的路径可以简写**：只写 `id_rsa` 这样的短名字，会拼到配置的凭据目录下；写绝对路径则原样使用。（配置文件里的路径必须写本机绝对路径，见 [配置手册](配置手册.md)。）

**取值顺序**：清单这一列 > 配置文件。清单里写了就覆盖配置。

从别处导出的清单如果**第一行是表头**（第一列不是 IP），工具会自动跳过它，并在终端提示一行。

### 一份都不用建：直接写一行

临时测一台机器时，`-f` 可以直接接一串服务器信息，不用建文件：

```bash
SSHFleet -f "192.168.1.10" -c "uptime"
SSHFleet -f "192.168.1.10,22,root,你的密码" -c "uptime"
```

写法与清单的 6 列一一对应：`-f` 后面的东西是已存在的文件就当清单文件，以 IP 开头就当内联的一行节点。

### 缺东西怎么办：报错，不问你

端口、用户名、密码这些，如果清单没写、配置里也没有，工具**不会停下来问你**——它会在**开工前**把问题一次报全，然后退出：

```text
发现以下错误:
行 3 (IP: 192.168.1.12): - 密码为空：清单第 4 列没写，配置 account.password 也没配
行 7 (IP: 192.168.1.16): - 端口必须是1-65535之间的整数，当前值为：abc
```

报错会点到**第几行、哪一列、什么问题**。改完再跑一次。**检查通过就一定会尝试连接。**

## 五种操作

每次执行**只能选一种**：`-c` / `-s` / `-u` / `-d` / `--change-password` 五选一。无论哪种，都要配 `-f`（清单）。

### 执行命令 `-c`

```bash
SSHFleet -f nodes.csv -c "df -h"
```

命令会在每台服务器上执行一次，输出实时回传。

**命令会套一层工具自备的外壳**（先把环境变量设好、再把命令交出去，`&&` 等行为与终端一致）。想直接执行原始命令，加 `--no-shell`——名字里的 **shell 指的就是这层外壳**。

`--no-shell` 是"原样下发"，命令直接交给目标节点的默认解释器执行——这时 `[interpreter]` 里配的自定义解释器**不参与执行**。两者一起用时，参数确认屏的「解释器」一行会提示「原样下发，本次不生效」；配置是 `bash` 时与默认行为一致，不提示。

### 执行脚本 `-s`

```bash
SSHFleet -f nodes.csv -s deploy.sh
```

把本地脚本发到每台服务器执行。用什么解释器按脚本后缀取配置——默认 `.sh` 用 `bash`、`.py` 用 `python3`，可自行增删（见 [配置手册](配置手册.md) 的解释器一节）。需要 root 权限时加 `--sudo`。

### 上传 `-u` + `-p`

```bash
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/
```

`-u` 是本地文件或目录，`-p` 是**服务器上的目录**。三条硬要求：

- `-p` 必须是**绝对路径**，且**以 `/` 结尾**（如 `/opt/app/`）。
- **远端目录必须已经存在**，工具不会替你创建；写错会在那台机器上报"远程路径不存在"并跳过它。
- 只接**一个**路径，不支持通配符。想传目录内容，直接写目录本身（`-u /本地/abc`，不要写 `/本地/abc/*`）。

**上传目录时保留内部的子目录层级，但目录自身那一层不会重复出现**：`-u /本地/abc -p /opt/` 得到的是 `/opt/<abc 里面的内容>`。想要 `/opt/abc/…` 这种结果，把 `abc` 的**父目录**传上去。

**远端已有同名文件时不覆盖**：逐个传，传到那个同名文件就停下——排在它前面的已经传上去，它自己和排在后面的都不传。有传成也有没传成的，那台机器的分类是"部分成功"；一个都没传成是"远程文件已存在"。两种情况在统计里**都算失败**。要覆盖就先把远端的旧文件清掉再传。

### 下载 `-d` + `-p`

```bash
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads
```

`-d` 是**服务器上的路径**（必须绝对路径），`-p` 是**本地已存在的目录**。每台服务器下载下来的东西按 IP 分目录存放。

两条限制：

- `--sudo` 模式下的下载，**文件读取仍以登录用户身份进行**。权限 `700` 这类 root-only 的文件会读失败——先用 sudo 命令模式把文件搬到登录用户可读的位置，再下载。
- 下载用的目录枚举依赖目标机的 GNU `find -printf`（多数 Linux 发行版自带；busybox / BSD 环境不兼容）。

### 软链接怎么处理

上传和下载都**一律过滤软链接**（含 Windows 目录联接、`.lnk` 快捷方式），不传输也不中断执行。被过滤的条目会写进那台机器的结果明细里。

只有一种情况会报错：**过滤之后一个可传文件都不剩**（比如整个目录全是软链接）。上传时还会在终端额外提示一句：

```text
[提示] 上传源中有 3 个软链接/快捷方式被过滤（不上传）：...
```

### 批量改密 `--change-password`

给一批机器的过期密码换成同一个新密码。工具自己认出远端在问什么（「当前的密码」「新的密码」「重新输入」），依次把答案喂进去——**你不用配任何东西**：

```bash
SSHFleet -f nodes.csv --change-password "新密码"
```

新密码怎么给随配置里的加密开关（`credential.encrypt`）：不开加密时直接写明文密码，开了加密时写**密文文件的本机绝对路径**。它在日志、报告、参数屏里一律只留前后各 2 位。改密会话里**登录密码取清单里那台机器自己的密码**——所以清单给的是登录密码，不是新密码。

改密是**执行模式之一，与 `-c`/`-s`/`-u`/`-d` 五选一**，另外也不能和 `-a`、`-p`、`-k`、`--no-shell`、`--sudo`、`--no-sudo` 一起用（改的是登录账号自己的密码，跟执行身份无关）。`-f`/`-n`/`-t`/`-T`/`-r`/`--yes` 照常用。

**已经有密码的机器不会被改**：远端没出现密码过期的信号就当作这台机器不需要改，结果里单独归一类「密码未过期」。这类机器**计入失败数**——它们本来就不在这次运行的目标里，报出来才知道实际改了几台。

远端问的话认不出来时不会瞎填，一律等 `-t` 到点收场（提示语言不认识、提示词表里没有那条措辞）。**撞到新措辞**就往 `config/keywords_passwd.conf` 的 `[[step]]` 补一段；**失败原因**按远端自己说的原话归类（「新密码不合规」「写不进密码文件」「旧密码不对」…），它一句解释都不给时才归「改密未完成」——那是"原因没认出来"，要加一类也在同一份文件的 `[[category]]` 里加。

## 参数表

| 短 | 长 | 说明 |
| --- | --- | --- |
| `-c` | `--command` | 命令模式：在每台服务器上执行一条命令 |
| `-s` | `--script` | 脚本模式：上传本地脚本并执行 |
| `-u` | `--upload` | 上传模式：把本地文件或目录传到服务器 |
| `-d` | `--download` | 下载模式：从服务器下载文件或目录到本地 |
| | `--change-password` | 改密模式：把清单里密码过期的账号改成同一个新密码 |
| `-f` | `--csv-file` | 节点清单：文件路径，或直接写一行节点信息 |
| `-p` | `--path` | 目标路径：上传时的服务器目录 / 下载时的本地目录 |
| `-k` | `--key` | 这次用密钥登录（不加 = 用密码） |
| `-t` | `--timeout` | 命令跑完、文件传完的最长等待（秒） |
| `-T` | `--connect-timeout` | 连上服务器的最长等待（秒） |
| `-n` | `--number` | 并发数：同时操作几台（不填 = 全部并行） |
| `-r` | `--remark` | 任务名，用作结果目录名的后缀（不填自动生成） |
| `-a` | `--answer` | 代填：看到触发词就自动填内容（值可写多行，格式与 `-f` 的清单相同） |
| | `--sudo` / `--no-sudo` | 用 root 身份 / 用登录用户身份执行 |
| | `--no-shell` | 命令模式：不套工具的外壳（`shell` 指的就是它），命令原样下发 |
| | `--yes` | 跳过确认，直接执行 |

## 代填 `-a`

有些脚本会停下来问你——选哪个架构、要 deb 还是 rpm。加上 `-a`，工具看到你写的触发词就自动把内容填进去。看一个完整的对应关系，远端脚本 `deploy.sh` 里有这样的提示（`read` 停下来等你输入）：

```text
请选择架构 (1=amd64, 2=arm64):
请选择包格式 (deb/rpm):
```

你手敲时会输入 `1` 回车、再输入 `deb` 回车——用 `-a` 就是把这两个动作预先写下来：

```bash
./SSHFleet -f nodes.csv -s deploy.sh -a "1,请选择架构\ndeb,请选择包格式"
```

**值的格式与 `-f` 的清单完全一样**，只是列的含义不同：**一行一条**，**第 1 段是要填进去的内容**（工具会替你补一个回车），**第 2 段起都是触发词**（在输出里看到它就填），列数不限。触发词不用抄整句提示，**从提示原文里原样抄一段就行**——上面脚本打印 `请选择架构 (1=amd64, 2=arm64):`，你抄其中的 `请选择架构` 就能认出来。一条可以挂多个触发词（提示措辞拿不准时多写几个）：

```bash
-a "1,请选择架构,请选择CPU架构"
```

条数多的时候写成文件更省事：`-a` 也可以直接给一个文件路径，文件内容按同一套格式写（空行与 `#` 开头的行会被跳过）：

```csv
# 第 1 列填进去的值,触发词,触发词
1,请选择架构
deb,请选择包格式
```

```bash
./SSHFleet -f nodes.csv -s deploy.sh -a answer.csv
```

**多条是并行匹配的**：谁的触发词先在输出里出现就先用谁，与书写顺序无关（脚本会跳过提问，比如那台本来就是 deb、根本没问包格式）。脚本是顺序提问的，所以工具报「触发词未命中：第 1、2 条」时，**看最小的那个序号就够**——那是第一个出错的地方。防乱序填错靠的是把触发词写得有区分度，不是靠顺序。

**两条边界**：

- 每条**至少要有一个触发词**——触发词是唯一的门，不写等于无条件盲填，工具会直接报错
- 第 1 段**留空**是合法写法，代表只按一个回车：`-a ",请按回车继续"`

**两处 CSV 口径**（与 `-f` 的清单同一套）：内联值里的 `\n`（反斜杠 + n）是行分隔符——命令行写不出真实换行，多行只能这么写；**文件里的 `\n` 就是两个普通字符，不分行**。逗号是列分隔符，要写进代填内容或触发词里，就用双引号把整段包起来：`-a '"a,b",请选择架构'`。**引号本身**要写进值里就写成两个——**从提示原文照抄触发词时最容易撞上**（提示常写成 `Enter "yes"`）：`-a '1,Enter ""yes""'`。

**触发词要有区分度**：远端开着回显，你填进去的内容会被打回来，工具一样会拿它去匹配。

**两条收尾规则**（都算失败，在统计块里单独计数）：

| 分类 | 含义 |
| --- | --- |
| `触发词未命中` | 命令结束时还有代填没送出去：脚本没问，或问的话没认出来 |
| `代填用尽后超时` | 代填都送完了，脚本再没出声直到 `-t` 到点（卡在没配触发词的提示上、或任务本身就长，工具分不出） |

**密码过期的机器会被当场终止**：`-a` 运行里认到"密码过期"的提示就立刻结束该机器的会话、归「密码过期」，不会白等到超时。

`-a` **不能**和 `--no-shell`、`-u`、`-d` 一起用——原样下发与传输两类都没有「代填要喂进去的那条会话」，工具会明确报错而不是悄悄忽略。

**`-a` 对解释器有范围**：它要把命令 / 脚本正文当「一段程序文本」交给解释器，而各家的启动参数不一样——shell 家族与 `python` 用 `-c`，`perl` / `ruby` / `node` / `nodejs` / `lua` / `luajit` 用 `-e`，`php` 用 `-r`，工具按解释器替你适配好了（可配的写法见 [配置手册](配置手册.md) 的解释器一节）。换成范围外的解释器（如 `tclsh`、`deno`），`-a` 会**当场报错并列出支持范围**，而不是闷着不跑；不用 `-a` 则不受影响。

## 密钥登录

工具**默认用密码登录**。要用密钥，加 `-k`：

```bash
SSHFleet -f nodes.csv -c "uptime" -k
```

私钥从清单第 5 列取，没写就取配置里的 `key`。密钥失败就是失败，不会回退用密码再试。

- 加了 `-k`，但清单和配置里都没有私钥 → 报错退出，并告诉你缺什么。
- **没加 `-k`，但清单第 5 列写了私钥** → 用密码登录，同时给一行提示（提醒你配了私钥却没启用）。
- 私钥本身带口令 → 在第 6 列给口令（或配置里配默认口令）。工具不检查第 6 列（它无从判断你的私钥加没加密），但如果解析时发现私钥是加密的、又没有口令，会明确告诉你该怎么办。

## 执行身份

默认取配置里的 `sudo` 字段。一次执行想临时改：

```bash
SSHFleet -f nodes.csv -c "systemctl restart nginx" --sudo      # 用 root
SSHFleet -f nodes.csv -c "whoami" --no-sudo                    # 用登录用户
```

**用 root 前，目标节点上这个登录账号得已经配好免密 sudo**（`NOPASSWD`）——工具只发 `sudo <命令>`，不会也无法替你输入 sudo 密码。典型配法是在目标机 `/etc/sudoers.d/` 下放一行 `用户名 ALL=(ALL) NOPASSWD:ALL`（权限 `440`）。没配的话，命令会停在 `sudo: a password is required`，这一台就按执行失败计。

## 命令在远端是怎么执行的

你敲的是 `-c "df -h"` 或 `-s deploy.sh`，但**远端收到的不是这一句原文**。工具会把它包成一条「先备好环境、再启动解释器」的启动命令，你真要跑的东西（命令原文或脚本正文）从**另一条通道**送过去。

**搞清楚这件事有什么用**：日志里那行 `sh -c 'export …'` 不是你敲的，第一次看到容易以为工具把命令改坏了。知道每段在干什么，你才分得清哪些差异是工具加的正常包装、哪些得你自己负责（比如加了 `--no-shell`，环境就归目标机了）。

远端实际收到的东西，按情况如下：

| 你怎么跑 | 远端命令行 | 命令正文走哪 |
| --- | --- | --- |
| `-c "hostname"` | `sh -c 'export LC_ALL=… LANG=… PATH=…; bash'` | 会话 stdin |
| `-s deploy.sh` | `sh -c 'export …; bash -c ". /dev/stdin" "deploy.sh"'` | 会话 stdin |
| 上面两条加 `-a` | `sh -c 'export …; bash -c "$(printf %s <base64> \| base64 -d)" "deploy.sh"'`（末尾的脚本名只在脚本模式有） | 编进命令行 |
| 任意一条加 `--sudo` | 上面各条里的 `bash` 前多一个 `sudo ` | 不变 |
| `-c` 加 `--no-shell` | **命令原文，一个字不加** | 不用 stdin |
| `-s` 加 `--no-shell` | `<解释器> -c ". /dev/stdin" "<脚本名>"`，不套外壳、不设环境 | 会话 stdin |

### 把命令行拆开：每段在干什么

以 `-s deploy.sh` 为例，远端命令行是（真机日志原样；日志里外层单引号内的引号会写成 `'\''`，这里为便于阅读略去）：

```text
sh -c 'export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin; bash -c ". /dev/stdin" "deploy.sh"'
```

| 片段 | 是什么 | 为什么是它 |
| --- | --- | --- |
| `sh -c '…'` | 让远端的 `/bin/sh` 把单引号里那串当一条命令跑 | `/bin/sh` 是 POSIX 强制存在的，到处都有；用它做「先设环境、再启动解释器」的容器 |
| `export LC_ALL=en_US.UTF-8` | 把字符集与排序锁死成 UTF-8 | 见下节 |
| `export LANG=en_US.UTF-8` | 同上，作兜底 | 有些程序 / shell 只认 `LANG` |
| `export PATH=/usr/local/sbin:…:/bin` | 一组标准可执行目录 | 见下节 |
| `;` | 分隔 | 先把 `export` 做完，再启动解释器 |
| `bash` | 跑你脚本的解释器 | 取 `[interpreter]` 里配的（`.sh` 默认 `bash`）；有 `--sudo` 时它是 `sudo bash` |
| `-c` | 「用后面这段程序文本启动我」 | 各解释器不同（`perl` / `ruby` / `node` / `lua` 是 `-e`、`php` 是 `-r`），工具按解释器适配 |
| `". /dev/stdin"` | 让 `bash` 把 stdin 上的脚本读进来执行 | 正文不落盘，只能从 stdin 送；见下文 |
| `"deploy.sh"` | 把脚本名交回去当 `$0` | 见下文 |

命令模式（`-c`）没有后两段——没有脚本文件、也没有要补的名字。

### 两个 `export` 在干什么：让整批结果「长得一样」

这一段跟你的命令逻辑无关，它唯一的目的是**让一批机器跑出同样的结果形态**。

**这一段可以自己改**：它来自配置文件 `[execution] env`——出厂给了 `LC_ALL` / `LANG` / `PATH` / `TERM` 四条，可以自行增删、留空即关掉某条（详见 [配置手册](配置手册.md) 的 env 一节）。下面讲的是**为什么出厂要带这几条**。

**问题出在哪。** SSH 用非交互方式拉起的命令，拿到的环境是目标机自己的默认值，而**每台机器不一样**：locale 有的机器是 `C`、有的是 `POSIX`、有的跟着发行版是 `zh_CN.GB18030`、`ja_JP.UTF-8`……；`PATH` 常常只剩 `/usr/bin:/bin`。locale 管的事比很多人以为的多——**字符编码**（同一段字节按 UTF-8 解是中文、按 GB18030 解可能是乱码）、**排序规则**（`sort`、`ls`、字符串比较的结果都会变）、**大小写与数字格式**（某些 `awk` / `printf` 的输出会变）。

**不统一的后果，正是批量场景最要命的**：

- 同一条命令，A 机输出正常中文、B 机一片乱码；
- 工具要把输出归成「成功 / 失败 / 哪一类失败」，形态不一致时**分类可能失准**——该认出来的没认出来，报告与统计跟着错；
- 两台机器的输出没法放在一起逐字比对。

**出厂那两条 `LC_ALL` / `LANG` 就是干这个的：把 locale 钉死成同一个 UTF-8。** `LC_ALL` 优先级最高（设了就覆盖所有 `LC_*` 类别），`LANG` 是没有 `LC_ALL` 时的兜底，两个都写上，是防某些程序或 shell 只认其中一个。这样不管你连的是哪台机器、它原本什么 locale，工具跑出来的**中文都是正常中文、排序规则一致、输出可逐字比对、分类稳定**。选 `en_US.UTF-8` 而不是 `C.UTF-8`，是因为它在各类发行版上更普遍、行为更稳。

**`PATH` 那句同理。** 非交互拉起的 `PATH` 常只剩 `/usr/bin:/bin`，而 `sudo` 在 `/usr/sbin`、`python3` 常在 `/usr/local/bin`、`/opt/…`——不补就是 `command not found`。出厂配置直接给一组标准目录，**不读目标机的 `/etc/profile`**：靠登录 shell 补环境要求目标机装着 bash、shell 认 `-l`、profile 还得是它能解析的语法，三样都不保证；写死 PATH 则**只要 `/bin/sh` 在就能跑**。两点要记住：

- PATH 里列了目标机上**不存在**的目录不会报错（查找时静默跳过），不影响你的命令输出；
- 解释器装在**非常规位置**时，工具不知道，要你在 `[interpreter]` 里写**绝对路径**。

### 为什么要套一层 `sh -c`

就是给那两句 `export` 和「启动解释器」找一个共同的容器，让它们**在同一个 shell 里按顺序发生**——`export` 只对当前 shell 及其子进程生效，必须先设好、再在同一层里启动解释器，环境才传得下去。

- 为什么用 `sh` 而不是 `bash -lc`：见上一节 `PATH` 那段——`bash -lc` 要靠登录 shell 读 `/etc/profile`，约束太多；`sh -c` 不读任何配置、不依赖 bash。
- 为什么正文放 stdin、不放命令行：命令行会经过远端 shell 的解析，正文里任何引号、`$`、反引号都可能被吃掉或展开，得层层转义还容易出错；从 stdin 送则**正文完全不参与 shell 解析**，也不占命令行的长度额度。

### 正文走哪条通道：stdin 还是命令行

- **默认（不带 `-a`）：走 stdin。** 命令行里只有那段固定外壳，正文从会话的标准输入喂进去，正文再大也不受命令行长度限制。
- **带 `-a`：改走命令行。** 一次会话只有一条 stdin，而 `-a` 的代填要**独占**它（工具得盯着远端输出、把答案写回去），正文只能换条路——base64 编码后编进命令行，远端再 `base64 -d` 解回来，**全程不落盘**。
  - 代价是**长度上限**：远端内核留给单条命令的位置有限（约 128KB），base64 又让体积涨到 4/3，所以正文**约 90KB 封顶**。超了工具在**开跑前**就本地拦下报错，不会跑到一半才失败。
  - 换句话说，这个上限换来的是「**脚本 + 代填能同时用**」——安装脚本往往又大、又要中途答题，这是最常见的组合。

### 脚本名（`$0`）为什么单独补一次

脚本模式的正文不是从磁盘上的文件跑的（默认经 stdin、带 `-a` 时编进命令行），解释器眼里它只是「一段来自标准输入的内容」——`$0` 于是只是解释器名、`BASH_SOURCE` 更是空的。凡是**靠自己的文件名取信息**的脚本（安装包常见：文件名里带目标 IP、站点类型）这时什么都取不到，后面拿这个空值做数值比较会直接报错（如 `[: -eq: unary operator expected`），脚本一声不响地走进「系统不支持」的分支。

工具的办法：把脚本名作为 `-c` 之后的**第一个参数**交回去——shell 的 `-c` 后面第一个参数就是本次的 `$0`，脚本再取自己的名字就和「落在磁盘上跑」一模一样了，而正文依旧不落盘。两个边界：

- **只对 shell 家族补**（`bash` / `sh` / `dash` / `ksh` / `zsh` / `mksh` / `ash`）。`python3` 的 `-c` 之后第一个参数落在 `sys.argv[1]`、不是 `argv[0]`，补了反而往它的参数表里塞个它不认的东西，所以 python 维持原样。
- **zsh 要单独适配**：zsh 的 `source` 会把 `$0` 重置成「被 source 的文件名」，等于把补回去的名字又盖成 `/dev/stdin`；工具对 zsh 先关掉 `FUNCTION_ARGZERO` 再 source，名字才能留住。bash、dash 等没有这个行为。

### `--no-shell` 关掉的是整层外壳

加 `--no-shell`，上面那**整层外壳都不要了**：不设 `export`、不走外壳、也不加 `sudo`，你写的命令**原封不动**交给目标机（由目标机自己的登录 shell 去解析、用它自己的环境跑）。脚本模式同样支持——剥掉外壳与环境后，只剩解释器自己那条调用（`<解释器> -c ". /dev/stdin" "<脚本名>"`），正文照旧走 stdin、`$0` 照旧补回。

它**与 `-a` 互斥**（代填要独占会话），冲突时当场报错、不会悄悄忽略。

用它的代价要清楚：**环境不再由工具统一**——`PATH` 只剩目标机给的那点（`sudo`、`python3` 可能 `command not found`），locale 也回到目标机默认值（中文可能乱码、输出形态可能不一致）。所以「批量要稳定结果」时不要加它；它适合你明确知道目标机环境、就要它原样跑一条命令的场合。

上传 / 下载 / 改密不涉及这套——没有"你的命令"要下发，各自的中间命令另有固定形态。

**自己核对**：执行期日志里的 `交给 SSH 执行` 一段，就是远端收到的东西：

```text
交给 SSH 执行：
  命令行： sh -c 'export LC_ALL=… LANG=… PATH=…; bash'
  stdin：  hostname; whoami
```

`report.txt` 同口径；带 `-a` 时那一段写成 `原始命令 / 处理方式 / 最终命令` 三段。

## 并发与超时

默认**全部节点一起连**。服务器或网络扛不住时限流：

```bash
SSHFleet -f nodes.csv -c "uptime" -n 10
```

超时分两个：`-T` 管连接，`-t` 管执行与传输（按模式取配置里的默认值）。

```bash
SSHFleet -f nodes.csv -c "uptime" -T 15 -t 60
```

上传时工具会按**上传总大小**给一个并发数建议（不超过节点数；与当前值相同就不问），在参数屏之后决定要不要采纳。

## 备注

`-r` 给这次执行起个名字，它会成为结果目录名的后缀：

```bash
SSHFleet -f nodes.csv -s deploy.sh -r 发布v2
# → history/2026-09-22_14-30-00_script_发布v2/
```

不填会自动生成（命令模式取命令的首个词，脚本 / 上传 / 下载取路径的文件名）。

## 执行前你会看到两屏

顺序是固定的：**先危险提示，再参数确认**。

**第一屏（可能没有）：危险命令提示屏。** 工具在执行前会检查命令内容（命令模式检查 `-c` 的内容，脚本模式检查脚本全文），命中规则时列出每一条：

```text
╔════════════════════════════════════════════════════════╗
║                   ⚠  发现危险命令  ⚠                    ║
╠════════════════════════════════════════════════════════╣
║    来源: 命令                                          ║
║    行号: 1                                             ║
║    内容: rm -rf /var/log/*                             ║
║    规则: 递归删除系统目录                              ║
║    级别: 禁止                                          ║
╠════════════════════════════════════════════════════════╣
║    这条命令有风险，请确认你确实要执行它                 ║
╚════════════════════════════════════════════════════════╝

确定继续？ [y/N]
```

几个级别共用同一套版面，区别只在颜色；页脚文字按级别调整（禁止级是"此命令被禁止执行，程序将立即退出！"，直接退出、不给确认）。来源与行号用来定位命中（命令模式下来源是"命令"，脚本模式下是脚本路径 + 行号），内容显示你敲的原文。没命中任何规则时，这一屏不出现。

同一条命令命中多条规则时，只显示风险最高的那一条——所以 `rm -rf /var/log/*` 同时撞上"删除日志文件"（中）与"递归删除系统目录"（禁止）时，上屏的是禁止级。

**第二屏：参数屏。** 把这次要执行的东西摊开给你看——执行身份、操作内容、节点清单、节点数量、并发数、超时；命令 / 脚本模式在解释器**不是 `bash`** 时，还会多一行写明用哪个解释器。看完确认：

```text
以上确认无误，开始执行？ [Y/n]
```

**上传模式在参数屏之后还有一步**：按上传总大小给出并发数建议；采纳的话，参数屏会**再显示一遍**（并发数那一行凸显）。

**级别决定后果**：`禁止` 级直接拒绝执行、工具立即退出；`高` / `中` / `低` 需要你确认一次。

规则写在 `config/keywords_dangerous.conf` 里，每条包含名字、示例、正则、级别。不想被某一条打扰，把它改成 `enabled = false`，或者用 `#` 注释掉整条。

## 不要任何确认

```bash
SSHFleet -f nodes.csv -s deploy.sh --yes
```

适合脚本和定时任务。加了这个，参数屏与确认全部跳过，直接执行。脚本后缀没配到解释器时的"继续用 `bash` 吗"也一并跳过——直接按回退解释器跑。危险命令的处理不受影响：`禁止` 级仍然拒绝，其余级别放行但会在工具日志里留一条记录。

## 执行完，结果在哪

每次执行都会在 `history/` 下建一个目录，名字是「时间 + 操作类型 + 备注」：

```text
工作目录/
├── latest_history                      指向最新那一次的历史目录（快捷方式 / 软链接）
└── history/
    ├── SSHFleetTools.log               工具自己的运行日志（滚动保留全部历史）
    └── 2026-09-22_14-30-00_command_看磁盘/
        ├── terminal-output.txt         终端显示的文本记录
        ├── terminal-output.xlsx        同上，Excel 格式
        ├── report.txt                  汇总报告
        ├── results.xlsx                每台机器的结果明细
        ├── SSHFleetExec.log            本次执行的明细日志
        └── assets/                     本次用到的清单、脚本与代填文件的备份
```

回看历史有两个入口：进 `history/` 找对应时间的目录，或者直接打开工作目录下的 `latest_history`（它总是指向最新那一次）。

**哪台机器出了问题、细节是什么，都在那一次的目录里**——终端上只给汇总，逐台明细只写在 `results.xlsx`、`SSHFleetExec.log` 与 `terminal-output.txt` 里。

终端上，执行过程中会实时显示进度；结束后输出统计：总耗时、节点数量、成功与失败台数、失败原因分类。分类后面可能跟着一段"提示"（该分类的可能原因）。

连上了却没跑成的行，会多给一段「错误详情」：报错原文、服务端提示、「未送出的代填」（哪几条代填没喂进去、触发词写的什么），以及「中间步骤」——工具为完成这次操作在远端额外跑的伴随命令（下载前的预检查、远程文件枚举、改密收尾）各自的退出码；某一步的退出码拿不到（超时 / 中断）会写明「未拿到退出码」，不会拿 0 冒充。

明细在命令 / 脚本模式下会实时打在终端；上传 / 下载模式下终端只有进度条与个别提示，逐文件的结果写进 `SSHFleetExec.log` 与 `terminal-output.txt`。
