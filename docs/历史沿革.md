# 历史沿革

> 这一页记的是**这个工具从哪来**，不是怎么用。怎么用看 `README.md`。

## 这一页为什么存在

2026-02 到 2026-11，这个工具换过四次仓库、重开过两次，五代实现的提交彼此没有父子关系。要把它们读成一条线，只能把各段的首提交改挂到上一段的末提交，再把这些改动烤成真实提交——**那一条线就是分支 `history/evolution`**。

分支末提交与 `master` 末提交内容完全一致。所以同一条线上，既是「当前代码」，也是「完整来路」。

## 断代在哪

| 断点 | 间隔 | 实情 |
| --- | --- | --- |
| 04-17 | 同日 | 三方重叠：原型 I 收口、引擎原型独立、原型 II 开仓，都在这天 |
| 05-14 → 07-01 | 48 天 | 原型 II 停在这里；07-01 以「SSHFleet工具init」重新开仓，连目录形态都换了 |
| 09-10 → 09-11 | 1 天 | Python 线刚修完危险命令识别，次日就起了 Go 重写方向稿 |

**接点两侧不是同一份代码的延续。** 那是当年确实换了仓库重来，不是历史丢了。看 `git show` 会发现接点前后目录结构突变，这是事实原貌。

## 拼接方式与代价

- 各段只取 `main`，不带标签与旁支。
- 接完后**本线上每个提交的 SHA 都与原仓库不同**；想对上原仓库，按提交信息与日期在原地址找。
- `sshexec-batch` 不单独成段：它唯一那条提交与原型 II 的首提交是同一个对象，本来就只有一份。

## 剔掉了什么

每次重新编译都把 Go 可执行文件提交进仓，外加一个 61.7MB 的打包 zip，原始合计约 360MB。归档按「单文件超过 5MB 一律剔除」清掉：

| 文件 | 量级 |
| --- | --- |
| `batch_ssh`、`batch_ssh.exe` | 7.7 ~ 8.4MB，多个版本 |
| `SSHFleet_Go`、`SSHFleet_Go.exe`、`SSHFleet`、`SSHFleet.exe` | 9.3 ~ 10MB，多个版本 |
| `sshfleet`（Linux 二进制） | 9.7MB |
| `others/sshexec-build.zip` | 61.7MB |

- 只改这些文件、其它没动的提交因此变空，自动摘掉，共 2 条。
- 源码、文档、配置、关键词规则、测试一律原样保留；本线最大单文件 0.21MB。
- 要取当年的二进制，回原仓库取。
