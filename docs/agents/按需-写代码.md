# 写代码

## 工作区结构

```text
.
├─ skills/    Agent 技能实体
├─ docs/      议题、决策、文档口径、手册
├─ modules/   各语言工程
├─ build/     过程产物
├─ release/   发布产物（开发者用）
├─ tools/     工程部件
└─ personal/  个人工具
```

- **`skills/`**——技能常放的位置，分 `person/`（自建）、`engineering/` 与 `productivity/`（上游副本）。**不必进去读**，用斜杠命令调即可。
- **`docs/`**——每类文档一个目录：`issues/` 放议题（规格与工单），`adr/` 放决策记录，`agents/` 放这套约束（`必读-`／`按需-` 两族）与写文档、走流程的口径；根下的 `docs/*.md` 里那六册是给使用者的手册（`1-使用手册` 到 `6-示例`）。
- **`modules/`**——按语言存放，目录名 `项目名_语言`；重构前的旧工程作 `*_bak*/` 放这儿，**只读不改**。
- **`build/`**——只放过程产物，**故意不进版本控制**。
- **`release/`**——发布产物落点，执行者不必关心。
- **`tools/`**——工程部件：提交闸门、测试入口、打包发布、A/B 车架。
- **`personal/`**——开发者自己的工具，与工程无关，**执行者不必读**。

## 代码工程

**默认不加**：未经要求的重构、依赖、设计模式、新增文件，一律不引入。

- 入口文件放工程根目录，**以入口为中心的集中式编排架构**；其余文件均为其中某个环节的分支实现，由入口统一调用并回收结果
- **MUST NOT** 在子模块反向驱动主流程（回调控制生命周期、全局状态跨模块流转）
- **MUST NOT** 读写他模块的**包级可变状态**。判据是「有没有人真的写它」，不是「语法上能不能写」：常量表、哨兵错误这类约定不改的包级值不在此列
- 根目录**必须**建 `src`（Py）/ `internal`（Go）：其内只建功能目录、不放散文件，且**必须**含 log 模块
- 代码按功能分目录存放，模块内各文件的用途应能被一句话说清；需要拆分时按**功能边界**拆，**不按行数**机械切割

**动结构**（拆包、并份、移函数、删死代码）：

- **只看当下指得出来的事实**。不算理由：观感类（看着乱、更好读）、预测类（以后可能要用）、度量类（行数变少、更好接测试）
- **算理由的两种事实**：某个依赖没用上，或只用了两个字段却把整个对象传进来；真发生过「改了 A 不得不改 B」。依赖指运行期依赖，lint 与构建脚本不算
- **MUST NOT** 为「以后可能要用」预留抽象——该不该预留由开发者判定，不由执行者推测
- 接新环节优先**新增**实现文件，不靠给既有模块加 `if` / `switch`；加分支明显更合适时（三五行、确是同一功能多一种情况）**先说出来**由开发者定
- 动手前先看谁在调：`codegraph sync && codegraph callers <符号>`，`<符号>` 换成真名；装不了 codegraph 就用 `grep -rn '<符号>'` 兜底。**不要用** `codegraph explore`

## 测试怎么写

- **测试只写在预先说定的接缝上。**「接缝」＝从外面调用就能观察到的那个入口（公开函数／命令入口／进程出入口）。动手前先把「这回测哪个接缝」跟开发者说定，**没说定不写测试**；说定不了就问，**MUST NOT** 自作主张挑一个「最保守的」口径就开写
- **MUST NOT** 测内部实现：不 mock 自己写的模块、不测私有函数、不断言内部调用次数、不绕过接口去查旁路。判据：**重构后行为没变、测试却红了**——那说明测错了地方。**此条只对红线区成立**，自定义区是它的豁免区（见下）
- **期望值 MUST 独立于被测代码**：用已知的正确字面量、手算样例、或规格里的数；**MUST NOT** 用和被测代码同样的算法把期望值再算一遍——那样按构造必然通过
- **一次一个纵切**：一个测试 → 一点实现 → 再下一个，**MUST NOT** 先把测试全写完
- 循环怎么转（先红后绿、一次一片、重构不掺在循环里）照 `/tdd`

**测试分两区，一条红了先分清为什么红：结构被人动了、需求变了，还是环境没起来。**

- **结构被人动了**：先判这是不是架构腐蚀。是，红线区红得对，该修的是结构，不是把断言改松。
- **需求变了**：测试跟着改；但这条住在红线区的，改它要走「改测试红线要开议题、写 ADR」那条，说清是工程设计变了还是复杂度变了。
- **环境没起来**：机器没起、网络不通、超时抖动——两区都不进，也不许按需求变更归档。这类必须修，修不掉说明那条测试本来就不该要机器（打标，无机器时跳过，跳过不算绿，见 `/tdd`）。

**接缝定死之后，两区都不必每次再说**：红线区的接缝由「红线区只许站三种接缝」那条定死，自定义区由写它的人当场定。

- **红线区只放结构，一条行为断言都不放**——混进「跑起来对不对」，改一个小需求就得改红线，红线就被拖下水了。断言只碰**形状与流向**（字段在不在、谁填的、下一站读不读得到、编译过不过），不碰**值算得对不对**。只收机械判得出来的约束；住单独的包，不与被测代码同包；只许站三种接缝：塔尖的进程出入口、站的入口（递一张纸、收一张纸）、横切包的那一件事。
- **红线区只许 import 标准库、契约、`message`，以及被它钉的那一个包**（站包或横切包，一个测试文件只能钉一个）；`message` 是造话的工具，检查器把它与契约同级放行。import 第二个被测包、或 import 两区共用的假件包，即报。**红线测试不享 `_test.go` 的依赖方向豁免**——否则它成了全工程唯一不被依赖检查看的代码。
- **自定义区跟着被测包走，怎么顺手怎么写**，伸进内部、mock 自己写的模块都随它。唯一硬规矩：**不许与红线区共用假件包**，假的连接、时钟各写一遍。
- **改红线区走 `必读-约束.md` 第 7 条。** 红线名单与每条的指纹同住一处；**指纹钉测试名与该测试直接引用到的生产符号，不钉字节**（`gofmt`、改注释、经 helper 间接引用的都不算），对不上就红。新增一条不算改，删掉、改名、收窄引用面算改。
