# Triage 标签

相关技能用五个标准分诊角色来表达状态。本文件把这些角色映射到本仓库 issue 载体中实际使用的标签字符串。**本仓库在此基础上多一个 `done`，共六个。**

| mattpocock/skills 中的标签 | 本仓库中的标签 | 含义 |
| ------------------------- | -------------- | ---- |
| `needs-triage`            | `needs-triage`    | 待维护者评估 |
| `needs-info`              | `needs-info`      | 等待提出方补充信息 |
| `ready-for-agent`         | `ready-for-agent` | 描述完整，可交给 AFK agent 执行 |
| `ready-for-human`         | `ready-for-human` | 需人工实现 |
| `wontfix`                 | `wontfix`         | 明确不做 |
| ——（技能原版无此值）       | `done`            | 已完成 |

**`done` 是本仓库新增，不来自技能原版。** 技能假设工单做完就被「关闭」——在 GitHub / Linear 那类载体上，关闭是一个动作而非标签，关掉的工单自动从列表里消失，所以不需要这个值。本仓库以本地 markdown 作载体，文件关不掉、永远留在目录里，因此需要一个能表达「已完成」的值。

> **授权记录**：2026-10-17，作者就「已完成该用哪个值」明确选定「自己加 `done`，并注明是本仓新增」。本条属于对约束类文件的实质修改，按「一、约束·1·2」记录下来源。

**`resolved` 不是普通工单的状态值**：它是 `/wayfinder` 探路工单专用的（与 `claimed` 配对，见 `issue-tracker.md`「Wayfinding 操作」），普通工单 **MUST NOT** 用它。

**一份文件只有一个 `Status:`**。状态不写进文件名——`spec-已闭环.md` 这类写法已废弃，文件名只承载 slug。

当某个技能提到某个角色时（例如「打上 AFK-ready 分诊标签」），使用本表中对应的标签字符串。

需要改用其他词汇时，直接编辑右侧一列即可。
