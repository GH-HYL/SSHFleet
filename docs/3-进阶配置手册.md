# 3 进阶配置手册

这是《2 基础配置手册》的附属手册，讲 `config/SSHFleet.conf` 里**进阶配置**段的字段。

它们随包都带出厂值，**不改也能跑**——只想简单用的人不必看这一册。要改的时候，这一册把每个字段**什么时候用、怎么配、配错会怎样**讲清楚；《2 基础配置手册》不展开它们，用到时只给一句指路，内容都在这儿。

> [!WARNING]
> 这一册讲的是**进阶配置**，理解起来比基础那几册费劲。这些字段随包都有出厂值、**不改也能跑**——只想把工具用起来的话，先跳过这一册。

> 进阶配置的字段和基础配置的一样，**必须写出来、一个都不能缺**——缺哪个，启动时点名报错。

---

## 1 凭据

`[credential]` 表管一件事：**密码和私钥口令怎么存**——直接写着，还是加密成文件、用的时候拿主密钥解开。**出厂默认加密**，所以这一节直接决定你每次登录递出去的是什么。

先看总开关——`config/SSHFleet.conf` 的 `[credential]` 段：

```toml
[credential]
encrypt = true                # 出厂值：加密
```

它一锤定音，同时决定**四个位置**该怎么写：配置里的 `password`、`key_password`，清单第 4 列（密码）、第 6 列（私钥口令）。

**加密（`encrypt = true`，出厂值）**——`config/SSHFleet.conf` 与清单文件里，这四处都写「凭据文件的本机绝对路径」，磁盘上只有密文。

`config/SSHFleet.conf`：

```toml
[credential]
encrypt = true                            # 加密开关
```

```toml
[account]
password = "C:/Keys/db_pass.sec"          # 密码文件的本机绝对路径
```

清单文件（如 `nodes.csv`）第 4 列：

```csv
192.168.1.10,,,C:/Keys/node10_pass.sec    # 这台机器的密码文件
```

**不加密（`encrypt = false`）**——同样这四处，改成直接写密码本身。

`config/SSHFleet.conf`：

```toml
[credential]
encrypt = false                 # 关掉加密
```

```toml
[account]
password = "你的密码"            # 直接写密码
```

清单文件（如 `nodes.csv`）第 4 列：

```csv
192.168.1.10,,,这台机器的密码    # 直接写密码
```

改开关时，**这四处要一起改**（从"密码本身"换成"文件路径"，或反向），否则工具解不开。两种写法的差别、怎么生成密文文件 → 下一节「2 加密与密钥」。

余下三个字段多数只在你要用**密钥登录**时才碰：

| 字段 | 默认 | 什么时候改 |
| --- | --- | --- |
| `credential.key` | `""` | 所有机器共用一把私钥时，填它的本机绝对路径；某台要用别的，在那台清单第 5 列覆盖 |
| `credential.key_password` | `""` | 私钥本身带口令时填：不加密填口令明文，加密填口令文件的本机绝对路径 |
| `credential.secret_dir` | `""` | 凭据目录，**只对清单里的相对路径生效**——第 5 列写 `id_rsa` 这样的短名字会拼到这里；留空则清单里必须写绝对路径 |

密钥登录怎么用（`-k` 开关、口令怎么给）→ 见「2.4 私钥怎么配」。

## 2 加密与密钥

出厂默认就是加密：密码与口令以密文存在磁盘上，解开它要一把**单独存放的主密钥**。这一节把"从零用起来"和"要关掉它"两条路都走一遍。

### 2.1 一个开关，两处写法

`config/SSHFleet.conf` 的 `[credential]` 段：

```toml
[credential]
encrypt = true           # 出厂值：true = 加密（填文件路径）；false = 明文
```

同一个位置，两种写法，看开关：

| | 配置里的 `password` | 清单第 4 列 |
| --- | --- | --- |
| `encrypt = false` | 写**密码本身**：<br>`password = "Abc@1234"` | 写**密码本身**：<br>`192.168.1.10,,,Abc@1234` |
| `encrypt = true` | 写**密码文件的本机绝对路径**：<br>`password = "C:/Keys/db_pass.sec"` | 写**密码文件的本机绝对路径**：<br>`192.168.1.10,,,C:/Keys/node10_pass.sec` |

第 6 列（私钥口令）与配置里的 `key_password` 同一套规则。

- 不加密：密码就摆在文件里；配置与清单**都不要外传**。
- 加密：磁盘上只有密文，要主密钥才解得开。

> 改这个开关，`password` / `key_password` 与清单第 4、6 列要**一起换写法**（"密码本身" ↔ "文件路径"）。

**主密钥是什么、为什么不能带着走、丢了会怎样** → [4 进阶知识手册](4-进阶知识手册.md) 的「7 主密钥为什么要单独存放」。

### 2.2 加密凭据文件

从头到尾走一遍（以 Linux 为例）：

```bash
# 1. 生成主密钥。只需一次；生成后要重开终端才能读到它
SSHFleet --gen-key

# 2. 把明文密码写进一个文件
echo -n '你的服务器密码' > /home/ops/.keys/db_pass.txt

# 3. 就地加密——文件内容被改写成密文
SSHFleet --convert-secret /home/ops/.keys/db_pass.txt

# 4. 把配置 / 清单里那几处，改成这个文件的绝对路径
#    config SSHFleet.conf:  password = "/home/ops/.keys/db_pass.txt"
#    清单第 4 列:           /home/ops/.keys/db_pass.txt
```

`--convert-secret` 是**自适应**的：它先看文件现在是什么，再按配置的开关转成该有的样子。

- 已经是目标格式 → 提示跳过，不做无用功。
- 需要先解开才能转（例如关掉加密后要把文件转回明文）→ 自动用主密钥解开再转，不必先改配置。
- 转换后有防呆：文件为空、含二进制内容、内容是多行（多半是误粘贴）都当场报错；需要解密却没配主密钥、或主密钥对不上，会明确提示并给出下一步。

**要关掉加密**（把 `encrypt` 改回 `false`）：

1. 对每个凭据文件跑一次 `SSHFleet --convert-secret <文件>`，把它转回明文；
2. 把配置 / 清单里那四处改成密码本身。

### 2.3 三命令速查

| 命令 | 什么时候用 |
| --- | --- |
| `SSHFleet --gen-key` | 第一次开启加密之前，生成主密钥（本机已有一把时，会先并排显示"本次用的"与"本机保存的"两把指纹再问你；为什么要这么存见 [4 进阶知识手册](4-进阶知识手册.md) 的「7 主密钥为什么要单独存放」） |
| `SSHFleet --key-status` | 提示"主密钥有问题"、或换了机器 / 终端之后，看现状：读到哪把、本机存的是哪把、是否一致、下一步做什么 |
| `SSHFleet --convert-secret <文件>` | 凭据填成明文之后（或改了加密开关之后），把文件转成该有的格式 |

这三个都**单独使用**，不跟批量执行一起用。
### 2.4 私钥怎么配

私钥不是"凭据文件"，不参与加密转换——私钥文件本身就是 PEM 原文（或它自己的加密格式），工具不改它。

要用密钥登录，就三件事：

1. **加 `-k`**（`--key`）。不加就是纯密码登录，配置里配了私钥也不会用。
2. **私钥路径**取清单第 5 列，没写就取配置的 `credential.key`。所有机器共用一把时，在 `config/SSHFleet.conf` 里配好一把默认的：

   ```toml
   [credential]
   key = "/home/ops/.keys/id_rsa"          # 默认私钥的本机绝对路径
   ```

   ```bash
   SSHFleet -f nodes.csv -c "uptime" -k    # 加 -k 才走密钥登录
   ```

3. **私钥口令**（私钥自己带密码时）取清单第 6 列，没写就取配置的 `credential.key_password`——按加密开关的规则填（不加密填口令明文，加密填口令文件的本机绝对路径）。

工具**不检查**第 6 列（无从判断私钥是否加密）；解析时发现私钥有口令、又没给口令，会明确提示怎么办。定时任务这类非交互场景同样适用：口令写在清单或配置里。

## 3 路径怎么写

配置里的凭据路径（`password` 打开加密时的值、`key`、`key_password`、`secret_dir`）一律写**本机绝对路径**——跑工具的那台机器要能直接打开它：

| 本机是 | 这样写 | 这样写会被拦下 |
| --- | --- | --- |
| Windows | `secret_dir = "D:/Keys"`<br>`key = "D:\Keys\id_rsa"` | `/home/ops/.keys` |
| Linux | `secret_dir = "/home/ops/.keys"`<br>`key = "/home/ops/.keys/id_rsa"` | `C:/Keys` |

三条规则：

- **一律绝对路径**。相对路径只在清单里能用（拼 `secret_dir`），配置里不行。
- **分隔符写 `\` 或 `/` 都行**，Windows 上两种都能读；程序使用时统一按 `/` 处理，盘符大小写也一样处理，你不必操心。
- **不支持 `~`**，要写完整路径。

## 4 输出开关

`[enable]` 表：三个开关都决定**产物里多不多出一份文件或一段提示**。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enable.output_to_xlsx` | `true` | 终端输出是否同时导出 Excel。`false` = 只留文本 |
| `enable.results_to_xlsx` | `true` | 结果明细是否导出 Excel。`false` = 不产出这个文件 |
| `enable.show_category_tips` | `true` | 统计末尾是否显示"提示："块（解释本次出现过的失败分类可能是什么原因） |

例：几百台机器的一次执行，`results.xlsx` 可能有几万行、打开很慢——只看终端与文本日志时，在 `config/SSHFleet.conf` 的 `[enable]` 段里把它关掉：

```toml
[enable]
results_to_xlsx = false      # 不导出结果明细表
```

## 5 交互代填

`[interactive]` 表：管 `-a` 代填与 `--change-password` 改密的匹配口径。这两个开关同时管代填的触发词与中止词、改密的提示词与入场信号。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `interactive.regex` | `false` | 触发词按子串包含匹配；`true` = 按正则匹配 |
| `interactive.case_sensitive` | `false` | 不区分大小写；`true` = 区分 |

默认那两项（子串、不区分大小写）与失败分类的判据口径一致，通常够用——触发词从提示里抄一段固定文字就行。只有当提示变体多、一段固定文字盖不住时，才在 `config/SSHFleet.conf` 的 `[interactive]` 段里开正则：

```toml
[interactive]
regex = true                 # 触发词改按正则匹配
```

例：远端提示有的机器是 `Are you sure? [y/n]`、有的写成 `确定继续？ [y/n]`——一段固定文字盖不住，开正则后触发词写 `Are you sure|确定继续` 即可。开启后触发词按正则解释，写法不对会在执行前报错。

## 6 远端环境变量

`[env]` 表（顶层段，跟 `[account]` 那几段平级）：命令行下发前在远端导入的环境变量——一行一个，写成 `名字 = "值"`。出厂给了四条：

| 名字 | 值 | 作用 |
| --- | --- | --- |
| `LANG` / `LC_ALL` | `en_US.UTF-8` | 统一字符集与排序 |
| `PATH` | 一组标准目录 | 补上 `sudo` / `python3` 所在目录 |
| `TERM` | `dumb` | 统一成哑终端，抑制彩色与转义序列 |

**为什么要设它们** → [4 进阶知识手册](4-进阶知识手册.md) 的「2 为什么要统一远端环境」。

**怎么改。**

- **加一条**：照 `MY_VAR = "值"` 的写法往下加一行。常用的还有 `DEBIAN_FRONTEND = "noninteractive"`（apt / dpkg 不弹交互）、`PYTHONIOENCODING = "utf-8"`（python 输出固定 UTF-8）、`TZ = "Asia/Shanghai"`（统一时区，脚本里的时间戳才可比）。
- **临时关掉一条**：把它的**值留空**（如 `LC_ALL = ""`），这一条就被当作不存在、不导入。
- **一条都不要**：`[env]` 下不写任何条目即可——工具就完全不导入环境变量。

**名字有要求**：必须是合法 shell 变量名（字母或下划线开头，后接字母、数字、下划线）。写 `123`、`A-B` 这类**启动就会报错**——shell 的 `export` 认不了这种名字，发下去只会收到 `not a valid identifier`、变量静默不生效。

**值按 shell 双引号里的写法落地。** 工具把每个值包成双引号下发，由目标节点在导入时就地处理：

- `$` 会被展开——`PATH = "/opt/bin:$PATH"` 就是在目标机原来的 `PATH` 前面加一段；要**字面**的 `$`，写 `\$`
- 空格、中文照原样送过去，不必自己加引号
- 值以 `\` 结尾会在**启动时报错**（那个反斜杠会吃掉下发串的收尾引号）
- 展开用的是**目标机非交互会话**那份环境，不是登录之后的环境（那份 `PATH` 常常只有 `/usr/bin:/bin`）——想让一批机器的结果形态一致，就把目录写全，别用 `$PATH`

**与 `--no-shell` 的关系**：`--no-shell` 是「原样下发」，那一次**不读这份配置**，也不套外壳。

> 注意：`--sudo` 时这些变量在 `sudo` **之前**导入，能不能穿过 sudo 取决于目标机的 sudoers（多数发行版保留 `LC_*`；`PATH` 则由 sudo 的 `secure_path` 决定）。依赖某个变量在 root 下也生效时，先确认目标机的 sudo 配置。

## 7 解释器

`[interpreter]` 表：管**命令模式（`-c`）与脚本模式（`-s`）用什么解释器跑**。上传 / 下载 / 改密不受它影响——那几类执行的命令另有固定形态。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `interpreter.command` | `"bash"` | 命令模式（`-c`）用的解释器 |
| `interpreter.script` | 见下 | 脚本模式（`-s`）：后缀 = 解释器，一行一种 |

`config/SSHFleet.conf` 的 `[interpreter.script]` 是"后缀 → 解释器"的映射，随包默认两条：

```toml
[interpreter.script]
".sh" = "bash"               # .sh 脚本用 bash 跑
".py" = "python3"            # .py 脚本用 python3 跑
```

- **加一种后缀**：自己加一行，如 `".pl" = "perl"`、`".rb" = "ruby"`、`".py3" = "python3"`。后缀要带点，比较时忽略大小写。
- **后缀怎么对**：只看文件名**最后一段**扩展名——`a.tar.sh` 按 `.sh` 那一条走。`.SH` 与 `.sh` 算同一个后缀（两条都配会被判重复）。
- **换解释器**：改等号右边那格。目标机只有 Python 2，就把 `".py" = "python3"` 改成 `".py" = "python2"`：

  ```toml
  [interpreter.script]
  ".sh" = "bash"
  ".py" = "python2"
  ```
- **后缀没配到的脚本**（如 `.bin`）：开跑前问一句"继续用 `bash` 吗"，同意才跑、不同意就退出。不想每次被问就加进这张表；加了 `--yes` 则跳过这一问，直接按回退解释器跑。

**值写什么**：写**名字**（`bash`、`python3`）最常见；写**绝对路径**（`/usr/local/bin/python3`）也行。工具把这段字符原样交给目标机，能不能跑取决于目标机的环境变量——**目标机报「找不到某某命令」时，就是 PATH 里没有它，改成绝对路径即可**。

把 `".sh"` 配成 `sh`（或 `dash`、`ash`、`mksh`）也照常工作：这类 shell 跑脚本时，工具仍会把脚本文件名交回去（脚本里的 `$0`），靠自身文件名取信息的脚本不受影响（为什么 → [4 进阶知识手册](4-进阶知识手册.md) 的「1 命令在远端是怎么执行的」）。

**几条检查**：命令模式项不能空；`[interpreter.script]` 至少一条，且每条的后缀与解释器都不能空、后缀不能重复（一个后缀只能配一个解释器）。

**与 `-a` 代填的关系**：`-a` 要把命令 / 脚本正文当「一段程序文本」交给解释器，各家的启动参数不同——shell 家族与 `python` 是 `-c`，`perl` / `ruby` / `node` / `nodejs` / `lua` / `luajit` 是 `-e`，`php` 是 `-r`，工具按解释器自动适配。把映射配成**范围外**的解释器（如 `tclsh`），一旦用了 `-a` 会在开跑前报错并列出支持范围；不用 `-a` 则不受影响。

**与 `--no-shell` 的关系**：`--no-shell`（不套工具那层外壳）是"原样下发"，命令直接交给目标节点的默认解释器——这时 `[interpreter]` 的配置**不参与执行**。两者一起用时，参数确认屏的「解释器」一行会提示「原样下发，本次不生效」；配置是 `bash` 时与默认行为一致，不提示。

## 8 改密配置

`--change-password` 要认的文字在另一份文件里（`config/keywords_passwd.conf`，随发布包提供，别删），两类：

| 段 | 用途 |
| --- | --- |
| `[[step]]` | 提示词表：哪段文字是提问 → 该喂哪个值 |
| `[[category]]` | 失败分类：改密失败时按远端说的原话归类 |

**值不在里面配**：当前密码取清单里那台机器自己的登录密码，新密码取 `--change-password` 的参数。

`config/keywords_passwd.conf`（随发布包提供，别删）：

```toml
[[step]]
keywords = ['当前的密码', 'Current password', '(current) UNIX password']
value = 'current'   # current = 清单里的登录密码；new = --change-password 的新密码
max = 1             # 这条最多喂几次

[[step]]
keywords = ['新的密码', 'New password']
value = 'new'
max = 4             # 弱密码会被 PAM 拒并重问，留几次余量

[[category]]
name = '新密码不合规'
keywords = ['BAD PASSWORD', '密码未被更改']
tip = '目标机的密码规则拒了新密码'
```

一份提示一条 `[[step]]`，顺序即提问顺序。**撞到没见过的措辞**（目标机语言不同、PAM 版本不同）就往对应那条的 `keywords` 里补一段，不用等发版——改动即时生效，没有缓存。

`[[category]]` 的写法与 `keywords_error.conf` 里的一样（`name` / `keywords` / `tip`，关键词可用 `*` 通配）。改密失败时，工具拿远端报错里的话来比这几张表，**自上而下先命中的算数**——所以更具体的原因写在前面。

字段缺一即报错（比如一条 `[[step]]` 都没有，启动就拦下），匹配口径（正则 / 大小写）跟着上面的 `[interactive]` 走。什么时候开始填也不在这份文件里配——它看 `keywords_error.conf` 里「密码过期」那几个关键词。

## 9 上传并发

`[upload]` 表：按上传总大小决定并发数，避免小文件被拖慢上传效率、大文件把服务器网络带宽压垮。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `upload.small_file` | `2097152` | 上传总大小小于它（字节）= 全量并发 |
| `upload.large_file` | `20971520` | 上传总大小大于它 = 串行上传 |
| `upload.medium_parallel` | `10` | 介于两者之间时用的并发数 |

两个阈值是**字节**：`2097152` = 2 MB，`20971520` = 20 MB。要按自己的带宽和网络调，就在 `config/SSHFleet.conf` 的 `[upload]` 段里照同一单位改：

```toml
[upload]
small_file = 5242880      # 5 MB 以下都全量并发
large_file = 52428800     # 50 MB 以上才串行
medium_parallel = 20      # 中间档一次 20 台
```

工具按本批**上传总大小**算出一档并发数，在参数屏之后给建议（不超过节点数、与当前值相同就不问），采纳与否你自己定。
