# 6 示例

这一册里的东西**都可以直接抄**，只需要把 IP、用户名、密码换掉。

> [!IMPORTANT]
> 下面所有的 IP 都是文档保留地址（`192.0.2.x` 是"示例专用"网段），**照抄跑不通**。请替换成你自己的服务器。

---

## 示例 1：一条命令，单台

不建任何文件，改完配置里的登录用户、端口、密码三项就能跑：

```bash
SSHFleet -f 192.0.2.10 -c "uptime"
```

## 示例 2：一份最小清单

`nodes.csv`：

# 机房 A

192.0.2.12

只写 IP，其余全从配置取。执行：

```bash
SSHFleet -f nodes.csv -c "df -h"
```

## 示例 3：每台密码不同

`nodes.csv`：

```csv
# IP, 端口, 用户名, 密码
192.0.2.10,,,AlphaPassw0rd
192.0.2.11,,,BravoPassw0rd
192.0.2.12,,,CharliePassw0rd
```

端口和用户名留空（逗号不能少），用配置里的默认值；密码逐台给。

> 如果打开了加密，第 4 列要改成每个密码文件的**本机绝对路径**，见 [3 进阶配置手册](3-进阶配置手册.md)。

## 示例 4：六列全写（全批用密钥）

`nodes.csv`：

```csv
# IP, 端口, 用户名, 密码, 私钥路径, 私钥口令
192.0.2.10,22,root,,/home/ops/.keys/id_rsa,
192.0.2.11,2222,deploy,,/home/ops/.keys/id_rsa,
192.0.2.12,22,root,,/home/ops/.keys/id_rsa,vaultPassw0rd
```

```bash
SSHFleet -f nodes.csv -c "uptime" -k
```

**用密钥是一次执行统一决定的**：加了 `-k`，这一次所有节点都走密钥登录，所以每一台都得有私钥。`192.0.2.12` 的私钥带口令，所以在第 6 列给它。

只想用密码时，把 `-k` 去掉——**连同第 5 列一起不生效**。

> 第 5 列可以写成短名字（如 `id_rsa`），会拼到配置里的凭据目录下；写绝对路径则原样使用。见 [1 使用手册](1-使用手册.md)。

## 示例 5：脚本

`deploy.sh`：

```bash
#!/bin/bash
APP_DIR=/opt/myapp
BACKUP_DIR=/opt/backup

echo "[$(hostname)] 开始部署"

# 备份旧版本
if [ -d "$APP_DIR" ]; then
    mkdir -p "$BACKUP_DIR"
    tar -czf "$BACKUP_DIR/app-$(date +%Y%m%d-%H%M%S).tar.gz" -C "$APP_DIR" . \
        && echo "旧版本已备份"
fi

# 解压新版本
mkdir -p "$APP_DIR"
tar -xzf /tmp/myapp.tar.gz -C "$APP_DIR" && echo "新版本已解压"

# 重启服务
systemctl restart myapp && echo "服务已重启"

echo "[$(hostname)] 部署完成"
```

执行（需要 root 权限）：

```bash
SSHFleet -f nodes.csv -s deploy.sh --sudo -r 部署v2
```

**默认支持 `.sh` 和 `.py`**（用什么解释器按后缀取配置，可自行扩展，见 [3 进阶配置手册](3-进阶配置手册.md)）。不需要 `chmod +x`——工具会自己处理。

## 示例 6：脚本在远端提问（代填）

安装脚本常会停下来等你选——架构、包格式、要不要覆盖。批量执行时没人去按回车，用 `-a` 把答案预先写下来。

`install.sh` 里会问：

```bash
请选择架构：
1) x86_64
2) arm64
read arch

请选择包格式 (deb/rpm):
read fmt
```

这样执行（两条代填用 `\n` 分隔，**一行一条、格式与 CSV 清单完全相同**）：

```bash
SSHFleet -f nodes.csv -s install.sh -a "1,请选择架构\ndeb,请选择包格式"
```

一行里逗号分段：**第 1 段是填进去的内容**（`1`、`deb`——就是你手敲时会敲的那串，工具替你补回车），**第 2 段起是触发词**（看到它就填）。触发词不用抄整句，**从上面脚本打印的提示里原样抄一段**就行：脚本打印 `请选择架构：`，你写 `请选择架构` 就能认出来。要写进内容或触发词里的逗号，用双引号包住那一列。多条代填**并行**匹配——谁的触发词先出现就先用谁。

条数多的时候写成文件更省事（`answer.csv`，一行一条，空行与 `#` 开头会被跳过）：

```csv
# 第 1 列填进去的值,触发词,触发词
1,请选择架构
deb,请选择包格式
```

```bash
SSHFleet -f nodes.csv -s install.sh -a answer.csv
```

收尾时看统计块：出现「触发词未命中」说明有机器上脚本问的话没认出来（触发词要按**目标机的提示语言**写）——脚本是顺序提问的，报出来的序号里**最小的那个就是第一个出错点**；出现「代填用尽后超时」说明填完它还在等。**密码过期**的机器在会话一开始就会被终止、单独归「密码过期」，不会白等到超时。细节见[1 使用手册](1-使用手册.md)的「4 代填 `-a`」。

## 示例 7：上传与下载

```bash
# 上传：把本地包分发到所有服务器的 /opt/ 下
SSHFleet -f nodes.csv -u ./myapp.tar.gz -p /opt/ --sudo

# 上传整个目录（保留内部层级，目录自身那一层不重复）
SSHFleet -f nodes.csv -u ./configs/ -p /opt/myapp/

# 下载：把所有服务器的日志收集到本地
SSHFleet -f nodes.csv -d /opt/myapp/logs/app.log -p ./downloads

# 下载整个日志目录
SSHFleet -f nodes.csv -d /opt/myapp/logs -p ./downloads
```

上传的三条硬要求：`-p` 是**绝对路径**、**以 `/` 结尾**、**远端目录必须已存在**。另外**远端已有同名文件时不覆盖**——传到它就停，那台机器按失败计，要覆盖先清掉旧文件（详见[1 使用手册](1-使用手册.md)）。

下载两条：`-d` 是绝对的**远端**路径，`-p` 是**本机已存在的目录**（工具不会替你建），下来之后每台服务器各占一个以 IP 命名的子目录。

## 示例 8：定时任务

不要任何确认，直接跑（`crontab` 里只能这样）：

```bash
SSHFleet -f nodes.csv -c "systemctl status myapp" --yes -r 巡检
```

加了 `--yes` 之后：

- **参数屏与确认全部跳过**，直接开始执行
- 危险命令：`禁止` 级仍然拒绝；其余级别放行，但会在工具日志里留一条记录

（清单或配置里缺东西一律**报错退出**，密码、端口、用户名要提前备好。）

配合 `-k` 与带口令的私钥也能跑：口令写在清单或配置里。

## 示例 9：一套能跑的最小组合

发布包里的配置文件**已经带着全部字段**，你要改的是基础配置 `[account]` 段里的三项：

```toml
[account]
user     = "jx_zyc"     # 改成你的登录用户名
port     = 10022        # 改成你的 SSH 端口
password = "C:/Users/Administrator/.MyPW/SSHFleet_pw"   # 发布包给的是凭据文件的本机绝对路径，改成你自己的
```

**`password` 这一项跟着加密开关走**——发布包默认开着加密（`credential.encrypt = true`），所以它给的是凭据文件的本机绝对路径：

- **不想用加密**：把 `[credential]` 段的 `encrypt` 改成 `false`，`password` 直接写密码字符串
- **要用加密**：先按 [3 进阶配置手册](3-进阶配置手册.md) 生成主密钥、转换凭据文件，再把 `password` 改成你自己凭据文件的本机绝对路径

```csv
# nodes.csv
192.0.2.10
192.0.2.11
```

```bash
SSHFleet -f nodes.csv -c "uptime"
```

## 示例 10：一批机器的密码过期了

先按原样跑一次，看统计块里哪些机器归了「密码过期」——那几台的密码已经到期，工具登得进去但执行不了命令。把这些机器单独写一份清单，跑改密：

```bash
SSHFleet -f expired.csv --change-password "NewPass2026!"
```

不用配触发词：工具认得远端的「当前的密码」「新的密码」「重新输入」，按顺序把清单里的登录密码和新密码喂进去，喂完自己收尾。

- 新密码怎么给看配置里的 `credential.encrypt`：不开加密直接写明文（如上），开了加密写密文文件的本机绝对路径
- **密码没过期的机器不会被改**，它们单独归一类「密码未过期」并计入失败数——所以清单只放要改的那几台最省事
- 撞到没见过的提示措辞（目标机是别的语言）就去 `config/keywords_passwd.conf` 的 `[[step]]` 补一段；失败分类（按远端原话归的那几类）也在同一个文件的 `[[category]]` 里

跑完统计块大致长这样：

```text
  总耗时：3.12 秒
  节点总数： 10  完成总数：10
  成功： 8    失败： 2
  失败分类统计 >>>  密码未过期 ×1   新密码不合规 ×1
```

失败的几类各是什么意思：

- **密码未过期**：这台的密码没到期，工具没动它——清单里只放要改的机器就不会出现
- **新密码不合规**：目标机的密码规则把新密码拒了（太短、太简单、与旧密码太像…），换一个复杂些的再来
- **写不进密码文件**：目标机写不进 `/etc/shadow`——磁盘满、根分区只读、账号被锁定都可能，得去那台机器上查
- **改密未完成**：远端没说出原因（只反复重问，或收下密码后一直不吭声），去目标机上确认一下新密码是不是不符合它的规则
