# 配置手册

工具的所有行为由 `config/SSHFleet.conf` 决定。文件在发布包里自带，**把基础配置改成你自己的信息就能跑**。

文件里分三部分，用横幅式注释标题隔开：

- **基础配置**——登录用户、端口、密码、执行身份、超时
- **凭据**——加密开关与密钥路径
- **进阶配置**——输出开关、交互代填、解释器、改密、上传并发

三部分的字段都必须写出来，一个都不能缺——缺任何一个，工具会拒绝启动并点名是哪个。

多写一个不存在的字段，工具同样会拒绝启动并列出名字——拼错的字段不会静默失效。

---

## 基础配置

（下面是基础配置的节选；凭据与进阶配置的字段在同一个文件里，不要删）：

```toml
# ════════════════════════ 基础配置 ════════════════════════

# 账号
[account]
user     = "jx_zyc"       # 登录用户名
port     = 10022          # SSH 端口
password = "C:/Users/Administrator/.MyPW/SSHFleet_pw"  # 凭据文件的本机绝对路径（随包默认开着加密；不加密时这里直接写密码字符串）

# 执行参数
[execution]
sudo             = true   # root 身份执行；false 用登录用户
timeout_connect  = 10     # 连接超时（秒）
timeout_execute  = 60     # 命令/脚本超时（秒）
timeout_transfer = 300    # 上传下载超时（秒）
```

### user

改成你的登录用户名。清单里没写用户名的机器，都用这个。

### port

改成你的 SSH 端口。清单里没写端口的机器，都用这个。

### password

随包配置默认开着加密，这一项给的是**凭据文件的本机绝对路径**；把 `credential.encrypt` 改成 `false` 后，这里改成**直接写密码本身**。清单里没写密码的机器，都用这个。

> 这个字段的含义由 `encrypt` 决定，两种写法见 [加密与密钥](加密与密钥.md)。

### sudo

`true` 用 root 身份执行（相当于命令前加了 `sudo`），`false` 用登录用户身份。

一次执行想临时改回来，用 `--sudo` / `--no-sudo` 覆盖。

**前提：目标节点上这个登录账号得已配免密 sudo（`NOPASSWD`）。** 工具只发 `sudo <命令>`，不会也无法替你输入 sudo 密码。典型配法是在目标机 `/etc/sudoers.d/` 下放一行 `用户名 ALL=(ALL) NOPASSWD:ALL`（权限 `440`）。没配的话命令会停在 `sudo: a password is required`，按执行失败计。

> 注意：下载时文件的读取仍以登录用户身份进行，下载文件不支持 root 身份下载，root-only 的文件（如权限 `700`）下载会失败——先用 sudo 命令模式把文件搬到登录用户可读的位置，再下载。

### env

命令行下发前，工具会先在远端导入这组环境变量——一行一个，写成 `名字 = "值"`。出厂给了四条：

| 名字 | 值 | 作用 |
| --- | --- | --- |
| `LANG` / `LC_ALL` | `en_US.UTF-8` | 统一字符集与排序 |
| `PATH` | 一组标准目录 | 补上 `sudo` / `python3` 所在目录 |
| `TERM` | `dumb` | 统一成哑终端，抑制彩色与转义序列 |

**为什么要设它们。** SSH 非交互会话拿到的是目标机自己的默认环境，各机器不一样：locale 不同会让同一条命令在一台机器上输出正常中文、在另一台变成乱码，排序与数字格式也会跟着变——于是「同一批机器跑同一条命令」的输出**没法逐字比对**，报告里的失败分类也可能失准；`PATH` 则常常只剩 `/usr/bin:/bin`，而 `sudo` 在 `/usr/sbin`、`python3` 常在 `/usr/local/bin`，不补就是 `command not found`。工具把这两样统一起来，为的就是让一批机器的结果形态一致。

**怎么改。**

- **加一条**：照 `MY_VAR = "值"` 的写法往下加一行。常用的还有 `DEBIAN_FRONTEND = "noninteractive"`（apt / dpkg 不弹交互）、`PYTHONIOENCODING = "utf-8"`（python 输出固定 UTF-8）、`TZ = "Asia/Shanghai"`（统一时区，脚本里的时间戳才可比）。
- **临时关掉一条**：把它的**值留空**（如 `LC_ALL = ""`），这一条就被当作不存在、不导入。
- **一条都不要**：`[execution.env]` 下不写任何条目即可——工具就完全不导入环境变量。

**名字有要求**：必须是合法 shell 变量名（字母或下划线开头，后接字母、数字、下划线）。写 `123`、`A-B` 这类**启动就会报错**——shell 的 `export` 认不了这种名字，发下去只会收到 `not a valid identifier`、变量静默不生效。

**值按 shell 双引号里的写法落地。** 工具把每个值包成双引号下发，由目标节点在导入时就地处理：

- `$` 会被展开——`PATH = "/opt/bin:$PATH"` 就是在目标机原来的 `PATH` 前面加一段；要**字面**的 `$`，写 `\$`
- 空格、中文照原样送过去，不必自己加引号
- 值以 `\` 结尾会在**启动时报错**（那个反斜杠会吃掉下发串的收尾引号）
- 展开用的是**目标机非交互会话**那份环境，不是登录之后的环境（那份 `PATH` 常常只有 `/usr/bin:/bin`）——想让一批机器的结果形态一致，就把目录写全，别用 `$PATH`

**与 `--no-shell` 的关系**：`--no-shell` 是「原样下发」，那一次**不读这份配置**，也不套外壳。

> 注意：`--sudo` 时这些变量在 `sudo` **之前**导入，能不能穿过 sudo 取决于目标机的 sudoers（多数发行版保留 `LC_*`；`PATH` 则由 sudo 的 `secure_path` 决定）。依赖某个变量在 root 下也生效时，先确认目标机的 sudo 配置。

### 三个超时

单位都是秒。`timeout_connect` 管建连，`timeout_execute` 管命令与脚本，`timeout_transfer` 管上传下载。默认值通常够用，网络慢或目标机响应慢时再调大。

## 凭据

`[credential]` 表：加密开关与密钥路径。`encrypt` 同时决定 `password`、`key_password` 与清单第 4、6 列的含义——不加密时那几个位置填的是密码/口令本身，加密时填的是文件的本机绝对路径。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `credential.encrypt` | `false` | 是否加密存放密码与口令。`false` = 明文，`true` = 加密（需要主密钥，见 [加密与密钥](加密与密钥.md)） |
| `credential.key` | `""` | 统一私钥的本机绝对路径。所有机器共用一把私钥时填这里；某台要用别的密钥，在清单第 5 列写它的路径（为随时加 `-k` 备着） |
| `credential.key_password` | `""` | 私钥口令。不加密时填口令明文，加密时填口令文件的本机绝对路径。某台机器口令不同，在清单第 6 列覆盖 |
| `credential.secret_dir` | `""` | 凭据目录。**只对清单里的相对路径生效**——清单第 5 列若写 `id_rsa` 这样的短名字，会拼到这个目录下。写空则清单里必须用绝对路径 |

## 进阶配置

以下是进阶配置的字段。它们和基础配置的字段一样都必须写出来、一个都不能缺。

### 输出开关

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enable.output_to_xlsx` | `true` | 终端输出是否同时导出 Excel。`false` = 只留文本 |
| `enable.results_to_xlsx` | `true` | 结果明细是否导出 Excel。`false` = 不产出这个文件 |
| `enable.show_category_tips` | `true` | 统计末尾是否显示"提示："块（解释本次出现过的失败分类可能是什么原因） |

### 交互代填

管 `-a` 代填与 `--change-password` 改密的匹配口径。整段落名就叫 `[interactive]`，两个开关同时管代填的触发词与中止词、改密的提示词与入场信号。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `interactive.regex` | `false` | 触发词按子串包含匹配；`true` = 按正则匹配 |
| `interactive.case_sensitive` | `false` | 不区分大小写；`true` = 区分 |

默认的两项（子串、不区分大小写）与失败分类的判据口径一致。打开正则后触发词按正则解释，写法不对会在执行前报错。

### 解释器

管**命令模式（`-c`）与脚本模式（`-s`）用什么解释器跑**。整段落名就叫 `[interpreter]`。上传 / 下载 / 改密不受它影响——那几类执行的命令另有固定形态。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `interpreter.command` | `"bash"` | 命令模式（`-c`）用的解释器 |
| `interpreter.script` | 见下 | 脚本模式（`-s`）：后缀 = 解释器，一行一种 |

`[interpreter.script]` 是"后缀 → 解释器"的映射，随包默认两条：

```toml
[interpreter.script]
".sh" = "bash"
".py" = "python3"
```

- **加一种后缀**：自己加一行，如 `".pl" = "perl"`、`".rb" = "ruby"`、`".py3" = "python3"`。后缀要带点，比较时忽略大小写。
- **后缀怎么对**：只看文件名**最后一段**扩展名——`a.tar.sh` 按 `.sh` 那一条走。比较忽略大小写，`.SH` 与 `.sh` 算同一个后缀（两条都配会被判重复）。
- **换解释器**：改等号右边那格——比如目标机只有 Python 2，就把 `".py" = "python3"` 改成 `".py" = "python2"`。
- **后缀没配到的脚本**（如 `.bin`）：工具会在开跑前问一句"继续用 `bash` 吗"，同意才跑、不同意就退出。不想每次都被问，就把它加进这张表；加了 `--yes` 则跳过这问，直接按回退解释器跑。

**值写什么**：写**名字**（`bash`、`python3`）是最常见的写法；写**绝对路径**（`/usr/local/bin/python3`）也行。工具把这段字符原样交给目标机，能不能跑取决于目标机的环境变量——**目标机报「找不到某某命令」时，就是 PATH 里没有它，改成绝对路径即可**。

把 `".sh"` 配成 `sh`（或 `dash`、`ash`、`mksh`）也照常工作：这类 shell 跑脚本时，工具仍会把脚本文件名交回去（脚本里的 `$0`），靠自身文件名取信息的脚本不受影响。

**几条检查**：命令模式项不能空；`[interpreter.script]` 至少一条，且每条的后缀与解释器都不能空、后缀不能重复（一个后缀只能配一个解释器）。

**与 `-a` 代填的关系**：`-a` 要把命令 / 脚本正文当「一段程序文本」交给解释器，各家的启动参数不同——shell 家族与 `python` 是 `-c`，`perl` / `ruby` / `node` / `nodejs` / `lua` / `luajit` 是 `-e`，`php` 是 `-r`，工具按解释器自动适配。若把映射配成**范围外**的解释器（如 `tclsh`），一旦用了 `-a` 会在开跑前报错并列出支持范围；不用 `-a` 则不受影响（这部分属于进阶配置知识，不明白没关系，不必在意）。

**与 `--no-shell` 的关系**：`--no-shell`（不套工具那层外壳）是"原样下发"，命令直接交给目标节点的默认解释器——这时 `[interpreter]` 的配置**不参与执行**。两者一起用时，参数确认屏的「解释器」一行会提示「原样下发，本次不生效」；配置是 `bash` 时与默认行为一致，不提示。

### 改密配置

`--change-password` 要认的文字都在这份文件里（`config/keywords_passwd.conf`，随发布包提供，别删），两类：

| 段 | 用途 |
| --- | --- |
| `[[step]]` | 提示词表：哪段文字是提问 → 该喂哪个值 |
| `[[category]]` | 失败分类：改密失败时按远端说的原话归类 |

**值不在里面配**：当前密码取清单里那台机器自己的登录密码，新密码取 `--change-password` 的参数。

```toml
[[step]]
keywords = ['当前的密码', 'Current password', '(current) UNIX password']
value = 'current'   # current = 清单里的登录密码；new = --change-password 的新密码
max = 1             # 这条最多喂几次

[[step]]
keywords = ['新的密码', 'New password']
value = 'new'
max = 4             # 弱密码会被 PAM 拒并重问，留几次余量

[[category]]
name = '新密码不合规'
keywords = ['BAD PASSWORD', '密码未被更改']
tip = '目标机的密码规则拒了新密码'
```

一份提示一条 `[[step]]`，顺序即提问顺序。**撞到没见过的措辞**（目标机语言不同、PAM 版本不同）就往对应那条的 `keywords` 里补一段，不用等发版。改动即时生效，没有缓存。

`[[category]]` 的写法与 `keywords_error.conf` 里的一样（`name` / `keywords` / `tip`，关键词可用 `*` 通配）。改密失败时，工具拿远端报错里的话来比这几张表，**自上而下先命中的算数**——所以更具体的原因写在前面。

字段缺一即报错（比如一条 `[[step]]` 都没有，启动就拦下），匹配口径（正则 / 大小写）跟着上面的 `[interactive]` 走。什么时候开始填也不在这份文件里配——它看 `keywords_error.conf` 里「密码过期」那几个关键词。

### 上传并发

按上传总大小决定并发数，避免小文件被拖慢上传效率、大文件把服务器网络带宽压垮。整段落名就叫 `[upload]`。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `upload.small_file` | `2097152` | 上传总大小小于它（字节）= 全量并发 |
| `upload.large_file` | `20971520` | 上传总大小大于它 = 串行上传 |
| `upload.medium_parallel` | `10` | 介于两者之间时用的并发数 |

## 路径怎么写

配置里的凭据路径（`password` 打开加密时的值、`key`、`key_password`、`secret_dir`）一律写**本机绝对路径**——跑工具的那台机器要能直接打开它：

| 本机是 | 这样写 | 这样写会被拦下 |
| --- | --- | --- |
| Windows | `secret_dir = "D:/Keys"`<br>`key = "D:\Keys\id_rsa"` | `/home/ops/.keys` |
| Linux | `secret_dir = "/home/ops/.keys"`<br>`key = "/home/ops/.keys/id_rsa"` | `C:/Keys` |

三条规则：

- **一律绝对路径**。相对路径只在清单里能用（拼 `secret_dir`），配置里不行。
- **分隔符写 `\` 或 `/` 都行**，Windows 上两种都能读；程序使用时统一按 `/` 处理，盘符大小写也一样处理，你不必操心。
- **不支持 `~`**。要写完整路径。

## 不在配置里的东西

产物的文件名与目录名（执行记录目录、日志名、终端输出名、报告名、结果表名、规则文件名等）**不开放配置**，由程序内置。

## 改错了会看到什么

| 现象 | 原因 |
| --- | --- |
| `配置缺少必填字段：account.port, ...` | 有字段没写——**基础配置和进阶配置的字段都不能缺**。报错会一次列全 |
| `配置包含未识别字段：account.pasword` | 字段名拼错了，或写了工具不接受的字段。报错会列出名字 |
| 提示 `credential.encrypt` 取值不对 | 它只能是 `true` 或 `false` |
| 提示某个路径字段取值有问题 | 写了相对路径 →「必须是绝对路径」；写了**另一边平台**的写法（Linux 上写 `C:/Keys`、Windows 上写 `/home/ops/.keys`）→「不是本机的绝对路径」；写了 `~` →「不支持 ~」 |
| 提示 `interpreter.command` 不能为空 | 命令模式没写解释器 |
| 提示 `interpreter.script` 的后缀/解释器为空、或后缀没带点、或后缀重复 | 脚本映射那几条写得不完整 |
| 提示 `-a 代填不支持解释器 "xxx"` | 开了 `-a`，但解释器不在支持范围（见上面的「解释器」一节） |
| 报错"这个位置没有配置文件" | 当前目录不对。报错里会给出当前目录与该放的位置，`cd` 到程序所在目录再执行 |
