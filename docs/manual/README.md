# SSHFleet

SSHFleet 是一个 **SSH 批量运维工具**：一次命令输入，派出一支"舰队"（fleet）——批量连接清单里的每一台服务器，执行命令、运行脚本、上传/下载文件，结果自动统计归档。

它**只有一个可执行文件**：Windows 一个 `SSHFleet.exe`、Linux 一个 `SSHFleet`——不需要 Python，也不需要额外准备任何引擎或运行时。

> [!WARNING]
> 该工具可能存在 BUG，请在测试环境验证后再用于生产。数据无价，操作前请再三思量。

## ① 这是什么，能干什么

### 1.1 定位

把「SSH 登录 → 执行 → 退出」这套逐台操作，变成「**一条命令操作清单里的所有服务器**」。你准备一份节点清单，告诉工具要做什么，剩下的并发、收集、统计、归档都交给工具。

### 1.2 能力

| 能力              | 说明                                                       |
| ----------------- | ---------------------------------------------------------- |
| 批量执行命令      | 一条命令跑遍清单里的所有服务器，实时看进度                 |
| 批量执行脚本      | 把本地 `.sh` / `.py` 脚本发到每台服务器执行                |
| 批量上传文件      | 本地文件/目录分发到每台服务器的指定位置                    |
| 批量下载文件      | 收集每台服务器的文件/目录，按 IP 分目录存到本地            |
| 危险命令防护      | 自动识别 `rm -rf /` 等危险命令，执行前提示风险并要求确认   |
| 密码 / 密钥双认证 | 密码登录与密钥登录，按一次执行统一选用                     |
| 结果自动归档      | 每次执行生成独立目录：终端输出（txt / Excel）、汇总报告、资源备份 |

## ② 安装

### 2.1 前置要求

| 项       | 要求                                 |
| -------- | ------------------------------------ |
| 操作系统 | Windows / Linux（均为 64 位）        |
| 运行时   | 无——不需要 Python、Node 或其它运行时 |
| 磁盘     | 约 20MB（可执行文件本身）            |

### 2.2 安装步骤

1. 取到对应平台的发布包：`SSHFleet_<打包时间>_windows.zip`（Windows）或 `SSHFleet_<打包时间>_linux.tar.gz`（Linux）。
2. 解压到任意目录（建议单独放一个目录，例如 `D:\Tools\SSHFleet`），会得到：

   ```text
   SSHFleet.exe                  # Windows（Linux 为无后缀的 SSHFleet）
   config/
   ├── SSHFleet.conf             # 配置文件——用之前按你的环境改这里
   ├── dangerous_keywords.conf   # 危险命令规则
   └── error_keywords.conf       # 错误分类关键词
   docs/                         # 手册（本文件、使用手册、配置手册、加密与密钥、常见问题、示例）
   ```

3. 修改 `config/SSHFleet.conf` 里的登录用户、SSH 端口、密码三项（都在基础段），详见 [配置手册](配置手册.md)。
4. **在解压出来的这个目录里**运行工具（它从**当前工作目录**读 `./config/SSHFleet.conf`）：

   ```bash
   # Windows（在解压目录打开终端）
   SSHFleet.exe

   # Linux
   ./SSHFleet
   ```

   不带任何参数会打印帮助。

> [!IMPORTANT]
> **关于配置文件**
>
> - **必须**和可执行文件放在同一个目录下：工具从当前工作目录读 `./config/SSHFleet.conf`。先 `cd` 到那个目录再执行，否则会报「配置文件不存在」。
> - 配置里**所有字段都必须写出来**（个别项的值可以留空）。工具不设任何隐藏默认值，缺字段或取值不合法会在启动时一次告诉你是哪几项。
> - 打开加密（`encrypt = true`）时，需要先有一个主密钥，详见 [加密与密钥](加密与密钥.md)。

> [!NOTE]
> 📖 **自行编译**（可选）
>
> 不自己编译可以跳过这段。源码在 `modules/SSHFleet_Go/`，需要 **Go 1.27+**，在工程目录下 `go build` 即可得到可执行文件。

## ③ 快速上手

这一章讲**整体怎么用**：从最快到最标准，先跑通一条命令。清单、密码、参数这些的完整说明在 [使用手册](使用手册.md)。

> 下面示例统一写 `SSHFleet`；Windows 下请写成 `SSHFleet.exe`。

### 3.1 最快路径：内联清单（不需要建任何文件）

`-f` 可以直接接一段服务器信息，最小写法只写 IP：

```bash
SSHFleet -f 192.168.1.10 -c "uptime"
```

回车后有一屏参数确认，确认后即可连接该服务器执行命令。端口、用户名、密码都从配置里取。

### 3.2 标准流程：一份清单，多条命令

一次要操作多台时，把服务器写成一份清单文件：

```bash
# 第 1 步：写清单（每行一台，只写 IP 即可）
#    nodes.csv:
#    192.168.1.10
#    192.168.1.11
#    192.168.1.12

# 第 2 步：执行
SSHFleet -f nodes.csv -c "uptime"
```

清单的六列分别是什么、某台要用不一样的端口或密码怎么写 → [使用手册](使用手册.md)。

### 3.3 常用场景示例

```bash
# 批量执行命令（看磁盘）
SSHFleet -f nodes.csv -c "df -h"

# 批量跑部署脚本（root 权限）
SSHFleet -f nodes.csv -s deploy.sh --sudo

# 分发文件到所有服务器（远端目录要已存在，且以 / 结尾）
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/

# 收集所有服务器的日志（按 IP 分目录存到本地）
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads

# 密钥登录（所有节点统一用配置里那把私钥）
SSHFleet -f nodes.csv -c "uptime" -k

# 不要任何确认（定时任务）
SSHFleet -f nodes.csv -s deploy.sh --yes
```

更多可照抄的场景 → [示例](示例.md)。

## ④ 核心概念

批量操作时你会接触到三样东西：**节点清单**、**密码**、**配置默认值**。这一章讲清它们，⑤ 再讲四种模式怎么选。

### 4.1 节点清单

清单是一份纯文本，**每行一台服务器**，英文逗号分隔，可以用记事本 / VSCode 编辑。空行会被跳过；以 `#` 开头的行会被当作注释跳过。

```csv
# 生产环境
192.168.1.10
192.168.1.11
192.168.1.12
```

**只写 IP 就够了**——端口、用户名、密码都从配置里取。想让某台用别的值，往后接着写；最多六列，依次是 IP、端口、用户名、密码、私钥路径、私钥口令。

`-f` 除了接文件路径，也能直接接一串服务器信息（内联清单），写法与那六列一一对应：

```bash
SSHFleet -f "192.168.1.10,22,root,你的密码" -c "uptime"
```

六列的取值规则、每台不同的写法、各列留空时的取值顺序 → [使用手册](使用手册.md)。

### 4.2 密码与加密

默认（不加密）时，密码**直接写在配置里或清单第 4 列**，一眼能看出是什么意思。

清单文件常被复制、分享、留存或进版本库——**如果不放心，就把加密打开**：打开之后，那几个位置改成填"密码文件的绝对路径"，磁盘上只有密文，解密要一把单独存放的主密钥。

加密怎么开、主密钥怎么管 → [加密与密钥](加密与密钥.md)。

### 4.3 配置默认值与路径

配置文件是 `config/SSHFleet.conf`，提供清单留空字段的默认值。它分两档排：**基础段**是你入门就该配的（登录用户、端口、密码、执行身份、超时），**进阶段**是进阶才动的。

**两档的字段都必须写出来**，缺一个工具会拒绝启动；分档只是让你一眼看出哪些是入门就要配的、哪些是进阶才动的。

默认取值的优先级：**命令行 > 清单 > 配置文件**。配置里的凭据路径要写绝对路径，分隔符 `\` 或 `/` 都行（程序会统一处理）。

每个字段的完整说明、路径怎么写 → [配置手册](配置手册.md)。

## ⑤ 四种模式与参数

### 5.1 四种模式

四种操作模式，**每次只能选一种**：

| 模式 | 参数                      | 作用                   | 示例                                  |
| ---- | ------------------------- | ---------------------- | ------------------------------------- |
| 命令 | `-c "命令"`               | 每台服务器执行一条命令 | `-c "df -h"`                          |
| 脚本 | `-s 脚本文件`             | 上传本地脚本并执行     | `-s deploy.sh`                        |
| 上传 | `-u 本地路径 -p 远端目录` | 分发文件/目录到服务器  | `-u ./app.tar.gz -p /opt/`            |
| 下载 | `-d 远端路径 -p 本地目录` | 收集服务器文件/目录    | `-d /opt/logs/app.log -p ./downloads` |

```bash
SSHFleet -f nodes.csv -c "df -h"
SSHFleet -f nodes.csv -s deploy.sh
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads
```

> [!IMPORTANT]
> **上传 / 下载的硬性约定**
>
> - `-p` 是"目标路径"：上传的目标在服务器，下载的目标在本地。上传时必须写**绝对路径且以 `/` 结尾**（如 `/opt/app/`）；下载时必须是一个**已经存在**的本地目录。
> - 上传时**远端目录必须已经存在**——工具不会替你创建目录。写错路径时会在那一台上直接报「远端路径不存在」并跳过该节点，而不是在错的地方悄悄建出一个目录。
> - 上传目录时**保留内部的子目录层级**，但**目录自身那一层不会重复出现**——`-u /本地/abc -p /opt/` 得到的是 `/opt/<abc 的内容>`。想要 `/opt/abc/…` 这种结果，把 `abc` 的**父目录**传上去。
> - **不支持也不需要通配符**：`-u` 只接收一个路径。写成 `-u /本地/abc/*` 会被终端展开成多个参数，工具会直接报「出现多余的参数」并列出未被使用的那些。
> - **软链接一律不上传、不下载**：源里的软链接（含 Windows 目录联接、`.lnk` 快捷方式）会被**跳过**，不中断执行，被跳过的条目写进该节点的结果明细。只有**过滤后一个可传文件都不剩**才报错。

### 5.2 参数总表

每个参数都有等价的**长选项**（`-c` / `--command`、`-f` / `--csv-file`、`-T` / `--connect-timeout` …）——长选项更适合写在脚本里，程序 `--help` 里成对列出。

批量执行的用法：

```text
SSHFleet ( -c | -s | -u | -d ) ( -f ) ( -p ) [其他可选参数]   批量执行（四种模式四选一）
```

单独使用的密钥管理命令（不跟批量执行一起用）：

```text
SSHFleet --gen-key
SSHFleet --key-status
SSHFleet --convert-secret 文件路径
```

**模式参数（四选一）**

| 参数          | 说明                                          |
| ------------- | --------------------------------------------- |
| `-c "命令"`   | 命令模式：在每台服务器执行一条命令            |
| `-s 脚本文件` | 脚本模式：上传本地脚本并执行（`.sh` / `.py`） |
| `-u 本地路径` | 上传模式：把本地文件/目录传到服务器（需 `-p`） |
| `-d 远端路径` | 下载模式：从服务器下载文件/目录到本地（需 `-p`） |

**其他参数**

| 参数           | 说明                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| `-f csv_file`  | 节点清单：CSV 文件路径，或内联的一段服务器信息（四种模式都必须带）                     |
| `-p path`      | 目标路径（上传/下载必带，方向见上）                                                   |
| `-k` / `--key` | 这次用密钥登录（不加 = 用密码）                                                       |
| `--sudo`       | 用 root 身份执行（配置里的默认执行身份见 [配置手册](配置手册.md)）                      |
| `--no-sudo`    | 用登录用户身份执行                                                                    |
| `-t timeout`   | 单台执行/传输超时（秒）；默认取配置：执行用 `timeout_execute`、传输用 `timeout_transfer` |
| `-T timeout`   | 连接每台服务器的超时（秒）；默认取配置 `timeout_connect`                              |
| `-n number`    | 并发数：同时操作几台服务器；不填默认全部并行                                          |
| `-r remark`    | 任务备注，作为历史记录文件夹的后缀（不填自动生成）                                    |
| `--no-bash`    | 命令模式专用：不套一层 bash 环境，直接执行原始命令                                    |
| `--yes`        | 跳过确认，直接执行（定时任务常用）                                                    |

**密钥管理（单独使用）**

| 参数                      | 说明                                                      |
| ------------------------- | --------------------------------------------------------- |
| `--gen-key`               | 生成主密钥并持久化到系统环境变量（打开加密前用一次）      |
| `--key-status`            | 查看主密钥状态：读到哪把、已存哪把、是否一致、下一步怎么办 |
| `--convert-secret 文件` | 转换凭据文件：把明文或已加密的内容转成当前该有的格式      |

每个参数的完整行为、各模式的具体要求 → [使用手册](使用手册.md)。

## ⑥ 进阶用法

### 6.1 密钥登录

工具默认用密码登录。要用密钥，加 `-k`：

```bash
SSHFleet -f nodes.csv -c "uptime" -k
```

私钥从清单第 5 列取，那颗没写就取配置里的 `key`。**密钥登录就是密钥登录**——私钥不行就这一台失败，不会再拿密码去试一次。

私钥带口令时，口令写在清单第 6 列或配置里。完整的规则（包括"配了私钥却忘了加 `-k`"会怎样）→ [使用手册](使用手册.md)。

### 6.2 提权 / 并发 / 超时 / 不要确认

```bash
# root 身份执行
SSHFleet -f nodes.csv -c "systemctl restart nginx" --sudo

# 限流（默认全部并行）
SSHFleet -f nodes.csv -c "uptime" -n 10

# 控制超时：-T 连接、-t 执行或传输
SSHFleet -f nodes.csv -c "uptime" -T 15 -t 60

# 跳过所有确认
SSHFleet -f nodes.csv -s deploy.sh --yes
```

**危险命令防护**：执行前工具会分析命令内容（命令模式分析 `-c`，脚本模式分析脚本全文），命中规则时列出每一条——来源、行号、内容、规则、级别。**禁止级**直接拒绝执行并退出；其余级别需要你确认一次。规则写在 `config/dangerous_keywords.conf` 里，不想被某条打扰就把它改成 `enabled = false`，或用 `#` 注释掉。

> 脚本会经语法解析后逐条分析（含 `$(...)`、反引号、`sudo`/`env`/`xargs` 等包装形式与 `bash -c`、`eval` 这类间接执行），换行断开的命令也能正确识别。

危险命令这一屏每条字段的含义、非交互模式下的行为 → [使用手册](使用手册.md)。

### 6.3 加密凭据

默认不加密，密码直接写在配置或清单里。要加密就把配置里的 `encrypt` 改成 `true`，然后：

1. `SSHFleet --gen-key` 生成主密钥，**重开终端**
2. 把明文写进凭据文件，用 `SSHFleet --convert-secret <文件>` 转成密文
3. 配置与清单里那几个位置改成填**文件的绝对路径**

完整的步骤、主密钥的范围（**它是"这个用户、这台机器"的，加密后的凭据文件不能带着走**）、忘了重开终端怎么办 → [加密与密钥](加密与密钥.md)。

## ⑦ 结果与历史记录

每次执行自动归档到 `history/` 下独立目录：

```text
history/
├── SSHFleetTools.log                     # 工具运行日志（滚动文件，保留全部历史）
└── 2026-09-22_14-30-00_command_看磁盘/    # 每次执行一个目录：时间+模式+备注
    ├── SSHFleetExec.log                  # 本次执行的明细日志（每台服务器的连接/执行/分类）
    ├── terminal-output.txt               # 终端输出（txt）
    ├── terminal-output.xlsx              # 终端输出（Excel）
    ├── report.txt                        # 汇总报告
    ├── results.xlsx                      # 结果明细（Excel）
    └── assets/                           # 资源备份（本次用到的清单与脚本）
```

目录名里的模式为 `command` / `script` / `upload` / `download`；`-r 备注` 可让目录名更好认（如 `-r 发布v2`）。

回看历史有两个入口：进 `history/` 找对应时间目录，或直接看工作目录下的 **`latest_history`**（它总是指向最新一次的历史目录，Windows 与 Linux 都支持）。

终端会实时显示进度（总进度、每台服务器进度、成功/失败台数、传输字节与速度），执行结束后输出统计块：总耗时、节点数与完成数校验、成功/失败台数、失败分类统计。分类下面可能跟着一段"提示："，解释本次出现过的原因大概是什么；`执行失败(退出码N)` 那条会带上常见退出码的含义（如 `127 = 命令未找到`）。

各模式的终端显示范围不同：**命令 / 脚本模式**下每台服务器的明细（连接状态、输出内容、分类）会实时打到终端；**上传 / 下载模式**下终端只有进度条——逐文件明细（含被跳过的软链接）不占屏幕，直接写进归档的 `SSHFleetExec.log` 与 `terminal-output.txt`。

哪里看哪台机器出了什么问题 → [使用手册](使用手册.md)。

## ⑧ 技术架构

它是**单一 Go 程序**，没有子进程、没有本地端口：

```text
你的命令 → 解析与校验 → 危险命令分析 → 并发连接所有服务器（命令 / 脚本 / SFTP）
     → 实时进度与结果回流 → 统计 / 报告 / 归档
```

- **执行**：`golang.org/x/crypto/ssh` 负责连接与命令执行，`github.com/pkg/sftp` 负责文件传输
- **并发**：按清单节点数并行，可用 `-n` 限流；中断（Ctrl+C）时停止派发新任务，已经完成的节点结果照常整理归档
- **危险命令分析**：先用 shell 语法解析器（`mvdan.cc/sh`）把命令拆成语法树再逐条判定，语法有误时回退到逐行分析
- **配置与规则**：配置文件为 TOML 格式，启动时校验，问题一次报清

## ⑨ 常见问题（FAQ）

**Q1：启动就报「配置缺少必填字段」/「取值非法」？** A：配置里所有字段都必须写出来且取值合法——基础段和进阶段的字段都不能缺。按报错里点名的字段补齐即可，报错会一次列全。

**Q2：提示「配置文件不存在」？** A：工具从**当前工作目录**读 `./config/SSHFleet.conf`。先 `cd` 到解压出来的目录（`config/` 与可执行文件同级）再运行。

**Q3：提示「配置包含未识别字段」？** A：字段名拼错了，或写了工具不接受的字段。报错会列出具体名字。

**Q4：连接超时？** A：网络不通或服务器响应慢。用 `-T 30` 加大连接超时；批量前先拿单节点 `-c "uptime"` 验证连通性。

**Q5：我配了私钥，怎么还是用密码登录了？** A：**要用密钥必须加 `-k`**，不加就是纯密码登录，配置和清单里配了私钥也不会用。

**Q6：上传报「远端路径不存在」？** A：工具不替你创建远端目录。先在目标机上建好目录，`-p` 写绝对路径且以 `/` 结尾，例如 `/opt/app/`。

**Q7：报错「出现多余的参数（未被使用）」？** A：多半是这三种之一——① 写了通配符如 `-u /本地/abc/*`，被终端展开成多个路径（上传目录不需要通配符）；② 路径含空格但没加引号；③ 参数打多了或打错了。报错里会列出未被使用的参数。

**Q8：提示「主密钥」相关的问题？** A：那说明你打开了加密。先跑 `SSHFleet --key-status` 看现状；最常见的是刚生成完密钥，**重开终端**即可。详见 [加密与密钥](加密与密钥.md)。

**Q9：历史记录在哪看？** A：`history/` 目录，每次执行一个时间目录；也可以直接看工作目录下的 `latest_history`，它指向最新一次。

更多问题（连接、认证、上传下载、加密、结果）→ [常见问题](常见问题.md)。
