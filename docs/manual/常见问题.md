# 常见问题

这一册只收**上手阶段最容易撞到的问题**——从解压到第一次跑通之间会遇到的。深入的问题在其它几册里。

---

## 启动阶段

**Q：提示"配置文件不存在"。**

工具从**当前工作目录**读 `./config/SSHFleet.conf`。先 `cd` 到解压出来的那个目录再执行。

这不是缺陷——工具会把 `history/` 等产物生成在**当前目录**下，所以它要求你在正确的目录里执行，免得把结果散落到别处。

**Q：提示"配置缺少必填字段：account.port, ..."。**

**基础段与进阶段的字段都得写出来（一共 17 个）**，缺哪个都会拒绝启动。报错会**一次列全**，不用逐轮试。见 [配置手册](配置手册.md)。

**Q：提示"配置包含未识别字段：account.pasword"。**

字段名拼错了，或者写了工具不认识的字段。报错里会列出具体名字，照着改。**这一条是有意设计的**：不然拼错的字段会被静默忽略，你以为配上了、其实没生效。

**Q：提示某个字段"取值非法"。**

取值超出允许范围。报错会说明范围（比如端口是 1–65535、超时必须是正整数、是否加密只能是 `true` / `false`）。

**Q：提示"清单里有错误"，列了好几行。**

工具在**开工前**把清单检查一遍，把问题一次报全，然后退出。报错会点到**第几行、哪一列、什么问题**，比如：

```text
发现以下错误:
行 3 (IP: 192.168.1.12): - 密码不能为空
行 7 (IP: 192.168.1.16): - 端口必须是1-65535之间的整数，当前值为：abc
```

改完那几行再跑。**检查通过就意味着一定会尝试连接**，不会跑到一半再冒出缺字段。

## 连接与登录

**Q：连接超时。**

网络不通或目标机响应慢。先用单台验证连通性：

```bash
SSHFleet -f 192.168.1.10 -c "uptime"
```

确认这台能连上，再把超时调大（`-T` 管连接超时）。

**Q：密码不对 / 认证失败。**

工具不会重试、也不会退回别的方式。先确认这台机器的用户名、端口、密码三样对不对——写错一个就是认证失败。

**Q：我配了私钥，怎么还是用密码登录了？**

**要用密钥必须加 `-k`**（`--key`）。不加就是纯密码登录，配置和清单里配了私钥也不会用。

如果清单第 5 列写了私钥却没加 `-k`，工具会给一行提示提醒你——看到那句提示就是这件事。

**Q：加了 `-k`，它说缺私钥。**

`-k` 只是说"这次用密钥"，私钥从哪来还要给：清单第 5 列，或者配置里的 `key`。两处都没有就会报错。

**Q：私钥有口令，怎么办？**

在清单第 6 列给口令，或者在配置里配一个默认口令（`key_password`）。

工具**不检查**第 6 列——它无从判断你的私钥加没加密。但如果解析时发现私钥确实是加密的、又没有口令，会明确告诉你该往哪填。

**Q：提示"主密钥"相关的问题。**

那说明你打开了加密（配置里 `encrypt = true`）。加密用的钥匙存在系统环境变量里，与凭据文件分处两地。

```bash
SSHFleet --key-status      # 看现状：本次读到哪把、本机存的是哪把、是否一致、下一步做什么
```

**最常见的一种是"刚生成完密钥"**：当前终端读不到刚写进去的环境变量，**重开终端**即可。

> 注意：如果它说的是"本机已保存、但当前终端没读到"，**不要重新生成**——重新生成会换掉钥匙，已经加密的凭据就都打不开了。

## 执行阶段

**Q：提示"发现危险命令"，我该做什么？**

工具在执行前会检查命令内容，命中规则时列出来。看清**来源、行号、内容、规则、级别**——内容是判断危不危险的依据，行号用来在脚本里定位。

- 级别 `禁止`：命令被直接拒绝，工具退出，没有"继续"这个选项
- 级别 `高` / `中` / `低`：确认无误就继续

不想被某一条规则打扰，去 `config/dangerous_keywords.conf` 把那条改成 `enabled = false`，或用 `#` 注释掉。

**Q：报错"出现多余的参数（未被使用）"。**

多半是这三种之一：

1. 写了通配符 —— `-u /本地/abc/*` 会被终端**展开成多个路径**。上传目录不需要通配符，直接写目录本身
2. 路径含空格但没加引号 —— 写成 `"路径 含 空格"`
3. 参数打多了或打错了

报错里会列出未被使用的那些，照它去掉即可。

## 上传与下载

**Q：上传报"远程路径不存在"。**

工具不会替你创建远端目录。先在目标机上把目录建好，`-p` 写绝对路径、以 `/` 结尾，例如 `/opt/app/`。

**Q：上传目录之后，目标里怎么没有 `abc` 这一层？**

上传目录传的是**它的内容**（内部子目录层级会完整保留），目录自身那一层不重复出现。想要 `/opt/abc/…` 这种结果，把 `abc` 的**父目录**传上去。

**Q：上传时提示"有 N 个软链接被过滤"。**

这不是错误。上传和下载都**一律过滤软链接**（含 Windows 目录联接、`.lnk`），不中断执行，被过滤的条目写进那台机器的结果明细里。

只有过滤之后**一个可传文件都不剩**才会报错（比如整个目录全是软链接）。上传时会在终端额外提示一句，是因为上传源在本地、参数一输入就能查到。

**Q：`--sudo` 了，下载 root-only 的文件还是失败。**

`--sudo` 只提升**上传落盘**那一侧（在目标机上建目录、搬文件），**下载的文件读取仍以登录用户身份进行**。权限 `700` 这类文件会读失败。

办法：先用 sudo 命令模式把文件搬到登录用户可读的位置，再下载。

**Q：下载报枚举失败。**

下载用的目录枚举依赖目标机的 GNU `find -printf`。多数 Linux 发行版自带；busybox / BSD 环境不兼容。

## 加密相关

**Q：打开加密之后，提示找不到密码文件。**

打开加密会**同时改变两处字段的含义**：`password` 与清单第 4 列，从不加密时的"密码本身"变成"密码文件的绝对路径"。所以打开之后，那两处的内容也要跟着换成文件路径。

同理，第 6 列与 `key_password` 也是这套规则。见 [进阶：加密与密钥](加密与密钥.md)。

**Q：加密后的凭据文件能拷到别的机器用吗？**

不能。主密钥存在**这台机器的这个用户**下（Windows 注册表 / Linux 你登录 shell 的启动文件），换机器、换用户都可能读不到。

所以**加密适合在一台固定机器上长期跑**；如果你需要把凭据文件到处拷、或者经常换机器执行，就别打开它。

## 结果

**Q：执行完了，细节在哪看？**

每次执行都在 `history/` 下按时间单独建一个目录，里面有终端记录、汇总报告、每台节点的结果明细、执行日志，以及本次用到的清单备份。

也可以直接打开工作目录下的 `latest_history`，它总是指向最新一次。

**Q：终端上只看到汇总，逐台输出在哪？**

命令 / 脚本模式下逐台明细会实时打在终端；上传 / 下载模式下终端只有进度条与个别提示，逐文件结果写进那一次的 `SSHFleetExec.log` 与 `terminal-output.txt`。

**Q：统计里的失败分类是什么意思？**

分类名下面可能跟着一段"提示："，解释本次出现过的原因大概是什么。`执行失败(退出码N)` 那条会带上常见退出码的含义（如 `127 = 命令未找到`）。

不想要这个提示块，把配置 `[enable]` 段里的 `show_category_tips` 改成 `false`。
