# 进阶：加密与密钥

这一册讲两件事：**把密码/口令加密存放**，以及**私钥怎么配**。日常用明文就够了，看到这里说明你有更严的要求。

---

## 加密：一个开关，两处写法

配置里有一个布尔字段：

```toml
[account]
encrypt = false          # false = 明文；true = 加密
```

**它决定的不只是一个开关，而是"密码写在哪里"：**

| | 配置里的 `password` 字段 | 清单第 4 列 |
| --- | --- | --- |
| `encrypt = false` | 填**密码本身** | 填**密码本身** |
| `encrypt = true` | 填**密码文件的绝对路径** | 填**密码文件的绝对路径** |

第 6 列（私钥口令）与配置里的 `key_password` 同一套规则。

**不加密最好懂**：密码就写在文件里，一眼能看出是什么意思。代价是明文——所以配置文件与清单**不要外传**。

**加密是给"敏感环境"用的**：磁盘上只有密文，解密要一把单独存放的钥匙（主密钥）。多一道手续，换来的是"文件被拿走也打不开"。

> **打开这个开关不是改一个数字。** 它同时改变了上面那两处的含义，所以那两处的内容也得一起换（从"密码本身"变成"文件路径"）。改完之后第一次运行，如果它提示某个路径不对，先想想是不是这个开关刚动过。

---

## 主密钥

加密用的钥匙叫**主密钥**：一串随机字符，存在**系统环境变量**里，与凭据文件分处两地——这就是它比明文安全的原因。

它存在哪：

- **Windows**：写进注册表
- **Linux**：写进你登录 shell 的启动文件（bash 是 `~/.bashrc`、zsh 是 `~/.zshrc`）

所以它的作用范围是**这个用户、这台机器**。

**据此判断要不要打开加密：**

| 你的情况 | 建议 |
| --- | --- |
| 在一台固定机器上长期跑（定时任务、日常工作机） | 适合打开 |
| 需要把凭据文件到处拷、或经常换机器执行 | **不要打开**——换机器、换用户、换终端会话都可能读不到主密钥 |

### 生成

```bash
SSHFleet --gen-key
```

显示新密钥的指纹，并把它写进上面那两处。如果本机已经有一把，它会先把"本次运行用的哪把、本机存的是哪把"并排摆出来再问你，避免你稀里糊涂换掉一把还在用的钥匙。

**生成之后要重开终端。** 当前终端读不到刚写进去的环境变量——这不是缺陷，是环境变量的工作方式。

### 万一忘了

工具每次运行都会自己体检一遍（当前终端读到的 vs 本机保存的），发现对不上会当场说清现状与下一步，不用你记着。也可以随时手动查看：

```bash
SSHFleet --key-status
```

它会告诉你：本次运行读到哪把（指纹）、本机保存的是哪把、两处是否一致、下一步该做什么。

**两处不一致时**，**加密方向会被直接拦下**——因为用旧钥匙加密出来的文件，重开终端后就再也打不开了，这是不可逆的损失，不给你侥幸的空间。解密方向只警告不拦（文件可能正是用当前这把加密的）。

### 丢了会怎样

**主密钥丢了，已加密的凭据文件就解不开了**，只能重新把明文写进文件、重新加密一次。所以：

- 不要把主密钥和凭据文件放在同一个地方备份
- 不要在提示"本机已保存但当前终端没读到"时**重新生成**——那种情况是重开终端就好的，重新生成会换掉钥匙，已加密的凭据全部失效

## 加密凭据文件

打开加密之后，凭据文件里存的必须是密文。用一个命令完成：

```bash
# 1. 先把明文写进一个文件（记事本新建、或用命令）
echo -n '你的服务器密码' > /home/ops/.keys/db_pass.txt

# 2. 就地加密（文件内容被改写成密文）
SSHFleet --convert-secret /home/ops/.keys/db_pass.txt
```

这个命令是**自适应**的：它先认文件里现在是什么，再按配置的开关转成该有的样子。

- 文件已经是目标格式 → 提示跳过，不做无用功
- 需要先解开才能转（比如把加密关掉之后要把文件转回明文）→ 自动用主密钥解开再转，不必先改配置

转换后有防呆检查：文件为空、含二进制内容、内容是多行（多半是误粘贴）都会当场报错；需要解密但没配主密钥、或主密钥对不上，也会明确提示并给出操作指引。

---

## 三命令速查

| 命令 | 什么时候用 |
| --- | --- |
| `SSHFleet --gen-key` | 打开加密之前，生成主密钥 |
| `SSHFleet --key-status` | 提示"主密钥有问题"、或换了机器/终端之后，看现状 |
| `SSHFleet --convert-secret <文件>` | 凭据填成明文之后（或改了加密开关之后），把文件转成该有的格式 |

这三个命令都**单独使用**，不跟批量执行一起用。

## 私钥怎么配

私钥不是"凭据文件"，它不参与加密转换——私钥文件本身就是 PEM 原文（或它自己的加密格式），工具不改它。

三件事：

1. **要用密钥登录就得加 `-k`**（`--key`）。不加就是纯密码登录，配置里配了私钥也不会用。
2. **私钥路径**取清单第 5 列，那颗没写就取配置里的 `key`。想要"上千台统一一把"，就在配置里配一把默认的。
3. **私钥口令**取清单第 6 列，那颗没写就取配置里的 `key_password`。按加密开关的规则填（不加密时填口令明文，加密时填口令文件的绝对路径）。

工具**不检查**第 6 列——它无从判断你的私钥加没加密，报了也是误报。但如果解析时发现私钥确实是加密的、又没有口令，会明确告诉你该怎么办。

**非交互场景**（`--yes`、定时任务）下也用同样的规则，所以带口令的私钥照样能跑——口令写在清单或配置里，不需要有人在场敲。
