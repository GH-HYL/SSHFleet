# 测试环境使用指南

> 给任何要「找台目标机验点东西」的会话（AI 或人）。**读完这一页就够**，不必去翻 `docs/个人开发规范.md` 的三·4——那里只留指针与两条硬约束。
>
> 三步：**认开发机 → 按场景选机器 → 照抄命令**。地址、端口、账号都在本文里，不用猜，也不用现配环境。

---

## 一、先认开发机：本机不等于目标机

| 你在 | 要验的 | 去哪 |
| --- | --- | --- |
| Linux 开发机（本工作区跑在 Ubuntu 26.04） | Linux / bash 语义 | **本机直接跑**，不用起容器 |
| Linux 开发机 | 另一个发行版的行为（CentOS 7.9） | Podman 起容器（第三节） |
| Windows 开发机 | Linux / bash 语义 | **WSL2 里跑**；不要把 cmd / PowerShell 的输出当目标机行为，它们不是同一套语义 |
| Windows 开发机 | 编出来的 exe 的真实行为 | **Windows 本机**跑原生 go 编的 exe。WSL 里编的是 linux 版，`path` / `filepath` 按 `GOOS` 在编译期就定死，测了等于没测 |

`podman` 前面挂了个包装脚本（`~/.local/bin/podman`）：rootful 跑、按 tag 自动补挂载与固定 IP。**正常用 `podman` 就行**，别绕过它直连 `/usr/bin/podman`。

## 二、三种场景，按成本从低到高

### A. 只想看某条命令输出长什么样（与工具无关）

- Linux 开发机、要的就是 bash/Linux 语义：直接跑，`bash -lc '<命令>'`。
- 要另一个发行版：`podman exec <容器> bash -lc '<命令>'`（容器按第三节起）。
- Windows 开发机：`wsl -d Ubuntu-26.04 -- bash -lc '<命令>'`（发行版名按实际装的写）。

成本：零，或者「起一个容器」。

### B. 写 / 跑测试代码

对象是 `modules/SSHFleet_Go/internal/ssh` 下那批 `//go:build integration` 的用例。两点先记住：`go test ./...` **不加载**它们；连接变量缺一个就整批 skip。

起目标机（第三节），然后给五个变量：

| 变量 | 作用 |
| --- | --- |
| `SSHFLEET_TEST_HOST` / `PORT` / `USER` / `PASSWORD` | 缺一个就全 skip |
| `SSHFLEET_TEST_FULLDIR` | 那块 64MB 卷上的可写目录，填 `/mnt/small64/w` |
| `SSHFLEET_TEST_SUDO=1` | 打开需要提权的两条 |
| `SSHFLEET_TEST_RACE=1` | 并发占盘那条，默认关着 |

跑：`go test -tags integration -count=1 ./internal/ssh/`。变量名以代码为准，本文只是抄一份给你。

### C. 真的把工具跑起来做端到端

目标机还是第三节那两台，**区别只在配置与产物**：不要碰 `modules/SSHFleet_Go/config/SSHFleet.conf`（那是作者本机配置），拷一份到 `build/<用途>_<时间戳>/` 里改。

最小一套：`SSHFleet-for-linux.conf` → `config/SSHFleet.conf`，补三份 `keywords_*.conf`，`[credential]` 的 `encrypt` 改 `false`，清单里写明文密码，命令加 `--yes` 免确认屏。要看结果就读 `history/SSHFleetTools.log` 里的 `r=` / `s=` / `u=` / `d=` / `p=` 行——那是进入后续环节的实际值。

**B 和 C 常被当成一件事，其实差一层**：B 是代码里的用例，C 是人或脚本驱动真实二进制。要验的行为已经有用例 → 走 B；要看整条链路（终端文案、归档目录、xlsx）或改完想眼见为实 → 走 C。

## 三、目标机池：现成的两套

| 镜像 | 发行版 |
| --- | --- |
| `localhost/sshfleet-ubuntu:26.04` | Ubuntu 26.04 |
| `localhost/sshfleet-centos:7.9` | CentOS 7.9 |

起（两行，照抄）：

```bash
podman run -d --name u1 --hostname u1 -p 127.0.0.1:2201:22 localhost/sshfleet-ubuntu:26.04
podman run -d --name c1 --hostname c1 -p 127.0.0.1:2202:22 localhost/sshfleet-centos:7.9
```

- **地址不用猜**：宿主端口 2001–2254 → 容器 IP `10.88.1.<端口−2000>`。上面这两行就是 `10.88.1.201` / `10.88.1.202`。包装脚本自动加 `--ip`，并顺手挂一块 64MB 的 `/mnt/small64`。
- **不要加 `--network=host`**：容器里绑不上 22。
- **账号只有一个**：`sshfleet` / `Sshfleet#2026`，`NOPASSWD` sudo 直接过；root 直登是关的。
- **先 `podman ps` 看一眼**：`u1` / `c1` 可能已经开着，重名再起会失败。
- 镜像库里还留着旧的四个 `*forpod:*-sshfleet-{base,tiny-tmp}`（带四个账号、小卷、自检 Banner 的夹具版）。**新东西别再用它们**，它们按用例定制，跟现在的边界不符。

## 四、要「非默认」的目标机，自己在容器里加

| 要什么 | 怎么做（都用 `u1`，换台改名字） |
| --- | --- |
| 普通的第二个账号 | `podman exec u1 useradd -m t1`，然后 `echo 't1:口令' \| podman exec -i u1 chpasswd` |
| 密码已过期（改密入场） | 接上一条再 `podman exec u1 chage -d 0 t1` |
| 登录被禁 | `podman exec u1 useradd -m t2 -s /sbin/nologin` |
| 「远端不吭声」 | 造个只会 `exit 1` 的桩当登录 shell：写 `/usr/local/bin/quiet`（两行：`#!/bin/sh` + `exit 1`），`chmod 755`，再 `useradd -m -s /usr/local/bin/quiet t3`。实测效果：会话建得起来、零输出、退出码 1 |
| 700 的 root 目录 | `podman exec u1 sudo mkdir /ro && podman exec u1 sudo chmod 700 /ro` |
| `/tmp` 限小 | **得重建容器**：`podman run ... --tmpfs /tmp:size=32m,mode=1777` |
| 另一块盘 | 同上，`--tmpfs /mnt/big:size=512m` |

## 五、坑（都踩过）

- **CentOS 7 没有 `C.UTF-8`**：你带着 `LC_ALL=C.UTF-8` 连过去，远端每个命令前都会刷一行 `setlocale: cannot change locale`。这是 ADR-0030 的由来，不是工具的问题。
- **`/tmp` 限小与大文件上传互斥**：判暂存侧空间不足那条要求 `/tmp` 小于 40MB，而「贴着边也能传成」那条要传 60MB 上下——两者别放同一个容器。
- **root 不能当测试账号**：程序里 `effectiveSudo := useSudo && cfg.User != "root"`，root 登录会把整段 sudo 路径跳过，测了等于没测。
- **容器重启会清空**：`/tmp` 与 `/mnt/small64` 都是 tmpfs，`stop` / `start` 之后内容没了。
- **产物不许出工作区**：沙盒落 `build/<用途>_<时间戳>/`，按天清理；容器里的临时文件也别往回拷。

## 六、收尾

`podman rm -f u1 c1`。镜像留着，下次还要用。
