# SSHFleet

SSHFleet 是一个 **SSH 批量运维工具**：一条命令，批量操作清单里的所有服务器——执行命令、运行脚本、上传/下载文件，结果自动统计归档。

整个工具就一个可执行文件：Windows `SSHFleet.exe`、Linux `SSHFleet`。

> [!WARNING]
> 该工具可能存在 BUG，请在测试环境验证后再用于生产。数据无价，操作前请再三思量。

## 1 这是什么，能干什么

### 1.1 定位

把逐台「登录 → 执行 → 退出」变成一条命令操作清单里的所有服务器：你准备一份节点清单，并发、收集、统计、归档都交给工具。

### 1.2 能力

| 能力              | 说明                                                       |
| ----------------- | ---------------------------------------------------------- |
| 批量执行命令      | 一条命令跑遍清单里的所有服务器，实时看进度                 |
| 批量执行脚本      | 把本地脚本发到每台服务器执行（默认识别 `.sh` / `.py`，解释器可在配置里扩展） |
| 交互代填          | 脚本在远端提问（选架构、选包格式等）时按预置的触发词自动填入内容（`-a`） |
| 批量改密          | 把清单里密码过期的账号改成同一个新密码，工具自己认提示、自己喂（`--change-password`） |
| 批量上传文件      | 本地文件/目录分发到每台服务器的指定位置                    |
| 批量下载文件      | 收集每台服务器的文件/目录，按 IP 分目录存到本地            |
| 危险命令防护      | 自动识别 `rm -rf /` 等危险命令，执行前提示风险并要求确认   |
| 密码 / 密钥双认证 | 密码登录与密钥登录，按一次执行统一选用                     |
| 结果自动归档      | 每次执行生成独立目录：终端输出（txt / Excel）、汇总报告、资源备份 |

## 2 安装

### 2.1 前置要求

| 项       | 要求                                 |
| -------- | ------------------------------------ |
| 操作系统 | Windows / Linux（均为 64 位）        |
| 运行时   | 无                                   |
| 磁盘     | 约 20MB（可执行文件本身）            |

### 2.2 安装步骤

1. 取到对应平台的发布包：`SSHFleet_<打包时间>_windows.zip`（Windows）或 `SSHFleet_<打包时间>_linux.tar.gz`（Linux）。
2. 解压到任意目录（建议单独放一个目录，例如 `/opt/SSHFleet`），会得到（以 Linux 包为例；Windows 包的可执行文件带 `.exe` 后缀）：

   ```text
   SSHFleet                      # 可执行文件（Windows 下是 SSHFleet.exe）
   README.md                     # 本文件：快速开始
   CHANGELOG.md                  # 版本记录
   config/
   ├── SSHFleet.conf             # 配置文件——用之前按你的环境改这里
   ├── keywords_dangerous.conf   # 危险命令规则
   ├── keywords_error.conf       # 错误分类关键词
   └── keywords_passwd.conf      # 批量改密：认提问、认失败原因
   docs/                         # 六册手册
   ```

3. 修改 `config/SSHFleet.conf` 里的登录用户、SSH 端口、密码三项（都在基础配置），详见 [2 基础配置手册](docs/2-基础配置手册.md) 的「1 基础配置」。
4. **在这个目录里**运行它。最小用法就是连一台机器、跑一条命令：

   Windows（命令提示符 / PowerShell）：

   ```bat
   SSHFleet.exe -f 192.168.1.10 -c "uptime"
   ```

   Linux / macOS（bash）：

   ```bash
   ./SSHFleet -f 192.168.1.10 -c "uptime"
   ```

   想把 `SSHFleet` 装成随处能敲的命令：复制到 `PATH` 里的目录（如 `/usr/local/bin`）再 `chmod +x`。

> [!IMPORTANT]
> **关于配置文件**
>
> - **`config/` 必须就在当前工作目录下**：工具从当前目录读 `./config/SSHFleet.conf`，找不到就报「配置文件不存在」。所以先 `cd` 到解压出来的目录再执行。
> - 配置里**所有字段都必须写出来**（个别项的值可以留空）。工具不设任何隐藏默认值，缺字段或取值不合法会在启动时一次告诉你是哪几项。
> - 加密默认开着（`encrypt = true`），需要先有一个主密钥，详见 [3 进阶配置手册](docs/3-进阶配置手册.md) 的「2 加密与密钥」。

> [!NOTE]
> 📖 **自行编译**（可选）
>
> 不自己编译可以跳过这段。源码在 `modules/SSHFleet_Go/`，需要 **Go 1.27+**，在工程目录下 `go build` 即可得到可执行文件。

## 3 快速上手

> 下面示例统一写 `SSHFleet`；Windows 下请写成 `SSHFleet.exe`。
>
> 忘了某个选项怎么写？**直接运行 `SSHFleet`（不带任何选项）就会打印完整帮助**，等同 `-h`。

### 3.1 最快路径：内联清单（不需要建任何文件）

`-f` 可以直接接一段服务器信息，最小写法只写 IP：

```bash
SSHFleet -f 192.168.1.10 -c "uptime"
```

回车后有一屏参数确认，确认后即可连接该服务器执行命令。端口、用户名、密码都从配置里取。

### 3.2 标准流程：一份清单，多条命令

一次要操作多台时，把服务器写成一份清单文件：

```bash
# 第 1 步：写清单（每行一台，只写 IP 即可）
#    nodes.csv:
#    192.168.1.10
#    192.168.1.11
#    192.168.1.12

# 第 2 步：执行
SSHFleet -f nodes.csv -c "uptime"
```

清单的六列分别是什么、某台要用不一样的端口或密码怎么写 → [1 使用手册](docs/1-使用手册.md) 的「1 节点清单」。

### 3.3 常用场景示例

```bash
# 批量执行命令（看磁盘）
SSHFleet -f nodes.csv -c "df -h"

# 批量跑部署脚本（root 权限）
SSHFleet -f nodes.csv -s deploy.sh --sudo

# 分发文件到所有服务器（远端目录要已存在，且以 / 结尾）
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/

# 收集所有服务器的日志（按 IP 分目录存到本地）
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads

# 密钥登录（所有节点统一用配置里那把私钥）
SSHFleet -f nodes.csv -c "uptime" -k

# 不要任何确认（定时任务）
SSHFleet -f nodes.csv -s deploy.sh --yes
```

更多可照抄的场景 → [6 示例](docs/6-示例.md)。

## 4 核心概念

### 4.1 节点清单

清单是一份纯文本，**每行一台服务器**，英文逗号分隔，可以用记事本 / VSCode 编辑。空行会被跳过；以 `#` 开头的行会被当作注释跳过。

```csv
# 生产环境
192.168.1.10
192.168.1.11
192.168.1.12
```

**只写 IP 就够了**——端口、用户名、密码都从配置里取。想让某台用别的值，往后接着写；最多六列，依次是 IP、端口、用户名、密码、私钥路径、私钥口令。

`-f` 除了接文件路径，也能直接接一串服务器信息（内联清单），写法与那六列一一对应：

```bash
SSHFleet -f "192.168.1.10,22,root,你的密码" -c "uptime"
```

六列的取值规则、每台不同的写法、各列留空时的取值顺序 → [1 使用手册](docs/1-使用手册.md) 的「1 节点清单」。

### 4.2 密码与加密

**出厂默认就是加密的**（`encrypt = true`）：密码、口令以密文存在磁盘上，配置和清单里填的是**凭据文件的本机绝对路径**，解开它要一把单独存放的主密钥。

也支持不加密——那是**图省事**：这几个位置改成直接写密码本身，一眼看得出是什么意思。代价是清单一旦被复制、分享或进版本库，密码就跟着走了；**建议保持加密**。

加密怎么开、主密钥怎么管 → [3 进阶配置手册](docs/3-进阶配置手册.md) 的「2 加密与密钥」。

### 4.3 配置默认值与路径

配置文件是 `config/SSHFleet.conf`，提供清单留空字段的默认值。分**基础配置**与**进阶配置**两部分，字段都必须写出来，缺一个工具会拒绝启动。

默认取值的优先级：**命令行 > 清单 > 配置文件**。配置里的凭据路径要写绝对路径，分隔符 `\` 或 `/` 都行（程序会统一处理）。

每个字段的完整说明、路径怎么写 → [2 基础配置手册](docs/2-基础配置手册.md) 的「1 基础配置」、[3 进阶配置手册](docs/3-进阶配置手册.md) 的「3 路径怎么写」。

## 5 五种模式与选项

### 5.1 五种模式

五种操作模式，**每次只能选一种**：

| 模式 | 选项                      | 作用                   | 示例                                  |
| ---- | ------------------------- | ---------------------- | ------------------------------------- |
| 命令 | `-c "命令"`               | 每台服务器执行一条命令 | `-c "df -h"`                          |
| 脚本 | `-s 脚本文件`             | 上传本地脚本并执行     | `-s deploy.sh`                        |
| 上传 | `-u 本地路径 -p 远端目录` | 分发文件/目录到服务器  | `-u ./app.tar.gz -p /opt/`            |
| 下载 | `-d 远端路径 -p 本地目录` | 收集服务器文件/目录    | `-d /opt/logs/app.log -p ./downloads` |
| 改密 | `--change-password 新密码` | 把密码过期的账号改成同一个新密码 | `--change-password "你的新密码"` |

```bash
SSHFleet -f nodes.csv -c "df -h"
SSHFleet -f nodes.csv -s deploy.sh
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads
SSHFleet -f nodes.csv --change-password "你的新密码"
```

> [!IMPORTANT]
> **上传 / 下载的两条硬约定**
>
> - `-p` 是"目标路径"：上传的目标在服务器（**绝对路径、以 `/` 结尾**，如 `/opt/app/`），下载的目标是一个**已经存在**的本地目录。
> - 上传时**远端目录必须已经存在**，工具不会替你创建。
>
> 目录层级、软链接过滤、通配符这些细节 → [1 使用手册](docs/1-使用手册.md) 的「2 五种操作」。

### 5.2 选项

每个选项都有等价的**长写法**（`-c` 与 `--command`、`-T` 与 `--connect-timeout` …），两种写法完全等价：短写法手敲快，长写法自解释。批量执行的用法骨架（五种模式五选一，`-p` 仅上传 / 下载需要）：

```text
SSHFleet ( -c | -s | -u | -d | --change-password ) -f 清单 [其他可选参数]
```

每个选项的完整说明、长短写法对照 → [1 使用手册](docs/1-使用手册.md) 的「3 选项表」；三个单独使用的密钥管理命令（`--gen-key` / `--key-status` / `--convert-secret`）→ [3 进阶配置手册](docs/3-进阶配置手册.md) 的「2.3 三命令速查」。

## 6 进阶用法

### 6.1 密钥登录

工具默认用密码登录。要用密钥，加 `-k`：

```bash
SSHFleet -f nodes.csv -c "uptime" -k
```

私钥从哪取、口令怎么给、配了私钥却忘了加 `-k` 会怎样 → [1 使用手册](docs/1-使用手册.md) 的「5 密钥登录」。

### 6.2 提权 / 并发 / 超时 / 不要确认

```bash
# root 身份执行
SSHFleet -f nodes.csv -c "systemctl restart nginx" --sudo

# 限流（默认全部并行）
SSHFleet -f nodes.csv -c "uptime" -n 10

# 控制超时：-T 连接、-t 执行或传输
SSHFleet -f nodes.csv -c "uptime" -T 15 -t 60

# 跳过所有确认
SSHFleet -f nodes.csv -s deploy.sh --yes
```

> [!WARNING]
> **用 root 之前，目标节点上这个账号得已经配好免密 sudo**——工具只发 `sudo <命令>`，不代你输密码。
> 配法与没配的现象 → [1 使用手册](docs/1-使用手册.md) 的「6 执行身份」。

另外两件开跑前会拦你一下的事：命令命中**危险命令**规则时会列出来要你确认（禁止级直接拒绝执行，规则在 `config/keywords_dangerous.conf` 里）、以及执行前的参数确认屏。两屏分别长什么样 → [1 使用手册](docs/1-使用手册.md) 的「10 执行前你会看到两屏」。

### 6.3 加密凭据

**出厂默认就是加密的**（`encrypt = true`）：密码、口令以密文存盘，填给配置和清单的是凭据文件的本机绝对路径；用之前先备好主密钥。**不加密也能跑**——那是给图省事的人留的：改成 `false`、把密码直接写进配置或清单。代价是**凭据一旦裸奔就有泄露风险**（清单一被复制、分享、进版本库，密码就跟着走），只建议在清楚风险、且文件不外流时用。

改开关、生成主密钥、把凭据转成密文，完整步骤（含主密钥为什么不能带着走、忘了重开终端怎么办）→ [3 进阶配置手册](docs/3-进阶配置手册.md) 的「2 加密与密钥」。

### 6.4 远端交互代填 `-a`

安装脚本经常停下来问你「请选择架构」「要 deb 还是 rpm」——批量跑的时候没人守着按回车，整批会卡到超时。`-a` 把你预知的答案先写下来：工具在远端输出里认出你指定的**触发词**，就自动把对应内容填进去。

```bash
# 远端脚本会依次打印这两句，各停下来等一次回车：
#   请选择架构 (1=amd64, 2=arm64):     → 敲 1
#   请选择包格式 (deb/rpm):            → 敲 deb
# -a 就是把这两下预先写下来：一行一条（格式与 -f 的清单相同），
# 第 1 列是要填进去的值，第 2 列起是从提示原文抄的触发词
SSHFleet -f nodes.csv -s install.sh -a "1,请选择架构\ndeb,请选择包格式"
```

值的完整写法、CSV 文件形式、两类收尾失败的含义 → [1 使用手册](docs/1-使用手册.md) 的「4 代填 `-a`」；照着抄的完整例子 → [6 示例](docs/6-示例.md)。

### 6.5 批量改密 `--change-password`

一批服务器的密码同时到期了——很多系统这时会强制你先改密码，批量跑命令直接卡住。这条命令把它们的密码一次改成同一个新的：

```bash
# 不开加密时：后面直接写新密码
SSHFleet -f nodes.csv --change-password "你的新密码"

# 开了加密时：后面写密文文件的绝对路径
SSHFleet -f nodes.csv --change-password "C:/keys/newpw.sec"
```

**你不用配任何触发词**：远端会依次问「当前的密码」「新的密码」「重新输入」，工具自己匹配提示词、自己填。密码没到期的机器不会被改，单独归一类「密码未过期」并计入失败数。

完整的判定规则与全部失败分类 → [1 使用手册](docs/1-使用手册.md) 的「2.6 批量改密 `--change-password`」；照着跑的完整例子 → [6 示例](docs/6-示例.md)。

### 6.6 脚本解释器（可配）

命令模式（`-c`）与脚本模式（`-s`）用什么解释器跑，在配置文件的 `[interpreter]` 里定，随包默认 `.sh` 用 `bash`、`.py` 用 `python3`：

```bash
# 目标机只有 Python 2 —— 把配置里的 ".py" 改成 python2 即可
SSHFleet -f nodes.csv -s install.py

# 想跑 .pl 脚本 —— 在 [interpreter.script] 里加一行 ".pl" = "perl"
SSHFleet -f nodes.csv -s deploy.pl
```

每种后缀怎么配、目标机报「找不到某某命令」怎么办 → [3 进阶配置手册](docs/3-进阶配置手册.md) 的「7 解释器」。

### 6.7 命令在远端是怎么执行的

工具**不把命令原文直接交给目标机**：默认在远端套一层外壳，先把环境变量设好，再把你的命令交给解释器。你敲的是：

```bash
SSHFleet -f nodes.csv -c "df -h"
```

目标机上实际跑的是下面这条——`df -h` 本身经 stdin 喂给内层解释器，不出现在命令行里：

```text
sh -c 'export LANG="en_US.UTF-8" LC_ALL="en_US.UTF-8" PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin" TERM="dumb"; sudo bash'
```

加了 `--no-shell`，这一整层外壳就不要了，命令原样下发。

为什么要套这层外壳、正文从哪条路送下去 → [4 进阶知识手册](docs/4-进阶知识手册.md) 的「1 命令在远端是怎么执行的」。

## 7 结果与历史记录

每次执行自动归档到 `history/` 下独立目录：

```text
工作目录/
├── latest_history                        # 指向最新一次的历史目录
└── history/
    ├── SSHFleetTools.log                 # 工具运行日志（滚动文件，保留全部历史）
    └── 2026-09-22_14-30-00_command_看磁盘/    # 每次执行一个目录：时间+模式+备注
        ├── SSHFleetExec.log              # 本次执行的明细日志（每台服务器的连接/执行/分类）
        ├── terminal-output.txt           # 终端输出（txt）
        ├── terminal-output.xlsx          # 终端输出（Excel）
        ├── report.txt                    # 汇总报告
        ├── results.xlsx                  # 结果明细（Excel）
        └── assets/                       # 资源备份（本次用到的清单、脚本与代填文件）
```

目录名里的模式为 `command` / `script` / `upload` / `download` / `passwd`；`-r 备注` 可让目录名更好认（如 `-r 发布v2`）。

回看历史有两个入口：进 `history/` 找对应时间目录，或直接看工作目录下的 **`latest_history`**（它总是指向最新一次的历史目录，Windows 与 Linux 都支持）。

终端会实时显示进度（总进度、每台服务器进度、成功/失败台数、传输字节与速度），执行结束输出统计块：总耗时、节点数校验、成功/失败台数、失败分类统计；`执行失败(退出码N)` 附常见退出码的含义（如 `127 = 命令未找到`）。连上了却没跑成的行会多给一段「错误详情」：报错原文之外，还有「未送出的代填」与「中间步骤」（工具为完成操作在远端额外跑的伴随命令及其退出码），排查时不用再猜工具背后做了什么。

各模式的终端显示范围不同：**命令 / 脚本模式**下每台服务器的明细（连接状态、输出内容、分类）会实时打到终端；**上传 / 下载模式**下终端只有进度条，外加个别提示（如上传源里有软链接被过滤）——逐文件明细不占屏幕，直接写进归档的 `SSHFleetExec.log` 与 `terminal-output.txt`。

逐台的明细在哪、怎么定位某台机器的问题 → [1 使用手册](docs/1-使用手册.md) 的「12 执行完，结果在哪」。

## 8 技术架构

它是**单一程序**：没有子进程、没有本地端口，目标机上也不需要装额外的东西。

- **执行**：本机直接连上目标机的 SSH 干活，传文件走 SFTP
- **并发**：按清单节点数并行，可用 `-n` 限流；中断（Ctrl+C）时停止派发新任务，已经完成的节点结果照常整理归档
- **危险命令分析**：把命令拆成语法结构再逐条判定，不是简单地找关键词
- **配置与规则**：配置文件用 TOML 写法，启动时校验，问题一次报清

完整的处理链路 → [4 进阶知识手册](docs/4-进阶知识手册.md) 的「8 工具的内部骨架」。

## 10 手册之间的关系

`README` 是入口；`docs/` 下的**六册**分两档：

- **基础档（4 册）**讲「怎么用」：《1 使用手册》《2 基础配置手册》《5 常见问题》《6 示例》。
- **进阶档（2 册）**讲「为什么这样、还能怎样、代价是什么」：《3 进阶配置手册》《4 进阶知识手册》——它们是从属的。

两册进阶各自从属于谁：

- **《3 进阶配置手册》从属于《2 基础配置手册》**：配置里「进阶配置」段每个字段怎么配，`2` 不展开，用到时指过来。
- **《4 进阶知识手册》从属于全部手册**：工具内部怎么处理、为什么这么设计——任何一册里遇到「为什么」，都指到它。

为什么要分两档：**基础越短越好**——只关心基本功能的人，翻两下就能走；**进阶越细越好**——想弄清一件事的人，要的是掰开揉碎。所以基础册不展开进阶内容、进阶册不重复基础内容，两边一律「见某册某节」互相指路；**新增或修改文档也照这条线**——先定它属于哪一档、挂在哪一册，再动笔。
