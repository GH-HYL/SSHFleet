# SSHFleet

SSHFleet 是一个 **SSH 批量运维工具**：一次命令输入，派出一支"舰队"（fleet）——批量连接清单里的每一台服务器，执行命令、运行脚本、上传/下载文件，结果自动统计归档。

从 5.0.0 起它是**一个可执行文件**：Windows 一个 `SSHFleet.exe`、Linux 一个 `SSHFleet`，不需要 Python，也不需要额外准备引擎程序。

> [!WARNING]
> 该工具可能存在 BUG，请在测试环境验证后再用于生产。数据无价，操作前请再三思量。

## ① 这是什么，能干什么

### 定位

把「SSH 登录 → 执行 → 退出」这套逐台操作，变成「**一条命令操作清单里的所有服务器**」。你准备一份服务器清单，告诉工具要做什么，剩下的并发、收集、统计、归档都交给工具。

### 能力

| 能力              | 说明                                                            |
| ----------------- | --------------------------------------------------------------- |
| 批量执行命令      | 一条命令跑遍清单里的所有服务器，实时看进度                      |
| 批量执行脚本      | 把本地 `.sh` / `.py` 脚本发到每台服务器执行                     |
| 批量上传文件      | 本地文件/目录分发到每台服务器的指定位置                         |
| 批量下载文件      | 收集每台服务器的文件/目录，按 IP 分目录存到本地                 |
| 危险命令防护      | 自动识别 `rm -rf /` 等危险命令，执行前提示风险并要求确认        |
| 密码 / 密钥双认证 | 支持密码登录与密钥登录（密钥优先、密码兜底），`-k` 三种用法分流 |
| 结果自动归档      | 每次执行生成独立目录：终端输出（txt/excel）、汇总报告、资源备份 |

## ② 安装

### 前置要求

| 项       | 要求                                    |
| -------- | --------------------------------------- |
| 操作系统 | Windows / Linux（均为 64 位）           |
| 运行时   | 无——不需要 Python、Node 或其它运行时    |
| 磁盘     | 约 20MB（可执行文件本身）               |

### 安装步骤

1. 取到对应平台的发布包：`SSHFleet_<版本>_windows.zip` 或 `SSHFleet_<版本>_linux.tar.gz`。
2. 解压到任意目录（建议单独放一个目录，例如 `D:\Tools\SSHFleet`），会得到：

   ```text
   SSHFleet.exe            # Windows（Linux 为无后缀的 SSHFleet）
   README.md               # 本文件
   config/
   ├── SSHFleet.conf           # 配置文件——用之前按你的环境改这里
   ├── dangerous_keywords.toml # 危险命令规则
   └── error_keywords.toml     # 错误分类关键词
   ```

3. 修改 `config/SSHFleet.conf` 里的默认账号信息（至少 `account.user`、`account.port`、`account.secret_dir`），详见 [4.3](#43-配置默认值与相对路径)。
4. **在解压出来的这个目录里**运行工具（它从**当前工作目录**读 `./config/SSHFleet.conf`）：

   ```bash
   # Windows（在解压目录打开终端）
   SSHFleet.exe

   # Linux
   ./SSHFleet
   ```

   不带任何参数会打印帮助。

> [!IMPORTANT]
> **关于配置文件的两个"必须"**
>
> - **必须**和可执行文件放在同一个目录下：工具从当前工作目录读 `./config/SSHFleet.conf`。先 `cd` 到那个目录再执行，否则会报「配置文件缺失」。
> - 配置里**所有字段都必须写出来**（允许留空字符串）。5.0.0 起不设任何隐藏默认值，缺字段或取值不合法会在启动时直接告诉你是哪一项。
>
> **如果配置里 `account.password_security = 3`（加密等级）**，首次使用前先执行一次 `--gen-key` 生成主密钥（详见 [4.2](#42-凭据文件)）；否则用到凭据时会提示缺少主密钥。

> [!NOTE]
> 📖 深入：自行编译（可选）
>
> 不自己编译可以跳过这段。源码在 `modules/SSHFleet_Go/`，需要 **Go 1.27+**：
>
> ```bash
> # 工作区根目录下提供了两个构建脚本，双击/直接运行即可
> build-windows.bat            # Windows：编译双平台，产物落 build\
> ./build-linux.sh             # Linux / 自动化：编译双平台，产物落 build/
>
> # 需要连发布目录和压缩包一起产出时，加一个 release 参数
> build-windows.bat release    # 产出 release\SSHFleet_<版本>_windows.zip
> ./build-linux.sh release     # 产出 release/SSHFleet_<版本>_linux.tar.gz
> ```
>
> 版本号取自 `CHANGELOG.md` 顶部第一个正式版本号；取不到时用当天日期。

## ③ 快速上手

这一章讲**整体怎么用**：从最快到最标准，先跑通一条命令。过程中涉及的概念（清单、凭据文件、参数）在后续章节详解，这里先用最小例子跑起来。

> 下面示例统一写 `SSHFleet`；Windows 下请写成 `SSHFleet.exe`。

### 3.1 最快路径：内联清单（不需要建任何文件）

`-f` 可以直接接一段服务器信息（内联清单），最小写法只写 IP：

```bash
SSHFleet -f "192.168.1.10" -c "uptime"
```

回车后工具交互询问密码（输入不显示属正常），即可连接该服务器执行命令。

> [!NOTE]
> 📖 深入：内联清单（`-f` 的第二种用法）
>
> `-f` 既能接文件路径（`-f nodes.csv`），也能直接接一段服务器信息。内联清单用英文逗号分隔，最多 6 段，与 CSV 6 列一一对应：
>
> ```text
> -f "IP, 端口, 用户名, 密码文件路径, 密钥文件路径, 私钥口令文件路径"
> ```
>
> **只写 IP 时**其余全用配置默认值（端口/用户名），密码由工具交互询问。临时测一台机器时，内联清单比建 CSV 快得多。各段省略时的取值顺序见 [4.1](#41-节点清单-csv)。

### 3.2 标准流程：清单 + 密码文件 + 模式

准备一台以上服务器、一个账号密码，然后照这个流程走：

```bash
# 第 1 步：准备密码文件（把明文密码写进文件，再用转换命令按当前等级转换，详见 4.2）
echo -n '你的服务器密码' > ~/.MyPW/pw.txt
SSHFleet --convert-password ~/.MyPW/pw.txt

# 第 2 步：写清单（所有服务器配置一样且已在配置里配好默认值时，只写 IP 即可）
#    nodes.csv:
#    192.168.1.10
#    192.168.1.11
#    192.168.1.12

# 第 3 步：执行
SSHFleet -f nodes.csv -c "uptime"
```

### 3.3 常用场景示例

```bash
# 批量执行命令（看磁盘）
SSHFleet -f nodes.csv -c "df -h"

# 批量跑部署脚本（sudo 权限）
SSHFleet -f nodes.csv -s deploy.sh -m sudo

# 分发文件到所有服务器（远端目录要已存在，且以 / 结尾）
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/

# 收集所有服务器的日志（按 IP 分目录存到本地）
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads

# 密钥登录（所有节点统一用一把私钥，详见 6.1）
SSHFleet -f nodes.csv -c "uptime" -k ~/.ssh/id_rsa

# 非交互批量（跳过所有确认）
SSHFleet -f nodes.csv -s deploy.sh --disinteractive
```

## ④ 核心概念

批量操作时你会接触到三个概念：**节点清单 CSV**、**凭据文件**（放密码/私钥口令的地方）、**配置默认值**。这一章讲清它们，⑤ 再讲四种模式怎么选。

### 4.1 节点清单 CSV

CSV 是一份"服务器清单"：纯文本，每行一台服务器，英文逗号分隔，可以用记事本 / VSCode 编辑。空行会被跳过；以 `#` 开头的行会被当作注释跳过。

```csv
# 生产环境
192.168.1.10
192.168.1.11
192.168.1.12
```

上面的清单表示 3 台服务器，其余信息（端口/用户名/密码）按 4.3 的规则取默认值。

> [!NOTE]
> 📖 深入：CSV 6 列详解
>
> 每行固定 **6 列**，按顺序排列，后面的列可留空：
>
> | 列  | 字段             | 必填 | 说明                                                                              |
> | --- | ---------------- | ---- | --------------------------------------------------------------------------------- |
> | 1   | IP               | 是   | 服务器 IP（**格式必须是标准 IPv4**，域名或 `IP:端口` 写法都会报错）                |
> | 2   | 端口             | 否   | SSH 端口，默认用配置 `account.port`                                               |
> | 3   | 用户名           | 否   | 登录用户名，默认用配置 `account.user`                                             |
> | 4   | 密码文件路径     | 否   | **密码文件的路径，不是密码本身**（见 4.2），默认用配置 `account.password`         |
> | 5   | 密钥文件路径     | 否   | PEM 私钥路径，仅在写了 `-k` 之后才生效（见 6.1），默认用配置 `account.key`        |
> | 6   | 私钥口令文件路径 | 否   | 仅当第 5 列私钥本身加密时填，与第 5 列**成对**使用，默认用配置 `account.key_passphrase` |
>
> 文件首行如果是表头（第 1 列不是 IP 格式），会被自动跳过并提示一行 INFO——从 Excel 里导出的清单可以带表头。
>
> **常见写法（从简到全，照着抄）：**
>
> ```csv
> # ① 单个 IP（最简单）——其余全用配置默认值
> 192.168.1.10
>
> # ② 常用配置：IP + 端口 + 用户名 + 密码文件路径
> 192.168.1.10,22,root,~/.MyPW/pw.txt
>
> # ③ 多台服务器共用一个密码文件（端口/用户名留空用默认）
> 192.168.1.10,22,root,~/.MyPW/pw.txt
> 192.168.1.11,,user,~/.MyPW/pw.txt
> 192.168.1.12,,,~/.MyPW/pw.txt
>
> # ④ 每台密码不同——第 4 列各自指向不同的密码文件
> 192.168.1.10,,,/opt/keys/node10_pw.txt
> 192.168.1.11,,,/opt/keys/node11_pw.txt
>
> # ⑤ 密钥登录（不用密码）——第 4 列留空，第 5 列写私钥路径，并且命令行要带 -k
> 192.168.1.10,,,,~/.ssh/id_ed25519
>
> # ⑥ 私钥本身需要口令（有 passphrase）——再加第 6 列口令文件
> 192.168.1.10,22,root,,~/.ssh/id_ed25519,~/.MyPW/key_pp.txt
>
> # ⑦ 全满配置：6 列全填
> 192.168.1.10,10022,deploy,~/.MyPW/pw.txt,~/.ssh/id_ed25519,~/.MyPW/key_pp.txt
> ```
>
> **列留空时的取值顺序**：命令行 > 清单列 > 配置文件 > 交互询问（`--disinteractive` 非交互模式下无法询问，会直接报错）。
>
> **认证判定**（一台服务器用哪种方式登录）：
>
> - 第 4、5 列都填 → 先试密钥，密钥被拒再回退用密码；两者都被拒时结果显示「密钥与密码均失败」
> - 只填第 5 列 → 纯密钥登录
> - 只填第 4 列 / 都空 → 用密码登录
> - **密钥登录必须显式写 `-k`**（见 6.1）；不写 `-k` 时第 5、6 列会被整体忽略
> - 用密钥的服务器**不会**被套上配置里的默认密码——那份密码对它没用

> [!WARNING]
> 密码不要直接写进 CSV：清单文件常被复制、分享、留存或进版本库，明文密码等于裸奔。密码放独立"凭据文件"，CSV 只写路径（见 4.2）。

### 4.2 凭据文件

**密码 / 私钥口令不直接写进 CSV，而是放在一个"凭据文件"里，CSV 只引用文件路径。** 文件里的内容格式由配置的「密码安全等级」`account.password_security` 决定，共三档：

| 等级            | 文件里的内容       | 安全度 | 适合场景          | 需要做什么                                       |
| --------------- | ------------------ | ------ | ----------------- | ------------------------------------------------ |
| **1（明文）**   | 密码原文           | 最低   | 本机 / 临时演示   | 密码直接写入文件                                 |
| **2（base64）** | 密码的 base64 编码 | 中等   | 简单的工作环境    | 写明文后转换一次，转换后可复用，无须再次转换     |
| **3（加密）**   | 加密密文           | 最高   | 多环境 / 敏感场景 | 先生成主密钥，再转换；复用逻辑同 base64         |

> [!NOTE]
> 📖 深入：密码与凭据文件
>
> **为什么不能把密码直接写进 CSV？** 清单文件经常被复制、分享、留存、审计或进版本库，密码写进去就等于跟着清单到处跑。约定：密码单独放文件，CSV 只写"文件在哪"。
>
> **等级 3 需要主密钥**，先生成一次：
>
> ```bash
> SSHFleet --gen-key
> ```
>
> 主密钥是随机生成的字符串，保存在系统环境变量 `SSHFleet_KEY` 中（Windows 写入注册表、Linux 写入登录 shell 的 rc 文件）。生成后**需要重开终端**才能读到；密钥与凭据文件分离存放，这是等级 3 比 base64 更安全的原因。
>
> **正确用法：用转换命令按等级转换**（`--convert-password` 自动识别文件内容格式——明文 / base64 / 加密，再转成配置等级对应的格式）：
>
> ```bash
> SSHFleet --convert-password ~/.MyPW/pw.txt
> ```
>
> 转换命令读的是**文件里的明文内容**，所以先把明文密码写进一个文件（记事本新建或命令行都行）：
>
> ```bash
> echo -n '你的服务器密码' > ~/.MyPW/pw.txt
> ```
>
> 然后运行转换命令，文件内容被就地转为配置等级对应的格式。转换后 CSV 第 4 列（或配置 `account.password`）指向该文件，工具运行时会按等级自动还原密码。**转换是自适应的**：文件已是目标格式会提示跳过；从高等级降到低等级（如加密→base64、加密→明文）会自动用主密钥解密转换，无需先改配置。
>
> 路径写法与其它凭据字段一致：写相对路径时会拼接 `account.secret_dir`（见 4.3）。
>
> 转换命令自带防呆校验：文件为空 / 含二进制数据（非文本文件）会直接报错；明文内容含换行（误粘贴多行）会报错提示；需要解密（降级或加密格式转换）但未配置主密钥、或主密钥不匹配时，会明确提示并附操作指引。
>
> **等级怎么选？** 简单环境用 **2（base64）** 足够；安全性要求高再切 **3（加密）**；完全信任本机环境才用 **1（明文）**。
>
> **手动生成**（仅等级 2 适用，等级 3 无法手算）：
>
> ```bash
> # Linux / macOS:
> echo -n '你的服务器密码' | base64 > ~/.MyPW/pw.txt
>
> # Windows PowerShell:
> [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('你的服务器密码')) | Out-File -NoNewline ~/.MyPW/pw.txt
> ```
>
> 旧版本（4.x）生成的加密凭据**可以直接使用**，无需重新转换。

### 4.3 配置默认值与相对路径

配置文件是 `config/SSHFleet.conf`（TOML 格式），提供 CSV 留空字段的默认值：

```toml
[account]
port = 22                  # 默认端口：CSV 第 2 列留空时用
user = "root"              # 默认用户名：CSV 第 3 列留空时用
password = "SSHFleet_pw"   # 默认密码文件：CSV 第 4 列留空时用（填文件名或路径，不是密码本身）
```

> [!NOTE]
> 📖 深入：相对路径的拼接规则（`secret_dir`）
>
> 配置 `account.secret_dir` 是"凭据目录"。CSV 或配置里写**相对路径**（如 `pw.txt`）时，会拼接成 `secret_dir/pw.txt`。
>
> 三种路径写法：
>
> | 写法                | 含义                        |
> | ------------------- | --------------------------- |
> | `~/.MyPW/pw.txt`    | `~` 展开为用户目录          |
> | `/home/user/pw.txt` | 绝对路径，原样使用          |
> | `pw.txt`            | 相对路径，拼接 `secret_dir` |
>
> 只需在配置里写一次 `secret_dir`，CSV 里写短文件名即可，密码文件集中管理。若 `secret_dir` 留空却又用了相对路径，工具会明确提示「未配置 secret_dir」并给出两条出路（改写绝对路径，或补上 secret_dir），不会拼出一个莫名其妙的路径。

## ⑤ 四种模式与参数

四种操作模式，**每次只能选一种**：

| 模式 | 参数                      | 作用                   | 示例                                  |
| ---- | ------------------------- | ---------------------- | ------------------------------------- |
| 命令 | `-c "命令"`               | 每台服务器执行一条命令 | `-c "df -h"`                          |
| 脚本 | `-s 脚本文件`             | 上传本地脚本并执行     | `-s deploy.sh`                        |
| 上传 | `-u 本地路径 -p 远端目录` | 分发文件/目录到服务器  | `-u ./app.tar.gz -p /opt/`            |
| 下载 | `-d 远端路径 -p 本地目录` | 收集服务器文件/目录    | `-d /opt/logs/app.log -p ./downloads` |

```bash
SSHFleet -f nodes.csv -c "df -h"
SSHFleet -f nodes.csv -s deploy.sh
SSHFleet -f nodes.csv -u ./app.tar.gz -p /opt/
SSHFleet -f nodes.csv -d /opt/logs/app.log -p ./downloads
```

> [!IMPORTANT]
> **上传 / 下载的两个硬性约定**
>
> - `-p` 是"目标位置"：上传的目标在服务器，下载的目标在本地。上传时必须写**绝对路径且以 `/` 结尾**（如 `/opt/app/`）；下载时必须是一个**已经存在**的本地目录。
> - 上传时**远端目录必须已经存在**——工具不会替你创建目录。写错路径时会在那一台上直接报「远程目标路径不存在」并跳过该节点，而不是在错的地方悄悄建出一个目录。
> - 上传目录时**保留内部的子目录层级**，中间目录会按需创建；但**目录自身那一层不会重复出现**——`-u /本地/abc -p /opt/` 得到的是 `/opt/<abc 的内容>`。想要 `/opt/abc/…` 这种结果，把 `abc` 的**父目录**传上去即可（层级同样保留）。
> - **不支持也不需要通配符**：`-u` 只接收一个路径（写目录本身就够，内容会按原层级传过去）。若写成 `-u /本地/abc/*`，通配符会被终端展开成多个参数，工具会直接报「出现多余的参数」并列出未被使用的那些，而不是悄悄少传。
> - **软链接一律不上传、不下载**：源里的软链接（含 Windows 目录联接、`.lnk` 快捷方式）会被**过滤**掉，不会中断执行——上传时在终端提示被过滤了哪几个，下载时把提示写进该节点的结果明细。只有**过滤后一个可传文件都不剩**才报错（例如整个目录全是软链接）。

### 参数总表

批量执行（四种模式**四选一**）：

```text
SSHFleet  ( -c | -s | -u | -d )  -f  [ -p ]  [其他可选参数]
```

工具选项（**单独使用**，不与批量执行模式搭配）：

```text
SSHFleet --gen-key
SSHFleet --convert-password 文件路径
```

**① 模式参数（四选一）**

| 参数          | 说明                                             |
| ------------- | ------------------------------------------------ |
| `-c "命令"`   | 命令模式：在每台服务器执行一条命令               |
| `-s 脚本文件` | 脚本模式：上传本地脚本并执行（`.sh` / `.py`）    |
| `-u 本地路径` | 上传模式：把本地文件/目录传到服务器（需 `-p`）   |
| `-d 远端路径` | 下载模式：从服务器下载文件/目录到本地（需 `-p`） |

**② 工具选项（单独使用）**

| 参数                      | 说明                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| `--gen-key`               | 生成主密钥并持久化到系统环境变量 `SSHFleet_KEY`（等级 3 加密凭据用，见 4.2）                 |
| `--convert-password 文件` | 转换凭据文件：自动识别格式（明文/base64/加密）并按配置等级转换，支持升降级（见 4.2）        |

**③ 其他参数**

| 参数               | 说明                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| `-f csv_file`      | 节点清单：CSV 文件路径，或内联的一段服务器信息（`-c`/`-s`/`-u`/`-d` 时必须带，见 3.1）          |
| `-p path`          | 目标位置（上传/下载必带，方向见上）                                                             |
| `-m mode`          | 执行身份：`direct`=登录用户身份，`sudo`=root 身份（默认取配置 `execution.mode`）                 |
| `-t timeout`       | 单台执行/传输超时（秒）；默认取配置：执行用 `timeout_execute`、传输用 `timeout_transfer`        |
| `-T timeout`       | 连接每台服务器的超时（秒）；默认取配置 `timeout_connect`                                        |
| `-n number`        | 并发数：同时操作几台服务器；不填默认全部并行                                                    |
| `-r remark`        | 任务备注，作为历史记录文件夹的后缀（不填自动生成，默认取命令内容）                              |
| `--nobash`         | 命令模式专用：不套一层 bash 环境，直接执行原始命令                                              |
| `--disinteractive` | 跳过所有确认/询问直接执行                                                                       |
| `-k [路径]`        | 密钥登录开关（三种用法，见 6.1）                                                                |

## ⑥ 进阶用法

### 6.1 密钥登录与 `-k` 三态

工具**不会**因为清单配了密钥就自动用密钥，**必须显式加 `-k`** 才启用密钥登录。

> [!NOTE]
> 📖 深入：`-k` 的三种用法
>
> **① 不写 `-k` = 纯密码登录**  
> 忽略所有密钥配置（清单第 5/6 列、配置里的 `key` / `key_passphrase`），只走密码逻辑。
>
> **② 仅写 `-k`（不带路径）= 逐节点用自己的密钥**  
> 私钥按「清单第 5 列 → 配置 `account.key`」解析；私钥口令**与私钥同源**：「清单第 6 列 → 配置 `account.key_passphrase`」。适合每台密钥不同。
>
> **③ `-k /path/to/key` = 所有节点统一用这把私钥**  
> 强制使用该私钥，忽略节点自带的密钥/口令；私钥有口令时在运行时交互询问（直接回车 = 无口令）。路径相对终端工作目录（`~` 展开）。
>
> ```bash
> # 统一私钥登录（加密私钥会交互问口令）
> SSHFleet -f nodes.csv -c "df -h" -k /opt/keys/id_rsa
>
> # 每台用各自的密钥（清单/配置里配好）
> SSHFleet -f nodes.csv -c "df -h" -k
>
> # 纯密码（忽略一切密钥配置）
> SSHFleet -f nodes.csv -c "df -h"
> ```

### 6.2 sudo / 并发 / 超时 / 非交互

**sudo 执行**（命令需要 root 权限时，也可在配置里把 `execution.mode` 长期设为 `sudo`）：

```bash
SSHFleet -f nodes.csv -c "systemctl restart nginx" -m sudo
```

**限制并发**（默认全部并行，服务器扛不住时限流）：

```bash
SSHFleet -f nodes.csv -c "uptime" -n 10
```

**超时控制**：`-T` 连接超时、`-t` 执行/传输超时：

```bash
SSHFleet -f nodes.csv -c "uptime" -T 15 -t 60
```

**非交互模式**：跳过所有确认和询问（需要交互的部分如密码/口令会直接报错，需提前在清单或配置里备好）：

```bash
SSHFleet -f nodes.csv -s deploy.sh --disinteractive
```

> [!NOTE]
> 📖 深入：危险命令与确认环节
>
> 执行前工具会分析命令（命令模式分析 `-c` 的内容，脚本模式分析脚本文件），命中危险规则时给出提示：
>
> - **禁止级**（如删除系统根目录、删除系统目录）：直接拒绝执行并退出，不给"继续"的选项
> - **高 / 中 / 低风险**：列出命中的每一条（含来源行号、内容、规则名与级别），询问「已明确风险继续执行？」；回答否即取消
> - 非交互模式（`--disinteractive`）下，禁止级仍然拒绝；其余级别放行，但会在工具日志里留下一条记录，事后可查
> - 规则写在 `config/dangerous_keywords.toml`：每条 = 名字 / 示例 / 正则 / 级别；不想被某条打扰，把它改成 `enabled = false` 或用 `#` 注释掉整条
> - 脚本会经语法解析后逐条分析（含 `$(...)`、反引号、`sudo`/`env`/`xargs` 等包装形式与 `bash -c`、`eval` 这类间接执行），换行断开的命令也能正确识别

### 6.3 配置文件全解

> [!NOTE]
> 📖 深入：配置项详解（全字典）
>
> 以下为完整配置（与随包提供的 `config/SSHFleet.conf` 一致），注释即说明：
>
> ```toml
> # 账号信息
> [account]
> port = 10022                 # 默认 SSH 端口（清单第 2 列留空时用）
> user = "root"                # 默认用户名（清单第 3 列留空时用）
> password_security = 2        # 密码安全等级：1=明文 / 2=base64 / 3=加密
> secret_dir = "~/.MyPW"       # 凭据目录：密码/私钥/私钥口令文件的相对路径都拼到这里（"" 即未配置）
> password = "SSHFleet_pw"     # 默认密码文件路径（内容格式随 password_security，用 --convert-password 转换）
> key = ""                     # 默认私钥文件路径（内容为 PEM 私钥原文）
> key_passphrase = ""          # 默认私钥口令文件路径（内容格式同密码文件）
>
> # 执行参数
> [execution]
> mode = "sudo"                # 执行身份：direct=用登录用户身份执行，sudo=用 root 身份执行
> timeout_connect = 10         # 连接超时（秒）
> timeout_execute = 60         # 执行超时（秒），执行命令或脚本
> timeout_transfer = 300       # 传输超时（秒），上传或下载文件
>
> # 功能开关（必填）
> [enable]
> output_to_xlsx = true        # 终端输出同时导出 xlsx；false=仅输出到 txt
> results_to_xlsx = true       # 结果固化到 xlsx 文件；false=不输出到本地文件
>
> # 文件路径（规则文件、日志与结果文件名）
> [paths]
> error_keywords = "./config/error_keywords.toml"          # 错误分类关键词文件
> dangerous_keywords = "./config/dangerous_keywords.toml"  # 危险命令规则文件
> historys = "historys"        # 历史记录目录名
> tool = "SSHFleetTools.log"   # 工具日志文件名
> exec = "SSHFleetExec.log"    # 执行日志文件名
> asset = "assets"             # 历史记录里存放清单/脚本备份的目录名
> output = "output.txt"        # 终端输出文件名（txt）
> output_xlsx = "output.xlsx"  # 终端输出文件名（xlsx）
> report = "report.txt"        # 统计报告文件名
> results_xlsx = "results.xlsx" # 结果固化文件名（xlsx）
>
> # 上传并发策略（按文件大小，单位字节 B）
> [upload.concurrency_thresholds]
> small_file = 2097152         # 2MB；小于此值全量并发
> large_file = 20971520        # 20MB；大于此值串行上传
> medium_concurrency = 10      # 介于两者之间时的并发数
> ```
>
> 取值原则：**命令行 > 清单 > 配置 > 交互询问**。大部分配置保持默认即可，通常只需按环境调整 `account` 段的默认账号信息；`password_security` 与 `password` / `key` / `key_passphrase` 要保持同一套（见 4.2）。

## ⑦ 结果与历史记录

每次执行自动归档到 `historys/` 下独立目录：

```text
historys/
├── SSHFleetTools.log                     # 工具运行日志（滚动文件，保留全部历史）
└── 2026-08-25_14-30-00_command_备注/      # 每次执行一个目录：时间+模式+备注
    ├── SSHFleetExec.log                  # 本次执行的明细日志（每台服务器的连接/执行/分类）
    ├── output.txt                        # 终端输出（txt）
    ├── output.xlsx                       # 终端输出（Excel，可在配置里关闭）
    ├── report.txt                        # 汇总报告
    ├── results.xlsx                      # 结果明细（Excel，可在配置里关闭）
    └── assets/                           # 资源备份（本次用到的清单与脚本）
```

目录名里的模式为 `command` / `script` / `upload` / `download`；`-r 备注` 可让目录名更好认（如 `-r 发布v2`）。

终端会实时显示进度（总进度、每台服务器进度、成功/失败台数、传输字节与速度），执行结束后输出统计块：总耗时、节点数与结果数校验、成功/失败台数、失败分类统计（含常见退出码含义提示，如 `127 = 命令未找到`）。

回看历史有两个入口：进 `historys/` 找对应时间目录，或直接看工作目录下的 **`latest_history`**（它总是指向最新一次的历史目录，Windows 与 Linux 都支持）。

## ⑧ 技术架构

5.0.0 起是**单一 Go 程序**，没有子进程、没有本地端口：

```text
你的命令 → 解析与校验 → 危险命令分析 → 并发连接所有服务器（命令 / 脚本 / SFTP）
     → 实时进度与结果回流 → 统计 / 报告 / 归档
```

- **执行**：`golang.org/x/crypto/ssh` 负责连接与命令执行，`github.com/pkg/sftp` 负责文件传输
- **并发**：按清单节点数并行，可用 `-n` 限流；中断（Ctrl+C）时停止派发新任务，已经完成的节点结果照常整理归档
- **危险命令分析**：先用 shell 语法解析器（`mvdan.cc/sh`）把命令拆成语法树再逐条判定，语法有误时回退到逐行分析
- **配置与规则**：均为 TOML 文件，启动时校验，问题一次报清

## ⑨ 常见问题（FAQ）

**Q1：启动就报「配置缺少必填字段」/「取值非法」？** A：5.0.0 起配置里所有字段都必须写出来且取值合法。按报错里点名的字段补齐即可——报错会一次列全，不用逐轮试。

**Q2：提示「配置文件缺失」？** A：工具从**当前工作目录**读 `./config/SSHFleet.conf`。先 `cd` 到解压出来的目录（`config/` 与可执行文件同级）再运行。

**Q3：提示缺少主密钥？** A：配置里 `account.password_security = 3` 时，加解密凭据需要主密钥。执行一次 `SSHFleet --gen-key`，然后**重开终端**再跑（当前终端读不到刚写入的环境变量）。

**Q4：连接超时？** A：网络不通或服务器响应慢。用 `-T 30` 加大连接超时；批量前先拿单节点 `-c "uptime"` 验证连通性。

**Q5：密码文件打不开 / 解码失败？** A：工具会自动识别文件内容格式（明文/base64/加密）并提示与配置等级是否匹配。若提示"与当前等级不匹配"，按提示把配置 `account.password_security` 改成文件实际等级，或用 `--convert-password` 直接转换（会自动识别并转到目标等级），见 [4.2](#42-凭据文件)。

**Q6：遇到危险命令提示怎么办？** A：工具会列出命中的规则与级别并询问是否继续，输入 `y` 继续；**禁止级**（删根、删系统目录）不给继续的选项，直接退出。规则可在 `config/dangerous_keywords.toml` 里调整（`enabled = false` 或注释掉）。定时任务等场景可加 `--disinteractive` 跳过确认（放行会留痕在工具日志，请谨慎使用）。

**Q7：密钥登录不生效？** A：必须显式加 `-k`（不带路径 = 逐节点用清单/配置里的密钥；带路径 = 所有节点统一用这把私钥）。只改清单不会启用，见 [6.1](#61-密钥登录与-k-三态)。

**Q8：上传报「远程目标路径不存在」？** A：工具不替你创建远端目录。先在目标机上建好目录，`-p` 写绝对路径且以 `/` 结尾，例如 `/opt/app/`。

**Q9：上传目录后，目标里怎么没有 `abc` 这一层？** A：上传目录传的是**它的内容**（内部子目录层级会完整保留），目录自身那一层不会重复出现；中间目录也不需要你手动建，工具会按需创建。想要 `/opt/abc/…` 这种结果，把 `abc` 的**父目录**传上去即可。

**Q10：报错「出现多余的参数（未被使用）」？** A：多半是这三种情况之一——① 写了通配符如 `-u /本地/abc/*`，被终端**展开成多个路径**（上传目录不需要通配符，直接写目录本身即可）；② 路径含空格但**没加引号**（请写成 `"路径 含 空格"`）；③ 参数打多了或打错了。报错里会列出未被使用的参数，照它去掉即可。

**Q11：历史记录在哪看？** A：`historys/` 目录，每次执行一个时间目录；也可以直接看工作目录下的 `latest_history`，它指向最新一次。详见 [⑦](#⑦-结果与历史记录)。

**Q12：服务器同时配了私钥和密码，日志里「密钥与密码均失败」是什么意思？** A：表示这台服务器两种认证方式都被拒绝——先试的密钥被拒，回退用的密码也被拒。若只配了其中一种而失败，结果会直接给原始错误、不带这个分类。

**Q13：源目录里有软链接会怎样？** A：**一律过滤掉，不中断执行**。上传时终端会提示「上传源中有 N 个软链接/快捷方式被过滤（不上传）：…」；下载时同样的提示写进该节点的结果明细（归档里的 `output.txt`、执行日志、`output.xlsx` 都能看到）。只有**过滤后一个可传文件都不剩**才报错，并说明已过滤多少个——例如整个目录全是软链接，或 `-d` 指向的路径本身就是软链接。
